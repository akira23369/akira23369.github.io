在 Unity 中，UI 的 Draw Call（绘制调用）主要由**材质 / 纹理切换**和**渲染状态变更**导致。合理设置 UI 面板的层级（Hierarchy 顺序），本质是让 Unity 尽可能合并相同材质 / 纹理的 UI 元素的渲染批次（Batch），从而减少 Draw Call。将文字放在最高层，也是基于这个逻辑的优化手段。下面从渲染机制、层级设置原则、文字特殊处理三个方面详细说明：

# UI的Draw Call为什么会产生？

Unity 的 UI 渲染遵循 “**同材质连续渲染可合并批次**” 的原则：
- 当多个 UI 元素使用**完全相同的材质（Material）和纹理（Texture）**，且在渲染顺序上连续（中间没有插入其他材质的元素）时，Unity 会将它们合并为一次 Draw Call。
- 反之，若不同材质的元素交替出现（如 “图片→文字→图片→文字”），每切换一次材质就会增加一次 Draw Call（因为 GPU 需要重新加载材质参数）。

例如：
- 3 个使用同一图集的图片连续排列 → 1 次 Draw Call。
- 1 个图片（材质 A）→ 1 个文字（材质 B）→ 1 个图片（材质 A）→ 3 次 Draw Call（A→B→A，两次切换）。


# 降低Draw Call的层级设置核心原则
UI 层级（Hierarchy 中的上下顺序）直接决定渲染顺序，设置时需遵循 **“相同材质 / 类型的元素连续排列，不同材质 / 类型的元素集中分组”**，具体规则如下：
1. 按 “材质 / 纹理” 分组，连续排列相同材质的元素
将使用同一材质（或同一图集）的 UI 元素放在相邻层级，避免不同材质元素交替穿插。

反例：
```txt
Panel
├─ Image1（材质A）
├─ Text1（材质B）  // 切换材质B，增加Draw Call
├─ Image2（材质A）  // 切换回材质A，再增加Draw Call
└─ Text2（材质B）  // 切换回材质B，再增加Draw Call
→ 共4次Draw Call（A→B→A→B）
```
正例：
```txt
Panel
├─ Image1（材质A）  // 同一材质连续渲染
├─ Image2（材质A）  // 合并为1次Draw Call（材质A）
├─ Text1（材质B）   // 切换到材质B，1次Draw Call
└─ Text2（材质B）   // 合并为1次Draw Call（材质B）
→ 共2次Draw Call（A→B）
```



2. 按 “渲染层级” 从底到顶排列，避免 “底层元素遮挡顶层元素” 导致的批次拆分
UI 的渲染顺序是 “先渲染 Hierarchy 上层的元素，后渲染下层的元素”（后渲染的会覆盖先渲染的）。如果**底层元素被顶层元素完全遮挡**，Unity 会优化掉底层元素的渲染（减少 Draw Call）；但如果是 “部分遮挡”，则两者都需要渲染，且可能无法合并批次。

设置原则：
- 背景、底板等 “底层静态元素” 放在 Hierarchy 上层（先渲染）。
- 按钮、图标等 “中层交互元素” 放在中间。
- 文字、提示框等 “顶层元素” 放在 Hierarchy 下层（后渲染）。
这样可以最大化利用 “遮挡剔除”，减少无效渲染。


3. 避免 “动态元素” 穿插在静态元素中间
动态元素（如频繁更新的文本`Text`、动画`Animator`控制的图片）会打断 Unity 的批次合并 —— 即使和静态元素材质相同，只要中间有动态元素，前后的静态元素也无法合并。

设置原则：
- 将所有动态元素集中放在一个独立分组（如`Dynamic_Group`），放在 Hierarchy 的最下层（最后渲染）。
- 静态元素（如背景、图标）集中放在上层，确保连续渲染。


# 为什么 “文字通常放在最高层”？

文字（`Text`组件）是 UI 中最特殊的元素之一，其渲染特性决定了它通常需要放在层级最上层（Hierarchy 最下层，最后渲染）：

文字的材质与图片不同，无法和图片合并批次
- 图片（`Image`）通常使用`Sprite`材质，依赖图集（`Sprite Atlas`）中的纹理。
- 文字（`Text`）使用的是**字体材质**（`Font Material`），纹理是字体的图集（每个字符对应一个字形）。

```txt
Panel
├─ 静态图片组（材质A）  // 所有图片连续，合并为1次Draw Call
│  ├─ Image1
│  ├─ Image2
│  └─ Image3
└─ 文字组（材质B）     // 所有文字连续，合并为1次Draw Call
   ├─ Text1
   ├─ Text2
   └─ Text3
→ 共2次Draw Call（A→B）
```

文字（如按钮文字、提示文本）通常需要清晰可见，不能被图片遮挡。放在最高层（最后渲染）能自然覆盖其他元素，无需额外设置`Sorting Order`，同时符合渲染逻辑。


# 结合图集和 Canvas 分组进一步降 Draw Call

1. 用 “Sprite Atlas” 合并图片纹理
将所有静态图片（如按钮、图标、背景）放入同一个`Sprite Atlas`（图集），Unity 会自动为它们分配**相同的材质**。配合层级中连续排列，可将所有图片合并为 1 次 Draw Call。
注意：
- 动态图片（如频繁切换的技能图标）建议单独放一个图集，避免影响静态图片的批次合并。
- 图集尺寸不宜过大（建议不超过 2048x2048），否则可能导致内存浪费。

2. 合理使用 “Canvas Group”，但避免过度拆分 Canvas
- `Canvas Group`可统一控制子元素的透明度、交互性，但**每个 Canvas Group 会强制打断批次合并**（即使材质相同）。
- 原则：同一批次的元素应放在同一个`Canvas Group`下，不同批次的元素（如图片组和文字组）可分拆为不同`Canvas Group`，但总数不宜过多（否则 Canvas 切换也会增加开销）。

1. 减少 “材质变体”，统一 UI 风格
- 避免为相同图片使用不同材质（如轻微调整颜色就新建材质），可通过`Image`的`Color`属性调整颜色，而非新建材质。
- 文字尽量使用同一种字体（不同字体会生成不同材质），如需多种字体，将同字体的文字集中排列。

# 总结
1. **按材质分组**：将图片（同图集）、文字（同字体）、动态元素分别集中，放在相邻层级。
2. **按渲染顺序排列**：背景（最上层，先渲染）→ 静态图片 → 交互元素 → 文字（最下层，最后渲染）。
3. **隔离动态元素**：动态 UI 单独分组，放在最后渲染，避免打断静态元素的批次合并。
