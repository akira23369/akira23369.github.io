## 小结

第6章「控件类」全部学完了。这一章是整个 WPF 学习路线上的一个里程碑——在此之前，你学的是“怎么把东西摆对地方”（布局）、“数据怎么存、怎么变”（依赖项属性）、“事情发生了怎么通知”（路由事件）。这些都是底层基础和骨架。而从这一章开始，你真正进入了“用户能看到能摸到的”层面——**控件**。

按钮、文本框、下拉框、列表、滑动条、进度条、日期选择器……这些你每天都在用的标准界面零件，现在你不仅会用，还知道它们背后的共同设计模式、继承关系和运作原理。下面把整章的内容从全局视角串一遍，帮你把几十个小知识点焊成一张清晰的大网。

---

## 一、所有控件的通用特性（6.1 节）

任何一个 WPF 控件，不管它是按钮还是列表还是日期选择器，都从 `Control` 基类那里继承了一套通用的外观属性。这些属性是控件的“皮肤”，让你不必深入模板就能调整控件的外观：

**背景和前景画刷**：`Background` 和 `Foreground` 的类型是 `Brush`，不是简单的颜色。这意味着你可以设纯色（`SolidColorBrush`）、渐变（`LinearGradientBrush`、`RadialGradientBrush`）、图片（`ImageBrush`）、甚至另一个控件的视觉效果（`VisualBrush`）。这是 WPF 表现力远超传统 UI 框架的重要原因之一。XAML 里直接写颜色字符串（如 `"Red"`）靠的是类型转换器自动翻译成画刷对象。

**字体**：`FontFamily`、`FontSize`、`FontWeight`、`FontStyle`、`FontStretch` 这一套属性控制文字外观。它们都是依赖项属性，并且设置了 `Inherits = true`——你在窗口或容器上设一次字体，里面的所有控件自动继承，除非显式覆盖。这是统一界面字体风格的基石。

**鼠标光标**：`Cursor` 属性定义鼠标悬停时的光标样式。WPF 内置了几十种标准光标（`Cursors.Hand` 手型、`Cursors.IBeam` I型、`Cursors.Wait` 等待、`Cursors.No` 禁止等）。光标不通过依赖项属性继承，但会沿视觉树向上查找未设值的元素。`Mouse.OverrideCursor` 可以强行全局覆盖所有光标（常用于长时间操作时的忙等待指示）。

这三个通用外观维度，加上所有控件都继承的布局属性（`Width`、`Height`、`Margin`、`HorizontalAlignment` 等），构成了 WPF 控件的“通用基因”。

## 二、内容控件：WPF 内容模型的基石（6.2 节）

这一章最核心的设计理念，当之无愧是 **`ContentControl`（内容控件）**。它回答了 WPF 一个根本性的设计问题：“控件里装什么？”

**Content 是 object**：`ContentControl.Content` 属性的类型是 `object`，不是 `string`。这意味着一个按钮的“内容”可以是纯文字，可以是一张图片，可以是一个 `StackPanel` 里面套着图标+文字+别的什么，甚至可以是一个 `MediaElement` 播放视频。控件的**行为**（按钮的点击、标签的访问键）和控件的**外观**（里面显示什么）彻底解耦了。

**内容驱动的布局**：内容控件不写死尺寸。它的期望尺寸由 `Content` 里的元素需要多大空间来决定，加上 `Padding` 和边框。这完全符合 WPF 布局原则——“让内容决定大小，让父容器决定位置”。

**组合优于继承**：传统 UI 框架要做“带图标的按钮”，得写一个 `ImageButton` 子类；要做“带图标的菜单项”，又得写一个 `ImageMenuItem`。WPF 完全不需要——直接往 `Content` 里塞一个 `StackPanel` + `Image` + `TextBlock`，三行 XAML 搞定所有。复用性来自组合，不来自继承。

**内容对齐**：`HorizontalContentAlignment` 和 `VerticalContentAlignment` 控制内容在控件内部的摆放（靠左、居中、靠右、拉伸）。注意和 `HorizontalAlignment` / `VerticalAlignment`（控件在父容器里的对齐）区分——前者对内，后者对外。

**具体的内容控件**：
- `Label`：标签，有独特的访问键功能（下划线标记 + `Target` 属性），让用户按 Alt+快捷键 直接聚焦到关联输入框。
- `Button` 系列：`ButtonBase`（通用按钮行为）→ `Button`（标准按钮）、`ToggleButton`（开关按钮，`IsChecked`）、`CheckBox`（复选框，支持三态）、`RadioButton`（单选按钮，`GroupName` 互斥）、`RepeatButton`（长按连续触发，是 `ScrollBar` 的底层实现）。核心属性：`Click` 事件、`ClickMode`（Press/Release/Hover）、`Command`（为 MVVM 命令铺路）。
- `ToolTip`：工具提示，也是内容控件。可以显示简单的文字，也可以显示带标题、图片、布局面板的复杂提示卡片。`ToolTipService` 附加属性控制延迟和显示时长。

## 三、特殊容器：解决“内容太多怎么装”（6.3 节）

这些控件也都是 `ContentControl`，但它们的独特价值在于**提供空间管理服务**，而不是交互行为。

**ScrollViewer**：内容超出可用空间时自动出现滚动条。核心属性：`HorizontalScrollBarVisibility` / `VerticalScrollBarVisibility`（Auto/Visible/Hidden/Disabled）、`CanContentScroll`（像素滚动 vs 逻辑单元滚动）。提供 `ScrollToXxx` 方法程序化滚动，`ScrollChanged` 事件用于无限滚动加载。`ScrollViewer` + `TextBlock` 是长文本查看的经典组合。

**GroupBox**：带标题的视觉分组框。`Header` 属性（`object` 类型）支持复杂标题布局（图标+文字等）。内容区只能包一个元素（通常用面板套多个），常用在设置面板中将相关选项圈在一起。

**TabItem** + `TabControl`：选项卡控件。每个 `TabItem` 有 `Header`（标签头）和内容。用户点击标签头切换显示内容。`TabStripPlacement` 控制标签条位置（Top/Bottom/Left/Right）。`IsSelected` 程序化切换选项卡。

**Expander**：可折叠/展开的内容容器。点击标题头切换内容的显隐。`IsExpanded` 控制展开状态，`ExpandDirection` 控制展开方向。`Expanded`/`Collapsed` 事件支持延迟加载。多个 `Expander` 垂直堆叠可实现手风琴效果。

## 四、文本控件：显示和编辑文字（6.4 节）

文字是用户界面最基础的载体。WPF 为不同的文本处理需求提供了分工明确的几个控件：

**TextBlock**：轻量级只读文本显示。支持多行、自动换行（`TextWrapping`）、文字截断加省略号（`TextTrimming`）、内联样式（`Run`、`Bold`、`Italic` 等）。性能好，适用于大量只读文字。

**TextBox**：文本输入框，这是表单里使用频率最高的控件。默认单行，通过 `AcceptsReturn="True"` 开启多行。`TextWrapping="Wrap"` 自动折行。`IsReadOnly` 做只读显示（用户可以选择复制），和 `IsEnabled="False"`（完全禁用不可操作）不同。选择文本方面：`SelectionStart`、`SelectionLength`、`SelectedText` 获取和操作选中内容。`SpellCheck.IsEnabled="True"` 开启内置英语拼写检查（右键给出建议，支持自定义词典）。`MinLines`/`MaxLines` 控制可视行数范围。

**RichTextBox**：富文本编辑器。内容存储在 `FlowDocument` 对象中，支持不同字体、颜色、大小混排、嵌入图片和控件。选择模型和 `TextBox` 一致。需要富文本编辑能力时才上它。

**PasswordBox**：专用密码输入框。输入显示为掩码字符（默认圆点，可通过 `PasswordChar` 自定义）。`Password` 属性是**普通 CLR 属性**（不是依赖项属性），这是安全设计——防止密码通过数据绑定被无意泄露。推荐使用 `SecurePassword`（`SecureString` 类型）安全处理密码。`PasswordChanged` 事件响应密码变化。`MaxLength` 限制长度。

---

## 五、列表控件：管理“一堆东西”（6.5 节）

当数据不是一个而是一堆时，就该列表控件上场了。所有列表控件的基类是 **`ItemsControl`**，它提供了管理条目集合的通用能力。

**条目来源**：`Items`（手动添加子元素）和 `ItemsSource`（数据绑定自动生成条目），两者互斥。

**条目外观**：`ItemTemplate`（`DataTemplate`）定义每个条目怎么把数据渲染成 UI。`DisplayMemberPath` 是快速单属性显示的便捷方式。

**条目排列**：`ItemsPanel`（`ItemsPanelTemplate`）定义条目用什么面板排列——默认垂直 `StackPanel`，可以换成水平或换行 `WrapPanel`。

**ListBox**：在 `ItemsControl` 基础上增加了**选择**能力（继承自 `Selector`）。`SelectionMode`：`Single`（单选）、`Multiple`（简单多选）、`Extended`（扩展多选，Ctrl/Shift）。`SelectedItem` / `SelectedIndex`（单选）、`SelectedItems`（多选）。`SelectedValuePath` + `SelectedValue`：快速提取选中项的某个属性值，MVVM 友好。`SelectionChanged` 事件通知选中变化。内置 UI 虚拟化（`VirtualizingStackPanel`），大列表性能有保障。

**ComboBox**：下拉框，本质是按钮 + 弹出 `ListBox`。继承关系同 `ListBox`（`Selector` → `ItemsControl`），所以选择机制完全一样。`IsEditable="True"` 开启可编辑模式，用户可手动输入文本（`Text` 属性）。`IsDropDownOpen` 控制下拉框开闭，`MaxDropDownHeight` 限制下拉框最大高度。

## 六、基于范围的控件：表达数值进度（6.6 节）

`Slider` 和 `ProgressBar` 共享 `RangeBase` 基类，核心数据模型是 `Minimum`、`Maximum`、`Value` 三元组。

**RangeBase**：定义 `Minimum`（默认 0）、`Maximum`（默认 10）、`Value`（夹在中间，有强制回调保证不越界）、`SmallChange`/`LargeChange`（键盘和点击调节步长）。`ValueChanged` 事件。

**Slider**：用户可拖动滑块改变值。`Orientation`（水平/垂直）。刻度系统：`TickFrequency`（等距刻度）、`Ticks`（自定义位置）、`TickPlacement`（位置）、`IsSnapToTickEnabled`（吸附刻度）。`IsDirectionReversed`（反向轨道）、`IsMoveToPointEnabled`（点哪跳哪）。常用于音量、亮度、缩放等需要连续值调节的场景。

**ProgressBar**：纯展示进度，不给用户拖。确定模式通过更新 `Value` 展示百分比。不确定模式（`IsIndeterminate="True"`）显示循环滚动光带动画，表示“正在忙但未知时长”。常配合后台任务和 `IProgress<T>` 接口使用。

## 七、日期控件：选择日期和时间（6.7 节）

日期输入是业务应用的刚需，WPF 提供了两个互补的日期控件：

**DatePicker**：紧凑型日期输入控件，外观是文本框 + 日历按钮。点击后弹出完整月历供选择。`SelectedDate`（`DateTime?`）存储选中日期，支持数据双向绑定。`DisplayDate` 控制弹窗日历初始月份。`IsEditable` 允许手动输入日期文本。`BlackoutDates` 集合定义不可选日期。常用于表单中的日期字段。

**Calendar**：完整展开的月历面板，直接嵌在界面上。`SelectionMode` 支持单选、单范围、多范围、只读。`SelectedDate`（单选）、`SelectedDates`（多选/范围）。`DisplayMode` 支持月/年/十年三级浏览。`FirstDayOfWeek` 自定义周起始日。`BlackoutDates` 同样可用。常用于日程管理、航班查询等需要常年可见日历的场景。

## 八、控件家族继承认知图

理解 WPF 控件的继承层次，你就不会把它们看成孤立的零件，而是一棵有组织的树：

```
FrameworkElement（布局、依赖项属性、路由事件、光标）
 └─ Control（背景/前景/字体/边框）
     ├─ ContentControl（单内容容器）
     │   ├─ Label
     │   ├─ ButtonBase → Button / ToggleButton → CheckBox / RadioButton
     │   ├─ RepeatButton
     │   ├─ ToolTip
     │   ├─ ScrollViewer
     │   ├─ GroupBox
     │   ├─ TabItem
     │   ├─ Expander
     │   └─ Window（继承自 ContentControl）
     ├─ ItemsControl（多条目容器）
     │   └─ Selector（带选择能力）
     │       ├─ ListBox
     │       ├─ ComboBox
     │       └─ TabControl
     ├─ RangeBase（范围值模型）
     │   ├─ Slider
     │   └─ ProgressBar
     ├─ TextBoxBase（文本编辑基础）
     │   ├─ TextBox
     │   └─ RichTextBox
     ├─ DatePicker
     └─ Calendar
```

这个树不是背的，是理解出来的。每一层添加了什么能力，前面章节都有解释：`FrameworkElement` 给了布局和生命周期，`Control` 给了外观皮肤，`ContentControl` 给了“装一个东西”的能力，`ItemsControl` 给了“装一堆东西”的能力，`Selector` 在条目基础上加了选择，`RangeBase` 定义了范围值模型……往下每个具体控件，只是在这层层积累的能力上加上自己独特的行为和外观。

## 九、回头看：控件体系的设计哲学

学完这一整章，你应该能感受到 WPF 控件设计的几条主线：

**1. 内容与行为分离。** 按钮的可点击行为和按钮里显示的东西完全解耦。这让你可以极其自由地定制控件外观，而不必修改控件的行为代码。

**2. 组合优于继承。** 复杂的视觉效果通过嵌套内容控件和布局面板来实现，而不是通过写无穷无尽的子类。`Button.Content = StackPanel { Image + TextBlock }` 就是一个带图标的按钮。

**3. 申明优于编码。** 绝大多数控件的属性、行为、数据源都可以在 XAML 里申明式地表达，配合数据绑定、样式和模板，可以写出几乎没有代码隐藏的干净界面。

**4. 统一的基类体系。** 所有控件共享一套通用属性（布局、字体、颜色、光标），继承链清晰明确。掌握了一个内容控件的用法，所有内容控件都顺着模式走；掌握了列表控件的 `ItemsSource` + `ItemTemplate` + `Selector`，所有列表类控件一通百通。

**5. 处处可绑定、可样式化、可模板化。** 控件的核心属性基本都是依赖项属性，这意味着你可以用数据绑定驱动它们的值，用样式统一设置它们的外观，用模板完全重绘它们的视觉树。这三把武器会在后面的章节（数据绑定、样式、模板）中一一亮相。

## 十、往前看

第 6 章是“认识零件”。你现在已经完全熟悉了 WPF 提供给你的各种开箱即用的界面零件——按钮怎么用、文本框怎么设、列表怎么绑数据、滑动条怎么响应拖动、日期怎么选。但会用零件只是第一步，真正让应用活起来的是让这些零件“互相配合、协同工作”。

接下来的章节会逐步展开：

- **第 7 章 Application 类**：了解 WPF 应用程序的全局生命周期、启动参数、全局异常处理。
- **第 8 章 元素绑定**：一个控件的属性和另一个控件的属性直接关联，不需要写事件。
- **第 9 章 命令**：把“用户做了什么操作”抽象成可复用、可绑定的命令对象，告别到处都是 Click 事件的代码隐藏。
- **第 10 章 资源**：把颜色、画刷、样式、模板等可复用对象统一管理，一处定义、多处引用。
- **第 11 章 样式和行为**：统一设置多个同类控件的外观，实现主题和皮肤。

现在你的工具箱里已经装满了各种控件，接下来就是学怎么指挥它们协同作战了。回顾第 6 章，你能说出每个控件的核心属性、典型用途、以及它在继承树上的位置，那你为后面打下的地基就非常牢固了。
