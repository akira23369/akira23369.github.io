## 内容控件

上一节讲了所有控件都有的通用外观属性——背景、前景、字体、光标。这些是控件的“皮肤”。从这一节开始，咱们要深入控件的“内脏”，看看 WPF 控件是怎么组织和管理它们内部显示的东西的。

在 WPF 的控件体系里，有一类最基础、也最重要的控件叫**内容控件（Content Control）**。什么叫内容控件？一句话：**这个控件可以往里塞一个东西。** 这个东西可以是简单的文字，也可以是一个复杂的布局面板，甚至可以是另一个控件。按钮是最典型的内容控件——一个按钮里你可以放文字，也可以放图片，还可以放文字+图片的组合。

这种“一个控件只包一个子对象”的设计看起来简单，但它是 WPF 整个内容模型的核心。理解了内容控件的运作方式，你就能理解为什么 WPF 的界面可以像乐高积木一样自由嵌套组合。

`ContentControl` 是所有内容控件的基类，它继承自 `Control`，并增加了处理“内容”的能力。所有具备“往里塞东西”能力的控件——`Button`、`Label`、`ToolTip`、`ScrollViewer`、`GroupBox`、`Window` 等等——都直接或间接继承自 `ContentControl`。

这一节 6.2 就把内容控件的核心机制讲透：`Content` 属性到底怎么用（6.2.1）、内容怎么对齐（6.2.2）、WPF 内容模型的几条黄金原则（6.2.3），然后挑出三个最常用的具体内容控件——标签（6.2.4）、按钮（6.2.5）和工具提示（6.2.6）——详细拆解。

### Content 属性

`ContentControl` 有个最重要的属性叫 **`Content`**。它的类型是 **`object`**。对，你没看错，是 `object`，不是 `string`。

这一点是整个 WPF 内容模型最核心的设计。在传统的 Windows 界面库里，一个按钮上能显示什么？基本就是文字。要放图片？得用专门的图片按钮控件。要在按钮里同时放文字和图片？要么自绘，要么找第三方控件。但在 WPF 里，`Content` 是 `object` 类型，这意味着你往里面塞什么都可以——字符串、数字、日期、`Image` 控件、`StackPanel` 面板、甚至一个 `MediaElement` 放视频都可以。

#### 塞简单文字

最常见的用法——往 `Content` 里塞字符串。因为 `Content` 是 `object` 类型，字符串是 `object` 的子类，而且在 XAML 里可以直接写：

```xml
<Button Content="点击我" />
```

这是你一直用的写法。背后的类型转换器会自动把字符串 `"点击我"` 包装成 `Content` 属性的值。在内部，WPF 检测到 `Content` 是字符串时，会用一个 `TextBlock` 来显示它。也就是说，下面两种写法是等价的：

```xml
<Button Content="点击我" />
```

和：

```xml
<Button>
    <TextBlock Text="点击我" />
</Button>
```

第一种写法性能更高一点（WPF 内部会缓存在多个按钮间共享同一个隐式 `TextBlock` 的样式），但两种效果完全一样。

#### 塞任意控件

因为 `Content` 是 `object`，你完全可以在按钮里放一张图片：

```xml
<Button>
    <Image Source="icon.png" Width="32" Height="32" />
</Button>
```

或者放一个复杂的组合布局——一个水平 `StackPanel`，里面包含一个图标和一段文字：

```xml
<Button Margin="5">
    <StackPanel Orientation="Horizontal">
        <Image Source="save.png" Width="16" Height="16" Margin="0,0,5,0" />
        <TextBlock Text="保存" VerticalAlignment="Center" />
    </StackPanel>
</Button>
```

这个按钮的外观就变成了图标+文字的组合，而且行为和普通按钮完全一样——能点击、有悬停效果、能触发 `Click` 事件。这就是 WPF 内容模型的威力：**按钮的行为和外观完全解耦了。** 按钮的行为（点击处理、焦点、键盘响应）由 `Button` 类负责，按钮的外观（里面显示什么）由你塞进去的 `Content` 决定。

#### 内容控件的“单子对象”限制

`ContentControl` 只能包**一个**子对象。这是它和布局面板（如 `StackPanel`、`Grid`）最根本的区别——面板的 `Children` 是集合，可以放多个子元素；内容控件的 `Content` 是单个属性，只能放一个东西。

但这不意味着内容控件只能显示一个东西。因为它可以放一个 `StackPanel`，而 `StackPanel` 可以放很多子元素。所以“只能包一个子对象”其实是一个可以轻易绕过的限制——只需要在 `Content` 里塞一个面板，然后面板里想放多少放多少。

#### Content 在代码中的操作

因为 `Content` 的类型是 `object`，你在代码里可以非常灵活地操作它：

```csharp
// 设文字
myButton.Content = "确定";

// 设数字
myButton.Content = 42;

// 设图片
myButton.Content = new BitmapImage(new Uri("icon.png", UriKind.Relative));

// 设一个复杂的控件组合
myButton.Content = new StackPanel
{
    Orientation = Orientation.Horizontal,
    Children = {
        new Image { Source = new BitmapImage(new Uri("icon.png", UriKind.Relative)), Width = 16, Height = 16 },
        new TextBlock { Text = "保存", VerticalAlignment = VerticalAlignment.Center }
    }
};
```

获取 `Content` 也类似，但要注意类型转换：

```csharp
// 假设你之前塞了一个字符串
string text = myButton.Content as string;
if (text != null) { /* 是字符串 */ }

// 或者直接强转
string text = (string)myButton.Content;
```

如果你不确定 `Content` 里是什么类型，用 `as` 或者 `is` 检查一下再取。

#### 有 Content 也有其他属性的控件注意

`ContentControl` 除了 `Content` 属性，本身还继承自 `Control` 的所有外观属性（`Background`、`Foreground`、`FontSize` 等）。需要注意的是，`Content` 里的元素受这些属性影响的方式：

- 如果是字符串，WPF 会用内部隐式 `TextBlock` 渲染，这个 `TextBlock` 会自动继承 `ContentControl` 的字体和前景色属性。
- 如果你自己放了显式的 `TextBlock` 在 `Content` 里，并且没有设它的 `Foreground` 和 `FontSize`，它会从父级（即 `ContentControl`）自动继承。否则会使用你自己的设置覆盖。

所以你可以灵活地在按钮外层统一设字体颜色，内部元素默认继承；或者内部覆盖为自己的颜色。

### 对齐内容

一个内容控件从外到内有三层空间：

1. **控件本身占用的总空间**：由父容器布局决定。
2. **控件的“内容区”**：控件内部扣除 `Padding` 和 `BorderThickness` 后剩余的区域。
3. **内容自己需要的尺寸**：由 `Content` 里面的元素根据自身内容决定。

当内容区比内容自身需要的尺寸大时（父容器给了控件更多空间），内容在内容区里的摆放位置就需要被控制。这就是 `HorizontalContentAlignment` 和 `VerticalContentAlignment` 两个属性的作用。

#### HorizontalContentAlignment 和 VerticalContentAlignment

```xml
<Button Content="居中" 
        HorizontalContentAlignment="Center" 
        VerticalContentAlignment="Center"
        Width="200" Height="80" />
```

这个按钮占地 200×80，但文字只需要 50×20 左右。设了 `HorizontalContentAlignment="Center"` 和 `VerticalContentAlignment="Center"`，文字就会在按钮的正中央显示。

四个常用值（和 `HorizontalAlignment` 一样）：

- `Left` / `Top`：靠左/靠上。
- `Center`：居中。
- `Right` / `Bottom`：靠右/靠下。
- `Stretch`：拉伸填满。对于文字来说，水平拉伸通常只影响 `TextBlock` 的宽度而不会拉宽文字本身；垂直拉伸可能看不出效果（文字高度仍然由字号决定）。

默认值是什么？不同的控件可能有不同的默认值。`Button` 默认是 `Center, Center`（文字居中）。`Label` 默认是 `Left, Top`。你可以用这些属性覆盖默认行为。

#### ContentAlignment vs Alignment

初学者很容易把这两对属性搞混：

- **`HorizontalAlignment` / `VerticalAlignment`**：定义控件在**它的父容器**里的对齐方式。比如一个按钮在 `StackPanel` 里是靠左还是靠右。
- **`HorizontalContentAlignment` / `VerticalContentAlignment`**：定义控件的**内容**在控件内部的对齐方式。比如按钮里的文字在按钮框里是靠左还是居中。

一个具体的例子：

```xml
<StackPanel Width="300" Height="200">
    <Button Content="角落" 
            HorizontalAlignment="Right" 
            VerticalAlignment="Bottom"
            HorizontalContentAlignment="Left" 
            VerticalContentAlignment="Top"
            Width="100" Height="60" />
</StackPanel>
```

- `HorizontalAlignment="Right"`：按钮作为 `StackPanel` 的子元素，靠右放。
- `VerticalAlignment="Bottom"`：按钮靠下放。
- `HorizontalContentAlignment="Left"`：按钮内部的文字靠左。
- `VerticalContentAlignment="Top"`：文字靠上。

最终效果：按钮贴在 StackPanel 的右下角，按钮内的文字贴在按钮框的左上角。

#### Padding 的作用

`Padding` 是内容控件另一个重要的属性。它定义内容区离控件边框内边缘的距离，相当于往里缩进。`Padding` 会吃掉内容区的一部分空间，所以会影响 `ContentAlignment` 的实际表现。

```xml
<Button Content="内边距" Padding="20,10" 
        HorizontalContentAlignment="Center"
        Width="200" Height="60" />
```

文字仍然居中，但因为 `Padding` 在左右各留了 20、上下各留了 10，文字离按钮边缘有了呼吸空间。

### WPF 内容原则

这一小节不是讲代码，而是讲设计哲学。理解了 WPF 的内容模型原则，你才能从“照猫画虎”的层次上升到“为什么这么设计”的层次。

WPF 的内容模型有几条核心原则，它们贯穿了整个控件体系：

#### 原则一：内容驱动尺寸

控件的尺寸应该由它的内容来决定，而不应该被写死。这和第 3 章布局原则第一条完全一致。一个按钮如果里面的文字变长了（比如切换语言），按钮应该自动变宽，而不是截断文字。一个按钮如果里面放了更大尺寸的图标，按钮应该自动变高。

这种行为在 `ContentControl` 上是默认的——如果你不设 `Width` 和 `Height`，内容控件在测量阶段会去问 `Content` 里面的元素需要多大空间，然后自己加上 `Padding` 和 `BorderThickness`，把这个总尺寸作为自己的期望尺寸汇报给父容器。

所以写 WPF 界面的最佳实践是：**除非有明确的固定尺寸需求（如小图标、分隔线），否则永远不要设控件的 `Width` 和 `Height`。** 让内容和布局系统决定一切。

#### 原则二：内容与行为分离

前面按钮的例子已经体现了这一点：`Button` 提供了“可点击”的行为（点击事件、焦点响应、键盘快捷键、视觉状态变化），而按钮**里面显示什么**完全由 `Content` 决定。你可以让一个按钮看起来像一个图标、一个文字链接、甚至一个视频缩略图，但它的点击行为始终如一。

这种分离让你可以大规模复用控件的行为逻辑，而不被外观绑定。这也是 WPF 里**控件模板（ControlTemplate）** 的基础——模板更进一步，连控件的整个视觉树都可以替换，而行为保持不变。后面第 17 章会深入讲模板，但根在这里。

#### 原则三：组合优于继承

在传统的面向对象 UI 框架里，如果你想做一个“带图标的按钮”，你可能需要写一个 `ImageButton` 类，继承自 `Button`，然后在子类里添加一个 `ImageSource` 属性。如果你想做一个“带图标的菜单项”，又要再写一个 `ImageMenuItem`。属性组合爆炸，最终类的数量失控。

WPF 走了完全不同的路：**不要为每一种视觉组合写一个新的类。** 直接利用内容控件的能力，往 `Content` 里塞一个 `StackPanel` + `Image` + `TextBlock`，三行 XAML 就搞定了“带图标的按钮”、“带图标的菜单项”、“带图标的标签”。不需要一行新 C# 代码，不需要定义任何新类。

这正是 WPF 被称为“组合式 UI 框架”的原因——它的控件不是一棵棵孤立的树，而是可以互相嵌套的乐高积木。

#### 原则四：控件树是真正的数据驱动和样式驱动的基础

内容控件的嵌套能力让整个 UI 成了一棵任意的、深度嵌套的控件树。而路由事件沿着树传播，依赖项属性可以在树上继承，数据绑定可以在树上任何位置被解析，样式和资源可以在树上任何层级被应用。所有 WPF 的高级特性，都是在内容模型定义的这棵“内容树”上展开的。

理解了这个原则，你就会明白为什么后面学模板（`DataTemplate`、`ControlTemplate`）时，那些机制看起来像是魔法——因为模板只是用一种更正式、更可复用的方式，来定义“怎么把一个数据对象映射成一棵控件树”。

#### 原则五：轻量与重量内容的取舍

内容控件让你可以往里面塞任何东西，但这不意味着你应该无脑往里塞重量级内容。比如，你做了一个列表控件，里面有成百上千个列表项。每个列表项如果是一个很复杂的 `UserControl`，里面有十几种嵌套控件和绑定时，性能就会受影响。WPF 提供了虚拟化（Virtualization）机制来优化这种情况，但理解“内容控件的灵活性是有成本的”这一点很重要——简单的文本内容开销极低，复杂的面板嵌套开销更高。在日常开发中，大多数场景下这个开销可以忽略不计，但大规模列表时需要留意。

### 标签

`Label` 是 WPF 里最简单的内容控件之一——它就是用来显示一段文字（或任意内容），但它有一个其他文本控件不具备的特殊能力：**支持访问键（Access Key）**。

#### Label 的基本用法

```xml
<Label Content="用户名：" />
<Label Content="密码：" />
```

和 `TextBlock` 类似，`Label` 默认把内容渲染为文本（如果 `Content` 是字符串的话）。但和 `TextBlock` 不同的是，`Label` 是一个 `ContentControl`，所以它支持前面讲的 `HorizontalContentAlignment`、`VerticalContentAlignment`、`Padding` 等所有内容控件属性。而 `TextBlock` 不是内容控件，它是 `FrameworkElement` 的直接子类，专门为文本渲染优化。

**什么时候用 Label，什么时候用 TextBlock？**

- **需要访问键（见下文）时**，必须用 `Label`。
- **需要显示大量或多行文本**时，用 `TextBlock`（它支持 `TextWrapping`、`TextTrimming` 等高级文本功能，且性能更好）。
- **有些场景下只是简单的一句话**，两者都可以，差别不大。但在表单里一般用 `Label` 配合输入框，因为它能和输入框关联。

#### 访问键（Access Key）

`Label` 的一个独特功能是支持**访问键**——带有下划线标记的快捷键。当你在 `Content` 文字里写一个下划线，紧跟着的那个字符就会成为访问键，用户按 `Alt + 那个字符` 就能快速聚焦到和这个 `Label` 关联的控件上。

```xml
<Label Content="用_户名：" Target="{Binding ElementName=txtUserName}" />
<TextBox x:Name="txtUserName" />
```

界面显示时，“户”字前面会有一个下划线（或者按 Alt 键才显示下划线，取决于系统设置）。用户按 `Alt+U`（U 是“用户”中下划线后面的字符，“用”的拼音首字母），键盘焦点就会跳到 `txtUserName` 文本框里。

这个功能对提高表单的可访问性和键盘操作效率非常有帮助——用户不用鼠标，只用键盘就能在表单字段之间快速切换。

访问键的实现依靠 `Label.Target` 属性，它把一个 `Label` 绑定到另一个控件（通常是输入控件）上。当用户按下 `Alt+快捷键` 时，`Label` 会调用 `target.Focus()`。

#### Label 的其他特性

`Label` 的内容可以是任何对象（因为它是 `ContentControl`），所以你可以往 `Label` 里塞图片、面板等，但说实话很少有人这么做——`Label` 的定位就是短文本标签，复杂内容放标签里不太符合直觉。

`Label` 也完整支持字体、前景/背景画刷、光标等所有 `Control` 通用属性。

### 按钮

按钮是每个桌面应用里出现频率最高的控件，没有之一。WPF 的按钮体系非常丰富——最基础的是 `Button`，此外还有 `CheckBox`、`RadioButton`、`RepeatButton`、`ToggleButton` 等。它们都继承自 `ButtonBase`，而 `ButtonBase` 继承自 `ContentControl`。

#### ButtonBase 公共特性

所有按钮都继承自 `ButtonBase`，`ButtonBase` 又继承自 `ContentControl`，所以所有按钮都是内容控件——它们都有一个 `Content` 属性，可以塞任意东西。按钮的通用属性：

- **`IsPressed`**：只读，表示按钮当前是否处于被按下的状态。
- **`IsEnabled`**：按钮是否可用。设为 `false` 后按钮变灰，不响应任何交互。
- **`Click` 事件**：按钮被点击时触发（最常用的事件）。点击可以来自鼠标左键、键盘回车或空格。
- **`ClickMode`**：控制 `Click` 事件什么时候触发。三个值：
  - `ClickMode.Release`（默认）：鼠标左键在按钮上**松开**时触发。这是标准按钮行为。
  - `ClickMode.Press`：鼠标左键在按钮上**按下**的瞬间触发。适合需要即时响应的场景（如游戏里的开火按钮）。
  - `ClickMode.Hover`：鼠标光标**悬浮**在按钮上时就触发。用得很少，适用于某些悬浮自动操作的场景。
- **`Command` 和 `CommandParameter`**：用于命令绑定，这是 WPF 高级模式（MVVM）的核心，后面第 9 章会详细讲。

#### Button 控件

`Button` 是 `ButtonBase` 最直接的子类，没附加什么特殊功能，只是继承。它是 WPF 中最常用的按钮。

```xml
<Button Content="普通按钮" Click="OnButtonClick" />
<Button Content="不可用" IsEnabled="False" />
<Button Content="图片按钮">
    <Image Source="icon.png" Width="32" Height="32" />
</Button>
```

`Button` 也是 `ContentControl`，所以前面讲的所有内容控件的玩法全部适用——往里面塞字符串、图片、面板，都行。

#### ToggleButton（开关按钮）

`ToggleButton` 是 `ButtonBase` 的另一个子类，它是一个可以“保持按下状态”的按钮。点一下变成按下状态，再点一下弹回来。它有一个额外属性：

- **`IsChecked`**：可为 `null` 的 `bool?`。`true` 表示按下状态，`false` 表示弹起状态，`null` 表示不确定状态（仅在 `IsThreeState="True"` 时有效）。

```xml
<ToggleButton Content="开关" IsChecked="False" />
```

`ToggleButton` 有 `Checked`、`Unchecked`、`Indeterminate` 三个事件，分别在三种状态变化时触发。

在实际开发中，你很少直接用裸的 `ToggleButton`，而是用它的两个子类——`CheckBox` 和 `RadioButton`。

#### CheckBox（复选框）

`CheckBox` 直接继承自 `ToggleButton`，外观上显示一个方框和打勾标记。它的所有行为都是继承来的——`IsChecked`、`Checked`/`Unchecked` 事件等。

```xml
<CheckBox Content="同意用户协议" IsChecked="False" />
<CheckBox Content="三态复选框" IsThreeState="True" 
          Checked=、Unchecked=等等 />
```

当 `IsThreeState="True"` 时，用户点击会在 `null`（不确定，显示一个方块）→ `false`（不勾选）→ `true`（勾选）三者之间循环。这常用于“部分选中的树形复选框”（比如安装程序里选择组件时，只选了一个子组件，父级显示为不确定状态）。

#### RadioButton（单选按钮）

`RadioButton` 继承自 `ToggleButton`，和 `CheckBox` 是亲兄弟。区别在于，`RadioButton` 具有**互斥分组**的特性——同一组内的 `RadioButton` 只有一个能被选中。

怎么分组？通过 **`GroupName`** 属性。具有相同 `GroupName` 的 `RadioButton` 会自动互斥。

```xml
<StackPanel>
    <RadioButton Content="男" GroupName="Gender" IsChecked="True" />
    <RadioButton Content="女" GroupName="Gender" />
</StackPanel>
```

如果你没有显式设 `GroupName`，WPF 默认把同一个父容器内的所有 `RadioButton` 自动归为同一组。所以上面的例子即使不写 `GroupName="Gender"`，两个单选框也会互斥（因为它们都在同一个 `StackPanel` 里）。但如果你需要跨容器分组（比如两个不同面板里的选项放在同一组），就必须指定相同的 `GroupName`。

`RadioButton` 也有 `Checked`/`Unchecked` 事件，和最常用的 `IsChecked` 属性。

#### RepeatButton（重复按钮）

`RepeatButton` 是一个很特殊的按钮：当你按住它不放时，它会**连续不断地触发 `Click` 事件**，就像键盘上按住一个键会产生重复输入一样。

```xml
<RepeatButton Content="长按我" Delay="500" Interval="100" />
```

- **`Delay`**：按住后首次触发前的等待时间（毫秒），默认是键盘重复延迟值。
- **`Interval`**：之后两次 `Click` 之间的间隔（毫秒）。

`RepeatButton` 一般不会独立出现在界面上，它是 `ScrollBar` 两端的箭头按钮、`Slider` 两侧的增减按钮、`NumericUpDown` 的加减按钮的底层实现。你在自定义控件模板里会经常见到它。

### 工具提示

工具提示（ToolTip）是当用户把鼠标光标悬停在控件上时，弹出来的那个小黄框，里面写着一两行说明文字。在 WPF 里，工具提示也是内容控件——因为 `ToolTip` 继承自 `ContentControl`。这意味着你往里面塞的不只可以是文字，还可以是图片、布局面板等任何东西。

#### 基本用法

最简单的方式：直接在控件上设置 `ToolTip` 属性（`FrameworkElement.ToolTip`，类型为 `object`）。

```xml
<Button Content="保存" ToolTip="点击保存当前文档" />
```

背后，WPF 会自动把字符串包装成一个 `ToolTip` 对象，然后在鼠标悬停足够时间后自动弹出。

`ToolTip` 弹出的时机由系统设置控制，`ToolTipService` 类提供了几个附加属性来调整：

- **`ToolTipService.InitialShowDelay`**：鼠标悬停后首次显示等待时间（毫秒）。默认大约 400ms。
- **`ToolTipService.ShowDuration`**：弹出后显示多长时间（毫秒）。默认大约 5000ms。
- **`ToolTipService.BetweenShowDelay`**：当从一个控件移到另一个控件时，第二个提示框显示前的等待时间。默认约 100ms。

这些附加属性可以设在单个控件上，也可以设在容器或窗口上影响全局。

```xml
<Button Content="保存" ToolTip="保存文档" 
        ToolTipService.InitialShowDelay="200" 
        ToolTipService.ShowDuration="3000" />
```

#### ToolTip 作为内容控件

因为 `ToolTip` 是 `ContentControl`，你可以往里面放任何东西：

```xml
<Button Content="导出">
    <Button.ToolTip>
        <ToolTip>
            <StackPanel>
                <TextBlock Text="导出数据" FontWeight="Bold" />
                <TextBlock Text="将当前数据导出为 CSV 格式" />
                <Image Source="export_icon.png" Width="32" Height="32" Margin="0,5,0,0" />
            </StackPanel>
        </ToolTip>
    </Button.ToolTip>
</Button>
```

这样鼠标悬停时弹出的就不是一行干巴巴的文字，而是一个带有标题、描述文字和小图标的丰富提示卡片。

你也可以直接往 `ToolTip` 属性里塞一个自定义内容，不需要显式写 `<ToolTip>` 标签——WPF 会自动检测类型，如果不是 `ToolTip` 对象就帮你包一层。不过为了可读性和后续扩展，建议复杂内容时还是显式写 `<ToolTip>` 标签。

#### ToolTip 位置和显示控制

`ToolTip` 有 `Placement` 属性，控制提示框出现在光标或控件的哪一侧：`Mouse`（跟随鼠标位置）、`Top`、`Bottom`、`Left`、`Right`、`Center` 等。

`ToolTip` 的 `IsOpen` 属性可以让你通过代码控制是否显示。`Opened` 和 `Closed` 事件分别在弹出和关闭时触发，可以做动画等高级效果。

`ToolTipService` 还提供 `IsEnabled` 附加属性来禁用某个控件的工具提示：`ToolTipService.IsEnabled="False"`。

#### 工具提示在数据绑定场景中的作用

在列表控件（如 `ListBox`、`DataGrid`）里，工具提示经常被用来显示某一项的详细信息。你可以通过绑定或样式，让鼠标悬停在某一项上时弹出一个卡片，展示该项的所有字段。这是非常常见的数据浏览交互模式。

## 总结

6.2 节是“控件类”这一章里最核心的一节，它定义了 WPF 控件体系中最基础的一个类别——内容控件（`ContentControl`）。

**Content 属性（6.2.1）**：
- `Content` 的类型是 `object`，这意味着你可以往里面塞任意东西——字符串、控件、面板、甚至视频。
- 字符串由内部隐式 `TextBlock` 渲染。
- 内容控件只能包一个子对象，但可以通过在 `Content` 里放面板来绕过这个限制。

**对齐内容（6.2.2）**：
- `HorizontalContentAlignment` / `VerticalContentAlignment` 控制内容在控件内部的对齐。
- 和 `HorizontalAlignment` / `VerticalAlignment`（控件在父容器里的对齐）是两套独立的机制。
- `Padding` 控制内容区向内缩进的距离。

**WPF 内容原则（6.2.3）**：
- 内容驱动尺寸：控件大小由内容决定。
- 内容与行为分离：控件的行为（如按钮的点击）和外观（Content）完全解耦。
- 组合优于继承：不需要为每种视觉组合写新类，直接用内容嵌套解决。
- 控件树是数据绑定和样式系统的基础。
- 轻量与重量内容需要根据场景取舍，大规模列表注意性能。

**标签（6.2.4）**：
- `Label` 是简单的内容控件，主要用于表单中的标签文本。
- 独特的**访问键**功能：`Content` 中下划线后的字符成为快捷键，配合 `Target` 属性可以直接让关联控件获得焦点。

**按钮（6.2.5）**：
- `ButtonBase` 是所有按钮的基类，继承了 `ContentControl`。
- 核心属性：`IsPressed`、`IsEnabled`、`Click` 事件、`ClickMode`（Press/Release/Hover）、`Command`。
- `Button`：最常用的标准按钮。
- `ToggleButton`：保持按下/弹起状态的按钮。`IsChecked` 属性。
- `CheckBox`：复选框，支持三态（`IsThreeState`）。
- `RadioButton`：单选按钮，同一 `GroupName` 内互斥。
- `RepeatButton`：长按连续触发的按钮，用于 `ScrollBar` 等控件内部。

**工具提示（6.2.6）**：
- `ToolTip` 是内容控件，可以用文字或任意复杂内容。
- `ToolTipService` 附加属性控制延迟、显示时长等。
- 支持通过 `Placement` 控制弹出位置。
- 在数据绑定中常用于丰富的数据预览卡片。

内容控件是 WPF 灵活性的来源之一。相比于老框架里控件内容和外观的僵硬绑定，WPF 的 `ContentControl` 把“里面装什么”这件事彻底放开了。接下来 6.3 节要学的是几个特殊容器——`ScrollViewer`、`GroupBox`、`TabItem`、`Expander`——它们本身也是内容控件，但在“装东西”之外还增加了滚动、分组、切换等特殊容器行为。
