# 笔记33《Application类》7.1节——应用程序的生命周期

## 7.1 应用程序的生命周期

前面六章你学了 WPF 的布局、依赖项属性、路由事件、以及各种各样的控件。但是你有没有想过一个问题：**这些东西是怎么“跑起来”的？** 你双击一个 exe，窗口是怎么弹出来的？你点了窗口右上角的叉叉，程序是怎么退出的？如果程序在启动的时候想干点什么事（比如加载配置、检查数据库连接），该在哪儿写代码？

这些问题的答案都指向一个东西——**Application 对象**。

任何一个 WPF 程序，不管它有一个窗口还是一百个窗口，背后都有一个全局的 `Application` 对象在管理着整个程序的生命周期。这个对象是 WPF 应用程序的“大总管”，它负责：

- 启动程序，加载初始界面。
- 管理所有打开的窗口。
- 处理应用程序级别的事件（启动、退出、未捕获异常等）。
- 决定程序什么时候该关闭。
- 提供全局资源（全局样式、皮肤、数据等）。
- 管理命令行参数。

7.1 节的重点就是把这个“大总管”从生到死的过程讲清楚：它怎么被创建（7.1.1）、你可以怎么自定义它（7.1.2）、程序有几种关闭方式（7.1.3）、以及在整个生命周期中会触发哪些关键事件让你可以插入自己的代码（7.1.4）。

---

### 7.1.1 创建 Application 对象

WPF 应用程序的入口点看起来和传统的 Windows 程序不一样——你找遍项目文件也找不到一个显式的 `Main` 方法。但实际上，`Main` 方法还是存在的，只不过被 Visual Studio 自动生成了，藏在了你看不到的编译产物里。

#### 传统的入口方式（显式创建 Application）

在 WPF 的早期（以及一些手动配置的项目里），你会自己写一个 `Main` 方法来创建 `Application` 对象：

```csharp
public class Program
{
    [STAThread]
    public static void Main()
    {
        Application app = new Application();
        MainWindow mainWindow = new MainWindow();
        app.Run(mainWindow);
    }
}
```

这段代码做了三件事：

1. **创建 Application 对象**：这是整个程序的大总管。
2. **创建主窗口**：`MainWindow` 就是你想显示的第一个窗口。
3. **调用 `app.Run(mainWindow)`**：这个方法启动了 WPF 的消息循环（也叫 Dispatcher 循环），并把主窗口显示出来。消息循环是一个死循环，不停地从 Windows 消息队列里取消息（鼠标点击、键盘按下、重绘请求等），然后分发给对应的控件去处理。`Run` 方法会一直阻塞，直到程序关闭后才返回。

`[STAThread]` 属性是 COM 线程模型要求，WPF 的主线程必须是单线程单元（STA），这是 Windows 的历史遗留问题，你照抄就行，不用深究。

#### 现代 WPF 项目的默认方式

你在 Visual Studio 里新建一个 WPF 项目，会发现没有 `Program.cs` 文件，只有 `App.xaml` 和 `App.xaml.cs`。这是怎么一回事？

原因在于，Visual Studio 用了一种更简洁的方式来定义 `Application` 对象——**通过 XAML**。

打开 `App.xaml`，你会看到：

```xml
<Application x:Class="MyApp.App"
             xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
             xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
             StartupUri="MainWindow.xaml">
</Application>
```

这里的关键是 `x:Class="MyApp.App"` 和 `StartupUri="MainWindow.xaml"`。

- `x:Class`：告诉编译器“用这个 XAML 去生成一个叫 `MyApp.App` 的类，它继承自 `Application`”。这个 `App` 类就是你的自定义 Application 对象。
- `StartupUri`：指定启动时自动加载并显示的窗口。编译器在背后生成的 `Main` 方法大致等价于：

```csharp
Application app = new MyApp.App();  // 创建自定义的 Application 对象
app.InitializeComponent();          // 加载 App.xaml 中的资源和设置
app.Run(new MainWindow());          // 创建 StartupUri 指定的窗口并启动消息循环
```

**所以 `App.xaml` 本质上就是用 XAML 来声明 Application 对象的属性和资源，取代了手写 `Main` 方法的需要**。

`App.xaml.cs` 是代码隐藏文件：

```csharp
public partial class App : Application
{
    // 在这里处理应用程序级别的事件和逻辑
}
```

这个 `App` 类就是你的自定义 Application。你可以重写它的方法、订阅它的事件来处理程序的启动、退出、异常等。

#### 两种方式的对比

| 方式 | 优点 | 缺点 |
|------|------|------|
| 手写 Main 方法 | 完全控制启动过程，灵活 | 需要手动管理 StartupUri 等 |
| App.xaml（默认） | 简洁，自动生成 Main，支持 XAML 资源定义 | 灵活性略低（但足以应对绝大多数需求） |

实际上 99% 的情况下你不需要自己去写 `Main` 方法，用 `App.xaml` 就够了。但理解背后的原理很重要——这样你就知道 `App.xaml.cs` 里的 `App` 类其实就对应着那个全局的 `Application` 对象，它从程序启动活到程序退出。

### 7.1.2 派生自定义的 Application 类

上一小节你看到了 `App.xaml` 和 `App.xaml.cs` 共同定义了一个继承自 `Application` 的 `App` 类。这个类就是你的“自定义 Application”。为什么需要自定义？因为你可以在这个类里：

- 处理应用程序级别的事件（启动、退出、异常等）。
- 定义全局资源（如全局样式、画刷、数据模板）。
- 重写虚方法来做更精细的控制。

#### App.xaml 中的全局资源

`App.xaml` 不仅仅能设 `StartupUri`，它最重要的角色之一是**定义全局资源**。你在 `App.xaml` 的 `<Application.Resources>` 里放的东西，整个程序的任何窗口、任何控件都能用。

```xml
<Application x:Class="MyApp.App"
             xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
             xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
             StartupUri="MainWindow.xaml">
    <Application.Resources>
        <!-- 全局画刷 -->
        <SolidColorBrush x:Key="PrimaryBrush" Color="#1E90FF" />
        <!-- 全局样式 -->
        <Style TargetType="Button">
            <Setter Property="Background" Value="{StaticResource PrimaryBrush}" />
            <Setter Property="Foreground" Value="White" />
            <Setter Property="FontSize" Value="14" />
        </Style>
    </Application.Resources>
</Application>
```

这样整个程序所有的按钮都会默认应用这个蓝色背景、白色文字、14 号字的样式，不需要在每一个按钮上重复设置。

#### App.xaml.cs 中的事件处理

`App.xaml.cs` 中，你可以订阅 `Application` 对象的各种事件来响应程序的生命周期：

```csharp
public partial class App : Application
{
    protected override void OnStartup(StartupEventArgs e)
    {
        base.OnStartup(e);
        // 在这里做启动时的初始化工作：加载配置、检查环境、判断是否跳过主窗口等
        if (/* 某些条件 */)
        {
            // 比如命令行参数传了 /silent，就不显示主窗口
            this.ShutdownMode = ShutdownMode.OnExplicitShutdown;
        }
    }

    protected override void OnExit(ExitEventArgs e)
    {
        // 在这里做清理工作：保存设置、关闭文件、释放资源
        base.OnExit(e);
    }
}
```

重写 `OnStartup` 和 `OnExit` 是很常见的模式。当然你也可以用事件订阅来处理，但重写虚方法更简洁高效（少了一次委托分配）。

#### 自定义 Application 类的常见用途

- **集中处理未捕获的异常**（`DispatcherUnhandledException` 事件），弹出友好的错误提示而不是让程序直接崩溃。
- **单实例控制**：在 `OnStartup` 中检测是否已经有另一个实例在运行，如果是，就把命令行参数传给那个实例然后退出当前实例。
- **自定义启动逻辑**：根据命令行参数或系统状态决定加载哪个窗口，或者启动时不显示任何窗口而只是一个系统托盘图标。
- **全局主题管理**：在 `App` 类中提供方法来切换整个应用的皮肤（深色/浅色模式）。

### 7.1.3 应用程序的关闭方式

WPF 程序的关闭不像传统 Win32 程序那么单纯——不是主窗口关了程序就一定退出，也不是所有窗口都关了程序才退出。到底什么时候算“程序该关了”，由 `Application.ShutdownMode` 属性决定。

#### ShutdownMode 的三种模式

`ShutdownMode` 是一个枚举，定义了程序退出的触发条件：

**`ShutdownMode.OnLastWindowClose`（默认）**

这是 WPF 应用程序的默认行为。当程序打开的**最后一个窗口**被关闭时，`Application` 自动调用 `Shutdown` 方法，程序退出。

这意味着如果你的程序有多个窗口，用户关掉主窗口不会导致程序退出，只要还有其他窗口开着，程序就继续运行。只有当所有窗口全部关掉后，程序才退。

```xml
<Application x:Class="MyApp.App" 
             ShutdownMode="OnLastWindowClose"
             StartupUri="MainWindow.xaml">
</Application>
```

注意：这里说的“窗口”指的是通过 `Application.Run` 启动后创建并显示过的 `Window` 对象。如果某个窗口被 `Close()` 掉了但后来又 New 了新窗口并且 Show 了，那新窗口继续维持程序生命。

**`ShutdownMode.OnMainWindowClose`**

当**主窗口**关闭时，程序立刻退出，不管还有没有其他窗口开着。这是很多传统桌面应用的行为——主窗口关了，整个应用就关了。

```xml
<Application ShutdownMode="OnMainWindowClose" />
```

那“主窗口”是哪个？就是 `Application.MainWindow` 属性指向的那个窗口。你可以通过以下方式指定：

- 设置 `Application.StartupUri` 来加载的窗口自动成为主窗口。
- 在调用 `Application.Run(window)` 时传入的窗口自动成为主窗口。
- 手动设置 `Application.MainWindow = myWindow` 来显式指定。

当你关了主窗口，`Application` 会自动关闭所有还在开的其他窗口，然后退出。

**`ShutdownMode.OnExplicitShutdown`**

程序**不会自动关闭**，必须由你显式调用 `Application.Current.Shutdown()` 才退出。这适用于那些不以窗口为主要界面的程序——比如后台服务、系统托盘程序、或者显示窗口的逻辑完全由你自己的代码控制的场景。

```csharp
// 程序不会因为任何窗口关闭而自动退出
this.ShutdownMode = ShutdownMode.OnExplicitShutdown;

// 当真正需要退出时
Application.Current.Shutdown();
```

#### 手动调用 Shutdown

不管 `ShutdownMode` 设成什么，你都可以随时通过 `Application.Current.Shutdown()` 来强制退出程序。这个方法会让 `Application` 关闭所有打开的窗口，停止消息循环，触发 `Exit` 事件，最终让 `Run` 方法返回。

```csharp
Application.Current.Shutdown();
```

还可以给 `Shutdown` 传一个整数退出代码（0 表示正常退出，非 0 表示异常退出）。这个代码会返回给操作系统，对于命令行工具和脚本调用有意义：

```csharp
Application.Current.Shutdown(1);  // 异常退出
```

#### 阻止窗口关闭

有时候用户点了窗口的 X，你不希望窗口关掉（比如文档没保存）。这在前一章窗口生命周期事件里已经讲过：在 `Window.Closing` 事件里设 `e.Cancel = true` 可以阻止窗口关闭。

但是注意：如果你阻止了窗口关闭，对于默认的 `OnLastWindowClose` 模式，程序也就不会退出——因为窗口还开着。这是一种简单有效的“取消退出”机制。

### 7.1.4 应用程序事件

`Application` 对象在整个生命周期中会触发一系列事件，让你可以在程序的各个关键节点插入自己的逻辑。这些事件不是路由事件（它们是普通的 CLR 事件），但它们在你的程序架构中扮演着至关重要的角色。

#### Startup 事件

**触发时机**：`Application.Run` 被调用后，主窗口显示**之前**。这是程序“即将开始运行”的最后一个关口。

**事件参数类型**：`StartupEventArgs`（继承自 `EventArgs`）。

**用途**：
- 检查启动参数（`e.Args` 是一个字符串数组，包含命令行参数）。
- 根据参数动态决定加载哪个窗口。
- 初始化全局服务（日志、数据库连接、缓存等）。
- 检查程序运行环境（如缺少必要配置文件则弹提示退出）。

```csharp
protected override void OnStartup(StartupEventArgs e)
{
    base.OnStartup(e);
    
    // 检查命令行参数
    if (e.Args.Contains("/debug"))
    {
        // 开启调试模式
    }
    
    // 如果不需要显示窗口，可以让程序继续运行但不加载 StartupUri 指定的窗口
    // 这需要在 App.xaml 中不设 StartupUri，完全由代码控制
}
```

如果 `OnStartup` 里调用了 `Shutdown`，主窗口根本不会显示，程序直接退出。这适用于“条件启动失败”的场景。

#### Activated 和 Deactivated 事件

这两个事件的触发对象是整个应用程序，而不是某个窗口。

- **`Activated`**：当程序中的**任何一个窗口**变成活动窗口时触发。用户从别的程序切回你的程序时会触发。
- **`Deactivated`**：当程序中的**最后一个活动窗口**失去激活状态时触发。用户从你的程序切到别的程序时会触发。

用途：暂停和恢复后台处理、动画、视频播放等，以节省资源。比如用户切走了，你暂停实时数据刷新；用户切回来了，恢复刷新。

#### Exit 事件

**触发时机**：程序正在关闭，窗口都已经销毁，消息循环即将停止。这是程序“临终前”的最后一个事件。

**事件参数类型**：`ExitEventArgs`。

**用途**：
- 保存全局状态（窗口位置、设置、用户偏好）。
- 释放全局资源（关闭日志文件、断开数据库连接）。
- 记录程序退出的日志。

```csharp
protected override void OnExit(ExitEventArgs e)
{
    // 保存设置
    Properties.Settings.Default.Save();
    // 记录日志
    Logger.Info($"程序退出，退出代码: {e.ApplicationExitCode}");
    base.OnExit(e);
}
```

`e.ApplicationExitCode` 可以获取或设置退出代码。你在 `Shutdown(code)` 里传的值就在这里能拿到。

**注意**：`Exit` 事件里不要再做耗时的异步操作，窗口已经没了，用户就看到界面已经关了但进程还在跑（体验很差）。

#### SessionEnding 事件

**触发时机**：Windows 操作系统正在注销或关机，你的程序需要被关闭。

**事件参数类型**：`SessionEndingCancelEventArgs`。有一个 `Cancel` 属性，设为 `true` 可以**阻止关机/注销**（但这在现代 Windows 版本上已经不太灵了，操作系统通常会在几秒后强制关闭程序）。它还有一个 `ReasonSessionEnding` 属性告诉你原因是 `Logoff`（注销）还是 `Shutdown`（关机）。

```csharp
protected override void OnSessionEnding(SessionEndingCancelEventArgs e)
{
    base.OnSessionEnding(e);
    if (e.ReasonSessionEnding == ReasonSessionEnding.Shutdown)
    {
        // 紧急保存数据
        SaveUnsavedWork();
        // 不给用户取消，直接保存并允许关闭
    }
}
```

这个事件给你的程序一个紧急保存的机会，防止数据丢失。

#### DispatcherUnhandledException 事件

**这是整个程序全局异常处理的最后一道防线。**

任何在 UI 线程（主 Dispatcher 线程）上未被捕获的异常，最终都会冒泡到这个事件。如果你没有处理这个事件，程序就会弹出一个系统默认的“程序已停止工作”对话框，然后崩溃。

**事件参数类型**：`DispatcherUnhandledExceptionEventArgs`。核心属性：

- `Exception`：未捕获的异常对象。
- `Handled`：设为 `true` 可以标记异常“已被处理”，程序**不会崩溃**，继续运行。

```csharp
protected override void OnDispatcherUnhandledException(
    DispatcherUnhandledExceptionEventArgs e)
{
    // 记录异常详情
    Logger.Error($"未处理异常: {e.Exception}");

    // 显示友好的错误提示
    MessageBox.Show($"发生了一个错误: {e.Exception.Message}\n程序将尝试继续运行。",
                    "错误", MessageBoxButton.OK, MessageBoxImage.Error);

    // 标记已处理，阻止程序崩溃
    e.Handled = true;

    // 注意：不要在这里调用 base.OnDispatcherUnhandledException，
    // 因为基类实现什么都没做，直接不调用也没问题。
}
```

**几个重要注意事项**：

1. **只捕获 UI 线程的异常**。后台线程（如 `Task.Run`、`Thread`）里没处理的异常不会跑到这里。后台线程的异常需要用 `TaskScheduler.UnobservedTaskException` 或在线程入口处用 try-catch 兜底。
2. **标记已处理后，程序可能有状态不一致的风险**。因为异常发生时的操作没有被正确完成，继续运行可能出别的问题。所以最稳妥的做法通常是通知用户“程序遇到问题，建议重新启动”，然后自动调用 `Shutdown` 优雅退出。只有在确信某个异常是无害的（如偶然的渲染错误），才标记 `Handled = true` 继续跑。
3. **不要在这个事件里再做可能抛异常的操作**。比如写日志文件也可能因为磁盘满而失败，所以日志操作也要包 try-catch。

#### 其他不常用事件

- **`Navigating`、`Navigated` 等**：用于 XAML 浏览器应用（XBAP）或页面导航，桌面程序基本不用。
- **`LoadCompleted`**：同上，主要用于导航场景。

## 7.1 节总结

7.1 节把 WPF 应用程序的“生老病死”全讲透了：

**创建 Application 对象**：
- 传统方式：手写 `Main` 方法 `new Application().Run(mainWindow)`。
- 现代方式：用 `App.xaml`（`x:Class` + `StartupUri`）由编译器自动生成 `Main`，更简洁且支持 XAML 全局资源定义。

**派生自定义 Application 类**：
- `App.xaml` 中可定义全局资源（样式、画刷、数据模板），整个程序所有地方都能用。
- `App.xaml.cs` 中可重写虚方法或订阅事件来处理程序级别的逻辑。

**应用程序的关闭方式**：
- `ShutdownMode.OnLastWindowClose`（默认）：所有窗口都关了才退出。
- `ShutdownMode.OnMainWindowClose`：主窗口关了立刻退出。
- `ShutdownMode.OnExplicitShutdown`：全靠手动调 `Shutdown()`。
- `Shutdown(int exitCode)` 传递退出代码给操作系统。

**应用程序事件**：
- **`Startup`**：启动时，主窗口显示前。初始化全局服务、处理命令行参数、条件性跳过窗口显示。
- **`Activated` / `Deactivated`**：应用程序整体级别的前后台切换通知。
- **`Exit`**：程序退出时的最后清理机会。保存设置、释放资源。
- **`SessionEnding`**：系统关机/注销时的紧急保存机会。
- **`DispatcherUnhandledException`**：UI 线程未捕获异常的最后防线，设 `Handled = true` 可阻止崩溃，但需谨慎处理状态一致性。

理解这些事件和生命周期，你就掌握了 WPF 程序最顶层的控制权。什么时候初始化、什么时候清理、什么时候拦截异常、程序要怎么退出——这些架构级的问题，答案全在 `Application` 对象里。后面 7.2 节会继续深入 Application 的高级任务（命令行参数、单实例、窗口间交互等），7.3 节讲程序集资源管理，7.4 节讲本地化多语言。
