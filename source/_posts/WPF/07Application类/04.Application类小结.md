# 笔记37《Application类》7.5节——小结

## 7.5 小结

第7章「Application 类」全部学完了。如果说前面六章是在学习和组装各种零件（布局、属性、事件、控件），那这一章就是把整个“机器”运转起来的引擎和控制中心搞明白了。`Application` 对象虽然在界面上看不见摸不着，但它决定着你的程序怎么启动、怎么退出、启动时干什么、关不掉怎么办、文件怎么带、语言怎么换。

整章的信息量不小，但逻辑非常清晰：一条命（生命周期）、五个任务（启动画面、命令行参数、全局访问、窗口交互、单实例）、两个仓库（程序集资源、内容文件）、一门语言（本地化）。下面把整章从头到尾串一遍，让你带着一张清晰的脑图走出这一章。

---

## 一、Application 对象的生命周期（7.1 节）

WPF 程序的“命”是由 `Application` 对象管着的。从双击 exe 那一下到最后进程退出，中间的每一步都有对应的事件让你插手。

**创建 Application 对象**：
- 传统方式是自己写 `Main` 方法，`new Application().Run(mainWindow)`。
- Visual Studio 默认方式是用 `App.xaml`（`x:Class` + `StartupUri`），编译器自动生成 `Main` 方法。`App.xaml` 让你可以用 XAML 声明应用级别的资源和设置。

**派生自定义 Application 类**：
- `App.xaml` 和 `App.xaml.cs` 共同定义一个 `partial class App : Application`。这是你自定义整个应用行为的起点。
- `App.xaml` 中可以定义全局资源（样式、画刷、模板），整个程序到处都能用。
- `App.xaml.cs` 中可以重写虚方法或挂事件，处理启动、退出、异常等应用级逻辑。

**应用程序的三种关闭模式**：
- `ShutdownMode.OnLastWindowClose`（默认）：所有窗口都关了，程序才退出。
- `ShutdownMode.OnMainWindowClose`：主窗口关了，程序立刻退出，不管其他窗口。
- `ShutdownMode.OnExplicitShutdown`：完全由你手动调用 `Shutdown()` 来退出，适用于后台程序或系统托盘程序。

**应用程序关键事件**：
- **`Startup`**：启动时，主窗口显示前的最后准备机会。初始化服务、处理命令行参数、根据条件决定是否跳过主窗口。
- **`Activated` / `Deactivated`**：应用程序级别的前后台切换通知。
- **`Exit`**：退出时的最后一次清理机会。保存设置、释放资源、记录日志。
- **`SessionEnding`**：系统关机或注销时的紧急保存机会。
- **`DispatcherUnhandledException`**：UI 线程未捕获异常的最后防线。设置 `e.Handled = true` 可阻止程序崩溃，但要谨慎处理状态一致性。

## 二、Application 的五大核心任务（7.2 节）

`Application` 对象不仅被动响应事件，还主动承担着几个全局性的任务：

**显示初始界面**：
- **内置闪屏**：把图片的生成操作设为 `SplashScreen`，零代码实现最早显示。但只能是静态图。
- **自定义闪屏窗口**：自己写一个 `Window` 在 `OnStartup` 里显示，支持进度条、状态文字等复杂效果。

**处理命令行参数**：
- 在 `OnStartup(StartupEventArgs e)` 中通过 `e.Args` 获取参数数组。
- 常见模式：开关参数（如 `/debug`）、键值对参数（如 `/mode=report`）、位置参数（文件路径）。
- 参数通过构造函数或公共属性传给主窗口。

**访问当前 Application 对象**：
- `Application.Current` 在程序的任何地方都能获取全局唯一的 `Application` 实例。
- 用于访问全局资源、关闭程序、获取主窗口、遍历所有打开窗口等。
- **只能在 UI 线程上访问**，不能跨线程。

**窗口之间交互**：
- 遍历 `Application.Current.Windows` 找目标窗口。
- 持有窗口引用，通过属性和方法交互（最直接，适合模态对话框）。
- 通过事件通信（发布-订阅模式，松耦合）。
- 通过共享 ViewModel / Messenger（MVVM 标准做法，最解耦）。
- 静态全局属性（简单但易滥用）。

**单实例应用程序**：
- 核心原理：命名 Mutex 检测是否已有实例在运行。
- 基本版：检测到已有实例就弹提示退出。
- 升级版：激活已有实例的主窗口并拉到前台。
- 高级版：通过命名管道等 IPC 机制传递命令行参数给第一个实例。

## 三、程序集资源和内容文件（7.3 节）

一个桌面程序不仅要逻辑正确，还得把要用到的所有物理文件（图片、字体、音视频等）带齐。

**程序集资源（Resource）**：
- 生成操作设为 `Resource`，文件会嵌入 exe 或 dll 内部。
- 通过 pack URI `pack://application:,,,/路径` 访问。
- 优点：发布简单，不丢文件。缺点：exe 体积变大，更新资源需重新编译。
- 适合小文件：图标、按钮小图、默认背景、嵌入字体等。

**内容文件（Content）**：
- 生成操作设为 `Content`，文件作为松散文件放在 exe 旁边，需设置“复制到输出目录”。
- 通过 pack URI `pack://siteoforigin:,,,/路径` 或直接文件路径访问。
- 优点：不影响 exe 体积，可单独更新，可读写。缺点：部署不能遗漏文件。
- 适合大文件或需要修改的文件：视频、配置文件、可替换的皮肤包。

**pack URI**：
- WPF 统一资源标识符。`pack://application:,,,/程序集名;component/路径` 访问嵌入资源，`pack://siteoforigin:,,,/路径` 访问内容文件。
- 可以跨程序集引用资源（用 `;component` 标记）。
- XAML 中的相对 URI（如 `Source="Images/logo.png"`）编译后会翻译为完整的 pack URI。

**选用建议**：默认用 Resource；文件大、需更新、需修改时用 Content。

## 四、本地化（7.4 节）

让你的程序开口说多种语言，不是后期打补丁，而是从设计第一天就该考虑的事。

**构建能本地化的界面**：
- 本地化的四大挑战：文字长度变化、文字方向变化、控件尺寸变化、区域格式差异。
- WPF 的五大友好特性：自适应布局、Grid 比例尺寸、`FlowDirection` 文字方向、内容与资源分离、字体回退。
- 黄金法则：永远不要硬编码自然语言文字，永远不要写死控件尺寸，永远用动态布局。

**为本地化做好准备**：
- WPF 原生方案：`x:Uid` + LocBaml → 提取 CSV → 翻译 → 生成附属程序集 dll。
- 附属程序集随 `CurrentUICulture` 自动加载，不需要写代码。

**管理翻译过程**：
- LocBaml 有局限性：Uid 管理麻烦、CSV 无上下文、无翻译记忆。
- 专业方案：RESX 资源文件 + `x:Static` 引用 + 翻译管理系统（TMS）。利用标准 .NET 资源机制，配合专业工具做翻译版本管理，体验和效率远胜裸 LocBaml。
- 本地化测试要检查：字符串截断、控件重叠、布局方向、日期格式、快捷键、文化敏感性。

## 五、Application 对象和其他章节的联系

`Application` 类是 WPF 程序的最高层管理者，它和你前面学过的几乎所有东西都有联系：

- **第3章布局**：`Application.MainWindow` 就是你精心布局的那个窗口的宿主。`SizeToContent` 和自适应布局让本地化更顺畅。
- **第4章依赖项属性**：`Application.Current.Resources` 是一个 `ResourceDictionary`，里面的每个资源都是依赖项属性机制可以查询到的对象。
- **第5章路由事件**：`Application` 本身的事件不是路由事件（它们是标准 CLR 事件），但你的 UI 控件上的路由事件最终都是在这个应用程序的消息循环里被分发的。
- **第6章控件**：每个控件的 `Source`（图片、视频）、`FontFamily`（嵌入字体）都依赖程序集资源机制。
- **第7章本身就是本章**，8~11 章的数据绑定、命令、资源和样式，很多也都涉及到 `Application.Current` 这个全局访问点。

## 六、学完第7章你应该能回答的问题

1. **程序是怎么从 exe 双击变成窗口的？** → `Application.Run()` 启动了消息循环，加载了主窗口。
2. **怎么让程序在启动时先显示一个 Logo 图片？** → 内置闪屏（SplashScreen 生成操作）或自定义闪屏窗口。
3. **怎么让程序只允许开一个实例？** → 命名 Mutex，第二个实例检测到存在即退出（并可激活旧实例）。
4. **图片应该嵌入 exe 还是放在外面？** → 小文件嵌入（Resource），大文件或需修改的放外面（Content）。用 pack URI 访问。
5. **程序要出英文版，界面怎么办？** → 从第一天起就别在 XAML 里硬编码文字。用 RESX + `x:Static` 或 LocBaml + 附属程序集来管理多语言资源。
6. **怎么在程序任何地方访问主窗口或全局资源？** → `Application.Current.MainWindow` 和 `Application.Current.Resources`。
7. **用户点 X 关窗口时，弹“是否保存？”怎么实现？** → 在 `Window.Closing` 事件里处理，设 `e.Cancel = true` 可阻止关闭。同时也要配合 `Application.ShutdownMode` 的行为。

## 七、往前看

第7章是“程序级别”的最后一站。学到这里，你已经能把一个 WPF 程序从启动到退出管理得井井有条，知道资源怎么带、多语言怎么搞。

接下来要进入的是 WPF 真正开始展现“魔性”的部分：

- **第8章 元素绑定**：让一个控件的值跟着另一个控件自动变，不用写事件。
- **第9章 命令**：告别到处都是的 `Click="..."`，把用户操作抽象成可复用、可绑定的命令对象。
- **第10章 资源**：深入 WPF 的逻辑资源系统，把样式、模板、数据模板统一管理。
- **第11章 样式和行为**：用一套规则给所有按钮、所有文本框穿上统一的皮肤。

如果说前 7 章是“建造骨架、学习零件”，那接下来这些章节就是“注入灵魂”——让界面自动响应数据变化，让交互逻辑干净纯粹，让外观随心所欲。准备好了就继续前进。
