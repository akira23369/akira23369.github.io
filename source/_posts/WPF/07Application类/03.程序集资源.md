# 笔记35《Application类》7.3节——程序集资源

## 7.3 程序集资源

前面讲了很多 WPF 的逻辑资源——样式、画刷、模板，扔在 `Resources` 字典里，用 `{StaticResource}` 引用。这些“资源”是站在 WPF 框架层面说的。但这一节要讲的是另一类东西：**程序集资源**——也就是你的程序需要用到的那些**物理文件**。图片、图标、音频、视频、字体、文本文件、甚至别的 DLL，它们都要随着你的程序一起发布部署。怎么在开发阶段把它们管好，在运行时能正确加载到界面上，就是这一节要解决的问题。

WPF 有两种主要的方式把文件带进你的程序里：

- **程序集资源（Assembly Resource）**：文件直接嵌入到编译好的 exe 或 dll 文件内部。发布时不用单独拷贝文件，运行时从程序集里读取。适合不会经常变的小文件——图标、默认图片、字体、内嵌音频。这是 WPF 里**最常用**的方式。

- **内容文件（Content File）**：文件不嵌入 exe，而是作为独立文件放在程序旁边，发布时需要一并拷贝。适合需要单独更新的文件、用户可修改的文件、以及非常大的媒体文件。

这两种方式对应 Visual Studio 里文件属性的不同“生成操作”（Build Action）。下面从添加资源开始，一步步把这两条路都走通，最后再好好地讲一下 WPF 里独一无二的 **pack URI**，这是你访问这些资源文件的唯一地址格式。

---

### 7.3.1 添加资源

你在 Visual Studio 里往项目里加一个图片或别的文件，最常见的行为就是**拖进项目里**。然后，在解决方案资源管理器里选中这个文件，按 F4 打开属性窗口，就能看到这几个关键设置：

- **生成操作（Build Action）**
- **复制到输出目录（Copy to Output Directory）**

#### 生成操作：文件怎么打包

生成操作决定了编译器如何处理这个文件。WPF 相关的常用生成操作有下面几种：

**1. Resource（WPF 程序集资源）**

这是 WPF 项目里对图片、字体等文件最常用的设定。当你把生成操作设为 `Resource` 时，这个文件会被编译器打包进程序集（exe 或 dll）的内部。最终发布的 exe 文件里就包含了这些文件，不需要额外的文件夹。

- 文件被嵌入为二进制资源，以 `application://` 协议通过 pack URI 访问。
- 适合：应用图标、按钮小图、默认状态下的背景图、嵌入的字体文件、音效等小型静态文件。
- 优点：发布简单，就一个 exe（加几个必要的 dll），不怕丢文件。
- 缺点：exe 体积变大；文件一更新就得重新编译整个程序集。

在 XAML 里引用一个生成操作为 `Resource` 的文件时，通常用相对 URI（WPF 会自动推断它在当前程序集里作为 Resource）：

```xml
<Image Source="Images/logo.png" />
```

**2. Content（内容文件）**

生成操作设为 `Content` 时，文件**不会被嵌入**到 exe 里。它作为一个独立文件呆在项目输出目录（bin\Debug）里。你还需要设置“复制到输出目录”属性来指示编译器是否自动帮你拷贝过去。

- 文件在运行时作为松散文件存在，可以通过 `pack://siteoforigin:,,,` 或直接文件路径访问。
- 适合：配置文件（用户可能要改）、庞大的视频、音频文件（几百 MB 的视频嵌进 exe 既不现实也浪费内存）、或需要动态替换的资源包。
- 优点：更新文件不用重新编译 exe；减小 exe 体积。
- 缺点：部署时需要记得带齐这些文件，容易遗漏。

复制到输出目录有三个选项：
- **不复制**：编译器不自动拷贝，你得自己手动拷到 exe 旁边的对应目录。
- **始终复制**：每次生成都把文件拷过去，即使没修改。
- **如果较新则复制**：文件有变动才拷贝，节省时间。

通常设置为**始终复制**或**如果较新则复制**。

在 XAML 中引用一个内容文件时，URI 形式稍有不同，后面讲 pack URI 会详述。

**3. Embedded Resource（传统 .NET 嵌入资源）**

这是 .NET 从 1.0 就有的老式嵌入资源机制。把文件嵌入程序集，但通过 `Assembly.GetExecutingAssembly().GetManifestResourceStream()` 来访问。**WPF 一般不用这个**，因为它不兼容 WPF 的 pack URI 系统，无法直接在 XAML 里写 Source。了解有这个东西就行，别误用。

**4. None**

顾名思义，编译器完全不管这个文件。你可能只是把某个文件放在项目里方便编辑，但不需要它作为任何输出的一部分。比如项目文档、设计草稿。

#### 怎么添加一个程序集资源

1. 在 Visual Studio 的解决方案资源管理器中，右键项目 → 添加 → 新建文件夹，命名为 `Images`（或你喜欢的名字）。
2. 把 `logo.png` 拖进这个文件夹。
3. 选中 `logo.png`，属性窗口里确认：
   - 生成操作：`Resource`
   - 复制到输出目录：`不复制`（因为已经嵌入 exe 了，不用额外拷贝）

完成。现在这个文件就成了程序集资源，可以在 XAML 和代码里通过 pack URI 引用了。

对于内容文件，步骤相似，只是生成操作选 `Content`，并设置“复制到输出目录”为“始终复制”。

### 7.3.2 检索资源

资源加进项目之后，怎么在界面上用呢？分 XAML 和 C# 代码两种情况。

#### 在 XAML 中访问程序集资源

最常见的就是给 `Image` 的 `Source` 设一张图片。假设你的文件路径是项目根目录下的 `Images/logo.png`，生成操作为 `Resource`。

**相对 URI（最省事，首选）**：

```xml
<Image Source="Images/logo.png" />
```

就这么简单。WPF 会在当前程序集内根据相对路径去找这个 `Resource` 文件。相对 URI 不需要写 `pack://` 前缀，因为 XAML 解析器会自动补全。

**绝对 URI（明确指定程序集）**：

有时候你需要引用其他程序集（比如一个单独的类库）里的资源，或者想写得很明确，就用 pack URI：

```xml
<Image Source="pack://application:,,,/MyApp;component/Images/logo.png" />
```

这里：
- `pack://application:,,,` 表示访问程序集嵌入资源。
- `/MyApp;component/`：MyApp 是程序集名，`component` 是固定写法。
- `Images/logo.png` 就是项目里的相对路径。

如果资源就在当前程序集里，你可以简写成：

```xml
<Image Source="pack://application:,,,/Images/logo.png" />
```

后面 7.3.3 节会详细拆解 pack URI 的所有格式。

**在 XAML 中访问内容文件**

如果文件的生成操作是 `Content`，XAML 里需要用 `pack://siteoforigin:,,,` 前缀：

```xml
<Image Source="pack://siteoforigin:,,,/Images/logo.png" />
```

表示从 exe 所在目录（site of origin）去寻找 `Images/logo.png`。

也可以直接用文件系统绝对路径，但不推荐，因为路径不固定。

#### 在 C# 代码中访问资源

代码里加载资源有几种方法：

**方法一：使用 `new BitmapImage` 配合 pack URI**

```csharp
string uri = "pack://application:,,,/Images/logo.png";
BitmapImage bmp = new BitmapImage();
bmp.BeginInit();
bmp.UriSource = new Uri(uri, UriKind.RelativeOrAbsolute);
bmp.EndInit();
myImage.Source = bmp;
```

或者用简化的构造函数：

```csharp
BitmapImage bmp = new BitmapImage(
    new Uri("pack://application:,,,/Images/logo.png"));
myImage.Source = bmp;
```

注意这种方法适用于 `Resource` 生成操作的文件。如果是内容文件，把 `application` 换成 `siteoforigin`。

**方法二：通过 `Application.GetResourceStream`**

```csharp
Uri uri = new Uri("pack://application:,,,/Images/logo.png");
StreamResourceInfo sri = Application.GetResourceStream(uri);
if (sri != null)
{
    using (Stream stream = sri.Stream)
    {
        BitmapImage bmp = new BitmapImage();
        bmp.BeginInit();
        bmp.StreamSource = stream;
        bmp.CacheOption = BitmapCacheOption.OnLoad;
        bmp.EndInit();
        bmp.Freeze();  // 冻结以便跨线程使用
        myImage.Source = bmp;
    }
}
```

`Application.GetResourceStream` 返回一个 `StreamResourceInfo`，里面包着原始数据流。你可以用这个流灵活地处理各种类型（不限于图片）。对于大文件，用流的方式可以避免在内存中多次复制。

不过，`GetResourceStream` 要求传入的 URI 只能是 `Resource` 类型的 pack URI，不能用于内容文件。内容文件得用 `FileStream` 或 `WebClient` 等其他方式读取。

**方法三：加载字体资源**

如果你通过 `Resource` 嵌入了一个自定义字体文件 `Fonts/MyFont.ttf`，想在代码里用它：

```csharp
FontFamily myFont = new FontFamily(
    new Uri("pack://application:,,,/"), 
    "./Fonts/#MyFontName");
textBlock.FontFamily = myFont;
```

注意 `#` 后面的 `MyFontName` 是字体内部的名字（跟文件名未必一样）。你可以双击 ttf 文件在 Windows 字体预览里看到这个名字。

也可以在 XAML 中直接声明：

```xml
<TextBlock FontFamily="/Fonts/MyFont.ttf#MyFontName" Text="Hello" />
```

**方法四：加载音视频**

对于音频（如 wav）和视频（如 wmv），WPF 使用 `MediaPlayer` 或 `MediaElement` 来播放。`MediaElement` 的 `Source` 也接受 pack URI，与图片完全一致：

```xml
<MediaElement Source="Audio/click.wav" />
```

但注意，`MediaElement` 对程序集资源支持并不好，大文件建议用内容文件（Content），并通过 `pack://siteoforigin:,,,` 加载。

#### 区分“程序集资源”和“WPF 逻辑资源”

这里要特别强调一个容易混淆的点：

- **程序集资源（Assembly Resource）**：就是本节讲的，是物理文件（图片、字体等），嵌入程序集或作为内容文件。在 XAML 里通过 `Source="..."` 引用。
- **WPF 逻辑资源（Logical Resource）**：是 WPF 的样式、画刷、模板等对象，放在 `Resources` 字典里，用 `{StaticResource key}` 引用。这是后面第 10 章的主题。

两者的关系：你可以把程序集资源（比如一张图片）加载后作为一个逻辑资源（一个 `BitmapImage` 对象）放到 `Window.Resources` 里，然后在多个地方用 `{StaticResource}` 复用。但本质上它们来自不同的体系。

### 7.3.3 pack URI

前面反复提到了 `pack://application:,,,` 这种奇怪的字符串。它就是 WPF 为你访问嵌入资源和内容文件而设计的统一资源标识符——**pack URI**。只要想引用项目里的文件，就得跟它打交道。这一节把它彻底拆明白。

#### pack URI 的基本结构

一个标准的 pack URI 长这样：

```
pack://application:,,,/程序集名;component/资源的相对路径
```

逐段拆解：

- **`pack://`**：协议头，表示这是一个 pack URI。
- **`application:,,,`**：授权部分，表示访问的是编译进程序集的资源。注意这里有三个逗号，这是固定的语法，源于 URI 的规范格式：`pack://<authority>/<path>`。`application:` 是授权类型，后面的 `,,,` 是占位。
- **`/程序集名;component/`**：指定要访问哪个程序集。`;component` 是 WPF 的固定标记，表示这是程序集中的资源。
  - 如果省略程序集名和 `;component`，WPF 会默认从当前入口程序集里找。比如 `pack://application:,,,/Images/logo.png`。
- **`资源的相对路径`**：就是在项目中的路径。注意，是以项目根目录为基准，`/` 开头。

#### 访问当前程序集的资源

最常见的就是访问自己 exe 里嵌入的资源：

```xml
<Image Source="pack://application:,,,/Images/logo.png" />
```

路径 `/Images/logo.png` 前面的 `/` 就是项目根目录。

XAML 中的相对 URI 写法（`Source="Images/logo.png"`）最后编译后也会转换为这种绝对 pack URI。

#### 访问其他程序集的资源

如果你的资源在另一个程序集里，比如 `MyControls.dll`，里面有张图片路径为 `Images/icon.png`，那么要这样写：

```
pack://application:,,,/MyControls;component/Images/icon.png
```

注意 `MyControls` 是程序集名称（不含 `.dll`），后面紧跟 `;component`，然后是那个程序集内部的资源路径。

#### 访问内容文件（松散文件）

如果文件生成操作为 `Content`，不在程序集内部，而是放在 exe 旁边的文件系统里，那就要用 **siteoforigin** 授权：

```
pack://siteoforigin:,,,/Images/logo.png
```

`siteoforigin` 表示“程序起源的目录”，也就是 exe（或快捷方式）所在的文件夹。这个路径是运行时可变的，WPF 会在运行时解析。

**重要区别**：
- `application` 资源嵌入在 exe/dll 内，发布时不需要额外文件。
- `siteoforigin` 资源是独立的文件，必须放在 exe 所在的目录下（或子目录），部署时不能漏掉。

#### 相对 pack URI 在代码中的使用

如果你在代码里用 `new Uri(...)` 创建 URI，可以指定 `UriKind.Relative` 或 `UriKind.Absolute`。

- 如果是 `application` 资源，可以用相对 URI 结合 `Application.GetResourceStream`，但你必须提供包含了程序集名的绝对 URI。实际上在代码里最保险是用绝对 pack URI。
- 如果是 `siteoforigin` 内容文件，你可以直接用文件系统路径，因为你知道 exe 的位置。但是用 pack URI 更统一。

通常，代码里加载嵌入资源用：

```csharp
Uri uri = new Uri("/MyApp;component/Images/logo.png", UriKind.Relative);
```

或者直接用全路径 pack URI。相对 URI 在代码里依赖当前上下文，有时会出错，建议代码里直接写明完整的 pack URI。

#### pack URI 的别名和简化

你可能会在别处看到这样的写法：

```
/MyApp;component/Images/logo.png
```

这是一个**相对 pack URI**，省略了 `pack://application:,,,`。WPF 在很多情况下允许这样写，特别是在 XAML 中。但为了清晰，建议在代码中还是用完整形式。

#### 特殊字符和转义

如果文件名里有空格或特殊符号，需要对它们进行 URI 编码（百分号编码）。比如 `My Image.png` 要写成 `My%20Image.png`。不过一般建议文件命名避免空格和非 ASCII 字符。

#### pack URI 在配置文件中的局限

需要注意的是，`pack://application:,,,` 资源是只读的。你不能用 FileStream 去修改一个嵌入在 exe 里的文件。如果需要读写数据文件，应该使用内容文件（siteoforigin），并直接用文件路径读写。

### 7.3.4 内容文件

上一节已经频频提到内容文件，这一节把它们单独拎出来再总结深化，并且讲清楚它们和程序集资源的选用准则。

#### 什么是内容文件

生成操作为 `Content`，并设置复制到输出目录的文件就是内容文件。它们和 exe 本身分开，呆在 exe 所在的文件夹里。WPF 把它们视为“松散资源”，不属于任何程序集。

典型的目录结构（编译输出后）：

```
bin\Debug\
    MyApp.exe
    MyApp.dll
    \Images
        logo.png       (这是内容文件)
    \Audio
        intro.mp3      (也是内容文件)
```

#### 为什么要有内容文件？

**原因一：资源体积过大。** 假设你有一个 200MB 的高清宣传视频。把它嵌入 exe，exe 的体积暴增 200MB，而且启动时系统需要把整个 exe 加载进内存，这会严重拖慢启动速度，甚至导致内存不足。把视频放在内容文件里，程序只用的时候才流式加载，内存友好得多。

**原因二：文件需要被修改。** 比如用户配置文件（json、xml），程序启动时读取，运行过程中可能保存修改。嵌入资源是只读的，无法改。内容文件则可以被自由读写。

**原因三：可以单独更新。** 如果你的程序支持“换肤”，用户可以从网上下载新的皮肤包（一堆图片）。你不可能让用户重新下载整个 exe，只需要把这些新图片放到皮肤文件夹里，程序用 siteoforigin 加载即可。

#### 如何配置内容文件

1. 把文件加入项目，生成操作选 `Content`。
2. 复制到输出目录选择合适的复制选项：
   - **始终复制**：最省心，每次都拷贝。
   - **如果较新则复制**：文件日期有变化才拷，提升增量编译速度。
   - **不复制**：自己手动管理文件。除非你通过后期生成事件或别的脚本拷贝，否则运行时找不到文件。

对于需要用户可见的文件（比如在 exe 旁边有个 ReadMe.txt），设为内容文件并始终复制。

#### 在代码和 XAML 中访问内容文件

在 XAML 中，使用 `pack://siteoforigin:,,,` 前缀：

```xml
<Image Source="pack://siteoforigin:,,,/Images/logo.png" />
```

在代码中，除了用 pack URI 创建 `BitmapImage`，你也可以直接用文件路径：

```csharp
string path = System.IO.Path.Combine(
    AppDomain.CurrentDomain.BaseDirectory, "Images", "logo.png");
BitmapImage bmp = new BitmapImage(new Uri(path));
```

或者直接用 `File.ReadAllText` 读取文本内容文件。

**BaseDirectory** 就是 exe 所在目录，等价于 `siteoforigin`。

#### 资源文件 vs 内容文件 选用指南

| 特性 | 程序集资源 (Resource) | 内容文件 (Content) |
|------|----------------------|-------------------|
| 存储位置 | 嵌入程序集 (exe/dll) 内部 | exe 目录旁的松散文件 |
| 部署方式 | 随 exe 一起，不丢文件 | 必须保持目录结构一并复制 |
| 运行时修改 | 不可修改 | 可以读写 |
| 适合的文件 | 图标、小图片、字体、音效 | 大视频、配置文件、可换皮肤 |
| 加载速度 | 极快（内存映射） | 取决于磁盘和文件大小 |
| 程序集体积 | 增加 | 不影响 |
| 文件更新 | 需要重新编译 | 替换文件即可 |

通用准则：
- 默认放**Resource**，方便又安全。
- 文件超过几百 KB 且不频繁访问的，考虑**Content**。
- 用户可能会改的，如配置，用**Content**。
- 需要动态下载的，也必须是**Content**。

#### 一个常见的混合方案

很多应用会这样做：把默认的皮肤、字体等作为程序集资源嵌入，保证开箱即用。同时预留一个外部文件夹，如果检测到外部文件夹有用户自定义资源，就优先加载外部文件，否则回退到内部嵌入资源。这样既有单 exe 的简洁，又有可扩展性。

## 7.3 节总结

7.3 节把 WPF 的物理文件管理讲得非常透彻了：

**添加资源**：
- 生成操作 `Resource`：嵌入 exe/dll，WPF 程序集资源，最常用。
- 生成操作 `Content`：松散内容文件，不嵌入，需设置复制到输出目录。
- 其他（`Embedded Resource`、`None`）WPF 基本不用。

**检索资源**：
- XAML 中直接用相对 URI（`Source="Images/logo.png"`）访问嵌入资源。
- 代码中用 `new BitmapImage(new Uri("pack://..."))` 或 `Application.GetResourceStream` 加载。
- 访问内容文件要用 `pack://siteoforigin:,,,` 或直接文件路径。

**pack URI**：
- 结构：`pack://application:,,,/程序集;component/路径`（程序集资源）
- 结构：`pack://siteoforigin:,,,/路径`（内容文件）
- 可以跨程序集引用，用 `;component` 标记。
- XAML 相对 URI 最终也会转为 pack URI。

**内容文件**：
- 独立于 exe，适合大文件、可修改文件、可替换文件。
- 访问方式灵活，但部署不能遗漏。
- 与程序集资源互补，根据体积、更新需求、可否修改选择。
