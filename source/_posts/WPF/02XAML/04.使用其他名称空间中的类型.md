## 使用其他名称空间中的类型

前面讲命名空间的时候，其实已经提了一嘴怎么引入自定义类型。但这一节是专门深入这个主题，告诉你：**当你需要在自己写的 XAML 里用到别人的类（不管是自己项目的其他命名空间，还是第三方库，还是 .NET 框架里但不在 WPF 默认命名空间的），应该怎么操作**。

说白了就是，你不是只能在 XAML 里写 `Button`、`TextBox` 这些微软给你的东西，你想把自己写的一个类当成控件放到 XAML 里，也完全能行。这节的焦点就是破除“XAML 只能用 WPF 自带控件”的误解。

---

### 什么时候需要引入其他命名空间？

回顾一下，WPF 默认映射的那个命名空间（`xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"`）已经覆盖了绝大部分常用的控件、面板、图形类。所以大多数时候你直接用 `<Button>`、`<StackPanel>` 不需要额外声明。

但总有些情况，默认的命名空间帮不上忙：

1. **你用到了 .NET 框架里的某个类，但它在别的程序集里，而且没有被默认命名空间涵盖。** 比如 `System.Windows.Media.Matrix` 这个类虽然跟图形有关，但你直接用 `<Matrix>` 是找不到的，需要手动映射。

2. **你自己在项目里定义了一个用户控件或者一个自定义类，你想在 XAML 里使用它。** 比如你写了个 `MyCoolButton` 类，继承自 `Button`，放在 `MyApp.Controls` 命名空间下。你要在 `MainWindow.xaml` 里放这个按钮，就得把 `MyApp.Controls` 映射进来。

3. **你引用了一个第三方 WPF 控件库**（比如 Telerik、ComponentOne、或者其他开源库），那些库里的控件你当然也要引入才能用。

4. **你有一些纯粹的数据类（View Model 或者其他的），想通过 XAML 实例化。** 因为 XAML 本质上可以创建任何 CLR 对象，不一定非得是控件。你可以在 XAML 里把一个普通类的对象声明为资源，用标记扩展引用。

---

### 引入同项目其他命名空间

最典型的场景：你项目叫 `MyApp`，你建了个 `Views` 文件夹，里面放了个用户控件叫 `UserProfileView.xaml`。然后在 `MainWindow.xaml` 里想用这个 `UserProfileView`。

怎么做？在 `MainWindow.xaml` 的根标签上加上一行命名空间映射：

```xml
<Window x:Class="MyApp.MainWindow"
        xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
        xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
        xmlns:views="clr-namespace:MyApp.Views"
        Title="MainWindow">
    <views:UserProfileView />
</Window>
```

看到没，语法就是 `xmlns:你随便取的前缀="clr-namespace:命名空间名"`。然后你就可以用 `views:UserProfileView` 来实例化那个控件了。

这两个关键点再强调一下：

- **前缀可以随便取**：这里取的是 `views`，你也可以取 `v`、`myControls` 都行，但尽量有意义一点，别写成 `a`、`b`，过一个月你自己都忘了代表什么。
- **clr-namespace 后面的命名空间名必须和你的 C# 类定义里的 `namespace MyApp.Views` 完全一致**，包括大小写和点号。写错一个字符，编译就报错，告诉你找不到对应类型。

### 引入不同程序集（DLL）里的类型

如果你用的类型不在当前项目的程序集里，而是在另一个 DLL 里（不管是自己建的类库项目，还是第三方 NuGet 包），那映射的时候除了指定命名空间，还得指定程序集名称。

语法变成：

```xml
xmlns:ext="clr-namespace:SomeLibrary.Controls;assembly=SomeLibrary"
```

这里 `SomeLibrary.Controls` 是目标命名空间，`SomeLibrary` 是程序集名（不含 `.dll` 扩展名）。中间用分号隔开，这种格式在 XAML 里叫“CLR 命名空间限定名”。

举个例子，你用了个假想的三方图表库 `SuperChart.dll`，里面有个 `Chart` 类在 `SuperChart.Controls` 命名空间下，那就得写：

```xml
xmlns:chart="clr-namespace:SuperChart.Controls;assembly=SuperChart"
```

之后就可以 `<chart:Chart ... />` 来用了。

这里有个新手坑：程序集名称不等于 NuGet 包名，也不等于项目名（虽然经常相同）。你得去看那个 DLL 的实际文件名，比如 `SuperChart.dll` 它的程序集名就是 `SuperChart`。你还可以在 Visual Studio 的“引用”里右键点那个程序集看属性，里面有个“程序集名称”字段，抄那个就对了。

还有一个特殊情况：**如果你要引入的类型在 mscorlib.dll 或者 System.dll 这种 WPF 项目本来就引用的基础程序集里**，是不是还得写 `assembly=` 呢？答案是：看情况。WPF 默认的命名空间已经映射了 `PresentationFramework`、`PresentationCore`、`WindowsBase` 等核心程序集，所以不用额外声明。但如果一个类在 `System` 命名空间下的某个你没映射到的程序集里，你还是得写完整的映射，包括 `assembly=`。不过实践中很少会这样，大多数情况默认命名空间已经够了。

### XAML 里使用非控件类

前面提过，XAML 不光能创建控件，任何公共的、有无参构造函数的 CLR 对象都可以在 XAML 里创建。比如你有一个数据类：

```csharp
namespace MyApp.Models
{
    public class Person
    {
        public string Name { get; set; }
        public int Age { get; set; }
    }
}
```

你完全可以在 XAML 里写：

```xml
xmlns:models="clr-namespace:MyApp.Models"

<Window.Resources>
    <models:Person x:Key="me" Name="张三" Age="25"/>
</Window.Resources>
```

然后通过 `{StaticResource me}` 引用这个资源。这个功能在 MVVM 里面用得挺多，比如在 XAML 里声明一个 `ObjectDataProvider` 或者一个 ViewModel 实例，作为数据上下文。

不过这要求你的类必须满足：

- 公开的（`public`）
- 有无参构造函数（如果你没定义任何构造函数，系统自动提供了一个无参的，那就满足条件；如果你只定义了带参的构造函数，那就没法在 XAML 里直接创建，除非用特殊手段）
- 属性有公开的 `get` 和 `set`，否则 XAML 无法通过属性语法赋值

如果你违反了这些规则，编译时可能直接报错，或者属性设了没反应。

### 复杂前缀与冲突处理

有时候你可能需要引用两个不同的程序集，而它们内部有同名的类，比如你自己写了个 `Button` 类，在 `MyApp.Controls` 命名空间下。这时候你在 XAML 里用 `Button`，解析器怎么知道是微软的 `Button` 还是你的 `Button`？

这就是引入命名空间前缀的意义。默认命名空间的 `Button` 是微软的，而你映射出 `local` 前缀（假设你写 `xmlns:local="clr-namespace:MyApp.Controls"`），你的按钮就叫 `local:Button`，两者互不干扰。

这也提醒我们，在 XAML 里，控件的类型全靠前缀来区分所属命名空间，清晰度很重要。如果你胡乱把前缀取成 `b`、`c`，自己都搞不清哪个是哪个，后期维护会很痛苦。

---

### 和 “x:” 命名空间的区别

再提醒一下以免混淆：`x:` 命名空间是 XAML 语言本身的“元命名空间”，它和你要引入的那些控件命名空间不是一个概念。`x:Class`、`x:Key`、`x:Name` 这些属于 XAML 编译器理解的特殊东西，而你要引用的其他命名空间只是普通的 .NET 类型来源。前者是 XAML 的内置功能，后者是你自己找来的原材料。

---

### 使用 Blend 或设计器时的注意事项

如果你在用 Expression Blend，或者 Visual Studio 的设计视图拖拽控件，它通常会自动帮你添加好所需的命名空间映射。但是，如果你手动敲 XAML 代码，或者从别处复制了一段 XAML 想用某个控件，你就得自己把命名空间声明补上。编译器的报错信息这时候挺有用，“找不到类型”多半就是你没映射或者映射错了。

---

## 小结一下

说白了，zhe节就是在告诉你：**XAML 不是封闭的，它可以自由地使用任何你告诉它去哪找的 .NET 类**。

记住几个要点：

- 用 `xmlns:前缀="clr-namespace:命名空间"` 引入同项目的类。
- 用 `xmlns:前缀="clr-namespace:命名空间;assembly=程序集名"` 引入外部 DLL 的类。
- 任何公开的、有无参构造函数的 .NET 类都可以在 XAML 里创建，不仅仅是控件。
- 前缀可以随便取，但建议有意义。
- 如果不映射清楚，同名的类会冲突，前缀就是用来区分它们的。

这节内容不多，但它是你后面使用用户控件、第三方库、MVVM 资源绑定这些事情的前提，必须彻底搞熟练，做到伸手就能写出正确的命名空间映射。
