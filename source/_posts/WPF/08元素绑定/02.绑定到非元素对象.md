# 笔记39《元素绑定》8.2节——绑定到非元素对象

## 8.2 绑定到非元素对象

上一节 8.1 讲的是把两个控件直接绑在一起——滑动条拖动，文本自动更新。那种绑定的源是另一个 WPF 控件，靠 `ElementName` 来指认。这是学习绑定的绝佳切入点，因为直观、好理解。

但在真实应用中，这种“控件绑控件”的场景其实不多。更多的情况是：**你的数据不在另一个控件里，而在一个普通的 C# 对象里。** 比如用户的姓名、年龄、订单列表、配置选项、股票实时价格……这些数据都是普通的 .NET 对象，可能是从数据库查出来的，也可能是从网络请求回来的。你的界面需要显示它们，并且当数据变化时界面自动刷新。

这时候绑定源就从一个可见的控件变成了一个“看不见”的数据对象。怎么把绑定指向这个对象？WPF 提供了三种方式：

- **`Source` 属性**：直接指定源对象（“就是它！”）。
- **`RelativeSource` 属性**：相对于目标元素在视觉树上找源（“找我的祖先/兄弟/自己”）。
- **`DataContext` 属性**：通过依赖项属性的值继承机制，让整棵子树共享一个数据源（“我爸的数据就是我的数据”）。

这三种方式各有各的适用场景，而且 `DataContext` 是 MVVM 架构的基石。理解了这三条路，你就能把数据从任何地方连接到界面上的任何控件。

---

### 8.2.1 Source 属性

`Source` 是 `Binding` 类的一个属性，类型是 `object`。它就是最直接的方式：**你给绑定指定一个具体的源对象，绑定引擎就去读这个对象上的属性。**

#### 基本用法

假设你定义了一个普通的 C# 类（注意不是控件，不继承自 `UIElement`）：

```csharp
public class Person
{
    public string Name { get; set; }
    public int Age { get; set; }
}
```

你想在界面上显示一个人的信息。一种方式是在 XAML 里创建这个对象，放在资源字典里，然后用 `Source` 绑定：

```xml
<Window.Resources>
    <local:Person x:Key="person" Name="张三" Age="30" />
</Window.Resources>

<StackPanel>
    <TextBlock Text="{Binding Source={StaticResource person}, Path=Name}" />
    <TextBlock Text="{Binding Source={StaticResource person}, Path=Age, StringFormat={}年龄: {0}}" />
</StackPanel>
```

这里：
- `Source={StaticResource person}` 告诉绑定“源对象是资源字典里 key 为 person 的那个 `Person` 对象”。
- `Path=Name` 告诉绑定“去读这个对象的 `Name` 属性”。

**注意**：`Person.Name` 是普通 CLR 属性，不是依赖项属性。这没关系——**绑定源可以是普通 CLR 属性**，绑定引擎通过反射来读取它的值。但是，普通 CLR 属性没有变更通知机制——如果 `Person.Name` 在运行时被修改了，WPF 不会自动知道，界面也不会更新。想让界面自动更新，源对象需要实现 `INotifyPropertyChanged` 接口，这个后面 8.3 小结或后续章节会展开。

#### Source 在代码中设置

更常见的情况是，数据对象在 C# 代码里创建，然后通过代码把绑定挂上去：

```csharp
Person person = new Person { Name = "李四", Age = 25 };

Binding nameBinding = new Binding
{
    Source = person,
    Path = new PropertyPath("Name"),
    Mode = BindingMode.OneWay
};
nameTextBlock.SetBinding(TextBlock.TextProperty, nameBinding);
```

或者更简洁一点，直接把 `Source` 赋值给一个已有的绑定。

#### Source 的特点

- **直接明确**：没什么隐藏的、需要推断的东西，绑定源一眼就看出来了。
- **耦合度高**：每个绑定都要单独指定源，当界面里同一个数据对象要被很多控件绑定时，每个绑定都要重复写 `Source`，XAML 会很冗余。
- **适合单一明确的源**：比如绑定到某个资源对象、某个静态属性、某个通过代码创建并拿在手里的对象。

#### 什么时候用 Source？

- 绑定到 `x:Static` 静态成员（如 `{Binding Source={x:Static SystemFonts.IconFontFamily}, Path=...}`）。
- 绑定到某个手动创建的 C# 对象并只在代码中管理绑定。
- 绑定到某个资源字典中的对象。

对于大型界面中所有控件都围绕同一个“数据上下文”工作的场景，`Source` 太啰嗦了，这时候就该 `DataContext` 上场了。

### 8.2.2 RelativeSource 属性

有时候，绑定源不是某个名字已知的元素，也不是某个独立的数据对象，而是**和目标元素有某种相对关系**的元素。最常见的就是：某个控件想绑定到它自己的另一个属性，或者绑定到它的父容器的某个属性。

这时候 `RelativeSource` 就派上用场了。它不指定一个具体的源对象，而是指定**一种查找源的方式**。

#### RelativeSource 的三种模式

**`Self` 模式**：源就是目标元素自己。

这意味着一个控件的某个属性可以绑定到它自己的另一个属性。听起来有点奇怪，但实际很有用。

```xml
<TextBlock Text="{Binding RelativeSource={RelativeSource Self}, Path=ActualWidth}" />
```

这个 `TextBlock` 的 `Text` 会显示它自己的实际宽度（以 WPF 单位计）。每当窗口大小变化，`TextBlock` 的宽度变了，`Text` 自动更新显示新宽度。

另一个经典例子：一个圆形 `Ellipse` 的宽度和高度始终相同，保持正圆：

```xml
<Ellipse Width="100" 
         Height="{Binding RelativeSource={RelativeSource Self}, Path=Width}"
         Fill="Red" />
```

`Height` 绑定到自己的 `Width` 上。你改了 `Width`，`Height` 自动跟上，始终保持圆形。不需要写任何事件代码。

**`FindAncestor` 模式**：沿视觉树向上找某个类型的祖先元素。

这是最常用的 `RelativeSource` 模式。你不需要给父元素起名字，只要指定它的类型和（可选的）层级，WPF 就会沿着视觉树往上一层层找，直到找到匹配的元素。

```xml
<TextBlock Text="{Binding RelativeSource={RelativeSource FindAncestor, AncestorType={x:Type Window}}, 
                          Path=Title}" />
```

这个 `TextBlock` 不管嵌套在多深的布局里，它自动向上找最近的 `Window` 祖先，然后显示这个窗口的 `Title`。

**`AncestorLevel` 参数**：当你往上找的祖先类型可能有多层时（比如 `Grid` 里面套 `Grid`），可以通过 `AncestorLevel` 指定找第几层的。默认是 1（最近的一个）。

```xml
<!-- 找第 2 层外的 ScrollViewer -->
<TextBlock Text="{Binding RelativeSource={RelativeSource FindAncestor, 
              AncestorType={x:Type ScrollViewer}, AncestorLevel=2}, 
              Path=VerticalOffset}" />
```

**实际案例**：在一个 `ItemsControl` 的数据模板里，绑定到列表本身的 `Items.Count` 属性：

```xml
<ItemsControl ItemsSource="{Binding Items}">
    <ItemsControl.ItemTemplate>
        <DataTemplate>
            <TextBlock Text="{Binding RelativeSource={RelativeSource FindAncestor, 
                              AncestorType={x:Type ItemsControl}}, 
                              Path=Items.Count}" />
        </DataTemplate>
    </ItemsControl.ItemTemplate>
</ItemsControl>
```

每个条目都知道整个列表有多少项，可以用来显示“第 X / 共 N 项”。

**`TemplatedParent` 模式**：绑定到应用了此模板的控件。这在控件模板（`ControlTemplate`）内部非常常用。一个模板里的元素可以绑定到控件自身的属性。这个等到后面第 17 章控件模板时会详细展开。这里先知道有这个概念。

#### RelativeSource 的特点

- **动态、松耦合**：不需要给父元素起名字，布局结构变了只要有目标类型的祖先就依然能工作。
- **适合模板和样式中使用**：因为模板里的元素和外部控件的名字是隔离的，`ElementName` 跨模板边界不好使，而 `RelativeSource` 可以在模板内部找到模板目标。
- **不适合跨大范围查找**：在很深的视觉树里频繁用 `FindAncestor` 可能影响性能（很少见，但在极端场景下需注意）。

### 8.2.3 DataContext 属性

如果说 `Source` 是“手动指定源”，`RelativeSource` 是“根据相对关系找源”，那么 `DataContext` 就是“**自动继承数据源**”。这是 WPF 数据绑定里最巧妙、也最符合直觉的设计。

#### DataContext 是什么？

`DataContext` 是 `FrameworkElement` 上的一个**依赖项属性**，类型是 `object`。任何 WPF 的可视元素都有这个属性。最关键的是：**它的元数据设置了 `Inherits = true`，会自动从父元素继承。**

这意味着什么？意味着你只需要在窗口的根容器（或任何一个你希望的范围）上设置一次 `DataContext`，这个容器里的所有子元素（以及子元素的子元素，无限递归）都会自动拥有同样的数据上下文。然后子元素的绑定不需要指定任何源——绑定引擎会自动使用当前的 `DataContext` 作为源。

这就是“数据上下文”这个名字的来源——它为整棵子树提供了“数据环境”。

#### 从代码设置 DataContext

最典型的场景：在 C# 里创建一个数据对象，然后把它赋给窗口的 `DataContext`。

```csharp
public partial class MainWindow : Window
{
    public MainWindow()
    {
        InitializeComponent();
        
        Person person = new Person { Name = "王五", Age = 28 };
        this.DataContext = person;  // 整个窗口的数据上下文就是这个 Person 对象
    }
}
```

XAML 里，所有绑定直接用 `Path` 即可，不需要指定 `Source`：

```xml
<StackPanel>
    <TextBlock Text="{Binding Path=Name}" />
    <TextBlock Text="{Binding Path=Age, StringFormat={}年龄: {0}}" />
</StackPanel>
```

因为 `StackPanel` 和 `TextBlock` 都继承了窗口的 `DataContext`，所以 `{Binding Path=Name}` 其实就是去读 `this.DataContext.Name`。你不需要告诉绑定“源是谁”，它自己知道。

**这就是 MVVM 模式的萌芽**：
- 窗口的 `DataContext` 设成一个 ViewModel 对象。
- XAML 里所有控件通过 `{Binding Path=属性}` 自动连接到 ViewModel。
- 代码隐藏（`.xaml.cs`）里几乎不剩什么代码，逻辑全在 ViewModel 里。
- 界面和逻辑完全解耦。

#### 隐式绑定（省略 Path）

`{Binding}` 如果不指定 `Path`，它就绑定到 `DataContext` 本身，而不是它的某个属性。这在某些场景下很有用，比如 `ListBox` 的 `ItemsSource` 绑定到整个集合：

```xml
<ListBox ItemsSource="{Binding}" />
```

等价于：

```xml
<ListBox ItemsSource="{Binding Path=.}" />
```

`.` 表示当前数据上下文本身。

#### 局部覆盖 DataContext

因为 `DataContext` 是依赖项属性，你可以在任何子元素上显式设置它，从而**覆盖**继承来的值。该元素及其子元素将使用新的数据上下文。

```xml
<StackPanel DataContext="{Binding Address}">
    <!-- 这一块的数据上下文变成了 Person.Address -->
    <TextBlock Text="{Binding City}" />
    <TextBlock Text="{Binding Street}" />
</StackPanel>
```

外面还是 `Person` 对象，但这个 `StackPanel`（及内部）的数据上下文变成了 `Person.Address` 对象。所以里面的绑定直接写 `City` 和 `Street` 就能工作，不需要写 `Address.City`。

#### DataContext 解析绑定源的过程

当 WPF 遇到一个 `{Binding Path=Name}` 时（没有指定 `ElementName` 也没有指定 `Source` 没有指定 `RelativeSource`），它会沿着元素树**向上查找**，直到找到一个不为 `null` 的 `DataContext`。然后把这个 `DataContext` 作为绑定源，再应用 `Path`。如果一路向上找到根元素都没有 `DataContext`，绑定源就是 `null`，绑定会失败（但不会抛异常，只会在输出窗口打印错误，属性保持默认值或 FallbackValue）。

**查找过程**：

1. 看当前元素的 `DataContext` 是否是 `null`。
2. 是 `null` → 看父元素的 `DataContext`。
3. 父元素也是 `null` → 继续往上，直到找到一个非 `null` 的 `DataContext`，或者到达根元素。

这就是依赖项属性的值继承在起作用。

#### 一个完整示例：DataContext 继承与覆盖

```xml
<Window x:Class="Demo.MainWindow" ...>
    <Window.DataContext>
        <local:Person Name="赵六" Age="35">
            <local:Person.Address>
                <local:Address City="北京" Street="长安街" />
            </local:Person.Address>
        </local:Person>
    </Window.DataContext>

    <StackPanel>
        <!-- 直接绑定到 Person 的属性 -->
        <TextBlock Text="{Binding Name}" />   <!-- 显示 "赵六" -->
        
        <GroupBox Header="地址信息">
            <!-- 这一块覆盖 DataContext 为 Person.Address -->
            <StackPanel DataContext="{Binding Address}">
                <TextBlock Text="{Binding City}" />     <!-- 显示 "北京" -->
                <TextBlock Text="{Binding Street}" />   <!-- 显示 "长安街" -->
            </StackPanel>
        </GroupBox>
    </StackPanel>
</Window>
```

每个 `TextBlock` 的 `Binding` 都没有写源，全部依赖 `DataContext` 的自动继承和局部覆盖。XAML 简洁、语义清晰。

#### DataContext 在大型列表中的应用

在 `ItemsControl`（如 `ListBox`）里，`DataContext` 的另一个巨大作用显现出来：每个列表项的容器（如 `ListBoxItem`）会自动把它的 `DataContext` 设置为当前那一条数据对象。这意味着你只需要在 `ItemTemplate` 里写 `{Binding Path=属性}`，绑定引擎就会自动去读每条数据的那个属性，不需要任何额外配置。

```xml
<ListBox ItemsSource="{Binding UserList}">
    <ListBox.ItemTemplate>
        <DataTemplate>
            <StackPanel>
                <TextBlock Text="{Binding Name}" FontWeight="Bold" />
                <TextBlock Text="{Binding Email}" Foreground="Gray" />
            </StackPanel>
        </DataTemplate>
    </ListBox.ItemTemplate>
</ListBox>
```

`UserList` 是一个 `ObservableCollection<User>`。每个 `User` 对象在生成 `ListBoxItem` 时，自动成为该 `ListBoxItem` 的 `DataContext`。模板里的 `{Binding Name}` 等于 `{Binding Path=Name}`，绑定源就是当前项自己的 `DataContext`。

这个机制是数据驱动 UI 的基石。

#### Source、RelativeSource、DataContext 的优先级与混用

一个 `Binding` 对象上可以同时指定 `Source`、`ElementName`、`RelativeSource`。它们的优先级是：**你自己显式指定的比隐式的 DataContext 更高。** 如果你同时加了 `Source`，WPF 直接用这个 `Source`，不再往父级找 `DataContext`。

实际上你很少混用，大多数清晰的设计是：
- **绝大多数绑定用 `DataContext` 继承**（配合 MVVM 的 ViewModel）。
- **需要绑定到控件自身或视觉树祖先时用 `RelativeSource`**。
- **偶尔绑定到特定静态/资源对象时用 `Source`**。

## 8.2 节总结

8.2 节把绑定的源从“另一个控件”拓展到了整个对象世界：

**Source 属性**：
- 直接指定一个具体的源对象（资源字典里的对象、代码中创建的对象）。
- 类型为 `object`，可以绑定到普通 CLR 对象。
- 用于单一明确的源，缺点是每个绑定都要单独设源，不适合全局共享数据上下文。

**RelativeSource 属性**：
- 通过相对关系找源：`Self`（自己）、`FindAncestor`（沿树向上找祖先）、`TemplatedParent`（模板目标）。
- 解耦命名依赖，在模板、样式内部非常有用。
- `FindAncestor` 模式可以查找指定类型的祖先，支持 `AncestorLevel` 指定第几层。

**DataContext 属性**：
- `FrameworkElement` 的依赖项属性，元数据设置 `Inherits = true`，父元素的 DataContext 自动被子元素继承。
- 只需在最外层容器（如 Window）设置一次 `DataContext`，内部所有绑定自动使用它作为源。
- 绑定不需要写源，只需写 `{Binding Path=属性}`。
- 可以在子树中局部覆盖 `DataContext`，实现数据上下文的切换。
- 是 MVVM 架构的核心基础——ViewModel 对象赋给 View 的 `DataContext`，View 的所有控件通过绑定自动连接到 ViewModel 的属性。

**三种方式的对比**：

| 方式 | 适用场景 | 优点 | 缺点 |
|------|---------|------|------|
| `Source` | 绑定到特定静态/资源对象 | 直接明确 | 每个绑定都要写，冗余 |
| `RelativeSource` | 绑定到自己或祖先 | 松耦合，无需命名 | 只能处理相对关系 |
| `DataContext` | 全局共享数据上下文 | 简洁优雅，MVVM 基石 | 需要理解继承机制 |

学完这一节，你对绑定的认识就从“两个控件手拉手”升级到了“界面和数据的自由恋爱”。`DataContext` 这条通路是后面所有 MVVM 内容的高速公路，你会在接下来无数章节里反复看到它。下一节 8.3 是第 8 章的小结，会把本章的所有绑定知识串联成一张完整的网。
