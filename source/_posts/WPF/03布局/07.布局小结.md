## 布局小结

学完第3章，你已经跨过了 WPF 入门最大的一道坎。布局是 WPF 桌面开发的骨架，界面上的所有按钮、文本框、列表、图片，全都要靠布局来决定它们待在哪儿、占多大地方。没有布局，控件就是一团散沙；有了布局，你能构建出灵活、健壮、适应各种屏幕和窗口大小的专业级界面。

这一节咱们把全章的东西串一串，帮你从“学会每个面板怎么用”上升到“知道什么时候该用哪个面板，以及它们怎么配合”。

---

## 一、WPF 布局的核心理念：告别像素，拥抱自适应

老式 Windows 开发（比如 Windows Forms）靠的是绝对坐标和固定尺寸。按钮放在 (100, 200)，宽度 75，写死。窗口一拖大，傻眼了；分辨率一变，界面要么缩成蚂蚁要么大到溢出。更痛苦的是多语言支持——德文文本比英文长一倍，所有标签都被截断。

WPF 用一整套**布局原则**彻底解决了这个问题：

**第一条：不要显式设置元素的固定尺寸。** 控件的大小应该由它的内容和父容器的分配来决定，而不是你拍脑袋写死一个数。一个按钮的文字多了，按钮自动变宽；窗口拉大了，输入框自动延伸填满剩余空间。

**第二条：不要用像素坐标指定位置。** 元素的位置完全交给布局面板根据算法自动计算。你想竖排一溜控件，就用 `StackPanel`；想做成表格，就用 `Grid`。你描述规则，面板替你算出所有坐标。

**第三条：布局容器和子元素可以递归嵌套。** 这是 WPF 布局灵活性的根本来源。一个 `Grid` 里面能放 `StackPanel`，`StackPanel` 里面又能放 `DockPanel`，层层套，每层只管自己的小局部，组合起来能表达任意复杂的界面结构。

**第四条：布局是动态自适应的。** 窗口大小改变、系统 DPI 改变、控件内容改变，WPF 会自动重新测量和排列所有受影响的元素，不用你写一行 Resize 事件代码。这就是“内容驱动 + 自动布局”的威力。

配合第1章讲过的**分辨率无关性**（WPF 单位 = 1/96 英寸，系统 DPI 自动缩放），你的界面在高分屏上既不模糊也不变形，而且在高 DPI 下天然更清晰。

## 二、布局是怎么工作的：测量与排列

布局不是魔法，它背后有一个明确的两阶段流程：**测量（Measure）** 和 **排列（Arrange）**。

**测量阶段**：父容器问每个子元素“在不超过某个最大可用空间的前提下，你理想中需要多大？”子元素根据自己内容（文字、图片、边距等）计算出一个期望尺寸（`DesiredSize`），汇报给父容器。这个过程从布局树的根往下递归，每个父面板都会综合所有子元素的 DesiredSize 和自己的布局算法，算出自己需要的尺寸汇报给再上一级。

**排列阶段**：测量的结果汇总到顶层后，父容器根据实际可用空间和自己的布局规则，决定每个子元素最终分配到的矩形（位置 + 大小），然后调用子元素的 Arrange 方法，把这块地正式划给它。子元素在这块地里再对它的内容进行最终定位和渲染。

当窗口大小改变、内容变化、甚至控件增删时，受影响的那部分布局树会被标记为“需要重新测量”，然后触发新一轮的测量和排列。这个机制是 WPF 自适应能力的底层保障。

理解这两个阶段，将来你写自定义面板或自定义控件时，就知道要重写 `MeasureOverride` 和 `ArrangeOverride` 方法；平时用现成面板，知道系统在背后干了些啥，就不会对“为什么这个控件突然变宽了”感到困惑。

## 三、六大核心布局面板，各有各的绝活

第3章把 WPF 自带的布局面板逐个拆了一遍，每个面板都解决一类特定的布局问题。下面用一句话概括每个面板的定位，再展开回忆关键细节：

### StackPanel：线性排列

**一句话**：把子元素沿一个方向（垂直或水平）一溜排开，一个接一个。

- **核心属性**：`Orientation`（`Vertical` 垂直，`Horizontal` 水平）。
- **行为特点**：在排列方向上给子元素无限空间（子元素要多大给多大），因此在该方向上对齐属性无效。在非排列方向上，子元素默认拉伸填满面板宽度（或高度），你可以用 `HorizontalAlignment` / `VerticalAlignment` 控制靠边、居中或拉伸。
- **典型用途**：菜单项、工具栏按钮、表单中的字段堆叠、对话框底部的按钮行。
- **致命缺陷**：空间不够时子元素直接被截断，不会自动换行。

### WrapPanel：带换行的线性排列

**一句话**：StackPanel 的升级版，一行（或一列）排不下了自动换行。

- **核心属性**：同样有 `Orientation`，外加 `ItemHeight` 和 `ItemWidth` 可统一子元素尺寸。
- **行为特点**：水平和垂直模式换行/换列逻辑不同，但本质都是“排到边缘自动折”。
- **典型用途**：标签云、缩略图墙、数量不定的复选框组、可自适应宽度的工具栏。
- **局限**：不能做严格对齐的表格（各行/列的边界不对齐）。

### DockPanel：贴边停靠

**一句话**：子元素可以贴在上下左右任一边，最后一个子元素填满剩余空间。

- **核心属性**：附加属性 `DockPanel.Dock`（`Top`、`Bottom`、`Left`、`Right`）；属性 `LastChildFill`（最后一个子元素是否自动填满）。
- **行为特点**：子元素按声明顺序依次占边，先来的先占，后来的只能在剩余空间里操作。贴边的元素在停靠方向上的大小由内容决定，在另一方向上被拉伸填满。
- **典型用途**：经典三段式/四段式布局（顶部菜单、底部状态栏、左侧导航、右侧属性、中间主内容区）。
- **注意坑**：最后填满的元素一定要放在声明的最后；默认 Dock 是 `Left`，而不是很多人以为的 `Top`，所以别忘显式写 Dock。

### Grid：表格网格

**一句话**：最强大、最通用的面板。把空间切成行和列，形成网格，子元素放格子里。

- **核心组件**：`RowDefinitions`、`ColumnDefinitions`。
- **三种尺寸模式**：
  - **固定尺寸**（如 `Height="100"`）：精确控制，适合标题栏、状态栏。
  - **自动尺寸**（`Height="Auto"`）：根据内容自动伸缩，适合标签行、分隔区。
  - **比例尺寸**（`Height="*"`、`Height="2*"`）：按比例瓜分剩余空间，这是自适应布局的灵魂。
- **跨越行列**：`Grid.RowSpan` 和 `Grid.ColumnSpan`，实现合并单元格。
- **GridSplitter**：让用户拖拽调整行列大小，实现可交互的分割窗口。
- **SharedSizeGroup**：跨多个独立 Grid 同步列宽/行高，需要父容器开启 `IsSharedSizeScope="True"`。
- **UniformGrid**：简化版 Grid，所有格子等大，只需指定行列数或自动推算。
- **典型用途**：所有需要精确控制行列对齐的场景——设置表单、仪表盘、邮件客户端三栏布局、几乎所有复杂界面的外层框架。

`Grid` 是整个 WPF 布局系统里事实上的“主力选手”，你花在 Grid 上的练习时间会得到最大回报。

### Canvas：绝对坐标定位

**一句话**：WPF 里唯一基于坐标定位的面板，违背了自动布局原则，但填补了精确图形控制的空白。

- **核心属性**：附加属性 `Canvas.Left`、`Canvas.Top`、`Canvas.Right`、`Canvas.Bottom`。
- **行为特点**：子元素的位置完全由坐标指定，不自动排列、不自动换行、不拉伸。面板自身尺寸可由子元素最大坐标决定，也可手动固定。对齐属性和 Margin 在此效果有限。
- **Z 顺序**：多个元素重叠时，谁在上谁在下由 `Panel.ZIndex` 属性控制（值越大越靠上）。这个属性在所有 Panel 里都有效。
- **InkCanvas**：Canvas 的衍生，专门用于手写笔迹和涂鸦，内置笔画收集、编辑、序列化功能。
- **典型用途**：绘图应用、拖拽设计器、2D 游戏画布、精确定位的动画场景、悬浮提示框。

**使用原则**：能用自动布局面板搞定的时候别用 Canvas。Canvas 只在确实需要像素级坐标控制时才登场。

## 四、布局的通用工具：对齐、边距、尺寸约束

除了每个面板独有的属性，WPF 还给所有 `FrameworkElement` 配备了一套通用的布局微调工具：

**对齐（Alignment）**：
- `HorizontalAlignment`：`Left`、`Center`、`Right`、`Stretch`
- `VerticalAlignment`：`Top`、`Center`、`Bottom`、`Stretch`
- 作用：在父容器分配给元素的矩形空间大于元素自身所需时，决定元素是靠边、居中还是拉伸填满。`Stretch` 是很多控件的默认值。

**外边距（Margin）**：
- 类型 `Thickness`，格式 `"左,上,右,下"`，也可单值（四边一样）、双值（左右/上下）。
- 作用：在元素周围制造空白间隔，把相邻元素推开。可用于制造控件间的呼吸感。

**尺寸约束（Min/MaxWidth, Min/MaxHeight）**：
- 优先于显式的 `Width`/`Height`，给你一个安全范围。
- 用 `MinWidth` 防止控件太窄内容被截断，用 `MaxWidth` 防止控件太宽导致阅读困难。
- 这是“不写死尺寸但要有底线”的最佳实践手段。

**显式尺寸（Width / Height）**：
- 谨慎使用。写了就剥夺了那个方向上的自适应能力。
- 适用于图标、分隔线、某些动画等确实需要精确固定大小的场景。

**Border 控件**：
- 严格不是面板，但总跟布局搭档出现。
- 给某个区域加上背景、边框、圆角。内部可包一个子元素（通常就是一个面板）。
- `Padding` 控制内容到边框内边缘的距离；`CornerRadius` 做圆角。

## 五、嵌套：化整为零的布局思维

单个面板能力有限，复杂界面靠的是**嵌套**——外层面板切大块，中层面板管区域，内层面板处理细节。这是一个分而治之的思维模式：

看到任何界面需求，先问自己：
1. **最外层怎么分大区？** 是上下分区（DockPanel）？还是左右分栏（Grid）？还是一溜排列（StackPanel）？
2. **每个大区内部需要什么次级结构？** 比如主内容区里面，是不是又有标题行、表单区和列表区？那就再放一个 Grid。
3. **最细节的排列用什么？** 比如一排按钮，用水平 StackPanel；一组文字+输入框，用两列 Grid。
4. **哪里需要用户可调？** 插入 GridSplitter。
5. **哪里需要视觉分组？** 用 Border 包裹加背景和边框。

这样一层层拆下来，再复杂的界面也能分解成你学过的这些面板的组合。嵌套不是炫技，而是工程上管理复杂度的必要手段。

## 六、选面板的速查指南

遇到布局需求时，按这个顺序思考：

| 需求特征 | 推荐面板 |
|---------|---------|
| 一维排列（上下或左右） | StackPanel |
| 一维排列 + 超出空间自动换行 | WrapPanel |
| 有明确的“顶、底、左、右”停靠区 | DockPanel |
| 二维表格，行列需对齐 | Grid |
| 等大格子矩阵 | UniformGrid |
| 精确坐标定位，图形绘制 | Canvas |
| 需要背景/边框/圆角装饰 | Border（包住面板） |

**实际中绝大多数界面**：顶层 `DockPanel` 或 `Grid` → 中层 `Grid` 细分 → 底层 `StackPanel` 或 `WrapPanel` 做细部排列。Canvas 按需在局部画布区域使用。

## 七、本章的能力检验

学完第 3 章，你应该能独立完成以下任务：

1. 搭建一个典型的三栏式布局（左导航、中内容、右属性），带可拖拽分割线。
2. 做一个设置对话框，标签和输入框严格对齐，支持窗口缩放。
3. 实现一个可折叠面板，点击按钮展开/隐藏详细内容，窗口自动调整大小。
4. 会使用 Margin、Alignment、Min/Max 尺寸精细调整控件位置和大小，而不是一律写死 Width/Height。
5. 理解 WPF 的测量和排列流程，知道为什么修改控件内容后布局会自动更新。
6. 知道何时该用 Grid 而不是多层 StackPanel 套娃，也知道何时用 Canvas 回到精确坐标。

如果你拿到一个界面截图，脑子里能自动把它拆成一层层的 WPF 面板嵌套，那你就真正把这一章消化透了。
