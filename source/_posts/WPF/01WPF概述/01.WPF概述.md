# 《WPF概述》

## Windows图形演化

这一小节主要是在讲，Windows系统里的图形界面是怎么一步一步发展过来的。了解了这个背景，你才能明白为什么 WPF 会诞生，它到底解决了什么老技术的痛点。

早些年，做 Windows 桌面程序基本就靠 User32 和 GDI/GDI+。User32 管窗口的框架、按钮、菜单这些控件，GDI 负责画图。GDI 这套东西从 Windows 1.0 就开始用了，简单理解就是“像素级绘图”——你想在屏幕上画个圆，就得告诉系统在哪个坐标画什么颜色的像素。这种方式一开始还行，但后来游戏、多媒体这些需求越来越强，GDI 就显得又慢又不灵活。特别是 3D 渲染、动画、透明效果，GDI 几乎做不了，或者做出来效果很卡顿。

于是微软就搞了 DirectX，专门针对游戏和高速图形。

### DirectX：新的图形引擎

DirectX 是一个底层的图形引擎，直接跟显卡驱动打交道，能调用显卡的硬件加速能力做复杂的 3D 渲染、纹理贴图、光影效果。它的出现彻底让 Windows 上的游戏画面质量飞跃了。

问题在于，DirectX 虽然很强大，但它是给游戏开发者用的，接口太底层了，写起来非常复杂。比如你想用 DirectX 显示一张图片，得写一大堆初始化设备、创建纹理、设置顶点缓冲区的代码，光是画一个简单的按钮就能让你写几百行。而传统桌面应用的开发者，习惯了拖个按钮控件就完事，谁受得了这种门槛？所以在很长一段时间里，DirectX 的强大能力和传统桌面开发的便利性是割裂的。游戏用 DirectX，传统软件还用 GDI/GDI+，两者井水不犯河水。

### 硬件加速与WPF

WPF 的出现打破了这堵墙。简单说，WPF 是“利用 DirectX 来做传统桌面应用”。它把 DirectX 的硬件加速能力封装到了高层框架里，你不需要懂什么顶点着色器、像素着色器，只是用 C# 写一段 XAML 或者代码，WPF 内部就自动通过 DirectX 渲染出来，而且全面享受显卡加速。

这意味着什么呢？以前你用 GDI 画个半透明窗口，系统会很吃力，因为 GDI 本身对透明支持就不好，而且几乎全靠 CPU 计算。而 WPF 里做透明、阴影、动画这些东西，显卡在硬件层面就能处理，CPU 占用很低，效果却很流畅。更关键的是，WPF 做 3D 也变得简单，直接把 3D 模型放到界面里，和按钮、文本框共存，这在以前是难以想象的。

所以，WPF 本质上就是把“游戏级图形能力”带进了普通桌面程序的世界。

## WPF：高级API

这一节强调了 WPF 是一个“高层 API”。什么叫做高层呢？就是它把很多底层的复杂操作给你藏起来了，你只需要面对一套统一、面向对象的编程模型。

比如你要显示一段文字，在 GDI 里你得关心字体句柄、设备上下文、绘制矩形，还要处理重绘消息，非常繁琐。而在 WPF 里，你只需定义一个 TextBlock 控件，设置字体、字号、颜色，往界面上一放就行了。WPF 自动帮你处理布局、自动重绘、自动适应不同分辨率。

而且 WPF 的控件体系非常丰富，除了传统的按钮、文本框、列表框，还有更高级的内容控件、布局面板、数据绑定、样式、模板、动画、多媒体等。最关键的是，WPF 整个控件树是可以完全自定义外观的——任意控件你都可以通过“模板”这个机制重新设计它长什么样，而不用改变它的行为逻辑。这跟以前 GDI 里完全自绘控件比起来，灵活性和复用性高太多了。

另外，WPF 把界面逻辑和业务逻辑分得很开，靠的是 XAML + 数据绑定 + MVVM 模式。你可以在 XAML 里声明式地设计界面，在 C# 里写业务逻辑，中间通过数据绑定让它们自动同步。这样界面设计人员和开发人员可以并行工作，代码维护起来也清晰。

## 分辨率无关性

这一部分可以说是 WPF 的一个核心卖点：让你的程序在不同 DPI 的屏幕上看起来一样大，而且不模糊。

老式的 Windows 程序是基于像素的。比如你设计界面时说这个按钮宽度 100 像素，在 96 DPI 的显示器上它看起来大小刚好，但到了高 DPI（比如 192 DPI）的显示器上，物理尺寸就缩成了原来的一半，字小得看不清，因为系统能看到的还是 100 个像素，而那个屏幕上的像素密度高，100 像素占的物理长度短了。虽然 Windows 可以开启缩放（比如 150%），但 GDI 窗口往往只会被系统强行拉伸，结果就是整个窗口变大了，可是文字和图像都虚了，因为只是简单地把位图放大。

WPF 从根本上解决了这个问题，因为它的度量单位不是像素，而是一种逻辑单位。

### WPF单位

WPF 里所有尺寸默认使用的单位是“设备无关像素”（device-independent pixel，简称 DIP），也常常叫 WPF 单位。1 个 WPF 单位被定义为 1/96 英寸。不管你的显示器实际 DPI 是多少，WPF 会保证 96 个 WPF 单位在屏幕上显示出来的物理长度就是 1 英寸。

这怎么做到的呢？WPF 会向系统查询当前的 DPI 设置，然后内部做一个换算：实际渲染时，把逻辑单位转换成真正要占用的物理像素。如果你的系统 DPI 是 96，那 1 个 WPF 单位就是 1 个物理像素；如果系统 DPI 是 192，那么 1 个 WPF 单位就会占用 2 个物理像素。这样，你定义宽度为 96 的按钮，在任何屏幕上物理大小都是 1 英寸，而且因为 WPF 渲染的是矢量图形（后面讲），放大后依然清晰。

### 系统DPI

系统 DPI 其实就是一个比值，它告诉系统和应用程序，屏幕的像素密度是多少。但现实很复杂：Windows 允许用户设置缩放比例（如 125%、150%），这个缩放比例本质上就是修改了系统的 DPI 值。Windows 会假设标准屏是 96 DPI，如果用户设了 150%，意味着系统报告给应用的 DPI 就是 96 × 1.5 = 144 DPI。

WPF 就是依靠这个系统 DPI 来实现自动缩放：因为它总是按照 1/96 英寸的逻辑单位来布局，当 DPI 变了，它自动调整实际占用的像素数，所以在高 DPI 下界面不会变小也不会模糊，而是和普通屏上“一样大”，但更细腻。

当然，这里有一个坑：如果程序没有显式声明自己支持高 DPI，Windows 可能会对老程序使用 DPI 虚拟化，也就是强行把物理分辨率降低后报告给程序，然后程序输出后再由系统放大，这就会导致模糊。所以 WPF 程序一般要在应用程序清单里声明 DPI 感知，才能充分利用分辨率无关性。

### 位图和矢量图形

分辨率无关性还有一个重要的技术基础：WPF 大量使用矢量图形。传统的 GDI/GDI+ 主要基于位图，位图是由固定数量的像素点组成的，放大后就变成马赛克。而矢量图形是用数学公式描述的几何图形（比如“从坐标A到坐标B画一条线，颜色红，线宽2”），不管放大多少倍，它都能重新计算并渲染出清晰的边缘。

WPF 里的控件外观、形状、文字都是矢量，所以当 DPI 变化导致元素尺寸变大时，WPF 是重新绘制这些矢量内容，而不是拉伸一张位图。这就是为什么 WPF 应用在高 DPI 下依然清晰锐利。

当然，WPF 也支持位图图像，对于位图，如果你希望它也能在放大时清晰，就要提供更高分辨率的版本，或者使用 WPF 的图像处理功能（比如使用 DecodePixelWidth 控制加载尺寸）。但框架本身的设计意图是尽量用矢量、少用位图，这样才能最大限度发挥分辨率无关的优势。

## WPF体系结构

WPF 的体系结构可以分成好几层，从上到下越来越底层。了解这个结构有助于你明白 WPF 是怎么运作的。

最顶层就是你写的托管代码（C#、VB.NET等）和 XAML。XAML 在编译时会被转换成 BAML（二进制版的 XAML），然后嵌入到程序集中，运行时由 WPF 解析。

接下来是 WPF 的核心层（**PresentationFramework、PresentationCore、WindowsBase** 这三个 DLL）。**PresentationFramework** 包含了高层控件、布局、数据绑定、样式、模板等等；**PresentationCore** 包含更基础的图形元素、视觉对象、动画等；**WindowsBase** 是最基础的，提供依赖项属性系统、路由事件系统、线程模型等。

再往下是 **milcore**，这个组件非常关键，它是个非托管的 DLL（用 C++ 编写），负责调用 DirectX 引擎。milcore 是 WPF 和 DirectX 之间的桥梁，它把上层的绘制指令翻译成 Direct3D 的指令，因此性能极高。

milcore 下面就是 DirectX 和 Windows 的图形驱动模型。最终，显卡驱动负责执行这些指令并将画面显示在屏幕上。

**为什么要分层这么清楚呢？**
因为这样托管层可以专注于给开发者提供好用、强大的功能，而非托管层则可以集中精力优化性能，直接和硬件打交道。而且这种分层把界面的表现和底层的渲染分开了，将来底层图形技术升级（比如从 DirectX 9 升级到 DirectX 11），只需要修改 milcore，上面托管代码不变，程序依然能受益。

另外，milcore 内还包含了 **“视觉对象”层（Visual Layer）** ，这是 WPF 几乎所有控件的基类所在。所有的 2D 绘制最终都会生成一个 **“视觉树”（Visual Tree）**，由 milcore 高效遍历并渲染。你的控件都是在视觉树上，控件之间可以叠加、裁剪、变换，一切尽在硬件加速中。

## 小结

总结一下第1章内容：

- Windows 图形从古老的 GDI 到针对游戏的 DirectX，最后到 WPF 把 DirectX 的高性能引入普通桌面应用，完成了一次升级。
- WPF 是一个高级 API，封装了底层图形细节，提供了控件、布局、数据绑定、样式模板等一大堆现代软件所需要的特性，让开发变得更简单、更高效。
- WPF 天生支持分辨率无关性，因为它采用逻辑单位（1/96 英寸）和系统 DPI 自动换算，同时内部大量使用矢量图形，保证在高 DPI 屏幕上不仅尺寸合适，而且清晰锐利。
- WPF 整个体系结构分托管 API 层、核心渲染层（milcore）和 DirectX 底层，各层各司其职，既保证开发效率，又保证图形性能。

这一章算是给整本书打了个底，让你先建立起对 WPF 整体定位和核心优势的认知。后面章节会详细展开怎么用这些特性去构建真正强大的桌面应用。
