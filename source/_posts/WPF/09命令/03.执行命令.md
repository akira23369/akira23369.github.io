# 笔记43《命令》9.3节——执行命令

## 9.3 执行命令

9.1 节给你建立了命令的“世界观”——四个角色各司其职。9.2 节把底层的接口和类拆开看了——`ICommand`、`RoutedCommand`、`RoutedUICommand`、命令库。现在是时候把这套模型**跑起来**了：一个命令从用户点击按钮到最终执行，中间具体发生了什么？各个环节怎么配置？

这一节就是把命令执行的完整链路从头到尾走一遍。你会看到命令源怎么发出指令、命令绑定怎么桥接逻辑、多个入口怎么指向同一个命令、命令的文字怎么自动显示、怎么在代码中直接调用命令、怎么禁用命令，以及哪些控件天生就自带命令处理能力。

---

### 9.3.1 命令源

**命令源**就是触发命令的那个东西。用户碰了它，它就喊一声“执行命令！”。在 WPF 里，任何实现了 `ICommandSource` 接口的控件都可以当命令源。这个接口定义了三个属性：

```csharp
public interface ICommandSource
{
    ICommand Command { get; }       // 要触发的命令对象
    object CommandParameter { get; } // 传给命令的参数
    IInputElement CommandTarget { get; } // 命令在谁身上执行
}
```

WPF 自带的命令源主要有：

- **`Button`**（按钮）
- **`MenuItem`**（菜单项）
- **`ToggleButton`**（开关按钮）
- **`RadioButton`**（单选按钮）
- **`Hyperlink`**（超链接）
- **`InputBinding`** 及其子类（`KeyBinding` 键盘快捷键、`MouseBinding` 鼠标手势）

这些控件都在它们的类定义里直接暴露出 `Command`、`CommandParameter`、`CommandTarget` 三个依赖项属性，可以直接在 XAML 里赋值。

#### 按钮作为命令源

最常用的命令源就是按钮。按钮被点击时，内部逻辑大致是这样的：

1. 读取自己的 `Command` 属性，拿到命令对象。
2. 调用命令的 `CanExecute(CommandParameter)` 判断自己该不该亮。
3. 如果 `CanExecute` 返回 `false`，按钮自动变灰（`IsEnabled = false`）。
4. 如果 `CanExecute` 返回 `true`，按钮可点击，用户点了之后按钮调用 `command.Execute(CommandParameter)`。
5. 按钮还订阅 `command.CanExecuteChanged` 事件，一旦命令状态变了，立刻重新执行步骤 2~4。

这些都是按钮内部写好了的，你不需要写任何代码。

```xml
<Button Command="ApplicationCommands.Copy" 
        CommandParameter="Hello"
        CommandTarget="{Binding ElementName=myTextBox}" />
```

- `Command`：指向 `ApplicationCommands.Copy` 这个预置命令。
- `CommandParameter`：传一个字符串作为参数（复制命令其实不需要参数，这是演示）。
- `CommandTarget`：告诉命令“在 myTextBox 上执行”（即复制 myTextBox 里选中的文字）。如果不设，默认目标就是当前键盘焦点所在的元素。

#### 菜单项作为命令源

`MenuItem` 也是实现 `ICommandSource` 的，用法和按钮几乎一模一样：

```xml
<Menu>
    <MenuItem Header="编辑">
        <MenuItem Command="ApplicationCommands.Copy" />
        <MenuItem Command="ApplicationCommands.Paste" />
        <MenuItem Command="ApplicationCommands.Cut" />
    </MenuItem>
</Menu>
```

`MenuItem` 同样会自动根据命令的 `CanExecute` 来灰化自己，不需要额外代码。

**一个细节**：如果你没有给 `MenuItem` 指定 `Header`，而绑定的命令是 `RoutedUICommand`（有 `Text` 属性），`MenuItem` 会**自动把命令的 `Text` 作为自己的 Header 显示**。所以上面的 `Copy` 命令，菜单项会自动显示 "Copy"。这就是 9.2.3 节说的 `Text` 属性的作用。

#### 快捷键作为命令源

把快捷键（键盘手势）绑定到命令，用的是 `KeyBinding`。`KeyBinding` 是 `InputBinding` 的子类，也实现了 `ICommandSource`。

通常把 `KeyBinding` 加到窗口或某个控件的 `InputBindings` 集合里：

```xml
<Window.InputBindings>
    <KeyBinding Key="S" Modifiers="Control" Command="ApplicationCommands.Save" />
    <KeyBinding Key="O" Modifiers="Control" Command="ApplicationCommands.Open" />
</Window.InputBindings>
```

当用户按下 `Ctrl+S` 时，`KeyBinding` 调用 `ApplicationCommands.Save.Execute(...)`。

**注意**：很多内置命令（如 `ApplicationCommands.Copy`）已经在 `RoutedCommand.InputGestures` 里预定义了默认快捷键。当你把命令绑定加到窗口上时，这些默认手势可能自动生效（取决于命令目标的 `CommandBindings` 是否激活了它们）。但手动加 `KeyBinding` 是最明确的方式。

#### 命令源如何自动更新状态

命令源（按钮、菜单项）在内部订阅了命令的 `CanExecuteChanged` 事件。每次事件触发，源就重新调一次 `CanExecute`，然后更新自己的 `IsEnabled`。这一切全自动，不需要你写 `myButton.IsEnabled = ...`。

但这里有一个重要的坑：**命令源必须在视觉树中，且命令的 `CanExecute` 结果依赖于焦点或选中状态时，才能得到及时更新。** 因为 `CommandManager` 的自动查询机制是基于 UI 线程的调度，并且主要响应输入事件和焦点变化。如果你的命令状态变化是由纯数据驱动的（比如后台数据加载完成、网络状态变化），`CommandManager` 不会自动感知——你需要手动触发 `CanExecuteChanged`。

### 9.3.2 命令绑定

命令源负责“发令”，但命令本身可以没有执行逻辑（比如 `RoutedCommand`）。**命令绑定（Command Binding）** 就是给命令提供实际执行逻辑的那个东西。

#### CommandBinding 的结构

`CommandBinding` 是一个类，它把三样东西绑在一起：

- **`Command` 属性**：指向一个具体的命令对象（如 `ApplicationCommands.Copy`）。
- **`Executed` 事件**：命令被执行时调用的处理程序。
- **`CanExecute` 事件**：查询命令是否可用时调用的处理程序。

```csharp
CommandBinding binding = new CommandBinding(
    ApplicationCommands.Copy,          // 命令
    Copy_Executed,                      // 执行处理
    Copy_CanExecute                     // 可用性判断
);

private void Copy_Executed(object sender, ExecutedRoutedEventArgs e)
{
    // 执行复制逻辑
    MessageBox.Show("复制命令被触发了");
}

private void Copy_CanExecute(object sender, CanExecuteRoutedEventArgs e)
{
    // 判断复制是否可用
    e.CanExecute = myTextBox != null && myTextBox.SelectionLength > 0;
}
```

#### 命令绑定放在哪？

命令绑定需要加到**某个 UIElement 的 `CommandBindings` 集合**里。这个集合是 `UIElement` 类的一个属性。你可以把它加在窗口上、某个容器上、或者直接加在控件自身上。

```xml
<Window.CommandBindings>
    <CommandBinding Command="ApplicationCommands.Copy" 
                    Executed="Copy_Executed"
                    CanExecute="Copy_CanExecute" />
</Window.CommandBindings>
```

**选择挂在哪个元素上很重要**，因为它决定了路由命令的传播范围。回想 9.2.2 节——`RoutedCommand` 的执行是通过冒泡路由事件沿控件树传播的。事件从命令目标开始往上冒，沿途寻找绑定了该命令的 `CommandBinding`。所以：

- 如果你把命令绑定挂在 `Window` 上，窗口范围内任意焦点元素触发该命令，都能冒泡到窗口，找到绑定，执行逻辑。
- 如果你把命令绑定挂在一个 `TextBox` 上，只有焦点在这个 `TextBox` 内（且命令目标指向它或它的子元素）时，才能找到这个绑定。

**所以一般推荐的策略**：把应用级别的命令绑定挂在顶层窗口上。如果某个控件需要覆盖默认行为（比如自定义文本框的复制逻辑），就在那个控件上单独加一个同命令的绑定。

#### Executed 和 CanExecute 的事件参数

**ExecutedRoutedEventArgs**（`Executed` 事件的参数）：
- `Command`：当前执行的命令。
- `Parameter`：命令参数。
- `Source`：事件源（触发绑定的元素）。
- `OriginalSource`：原始源。

**CanExecuteRoutedEventArgs**（`CanExecute` 事件的参数）：
- `Command`：当前查询的命令。
- `Parameter`：命令参数。
- `CanExecute`：你要设的 `bool` 值。默认为 `false`，设成 `true` 表示命令可用。
- `ContinueRouting`：如果设为 `true`，即使当前绑定的 `CanExecute` 返回了结果，事件还会继续沿树传播，给后续绑定一个机会。默认 `false`，一旦有人处理就停止。

#### 命令绑定和内置命令处理

很多 WPF 原生控件（`TextBox`、`RichTextBox`、`PasswordBox`、`FlowDocumentReader` 等）在自己的类内部已经预设了常见命令的命令绑定。比如 `TextBox` 内部就绑定了 `Copy`、`Cut`、`Paste`、`Undo`、`Redo`、`SelectAll` 等命令。所以当你焦点在文本框里，按 `Ctrl+C` 执行 `ApplicationCommands.Copy` 时，你不需要自己写任何命令绑定——文本框自己处理了。

如果控件自带处理，你通常不需要再加绑定。但如果你**想覆盖**控件的默认行为（比如自定义复制逻辑，附带格式处理），可以在它的父容器上加一个同命令的绑定，并在 `CanExecute` 里设 `e.ContinueRouting = false`，让新绑定截胡。

### 9.3.3 使用多命令源

同一个命令，可以有**多个命令源**同时指向它。这是命令模式相对于传统事件处理的杀手锏之一。一个典型的“保存”功能，触发入口可能有：

- 工具栏上的保存按钮
- 菜单栏里的“保存”菜单项
- 右键菜单里的“保存”
- 快捷键 `Ctrl+S`

在没有命令的时代，每个入口都要单独写 `Click` 事件，然后在事件处理里调同一个方法。有了命令，你只需要让所有这些入口的 `Command` 属性指向同一个命令对象即可。

```xml
<!-- 工具栏按钮 -->
<Button Command="ApplicationCommands.Save" Content="保存" />

<!-- 菜单栏 -->
<MenuItem Command="ApplicationCommands.Save" />

<!-- 键盘快捷键 -->
<KeyBinding Key="S" Modifiers="Control" Command="ApplicationCommands.Save" />
```

**所有命令源共享命令的 `CanExecute` 状态**。如果你通过命令绑定让“保存”命令在文档无修改时不可用，那么工具栏按钮、菜单项、快捷键会**同时变灰**。不用分别控制。

**命令参数可以各自不同**。即使同一个命令，不同的命令源可以传不同的 `CommandParameter`：

```xml
<Button Command="ApplicationCommands.Open" CommandParameter="data1.txt" Content="打开数据1" />
<Button Command="ApplicationCommands.Open" CommandParameter="data2.txt" Content="打开数据2" />
```

两个按钮触发同一个命令，但传的文件路径不同。

### 9.3.4 微调命令文本

有时候你不希望菜单项上显示命令的默认英文 `Text`（比如你做的中文软件，希望显示中文）。或者同一个命令在不同的菜单项上要显示不同的文字。这时候你就需要覆盖命令的默认文本。

最简单的方式：**在命令源上显式设置 `Content`（或 `Header`）**。

```xml
<MenuItem Command="ApplicationCommands.Copy" Header="复制" />
<Button Command="ApplicationCommands.Copy" Content="复制到剪贴板" />
```

一旦你显式设置了 `Content` 或 `Header`，控件的默认自动文字机制就被覆盖了。这是最简单也最推荐的做法。

对于 `RoutedUICommand`，它本身有一个 `Text` 属性。但这个属性是只读的（从命令注册时就定死了），你不能在运行时改它的 `Text`。如果你需要让命令本身携带本地化文本，有两种路：

1. **不用 `RoutedUICommand`，自己写一个带文本的自定义命令类。**
2. **在命令源上覆盖文字，不做在命令层。** 这是 90% 场景下的正确选择。

---

### 9.3.5 直接调用命令

你不一定非要用控件来触发命令。在代码里，你也可以直接调用命令的 `Execute` 方法。

```csharp
// 直接执行打开命令
ApplicationCommands.Open.Execute("data.txt", myTextBox);
```

第一个参数是命令参数（可传 `null`），第二个参数是命令目标（在哪个元素上执行）。

对于自定义的 `RelayCommand`：

```csharp
SaveCommand.Execute(null);
```

直接调 `Execute` 会立即执行命令逻辑。这在某些自动化流程、初始化操作、或从非 UI 代码中触发操作时很有用。

#### 区别：Execute vs RaiseEvent

如果你在处理一个 `RoutedCommand`，你还可以走“路由事件”的方式——手动构造 `ExecutedRoutedEventArgs` 并调用 `UIElement.RaiseEvent`。这比直接调 `Execute` 更底层，一般只在自定义控件内部才用到。常规用法直接用命令对象的 `Execute` 方法就行。

---

### 9.3.6 禁用命令

有两种层面禁用命令：

**层面一：命令本身的 `CanExecute` 返回 `false`**

这是最正统的禁用方式。命令绑定的 `CanExecute` 处理程序返回 `false`，命令源自动变灰。命令仍然在，只是暂时不可用。

```csharp
CommandBinding binding = new CommandBinding(
    ApplicationCommands.Save,
    (s, e) => { /* 保存 */ },
    (s, e) => { e.CanExecute = IsDocumentDirty; }  // 文档没改就不让保存
);
```

**层面二：直接禁用命令源**

你也可以直接设 `button.IsEnabled = false`。这和命令的 `CanExecute` 机制是分开的——即使命令说自己可用，按钮被手动禁用了就不可点。通常不推荐这种绕过命令的手动控制，因为它破坏了命令的状态统一性。但有时临时需要禁用某个特定入口（比如正在处理中，防止重复点击），直接控制 `IsEnabled` 更直接。

**层面三：移除命令绑定**

如果你把某个命令的绑定从元素上移除，那个元素就不再认识这个命令了。命令依然存在，但在这个元素的范围内没有任何绑定能处理它，导致 `CanExecute` 走了一圈返回 `false`，所有源都灰掉。这是比较极端的手段，一般不这么干。

**层面四：用 `CommandManager.InvalidateRequerySuggested` 强制刷新**

有时候你改了底层状态，但 WPF 的命令管理器没有立刻重新查询所有命令的 `CanExecute`。你可以手动调用：

```csharp
CommandManager.InvalidateRequerySuggested();
```

这会强制所有活动命令源的 `CanExecute` 都被重新查询一遍，UI 立刻更新。这在纯数据驱动状态变化（如属性更改）时特别有用。

### 9.3.7 具有内置命令的控件

很多 WPF 控件天生就**内置了某些命令的处理逻辑**。你不需要写命令绑定，它们自己就会响应命令。这些控件通常已经预设了 `CommandBindings`。

#### TextBox 内置的命令

`TextBox`（及其基类 `TextBoxBase`）内置了大量命令的绑定，包括：

- `ApplicationCommands.Copy`：复制选中文字到剪贴板。
- `ApplicationCommands.Cut`：剪切选中文字。
- `ApplicationCommands.Paste`：从剪贴板粘贴。
- `ApplicationCommands.Undo`：撤销上一次操作。
- `ApplicationCommands.Redo`：重做被撤销的操作。
- `ApplicationCommands.Delete`：删除选中文字（不复制）。
- `ApplicationCommands.SelectAll`：全选所有文字。
- `EditingCommands` 系列：`ToggleBold`、`ToggleItalic`、`AlignLeft` 等（仅 `RichTextBox`）。

这就是为什么你把焦点放在文本框里，按 `Ctrl+C` 就能复制，而不需要你写任何代码。

#### 其他有内置命令的控件

- **`RichTextBox`**：和 `TextBox` 基本相同，还额外支持 `EditingCommands` 的字体格式命令。
- **`PasswordBox`**：只支持有限的剪贴板命令（出于安全考虑，不支持复制密码到剪贴板，但支持粘贴）。
- **`FlowDocumentReader` / `FlowDocumentScrollViewer`**：支持缩放、查找、打印等文档导航命令。
- **`Frame` / `NavigationWindow`**：支持 `NavigationCommands`（前进、后退、刷新等）。
- **`ListBox` / `ListView`**：支持部分 `ComponentCommands`（如 `MoveUp`、`MoveDown`、`ScrollPageUp` 等）。

#### 如何知道一个控件支持哪些命令？

最直接的方法就是查 MSDN 文档中该控件的“命令”部分。也可以写代码去遍历控件的 `CommandBindings` 集合来看。

#### 和自定义命令绑定的关系

你可以在控件已有内置绑定的基础上再加自己的绑定。但要注意：如果你为同一个命令在**同一元素**上同时加了内置绑定和你自己的绑定，你自己的绑定会**附加**在列表后面，`Executed` 事件会先走内置的，再走你自己的（除非你在内置处理里设了 `e.Handled = true` 阻断了路由）。通常情况下，如果你只是想拦截命令并替换行为，最好在控件的**父容器**上加绑定，而不是直接往控件自身上加。这样你的绑定在冒泡的更上层把命令接住。

## 9.3 节总结

9.3 节把命令执行的完整链路从头讲到了尾：

**命令源（9.3.1）**：
- `ICommandSource` 接口定义了命令源的三个属性：`Command`、`CommandParameter`、`CommandTarget`。
- 常见命令源：`Button`、`MenuItem`、`ToggleButton`、`RadioButton`、`KeyBinding`。
- 命令源自动订阅 `CanExecuteChanged`，自动更新 `IsEnabled`。
- 快捷键通过 `KeyBinding` 绑定到命令，放在 `InputBindings` 集合里。

**命令绑定（9.3.2）**：
- `CommandBinding` 把命令和实际的 `Executed`、`CanExecute` 处理程序桥接起来。
- 绑定需要挂在某个 `UIElement` 的 `CommandBindings` 集合上。
- 挂在哪个元素决定了路由命令的传播范围（从命令目标往上冒，找到第一个匹配绑定即执行）。
- 很多 WPF 原生控件自带预设命令绑定（如 `TextBox` 支持 Copy/Cut/Paste）。

**多命令源（9.3.3）**：
- 多个按钮、菜单项、快捷键可以指向同一个命令。
- `CanExecute` 状态自动同步到所有命令源，统一变灰。
- 不同命令源可以传不同的 `CommandParameter`。

**微调命令文本（9.3.4）**：
- 命令源（按钮、菜单项）如果显式设了 `Content`/`Header`，覆盖命令的默认 `Text`。
- `RoutedUICommand.Text` 是只读的，本地化文字建议在命令源层覆盖。

**直接调用命令（9.3.5）**：
- 代码里可以直接调 `command.Execute(parameter, target)`。
- 用于自动化流程或非 UI 触发场景。

**禁用命令（9.3.6）**：
- 最正统方式：命令绑定的 `CanExecute` 返回 `false`。
- 也可手动设命令源的 `IsEnabled`，或调用 `CommandManager.InvalidateRequerySuggested()` 强制刷新。

**具有内置命令的控件（9.3.7）**：
- `TextBox`、`RichTextBox`、`PasswordBox`、`FlowDocumentReader`、`Frame` 等控件自带大量常用命令的绑定。
- 你可以通过父容器上的 `CommandBinding` 覆盖或增强内置行为。

学完这一节，你已经能熟练地把命令和界面上的按钮、菜单、快捷键全面连接起来，让它们自动协同工作。最后一节 9.4 会进入命令的高级应用——自定义命令的高级用法、命令参数、跟踪与翻转命令等。
