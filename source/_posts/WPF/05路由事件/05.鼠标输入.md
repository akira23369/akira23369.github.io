## 鼠标输入

键盘输入讲完了，现在轮到桌面应用里频率最高、事件种类最多的交互设备——**鼠标**。鼠标和键盘虽然都是输入设备，但在 WPF 的事件模型里有几个关键差异：

1. **键盘事件需要焦点**——只有拥有焦点的元素才能收到键盘事件。**鼠标事件不需要焦点**——鼠标点在哪个元素上，事件就从哪个元素开始路由，无论这个元素有没有焦点。

2. **键盘事件的原始源比较单纯**——焦点元素就是事件源。**鼠标事件的原始源要经过命中测试**——系统会根据鼠标光标的坐标，从视觉树上找到最上层的可见元素，这个元素就是 `OriginalSource`。

3. **鼠标事件带坐标信息**——`MouseEventArgs` 提供了 `GetPosition` 方法，可以获取鼠标相对于任何元素的坐标位置。这是做拖拽、绘图、点击热区等功能的基础。

4. **鼠标有“捕获”机制**——你可以强制让某个元素持续接收鼠标事件，即使光标已经移出了它的边界。这个机制在拖拽操作里至关重要。

5.5 节就分三个主题把鼠标输入讲透：鼠标单击事件（5.5.1）、鼠标捕获（5.5.2）、鼠标拖放（5.5.3）。

### 鼠标单击

鼠标单击不仅仅是“点了一下”这么简单。WPF 把一次完整的鼠标点击拆成了好几个细粒度的事件，让你可以在不同阶段插入逻辑。同时，WPF 还有检测双击的机制，以及一个更高级的 `Click` 事件（`ButtonBase` 提供）。

#### 鼠标按钮事件的分类

鼠标上的按钮不止一个（左键、右键、中键，还有侧键），WPF 为每个按钮都提供了独立的事件对：

- **左键**：`MouseLeftButtonDown` / `MouseLeftButtonUp`
- **右键**：`MouseRightButtonDown` / `MouseRightButtonUp`
- **中键（滚轮按下）**：`MouseMiddleButtonDown` / `MouseMiddleButtonUp`
- **扩展按钮（XButton）**：`MouseXButtonDown` / `MouseXButtonUp`（带有 `XButton` 属性区分 XButton1 还是 XButton2）

所有这些事件都是路由事件，都有对应的隧道版本（加上 `Preview` 前缀）。隧道从根向目标走，冒泡从目标向根走。

**事件参数类型**

`MouseButtonEventArgs`，继承自 `MouseEventArgs`。核心属性：

- **`MouseButton`**：告诉你这次事件是哪个按钮触发的（`Left`、`Right`、`Middle`、`XButton1`、`XButton2`）。
- **`ClickCount`**：你在一定时间内在同一位置点击了几次。1 表示单击，2 表示双击，3 表示三击…… WPF 会自动统计并设置这个值。这让你可以非常方便地区分单击和双击，不需要自己写定时器判断。
- **`GetPosition(IInputElement relativeTo)`**：获取鼠标当前相对于某个元素的坐标（返回 `Point`，包含 X 和 Y）。如果传 `null`，则返回相对于屏幕左上角的绝对坐标。这个方法是非常常用的，用来判断用户点在了元素的哪个位置。
- **`Source` / `OriginalSource`**：事件源（逻辑源 / 命中测试的原始物理源）。鼠标事件里，`OriginalSource` 特别重要，因为鼠标点的可能是控件模板内部的子元素。

**ClickCount 的用法**

如果你想同时处理单击和双击，可以直接在 `MouseLeftButtonDown` 里根据 `ClickCount` 区分：

```csharp
private void OnMouseLeftButtonDown(object sender, MouseButtonEventArgs e)
{
    if (e.ClickCount == 1)
    {
        // 单击逻辑
    }
    else if (e.ClickCount == 2)
    {
        // 双击逻辑
    }
}
```

注意：`ClickCount` 只在 `MouseDown` 事件里有意义，`MouseUp` 事件里的 `ClickCount` 始终为 0。

**一个完整的鼠标按下到松开的过程**

当用户在某个元素上按下鼠标左键再松开，事件触发顺序如下：

1. **`PreviewMouseLeftButtonDown`**（隧道）从窗口根传到目标元素。
2. **`MouseLeftButtonDown`**（冒泡）从目标元素冒回窗口根。
3. （中间可能穿插 `MouseMove` 事件，如果用户移动了鼠标）
4. **`PreviewMouseLeftButtonUp`**（隧道）从窗口根传到目标元素。
5. **`MouseLeftButtonUp`**（冒泡）从目标元素冒回窗口根。
6. 如果这是一个有效的“点击”（按下和松开在同一个元素上），并且这个元素是 `ButtonBase`（如 `Button`、`CheckBox`、`RadioButton`），还会额外触发一个更高级的 **`Click`** 事件。

**`Click` 事件 vs 鼠标按钮事件**

很多初学者闹不清什么时候用 `Click`，什么时候用 `MouseLeftButtonDown`。规则很简单：

- **`Click`** 是高级语义事件，表示“这个按钮被点击了”。它经过了内部处理（按下+松开在同一个元素上才算），并且支持键盘触发（当按钮有焦点时按回车或空格也能触发 `Click`）。**如果你只是想响应按钮被点，用 `Click` 就够了。**
- **`MouseLeftButtonDown`** 是底层输入事件，只关心物理鼠标左键按下了。不管你是不是在同一个元素上松开的，只要按了就触发。**在以下场景你需要用底层鼠标事件**：
  - 需要知道点击的具体坐标（`GetPosition`）。
  - 需要区分单击和双击（`ClickCount`）。
  - 需要拦截鼠标事件不让它冒泡（比如在自定义控件的内部处理原始输入，阻止 `Click` 被触发）。
  - 需要在非按钮控件上响应鼠标点击（比如图片、自定义绘图面板）。

#### 鼠标移动事件

除了按钮按下和松开，鼠标移动也是高频事件：

- **`MouseMove`**（冒泡） / **`PreviewMouseMove`**（隧道）

**触发频率**：鼠标每移动一个像素就会触发一次（甚至更高频率）。所以 `MouseMove` 的事件处理程序**必须轻量**，不能在里面做耗时计算，不然界面会卡顿。如果只是需要偶尔检测位置，建议用定时器取样，而不是直接堆在 `MouseMove` 里。

**事件参数类型**：`MouseEventArgs`（没有 `ClickCount`，但有 `GetPosition`）。

**`MouseEnter` 和 `MouseLeave`**

这两个事件不需要按按钮，只要光标进入或离开元素的边界就会触发：

- **`MouseEnter`**：光标进入元素时触发。**没有隧道版本**，直接冒泡。
- **`MouseLeave`**：光标离开元素时触发。同样没有隧道版本。

它们经常用来做悬停效果——比如鼠标移到图片上显示一个阴影边框，移走就消失。不过 WPF 有更优雅的触发器（`Trigger`）来做悬停效果，不需要在事件里写代码。但有些复杂的交互逻辑还是需要在 `MouseEnter`/`MouseLeave` 里实现。

**鼠标滚轮事件**

- **`MouseWheel`**（冒泡） / **`PreviewMouseWheel`**（隧道）

**事件参数类型**：`MouseWheelEventArgs`，继承自 `MouseEventArgs`。核心属性 `Delta`：表示滚轮滚动了多少“刻度”。向上滚动是正值（一般是 120），向下滚动是负值（一般是 -120）。你可以用这个值来做缩放（Ctrl+滚轮）或滚动自定义面板。

```csharp
private void OnMouseWheel(object sender, MouseWheelEventArgs e)
{
    if (Keyboard.Modifiers == ModifierKeys.Control)
    {
        // Ctrl+滚轮：缩放
        double scale = e.Delta > 0 ? 1.1 : 0.9;
        myCanvas.Scale *= scale;
        e.Handled = true;
    }
}
```

### 捕获鼠标

鼠标捕获是 WPF 鼠标系统里一个非常重要、但又容易被忽视的机制。它解决了一个根本性的矛盾：**拖拽操作需要持续接收鼠标事件，但鼠标可能会移出目标元素的边界。**

#### 问题场景

假设你做了一个可拖拽的滑块控件。用户用鼠标点住滑块的把手，开始拖动。拖动的过程中，光标很可能移出把手元素的边界（因为拖得比较快，或者滑块本身窄）。如果按照正常的事件路由规则，一旦光标移出把手元素的边界，`MouseMove` 事件就不再发给把手了，而是发给光标当前所在的那个新元素。你的滑块就把用户跟丢了，拖拽就会断掉。

这在所有拖拽类操作里都是致命的问题——滑块、滚动条、窗口标题栏拖动、控件拖拽重排、绘图工具里的画笔……

#### 解决方法：鼠标捕获

WPF 提供了一个 **“鼠标捕获”** 机制：一个元素可以主动“捕获”鼠标，之后无论鼠标光标移到哪里（甚至移出窗口外、移到别的应用程序上），所有鼠标事件都强制发送给这个捕获元素，直到它主动释放捕获或用户松开所有鼠标按钮。

**捕获鼠标**：调用元素的 `CaptureMouse()` 方法。

```csharp
myElement.CaptureMouse();
```

**释放捕获**：调用 `ReleaseMouseCapture()`。

```csharp
myElement.ReleaseMouseCapture();
```

**检查当前谁捕获了鼠标**：通过 `Mouse.Captured` 属性。

```csharp
if (Mouse.Captured == myElement)
{
    // myElement 当前持有鼠标捕获
}
```

#### 捕获的典型流程

以滑块拖拽为例：

```csharp
private bool _isDragging = false;

private void OnThumbMouseDown(object sender, MouseButtonEventArgs e)
{
    _isDragging = true;
    (sender as UIElement).CaptureMouse();  // 开始捕获
    e.Handled = true;
}

private void OnThumbMouseMove(object sender, MouseEventArgs e)
{
    if (_isDragging)
    {
        // 即使光标移出了 thumb 元素，这里仍然能收到 MouseMove
        Point pos = e.GetPosition(parentPanel);
        UpdateSliderPosition(pos);
    }
}

private void OnThumbMouseUp(object sender, MouseButtonEventArgs e)
{
    if (_isDragging)
    {
        _isDragging = false;
        (sender as UIElement).ReleaseMouseCapture();  // 释放捕获
        e.Handled = true;
    }
}
```

这个模式在 WPF 的自定义控件里极其常见——`ScrollBar`、`Slider`、`GridSplitter`、窗口标题栏拖拽全是用这个套路实现的。

#### 捕获的规则和注意事项

1. **一次只能有一个元素捕获鼠标**。调用 `CaptureMouse()` 会强制夺走之前的捕获。如果你要释放捕获，只能用 `ReleaseMouseCapture()`，或者用户松开所有鼠标按钮时 WPF 会自动释放捕获。

2. **自动释放**：当用户松开所有鼠标按钮（`MouseLeftButtonUp` 等）时，WPF 会自动调用 `ReleaseMouseCapture()`，所以通常你不需要显式释放，但显式释放是个好习惯。

3. **检测捕获丢失**：有时候操作系统或者其他程序会抢走鼠标捕获。`UIElement` 提供了 `LostMouseCapture` 事件，你可以监听这个事件来做清理：

```csharp
myElement.LostMouseCapture += (s, e) => {
    _isDragging = false;
    // 清理状态
};
```

4. **捕获和命中测试**：鼠标被捕获后，所有鼠标事件仍然会先经过正常的隧道/冒泡过程，只是目标元素被强制为捕获元素，且 `OriginalSource` 可能是捕获元素内部的某个子元素。`MouseEventArgs` 仍然有正确的坐标信息。

5. **禁用捕获标记**：如果你在父容器上监听了 `MouseMove`，但不想受子元素捕获的影响，可以用 `AddHandler` 的 `handledEventsToo` 参数处理已经被标记为已处理的事件。

### 鼠标拖放

拖放（Drag and Drop）是桌面应用里非常直观的一种交互：用户可以用鼠标把数据从一个地方“拖”到另一个地方。比如把文件拖进程序窗口打开、在列表里拖拽重排项目、从工具箱拖控件到设计器上。WPF 把拖放封装成了一个完整的子系统，用起来比原始鼠标事件方便得多。但它的底层仍然依赖鼠标捕获和路由事件。

#### 拖放的核心概念

拖放操作涉及两个角色：

- **拖放源（Drag Source）**：数据从哪儿来。你在这个元素上按下鼠标，开始拖动。
- **拖放目标（Drop Target）**：数据放到哪儿去。你把数据拖到这个元素上释放。

#### 拖放的流程

一次完整的拖放操作分成以下几步：

**第一步：开始拖放（在拖放源上）**

在 `MouseMove` 事件里，检测用户是否在按住鼠标左键的同时移动了足够距离（这叫做“拖拽阈值”，避免用户只是轻微晃动就触发拖放）。如果满足条件，调用 `DragDrop.DoDragDrop` 方法启动拖放。

```csharp
private Point _startPoint;

private void OnPreviewMouseLeftButtonDown(object sender, MouseButtonEventArgs e)
{
    _startPoint = e.GetPosition(null);  // 记录按下点
}

private void OnPreviewMouseMove(object sender, MouseEventArgs e)
{
    if (e.LeftButton == MouseButtonState.Pressed)
    {
        Point currentPoint = e.GetPosition(null);
        Vector diff = _startPoint - currentPoint;
        // 移动超过拖拽阈值（水平和垂直都超过 SystemParameters.MinimumHorizontalDragDistance）
        if (Math.Abs(diff.X) > SystemParameters.MinimumHorizontalDragDistance ||
            Math.Abs(diff.Y) > SystemParameters.MinimumVerticalDragDistance)
        {
            // 开始拖放
            object dragData = "要传递的数据";  // 可以是任何对象
            DragDropEffects result = DragDrop.DoDragDrop(
                this,          // 拖放源元素
                dragData,      // 要传递的数据
                DragDropEffects.Copy | DragDropEffects.Move  // 允许的操作
            );
            // result 是拖放结束后执行的操作（Copy/Move/None 等）
        }
    }
}
```

`DragDrop.DoDragDrop` 是一个同步方法——它会阻塞，直到拖放操作结束（用户松开了鼠标或者按 Esc 取消）。所以调用完这个方法后，你就可以根据返回值决定要不要从源数据里删除被移走的东西。

**第二步：拖放过程中（在潜在目标上）**

当用户拖着数据经过其他元素时，可能的目标元素会收到一系列事件。为了让一个元素能够成为拖放目标，它的 `AllowDrop` 属性必须设为 `true`（默认是 `false`）。

```xml
<Border AllowDrop="True" Background="LightYellow" />
```

设置 `AllowDrop="True"` 后，这个元素就能收到以下拖放相关事件：

- **`DragEnter`**：拖放的数据第一次进入目标元素边界时触发。
- **`DragOver`**：数据在目标元素上方悬停时持续触发（类似 `MouseMove`）。
- **`DragLeave`**：数据离开目标元素边界时触发。
- **`Drop`**：用户在目标元素上松开了鼠标按钮，数据被“投放”到这里。

这四个事件都是路由事件（冒泡策略，有对应的隧道版本），事件参数类型是 `DragEventArgs`。`DragEventArgs` 提供：

- **`Data`**：一个 `IDataObject` 对象，里面装着拖放源传过来的数据。你可以用 `e.Data.GetData(typeof(XXX))` 或者 `e.Data.GetDataPresent(typeof(XXX))` 来取数据。
- **`Effects`**：允许的操作类型（`DragDropEffects.Copy`、`Move`、`Link`、`None` 等）。目标可以在 `DragEnter` 或 `DragOver` 里设置这个属性，告诉系统和源“我接受什么样的操作”。这个设置会影响光标图标的显示（显示复制箭头还是移动箭头）。
- **`KeyStates`**：当前修饰键状态（Ctrl/Alt/Shift），可以用来实现“按 Ctrl 时复制，不按时移动”的行为。

**完整的目标端示例**：

```csharp
// DragEnter: 检查数据类型，决定是否接受
private void OnDragEnter(object sender, DragEventArgs e)
{
    if (e.Data.GetDataPresent(typeof(string)))
    {
        e.Effects = DragDropEffects.Copy;  // 接受复制操作
    }
    else
    {
        e.Effects = DragDropEffects.None;  // 不接受
    }
    e.Handled = true;
}

// DragOver: 持续更新效果（比如按 Ctrl 切换复制/移动）
private void OnDragOver(object sender, DragEventArgs e)
{
    if (e.Data.GetDataPresent(typeof(string)))
    {
        if ((e.KeyStates & DragDropKeyStates.ControlKey) != 0)
        {
            e.Effects = DragDropEffects.Copy;
        }
        else
        {
            e.Effects = DragDropEffects.Move;
        }
    }
    e.Handled = true;
}

// Drop: 取数据，执行业务逻辑
private void OnDrop(object sender, DragEventArgs e)
{
    if (e.Data.GetDataPresent(typeof(string)))
    {
        string data = (string)e.Data.GetData(typeof(string));
        targetListBox.Items.Add(data);
        e.Handled = true;
    }
}
```

**第三步：拖放结束**

用户在目标上松开鼠标（或在非目标上松开，丢弃拖放），`DragDrop.DoDragDrop` 返回。返回值是实际执行的操作类型（`DragDropEffects.Copy` / `Move` / `None` 等）。源可以根据这个返回值决定后续操作（比如如果是 Move 就把源数据删掉）。

#### 拖放的数据传递

拖放不只是传字符串，你可以传任何 .NET 对象。`DoDragDrop` 的第二个参数是 `object` 类型，你传什么，那边 `e.Data.GetData(typeof(YourType))` 就能拿到什么。

WPF 还支持标准化的数据格式，用于和外部程序（比如文件管理器）交互：

- **`DataFormats.Text`**：纯文本。
- **`DataFormats.FileDrop`**：文件路径列表。当你从 Windows 资源管理器拖文件到你的程序窗口时，数据就是这个格式。
- **`DataFormats.Bitmap`**：图片数据。
- **`DataFormats.Html`**：HTML 格式文本。

你可以用 `DataObject` 类把数据包装好再传：

```csharp
DataObject dataObj = new DataObject();
dataObj.SetData(DataFormats.Text, "一段纯文本");
dataObj.SetData("MyCustomFormat", myCustomObject);
DragDrop.DoDragDrop(source, dataObj, DragDropEffects.Copy);
```

接收方可以通过 `e.Data.GetFormats()` 查看所有可用格式，然后选择自己认识的格式来取数据。

#### 拖放和鼠标捕获的关系

`DragDrop.DoDragDrop` 内部会自动管理鼠标捕获——在拖放过程中，WPF 接管了鼠标的控制权，这样才能让光标上的拖放效果图标正常显示，并且保证目标元素能收到 `DragEnter` 等事件。你在拖放过程中不应该再去手动调 `CaptureMouse()`。

## 总结

鼠标输入比键盘输入事件种类更多，但底层的路由机制你已经熟透了（隧道+冒泡，`Handled` 拦截），所以主要是记住每种事件的触发时机和参数含义。

**鼠标单击（5.5.1）**：
- 鼠标按钮事件：`MouseLeft/Right/Middle/XButtonDown`、`MouseLeft/Right/Middle/XButtonUp`。都有隧道 `Preview` 版本。
- `ClickCount`：区分单击/双击/三击。
- `GetPosition`：获取鼠标相对于某元素的坐标。
- `Click` 事件（`ButtonBase`）：高级语义事件，键盘也能触发。用它来响应按钮点击；用底层鼠标事件来获取坐标、做自定义拖拽、做特殊交互。

**鼠标移动与滚轮**：
- `MouseMove`：高频触发，处理要轻量。
- `MouseEnter`/`MouseLeave`：光标进出边界，常用于悬停效果。
- `MouseWheel`：滚轮滚动，`Delta` 为正向上滚，为负向下滚。

**鼠标捕获（5.5.2）**：
- 解决问题：拖拽时鼠标移出目标元素后仍然能收到 `MouseMove` 事件。
- 用法：`element.CaptureMouse()` 开始捕获，`element.ReleaseMouseCapture()` 释放捕获。
- WPF 在用户松开所有鼠标按钮时会自动释放捕获。
- `LostMouseCapture` 事件用于处理捕获被意外夺走的清理。

**鼠标拖放（5.5.3）**：
- 高层拖放系统，封装了原始鼠标事件。
- 源端：检测拖拽距离 → 调用 `DragDrop.DoDragDrop`（阻塞等待拖放结束）。
- 目标端：必须设 `AllowDrop="True"`，然后处理 `DragEnter`、`DragOver`、`DragLeave`、`Drop` 事件。
- 数据通过 `IDataObject` 传递，支持自定义对象和标准格式（文本、文件、图片等）。
- `e.Effects` 控制允许的操作类型（Copy/Move/Link），影响光标图标。`e.KeyStates` 提供修饰键状态。

鼠标输入是 WPF 交互系统里最高频的一块，几乎每个应用都会大量用到。掌握好鼠标事件、捕获和拖放这三板斧，你就能从容应对绝大部分桌面交互需求。
