## 键盘输入

前面把路由事件的机制、生命周期事件、输入事件的总体分类都讲完了。从这一节开始，咱们进入具体输入设备的事件细节。第一个要啃的就是**键盘输入**。

键盘输入和鼠标输入有一个最大的不同：**鼠标事件可以发生在任何看得见的元素上，但键盘事件必须有一个“接收者”——也就是当前拥有焦点的那个元素。** 你敲一下键盘，系统必须先搞清楚“谁在听”，然后才能把键值送过去。这就注定了学键盘输入，你不仅要学事件本身，还得把**焦点（Focus）** 这个概念彻底搞懂。

5.4 节就分三块：5.4.1 讲按键事件（KeyDown、KeyUp、TextInput），5.4.2 深入焦点系统（逻辑焦点、键盘焦点、焦点导航），5.4.3 讲怎么主动查询键盘状态（比如按键是否还在按住、大写键有没有亮）。

---

### 处理按键事件

WPF 的键盘事件主要有三个：**`KeyDown`**、**`KeyUp`**、和 **`TextInput`**。前两个是路由事件（都有对应的隧道 Preview 版本 `PreviewKeyDown` / `PreviewKeyUp`），第三个 `TextInput` 是一个特殊的 CLR 事件（不是路由事件，但和键盘输入流程紧密相关）。

#### KeyDown 事件

当用户按下键盘上的任意一个键时触发。注意是“按下”那一瞬间触发，不是持续按住（按住不放会不断触发，但每次触发的 `IsRepeat` 属性为 `true`，见后文）。

**隧道版本**：`PreviewKeyDown`，从根向目标沿视觉树向下传播。
**冒泡版本**：`KeyDown`，从目标向根向上传播。

**事件参数类型**：`KeyEventArgs`。它有几个核心属性：

- **`Key`**：按下的具体键，类型是一个枚举 `System.Windows.Input.Key`。包括所有字母数字键（`Key.A`、`Key.D1` 等）、功能键（`Key.F1`~`Key.F12`）、修饰键（`Key.LeftCtrl`、`Key.LeftShift`、`Key.LeftAlt`、`Key.RightCtrl` 等）、方向键（`Key.Up`、`Key.Down`、`Key.Left`、`Key.Right`）、回车（`Key.Return`）、Esc（`Key.Escape`）、空格（`Key.Space`）、Tab、Delete、Back 等等。几乎你键盘上每一个物理按键都在这个枚举里有对应。
  
- **`KeyboardDevice`**：引发事件的键盘设备对象。一般桌面电脑只有一个物理键盘，但 WPF 支持多个键盘设备（如辅助输入设备），通过这个属性可以区分。

- **`IsRepeat`**：一个 `bool`，表示这次按键是否是因为用户持续按住某个键而产生的“重复按键”。Windows 系统本身有按键重复机制：按住一个键不放，过一小会儿就会自动以一定频率连续触发 `KeyDown`。如果你不想处理重复事件（比如做游戏时按住方向键移动，你已经通过计时器或别的方式处理了，不想被系统重复事件干扰），可以检查 `IsRepeat` 为 `true` 时直接 `return` 跳过。

- **`IsDown`**：按键当前是否处于按下状态。在 `KeyDown` 里这个肯定是 `true`……等一下，你可能会疑惑：`KeyUp` 也有 `IsDown` 属性吗？是的，`KeyUp` 事件里 `IsDown` 返回 `false`。

- **`IsUp`**：和 `IsDown` 相反。

- **`IsToggled`**：对于开关类按键（如 Caps Lock、Num Lock、Scroll Lock），返回当前是否处于锁定打开状态。注意：这个属性在 `KeyDown` 事件里反映的是**按下后**的状态——你按下 CapsLock 键，`KeyDown` 触发时 `IsToggled` 已经是反转后的值了。

- **`Timestamp`**：事件发生的时间戳（毫秒级）。

**示例：拦截 Esc 键关闭窗口**

```csharp
public MainWindow()
{
    InitializeComponent();
    // 在窗口上监听 PreviewKeyDown 隧道事件，确保最早拿到
    this.AddHandler(Window.PreviewKeyDownEvent, 
        new KeyEventHandler(OnPreviewKeyDown), true);
}

private void OnPreviewKeyDown(object sender, KeyEventArgs e)
{
    if (e.Key == Key.Escape)
    {
        this.Close();
        e.Handled = true;  // 阻止事件再往下传，其他元素收不到这个 Esc
    }
}
```

这里在窗口上挂 `PreviewKeyDown` 是为了隧道优先级：窗口是根，它是视觉树最顶端，所以它是**第一个**收到 `PreviewKeyDown` 的。如果等到冒泡的 `KeyDown`，`TextBox` 之类的焦点元素可能已经把事件吞掉了。

**示例：检测 Ctrl+S 组合键**

组合键检测也经常在 `KeyDown` 或 `PreviewKeyDown` 里完成：

```csharp
private void OnKeyDown(object sender, KeyEventArgs e)
{
    // 方式一：检查 Key 和 Keyboard.Modifiers
    if (e.Key == Key.S && Keyboard.Modifiers == ModifierKeys.Control)
    {
        SaveDocument();
        e.Handled = true;
    }

    // 方式二：检查具体哪个 Ctrl 键是否按下（适用于区分左右 Ctrl 的场景）
    if (e.Key == Key.S && (Keyboard.IsKeyDown(Key.LeftCtrl) || Keyboard.IsKeyDown(Key.RightCtrl)))
    {
        SaveDocument();
        e.Handled = true;
    }
}
```

`Keyboard.Modifiers` 返回当前按下的修饰键组合（`Ctrl`、`Alt`、`Shift`、`Windows`），它是一个位标志枚举，你可以用 `==` 直接比较。

#### KeyUp 事件

按键松开时触发。隧道版 `PreviewKeyUp`，冒泡版 `KeyUp`。参数也是 `KeyEventArgs`。

用的频率比 `KeyDown` 少很多，但在以下场景很有用：

- **游戏的按键释放**：比如松开方向键停止移动。
- **完成某次操作的结尾处理**：比如做一个“按住 Shift 显示高级选项”的功能，`KeyDown` 时显示，`KeyUp` 时隐藏。
- **检测按键的持续时间**：记录 `KeyDown` 和 `KeyUp` 的时间戳差值，算出用户按了多久。

#### TextInput 事件

`TextInput` 是一个很特殊的事件：它**不是路由事件**，是直接定义在 `UIElement` 上的普通 CLR 事件。但因为它和键盘输入流程高度相关，所以放在这里讲。

**触发时机**：在 `KeyDown` 事件**之后**，当 WPF 判断这次按键确实产生了一个可显示的文本字符时触发。比如你按下 A 键，先触 `KeyDown`，然后触 `TextInput`。如果你按下 F1 键，触发 `KeyDown`，但不会触发 `TextInput`，因为 F1 不产生文本。

**事件参数类型**：`TextCompositionEventArgs`。核心属性：

- **`Text`**：用户输入的文本字符串。对于普通按键这就是一个字符（如 "a"、"5"），但对于输入法（IME）可能是一段完整的组合文字（比如中文输入法打完拼音按空格确认后，`Text` 可能是 "你好" 两个字符）。
- **`SystemText`**：系统文本。一般和 `Text` 一样。
- **`ControlText`**：控件文本。某些输入法用于特殊格式。
- **`Handled`**：和路由事件的 `Handled` 类似，设为 `true` 表示这个文本输入已被处理，防止它再被其他监听器处理。

**为什么要有 TextInput？**

你可能会问：不是有 `KeyDown` 吗，为什么还要 `TextInput`？两个原因：

1. **输入法支持**：`KeyDown` 只能告诉你按了哪个物理键，但中文、日文、韩文等输入法需要组合多个按键才能生成一个或多个字符。`TextInput` 给你的不是“按了什么键”，而是“最终输入了什么文本”。这是处理文本输入的正确层级。

2. **逻辑分离**：`KeyDown` 关注物理按键（适合快捷键、游戏控制），`TextInput` 关注文本结果（适合文本框内容处理、富文本编辑器）。

**在什么地方处理 TextInput？**

通常你会在 `TextBox` 这类文本控件的 `TextChanged` 事件里做输入验证和格式化，很少直接处理 `TextInput`。但如果要做一个自定义的文本编辑器（比如富文本、代码编辑器），你可能会挂 `TextInput` 事件来拦截或修改用户的文本输入。

**TextInput 与 `KeyDown` 的顺序**

用户按下一个字符键（比如 "A"）：

1. `PreviewKeyDown`（隧道）从根传到焦点元素。
2. `KeyDown`（冒泡）从焦点元素冒回根。
3. 如果 `KeyDown` 没有被标记为 `Handled = true`，WPF 内部判断这个键产生文本字符。
4. 触发 `TextInput` 事件（直接事件，不沿树传播）。
5. （如果有 `KeyUp`，后面触发 `PreviewKeyUp` → `KeyUp`）

如果你在 `KeyDown` 里设了 `e.Handled = true`，后续的 `TextInput` 就不会触发了——这可以用于屏蔽某些按键的文本输入。

### 焦点

键盘输入的前提是“有个元素在接收”。这个接收者就是**拥有焦点（Focus）的元素**。焦点是 WPF 输入系统里和路由事件同等重要的一个基础机制。搞不清楚焦点，你的键盘事件可能就死活收不到。

#### 什么是焦点？

焦点就是当前正在等待接收键盘输入的那个元素的标识。在 Windows 的宏观层面，只有一个窗口是“活动窗口”；在 WPF 的微观层面，这个活动窗口内部**最多只能有一个元素拥有键盘焦点**。

拥有焦点的元素：
- 会收到所有的键盘事件（`KeyDown`、`KeyUp`、`TextInput`）。
- 通常会有视觉上的焦点指示器（比如 `Button` 上的虚线框、`TextBox` 里闪烁的光标）。

**逻辑焦点 vs 键盘焦点**

WPF 把焦点分成了两个层面来管理：

- **键盘焦点（Keyboard Focus）**：指当前**真正**能接收键盘输入的那一个元素。整个应用程序全局只有一个键盘焦点。用 `Keyboard.FocusedElement` 获取。

- **逻辑焦点（Logical Focus）**：在一个“焦点范围（Focus Scope）”内，记忆最近拥有键盘焦点的元素。当焦点离开这个焦点范围，又回来后，逻辑焦点会指示“该把键盘焦点还给谁”。

这个拆分是为了解决什么实际问题呢？典型的例子就是**多个容器切换焦点**。比如你做了一个窗口，左边是菜单，右边是工具栏，中间是文档区。如果用户从菜单切出去干别的事，再点回来，菜单应该记住之前选中的那个菜单项；工具栏也该记住；文档区也该记住。如果没有逻辑焦点，一旦键盘焦点离开一个区域，这个区域就会忘记谁曾是焦点。

WPF 的解决方式：把一个大界面划分成多个**焦点范围（Focus Scope）**，每个焦点范围独立维护自己的逻辑焦点。典型的就是：

- `Window` 本身是一个焦点范围。
- 每个 `Menu` 是一个焦点范围。
- 每个 `ToolBar` 是一个焦点范围。
- 每个 `Frame`（用于页面导航）是一个焦点范围。

当你在这个范围内按 Tab 移动键盘焦点时，逻辑焦点跟着同步更新；当键盘焦点切到别的范围，再切回来时，WPF 自动把键盘焦点恢复到该范围之前记下的逻辑焦点元素上。这一切对用户是透明的，但对开发者来说，理解逻辑焦点和键盘焦点的区别很重要。

**获取和设置焦点**

- **获取当前键盘焦点元素**：`IInputElement focusedElement = Keyboard.FocusedElement;`
- **设置键盘焦点到某个元素**：`myTextBox.Focus();` 或者 `Keyboard.Focus(myTextBox);`
- **获取某个焦点范围（如 Window）的逻辑焦点元素**：`IInputElement logicalFocus = FocusManager.GetFocusedElement(this);`（`this` 是焦点范围容器，比如 Window）
- **设置逻辑焦点**：`FocusManager.SetFocusedElement(this, myTextBox);`

**焦点事件**

当焦点变化时，会触发一系列路由事件（全是冒泡策略，没有隧道版本）：

- **`GotFocus`**：元素自身获得了键盘焦点（事件源是这个元素）。
- **`LostFocus`**：元素自身失去了键盘焦点。
- **`GotKeyboardFocus`** 和 **`LostKeyboardFocus`**：这两个名字看起来是重复的，但在 WPF 中 `GotFocus` 和 `LostFocus` 是 `UIElement` 上的 CLR 事件，同时也是路由事件；而 `GotKeyboardFocus` 和 `LostKeyboardFocus` 是 `Keyboard` 类的附加事件。在实际开发中，你挂 `GotKeyboardFocus` 和 `LostKeyboardFocus` 附加事件更常用，因为它们可以在父容器上监听子元素的焦点变化。

```xml
<StackPanel Keyboard.GotKeyboardFocus="OnChildGotFocus">
    <TextBox />
    <TextBox />
</StackPanel>
```

#### Tab 键导航和焦点遍历

用户按 `Tab` 键（或 `Shift+Tab`）时，WPF 会自动把焦点从一个元素移到另一个元素。这种移动不是随机的，它有一套规则：

**TabIndex 属性**

每个控件都有一个 `TabIndex` 属性（定义在 `Control` 上），数值越小越先获得焦点。默认值是 `Int32.MaxValue`（可以理解为“排到最后”）。你可以显式设定 `TabIndex` 来控制 Tab 顺序：

```xml
<StackPanel>
    <TextBox TabIndex="2" />
    <Button TabIndex="1" />
    <ComboBox TabIndex="3" />
</StackPanel>
```

按 Tab 键时，焦点顺序是：Button → TextBox → ComboBox。

**KeyboardNavigation 类**

WPF 还提供了 `KeyboardNavigation` 附加属性，让你控制焦点在一个容器内如何导航。核心属性：

- **`KeyboardNavigation.TabIndex`**：和控件的 `TabIndex` 属性配合。
- **`KeyboardNavigation.TabNavigation`**：控制在一个容器内按 Tab 时焦点的行为模式。取值：
  - `Continue`：默认，正常按 TabIndex 顺序走。
  - `Cycle`：在这个容器内循环，焦点不会跑出容器。
  - `Contained`：焦点可以进入容器，但在容器内各元素间按 Tab 走，到了尽头不会自动出容器（需要用户手动点出去）。
  - `Once`：焦点能进入这个容器，但只有一次 Tab 机会（进入后无论怎么按 Tab 都不会在里面兜圈）。
  - `None`：Tab 键跳过这个容器内的所有元素。
  - `Local`：类似 Cycle，但只在本地焦点范围循环。

这些属性在你做一些复杂的自定义控件或限制焦点活动范围时非常有用。比如做出一个模态对话框，你不希望焦点在按 Tab 时跑到对话框外面的按钮上，就可以在对话框面板上设置 `KeyboardNavigation.TabNavigation="Cycle"`，把焦点锁在对话框内部循环。

**IsTabStop 属性**

如果某个控件你不想让它被 Tab 键选中（但仍然可以显示、可以点击），可以设置 `IsTabStop="False"`。不过这个控件仍然可以通过代码获得焦点。与之对应的是 `Focusable` 属性，设为 `false` 后这个控件完全不能获得焦点（点击、Tab、代码 `Focus()` 都不行）。

### 获取键盘状态

有时候你不只是在事件处理里被动接收按键信息，你需要在某个时候**主动查询**键盘的当前状态。比如在做游戏或动画时，你需要在每一帧判断“方向键是否正在被按住”，或者检查“大写键现在亮没亮”。

WPF 提供了静态类 `Keyboard`，让你可以随时获取当前键盘的状态。

#### `Keyboard.IsKeyDown(Key key)`

判断某个键当前是否处于按下状态。

```csharp
if (Keyboard.IsKeyDown(Key.LeftShift) || Keyboard.IsKeyDown(Key.RightShift))
{
    // Shift 键正在被按住
}
```

这个方法在你需要做“持续按下”的动作时很有用。比如一个绘图工具，用户按住 Shift 画直线，你不能只在 `KeyDown` 事件里设一个 bool 标志然后等 `KeyUp` 清除，因为如果用户切出程序再切回来，你可能就漏掉了 `KeyUp` 事件，导致标志位永远卡在 `true`。用 `Keyboard.IsKeyDown` 是每次都直接问硬件状态，不依赖事件维护的标志位，更稳健。

#### `Keyboard.IsKeyToggled(Key key)`

判断开关类按键的锁定状态（Caps Lock、Num Lock、Scroll Lock）。

```csharp
if (Keyboard.IsKeyToggled(Key.CapsLock))
{
    // 大写锁定已开启
}
```

你可以用它来做状态条上的指示灯，或者在输入前判断默认大小写状态。

#### `Keyboard.Modifiers`

前面用过了，获取当前按下的修饰键组合（`Ctrl`、`Alt`、`Shift`、`Windows`）。这是一个静态属性，随时可用。

```csharp
ModifierKeys currentModifiers = Keyboard.Modifiers;
if (currentModifiers == (ModifierKeys.Control | ModifierKeys.Shift))
{
    // 同时按下了 Ctrl 和 Shift
}
```

#### `Keyboard.GetKeyStates(Key key)`

这个方法比 `IsKeyDown` 和 `IsKeyToggled` 更底层，返回一个 `KeyStates` 枚举（标志位组合），可以同时获取“按下/松开”和“锁定/未锁定”两种状态：

```csharp
KeyStates states = Keyboard.GetKeyStates(Key.CapsLock);
if ((states & KeyStates.Down) != 0)
{
    // CapsLock 键当前正被按住（物理按下中）
}
if ((states & KeyStates.Toggled) != 0)
{
    // CapsLock 处于锁定开启状态
}
```

这在需要同时判断多个状态时比较有用。

#### `Keyboard.FocusedElement`

获取当前拥有键盘焦点的元素（前面讲过了）。和键盘状态查询一起用，比如判断“当前是否在一个 TextBox 内按了回车”：

```csharp
if (e.Key == Key.Return && Keyboard.FocusedElement is TextBox)
{
    // 在文本框里按了回车
}
```

#### `Keyboard.PrimaryDevice`

获取主键盘设备对象。通过它你可以拿到更详细的设备信息，比如 `KeyboardDevice.ActiveSource`（当前输入源）、`KeyboardDevice.Target`（当前焦点元素）等。一般应用程序开发用不到这个层级，做自定义键盘处理框架时可能会接触到。

## 总结

键盘输入一节把 WPF 中与键盘相关的所有核心知识全串起来了：

**按键事件**：
- `KeyDown`：按键按下时触发。用于快捷键、游戏控制、非文本类按键检测。有隧道版 `PreviewKeyDown`。
- `KeyUp`：按键松开时触发。用于动作结束控制、按键时长计算。有隧道版 `PreviewKeyUp`。
- `TextInput`：有文本字符产生时触发（`KeyDown` 之后）。用来做文本级处理，支持输入法。不是路由事件。
- 重要规则：`Preview` 隧道先走（根→目标），然后冒泡（目标→根）。`Handled = true` 可拦截传播。
- `KeyEventArgs` 核心属性：`Key`、`IsRepeat`、`IsDown/IsUp`、`IsToggled`、`KeyboardDevice`。
- `TextCompositionEventArgs` 核心属性：`Text`。

**焦点**：
- 键盘事件只发给拥有焦点的元素。
- 逻辑焦点（Focus Scope 内记住的最后焦点）和键盘焦点（全局唯一的真实输入接收者）两层管理。
- 设置焦点：`element.Focus()` / `Keyboard.Focus(element)`。
- 获取焦点：`Keyboard.FocusedElement` / `FocusManager.GetFocusedElement(scope)`。
- 焦点变化事件：`GotFocus`/`LostFocus`（直接），`Keyboard.GotKeyboardFocus`/`LostKeyboardFocus`（附加，可冒泡监听到子级）。
- Tab 导航：`TabIndex` 控制顺序，`KeyboardNavigation.TabNavigation` 控制容器内行为，`IsTabStop` 决定是否被 Tab 访问。

**键盘状态查询**：
- 静态类 `Keyboard` 提供主动查询能力。
- `IsKeyDown`：某键是否正被按住。
- `IsKeyToggled`：开关键（Caps Lock 等）的锁定状态。
- `Modifiers`：当前修饰键组合（Ctrl/Alt/Shift/Windows）。
- `GetKeyStates`：底层状态位查询。

学完这一节，你应该对键盘事件和焦点系统已经心里有底了。后面 5.5 节会进入鼠标输入，鼠标事件也有捕获、拖放等独特机制，但路由框架你已经轻车熟路，学起来会非常快。
