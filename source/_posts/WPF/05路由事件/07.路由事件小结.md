## 一、路由事件为什么要存在？

传统的 .NET 事件在扁平对象模型里工作得很好——谁订阅谁处理，直来直去。但 WPF 的界面是**一棵控件树**，在这种树形结构里，传统事件暴露了三个大问题：

**1. 父元素需要感知子元素的事件。** 比如工具栏里有 20 个按钮，难道要给每个按钮都单独挂一个 Click 处理程序吗？直觉上你会想在工具栏这个父容器上挂一个监听就够了，但传统事件不支持“事件往上传递”。

**2. 多层元素需要依次处理同一个事件。** 用户点了一下鼠标，这个点击可能同时需要被目标元素自己、它的父容器、祖容器、甚至窗口级别的东西处理。传统事件没法让事件沿树传播、每层都有机会插手。

**3. 处理顺序不好控制。** 如果同一个事件有多个层级都想管，谁先谁后？传统事件没有“传播路径”的概念。

路由事件的解决方案本质上就一条：**事件不再只停留在事件源上，而是沿着控件树向上（或向下）传播，传播路径上的每一个元素都有机会处理它。** 这就是“路由”两个字的含义——事件像快递包裹一样按照指定路线在控件树上传递。

## 二、路由事件怎么定义和引发？

定义路由事件和定义依赖项属性非常相似，都不是普通的 C# 语法，而是需要向 WPF 的全局系统“注册”。

**第一步：注册。** 用 `EventManager.RegisterRoutedEvent` 方法，指定事件名称、路由策略（冒泡 Bubble / 隧道 Tunnel / 直接 Direct）、委托类型、所有者类型。注册后得到一个静态只读的 `RoutedEvent` 字段。这个字段就是后续所有操作的身份证。

```csharp
public static readonly RoutedEvent MyClickEvent =
    EventManager.RegisterRoutedEvent(
        "MyClick", RoutingStrategy.Bubble,
        typeof(RoutedEventHandler), typeof(MyControl));
```

**第二步：写 CLR 事件包装器。** 为了让 C# 代码能用 `+=` 和 `-=` 订阅，需要一个标准的 C# 事件语法包装，里面调的是基类的 `AddHandler` 和 `RemoveHandler` 方法。

```csharp
public event RoutedEventHandler MyClick
{
    add { AddHandler(MyClickEvent, value); }
    remove { RemoveHandler(MyClickEvent, value); }
}
```

**第三步：引发事件。** 在合适的时机构造 `RoutedEventArgs` 对象（或其子类），调用 `RaiseEvent` 方法。WPF 会根据注册时指定的路由策略，自动沿控件树传播事件。

```csharp
protected virtual void OnMyClick()
{
    RaiseEvent(new RoutedEventArgs(MyClickEvent, this));
}
```

**共享路由事件：** 和依赖项属性一样，路由事件也支持用 `AddOwner` 方法让多个类共用一个 `RoutedEvent` 对象，典型就是那些定义在 `UIElement` 上的输入事件，各种控件通过 `AddOwner` 共享使用。

## 三、事件路由的三种策略

路由事件的“路由”二字，核心就是三种传播策略：

**冒泡（Bubble）**：事件从事件源开始，沿着控件树一层层向上传播，直到树根。这是最常用的策略。父容器可以统一处理所有子元素的同类事件。`e.Handled = true` 可以中途截断传播。

**隧道（Tunnel）**：事件从控件树的根开始，沿着树一层层向下传播，直到事件源。隧道事件的命名以 `Preview` 开头（`PreviewMouseLeftButtonDown`、`PreviewKeyDown` 等）。它的目的是给祖先元素一个“在目标之前拦截”的机会——比如在窗口层级拦截 `Esc` 键关闭窗口，不让底下的文本框先吞掉事件。

**直接（Direct）**：事件只在事件源上触发，不沿树传播。行为和传统 .NET 事件一样。一些不需要传播的内部事件会用这个策略。

**隧道和冒泡的关系：** 绝大多数输入事件都是成对出现的——先走隧道（Preview 版本）从根到目标，再走冒泡版本从目标回根。隧道给你“拦截优先”，冒泡给你“处理优先”。两者在传播路径上是独立的，隧道被标记为 `Handled` 并不自动阻止对应的冒泡事件触发。

## 四、事件参数与事件处理

路由事件携带的信息封装在 `RoutedEventArgs`（及其各种派生类）里。这个类是理解路由事件运作的核心数据结构：

- **`RoutedEvent`**：当前正在传播的是哪个路由事件（指向那个静态的 `RoutedEvent` 字段）。
- **`Source`**：事件的逻辑源——引发事件的元素（逻辑树节点）。通常这是你关心的“谁发了事”。
- **`OriginalSource`**：事件的原始物理源——命中测试得到的最底层元素（可能是控件模板内部的子元素）。
- **`Handled`**：事件是否已被标记为处理完毕。设为 `true` 后，默认会阻止事件继续沿路由传播。

**处理已挂起的事件：** 如果某个事件在路径上已被标记 `Handled = true`，你仍然可以通过 `AddHandler(routedEvent, handler, handledEventsToo: true)` 来接收它。这用于“无论发生什么我都要知道”的全局监听场景。

**附加事件：** 本质上就是冒泡路由事件的另一种使用方式。事件由某个类定义，但另一类元素可以在 XAML 里用 `定义类.事件名="处理程序"` 的语法来监听。底层就是 `AddHandler`，只是给了 XAML 一个友好的语法糖。`Button.Click` 在 `StackPanel` 上的使用就是最典型的附加事件。

## 五、WPF 事件的分类

WPF 内置的事件可以清晰分为两大类：**生命周期事件**和**输入事件**。

**生命周期事件**反映一个元素或窗口从生到死的各个阶段：

- 所有 `FrameworkElement` 的通用事件：`Initialized`（属性加载完毕，但还没进视觉树）→ `Loaded`（加入视觉树，布局完成，这是初始化代码最常用的位置）→ `Unloaded`（从视觉树移除，资源清理）。
- `Window` 独有的生命周期事件，完整顺序为：构造函数 → `SourceInitialized`（底层 Win32 句柄就绪）→ `Initialized` → `Loaded` → `ContentRendered`（内容第一次渲染到屏幕）→ `Activated`（窗口成为活动窗口）→ [使用过程中 `Deactivated` 和 `Activated` 交替] → `Closing`（可设置 `Cancel = true` 阻止关闭）→ `Closed`（窗口已关闭，不可逆）→ `Unloaded`。

**输入事件**反映用户和程序的物理交互（鼠标、键盘、触控）。它们全部是路由事件，遵循隧道/冒泡的传播规则，并且每一种输入事件都有自己专用的 `EventArgs` 派生类携带上下文信息。

## 六、键盘输入的核心

键盘和鼠标最大的不同：键盘事件必须有一个接收者——**当前拥有焦点的元素**。

**焦点系统：** 全局只有一个键盘焦点（`Keyboard.FocusedElement`），但在每个焦点范围（Focus Scope，如 `Window`、`Menu`、`ToolBar`）内独立维护逻辑焦点。当焦点离开一个范围再回来时，逻辑焦点负责恢复原来的键盘焦点位置。设置焦点用 `element.Focus()` 或 `Keyboard.Focus()`。

**键盘事件：** `KeyDown`、`KeyUp`（路由事件，有 Preview 隧道版）和 `TextInput`（不是路由事件，但紧随 `KeyDown` 之后触发）。`KeyEventArgs` 提供 `Key`（按了什么键）、`IsRepeat`（是否因长按产生的重复事件）、`IsToggled`（开关类按键的锁定状态）、`KeyboardDevice` 等。`TextInput` 给出最终输入的文本字符，天然支持输入法。

**键盘状态主动查询：** 静态类 `Keyboard` 提供 `IsKeyDown`、`IsKeyToggled`、`Modifiers`、`GetKeyStates` 等方法，让你在任何时候（不依赖事件）都能知道键盘当前的状态。

**Tab 导航：** `TabIndex` 控制焦点顺序，`KeyboardNavigation.TabNavigation` 控制容器内的焦点循环行为，`IsTabStop` 决定控件是否被 Tab 键访问。

## 七、鼠标输入的核心

鼠标事件是桌面应用里频率最高的输入事件。和键盘不同，鼠标靠**命中测试**（根据光标坐标找视觉树上最上层的元素）来确定目标，不需要焦点。

**鼠标单击相关事件：**
- 各按钮独立的 Down/Up 事件：`MouseLeftButtonDown/Up`、`MouseRightButtonDown/Up`、`MouseMiddleButtonDown/Up`。都有 Preview 隧道版本。
- `Click` 事件（`ButtonBase` 提供）是高级语义事件，键盘也能触发（回车/空格）。大多数按钮响应用 `Click` 就够了；需要坐标、双击检测、自定义拖拽时才用底层鼠标事件。
- `ClickCount` 属性可直接区分单击、双击，不需要自己写定时器。
- `GetPosition(relativeTo)` 获取鼠标相对于任意元素的坐标。

**鼠标移动与滚轮：** `MouseMove`（高频触发，处理要轻量）、`MouseEnter`/`MouseLeave`（光标进出边界）、`MouseWheel`（滚轮，`Delta` 为正向上滚、为负向下滚）。

**鼠标捕获：** 拖拽操作的命根子。当一个元素调用 `CaptureMouse()` 后，无论鼠标光标移到哪里（甚至移出窗口），所有鼠标事件都强制发给它。用户松开所有鼠标按钮时自动释放捕获。`LostMouseCapture` 事件用于处理捕获被意外夺走的情况。`ScrollBar`、`Slider`、`GridSplitter`、窗口标题栏拖拽全都是用这个机制实现的。

**鼠标拖放：** WPF 封装好的高层拖放系统。源端在 `MouseMove` 里检测拖拽距离，调用 `DragDrop.DoDragDrop` 启动拖放（这是一个同步阻塞方法，直到用户松手或按 Esc 才返回）。目标端必须设 `AllowDrop="True"`，然后处理 `DragEnter`、`DragOver`、`DragLeave`、`Drop` 事件。数据通过 `IDataObject` 传递，支持自定义对象和标准格式（文本、文件路径、图片等）。`e.Effects` 控制允许的操作类型（复制/移动），影响光标图标。

## 八、多点触控输入的核心

触控输入不是简单的“手指当鼠标用”，它比鼠标丰富得多——支持多点同时触摸、连续手势、惯性物理。WPF 把触控分成四个层次，让你根据需求选择合适的抽象层级：

**层次一：原始触控。** 事件：`TouchDown`、`TouchUp`、`TouchMove`（都有 Preview 版）。一个手指一个事件，用 `TouchDevice.Id` 区分不同手指，用 `GetTouchPoint` 获取位置和接触面积。WPF 会自动把触控事件“提升”为鼠标事件（在 `TouchDown` 设 `Handled = true` 可阻止提升）。适合需要精确控制每个手指轨迹的场景（绘图、手写）。

**层次二：操作。** 事件：`ManipulationStarting`、`ManipulationDelta`、`ManipulationCompleted`。必须设置 `IsManipulationEnabled="True"` 启用。WPF 自动把原始多点触控翻译成平移（Translate）、缩放（Scale）、旋转（Rotate）三种高层操作。`ManipulationDeltaEventArgs` 提供 `DeltaManipulation`（每次微小变化量）和 `CumulativeManipulation`（累计变化量）以及 `Velocities`（速度）。适合照片查看器、地图、任何需要双指手势的场景。

**层次三：惯性。** 操作结束后，根据手指抬起时的速度，用动画模拟物理减速运动，让界面在手指离开后继续自然滑动直到停止。传统 WPF 需要用 `DoubleAnimation` 配合衰减公式手动实现惯性，但在概念上它属于操作的一个延续阶段。

**层次四：鼠标提升。** 自动把触控翻译为鼠标事件，让旧控件无需修改代码就能响应触控。这是默认行为，不需要写任何代码。

## 九、路由事件和依赖项属性的关系

路由事件和依赖项属性（第4章）是 WPF 的两大核心系统，它们经常被一起设计和配合使用：

- 依赖项属性用于“状态管理”（数据存储、绑定、动画、样式、继承、优先级），路由事件用于“行为通知”（交互、输入、生命周期）。
- 许多路由事件在处理过程中会修改依赖项属性的值——比如 `Slider` 在收到 `MouseMove` 事件时，会更新 `Value` 依赖项属性。
- 反过来，依赖项属性的变更通知回调（`PropertyChangedCallback`）里也可能引发路由事件。
- 附加事件和附加属性共享了“一个类定义的东西，可以被另一个类的实例使用”的设计哲学。

两者共同构成了 WPF 的“血液系统”：依赖项属性是数据流动的血管，路由事件是信号传递的神经。

## 十、现在你应该达到的状态

学完第 5 章，你应该能做到：

1. **解释路由事件的设计动机**，明白它相比传统事件的三个优势：父容器统一监听、多层依次处理、传播路径可控。

2. **独立注册和引发一个路由事件**，会写 `EventManager.RegisterRoutedEvent`，会写 CLR 事件包装器，会在合适的时机调用 `RaiseEvent`。

3. **分清三种路由策略**：冒泡（Bubble）从源到根，隧道（Tunnel）从根到源，直接（Direct）不传播。知道 Preview 前缀代表隧道事件。

4. **理解 `RoutedEventArgs` 的核心属性**：`RoutedEvent`（哪个事件）、`Source`（逻辑源）、`OriginalSource`（物理源）、`Handled`（截断标记）。知道 `sender` 不是事件源，而是挂载处理程序的元素。

5. **掌握附加事件**：本质就是冒泡路由事件，`定义类.事件名` 在 XAML 里是 `AddHandler` 的语法糖。

6. **清楚生命周期事件的顺序**：`Initialized` → `Loaded` → `Unloaded`。窗口特有的 `SourceInitialized`、`Activated`、`ContentRendered`、`Closing`、`Closed`、`Deactivated`。知道在哪写初始化代码（`Loaded`）、在哪写清理代码（`Unloaded`/`Closed`）、在哪拦截关闭（`Closing`）。

7. **熟悉键盘事件和焦点系统**：`KeyDown`/`KeyUp`/`TextInput` 的触发顺序和用途。逻辑焦点和键盘焦点的区别。怎么主动查询键盘状态。

8. **熟悉鼠标事件和捕获机制**：各种按钮的 Down/Up、`ClickCount` 双击检测、`GetPosition` 坐标查询、`MouseCapture` 的用法和释放规则、`DragDrop` 拖放系统的完整流程。

9. **了解触控输入的分层架构**：原始触控（`TouchDown/Up/Move` + `Id` 区分手指）、操作（`ManipulationDelta` 平移/缩放/旋转）、惯性（手动动画模拟）、鼠标提升（自动兼容老代码）。
