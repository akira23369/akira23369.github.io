## 多点触控输入

前面两节把键盘和鼠标讲完了。这两种设备统治了桌面应用几十年，WPF 对它们的支持已经非常成熟。但从 2007 年 iPhone 问世开始，整个计算机交互领域被一个全新的交互方式彻底改变了——**触控**。用手指直接在屏幕上点、滑、捏、转，不需要鼠标也不需要键盘。Windows 也从 Windows 7 开始加入了多点触控支持，WPF 在 .NET 4 时代正式把触控输入纳入了框架。

很多人觉得触控就是“把手指当鼠标用”，点一下就是左键单击，按住滑就是拖拽。但实际上触控比鼠标复杂得多，也丰富得多：

- **鼠标只有一个光标**，触控可以有**多个手指同时触摸**（多点触控）。
- **鼠标事件是离散的**（按下、松开），触控操作很多时候是**连续的手势**（捏合缩放、旋转、滑动平移）。
- **触控有压力、接触面积**等物理信息（取决于硬件），鼠标没有。
- **触控有惯性**：手指在屏幕上快速划过后抬起，内容应该继续滚一会儿才慢慢停下来，就像在物理世界里推一个东西。鼠标滚轮没有惯性语义。

WPF 为了同时支持简单的“手指当鼠标”和复杂的“手势操控”，把触控输入分成了**四个层次**。这一节 5.6 就是把这四层逐层拆开：5.6.1 讲这四层分别是什么以及为什么要分层，5.6.2 讲最底层的原始触控事件，5.6.3 讲中间层的操作（Manipulation）事件，5.6.4 讲最上层的惯性（Inertia）。

---

### 多点触控的输入层次

WPF 的触控输入不是一个扁平的事件列表，而是一个**从底层到高层的抽象栈**。每一层都建立在下层之上，给开发者提供不同粒度的控制力。

#### 四个层次

从底层到高层分别是：

**第一层：原始触控（Raw Touch）**
- 对应事件：`TouchDown`、`TouchUp`、`TouchMove`。
- 粒度：每一个手指的每一次接触、移动、抬起，都是一个独立的事件。
- 类比：相当于鼠标的 `MouseDown`、`MouseUp`、`MouseMove`，但是可以有多个手指同时进行。
- 谁用：开发自定义触控控件、绘图应用、需要精确处理每个手指轨迹的场景。

**第二层：操作（Manipulation）**
- 对应事件：`ManipulationStarting`、`ManipulationDelta`、`ManipulationCompleted`。
- 粒度：WPF 自动把多个手指的原始触控数据，翻译成**平移（Translate）、缩放（Scale）、旋转（Rotate）** 等高层次的手势操作。
- 类比：没有直接的鼠标类比，这更像一个手势识别引擎。
- 谁用：绝大多数触控应用，比如照片查看器（双指缩放旋转）、地图应用（拖拽平移、双指缩放）、可拖拽的面板。

**第三层：惯性（Inertia）**
- 不是独立的事件，而是操作的一个延续阶段。当用户在操作过程中手指抬起后，WPF 自动模拟物理惯性，让平移/缩放/旋转继续平滑地进行一段时间，慢慢减速直到停止。
- 谁用：任何需要“手指一滑内容继续滚”的场景，比如长列表滚动、地图平移、图片缩放后的自然停止。

**第四层：鼠标事件提升（Mouse Promotion）**
- WPF 会自动把触控输入“翻译”成对应的鼠标事件，这样老的用鼠标写的控件不用改任何代码，直接就能响应触控。
- 比如你用手指点了一个按钮，WPF 会依次触发 `TouchDown` → `MouseLeftButtonDown` → `Click`，老代码完全无感知。
- 这层是自动的，不需要开发者写额外代码，但理解这个机制能帮你解释一些奇怪的“双击触发两次”之类的问题。

#### 为什么要分层？

答案很简单：**不同的开发需求需要不同粒度的控制力。**

如果你在做一款绘图应用，需要跟踪用户每一根手指的精确轨迹，你就得用最底层的原始触控事件（`TouchMove`）来逐点画线。

如果你在做一款照片查看器，用户双指缩放旋转图片，你不需要自己写一堆三角函数去算两个手指之间的角度和距离变化——直接用操作事件（`ManipulationDelta`），WPF 已经帮你把原始坐标翻译成了 `Scale`、`Rotation`、`Translation`，你只要把这些值应用到图片的变换矩阵上就行。

如果你在做一款地图应用，用户手指一滑，地图应该继续滚动一段距离再慢慢停下，这时候你就开启惯性（Inertia），WPF 会模拟一个带摩擦力的减速运动，你不用自己写物理引擎。

这种分层设计让你可以**按需选择抽象层级**，简单需求用高层，复杂需求沉到底层。

### 原始触控

原始触控是触控输入体系的最底层。它直接报给每个手指的状态：什么时候按下的、什么时候抬起的、移动到了什么位置。

#### 触控事件

WPF 的原始触控事件有三个（都有对应的隧道 `Preview` 版本）：

- **`TouchDown`**（隧道 `PreviewTouchDown`）：手指接触屏幕。
- **`TouchUp`**（隧道 `PreviewTouchUp`）：手指离开屏幕。
- **`TouchMove`**（隧道 `PreviewTouchMove`）：手指在屏幕上移动。

这些事件都是路由事件，和鼠标事件一样走隧道+冒泡的传播路径。

#### 事件参数：`TouchEventArgs`

`TouchEventArgs` 提供了触控特有的信息：

- **`TouchDevice`**：触发事件的触控设备对象。通过它可以获取触控点的 ID（`Id`）——在多指触控时，每个手指都有一个唯一的 ID，你可以通过 ID 来区分和跟踪不同手指的轨迹。比如手指 1 按下，ID=0，手指 2 按下，ID=1，手指 1 抬起，ID=0 消失。
  
  ```csharp
  int fingerId = e.TouchDevice.Id;  // 当前手指的唯一标识
  ```

- **`GetTouchPoint(IInputElement relativeTo)`**：获取触控点相对于某元素的详细信息。返回一个 `TouchPoint` 对象，包含：
  - `Position`：触控点的坐标（`Point`）。
  - `Bounds`：接触区域（手指接触面近似为矩形，`Rect` 类型）。
  - `Size`：接触区域的大小。
  - `Action`：`Down`、`Move`、`Up` 枚举，表示这个触控点的动作类型。

- **`GetIntermediateTouchPoints`**：获取两次事件之间所有中间触控点（用于高精度轨迹记录）。因为 `TouchMove` 的触发频率有限，如果你的应用需要丝滑的笔画（比如手写签名），可以用这个方法拿到更精细的轨迹点。

#### 触控和鼠标的提升关系

这是新手最容易困惑的地方。WPF 默认会自动把触控事件“提升”为鼠标事件，这样旧的控件也能响应触控。具体来说：

1. 用户手指按下 → 触发 `TouchDown` → WPF 内部触发 `MouseLeftButtonDown`。
2. 用户手指移动 → 触发 `TouchMove` → WPF 内部触发 `MouseMove`。
3. 用户手指抬起 → 触发 `TouchUp` → WPF 内部触发 `MouseLeftButtonUp`。

这种提升是自动的，而且是**同步的**——在同一个处理管线里先后触发。

**如何禁用鼠标提升？**

有时候你不想要这种自动提升。比如你做了一款绘图应用，手指画线用的是 `TouchMove`，但鼠标事件也被触发了，可能导致一些你不想要的额外处理（比如触发了 `Click` 事件）。这时候可以设置：

```csharp
e.Handled = true;  // 在 TouchDown 里标记已处理
```

如果触控隧道事件被标记为 `Handled = true`，WPF 就**不会**再自动提升为鼠标事件了。

另一个更彻底的方式是设置 `Stylus.IsTouchFeedbackEnabled="False"` 或相关属性，但一般用 `Handled` 就够。

#### 多点触控的轨迹跟踪

跟踪多个手指的核心就是**用 `TouchDevice.Id` 区分不同手指**。每个手指从 `TouchDown` 到 `TouchUp`，`Id` 不变。你可以用一个字典来为每个手指存储状态：

```csharp
private Dictionary<int, Point> _activeFingers = new Dictionary<int, Point>();

private void OnTouchDown(object sender, TouchEventArgs e)
{
    int id = e.TouchDevice.Id;
    Point pos = e.GetTouchPoint(myCanvas).Position;
    _activeFingers[id] = pos;
    // 在这里开始追踪这个手指的轨迹
}

private void OnTouchMove(object sender, TouchEventArgs e)
{
    int id = e.TouchDevice.Id;
    if (_activeFingers.ContainsKey(id))
    {
        Point newPos = e.GetTouchPoint(myCanvas).Position;
        // 更新轨迹
        _activeFingers[id] = newPos;
    }
}

private void OnTouchUp(object sender, TouchEventArgs e)
{
    int id = e.TouchDevice.Id;
    _activeFingers.Remove(id);
    // 清理该手指的状态
}
```

有了 `Id` 来区分手指，你就可以同时处理多根手指的独立绘制——比如两个手指同时在画布上画两条线。

### 操作

原始触控给你每一个手指的原始坐标，但要识别“双指捏合缩放”这种手势，你得自己算两根手指之间的距离变化、角度变化，写一堆几何计算代码。这显然不应该是每个开发者都重复造轮子的活。WPF 因此提供了**操作（Manipulation）** 这一层抽象，自动把原始触控翻译成平移、缩放、旋转三个基本操作。

#### 操作事件

操作有三个核心事件：

- **`ManipulationStarting`**：用户开始操作时触发（第一个手指按下并开始移动）。在这里你可以设置允许的操作类型（平移/缩放/旋转）、操作的中心点等。
- **`ManipulationDelta`**：操作过程中不断触发（手指移动时）。事件参数包含了本次微小的平移量、缩放比例、旋转角度。
- **`ManipulationCompleted`**：操作结束时触发（所有手指都抬起）。可以在这里做一些收尾工作，或者开启惯性。

这些都是路由事件（冒泡策略，有对应的隧道版本）。

#### 启用操作

操作默认是关闭的。要启用，必须在接收操作的元素上设置：

```csharp
myElement.IsManipulationEnabled = true;
```

或者在 XAML 里：

```xml
<Canvas IsManipulationEnabled="True" />
```

只有设置了 `IsManipulationEnabled="True"` 的元素及其子元素，才会把原始触控“升级”为操作事件。

#### `ManipulationDelta` 事件参数详解

这是操作体系里最核心的事件。它的参数类型是 `ManipulationDeltaEventArgs`，关键属性：

- **`DeltaManipulation`**（类型 `ManipulationDelta`）：**本次微小变化**的平移、缩放、旋转向量。包含：
  - `Translation`（`Vector`）：X 和 Y 方向的平移量（手指移动了多远）。
  - `Scale`（`Vector`，通常两分量相等）：缩放比例变化。比如 `Scale.X = 1.1` 表示放大 10%，`Scale.X = 0.9` 表示缩小 10%。
  - `Rotation`（`double`）：旋转角度变化（单位**度**），正值顺时针，负值逆时针。
  - `Expansion`（`Vector`）：两个手指之间的距离变化量。
  
- **`CumulativeManipulation`**（类型 `ManipulationDelta`）：**从操作开始到现在的累积**变化。第一次平移到现在总共移了多远、总共缩放了多大、总共旋转了多少度。

- **`Velocities`**（类型 `ManipulationVelocities`）：当前操作的**速度**。包含：
  - `LinearVelocity`（`Vector`）：平移的线速度（WPF 单位/毫秒）。
  - `AngularVelocity`（`double`）：旋转的角速度（度/毫秒）。
  - `ExpansionVelocity`（`Vector`）：缩放的速度。
  
  速度数据在开启惯性时至关重要，WPF 用这些速度作为惯性的初始速度。

- **`ManipulationContainer`**：操作的参考容器，所有坐标和变换相对于这个容器。
- **`ManipulationOrigin`**：操作的起始中心点。

#### 一个完整的缩放+平移示例

```csharp
// 在构造函数或初始化里启用操作
myCanvas.IsManipulationEnabled = true;

// ManipulationStarting: 设置允许的操作类型
private void OnManipulationStarting(object sender, ManipulationStartingEventArgs e)
{
    e.Mode = ManipulationModes.Scale | 
             ManipulationModes.Translate | 
             ManipulationModes.Rotate;
    e.ManipulationContainer = this;  // 相对于窗口
}

// ManipulationDelta: 应用变换
private void OnManipulationDelta(object sender, ManipulationDeltaEventArgs e)
{
    // 获取当前变换
    Matrix matrix = myCanvas.RenderTransform.Value;
    
    // 平移
    matrix.Translate(e.DeltaManipulation.Translation.X, 
                     e.DeltaManipulation.Translation.Y);
    
    // 缩放（以操作中心点为原点缩放）
    Point origin = e.ManipulationOrigin;
    matrix.ScaleAt(e.DeltaManipulation.Scale.X, 
                   e.DeltaManipulation.Scale.Y, 
                   origin.X, origin.Y);
    
    // 旋转
    matrix.RotateAt(e.DeltaManipulation.Rotation, origin.X, origin.Y);
    
    // 应用变换
    myCanvas.RenderTransform = new MatrixTransform(matrix);
    
    e.Handled = true;
}
```

这样不需要任何原始触控坐标计算，WPF 直接告诉你“现在手指捏合缩放了 5%”，你把它乘到画布上就行。

#### 操作模式 `ManipulationModes`

`ManipulationStarting` 的 `Mode` 属性决定允许哪些操作：

- `ManipulationModes.None`：不接受任何操作。
- `ManipulationModes.Translate`：允许单指或多指平移。
- `ManipulationModes.Scale`：允许双指缩放。
- `ManipulationModes.Rotate`：允许双指旋转。
- `ManipulationModes.All`：允许以上所有。
- 可以用 `|` 组合。

另外还有：
- `ManipulationModes.TranslateX` / `TranslateY`：限定只在 X 或 Y 方向平移。
- `ManipulationModes.TranslateInertia`：为平移开启惯性（见下一节）。

合理的 Mode 设置可以约束用户行为——比如一个横向图片浏览器可以只设置 `TranslateX`，让图片只能左右滑。

### 惯性

手指在屏幕上快速划过，抬起后内容不会立刻停住，而是继续滑动然后慢慢减速停下。这就是**惯性（Inertia）**。如果你的触控应用没有惯性，用户会觉得界面“死沉死沉的”，不跟手。有了惯性，交互就感觉“物理上真实”。

WPF 把惯性作为操作的一个延续阶段来提供。在 `ManipulationCompleted` 事件里，你可以根据手指抬起时的速度开启惯性。

#### 开启惯性

在 `ManipulationCompleted` 事件里检查速度，如果不为零就开启惯性：

```csharp
private void OnManipulationCompleted(object sender, ManipulationCompletedEventArgs e)
{
    // 检查是否有剩余速度
    if (e.Velocities.LinearVelocity.Length > 0 ||
        Math.Abs(e.Velocities.AngularVelocity) > 0 ||
        e.Velocities.ExpansionVelocity.Length > 0)
    {
        // 开启惯性
        e.Cancel();  // 取消操作完成，不要让系统默认停止
        
        // 计算并启动惯性动画
        StartInertia(e);
    }
}
```

WPF 并没有一个“一键开惯性”的开关（在较新的版本和 UWP 里有，但在传统 WPF 中需要手动模拟）。惯性的本质是**一个从当前速度开始、在指定衰减时长内逐渐减速到零的动画**。你需要自己创建动画并播放。

#### 用动画模拟惯性

WPF 提供了 `InertiaTranslationBehavior`、`InertiaRotationBehavior`、`InertiaExpansionBehavior` 这三个类，但你通常还需要配合 `Storyboard` 或定时器来实际执行动画。标准做法是利用 `ManipulationDelta` 事件和 `ReportBoundaryFeedback` 等机制，或者用更底层的自定义惯性物理计算。

在实践中，很多开发者选择直接根据速度算出目标偏移量，然后用 `DoubleAnimation` 来平滑过渡：

```csharp
private void StartInertia(ManipulationCompletedEventArgs e)
{
    var matrix = myCanvas.RenderTransform.Value;
    
    // 计算惯性衰减后的最终偏移（简单线性衰减模型）
    double deceleration = 0.001;  // 衰减系数，单位：WPF单位/毫秒²
    double duration = 500;        // 惯性持续时长（毫秒）
    
    // 最终偏移 = 初速度 × 时长 - 0.5 × 衰减 × 时长²
    double finalX = e.Velocities.LinearVelocity.X * duration - 
                    0.5 * deceleration * duration * duration;
    double finalY = e.Velocities.LinearVelocity.Y * duration - 
                    0.5 * deceleration * duration * duration;
    
    // 创建动画
    var animX = new DoubleAnimation(matrix.OffsetX, matrix.OffsetX + finalX, 
                                     TimeSpan.FromMilliseconds(duration));
    var animY = new DoubleAnimation(matrix.OffsetY, matrix.OffsetY + finalY, 
                                     TimeSpan.FromMilliseconds(duration));
    
    // 应用动画（简化示意）
    myCanvas.BeginAnimation(Canvas.LeftProperty, animX);
    myCanvas.BeginAnimation(Canvas.TopProperty, animY);
}
```

不过这种方式比较手工。更完善的做法是使用 `Storyboard` 配合缓动函数（如 `PowerEase` 来模拟减速），或者直接用第三方控件库封装好的惯性支持。

**在 .NET Framework 4.x 里**，WPF 的操作惯性能力相对有限，很多团队会自己实现惯性物理。但理解这个分层概念很重要，因为到 UWP 和 WinUI 时代，惯性和操作已经深度集成，几乎一键搞定。

**如果你用的是新版 .NET（.NET Core / .NET 5+）的 WPF**，`Manipulation` 事件仍然存在，但性能和行为上有一些改进。

## 总结

5.6 节是 WPF 输入系统里最后一块拼图，把触控输入从底层到高层全讲通了：

**多点触控输入层次（5.6.1）**：
- 原始触控（Raw Touch）：一个手指一个事件，类似鼠标但支持多点。
- 操作（Manipulation）：WPF 自动把多点触控翻译为平移/缩放/旋转。
- 惯性（Inertia）：手指抬起后，模拟物理减速运动。
- 鼠标提升：自动把触控翻译为鼠标事件，兼容老控件。

**原始触控（5.6.2）**：
- 事件：`TouchDown`、`TouchUp`、`TouchMove`（都有 Preview 隧道版）。
- 关键参数：`TouchDevice.Id`（手指 ID，区分多点）、`GetTouchPoint`（位置和接触面积）。
- 鼠标提升会自动发生，在 `TouchDown` 设 `Handled = true` 可阻止提升。
- 通过 `Id` 可跟踪多指轨迹，适合绘图、手写等精细场景。

**操作（5.6.3）**：
- 事件：`ManipulationStarting`、`ManipulationDelta`、`ManipulationCompleted`。
- 必须设置 `IsManipulationEnabled="True"` 来启用。
- `ManipulationDeltaEventArgs` 提供 `DeltaManipulation`（每次微小变化的平移/缩放/旋转量）和 `CumulativeManipulation`（累积量）以及 `Velocities`（当前速度）。
- 适合照片查看器、地图、任何需要双指手势的控件。

**惯性（5.6.4）**：
- 在 `ManipulationCompleted` 里根据手指抬起时的速度开启。
- 传统 WPF 需要用动画手动模拟惯性衰减（`DoubleAnimation` + 物理公式）。
- 目标是让界面在手指抬起后继续平滑运动，增强触控体验的自然感。

学完触控输入，WPF 的三大输入设备（键盘、鼠标、触控）你就全部覆盖完了。这些输入事件全部建立在第 5 章开头讲的路由事件机制上——隧道先走、冒泡后走、`Handled` 截断。掌握了这个统一模型，以后学任何新的输入事件类型，你只要看一下它的策略和参数类就能立刻上手。
