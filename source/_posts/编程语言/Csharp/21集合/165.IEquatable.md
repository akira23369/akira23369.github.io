# `IEquatable<T>`

## 核心概念
`IEquatable<T>` 是 `System` 命名空间下的一个泛型接口。它**用于定义一种强类型的方法，来确定两个实例是否相等**。

**接口签名：**
```csharp
public interface IEquatable<T>
{
    bool Equals(T other);
}
```

---

## 为什么要用它？

在 C# 中，所有的类型都继承自 `System.Object`，因此都有一个 `public virtual bool Equals(object obj)` 方法。为什么还要多此一举搞个 `IEquatable<T>` 呢？
int和double这样的值类型内部都实现了两个Equals，一个重写object，一个是`IEquatable<T>`接口

*   **避免装箱/拆箱，大幅提升性能（针对值类型）：** 
    如果你的类型是 `struct`，使用默认的 `object.Equals(object)` 时，传入的值类型必须被“装箱（Boxing）”成引用类型。装箱会在堆上分配内存，消耗极大。使用 `IEquatable<T>.Equals(T other)` 传参是强类型的，**完全避免了装箱**。
*   **类型安全（Type Safety）：**
    默认的 `Equals(object)` 允许你把一只“狗”和一只“猫”进行比较，直到运行时才会返回 false。而 `IEquatable<T>` 在**编译阶段**就能限制只能将“狗”与“狗”比较。

---

## 适用场景
*   **对于结构体（Struct / 值类型）：** ⭐⭐⭐⭐⭐ **强烈推荐！** 只要你自定义了 struct，几乎都应该实现它。
*   **对于类（Class / 引用类型）：** ⭐⭐⭐ 视情况而定。如果你的类是“值对象”（即只要属性值相同，就认为是同一个对象，例如 `string` 或 `Version` 类），那么应该实现它。如果比较的是内存引用地址，则不需要。

---

## 黄金法则（连带责任）
在 C# 中实现 `IEquatable<T>` 有一套**必须遵守的连带规则**。如果你只实现了接口，而不做其他事，会导致严重的 Bug（比如放进 Dictionary 里找不到）。

**如果你实现了 `IEquatable<T>`，你必须同时做到以下 3 点：**
1.  **重写 `object.Equals(object)`**：让它内部调用强类型的 `Equals(T)`。
2.  **重写 `GetHashCode()`**：相等的对象**必须**返回相同的哈希码。
3.  **重载 `==` 和 `!=` 运算符**（强烈建议）：保持行为的一致性。

---

## 代码示例

下面是一个标准的、无懈可击的 `IEquatable<T>` 实现模板（以 `struct` 为例）：

```csharp
using System;

public struct Point : IEquatable<Point> // 1. 实现接口
{
    public int X { get; }
    public int Y { get; }

    public Point(int x, int y)
    {
        X = x;
        Y = y;
    }

    // 2. 实现 IEquatable<T> 定义的强类型 Equals
    public bool Equals(Point other)
    {
        // 核心比较逻辑
        return this.X == other.X && this.Y == other.Y;
    }

    // 3. 必须重写 object.Equals
    public override bool Equals(object obj)
    {
        // 如果 obj 是 Point 类型，则调用强类型的 Equals
        return obj is Point other && this.Equals(other);
    }

    // 4. 必须重写 GetHashCode
    public override int GetHashCode()
    {
        // C# 8.0+ 推荐使用 HashCode.Combine 快速生成哈希码
        return HashCode.Combine(X, Y);
    }

    // 5. 强烈建议重载 == 和 != 操作符
    public static bool operator ==(Point left, Point right)
    {
        return left.Equals(right);
    }

    public static bool operator !=(Point left, Point right)
    {
        return !(left == right); // 直接复用 == 逻辑
    }
}
```

*(如果是针对 `Class` 实现，强类型 `Equals` 第一行通常要加一句 `if (other is null) return false;` 以及 `if (ReferenceEquals(this, other)) return true;` 进行快速判断)*

## 底层运行机制与集合框架的联动
C# 的泛型集合（如 `List<T>`, `Dictionary<TKey, TValue>`, `HashSet<T>`）在进行包含性检查（如 `Contains`, `IndexOf`, 查找 Key）时，默认会使用 `EqualityComparer<T>.Default`。

`EqualityComparer<T>.Default` 的工作原理是：
1. 检查类型 `T` 是否实现了 `IEquatable<T>`。
2. 如果**实现了**，集合底层就会调用高效的强类型 `Equals(T)`。
3. 如果**没实现**，集合底层只能退化去调用慢速的、可能引发装箱的 `object.Equals(object)`。

---

## 总结
*   **是什么：** 强类型的对象相等性比较接口。
*   **最大好处：** 拯救值类型（Struct）的性能（去装箱）。
*   **最佳实践：** 实现它时，永远记得把 `object.Equals`、`GetHashCode`、`==`、`!=` 一家人整整齐齐地一起重写。
*   **C#9.0 补充：** 如果你使用 C# 9.0+ 的 `record` 关键字，编译器在底层**自动为你生成**了完美的 `IEquatable<T>` 实现代码，无需手动编写上述模板代码！
