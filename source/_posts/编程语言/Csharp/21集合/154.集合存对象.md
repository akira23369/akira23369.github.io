# 集合存储对象

## 一、 为什么需要集合？（vs 数组）
*   **数组 (Array) 的痛点**：长度是固定的。声明了 `Student[] arr = new Student[10];`，就只能存10个，想存第11个必须重新建一个更大的数组并搬运数据。
*   **集合 (Collection) 的优势**：**动态扩容**。集合底层其实也是数组，但它把“扩容”的脏活累活自己封装好了，你可以无限往里面 `Add` 对象。

---

## 二、集合里存的到底是什么？
当你把一个对象（比如 `Student` 类的实例）存入集合时，**集合里存的不是对象本身，而是对象的“引用”（内存地址）**。

**代码演示与内存图景：**
```csharp
class Student { public string Name; }

Student s1 = new Student { Name = "张三" };
List<Student> list = new List<Student>();
list.Add(s1);

// 此时修改 s1 的属性
s1.Name = "李四";

// 打印集合里的对象名字
Console.WriteLine(list[0].Name); // 输出：李四
```
*   **深度理解**：`s1` 和 `list[0]` 手里拿着同一把钥匙，开的是内存堆（Heap）里的同一扇门。修改其中一个，另一个也会受影响。

---

## 三、为什么现在只用“泛型集合”？
在C#历史中，集合分为两代：

1.  **第一代：非泛型集合（已淘汰，面试爱问）**
    *   命名空间：`System.Collections`
    *   代表：`ArrayList`
    *   **致命缺点**：它里面存的都是 `object` 类型。存进去时会发生**装箱**（值类型转引用类型，损耗性能），取出来时需要**拆箱**（强制类型转换，容易报错）。
2.  **第二代：泛型集合（绝对主力）**
    *   命名空间：`System.Collections.Generic`
    *   代表：`List<T>`
    *   **优点**：`<T>` 代表类型安全。`List<Student>` 只能存学生，存狗就会在编译时报错。**没有装箱拆箱，性能极高**。

---

## 四、常用泛型集合

假设我们有一个基础类：
```csharp
public class Student
{
    public int Id { get; set; }
    public string Name { get; set; }
}
```

### 动态数组：`List<T>`
*   **特点**：有序，可通过索引 `[i]` 访问，允许重复。
*   **适用场景**：90%的日常需求，按顺序存取对象。
```csharp
List<Student> students = new List<Student>();
students.Add(new Student { Id = 1, Name = "张三" });
students.Add(new Student { Id = 2, Name = "李四" });

// 遍历
foreach (var stu in students)
{
    Console.WriteLine(stu.Name);
}
```

### 字典：`Dictionary<TKey, TValue>`
*   **特点**：键值对（Key-Value）存储，**Key必须唯一**。通过Key找Value的速度极快（接近O(1)）。
*   **适用场景**：需要根据某个唯一标识（如学号、身份证号）快速查找对象的场景。
```csharp
Dictionary<int, Student> dic = new Dictionary<int, Student>();
// 以 Id 作为 Key，Student 对象作为 Value
dic.Add(1, new Student { Id = 1, Name = "张三" });
dic.Add(2, new Student { Id = 2, Name = "李四" });

// 极速查找 Id 为 2 的学生
Student target = dic[2]; 
```

### 哈希集合：`HashSet<T>`
*   **特点**：无序，**绝对不允许重复**。
*   **适用场景**：去重，或者做数学上的集合运算（交集、并集、差集）。
```csharp
HashSet<string> tags = new HashSet<string>();
tags.Add("VIP");
tags.Add("VIP"); // 第二次 Add 会被忽略，集合里依然只有一个 "VIP"
```

### 队列 `Queue<T>` 与 栈 `Stack<T>`
*   **Queue**：先进先出（FIFO）。像排队买票。方法：`Enqueue()` 入队，`Dequeue()` 出队。
*   **Stack**：后进先出（LIFO）。像弹夹压子弹。方法：`Push()` 压栈，`Pop()` 弹栈。

## 五、对象的比较与去重

这是一个初学者极容易踩坑的地方。
**问题**：如果你用 `Contains()` 检查集合是否包含某个对象，或者用 `HashSet` 去重，C# 是怎么判断两个对象“相等”的？

```csharp
List<Student> list = new List<Student>();
list.Add(new Student { Id = 1, Name = "张三" });

Student s2 = new Student { Id = 1, Name = "张三" };
Console.WriteLine(list.Contains(s2)); // 结果是 False！为什么？
```
**深度解析**：
默认情况下，C# 比较的是**内存地址（引用相等）**。虽然两个对象内容一样，但它们是 `new` 出来的两个独立内存块，所以不相等。

**解决方案：重写 `Equals` 和 `GetHashCode`**
如果你希望“只要Id一样，就是同一个学生”，你必须在 `Student` 类中重写这两个方法，或者实现 `IEquatable<T>` 接口：

```csharp
public class Student : IEquatable<Student>
{
    public int Id { get; set; }
    public string Name { get; set; }

    // 告诉集合：如何判断两个对象相等
    public bool Equals(Student other)
    {
        if (other == null) return false;
        return this.Id == other.Id; // 我们规定：Id相等即为同一个人
    }

    public override bool Equals(object obj) => Equals(obj as Student);

    // 告诉哈希表/HashSet：如何生成对象的指纹
    public override int GetHashCode()
    {
        return Id.GetHashCode(); 
    }
}
```
*加上这段代码后，上面的 `Contains(s2)` 就会返回 `True`，`HashSet` 也能正确去重了。*

## 六、Capacity 与 Count
*   **Count**：集合里当前实际存了几个对象。
*   **Capacity**：集合底层数组当前的物理长度。
*   **扩容机制**：当 `Count == Capacity` 时，如果再 `Add`，`List` 会在内存中开辟一个**两倍大**的新数组，把老数据拷过去。这个过程叫**内存分配与复制，非常消耗性能**。
*   **最佳实践**：如果你提前知道大概要存多少个对象，**在实例化时指定初始容量**。
```csharp
// 预先分配10000个位置，避免了从 4->8->16->...->8192 的多次扩容性能损耗
List<Student> bigList = new List<Student>(10000); 
```

## 七、结合 LINQ 操作对象集合
存入对象后，我们通常需要查询、排序。引入 `using System.Linq;` 后，集合会变得无比强大：

```csharp
List<Student> list = new List<Student> { /* 假设这里有很多学生 */ };

// 1. 过滤：找出 Id 大于 10 的学生
var vips = list.Where(s => s.Id > 10).ToList();

// 2. 排序：按 Id 降序排列
var sorted = list.OrderByDescending(s => s.Id).ToList();

// 3. 投影：只提取所有学生的名字，变成一个 List<string>
var names = list.Select(s => s.Name).ToList();

// 4. 查找：找到第一个叫"张三"的学生，找不到返回 null
var zhangsan = list.FirstOrDefault(s => s.Name == "张三");
```

## 八、如何选择合适的集合？

| 需求场景 | 应该选择的集合 | 时间复杂度 (查找) |
| :--- | :--- | :--- |
| **按顺序**存取，经常遍历，允许重复 | `List<T>` | O(n) |
| 需要通过**唯一标识（Key）**快速找对象 | `Dictionary<TKey, TValue>` | O(1) 极快 |
| 确保对象**绝对不重复**，经常做包含检查 | `HashSet<T>` | O(1) 极快 |
| 任务排队，先来后到 | `Queue<T>` | - |
| 撤销操作，后进先出 | `Stack<T>` | - |

## 九、对象集合方法使用：高频陷阱与注意事项

### 核心心法：时刻记住“引用类型”的本质
当你操作 `List<Student>` 时，你操作的不是学生本人，而是指向学生的一堆“遥控器”。

---

### 遍历与修改的陷阱

**陷阱 1：在 `foreach` 中调用 `Add()` 或 `Remove()`**
**现象**：程序直接崩溃，抛出 `InvalidOperationException: 集合已修改；可能无法执行枚举操作`。
**原因**：`foreach` 底层使用的是迭代器（Enumerator），它要求在遍历过程中，集合的元素数量绝对不能发生变化。
```csharp
List<Student> list = new List<Student> { s1, s2, s3 };
foreach (var stu in list)
{
    if (stu.Id == 1)
    {
        list.Remove(stu); // ❌ 致命错误！运行到这里直接崩溃
    }
}
```

**正确做法：**
*   **方案 A（推荐）**：使用 `List<T>` 自带的 `RemoveAll` 方法（性能最高，代码最简）。
    ```csharp
    list.RemoveAll(stu => stu.Id == 1); // 一行代码搞定，安全且高效
    ```
*   **方案 B**：使用 `for` 循环，并且**倒序遍历**（正序遍历删除会导致索引越界或漏删）。
    ```csharp
    for (int i = list.Count - 1; i >= 0; i--)
    {
        if (list[i].Id == 1) list.RemoveAt(i); // ✅ 倒序删除是安全的
    }
    ```

---

### 查找与判断的坑(`Contains`, `IndexOf`, `Remove`)

**陷阱 2：用新对象去查找老对象**
**现象**：明明集合里有一个 `Id=1, Name="张三"` 的对象，但我用 `Contains` 查，返回却是 `False`。
```csharp
List<Student> list = new List<Student>();
list.Add(new Student { Id = 1, Name = "张三" });

// ❌ 返回 False！并且 Remove 也删不掉！
bool exists = list.Contains(new Student { Id = 1, Name = "张三" }); 
```
**原因**：默认情况下，`Contains`、`IndexOf`、`Remove` 比较的是**内存地址**。你 `new` 了一个新对象，地址变了，集合当然不认。



**正确做法：**
*   **方案 A（LINQ 查找 - 推荐日常使用）**：不要用 `Contains`，改用 LINQ 的 `Any` 按条件查找。
    ```csharp
    // 只要集合里有任何一个元素的 Id 是 1，就返回 True
    bool exists = list.Any(stu => stu.Id == 1); 
    ```
*   **方案 B（根本解决）**：在 `Student` 类中重写 `Equals` 和 `GetHashCode` 方法（参考上面），告诉集合“只要Id相同就是同一个对象”。

---

### 排序的陷阱(`Sort`)

**陷阱 3：直接调用 `Sort()` 导致异常**
**现象**：调用 `list.Sort()`，抛出 `InvalidOperationException: 无法比较数组中的两个元素`。
**原因**：如果是 `List<int>`，C# 知道数字怎么比大小。但如果是 `List<Student>`，C# 不知道应该按学号排，还是按年龄、姓名排。

**正确做法：**
*   **方案 A（使用 LINQ - 推荐，不改变原集合）**：
    ```csharp
    // 生成一个排序后的新集合，原 list 顺序不变
    var sortedList = list.OrderBy(stu => stu.Age).ToList(); 
    ```
*   **方案 B（使用委托 - 就地排序，改变原集合）**：
    ```csharp
    // 告诉 Sort 方法：按照 Age 升序排列
    list.Sort((s1, s2) => s1.Age.CompareTo(s2.Age));
    ```

---

### 浅拷贝 vs 深拷贝

**陷阱 4：以为复制了集合，其实只复制了“遥控器”**
**现象**：把集合 A 复制给集合 B，修改集合 B 里的对象，集合 A 里的对象居然也跟着变了！
```csharp
List<Student> listA = new List<Student> { new Student { Name = "张三" } };

// ❌ 这叫“浅拷贝” (Shallow Copy)
List<Student> listB = new List<Student>(listA); 

listB[0].Name = "李四";
Console.WriteLine(listA[0].Name); // 输出：李四！(A 被污染了)
```
**原因**：`new List(listA)` 确实创建了一个新的集合（新盒子），但是**盒子里面装的“对象引用”是一模一样的**。A 和 B 指向内存中的同一个“张三”。

**正确做法（深拷贝 Deep Copy）：**
如果想要彻底独立，必须把集合里的**每一个对象都重新 `new` 一遍**。
```csharp
// 使用 LINQ 投影，为每个元素创建一个全新的对象
List<Student> listB = listA.Select(stu => new Student { 
    Id = stu.Id, 
    Name = stu.Name 
}).ToList();

listB[0].Name = "李四"; // 此时修改 B，绝对不会影响 A
```

### 性能相关的隐藏陷阱

#### `RemoveAt(0)` 是性能杀手
*   **原理**：`List<T>` 底层是数组。如果你删除最后一个元素，极快（O(1)）。但如果你删除第一个元素 `list.RemoveAt(0)`，**它后面的所有元素都要往前移动一格**（O(n)）。
*   **建议**：如果你的业务需要频繁在开头插入/删除对象，不要用 `List<T>`，应该改用 `LinkedList<T>`（双向链表）或 `Queue<T>`（队列）。

#### `Clear()` 的内存机制
*   **原理**：调用 `list.Clear()` 会把集合的 `Count` 变成 0，但**不会释放底层数组的内存空间**（`Capacity` 保持不变）。
*   **建议**：
    *   如果你接下来还要继续往里面存对象，用 `Clear()` 是极好的，避免了重新分配内存。
    *   如果你彻底不用这个集合了，并且它非常大，直接让 `list = null;`，把回收的工作交给 C# 的垃圾回收器（GC）。

---

### 多线程陷阱

**陷阱 5：多线程同时操作普通集合**
**现象**：在多线程/异步（Task）环境下，多个线程同时对一个 `List<T>` 或 `Dictionary` 进行 `Add` 操作，会导致数据丢失、索引越界或死循环。
**原因**：`System.Collections.Generic` 下的所有集合**都不是线程安全的**。

**正确做法：**
如果涉及多线程读写，必须使用 `System.Collections.Concurrent` 命名空间下的并发集合：
*   用 `ConcurrentBag<T>` 代替 `List<T>`
*   用 `ConcurrentDictionary<TKey, TValue>` 代替 `Dictionary`
*   用 `ConcurrentQueue<T>` 代替 `Queue<T>`

---

### 核心总结速查表

| 操作       | 容易犯的错误                   | 正确/最佳实践                        |
| :------- | :----------------------- | :----------------------------- |
| **遍历删除** | 用 `foreach` + `Remove()` | 用 `list.RemoveAll(条件)`         |
| **查找对象** | 用 `Contains(new Obj())`  | 用 `list.Any(x => x.Id == id)`  |
| **集合排序** | 直接调 `list.Sort()`        | 用 `list.OrderBy(x => x.属性)`    |
| **复制集合** | 以为 `new List(old)` 是完全独立 | 必须遍历并 `new` 出新对象（深拷贝）          |
| **清空集合** | 以为 `Clear()` 会释放内存       | `Clear()` 只清数据不缩容，释放内存用 `null` |
