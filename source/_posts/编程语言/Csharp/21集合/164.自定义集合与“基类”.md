# 自定义集合与“基类”

在前面的笔记中，我们都是手动去实现 `IList<T>` 或者 `IDictionary<TKey, TValue>`。你肯定边写边吐槽：“这也太累了吧！内部包一个 `List<T>`，然后我要把 `Add`、`Remove`、`Count` 等十几个方法全部手动‘甩锅’（委托）给内部列表，全都是毫无营养的**样板代码（Boilerplate Code）**！”

微软的设计师们早就想到了这一点。为了让开发者舒舒服服地写自定义集合，他们在 `System.Collections.ObjectModel` 命名空间下，为我们准备了**一系列极其强大的“基类”（Base Classes）**。



## 为什么不用 `List<T>`当基类？
很多初学者为了偷懒，会直接写 `class MyList : List<T>`。**这是极其错误的做法！**
为什么？因为 `List<T>` 的设计初衷是为了性能，它的核心方法（如 `Add`、`Remove`）**都不是虚方法（`virtual`）**。这意味着你无法重写（`override`）它们去拦截用户的操作、加入自己的业务逻辑。你只能眼睁睁地看着别人往你的集合里乱塞数据。

为了解决这个问题，微软提供了一个专门用于被继承的基类：**`Collection<T>`**。

## `Collection<T>`基类
`System.Collections.ObjectModel.Collection<T>` 已经帮你实现了 `IList<T>`、`ICollection<T>` 和 `IEnumerable<T>` 的所有样板代码。内部它也帮你维护好了一个泛型列表。

更绝的是，微软的设计师极其聪明，他们把所有修改集合的操作，最终都汇聚到了 **4 个受保护的虚方法（`protected virtual`）** 上：

1.  `InsertItem(int index, T item)`：控制**插入和添加**。（`Add` 内部其实调用的也是 `InsertItem`）
2.  `RemoveItem(int index)`：控制**删除**。
3.  `SetItem(int index, T item)`：控制**索引器赋值**（如 `list[0] = x`）。
4.  `ClearItems()`：控制**清空集合**。

**只要你重写这 4 个方法，你就能以极少的代码，100% 拦截并控制集合的所有修改操作！**

## 用 `Collection<T>`重写EventfulList
{% post_link 162.自定义集合与IListT#写一个带广播通知的自定义集合 EventfulList相关 %}
还记得第四篇中，我们写了上百行代码才实现了一个“带广播通知”的集合吗？现在看看用 `Collection<T>` 能有多优雅：

```csharp
using System;
using System.Collections.ObjectModel; // 引入神圣的命名空间

// 直接继承 Collection<T>，再也不用实现那十几个接口方法了！
public class ModernEventfulList<T> : Collection<T>
{
    public event Action<string> OnCollectionChanged;
    private void Notify(string message) => OnCollectionChanged?.Invoke(message);

    // 1. 拦截所有 添加/插入 操作
    protected override void InsertItem(int index, T item)
    {
        // 你的自定义逻辑：可以在这里检查 item 是否合法，不合法直接 throw Exception
        Notify($"准备在索引 {index} 插入新元素 [{item}]");
        
        // 核心：调用基类的方法，真正把元素存进去
        base.InsertItem(index, item); 
    }

    // 2. 拦截所有 移除 操作
    protected override void RemoveItem(int index)
    {
        T removedItem = this[index]; // 获取即将被删除的元素
        base.RemoveItem(index);      // 真正删除
        Notify($"删除了索引 {index} 的元素 [{removedItem}]");
    }

    // 3. 拦截所有 索引器替换 操作 (list[0] = newItem)
    protected override void SetItem(int index, T item)
    {
        T oldItem = this[index];
        base.SetItem(index, item);
        Notify($"索引 {index} 的元素从 [{oldItem}] 变成了 [{item}]");
    }

    // 4. 拦截 清空 操作
    protected override void ClearItems()
    {
        base.ClearItems();
        Notify("集合被清空了！");
    }
}
```
**总结：** 样板代码瞬间消失，你只需要关注你的**核心业务逻辑**（拦截器）。

> **微软剧透：** 其实，针对“带通知的集合”这个需求，微软连 `Collection<T>` 都帮你继承好了，直接提供了一个现成的类叫做 **`ObservableCollection<T>`**。你在 WPF、MAUI、Blazor 中做数据绑定时，用的几乎全是它！

## `KeyedCollection<TKey, TItem>`（列表与字典的结合体）
在写字典（`IDictionary`）时，我们经常遇到一种情况：**值（Value）本身已经包含了键（Key）**。
比如，你有一个 `Employee` 类，里面有 `Id` 和 `Name`。如果你用标准的字典，代码是这样的：
`Dictionary<string, Employee> dict = new ...`
然后添加时必须写：`dict.Add(emp.Id, emp)`。
这里的 `emp.Id` 被写了两遍，显得非常多余。而且它不像 `List` 那样保持插入顺序。

为了解决这种“对象自带主键”的场景，微软提供了 **`KeyedCollection<TKey, TItem>`**。它同时拥有 `List` 的按顺序索引和 `Dictionary` 的按键极速查找能力！

## 写一个极其清爽的员工集合

```csharp
using System;
using System.Collections.ObjectModel;

public class Employee
{
    public string Id { get; set; }
    public string Name { get; set; }
}

// 继承 KeyedCollection，指定 Key 是 string，元素是 Employee
public class EmployeeCollection : KeyedCollection<string, Employee>
{
    // 你只需要重写这唯一一个方法：告诉集合，怎么从元素中提取出 Key！
    protected override string GetKeyForItem(Employee item)
    {
        if (item == null) throw new ArgumentNullException(nameof(item));
        return item.Id; // 把员工的 Id 作为字典的 Key
    }
}
```

**测试它有多爽：**
```csharp
class Program
{
    static void Main()
    {
        var staff = new EmployeeCollection();

        // 像 List 一样添加，不需要再手动指定 Key！集合会自动去调 GetKeyForItem 提取 Id
        staff.Add(new Employee { Id = "E001", Name = "张三" });
        staff.Add(new Employee { Id = "E002", Name = "李四" });

        // 像 Dictionary 一样极速查找 (根据 Key)
        Employee boss = staff["E001"]; 
        Console.WriteLine($"查找到的员工: {boss.Name}");

        // 像 List 一样通过索引器查找 (根据位置)
        Employee firstEmp = staff[1];
        Console.WriteLine($"第2个员工是: {firstEmp.Name}");
    }
}
```
**`KeyedCollection` 简直就是处理“带主键实体列表”的终极神兵利器！**

## 总结
恭喜你！到这里，你已经构建了非常完整的 C# 集合知识体系。让我们回顾一下这六篇笔记的升华之旅：

*   **第一阶段：理解契约（底层原理）**
    *   `IEnumerable / IEnumerator`：揭开 `foreach` 的底层状态机面纱。
    *   `IEnumerable<T>`：引入泛型，利用 `yield return` 极速构建迭代器。
*   **第二阶段：能力扩展（行为定义）**
    *   `ICollection<T>`：赋予了集合增、删、计数的动态能力。
    *   `IList<T>`：赋予了线性集合精准的“索引定位”能力。
    *   `IDictionary<TKey, TValue>`：赋予了键值对集合 O(1) 的哈希极速检索能力。
*   **第三阶段：大道至简（工程实践）**
    *   `Collection<T>`：消灭所有接口样板代码，用 4 个虚方法轻松拦截集合变化。
    *   `KeyedCollection<TKey, TItem>`：完美融合 List 和 Dictionary 的双重优势。

**最后送给你的实战黄金法则：**
> 在 C# 中，如果是为了定义方法参数、返回值，**尽量使用接口（`IEnumerable<T>`, `IList<T>` 等）**，因为这样最灵活；
> 如果是为了自己写一个全新的集合类去存放数据，**绝对不要去实现接口，直接去继承 `System.Collections.ObjectModel` 下的基类！**
