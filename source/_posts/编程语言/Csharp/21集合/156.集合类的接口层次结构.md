# 集合类的接口层次结构

在 C# 中，集合不仅是简单的数据容器，它们背后有着极其严谨的接口继承体系（Interface Hierarchy）。理解这一层次结构，是编写高扩展性、松耦合以及高性能代码的关键。

## 核心分水岭：泛型 与 非泛型

C# 的集合体系在物理划分上主要存在于两个命名空间中：

- **System.Collections（非泛型）：** 包含 ArrayList、Hashtable 等。它们诞生于 C# 1.0 时代。由于没有类型限制，内部元素均以 object 类型存储。
    
    - 性能警告： 使用非泛型集合处理值类型（如 int、struct）时，会引发频繁的**装箱（Boxing）和拆箱（Unboxing）** 操作，导致托管堆内存剧增，严重拖累垃圾回收（GC）和整体性能。现代 C# 开发已**基本废弃**此类集合。
        
- **System.Collections.Generic（泛型）：** 包含 `List<T>、Dictionary<TKey, TValue>、Stack<T>` 等。诞生于 C# 2.0。它们提供了严格的编译时类型安全（Type Safety），彻底消除了装箱/拆箱的性能损耗。
## 泛型集合接口的层次结构

![](156.集合类的接口层次结构/file-20260325152548100.png)

### `IEnumerator` 和 `IEnumerator<T>` (枚举器接口)
*   **通俗理解**：想象你在读一本书，`IEnumerator` 就是你**指着字的那根手指**。它不知道整本书有多厚，它只知道当前指着哪个字（`Current`），以及如何移动到下一个字（`MoveNext()`）。
*   **作用**：它定义了遍历集合内部元素的底层机制。
*   **区别**：`IEnumerator` 读出来的字是 `object` 类型的；`IEnumerator<T>` 读出来的字是明确知道类型的（比如 `int` 或 `string`）。

---

### `IEnumerable` 和 `IEnumerable<T>` (可枚举接口)
*   **通俗理解**：如果 `IEnumerator` 是你的手指，那么 `IEnumerable` 就是**那本书本身**。这本书拍着胸脯保证：“我里面有内容，你可以拿手指（枚举器）从头到尾翻一遍”。
*   **作用**：**这是所有集合的“老祖宗”接口。** 只要一个类实现了这个接口，就意味着**它可以使用 `foreach` 循环**！
*   **核心方法**：它里面只有一个方法 `GetEnumerator()`，调用这个方法，就会把“手指（枚举器）”交给你。

> **图注说明**：图中间的 `Stack<T>` (栈，后进先出) 和 `Queue<T>` (队列，先进先出) 是具体的**类（class）**，它们直接实现了 `IEnumerable<T>`，这意味着你可以用 `foreach` 遍历它们，但它们不支持像数组那样通过索引（下标）去修改里面的值。

---

### `ICollection` 和 `ICollection<T>` (集合接口)
*   **通俗理解**：它在“能被遍历（IEnumerable）”的基础上，进化成了一个 **“真正的容器”**。
*   **作用**：它继承自 `IEnumerable`。它赋予了集合**管理大小和增删改**的能力。
*   **新增能力**：
    *   知道了自己有多大（提供了 `Count` 属性来获取元素数量）。
    *   可以添加元素（`Add()`）、删除元素（`Remove()`）、清空元素（`Clear()`）。

> **图注说明**：图下方的 `HashSet<T>` (哈希集合，一个不允许有重复元素的集合类) 就是直接实现了 `ICollection<T>`。

---

由 `ICollection` 往下，集合的形态分化成了两大主流门派：**列表派** 和 **字典派**。

### `IList` 和 `IList<T>` (列表接口)
*   **通俗理解**：这是一种**排好队的、有序号**的容器。就像酒店的房间号，001房、002房……
*   **作用**：它继承自 `ICollection`。最大的特点是**支持通过“索引（下标）”来访问元素**。
*   **新增能力**：你可以使用 `[index]` 的方式（比如 `myList[0]`）来读取、插入（`Insert`）或修改特定位置的元素。
*   **图中对应的实现类**：
    *   `List<T>`：现代C#最最最常用的集合类，泛型动态数组。
    *   `ArrayList`：老古董，非泛型的动态数组，现在别用它。

### `IDictionary` 和 `IDictionary<TKey, TValue>` (字典接口)
*   **通俗理解**：这是一种**通过“查字典”来找东西**的容器。它存的数据是一对一对的，叫**键值对（Key-Value Pair）**。比如：Key是学号"1001"，Value是名字"张三"。
*   **作用**：它也继承自 `ICollection`。它不靠序号排队，而是靠唯一的“钥匙（Key）”来快速找到对应的“锁（Value）”。
*   **新增能力**：你可以使用 `[key]` 的方式（比如 `myDictionary["1001"]`）来极其快速地获取对应的值。
*   **图中对应的实现类**：
    *   `Dictionary<TKey, TValue>`：现代C#最常用的字典类。
    *   `SortedList<TKey, TValue>`：按Key自动排序的字典类。
    *   `Hashtable`：老古董哈希表，非泛型，现在也别用它了。

---
## 面向接口编程

理解层次结构的最大价值在于**多态性** 的应用。
- **里氏替换原则 (LSP)：** 子类对象可以安全地赋值给父类（或父接口）的引用变量。
- **兄弟互斥：** 虽然 Dictionary 和 List 都是 ICollection，但你不能将 Dictionary 赋值给 IList 类型的变量，兄弟节点之间是不兼容的。

### 为什么声明变量时应优先使用接口？

《Effective C#》指出：在方法的参数和返回值中，应尽量使用接口而不是具体的实现类，这能极大提高代码的灵活性。

如果在代码中直接使用具体的类（如 Dictionary<TKey, TValue>），那么后续重构的成本极高。如果使用父接口（如 IDictionary），则可以随时无缝替换底层的数据结构。

**代码演示：解耦与底层结构替换**

```cs
using System;
using System.Collections.Generic;

namespace CollectionsHierarchy
{
    class Program
    {
        static void Main()
        {
            // 最佳实践：使用接口类型声明变量，使用具体类实例化
            IDictionary<int, string> employeeRecords;

            // 场景 A：初始需求只需要普通的键值对存储
            employeeRecords = new Dictionary<int, string>();
            employeeRecords.Add(2, "Allen");
            employeeRecords.Add(1, "Scott");

            // 场景 B：需求变更！现在要求遍历时必须按照员工 ID（Key）自动排序
            // 由于变量是 IDictionary 接口类型，我们只需要更改实例化这一行代码即可：
            employeeRecords = new SortedList<int, string>();
            employeeRecords.Add(2, "Allen");
            employeeRecords.Add(1, "Scott");

            // 下游的消费代码完全不需要修改，这就是面向接口编程的威力
            PrintRecords(employeeRecords);
        }

        // 方法参数同样使用最宽泛的接口
        // 如果这里写 Dictionary<int, string>，那么传递 SortedList 就会报错
        static void PrintRecords(IDictionary<int, string> records)
        {
            foreach (var record in records)
            {
                Console.WriteLine($"ID: {record.Key}, Name: {record.Value}");
            }
        }
    }
}
```


### 如何选择合适的方法参数接口类型？

根据方法实际需要的最少权限来选择接口（接口隔离原则 ISP）：

1. 如果方法**只需遍历**：参数类型设为 `IEnumerable<T>`。
2. 如果方法**需要获取数量或添加/删除元素**：设为 `ICollection<T>`。
3. 如果方法**需要通过索引器访问或修改特定位置**：设为 `IList<T>`。
