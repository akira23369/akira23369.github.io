# `Stack<T>`(栈)

## 一、核心概念与定位

`Stack<T>` 位于 `System.Collections.Generic` 命名空间下。它是一种严格遵循 **LIFO (Last-In-First-Out，后进先出)** 原则的数据结构。

可以将其心智模型理解为物理世界中的“一叠书”：
*   **自底向上构建**：最先放入的元素沉在栈底。
*   **顶部操作**：所有的存取操作都只能发生在栈顶（Top）。最后放入的元素始终处于栈顶，并且是下一个将要被取出的元素。
*   **封闭性**：与 `List<T>` 不同，`Stack<T>` 故意**不支持索引器访问**（即不能使用 `stack[2]`）。禁止随机访问是为了从数据结构层面强行保证 LIFO 的业务逻辑不被破坏。

## 二、底层运行机制

结合《CLR via C#》对 .NET 集合底层的剖析，`Stack<T>` 的表象是栈，但其底层的内存基石依然是**连续数组 (`T[]`)**。

1.  **内部状态维护**：`Stack<T>` 内部维护着一个泛型数组和一个名为 `_size` 的整型字段。`_size` 既代表当前栈中元素的数量，也充当着指向“栈顶下一个空闲位置”的指针。
2.  **动态扩容机制**：当不断 Push 元素导致 `_size` 达到底层数组的容量时，`Stack<T>` 会触发扩容。与 `List<T>` 完全一致！自动创建一个**容量翻倍**的新数组，并把老数据拷贝过去。
3.  **遍历顺序**：当使用 `foreach` 遍历 `Stack<T>` 时，内部的枚举器（Enumerator）是从 `_size - 1` 向 `0` 进行逆序遍历的。因此，遍历的输出顺序必定是**从栈顶到栈底**（即从最新加入的元素到最早加入的元素）。

## 三、核心属性与初始化

### `Count` (实际包含的元素数)
*   **说明**：获取栈中当前**实际包含**的元素数量。
*   **时间复杂度**：O(1) （直接返回底层的 `_size` 变量）。
*   **示例**：
```csharp
Stack<string> plates = new Stack<string>();
plates.Push("盘子1");
plates.Push("盘子2");
Console.WriteLine($"栈内有 {plates.Count} 个盘子"); // 输出: 2
```

### 隐藏的性能优化：构造函数预分配容量
与 `List<T>` 不同，`Stack<T>` **没有公开的 `Capacity` 属性**，你无法在外部读取它的总容量。但是，**它在构造函数中支持传入初始容量！**
*   **最佳实践**：如果你知道大概要压入多少个元素，一定要在 `new` 的时候指定容量，避免底层数组频繁翻倍扩容造成的性能浪费。
```csharp
// 预先分配 1000 个元素的连续内存，拒绝扩容开销
Stack<int> memoryOptimizedStack = new Stack<int>(1000); 
```

## 四、 核心操作：增与删

栈的核心只有三个动作：压入（Push）、弹出（Pop）、偷看（Peek）。

### `Push(T item)`
*   **说明**：将对象插入 `Stack<T>` 的**顶部**。
*   **时间复杂度**：平摊 O(1)。（如果触发扩容则是 O(n)）。
*   **示例**：
```csharp
Stack<string> browserHistory = new Stack<string>();
browserHistory.Push("www.google.com");
browserHistory.Push("www.github.com");
browserHistory.Push("www.stackoverflow.com");
// 此时栈顶是 stackoverflow，栈底是 google
```

### `Pop()`
*   **说明**：移除并返回 `Stack<T>` **顶部**的对象。
*   **时间复杂度**：O(1) （极快）。
*   **致命异常**：如果栈是空的（Count == 0），调用此方法会**直接抛出 `InvalidOperationException` (栈为空)** 异常！
*   **示例**：
```csharp
// 继续使用上面的 browserHistory
string currentPage = browserHistory.Pop(); 
Console.WriteLine($"我刚刚离开了: {currentPage}"); // 输出: www.stackoverflow.com

string previousPage = browserHistory.Pop();
Console.WriteLine($"我退回到了: {previousPage}"); // 输出: www.github.com

// 此时栈里只剩下 google.com
```

### `Peek()`
*   **说明**：返回 `Stack<T>` 顶部的对象，但**不将其移除**。
*   **时间复杂度**：O(1)。
*   **异常**：如果栈为空，同样抛出 `InvalidOperationException`。
*   **应用场景**：你想知道下一个要处理的数据是什么，但现在还没准备好处理它。
*   **示例**：
```csharp
Stack<int> tasks = new Stack<int>();
tasks.Push(100);
tasks.Push(200); // 200 在栈顶

int nextTask = tasks.Peek(); 
Console.WriteLine($"下一个要处理的任务ID是: {nextTask}"); // 输出: 200
Console.WriteLine($"任务还在吗？ Count: {tasks.Count}"); // 输出: 2 (200 并没有被移除)
```

## 五、安全操作

老手在用 `Pop` 和 `Peek` 前，都得先写一句 `if (stack.Count > 0)`，非常繁琐。从 .NET Core 开始，微软引入了 `Try` 系列方法。**强烈建议在现代 C# 代码中全面替代老的 `Pop/Peek`！**

### `TryPop(out T result)`
*   **说明**：尝试弹出栈顶元素。
*   **返回值**：如果栈不为空，移除栈顶元素，将其赋值给 `result`，并返回 `true`。如果栈为空，`result` 为默认值，返回 `false`（**绝对不报错！**）。
*   **示例**：
```csharp
Stack<string> undoStack = new Stack<string>();
undoStack.Push("输入了 Hello");

if (undoStack.TryPop(out string lastAction)) {
    Console.WriteLine($"成功撤销: {lastAction}");
} else {
    Console.WriteLine("没有可以撤销的操作了！");
}

// 再次尝试，此时栈已空
if (undoStack.TryPop(out string failedAction)) {
    // 进不来这里
} else {
    Console.WriteLine("没有可以撤销的操作了！"); // 会输出这句
}
```

### `TryPeek(out T result)`
*   **说明**：尝试获取栈顶元素（不移除）。栈为空时返回 `false`，不抛异常。
*   **示例**：
```csharp
Stack<int> numbers = new Stack<int>();
if (numbers.TryPeek(out int topNum)) {
    Console.WriteLine($"栈顶是 {topNum}");
} else {
    Console.WriteLine("栈是空的，别偷看了。"); // 执行这句
}
```

## 六、实用工具方法

### `Contains(T item)`
*   **说明**：确定某元素是否在 `Stack<T>` 中。
*   **时间复杂度**：O(n) （线性查找）。
*   **避坑指南**：虽然栈提供了这个方法，但**如果你发现你频繁在栈中使用 Contains，说明你的数据结构选错了！** 栈的设计初衷只允许访问栈顶，不支持从中间找东西。如果要频繁查找，请使用 `HashSet<T>` 或 `List<T>`。
*   **示例**：
```csharp
Stack<string> cards = new Stack<string>();
cards.Push("黑桃A");
cards.Push("红桃K");
bool hasAce = cards.Contains("黑桃A"); // 返回 true
```

### `Clear()`
*   **说明**：从 `Stack<T>` 中移除所有对象。
*   **时间复杂度**：O(n) （如果是引用类型，需要将底层数组全设为 null；如果是值类型则是 O(1)）。
*   **细节**：Count 归零，但**内部容量 (Capacity) 保持不变**。
*   **示例**：
```csharp
cards.Clear();
// cards.Count 变为 0
```

### `ToArray()`
*   **说明**：将栈复制到一个新的固定大小的数组中。
*   **时间复杂度**：O(n)。
*   **极其重要的细节（必考！）**：新生成的数组元素的顺序是**从栈顶到栈底（LIFO 顺序）**。也就是说，最后 Push 进去的元素，在新数组的索引是 `0`！
*   **示例**：
```csharp
Stack<int> stack = new Stack<int>();
stack.Push(1);
stack.Push(2);
stack.Push(3); // 3 在栈顶

int[] array = stack.ToArray();
// array 的内容是: [3, 2, 1] ！！！千万别以为是 [1, 2, 3]
```

### `TrimExcess()`
*   **说明**：如果栈的当前元素数量（Count）远小于底层数组的容量，调用此方法可以缩减底层容量以匹配 Count，从而**释放多余的内存**。
*   **示例**：
```csharp
Stack<int> hugeStack = new Stack<int>(10000); // 开辟了 10000 的内存
hugeStack.Push(1);
hugeStack.Push(2);

hugeStack.TrimExcess(); // 把多余的 9998 个空位内存还给操作系统
```

## 七、遍历栈

栈实现了 `IEnumerable<T>`，所以可以用 `foreach` 遍历。
*   **陷阱**：遍历的顺序**严格按照出栈的顺序（从栈顶到栈底）**！也就是先看到最后加进去的元素。
*   **注意**：`foreach` 遍历**只是读取，并不会弹出（移除）元素**！遍历后栈里的元素依然存在。
*   **示例**：
```csharp
Stack<string> books = new Stack<string>();
books.Push("C#入门");
books.Push("深入理解C#");
books.Push("C#并发编程"); // 栈顶

Console.WriteLine("书架上的书（从上往下看）:");
foreach (string book in books) {
    Console.WriteLine(book);
}
// 输出顺序:
// C#并发编程
// 深入理解C#
// C#入门

Console.WriteLine($"遍历完了，书还在吗？在！数量: {books.Count}"); // 数量还是 3
```

## 八、补充高级
### 经典实战：撤销与重做 (Undo / Redo 机制)
任何软件（Word, Photoshop, 游戏编辑器）的 Ctrl+Z 和 Ctrl+Y 都是靠**双栈模型**实现的！
```csharp
Stack<string> undoStack = new Stack<string>(); // 撤销栈
Stack<string> redoStack = new Stack<string>(); // 重做栈

// 1. 用户执行操作
void DoAction(string action) {
    undoStack.Push(action);
    redoStack.Clear(); // 一旦执行新操作，重做栈清空
    Console.WriteLine($"执行: {action}");
}

// 2. 用户按下 Ctrl+Z (撤销)
void Undo() {
    if (undoStack.TryPop(out string action)) {
        redoStack.Push(action); // 把撤销的动作放进重做栈
        Console.WriteLine($"撤销了: {action}");
    }
}

// 3. 用户按下 Ctrl+Y (重做)
void Redo() {
    if (redoStack.TryPop(out string action)) {
        undoStack.Push(action); // 重做的动作放回撤销栈
        Console.WriteLine($"重做了: {action}");
    }
}
```

### 经典算法：括号匹配 / 语法解析
编译器如何知道你的代码里 `{` 和 `}` 是否成对闭合？全靠 `Stack`！
遇到左括号就入栈，遇到右括号就出栈比对，最后栈为空则匹配成功。

**核心逻辑**
1. **遇到左括号** (`(`, `[`, `{`)：直接 **Push** 入栈。
2. **遇到右括号** (`)`, `]`, `}`)：
    - 检查栈是否为空。如果为空，说明右括号多余，匹配失败。
    - 如果不为空，**Pop** 出栈顶元素，检查是否与当前右括号**配对**。如果不配对，匹配失败。
3. **遍历结束**：检查栈是否为空。如果为空，说明全部配对成功；如果不为空，说明左括号多余。
```cs
using System;
using System.Collections.Generic;

public class BracketChecker
{
    public static bool IsBalanced(string input)
    {
        Stack<char> stack = new Stack<char>();

        // 建立配对关系字典，方便查询
        Dictionary<char, char> pairs = new Dictionary<char, char> {
            { ')', '(' },
            { ']', '[' },
            { '}', '{' }
        };

        foreach (char c in input)
        {
            // 如果是左括号，入栈
            if (c == '(' || c == '[' || c == '{')
            {
                stack.Push(c);
            }
            // 如果是右括号
            else if (pairs.ContainsKey(c))
            {
                // 栈为空，说明没有对应的左括号
                if (stack.Count == 0) return false;

                // 弹出栈顶，检查是否匹配
                char top = stack.Pop();
                if (top != pairs[c]) return false;
            }
        }

        // 最后栈必须为空才算完全匹配
        return stack.Count == 0;
    }

    public static void Main()
    {
        string code1 = "if (a > b) { return (list[0]); }";
        string code2 = "if (a > b) { return (list[0]; }"; // 少了右括号 )

        Console.WriteLine($"代码1 匹配结果: {IsBalanced(code1)}"); // True
        Console.WriteLine($"代码2 匹配结果: {IsBalanced(code2)}"); // False
    }
}
```

### 利用栈处理优先级/排名
栈非常适合处理需要“逆向回溯”或“基于最新高价值数据优先处理”的场景。
例如：假设有一组学生对象，按照分数从低到高依次进入系统。我们需要基于最新数据（即最高分）为学生分配排名。

**实战代码实现**
```csharp
using System;
using System.Collections.Generic;

public class Student
{
    public string Name { get; set; }
    public int Marks { get; set; }
    public int Rank { get; set; }
}

class Program
{
    static void Main()
    {
        Stack<Student> studentStack = new Stack<Student>();

        // 模拟数据流：按分数从低到高入栈
        studentStack.Push(new Student { Name = "John", Marks = 45 });
        studentStack.Push(new Student { Name = "Smith", Marks = 61 });
        studentStack.Push(new Student { Name = "Alice", Marks = 80 });

        int currentRank = 1;

        // 使用 while 循环配合 Pop 进行排名分配
        // 每 Pop 一次，就取出当前还在栈里的最高分学生，并将其移出栈
        Console.WriteLine("正在分配排名...");
        while (studentStack.Count > 0)
        {
            Student topStudent = studentStack.Pop();
            topStudent.Rank = currentRank;
            
            Console.WriteLine($"排名: {topStudent.Rank}, 姓名: {topStudent.Name}, 分数: {topStudent.Marks}");
            
            currentRank++;
        }
        
        // 此时栈已空
        Console.WriteLine($"操作结束，栈中剩余元素数量: {studentStack.Count}");
    }
}
```


### 多线程安全陷阱与 `ConcurrentStack<T>`
和 `List`, `Dictionary` 一样，普通的 `Stack<T>` **绝不是线程安全的**！
如果多个线程同时 Push/Pop，底层的 `_size` 指针会彻底乱套。
*   **并发解决方案**：请使用 `System.Collections.Concurrent.ConcurrentStack<T>`。
*   **并发栈的独家绝技**：它提供了 `PushRange(T[] items)` 和 `TryPopRange(T[] items)`，可以**一次性原子化地压入/弹出多个元素**，极大减少多线程锁的开销。

### 灵魂拷问：为啥不直接用`List<T>`
既然 `List<T>` 也能在尾部 `Add` 和 `RemoveAt(Count-1)`，为什么还要用 `Stack<T>`？
1.  **代码语义（Self-Documenting Code）**：当你看到 `Stack<T>` 时，你就知道它的数据流向严格受限。而 `List<T>` 允许别人随意 `Insert(0, item)` 破坏 LIFO 规则。用 `Stack` 是在用强类型约束团队的代码规范。
2.  **性能微调**：`Stack<T>` 底层没有 List 那么重的范围校验机制，在极致的高频压栈弹栈场景下，`Stack<T>` 略快一点点（毫秒级）。



## 九、最佳实践
撤销重做（双栈）、迷宫寻路（DFS算法）、括号匹配，遇到这三类需求，闭着眼睛选 `Stack<T>`！
### 废弃非泛型 Stack
除了 `System.Collections.Generic.Stack<T>` 之外，.NET 历史遗留了一个非泛型的 `System.Collections.Stack`。强烈建议在任何代码中**永远不要使用非泛型版本的 Stack**。它将所有元素视为 `object`，不仅丧失了编译期的类型安全，在处理值类型时还会引发致命的装箱/拆箱（Boxing/Unboxing）性能损耗。

### 预设容量优化性能
如果事先知道将要推入栈的最大元素数量，应当在初始化时使用带有容量参数的构造函数：
`Stack<T> myStack = new Stack<T>(100);`
这样可以避免底层数组在扩容时产生的内存分配和数据复制开销，最大化压栈（Push）的性能。

### 现代 C# 的安全取值机制
在多线程环境或数据流不确定的情况下，直接调用 `Pop()` 或 `Peek()` 可能会因为栈为空而导致异常奔溃。现代 C# 开发推荐使用 Try 模式的方法：
*   **`TryPop(out T result)`**：尝试弹栈。如果栈不为空，则将栈顶值赋给 `out` 参数并返回 `true`；如果栈为空，则返回 `false`。
*   **`TryPeek(out T result)`**：尝试窥探栈顶。行为与 `TryPop` 类似但不移除元素。
