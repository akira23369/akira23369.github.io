# 对象关系

## 核心概念：什么是对象关系？

在面向对象设计（OOD）中，类与类之间除了继承关系（"Is-A"，即父子关系）之外，最常见的便是**对象关系**（"Has-A" 或关联关系）。

当一个类中的字段或属性存储了另一个类的对象引用时，这两个类之间就建立了对象关系。
*   **内存视角（参考《CLR via C#》）：** 在托管堆（Managed Heap）上，对象是独立分配的内存块。对象关系并不是将一个对象物理地塞进另一个对象内部，而是在一个对象中保存了指向另一个对象内存地址的**指针（引用，Reference）**。
*   **设计原则（参考《代码大全》）：** 现代软件架构提倡“多用组合（关联），少用继承”。通过对象关系，可以构建出松耦合、高内聚的系统模块。

在实际业务（如电商、学校、企业系统）中，对象关系通常分为三种基本形态：一对一、一对多、多对一。

---

## 一对一关系

**定义：** 实体A的一个对象引用实体B的一个单独对象。

**业务场景：** 一名学生（Student）当前只隶属于一个特定的专业/分院（Branch）。

**代码实现：**
这里使用类作为数据类型。在 `Student` 类中，定义一个类型为 `Branch` 的属性。

```csharp
namespace CollegeSystem
{
    public class Branch
    {
        public string BranchName { get; set; }
        public int NumberOfSemesters { get; set; }
    }

    public class Student
    {
        public int RollNumber { get; set; }
        public string Name { get; set; }
        
        // 建立一对一对象关系
        // 该属性本质上是一个引用变量，用于存储Branch对象的内存地址
        public Branch StudentBranch { get; set; } 
    }

    class Program
    {
        static void Main()
        {
            // 独立创建 Branch 对象
            Branch csBranch = new Branch 
            { 
                BranchName = "Computer Science", 
                NumberOfSemesters = 8 
            };

            // 创建 Student 对象并将 Branch 对象引用赋给它
            Student student1 = new Student
            {
                RollNumber = 1,
                Name = "Scott",
                StudentBranch = csBranch // 引用传递
            };

            // 链式访问 (Chaining)
            Console.WriteLine($"学生: {student1.Name}, 专业: {student1.StudentBranch.BranchName}");
        }
    }
}
```

## 一对多关系

**定义：** 实体A的一个对象，引用了实体B的**多个**对象。这需要借助集合（如 `List<T>`）来实现。

**业务场景：** 一名学生（Student）在校期间会参加多场考试（Examination）。电商系统中，一个订单（Order）包含多个商品（Product）。

**代码实现与优化：**

*   **最佳实践（参考《Effective C#》）：** 
    1. 应当在类内部初始化集合属性，防止外部调用者在使用集合前遇到 `NullReferenceException`。
    2. 在更严谨的领域驱动设计（DDD）中，往往不对外直接暴露 `List<T>` 的 `set` 访问器，而是暴露 `IReadOnlyCollection<T>`，通过专门的方法（如 `AddExamination`）来操作集合，以保护内部状态的封装性。

```csharp
using System.Collections.Generic;

namespace CollegeSystem
{
    public class Examination
    {
        public string ExamName { get; set; }
        public string MonthYear { get; set; }
        public int MaxMarks { get; set; }
        public int SecuredMarks { get; set; }
    }

    public class ExamStudent
    {
        public int RollNumber { get; set; }
        public string Name { get; set; }

        // 一对多关系：一个学生对应多个考试
        // 最佳实践：直接在声明时初始化空集合，防止空引用异常
        public List<Examination> Examinations { get; set; } = new List<Examination>();
    }

    class Program
    {
        static void Main()
        {
            ExamStudent student = new ExamStudent { RollNumber = 101, Name = "Alice" };

            // 向集合中添加多个独立的对象引用
            student.Examinations.Add(new Examination { ExamName = "Module Test 1", MonthYear = "May 2023", MaxMarks = 100, SecuredMarks = 85 });
            student.Examinations.Add(new Examination { ExamName = "Final Exam", MonthYear = "March 2024", MaxMarks = 100, SecuredMarks = 92 });

            Console.WriteLine($"学生: {student.Name}");
            // 遍历一对多关系
            foreach (Examination exam in student.Examinations)
            {
                Console.WriteLine($"- 考试: {exam.ExamName} ({exam.MonthYear}) - 分数: {exam.SecuredMarks}/{exam.MaxMarks}");
            }
        }
    }
}
```

## 多对一关系

**定义：** 从代码结构上看，多对一类的内部结构与一对一完全相同（类中仅包含单一引用属性）。区别在于**运行时的内存状态**：有多个不同对象的引用属性，指向了托管堆上的**同一个目标对象**。

**业务场景：** 多个员工（Employee）隶属于同一个部门（Department）。
**内存透视：** 在这种模式下，`Employee` 对象在堆上有3个独立的实例，但它们的 `EmployeeDepartment` 属性都保存着完全相同的内存地址，均指向堆上唯一的那1个 `Department` 实例。如果修改了这个部门的名称，所有员工看到的部门名称都会同步发生改变。

**代码实现：**

```csharp
namespace CompanySystem
{
    public class Department
    {
        public int DepartmentId { get; set; }
        public string DepartmentName { get; set; }
    }

    public class Employee
    {
        public int EmployeeId { get; set; }
        public string EmployeeName { get; set; }
        
        // 结构上是一对一
        public Department EmployeeDepartment { get; set; }
    }

    class Program
    {
        static void Main()
        {
            // 内存中仅存在一个 Department 对象
            Department accDept = new Department 
            { 
                DepartmentId = 10, 
                DepartmentName = "Accounting" 
            };

            // 创建多个 Employee 对象，并建立 多对一 关系
            Employee emp1 = new Employee { EmployeeId = 1, EmployeeName = "Scott", EmployeeDepartment = accDept };
            Employee emp2 = new Employee { EmployeeId = 2, EmployeeName = "Allen", EmployeeDepartment = accDept };
            Employee emp3 = new Employee { EmployeeId = 3, EmployeeName = "Jones", EmployeeDepartment = accDept };

            // 验证共享引用
            Console.WriteLine($"{emp1.EmployeeName} 属于 {emp1.EmployeeDepartment.DepartmentName}");
            Console.WriteLine($"{emp2.EmployeeName} 属于 {emp2.EmployeeDepartment.DepartmentName}");
        }
    }
}
```

## 总结

在实际架构设计中：
1. **单一引用属性** 构成了 1:1 或 N:1 关系（取决于运行时是否共享目标对象）。
2. **泛型集合引用属性** 构成了 1:N 关系。
3. 如果互相持有对方的泛型集合引用，则构成了 **多对多 (M:N) 关系**（在业务系统中通常会引入一个中间映射类来拆解多对多关系）。


# 类与类之间的耦合度

## 引言
在面向对象编程中，我们常说“万物皆对象”。但在实际的软件系统中，单个对象是无法完成复杂任务的。系统是由多个对象相互协作、相互联系来运转的。理解对象之间的关系，是画好 UML 图、设计出高内聚低耦合系统的前提。

在 C# 中，对象之间的关系主要分为六种：**依赖、关联、聚合、组合、实现、继承**。今天我们来一一拆解。

---

## 依赖关系 —— “我用到了你” (Uses-a)
**耦合度：** ⭐ (极弱)
**概念：** 依赖关系是对象之间最弱的一种联系。通常表现为**一个类的方法使用了另一个类的对象**作为参数，或者在方法体内部实例化了另一个类。如果被依赖的类发生变化，可能会影响到依赖它的类。
**通俗比喻：** 程序员和电脑。程序员（类 A）需要用电脑（类 B）来写代码，但程序员并不“拥有”这台电脑（可能是公司借的），只在工作（方法）时使用它。

**C# 代码示例：**
```csharp
public class Computer 
{
    public void RunIde() 
    {
        Console.WriteLine("运行 Visual Studio...");
    }
}

public class Programmer 
{
    // Computer 作为方法的参数传入，这就是一种依赖
    public void WriteCode(Computer pc) 
    {
        pc.RunIde();
        Console.WriteLine("开始写 Bug...");
    }
}
```

**痛点：** 很多时候，我们在一个方法里直接 `new` 了一个具体的对象。这导致调用者和被调用者死死绑定在一起，无法替换。

**【反面教材：高耦合】**  
假设我们在写一个用户注册功能，注册成功后要往 MySQL 数据库存数据。
```cs
public class UserService 
{
    public void RegisterUser() 
    {
        // 高耦合：直接依赖了底层的具体实现类 MySqlDatabase
        MySqlDatabase db = new MySqlDatabase(); 
        db.Save("user_data");
    }
}
```
_致命缺陷：_ 如果明天公司要求换成 SQL Server 数据库，你必须修改 `UserService` 的代码。违反了“开闭原则（对扩展开放，对修改封闭）”。

**【经典改造：依赖倒置原则 (DIP)】**  
我们引入一个**接口**，让 `UserService` 只依赖接口（抽象），不依赖具体类。这就是经典的**依赖注入（DI）**。
```cs
// 1. 定义抽象（接口）
public interface IDatabase 
{
    void Save(string data);
}

// 2. 具体实现
public class MySqlDatabase : IDatabase { ... }
public class SqlServerDatabase : IDatabase { ... }

// 3. 业务类只依赖接口
public class UserService 
{
    // 通过方法参数注入依赖，彻底解耦！
    public void RegisterUser(IDatabase db) 
    {
        db.Save("user_data");
    }
}

// 客户端调用：想传什么数据库就传什么，UserService 代码一行都不用改！
// userService.RegisterUser(new SqlServerDatabase());

```

## 关联关系 —— “我认识你” (Knows-a / Has-a)
**耦合度：** ⭐⭐ (较弱)
**概念：** 关联关系是一种结构化的关系，指两个独立的类之间存在固定的联系。通常表现为 **一个类作为另一个类的属性（字段）** 存在。关联可以是单向的，也可以是双向的。
**通俗比喻：** 客户和地址。客户有一个常住地址，它们是平等的实体，即使客户销户了，地址这个实体依然客观存在。

**C# 代码示例：**
```csharp
public class Address 
{
    public string City { get; set; }
}

public class Customer 
{
    public string Name { get; set; }
    // Address 作为 Customer 的一个属性，建立了关联
    public Address HomeAddress { get; set; } 
}
```


**痛点：** 当一个类拥有另一个类作为属性时，如果这个属性是具体的类，一旦逻辑变化，包含它的类也要跟着改。
**【反面教材：死板的关联】**  
电商系统中，订单类关联了一个打折类。

```cs
public class NormalDiscount 
{
    public decimal Calculate(decimal price) => price * 0.9m; // 打9折
}

public class Order 
{
    public decimal TotalPrice { get; set; }
    // 强关联：把具体的打折类写死了
    public NormalDiscount Discount { get; set; } = new NormalDiscount();
    
    public decimal GetFinalPrice() => Discount.Calculate(TotalPrice);
}

```
_致命缺陷：_ 双十一来了，要搞“满减”，又要搞“VIP打8折”，你只能不断修改 `Order` 类。

**【经典改造：策略模式】**  
将关联的属性变成一个**接口**，你可以随时动态替换策略。
```cs
public interface IDiscountStrategy 
{
    decimal Calculate(decimal price);
}

public class VipDiscount : IDiscountStrategy { ... } // VIP打8折
public class HolidayDiscount : IDiscountStrategy { ... } // 节日满减

public class Order 
{
    public decimal TotalPrice { get; set; }
    // 弱关联：关联一个接口
    public IDiscountStrategy DiscountStrategy { get; set; } 

    // 动态注入不同的打折策略
    public Order(IDiscountStrategy strategy) 
    {
        DiscountStrategy = strategy;
    }

    public decimal GetFinalPrice() => DiscountStrategy.Calculate(TotalPrice);
}

```

## 聚合关系 —— “你是我的团队一员” (Weak Has-a)
**耦合度：** ⭐⭐⭐ (中等)
**概念：** 聚合是关联关系的一种特例，它体现的是**整体与部分**的关系。但这种关系比较松散，**部分可以脱离整体独立存在**（生命周期不同步）。通常通过构造函数或 Setter 方法将“部分”传递给“整体”。
**通俗比喻：** 球队与球员。球员属于球队，但如果球队解散了，球员依然存在，可以转会去其他球队。

**C# 代码示例：**
```csharp
public class Player 
{
    public string Name { get; set; }
}

public class Team 
{
    public string TeamName { get; set; }
    public List<Player> Players { get; set; }

    // 球员是通过外部传进来的，Team 并不负责 Player 的生死（实例化和销毁）
    public Team(string name, List<Player> players) 
    {
        TeamName = name;
        Players = players;
    }
}
```

**痛点：** 如果你在“整体”内部直接创建了“部分”，会导致两者生命周期强绑定，不仅无法共享“部分”，还极大地浪费内存。

**【反面教材：错误的资源管理】**  
一门课程有很多学生。
```cs
public class Course 
{
    public List<Student> Students { get; set; } = new List<Student>();

    public Course() 
    {
        // 错误：在课程内部实例化学生。如果课程取消，学生对象也没了？
        // 而且别的课程无法共享这些学生对象。
        Students.Add(new Student("张三")); 
    }
}
```


**【经典改造：外部聚合，对象共享】**  
通过外部传入（如依赖注入容器或工厂），管理各自独立的生命周期。
```cs
public class Course 
{
    public List<Student> Students { get; private set; }

    // 聚合关系的精髓：部分是从外部聚拢过来的
    public Course(List<Student> enrolledStudents) 
    {
        Students = enrolledStudents;
    }
}

// 外部逻辑：学生客观存在，可以加入多门课程。
var zhangSan = new Student("张三");
var mathCourse = new Course(new List<Student> { zhangSan });
var englishCourse = new Course(new List<Student> { zhangSan });

```

## 组合关系 —— “同生共死” (Strong Has-a / Contains-a)
**耦合度：** ⭐⭐⭐⭐ (较强)
**概念：** 组合也是**整体与部分**的关系，但它是最强的关联关系。在组合中，**整体和部分是同生共死的**（生命周期同步）。如果整体被销毁，部分也随之毁灭。“部分”通常在“整体”的构造函数内部被实例化。
**通俗比喻：** 人和心脏。人是由心脏等器官组成的。人一出生就有心脏，人去世了，心脏也就停止工作了（不考虑医学移植等极端情况）。
**“组合“的不同**：UML术语 和 设计模式的组合不一样

**C# 代码示例：**
```csharp
public class Heart 
{
    public void Beat() { Console.WriteLine("心脏跳动..."); }
}

public class Human 
{
    // 心脏作为整体的一部分
    private Heart myHeart;

    public Human() 
    {
        // 关键点：在整体的内部实例化部分。
        // 外界无法干预 Heart 的创建，Human 死了，myHeart 也就被垃圾回收了。
        myHeart = new Heart(); 
    }

    public void Live() 
    {
        myHeart.Beat();
    }
}
```

## 实现关系 —— “我能做这事” (Can-do)
**耦合度：** ⭐⭐⭐⭐⭐ (强)
**概念：** 指一个类实现了一个接口（Interface）。接口定义了“能做什么”（契约），而类提供了具体的“怎么做”（实现）。这是面向对象中实现多态的重要手段。
**通俗比喻：** 任何实现了“会飞的（IFlyable）”接口的东西，都可以飞。无论是鸟还是飞机。

**C# 代码示例：**
```csharp
// 定义契约
public interface IFlyable 
{
    void Fly();
}

// 飞机实现接口
public class Airplane : IFlyable 
{
    public void Fly() 
    {
        Console.WriteLine("依靠引擎和空气动力学飞行");
    }
}

// 鸟实现接口
public class Bird : IFlyable 
{
    public void Fly() 
    {
        Console.WriteLine("扇动翅膀飞行");
    }
}
```

## 继承关系 —— “我是一种...” (Is-a)
**耦合度：** ⭐⭐⭐⭐⭐⭐ (极强)
**概念：** 继承是面向对象三大特性之一。子类（派生类）继承父类（基类）的属性和方法，并且可以扩展自己的功能或重写父类的方法。这是最紧密的耦合关系，滥用继承会导致代码僵化。
**通俗比喻：** 狗是一种动物。狗拥有动物的共有特征（吃、睡），同时也有自己的特殊特征（看家、汪汪叫）。

**C# 代码示例：**
```csharp
// 父类
public class Animal 
{
    public void Eat() { Console.WriteLine("进食中..."); }
}

// 子类继承父类 (C# 中使用冒号 :)
public class Dog : Animal 
{
    public void Bark() 
    {
        Console.WriteLine("汪汪汪！");
    }
}
```

**【经典应用：模板方法模式】**  
如果非要用继承，最好的方式是：**父类定义算法骨架，子类实现特定步骤。**

假设我们要解析不同格式的文件（PDF, Word, Excel），提取文本。
```cs
// 父类：控制了整体流程，不可被子类篡改核心逻辑
public abstract class DocumentParser 
{
    // 模板方法：定义了处理流程
    public void ParseDocument(string filePath) 
    {
        OpenFile(filePath);
        ExtractText();     // 这一步不同文件格式不一样，留给子类实现
        CloseFile();
    }

    private void OpenFile(string path) { Console.WriteLine("打开文件..."); }
    private void CloseFile() { Console.WriteLine("关闭文件并清理内存..."); }

    // 留给子类去重写的钩子
    protected abstract void ExtractText(); 
}

// 子类：只负责自己该干的那部分，不干扰整个解析流程
public class PdfParser : DocumentParser 
{
    protected override void ExtractText() 
    {
        Console.WriteLine("使用 PDF 引擎提取文字...");
    }
}

public class WordParser : DocumentParser 
{
    protected override void ExtractText() 
    {
        Console.WriteLine("解析 Office XML 提取文字...");
    }
}

```

## 总结

为了方便大家记忆，可以参考这个表格：

| 关系名称 | 英文 | 关键字/语义 | 耦合度 | C# 代码特征 |
| :--- | :--- | :--- | :---: | :--- |
| **依赖** | Dependency | Uses-a (使用) | 最弱 | 类作为**方法参数**或局部变量 |
| **关联** | Association | Has-a (拥有) | 弱 | 类作为**成员属性/字段** |
| **聚合** | Aggregation | Weak Part-of (松散包含) | 中等 | 类作为成员属性，**外部传入** (独立存活) |
| **组合** | Composition | Strong Part-of (紧密包含) | 较强 | 类作为成员属性，**内部实例化** (同生共死) |
| **实现** | Realization | Can-do (能做) | 强 | 实现 `interface` 接口 |
| **继承** | Generalization| Is-a (是一种) | 最强 | 继承 `abstract class` 或普通类 (`:`) |
