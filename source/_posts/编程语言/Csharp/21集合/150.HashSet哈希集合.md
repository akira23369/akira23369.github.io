# `HashSet<T>` (哈希集合)

## 一、 核心概念与定位

`HashSet<T>` 位于 `System.Collections.Generic` 命名空间下。可以将其在心智模型中理解为**只有键没有值的哈希表（Hashtable/Dictionary）**。

它的核心设计目标非常明确：**提供极速的元素存在性检索（检索元素是否存在），并绝对保证集合中元素的唯一性。**

**与 `List<T>` 的本质区别**
*   在 `List<T>` 中检索一个元素是否存在（使用 `Contains`），必须从头到尾遍历底层数组，时间复杂度为 $O(N)$（线性查找）。当数据量达到百万级时，性能消耗极大。
*   在 `HashSet<T>` 中，通过哈希算法直接定位元素的内存地址，时间复杂度趋近于 $O(1)$。在处理海量数据的存在性验证时，`HashSet<T>` 是绝对的优先选择。

## 二、 底层运行机制

`HashSet<T>` 的极速特性建立在精妙的数学计算和底层结构之上。

### 索引的动态计算
与通过下标按序排列的数组不同，`HashSet<T>` 计算存储位置的公式与哈希表类似：
**目标索引 (Index) = 元素的 HashCode % 集合的内部容量 (Capacity)**

*   **素数容量**：为了最大程度降低哈希冲突（不同的值算出相同的索引），`HashSet<T>` 的底层数组容量始终维持为**素数**（默认初始为 17）。随着元素增加，扩容时会自动寻找下一个更大的素数作为新容量。
*   **重新散列 (Rehashing)**：每次扩容时，底层数组大小发生改变，所有的元素的索引必须根据新的容量重新计算并重新排布。

### HashCode 的获取机制
*   **基本类型**：数值类型（如 `int`）的哈希码就是数值本身；字符串（`string`）的哈希码由底层基于字符集的散列算法预设实现。
*   **自定义对象 (重要考点)**：如果将自定义类（如 `Employee`）放入 `HashSet<T>`，必须重写 `System.Object` 的 `GetHashCode()` 和 `Equals()` 方法。通常使用具有业务唯一性的属性（如 `EmployeeId`）来生成哈希码。

### 冲突处理
当两个不同的值计算出相同的索引时（哈希冲突），底层依靠引入“链表”结构解决。新元素会附加在同一索引下，并通过“Next”指针维护关系。查找时，定位到索引后再通过 `Equals()` 方法遍历极短的链表以确认具体值。

## 三、 `HashSet<T>` 核心特性与纠误

*   **唯一性**：不允许重复值。尝试 `Add` 相同的值不会抛出异常，而是直接返回 `false`。
*   **无索引器**：元素是基于哈希算法散布在内存中的，因此不支持按索引访问（例如不能写 `hashSet[0]`）。
*   **关于 Null 值**：引用类型的 `HashSet<T>` 允许且仅允许包含**一个** `null` 值。
*   **关于排序与顺序的纠正**：虽然在初次按顺序执行 `Add` 时，遍历输出的顺序可能看起来与插入顺序一致，但**在计算机科学和 C# 语言规范中，`HashSet<T>` 绝对不保证元素的排列顺序**。特别是发生过元素的 `Remove` 操作后，底层数组会出现“空洞（Holes）”，新的 `Add` 操作会优先填补这些空洞，此时遍历顺序将与插入顺序完全不一致。

## 四、核心属性

### `Count`
*   **说明**：获取集合中实际包含的元素数量。
*   **时间复杂度**：O(1)。
*   **示例**：
```csharp
HashSet<int> set = new HashSet<int> { 1, 2, 3, 3 }; // 重复的3会被自动过滤
Console.WriteLine(set.Count); // 输出: 3
```

## 五、 基础操作方法

### `Add(T item)`
*   **说明**：向集合中添加元素。
*   **返回值**：`bool`。如果添加成功（元素不存在）返回 `true`；如果元素已存在，返回 `false` 且不报错。
*   **时间复杂度**：平均 O(1)。
*   **示例**：
```csharp
HashSet<string> tags = new HashSet<string>();
bool isAdded1 = tags.Add("C#"); // true
bool isAdded2 = tags.Add("C#"); // false (重复了)
```

### `Remove(T item)`
*   **说明**：移除指定元素。返回 `true` 表示移除成功。
*   **时间复杂度**：平均 O(1)。
```csharp
tags.Remove("C#");
```

### `Clear()`
*   **说明**：清空集合所有元素。
```csharp
tags.Clear();
```

### `Contains(T item)`
*   **说明**：判断集合是否包含某元素。
*   **时间复杂度**：O(1)（**这是 HashSet 的杀手锏**）。
*   **示例**：
```csharp
HashSet<int> blackList = new HashSet<int> { 101, 202, 305 };
if (blackList.Contains(202)) {
    Console.WriteLine("该用户在黑名单中");
}
```

### `TryGetValue(T equalValue, out T actualValue)` 
*(现代 C# 特性)*
*   **说明**：寻找与传入值相等的元素，并返回集合中存储的那个**实际对象引用**。
*   **用途**：当两个对象 `Equals` 相等但引用不同时，可以获取到集合内已存在的那个实例。
```csharp
HashSet<string> set = new HashSet<string> { "HELLO" };
if (set.TryGetValue("hello".ToUpper(), out string found)) {
    // found 是集合里的 "HELLO"
}
```

## 六、集合运算方法

这是 `HashSet<T>` 最强大的地方。它提供了原生的数学集合运算。

*假设有两个集合：*
`var setA = new HashSet<int> { 1, 2, 3 };`
`var setB = new int[] { 3, 4, 5 };`

### `UnionWith(IEnumerable<T> other)` (并集 ∪)
*   **说明**：修改当前集合，使其包含自身和另一个集合的所有元素。
*   **示例**：
```csharp
setA.UnionWith(setB); 
// setA 变成: { 1, 2, 3, 4, 5 }
```

### `IntersectWith(IEnumerable<T> other)` (交集 ∩)
*   **说明**：修改当前集合，仅保留自身和另一个集合中**共有**的元素。
*   **示例**：
```csharp
setA.IntersectWith(setB); 
// setA 变成: { 3 }
```

### `ExceptWith(IEnumerable<T> other)` (差集 -)
*   **说明**：从当前集合中移除另一个集合中包含的所有元素。
*   **示例**：
```csharp
setA.ExceptWith(setB); 
// setA 变成: { 1, 2 } (移除了共有元素 3)
```

### `SymmetricExceptWith(IEnumerable<T> other)` (补集/对称差集 Δ)
*   **说明**：修改当前集合，使其仅包含：**要么在 A 中，要么在 B 中，但不同时在 A 和 B 中的元素**。
*   **示例**：
```csharp
setA.SymmetricExceptWith(setB); 
// setA 变成: { 1, 2, 4, 5 } (去掉了共同的 3)
```

## 七、 集合判定方法

这些方法返回 `bool`，不会修改原集合。

### `IsSubsetOf(IEnumerable<T> other)` (子集)
*   判断当前集合是否是另一个集合的子集（A ⊆ B）。
```cs
var setA = new HashSet<int> { 1, 2, 3 };
var setB = new HashSet<int> { 1, 2, 3, 4 };

bool isSubset = setA.IsSubsetOf(setB); 
// 结果: True (因为 1,2,3 都在 setB 里)

bool selfSubset = setA.IsSubsetOf(new HashSet<int> { 1, 2, 3 });
// 结果: True (集合本身也是自己的子集)
```

### `IsSupersetOf(IEnumerable<T> other)` (超集)
*   判断当前集合是否是另一个集合的超集（A ⊇ B）。
```cs
var setA = new HashSet<int> { 1, 2, 3 };
var setB = new HashSet<int> { 1, 2, 3, 4 };

bool isSuperset = setB.IsSupersetOf(setA); 
// 结果: True (setB 包含了 setA 的所有成员)

bool notSuperset = setA.IsSupersetOf(setB);
// 结果: False (setA 只有 3 个元素，包不下 setB 的 4 个)
```


### `IsProperSubsetOf(IEnumerable<T> other)` (真子集)
*   判断 A 是否是 B 的子集且 A != B。
```cs
var setA = new HashSet<int> { 1, 2, 3 };
var setB = new HashSet<int> { 1, 2, 3, 4 };
var setC = new HashSet<int> { 1, 2, 3 };

bool isProper = setA.IsProperSubsetOf(setB); 
// 结果: True (A 是 B 的子集，且 A 比 B 元素少)

bool notProper = setA.IsProperSubsetOf(setC);
// 结果: False (虽然元素一样，但因为相等，所以不是“真”子集)
```


### `IsProperSupersetOf(IEnumerable<T> other)` (真超集)
*   判断 A 是否是 B 的超集且 A != B。
```cs
var setA = new HashSet<int> { 1, 2, 3 };
var setB = new HashSet<int> { 1, 2, 3, 4 };

bool isProperSuper = setB.IsProperSupersetOf(setA); 
// 结果: True (B 包含 A 且多出了一个元素 '4')

bool notProperSuper = setB.IsProperSupersetOf(new HashSet<int> { 1, 2, 3, 4 });
// 结果: False (元素完全一样，不算“真”超集)
```

### `Overlaps(IEnumerable<T> other)` (重叠)
*   **说明**：判断两个集合是否有**任何**共同元素。
*   **性能建议**：如果你只是想知道“有没有重合”，用这个比用 `IntersectWith` 效率高得多，因为它只要找到一个匹配就立即返回。
```cs
var setA = new HashSet<int> { 1, 2, 3 };
var setD = new HashSet<int> { 3, 4, 5 };
var setE = new HashSet<int> { 6, 7, 8 };

bool hasOverlap = setA.Overlaps(setD); 
// 结果: True (它们都有元素 '3')

bool noOverlap = setA.Overlaps(setE);
// 结果: False (完全没有交集)
```

### `SetEquals(IEnumerable<T> other)` (相等)
*   **说明**：判断两个集合是否包含完全相同的元素（忽略顺序，忽略重复项）。
```csharp
HashSet<int> a = new HashSet<int> { 1, 2 };
int[] b = { 2, 1, 1, 2 };
bool equal = a.SetEquals(b); // 返回 true
```

## 八、 补充实用方法

### `RemoveWhere(Predicate<T> match)`
*   **说明**：按条件批量删除。
*   **示例**：
```csharp
HashSet<int> numbers = new HashSet<int> { 1, 2, 3, 4, 5, 6 };
numbers.RemoveWhere(n => n % 2 == 0); // 移除所有偶数
```

### `TrimExcess()`
*   **说明**：**收缩底层哈希桶数组，释放多余内存。**`HashSet<T>` 或 `List<T>` 在内部会预分配比实际元素更多的空间（容量），以避免频繁地重新分配内存。当你删除了大量数据后，这些预留空间依然占用内存。`TrimExcess()` 就像是把这些“空位”退掉。
```cs
var numbers = new HashSet<int>();

// 1. 模拟存入 10,000 个元素
for (int i = 0; i < 10000; i++) numbers.Add(i);

// 2. 模拟删除了绝大部分数据
for (int i = 0; i < 9000; i++) numbers.Remove(i);

// 此时，集合里只剩 1000 个元素，但它占用的内存可能还是 10,000 个位置的大小
Console.WriteLine($"当前元素数量: {numbers.Count}");

// 3. 强制收缩底层数组以释放内存
numbers.TrimExcess(); 

Console.WriteLine("已清理多余的预分配空间。");
```


### `CopyTo(T[] array)`
*   **说明**：当你需要把集合中的元素“导出来”放到一个普通的数组中进行处理（比如传给只接受数组的旧接口）时使用。

```cs
var fruitSet = new HashSet<string> { "Apple", "Banana", "Cherry" };

// 1. 准备一个目标数组，长度必须足够大
string[] fruitArray = new string[fruitSet.Count];

// 2. 将集合元素复制到数组中
fruitSet.CopyTo(fruitArray);

// 验证结果
Console.WriteLine($"数组第一个元素: {fruitArray[0]}"); 
// 输出: Apple (注意：HashSet 是无序的，顺序可能不固定)
```
变体用法：指定起始位置
如果你想把集合的内容插入到数组的中间位置：
```cs
string[] targetArray = new string[10];
// 从 targetArray 的索引 5 开始存放集合内容
fruitSet.CopyTo(targetArray, 5);
```

## 九、补充高级

### 性能对比：`HashSet` vs `List`
如果你有 50,000 个字符串，现在要检查某个字符串是否存在：
*   **`List<string>.Contains`**: 需要逐个对比，最坏情况对比 50,000 次。
*   **`HashSet<string>.Contains`**: 直接计算哈希值，对比 1 次（理想状态）。
*   **结论**：在处理大数据量的“成员资格检查”时，`HashSet` 是绝对的王者。

### 自定义对象的唯一性
《Effective C#》明确指出，如果在使用 `HashSet<T>` 时自定义对象作为泛型类型，开发者必须严格遵守 `Equals()` 和 `GetHashCode()` 的契约：
*   **相等对象必须具有相同的 HashCode**：如果 `A.Equals(B)` 为 true，则 `A.GetHashCode()` 必须等于 `B.GetHashCode()`。否则 `HashSet` 内部会出现逻辑崩溃（认为它们不同，存入多个副本，或检索不到）。
*   **哈希码应基于不可变（Immutable）字段生成**：如果把对象放入 `HashSet<T>` 后，又修改了参与生成 HashCode 的属性，该对象的哈希码就会改变，导致其在集合中“迷失”（存在于集合中，但通过新的哈希码找不到了），引发严重的内存泄漏与业务 Bug。


```csharp
public class User {
    public int Id { get; set; }
    public override bool Equals(object obj) => obj is User u && u.Id == Id;
    public override int GetHashCode() => Id.GetHashCode();
}

// 这样 HashSet 才能根据 Id 自动去重
```

### 构造函数的骚操作
你可以通过构造函数传入 `IEqualityComparer<T>` 来改变去重规则。
**示例：不区分大小写的字符串集合**
```csharp
var caseInsensitiveSet = new HashSet<string>(StringComparer.OrdinalIgnoreCase);
caseInsensitiveSet.Add("Apple");
bool hasApple = caseInsensitiveSet.Contains("apple"); // 返回 true!
```

### `HashSet` 与 LINQ `Distinct()` 的区别
*   `list.Distinct()` 会生成一个临时的 `HashSet` 来去重，并返回 `IEnumerable`（延迟执行）。
*   如果你需要多次查重，直接把数据存入 `HashSet` 常驻内存更高效，不要反复调用 `Distinct()`。

## 十、 总结提炼

1.  **定位**：**只要看到“去重”、“唯一”、“集合运算（交并差）”、“快速查找”，就用 HashSet。**
2.  **性能核心**：Contains/Add/Remove 都是 **O(1)**。
3.  **对比**：
    *   想排序？用 `SortedSet<T>`。
    *   想键值对+排序？用`SortedList<TKey, TValue>` 或 `SortedDictionary<TKey, TValue>`。
    *   想存键值对？用 `Dictionary<K,V>`。
    *   想按索引访问？用 `List<T>`。
    *   元素是否存在且不关心顺序？用`HashSet<T>`。
4.  **注意**：`HashSet` 遍历时顺序是不固定的，且不能通过索引访问。
5.  **必杀技**：`UnionWith`, `IntersectWith` 等方法可以直接在原地修改集合，代码简洁且性能极高。
