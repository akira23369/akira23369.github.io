# 排序从IComparable到LINQ

当我们在处理基础类型（如 `int`、`string`）时，调用 `list.Sort()` 是理所当然的。但当我们面对**自定义对象**（比如一个 `Student` 类，里面有成绩、年龄、姓名）时，编译器就懵了：“你让我排序，但我怎么知道哪个学生‘更大’？”

在 C# 中给对象排序，本质上是要解决一个问题：**A 和 B 谁排在前面？**
根据使用场景的不同，我们有 4 种主流的解决方案，它们按照**灵活性**和**现代程度**依次递进。

---

## `IComparable<T>`

**核心思想**：“我这个对象天生就知道怎么和同类比较大小。”

如果你希望你的自定义类有一个**默认的排序方式**（比如学生默认按“成绩”排序），你应该让这个类实现 `System.IComparable<T>` 接口。

**核心方法：`CompareTo`**
实现该接口，只需重写一个方法：`int CompareTo(T other)`。
这个方法的返回值非常重要，它是所有 C# 排序底层的通用契约：
*   **小于 0**（通常是 -1）：代表 `当前对象(this)` **小于** `other`（this 排在前面）。
*   **等于 0**：代表两者**相等**。
*   **大于 0**（通常是 1）：代表 `当前对象(this)` **大于** `other`（this 排在后面）。

```csharp
using System;
using System.Collections.Generic;

public class Student : IComparable<Student>
{
    public string Name { get; set; }
    public int Score { get; set; }

    // 实现 IComparable<T> 的方法
    public int CompareTo(Student other)
    {
        if (other == null) return 1; // 约定：正常对象永远大于 null

        // 技巧：直接借用内置类型 (int) 已经写好的 CompareTo 方法！
        // 这样写是升序 (从小到大)
        return this.Score.CompareTo(other.Score); 
        
        // 如果想默认降序 (从大到小)，反过来写即可：
        // return other.Score.CompareTo(this.Score);
    }
}

// 测试：
var list = new List<Student>
{
    new Student { Name = "张三", Score = 80 },
    new Student { Name = "李四", Score = 95 },
    new Student { Name = "王五", Score = 60 }
};

// 编译器会去找 Student 里的 CompareTo 方法
list.Sort(); 
// 排序后顺序：王五(60) -> 张三(80) -> 李四(95)
```
**优点**：调用简单，`list.Sort()` 直接搞定。
**缺点**：太死板！一个类只能有一种默认排序。如果我今天想按“成绩”排，明天想按“姓名”排，除非改类的源码，`IComparable<T>` 就无能为力了。

---

## `IComparer<T>`

**核心思想**：“对象本身不知道怎么比，我请一个第三方裁判来评判他们。”

当我们**无法修改类的源码**（比如用了第三方库的对象），或者需要**多种不同的排序规则**时，我们可以编写一个专门负责比较的“裁判类”，这个类要实现 `System.Collections.Generic.IComparer<T>` 接口。

**核心方法：`Compare`**
裁判需要实现：`int Compare(T x, T y)`。返回值契约与前面完全一致。

假设刚才的 `Student` 类除了成绩，还有 `Age`（年龄）。现在我们需要按年龄排序。

```csharp
public class AgeComparer : IComparer<Student>
{
    public int Compare(Student x, Student y)
    {
        if (x == null && y == null) return 0;
        if (x == null) return -1;
        if (y == null) return 1;

        return x.Age.CompareTo(y.Age);
    }
}

// 测试：
// 把裁判实例化，作为参数传给 Sort 方法！
list.Sort(new AgeComparer()); 
```
**优点**：解耦，极其灵活。你可以写无数个 Comparer（如 `NameComparer`, `ScoreComparer`）供不同场景使用。
**缺点**：太啰嗦！哪怕只是为了按年龄排个序，还要专门新建一个类，产生了大量的样板代码。

---

## `Comparison<T>`委托

**核心思想**：“为了排个序建个类太麻烦了，我直接把排序逻辑写在方法参数里。”

`List<T>.Sort()` 提供了一个重载，接受一个名为 `Comparison<T>` 的委托（本质上就是一个返回 `int`，接收两个参数的方法）。结合 C# 的 **Lambda 表达式**，我们可以把几十行的裁判类浓缩成一行代码！

不写任何 Comparer 类，直接在调用时手搓排序逻辑：
```csharp
// 1. 简单场景：按年龄升序
list.Sort((x, y) => x.Age.CompareTo(y.Age));

// 2. 复杂场景：先按成绩降序，成绩一样再按年龄升序
list.Sort((x, y) =>
{
    int scoreResult = y.Score.CompareTo(x.Score); // 降序：y比x
    if (scoreResult != 0)
    {
        return scoreResult; // 成绩不一样，直接出结果
    }
    else
    {
        return x.Age.CompareTo(y.Age); // 成绩一样，按年龄升序：x比y
    }
});
```
**优点**：极其简洁，不需要额外声明类，非常适合“一次性”的复杂排序规则。
**缺点**：它是**原地修改（In-place）** 操作，会改变原集合的顺序；且排序逻辑如果太复杂，写在 Lambda 里会导致代码可读性下降。

## LINQ(`OrderBy` / `ThenBy`)

**核心思想**：“别告诉我底层返回 1 还是 -1，直接告诉我你要按哪个字段排！”

在现代 C# 开发中，**90% 以上的日常排序都会使用 LINQ**。LINQ 将排序从“命令式（教机器怎么做）”提升到了“声明式（告诉机器我要什么）”。

**核心方法**
*   `OrderBy(x => x.Property)`：升序
*   `OrderByDescending(x => x.Property)`：降序
*   `ThenBy()` / `ThenByDescending()`：次要排序条件（当第一个条件相等时触发）


重写第三层中那个“先按成绩降序，再按年龄升序”的复杂逻辑：

```csharp
using System.Linq; // 必须引入 LINQ 命名空间

// 注意：LINQ 不会修改原集合！它会返回一个新的、排好序的 IEnumerable 序列。
var sortedList = list
    .OrderByDescending(s => s.Score)  // 第一条件：成绩降序
    .ThenBy(s => s.Age)               // 第二条件：年龄升序
    .ToList();                        // 固化为新的 List
```

**LINQ 排序的底层秘密**
很多初学者以为 LINQ 只是语法糖，其实大有门道：
*   **非破坏性（稳定排序）**：`list.Sort()` 会直接把原列表打乱重排，而 LINQ 会保持原列表不变，生成一个新的序列（纯函数思想）。
*   **稳定性（Stability）**：C# 的 `list.Sort()` 使用的是快速排序等不稳定算法（如果两个元素相等，它们在排序后的相对位置可能会变）；而 **LINQ 的 `OrderBy` 是稳定排序算法**，相等元素的相对位置严格保持不变！

## 总结

面对各种排序需求，我该怎么选？请参考这个决策树：

| 需求场景                      | 推荐方案                         | 核心特征                                  |
| :------------------------ | :--------------------------- | :------------------------------------ |
| **现代开发、查询数据、不改变原列表**      | **LINQ (`OrderBy`)**         | 代码最优雅，可读性满分，不改变原数据。                   |
| **需要在原列表上就地排序（对性能/内存敏感）** | **委托 (`Comparison` Lambda)** | `list.Sort((x,y) => ...)` 无需建类，内存开销小。 |
| **我写了一个核心业务实体，它就该有天生的顺序** | **实现 `IComparable<T>`**      | 制定对象的“默认出厂排序规则”。                      |
| **跨项目复用极其复杂的多维排序逻辑**      | **实现 `IComparer<T>`**        | 将排序逻辑单独封装成类，方便单元测试和复用。                |

**最后的一个小贴士（避坑）：**
当你手写 `CompareTo` 或 `Compare` 时，**永远不要使用减法**来返回结果！（比如 `return x.Score - y.Score;`）。
虽然数学上看起来很合理，但如果遇到极大的正数减去极小的负数，会发生**整数溢出（Integer Overflow）**，导致排序完全错乱！
**正确的做法永远是调用基础类型的 `CompareTo`：`return x.Score.CompareTo(y.Score);`**
