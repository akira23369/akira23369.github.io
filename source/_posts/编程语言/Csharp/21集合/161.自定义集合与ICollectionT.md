# 自定义集合与`ICollection<T>`

## 为什么需要 `ICollection<T>`？
在上一篇中，我们实现了 `IEnumerable<T>`，让自定义集合支持了 `foreach` 循环。但是 `IEnumerable<T>` 有很大的局限性：
1. **只能看，不能动**：它没有提供 `Add`、`Remove` 等修改集合的方法。
2. **不知道数量**：虽然你可以用 LINQ 的 `.Count()` 扩展方法，但对于纯粹的 `IEnumerable<T>`，LINQ 在底层必须把所有元素从头到尾遍历一遍才能数出数量，这在数据量大时性能极差（时间复杂度 O(N)）。

为了赋予集合**增、删、改、查数量**的能力，C# 提供了 `System.Collections.Generic.ICollection<T>` 接口。
> **注意**：`ICollection<T>` 继承自 `IEnumerable<T>`。也就是说，实现了 `ICollection<T>`，就必定具备了遍历的能力。

## `ICollection<T>`的“全家桶”成员
如果你在一个类上实现 `ICollection<T>`，编译器会要求你实现以下成员：

**两个属性：**
*   `Count`：获取集合中实际包含的元素数量（直接返回数字，时间复杂度 O(1)）。
*   `IsReadOnly`：表示该集合是否是只读的。如果是 `true`，调用 `Add` 或 `Remove` 就会抛出异常。

**五个方法：**
*   `Add(T item)`：把元素放入集合。
*   `Remove(T item)`：从集合中移除特定元素，成功返回 `true`，找不到返回 `false`。
*   `Clear()`：清空集合中的所有元素。
*   `Contains(T item)`：检查集合中是否包含特定元素。
*   `CopyTo(T[] array, int arrayIndex)`：将集合中的元素复制到一个数组中（通常用于底层内存交互或跨 API 传递数据）。

## 写一个“拒绝 Null”的自定义集合(内部`List<T>`)
实际开发中，如果我们要写自定义集合，通常**不需要从零开始申请内存（比如自己维护数组的扩容）**。最成熟的做法是 **“组合优于继承”**——在类的内部包一个标准的 `List<T>`，然后用 `ICollection<T>` 将我们需要的功能暴露出去，并加上我们自己的业务逻辑。

假设我们要写一个 `NotNullCollection<T>`，它具有普通集合的所有功能，但**绝对不允许添加 null 值**。

```csharp
using System;
using System.Collections;
using System.Collections.Generic;

// 限制 T 必须是引用类型 (class)，因为值类型本来就不能为 null
public class NotNullCollection<T> : ICollection<T> where T : class
{
    // 核心秘诀：内部用一个 List<T> 来干脏活累活
    private List<T> _innerList = new List<T>();

    // ================= 1. IEnumerable<T> 的成员 =================
    public IEnumerator<T> GetEnumerator()
    {
        return _innerList.GetEnumerator();
    }

    IEnumerator IEnumerable.GetEnumerator()
    {
        return _innerList.GetEnumerator();
    }

    // ================= 2. ICollection<T> 的属性 =================
    public int Count => _innerList.Count;
    
    // 我们的集合允许修改，所以返回 false
    public bool IsReadOnly => false; 

    // ================= 3. ICollection<T> 的方法 =================
    
    // 【核心业务逻辑】：重写 Add 方法，拦截 null 值
    public void Add(T item)
    {
        if (item == null)
        {
            throw new ArgumentNullException(nameof(item), "严重警告：本集合拒绝接受 null 元素！");
        }
        _innerList.Add(item);
    }

    // 下面的方法，直接“甩锅”给内部的 _innerList 即可
    public bool Remove(T item)
    {
        // 这里可以按需加入你自己的逻辑，比如记录日志：
        // Console.WriteLine($"正在移除 {item}");
        return _innerList.Remove(item);
    }

    public void Clear()
    {
        _innerList.Clear();
    }

    public bool Contains(T item)
    {
        return _innerList.Contains(item);
    }

    public void CopyTo(T[] array, int arrayIndex)
    {
        _innerList.CopyTo(array, arrayIndex);
    }
}
```

## 测试我们的自定义集合

```csharp
class Program
{
    static void Main()
    {
        var myCollection = new NotNullCollection<string>();

        // 1. 正常添加
        myCollection.Add("Hello");
        myCollection.Add("World");
        
        Console.WriteLine($"当前集合数量: {myCollection.Count}"); // 输出 2

        // 2. 遍历 (因为继承了 IEnumerable<T>)
        foreach (var item in myCollection)
        {
            Console.WriteLine(item);
        }

        // 3. 触发自定义逻辑拦截
        try
        {
            myCollection.Add(null); // 这里会抛出异常
        }
        catch (ArgumentNullException ex)
        {
            Console.WriteLine(ex.Message); 
            // 输出: 严重警告：本集合拒绝接受 null 元素！...
        }
    }
}
```


## 写一个“拒绝 Null”的自定义集合(T[])

要理解底层，我们要知道：**在内存世界里，数组（T[]）的长度一旦确定，是绝对无法改变的。**  
那么集合是如何做到“无限 Add”的呢？答案是：**狸猫换太子（动态扩容）**。

我们需要维护两个核心概念：

1. **容量（Capacity / 数组的 Length）**：当前租了多大的房子（内存）。
2. **计数（Count）**：当前房子里实际住了多少人（元素）。

当房子住满时（Count == Capacity），我们就**租一个大两倍的新房子，把老房子的人搬过去，然后退掉老房子**。
```cs
using System;
using System.Collections;
using System.Collections.Generic;

public class FastCollection<T> : ICollection<T>
{
    private T[] _items;    // 底层物理数组
    private int _count;    // 实际元素数量

    // 构造函数：初始化一个小数组（比如容量为 4）
    public FastCollection()
    {
        _items = new T[4]; 
        _count = 0;
    }

    public int Count => _count;
    public bool IsReadOnly => false;

    // ================= 1. 核心：Add 与 动态扩容 =================
    public void Add(T item)
    {
        // 如果房子住满了（实际数量 == 数组长度）
        if (_count == _items.Length)
        {
            // 1. 申请一个大两倍的新数组
            T[] newArray = new T[_items.Length * 2];
            // 2. 高效内存拷贝：把旧数组数据复制到新数组（底层是 C++ 的 memmove）
            Array.Copy(_items, newArray, _count);
            // 3. 狸猫换太子：将引用指向新数组（旧数组等待 GC 垃圾回收）
            _items = newArray; 
        }

        // 把新元素放到末尾，并且 Count 加 1
        _items[_count] = item;
        _count++;
    }

    // ================= 2. 核心：Remove 与 元素移位 =================
    public bool Remove(T item)
    {
        // 1. 找到元素所在的索引位置
        int index = Array.IndexOf(_items, item, 0, _count);
        if (index < 0) return false; // 没找到

        // 2. 将 index 后面的元素全部向左移动一位，覆盖掉要删除的元素
        // 比如：[A, B, C, D]，删 B (index 1)，就要把 [C, D] 拷贝到原来 B 的位置
        _count--; 
        if (index < _count)
        {
            // Array.Copy(源数组, 源起始位置, 目标数组, 目标起始位置, 拷贝长度)
            Array.Copy(_items, index + 1, _items, index, _count - index);
        }

        // 3. 【防内存泄漏神级操作】：将最后一位清空！
        // 因为移位后，最后一位仍保留着原来的引用，如果不清空，GC 无法回收那个对象
        _items[_count] = default(T); 

        return true;
    }

    // ================= 3. 其他常规方法 =================
    public void Clear()
    {
        // 不能只写 _count = 0，必须清除数组内的数据以释放引用类型的内存
        Array.Clear(_items, 0, _count);
        _count = 0;
    }

    public bool Contains(T item)
    {
        // 只需要在有效的 _count 范围内查找
        return Array.IndexOf(_items, item, 0, _count) >= 0;
    }

    public void CopyTo(T[] array, int arrayIndex)
    {
        Array.Copy(_items, 0, array, arrayIndex, _count);
    }

    // ================= 4. 遍历支持 =================
    public IEnumerator<T> GetEnumerator()
    {
        // 注意：不能直接遍历 _items，因为 _items.Length 可能大于 _count（有空房间）
        for (int i = 0; i < _count; i++)
        {
            yield return _items[i];
        }
    }

    IEnumerator IEnumerable.GetEnumerator() => GetEnumerator();
}
```
1. **倍增扩容法**：每次扩容 * 2 是一种经典的牺牲空间换取时间的策略。如果不采用这种策略（比如每次只扩容 +1），添加 1000 个元素就要开辟 1000 次新数组，会导致 CPU 和 GC 爆炸。
2. **Array.Copy 的魔力**：在做扩容和移除元素时，我们没有写 for 循环一个个赋值，而是使用了 Array.Copy。这是一个 CLR 级别的底层方法，执行速度极快。
3. **避免内存泄漏（Memory Leak）**：在 Remove 方法中，移位后将最后一位设为 default(T) 是重中之重。如果不这么做，被删除对象的引用就会一直残留在隐藏的物理数组末尾，导致内存永远无法被释放。

## 总结
1. **层次递进**：`IEnumerable<T>` 只负责“遍历”；`ICollection<T>` 在其基础上增加了“增、删、改、计数”的能力。
2. **实现技巧**：实现自定义 `ICollection<T>` 时，最常见且最稳妥的做法是**内部封装一个标准的集合（如 `List<T>` 或 `HashSet<T>`）**，对外实现接口并注入自己的业务逻辑。
3. **局限性提醒**：虽然 `ICollection<T>` 很强，但你会发现，我们**依然无法像数组那样，通过索引器（如 `myCollection[0]`）来访问里面的元素**！

为了获得通过索引（Index）精准访问和插入元素的能力，我们需要走向集合接口链条的最顶端：**`IList<T>`**。
