# 自定义集合与`IList<T>`

## 为什么还需要 `IList<T>`？
在上一篇中，我们用 `ICollection<T>` 让集合拥有了“增、删、改、查数量”的能力。但是它有一个明显的盲区：**它没有“位置（索引）”的概念**。

如果只有一个 `ICollection<T>`，你**无法**做到以下事情：
1. 获取第 3 个元素（不能写 `myCollection[2]`）。
2. 把新元素插队到第 1 个位置。
3. 替换掉第 5 个位置的元素。

为了对集合内部元素的**顺序和位置**进行精准打击，C# 提供了集合接口体系的最顶层（对于线性集合而言）：`System.Collections.Generic.IList<T>`。

## `IList<T>`的家族地位与核心成员
`IList<T>` 的继承链是这样的：
`IEnumerable<T>` (能遍历) 
    ↳ `ICollection<T>` (能增删、能计数) 
        ↳ **`IList<T>` (能通过索引精准操作)**

如果你要实现 `IList<T>`，除了要实现前面两篇提到过的{% post_link 161.自定义集合与ICollectionT#icollectiont的全家桶成员 所有方法%}外，还需要额外实现以下 4 个专属成员：

1. **`T this[int index] { get; set; }`**：**索引器**。让你能像数组一样使用 `[]` 来读取或修改指定位置的元素。
2. **`int IndexOf(T item)`**：找人。查出某个元素在集合中的索引（找不到返回 -1）。
3. **`void Insert(int index, T item)`**：插队。在指定的索引位置插入一个新元素，后面的元素自动后移。
4. **`void RemoveAt(int index)`**：精准打击。直接删除指定位置的元素。

## 写一个“带广播通知”的自定义集合
为什么要自己写 `IList<T>`？最常见的一个业务场景就是：**当集合发生变化（增、删、改）时，我们需要触发事件通知其他人（比如让 UI 界面刷新）**。WPF 中的 `ObservableCollection<T>` 就是这个原理。

今天我们自己手写一个轻量级的 `EventfulList<T>`（带事件的列表）。为了避免手写数组扩容的痛苦，我们依然采用“内部包一个 `List<T>`”的策略。

```csharp
using System;
using System.Collections;
using System.Collections.Generic;

public class EventfulList<T> : IList<T>
{
    private List<T> _innerList = new List<T>();

    // 定义一个事件：当集合内容改变时触发
    public event Action<string> OnCollectionChanged;

    // 辅助方法：触发事件
    private void Notify(string message)
    {
        OnCollectionChanged?.Invoke(message);
    }

    // ================= 1. IList<T> 专属成员 =================

    // 索引器
    public T this[int index]
    {
        get { return _innerList[index]; }
        set 
        { 
            T oldItem = _innerList[index];
            _innerList[index] = value; 
            Notify($"索引 {index} 的元素从 [{oldItem}] 被替换为 [{value}]");
        }
    }

    public int IndexOf(T item) => _innerList.IndexOf(item);

    public void Insert(int index, T item)
    {
        _innerList.Insert(index, item);
        Notify($"在索引 {index} 处插入了新元素 [{item}]");
    }

    public void RemoveAt(int index)
    {
        T removedItem = _innerList[index];
        _innerList.RemoveAt(index);
        Notify($"删除了索引 {index} 处的元素 [{removedItem}]");
    }

    // ================= 2. ICollection<T> 成员 =================
    
    public int Count => _innerList.Count;
    public bool IsReadOnly => false;

    public void Add(T item)
    {
        _innerList.Add(item);
        Notify($"在末尾添加了元素 [{item}]");
    }

    public bool Remove(T item)
    {
        bool success = _innerList.Remove(item);
        if (success) Notify($"移除了元素 [{item}]");
        return success;
    }

    public void Clear()
    {
        _innerList.Clear();
        Notify("集合被清空了！");
    }

    public bool Contains(T item) => _innerList.Contains(item);
    public void CopyTo(T[] array, int arrayIndex) => _innerList.CopyTo(array, arrayIndex);

    // ================= 3. IEnumerable<T> 成员 =================
    public IEnumerator<T> GetEnumerator() => _innerList.GetEnumerator();
    IEnumerator IEnumerable.GetEnumerator() => _innerList.GetEnumerator();
}
```

## 测试我们的EventfulList

现在，只要有人操作这个集合，我们就能收到“广播”！

```csharp
class Program
{
    static void Main()
    {
        var logs = new EventfulList<string>();

        // 订阅事件：一有风吹草动，就在控制台打印
        logs.OnCollectionChanged += message => Console.WriteLine($"[系统通知] {message}");

        Console.WriteLine("--- 开始操作集合 ---");
        
        logs.Add("张三");           // 触发 Add 通知
        logs.Add("李四");           // 触发 Add 通知
        
        logs.Insert(0, "王老板");    // 触发 Insert 通知
        
        logs[1] = "法外狂徒张三";    // 触发 索引器(Set) 通知
        
        logs.RemoveAt(2);          // 触发 RemoveAt 通知
        
        Console.WriteLine("\n--- 最终集合内容 ---");
        for (int i = 0; i < logs.Count; i++)
        {
            // 这里调用了 IList<T> 的索引器(Get)
            Console.WriteLine($"{i}: {logs[i]}"); 
        }
    }
}
```

**运行结果：**
```text
--- 开始操作集合 ---
[系统通知] 在末尾添加了元素 [张三]
[系统通知] 在末尾添加了元素 [李四]
[系统通知] 在索引 0 处插入了新元素 [王老板]
[系统通知] 索引 1 的元素从 [张三] 被替换为 [法外狂徒张三]
[系统通知] 删除了索引 2 处的元素 [李四]

--- 最终集合内容 ---
0: 王老板
1: 法外狂徒张三
```

## 总结
到目前为止，我们已经走完了 C# 线性集合的演进之路。请务必记住这张**接口全景图**：

*   **`IEnumerable<T>`**：最底层。只能用 `foreach` 从头到尾看一遍。
*   **`ICollection<T>`**：中层。能把元素 `Add` 进去，能 `Remove` 出来，还能知道 `Count`，但不知道元素在哪个位置。
*   **`IList<T>`**：顶层。增加了“游标卡尺”，能用 `[index]` 精确打击，能 `Insert` 到指定位置。

> **补充拓展**：如果是基于“键值对”的集合（比如字典），顶层接口就不是 `IList<T>` 了，而是 `IDictionary<TKey, TValue>`。但它的底层依然实现了 `ICollection<KeyValuePair<TKey, TValue>>`。
