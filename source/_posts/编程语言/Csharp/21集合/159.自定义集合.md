# 自定义集合

## 为什么需要自定义集合？
在C#中，我们经常使用 `List<T>`、`Dictionary<TKey, TValue>` 等现成的集合。但有时候，我们需要自己封装一个类（比如一个“播放列表”、“购物车”或者“公司员工列表”），并且希望能够像标准集合一样，使用 `foreach` 循环来遍历里面的数据。

要让一个自定义类支持 `foreach` 遍历，最基础的方法就是实现 `System.Collections.IEnumerable` 接口。

## IEnumerable 与 IEnumerator 的关系
这是初学者最容易混淆的两个概念：
*   **`IEnumerable`（可枚举的）**：代表**集合本身**。它只有一个方法 `GetEnumerator()`，用于“发一本名册”给调用者。
*   **`IEnumerator`（枚举器/迭代器）**：代表**遍历器**。它就像一个“书签”或“指针”，记录了当前遍历到了哪个位置。

`IEnumerator` 包含三个核心成员：
1.  `MoveNext()`：将游标移到下一个元素。如果还有元素，返回 true；到底了，返回 false。
2.  `Current`：获取当前游标指向的元素。
3.  `Reset()`：将游标重置到初始位置（通常是第一个元素的前面）。

## 写一个非泛型的自定义集合
下面我们完全**手动**实现这两个接口，来模拟一个“魔法书架”（`MagicBookshelf`）。

```csharp
using System;
using System.Collections;

// 1. 实现 IEnumerable 接口的集合类
public class MagicBookshelf : IEnumerable
{
    private string[] _books = { "C# 入门", "设计模式", "深入理解 CLR", "算法导论" };

    // 必须实现的方法：返回一个枚举器
    public IEnumerator GetEnumerator()
    {
        return new BookshelfEnumerator(_books);
    }
}

// 2. 实现 IEnumerator 接口的枚举器类（核心逻辑）
public class BookshelfEnumerator : IEnumerator
{
    private string[] _books;
    // 游标初始位置必须在第一个元素之前，所以设为 -1
    private int _position = -1;

    public BookshelfEnumerator(string[] books)
    {
        _books = books;
    }

    // 核心1：获取当前元素
    public object Current
    {
        get
        {
            if (_position < 0 || _position >= _books.Length)
                throw new InvalidOperationException();
            return _books[_position];
        }
    }

    // 核心2：移动游标
    public bool MoveNext()
    {
        _position++;
        return (_position < _books.Length);
    }

    // 核心3：重置游标
    public void Reset()
    {
        _position = -1;
    }
}
```

## 测试与原理解析
现在我们可以用 `foreach` 来遍历这个书架了：

```csharp
class Program
{
    static void Main()
    {
        MagicBookshelf shelf = new MagicBookshelf();

        // 为什么能用 foreach？因为实现了 IEnumerable
        foreach (var book in shelf)
        {
            Console.WriteLine(book);
        }
    }
}
```

**底层原理解析**：
当编译器看到 `foreach` 语句时，它实际上在底层把它转换成了类似下面的 `while` 循环代码：

```csharp
IEnumerator enumerator = shelf.GetEnumerator();
try
{
    while (enumerator.MoveNext())
    {
        object book = enumerator.Current;
        Console.WriteLine(book);
    }
}
finally
{
    // 清理工作
    IDisposable disposable = enumerator as IDisposable;
    disposable?.Dispose();
}
```

## 总结
通过实现非泛型的 `IEnumerable`，我们掌握了 `foreach` 的底层工作原理。但在现代 C# 开发中，非泛型的 `IEnumerable` 存在两个致命缺点：
1.  **类型不安全**：`Current` 返回的是 `object`，如果存放值类型，会导致性能损耗巨大的**装箱和拆箱**。
2.  **代码繁琐**：每次都要手写一个 Enumerator 类，太累了。



# 如何编写自定义集合

## 为什么要自定义集合？
在日常开发中，我们通常直接使用 `List<T>`、`Dictionary<TKey, TValue>` 等内置集合。但有时候我们需要自定义集合，主要原因包括：
1. **添加业务逻辑**：在添加、删除元素时进行数据校验（如：不能添加名字为空的用户）。
2. **触发事件**：当集合发生变化时（Add/Remove），通知其他组件（如 UI 刷新）。
3. **特定的数据结构**：实现框架没有提供的结构（如：环形缓冲区 Circular Buffer、优先队列等）。
4. **隐藏实现细节**：对外只暴露特定的操作，防止外部滥用（例如只读集合）。

---

## 集合的核心接口层次
了解 C# 集合体系，必须认识这三个核心接口（层层递进）：
*   `IEnumerable<T>`：**最低要求**。实现它就可以使用 `foreach` 遍历。只读，不能修改。
*   `ICollection<T>`：继承自 `IEnumerable<T>`。增加了 `Add`, `Remove`, `Clear`, `Contains`, `Count` 等功能。
*   `IList<T>`：继承自 `ICollection<T>`。增加了**索引器**访问（如 `list[0]`）和插入/移除特定索引位置的能力。

---

## 方式一：最基础的自定义（实现 `IEnumerable<T>`）

如果你的集合**不需要被外部修改**，只需要支持 `foreach` 遍历，实现 `IEnumerable<T>` 即可。

**核心语法糖：`yield return`**
在 C# 中，不需要手写复杂的 `IEnumerator` 状态机，直接使用 `yield return` 即可轻松实现。

```csharp
using System.Collections;
using System.Collections.Generic;

public class MyTeam : IEnumerable<string>
{
    private string[] _players = { "Alice", "Bob", "Charlie" };

    // 1. 实现泛型 GetEnumerator
    public IEnumerator<string> GetEnumerator()
    {
        for (int i = 0; i < _players.Length; i++)
        {
            // 使用 yield return 逐个返回元素
            yield return _players[i]; 
        }
    }

    // 2. 实现非泛型 GetEnumerator (历史遗留，必须实现)
    //    这里不是方法重载所有要写IEnumerable.
    IEnumerator IEnumerable.GetEnumerator()
    {
        return GetEnumerator();
    }
}

// 使用：
MyTeam team = new MyTeam();
foreach (var player in team)
{
    Console.WriteLine(player); // 输出: Alice, Bob, Charlie
}
```

---

## 方式二：使用组合模式（包装 `List<T>`）

如果你需要 `Add` 和 `Remove`，但不想从头实现 `ICollection<T>` 的所有方法（太繁琐），最好的办法是**在内部包装一个 `List<T>`**。

```csharp
public class ShoppingCart : IEnumerable<Item>
{
    // 内部使用 List<T> 存储
    private List<Item> _items = new List<Item>();

    // 暴露自定义的 Add 方法，可以加入业务逻辑
    public void Add(Item item)
    {
        if (item == null) throw new ArgumentNullException("商品不能为空");
        if (_items.Count >= 10) throw new Exception("购物车已满");
        
        _items.Add(item);
    }

    public bool Remove(Item item)
    {
        return _items.Remove(item);
    }
    
    public int Count => _items.Count;

    // 实现迭代器以便支持 foreach
    public IEnumerator<Item> GetEnumerator() => _items.GetEnumerator();
    IEnumerator IEnumerable.GetEnumerator() => _items.GetEnumerator();
}
```
*优点：简单灵活，只暴露你想暴露的方法，安全性高。*

---

## 方式三：微软推荐的最佳实践（继承 `Collection<T>`）

如果你想写一个**真正的、标准的集合**（支持 `IList<T>` 的一切操作），同时又想在 `Add/Remove` 时加入自己的逻辑，**千万不要去继承 `List<T>`**！

> **⚠️ 避坑指南**：`List<T>` 是高度优化的类，它的 `Add`、`Remove` 等方法**不是 virtual（虚方法）**，无法被重写(override)。

**✅ 正确做法：继承 `System.Collections.ObjectModel.Collection<T>`**

`Collection<T>` 专门为自定义集合设计，它提供了四个受保护的虚方法供你重写：
*   `InsertItem(int index, T item)`：添加元素时触发
*   `RemoveItem(int index)`：移除元素时触发
*   `SetItem(int index, T item)`：通过索引赋值时触发 (如 `list[0] = x`)
*   `ClearItems()`：清空集合时触发

**代码示例：一个不允许添加 Null 和重复元素的集合**

```csharp
using System.Collections.ObjectModel;

public class UniqueValidCollection<T> : Collection<T>
{
    // 拦截添加和插入操作
    protected override void InsertItem(int index, T item)
    {
        if (item == null)
            throw new ArgumentNullException(nameof(item), "不能添加空元素！");
            
        if (this.Contains(item))
            throw new ArgumentException("不能添加重复元素！");

        // 验证通过，调用基类方法真正插入数据
        base.InsertItem(index, item);
    }

    // 拦截索引赋值操作 (例如 list[0] = newItem)
    protected override void SetItem(int index, T item)
    {
        if (item == null)
            throw new ArgumentNullException(nameof(item));
            
        base.SetItem(index, item);
    }
    
    // 拦截删除操作 (可用于触发事件)
    protected override void RemoveItem(int index)
    {
        T removedItem = this[index];
        Console.WriteLine($"元素 {removedItem} 被移除了");
        base.RemoveItem(index);
    }
}
```

## 补充技能：自定义索引器

有时候我们希望集合能像字典一样通过特定的键来访问（例如 `myTeam["Alice"]`）。可以通过定义**索引器**来实现。

```csharp
public class Roster
{
    private Dictionary<string, string> _players = new Dictionary<string, string>();

    // 自定义索引器：this[参数类型 参数名]
    public string this[string name]
    {
        get 
        {
            return _players.ContainsKey(name) ? _players[name] : "未找到";
        }
        set 
        {
            _players[name] = value; // 赋值逻辑
        }
    }
}

// 使用：
Roster roster = new Roster();
roster["Alice"] = "Striker";    // 调用 set
Console.WriteLine(roster["Alice"]); // 调用 get
```

## 总结与选型决策树

在决定如何自定义集合时，请参考以下决策流：

1. **我只需要能 `foreach` 遍历，且不想对外暴露修改方法？**
   👉 实现 `IEnumerable<T>` 并使用 `yield return`。
2. **我需要实现特定的业务（如购物车），只提供有限的几个方法？**
   👉 使用**组合模式**，内部包含一个 `List<T>`，对外暴露特定的 `Add/Remove` 方法。
3. **我需要一个功能完整的集合（支持索引、List的所有功能），但要在增删改时加入数据校验或触发事件？**
   👉 继承 `System.Collections.ObjectModel.Collection<T>` 并重写 `InsertItem` 等虚方法。（这是框架级开发最常用的方式）。
4. **我需要实现一套全新的数据结构（如二叉树、红黑树）？**
   👉 从头实现 `ICollection<T>` 或 `IList<T>`。
