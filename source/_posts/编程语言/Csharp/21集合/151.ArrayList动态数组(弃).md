# ArrayList (动态数组)

## 一、核心概念与历史定位
`ArrayList` 位于非泛型命名空间 `System.Collections` 下，是 C# 1.0 时代引入的非泛型集合类。它是一个大小可按需动态增加的**无类型限制的动态数组**。

在内部，`ArrayList` 维护了一个 `System.Object` 类型的数组。由于 C# 中所有的类、结构体均直接或间接继承自 `Object`，因此 `ArrayList` 可以将任何类型的数据（如数字、字符串、日期甚至各种毫不相干的自定义对象）混合存储在同一个集合中。

**核心行为特征**
*   **按插入顺序存储**：与 `List<T>` 一样，元素追加在数组末尾，不会自动进行排序或哈希计算。
*   **动态扩容**：开发者无需在初始化时指定固定长度，集合会随着元素的增加自动申请更大的内存空间。
*   **API 高度相似**：由于 `List<T>` 在设计上是 `ArrayList` 的泛型替代品，两者在方法调用上（如 `Add()`, `Insert()`, `Remove()`, `AddRange()`）几乎完全一致。

## 二、代码实现与现代C#模式匹配

在处理包含多种数据类型的 `ArrayList` 时，遍历和类型转换是核心操作。由于提取出来的元素默认是 `object` 类型，如果直接调用 `ToString()`，对于自定义对象只会输出“命名空间.类名”（除非重写了 `ToString()` 方法）。

在现代 C#（C# 7.0 及更高版本）中，处理这种混合类型的集合应当使用**模式匹配 (Pattern Matching)** 语法，以确保类型转换的绝对安全。


**代码示例：
混合存储与安全解包**

```csharp
using System;
using System.Collections;

class Employee
{
    public string EmployeeName { get; set; }
}

class Program
{
    static void Main()
    {
        // 1. 初始化并混合存入不同类型的数据
        ArrayList mixedList = new ArrayList
        {
            10,                     // int
            'A',                    // char
            10.7,                   // double
            "Hello",                // string
            new Employee { EmployeeName = "John Doe" } // 自定义对象
        };

        // 2. 遍历集合
        // 注意：这里的 var 在编译时会被推断为 object 类型
        foreach (var item in mixedList)
        {
            // 3. 使用 is 关键字进行模式匹配与安全转换
            if (item is Employee emp)
            {
                // 如果 item 是 Employee 类型，则自动转换为 emp 变量
                Console.WriteLine($"[Employee Object] Name: {emp.EmployeeName}");
            }
            else if (item is int num)
            {
                Console.WriteLine($"[Integer] Value: {num}");
            }
            else
            {
                // 对于字符串、字符、浮点数等，调用默认的 ToString()
                Console.WriteLine($"[Other Type] Value: {item}");
            }
        }
    }
}
```

## 三、底层隐患(深度拓展)

虽然 `ArrayList` 看似灵活，可以容纳一切，但在现代 C# 开发中，**强烈不建议在任何新代码中使用 `ArrayList`**。结合经典技术书籍的观点，其原因集中在以下两点：

### 致命的性能惩罚：装箱与拆箱
《CLR via C#》中对非泛型集合的性能问题进行了深入剖析。由于 `ArrayList` 内部是一个 `object[]` 数组，当我们将值类型（如 `int`, `double`, `char`, `struct` 等）添加到集合中时，CLR 必须执行**装箱（Boxing）** 操作：
*   **装箱**：在托管堆（Heap）上分配一块新的内存，将栈（Stack）上的值类型数据复制过去，并返回一个对象的引用。
*   **拆箱**：从集合中取出数据使用时，又需要进行拆箱，将其强制转换回值类型。

频繁的装箱和拆箱不仅消耗大量的 CPU 时钟周期，还会产生大量短命的堆对象，给垃圾回收器（GC）带来巨大的压力，从而导致应用程序出现可感知的性能卡顿。

### 丧失编译期类型安全
《Effective C#》的黄金法则之一是 **“决不使用非泛型集合”**。
`ArrayList` 放弃了编译器的类型检查机制。在大型项目中，如果一个方法返回 `ArrayList`，调用者根本不知道里面装的是什么。这极易导致在运行时执行错误的强制类型转换，从而抛出 `InvalidCastException` 导致程序崩溃。

## 四、现代 C# 的替代方案

如果业务场景确实要求在一个集合中存储“不同类型”的数据，现代架构设计应当采用以下替代方案：

1.  **首选方案：面向接口编程**
    如果这些不同的类有某种共性，应该提取一个公共接口（如 `IPrintable` 或 `IEntity`），然后使用 `List<IPrintable>`。这既保证了类型安全，又实现了多态。
2.  **次选方案：使用 `List<object>`**
    如果真的需要存储完全无关的数据，请显式使用泛型的 `List<object>` 而不是 `ArrayList`。虽然两者在底层行为上依然会发生装箱，但 `List<object>` 在语义上向代码阅读者明确传达了“这是一个混合类型集合”的意图，并且 API 更加现代化（支持 LINQ 等扩展方法）。




## 五、核心属性

### `Count` 
*   **说明**：获取实际元素的数量。时间复杂度 O(1)。

### `Capacity` 
*   **说明**：与 `List<T>` 的扩容机制完全相同。默认初始为 0，添加第一个元素扩容为 4，之后**每次翻倍**（4 -> 8 -> 16...）。扩容需要开辟新数组并复制旧数据。

### `IsFixedSize` 与 `IsReadOnly`
*   **说明**：指示 `ArrayList` 是否具有固定大小 / 是否只读。默认都是 `false`。这是老一代集合接口 `IList` 的历史遗留产物。

### `IsSynchronized` 与 `SyncRoot` (多线程遗物)
*   **说明**：用于判断是否线程安全以及获取同步锁对象。（与 `Hashtable` 一样，现代开发已废弃，改用并发集合或自行加锁）。

## 六、索引器 - 强转的噩梦

### `this[int index]` (通过索引访问)
*   **读数据（Get）**：**取出来的永远是 `object`，必须强转！**
*   **写数据（Set）**：可以赋任何类型的值，极其自由，也极其危险。
*   **示例**：
```csharp
ArrayList list = new ArrayList();
list.Add("Hello"); // 存入 string
list.Add(100);     // 存入 int (发生装箱！)

// 危险读取操作：
string str = (string)list[0]; // 必须强转
int num = (int)list[1];       // 必须强转 (发生拆箱！)

// 运行期爆炸示范：
// string badStr = (string)list[1]; 
// 编译能通过，但运行直接崩溃：InvalidCastException (无法将 int 转为 string)
```

## 七、添加元素

### `Add(object value)`
*   **说明**：将对象添加到结尾。时间复杂度 O(1)。
```csharp
ArrayList mixedList = new ArrayList();
mixedList.Add(DateTime.Now); // 存入时间对象
mixedList.Add(3.14);         // 存入浮点数 (装箱)
```

### `AddRange(ICollection c)`
*   **说明**：将集合元素批量添加到末尾。底层一次性扩容，效率比循环 Add 高。
```csharp
ArrayList list = new ArrayList();
int[] numbers = { 1, 2, 3 };
list.AddRange(numbers); // 将数组里的所有数字塞进去 (批量装箱)
```

### `Insert(int index, object value)`
*   **说明**：在指定索引处插入元素。
*   **时间复杂度**：O(n)（该索引后面的所有元素都要向后移动一位，很慢）。

### `InsertRange(int index, ICollection c)`
*   **说明**：在指定索引处批量插入集合。时间复杂度 O(n)。

---

## 八、移除元素

###  `Remove(object obj)`
*   **说明**：移除**第一个**匹配的具体对象。
*   **时间复杂度**：O(n)（先线性查找，再移动数组元素）。
*   **底层**：使用 `object.Equals` 比较。

### `RemoveAt(int index)`
*   **说明**：移除指定索引处的元素。O(n)。

### `RemoveRange(int index, int count)`
*   **说明**：从指定索引开始，移除指定数量的元素。O(n)。
*   **优势**：连续删除时，比循环调 `RemoveAt` 性能高得多（底层只移动一次数据）。

### `Clear()`
*   **说明**：清空所有元素。将内部数组所有引用置为 `null`，以便 GC 回收。`Capacity` 保持不变。

---

## 九、查找与排序

### `Contains(object item)`
*   **说明**：判断是否包含特定对象。时间复杂度 O(n)。

### `IndexOf(object value)` / `LastIndexOf(object value)`
*   **说明**：返回从前往后（或从后往前）找，第一个匹配项的索引。找不到返回 `-1`。

### `BinarySearch(object value)`
*   **说明**：二分查找。时间复杂度 O(log n)。
*   **前提条件**：列表必须是**已排序**的。由于 ArrayList 里面类型大杂烩，如果你存了字符串又存了数字，调用此方法极易引发异常。

### `Sort()`
*   **说明**：对整个 ArrayList 进行原地排序。
*   **巨坑警告**：`Sort` 内部会调用元素的 `IComparable` 接口。如果你的 ArrayList 里既有 `int` 又有 `string`，调用 `Sort()` 会直接**程序崩溃**（抛出 `InvalidOperationException`：比较这两个元素失败）。
*   **示例**：
```csharp
ArrayList nums = new ArrayList { 5, 1, 9, 3 };
nums.Sort(); // 成功：排成 1, 3, 5, 9

ArrayList chaos = new ArrayList { 1, "Apple", 2 };
// chaos.Sort(); // 崩溃！苹果和数字无法比大小。
```

### `Reverse()`
*   **说明**：反转元素顺序。O(n)。

---

## 十、转换与辅助方法

### `ToArray()`
*   **说明**：将 ArrayList 转换为 `object[]` 数组。
```csharp
ArrayList list = new ArrayList { "A", "B" };
object[] arr = list.ToArray();
```

### `ToArray(Type type)` (稍微高级一点)
*   **说明**：将其转换为指定类型的强类型数组。
*   **前提**：ArrayList 里面的所有元素都必须能被安全转换为该类型，否则报错。
```csharp
ArrayList nums = new ArrayList { 1, 2, 3 };
// 将其转换为真正的 int[] 数组
int[] intArr = (int[])nums.ToArray(typeof(int)); 
```

### `GetRange(int index, int count)`
*   **说明**：返回表示原 ArrayList 某个范围的**浅表副本**（还是一个 ArrayList）。

## 补充高级

这部分是本文的精华，是老司机和菜鸟的分水岭。

### 终极对比：`ArrayList` vs `List<T>` vs `object[]`

| 特性 | `ArrayList` (被淘汰) | `List<T>` (现代标准) | `object[]` (基础数组) |
| :--- | :--- | :--- | :--- |
| **底层实现** | `object[]` (动态扩容) | `T[]` (动态扩容) | `object[]` (固定长度) |
| **类型安全** | ❌ 否 (全都是 object) | ✅ 是 (编译期检查) | ❌ 否 |
| **值类型性能**| ❌ 极差 (严重装箱拆箱) | ✅ 极佳 (直接存内存值) | ❌ 极差 (装箱) |
| **长度可变** | ✅ 是 | ✅ 是 | ❌ 否 (定长) |
| **读取是否需强转**| ✅ 是 (极易运行时崩溃) | ❌ 否 (安全直接拿) | ✅ 是 |

### 如何证明“装箱/拆箱”的性能损耗？
如果面试官让你手写代码证明，你可以提这个思路：
```csharp
int count = 10000000; // 一千万次

// --- List<int> 测试 (耗时约几毫秒) ---
List<int> genericList = new List<int>();
for (int i = 0; i < count; i++) {
    genericList.Add(i); // 零内存分配，直接写入连续内存
}

// --- ArrayList 测试 (耗时可能几百毫秒，且触发垃圾回收) ---
ArrayList legacyList = new ArrayList();
for (int i = 0; i < count; i++) {
    legacyList.Add(i); // 灾难！new 出了一千万个 object 堆内存对象！
}
```

### 线程安全包装：`ArrayList.Synchronized`
与 `Hashtable` 一样，它提供了一个线程安全的包装器。
```csharp
ArrayList list = new ArrayList();
// 返回一个自带加锁机制的 ArrayList
ArrayList safeList = ArrayList.Synchronized(list); 
// 现代替代方案：System.Collections.Concurrent.ConcurrentBag<T>
```

### 旧项目重构：如何把 `ArrayList` 优雅地转换为 `List<T>`？
当你接手一个祖传项目，看到满屏幕的 `ArrayList` 时，不要一个个去手动强转。利用 LINQ 扩展方法：
*   **`Cast<T>()`**：如果确定里面全是某类型，直接转。
*   **`OfType<T>()`**：如果里面是大杂烩，只过滤出特定的类型。

```csharp
using System.Linq;

ArrayList oldData = new ArrayList { 1, "Apple", 2, "Banana", 3 };

// 需求1：我只要里面的字符串，转成现代 List
List<string> strList = oldData.OfType<string>().ToList(); 
// strList: ["Apple", "Banana"]

// 需求2：(假设确定全是数字) 批量转换为泛型 List
ArrayList pureNums = new ArrayList { 10, 20, 30 };
List<int> intList = pureNums.Cast<int>().ToList();
// intList: [10, 20, 30]
```

## 总结

1.  **历史定位**：它是 C# 1.0 的时代英雄，但在 C# 2.0 推出泛型 `List<T>` 后彻底沦为垃圾。
2.  **原罪：Object**：因为它底层是 `object[]`，所以存放值类型会产生**装箱/拆箱**导致 GC 爆炸，读取必须**强制转换**导致类型极不安全。
3.  **核心差异**：`List<int>` 底层存的是真正的整型，内存紧凑；`ArrayList` 存了 100 个整数，相当于在堆上 `new` 了 100 个对象引用。
4.  **现代平替**：一切需要使用 `ArrayList` 的场景，请 100% 替换为 `List<object>` 或具体的 `List<T>`。遇到老代码返回 `ArrayList`，立刻用 LINQ 的 `.OfType<T>().ToList()` 洗成泛型集合。
