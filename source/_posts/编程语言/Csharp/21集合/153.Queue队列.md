# `Queue<T>`队列
在实际开发中，凡是涉及到 **“排队执行任务”、“广度优先搜索(BFS)”、“消息投递”、“异步缓冲”** 的场景，队列永远是唯一真神。
## 一、核心概念与底层逻辑

`Queue<T>` 位于 `System.Collections.Generic` 命名空间下。

*   **绝对核心原则：FIFO (First-In, First-Out，先进先出)**。
    想象你在超市收银台排队，第一个去排队的人，一定是第一个结账走人的人。后来的人只能排在队伍最后面。
*   **底层数据结构（极其重要！面试必考神级魔法！）：**
    `Queue<T>` 的底层是一个**环形数组**！
    *   **为什么不用普通数组？** 如果用普通数组，当你从头部拿走一个元素（出队）时，后面所有的元素都需要往前移动一位，时间复杂度是 O(n)，极其缓慢！
    *   **环形数组怎么解决的？** 它内部维护了两个指针：`_head`（头指针，指向将要出队的元素）和 `_tail`（尾指针，指向下一个要入队的位置）。
    *   当入队到数组末尾时，如果数组前端有空位（因为已经有人出队了），`_tail` 指针会**神奇地绕回到数组的索引 0 处**继续存数据！这就形成了一个完美的闭环，**无需移动任何数据**！
*   **时间复杂度**：正是因为环形数组的魔法，队列的入队（Enqueue）和出队（Dequeue）的**时间复杂度永远是完美的 O(1)**！

---

## 二、核心属性 与 初始化

### `Count`
*   **说明**：获取队列中当前**排队**的元素数量。
*   **时间复杂度**：O(1) （内部有一个专门的 `_size` 变量记录，不需要去算头尾指针的差值）。
*   **示例**：
```csharp
Queue<string> checkoutLine = new Queue<string>();
checkoutLine.Enqueue("顾客A");
checkoutLine.Enqueue("顾客B");
Console.WriteLine($"当前排队人数: {checkoutLine.Count}"); // 输出: 2
```

### 隐藏的性能优化：构造函数预分配容量
和 `Stack<T>` 一样，`Queue<T>` **没有公开的 `Capacity` 属性**，但你可以（且应该）在 `new` 的时候告诉它初始容量。
*   **扩容机制**：当环形数组真满了（首尾相接没有空隙了），它会开辟一个**两倍大**的新数组，并把老数据“按顺序”捋直了抄过去。扩容是 O(n) 的耗时操作。
```csharp
// 预知今天有 5000 个任务要处理，直接分配内存，拒绝扩容卡顿
Queue<int> taskQueue = new Queue<int>(5000); 
```

## 三、核心操作：进与出

队列的核心动作只有三个：入队（进队尾）、出队（出队头）、偷看（看队头）。

### `Enqueue(T item)`
*   **说明**：将对象添加到 `Queue<T>` 的**结尾（队尾）** 处。
*   **时间复杂度**：平摊 O(1)。（只有触发底层数组翻倍扩容时才是 O(n)）。
*   **示例**：
```csharp
Queue<string> printJobs = new Queue<string>();
printJobs.Enqueue("文档1.pdf"); // 第一个排队
printJobs.Enqueue("照片2.png"); // 第二个排队
printJobs.Enqueue("报表3.xlsx"); // 第三个排队
// 此时队伍: [头] 文档1 -> 照片2 -> 报表3 [尾]
```

### `Dequeue()`
*   **说明**：移除并返回位于 `Queue<T>` **开始（队头）** 处的对象。
*   **时间复杂度**：O(1) （极快，只是把 `_head` 指针往后挪一格）。
*   **致命异常**：如果队列是空的（Count == 0），调用此方法会**直接抛出 `InvalidOperationException` (队列为空)** 异常！
*   **示例**：
```csharp
// 继续使用上面的 printJobs
string currentJob = printJobs.Dequeue(); 
Console.WriteLine($"正在打印: {currentJob}"); // 输出: 文档1.pdf

Console.WriteLine($"剩下几个任务: {printJobs.Count}"); // 输出: 2
// 此时队伍: [头] 照片2 -> 报表3 [尾]
```

### `Peek()`
*   **说明**：返回位于 `Queue<T>` **开始处**的对象，但**不将其移除**。
*   **时间复杂度**：O(1)。
*   **异常**：如果队列为空，抛出 `InvalidOperationException`。
*   **应用场景**：你想看看下一个顾客是谁，但收银员还没准备好为他结账。
*   **示例**：
```csharp
Queue<int> vipLine = new Queue<int>();
vipLine.Enqueue(888); // VIP客户 888

int nextVip = vipLine.Peek(); 
Console.WriteLine($"下一位尊贵的VIP是: {nextVip}"); // 输出: 888
Console.WriteLine($"他还在队伍里吗？ Count: {vipLine.Count}"); // 输出: 1 (没被踢出队列)
```

## 四、安全操作

和栈一样，.NET Core 引入了 `Try` 系列方法。**强烈建议在所有现代 C# 异步任务、多线程、循环处理代码中，全面采用 `TryDequeue/TryPeek` 代替老方法！**

### `TryDequeue(out T result)`
*   **说明**：尝试移除并返回队头元素。
*   **返回值**：如果队列不为空，移除队头元素，赋值给 `result`，返回 `true`。如果队列为空，`result` 为默认值，返回 `false`（**完全不报错，不打断程序执行！**）。
*   **经典使用姿势（无限消费循环）**：
```csharp
Queue<string> messages = new Queue<string>();
messages.Enqueue("Msg_1");
messages.Enqueue("Msg_2");

// 优雅的消费者模式：只要队列里有东西，就一直拿
while (messages.TryDequeue(out string msg)) {
    Console.WriteLine($"处理消息: {msg}");
}
// 输出: 处理消息: Msg_1 \n 处理消息: Msg_2
// 循环安全退出，无需写 if(messages.Count > 0)
```

### `TryPeek(out T result)`
*   **说明**：尝试获取队头元素（不移除）。队列为空时返回 `false`，不抛异常。
*   **示例**：
```csharp
Queue<int> emptyQueue = new Queue<int>();
if (emptyQueue.TryPeek(out int frontItem)) {
    Console.WriteLine($"队头是 {frontItem}");
} else {
    Console.WriteLine("前面没人排队了！你可以直接过去。"); // 执行这句
}
```

## 五、实用工具方法

### `Contains(T item)`
*   **说明**：确定某元素是否在 `Queue<T>` 中。
*   **时间复杂度**：O(n) （线性查找）。
*   **避坑指南**：虽然有这个方法，但队列的设计初衷是不允许插队、不允许半路找人的。如果你频繁使用 `Contains`，说明你的业务逻辑可能需要 `HashSet<T>` 或 `List<T>`，而不是队列。
*   **示例**：
```csharp
Queue<string> players = new Queue<string>();
players.Enqueue("Faker");
players.Enqueue("ShowMaker");
bool isFakerWaiting = players.Contains("Faker"); // 返回 true
```

### `Clear()`
*   **说明**：从队列中移除所有对象。
*   **底层细节**：时间复杂度 O(n)（需清理引用以防内存泄漏）。把 `_head` 和 `_tail` 指针归零，Count 归零。**内部容量 (Capacity) 不变**。
*   **示例**：
```csharp
players.Clear();
// 队伍解散，Count 变为 0
```

### `ToArray()`
*   **说明**：将队列复制到一个新的固定大小的数组中。
*   **时间复杂度**：O(n)。
*   **极其重要的细节（与 Stack 的对比必考！）**：
    *   `Stack.ToArray()`：最新的元素（最后进的）在数组的索引 `0`。
    *   `Queue.ToArray()`：**最老的元素（最先进的，即排在队头的）在数组的索引 `0`！** 这非常符合人类直觉。
*   **示例**：
```csharp
Queue<int> q = new Queue<int>();
q.Enqueue(1); // 先进
q.Enqueue(2);
q.Enqueue(3); // 后进

int[] arr = q.ToArray();
// arr 的内容是: [1, 2, 3] ！完全保持了他们进入的原始顺序！
```

### `TrimExcess()`
*   **说明**：如果队列实际排队人数远小于环形数组的容量，调用此方法可以缩减底层容量以匹配 Count，**释放多余的空闲内存**。
*   **示例**：
```csharp
Queue<int> bigQueue = new Queue<int>(10000); 
bigQueue.Enqueue(99);
bigQueue.TrimExcess(); // 把多余的 9999 个空位内存还给操作系统
```

## 六、遍历队列的正确认知

队列实现了 `IEnumerable<T>`。
*   **遍历顺序**：**严格从队头（最老的数据）到队尾（最新的数据）**。
*   **核心特性**：`foreach` 遍历**只是读取，绝对不会出队（移除）元素**！
*   **示例**：
```csharp
Queue<string> toDos = new Queue<string>();
toDos.Enqueue("起床");
toDos.Enqueue("刷牙");
toDos.Enqueue("写代码");

Console.WriteLine("今天的待办事项清单:");
foreach (string task in toDos) {
    Console.WriteLine(task);
}
// 输出顺序: 起床 -> 刷牙 -> 写代码

Console.WriteLine($"清单看完了，事情做了吗？没做！队列长度: {toDos.Count}"); // 长度还是 3
```

## 七、补充高级特性

只会用 `Enqueue` 和 `Dequeue` 只能算入门，以下内容将带你掌握 C# 队列在现代架构中的真实玩法：

### 经典算法实战：广度优先搜索 (BFS)
在图论算法、迷宫寻路、树的层序遍历中，`Queue<T>` 是唯一指定工具！
它保证了“先发现的节点先被处理”，从而实现像水波纹一样向外扩散的搜索。
```csharp
// 伪代码演示 BFS 的核心框架
Queue<TreeNode> queue = new Queue<TreeNode>();
queue.Enqueue(rootNode);

while (queue.TryDequeue(out TreeNode currentNode)) {
    Console.WriteLine($"访问节点: {currentNode.Value}");
    
    // 把它的下一代全部排入队伍末尾
    if (currentNode.Left != null) queue.Enqueue(currentNode.Left);
    if (currentNode.Right != null) queue.Enqueue(currentNode.Right);
}
```

### `PriorityQueue<TElement, TPriority>` (优先级队列)
.Net 6+

*   **痛点**：普通队列不能插队。但如果医院排队，突然来个急救病人怎么办？
*   **解法**：以前需要自己写二叉堆，现在 C# 10 原生提供了 `PriorityQueue`！
*   **底层**：它是**最小堆 (Min-Heap)**，完全不是环形数组！每次 `Dequeue` 出来的，**永远是 TPriority 值最小（优先级最高）的元素**，无视进入的先后顺序。
```csharp
// 元素是 string(名字)，优先级是 int(数字越小越先出队)
PriorityQueue<string, int> erLine = new PriorityQueue<string, int>();

erLine.Enqueue("普通发烧患者", 3);
erLine.Enqueue("擦伤患者", 4);
erLine.Enqueue("心脏骤停急救！", 1); // 后来者，但优先级极高(1)

// 出队永远先出优先级最高(数字最小)的
string nextPatient = erLine.Dequeue(); 
Console.WriteLine(nextPatient); // 绝对输出: "心脏骤停急救！"
```

### 多线程杀手锏：`ConcurrentQueue<T>` (并发队列)
*   **警告**：`Queue<T>` **绝对不防多线程**！如果在高并发下多个线程同时 `Enqueue`，底层的环形数组指针会立刻崩溃，数据互相覆盖。
*   **多线程必选项**：请使用 `System.Collections.Concurrent.ConcurrentQueue<T>`。
*   **底层黑科技**：它内部没有使用传统的 `lock` 锁，而是采用了**无锁算法 (Lock-free) 的分段链表结构**，在极高并发的“生产者-消费者”模型中，性能强得离谱。
*   **专有方法**：它没有 `Dequeue`，只能强制你使用安全的 `TryDequeue`。

### `Queue<T>` vs `List<T>` 
**面试官问：** 既然 `List<T>` 有 `Add`（加到尾部），也可以用 `RemoveAt(0)`（移除头部），那到底为什么还需要 `Queue<T>`？
**满分回答：**
1.  **性能天壤之别**：`List.RemoveAt(0)` 的时间复杂度是 **O(n)**，因为移除头部后，后面的所有元素在内存中都要向前挪动一位！如果有 10 万个元素，挪动代价极其恐怖。而 `Queue<T>` 采用**环形数组指针**，出队时间复杂度是永远的 **O(1)**。
2.  **代码语义学**：队列在代码层面上强制规范了“只能头出尾进”，防止了团队中其他开发者随意从中间 `Insert` 或 `Remove`，保证了业务逻辑的绝对安全。

## 八、总结提炼

1.  **底层**：**环形数组，头尾双指针。** 这是它凭什么出队能达到 O(1) 。
2.  **安全**：坚决抛弃老式的 `Dequeue/Peek`，拥抱 .NET 时代的 `TryDequeue/TryPeek`，彻底告别异常满天飞。
3.  **选型**：
    *   单线程排队执行：用 `Queue<T>`。
    *   多线程高并发消息处理：用 `ConcurrentQueue<T>`。
    *   带有 VIP 插队属性的任务池：用 .NET 6 的 `PriorityQueue`。
4.  **应用场景**：消息队列（MQ）本地化模拟、BFS 广度优先搜索、异步任务缓冲池。
