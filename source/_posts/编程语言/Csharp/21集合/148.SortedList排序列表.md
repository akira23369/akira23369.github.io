# `SortedList<TKey, TValue>` 排序列表

## 一、 核心概念与底层逻辑

`SortedList<TKey, TValue>` 位于 `System.Collections.Generic` 命名空间下。

*   **最大特征**：它是一个**永远按 Key 排序**的键值对集合。
*   **底层数据结构（极其重要！）**：
    不要被它的名字欺骗！它的底层**绝对不是链表，也不是红黑树**，而是维护了**两个普通的数组（Twin Arrays）**：
    1.  `TKey[] keys`：专门存 Key。
    2.  `TValue[] values`：专门存 Value。
*   **排序与操作原理**：
    当你存入一个键值对时，它底层会使用**二分查找法（Binary Search）** 在 `keys` 数组中找到合适的位置，然后将该位置及之后的所有元素**向后平移**，最后把新的 Key 和 Value 塞进两个数组的对应缝隙里。
*   **时间复杂度（大O表示法）**：
    *   **查找 (按 Key)**：O(log n) （因为是二分查找，很快）。
    *   **查找 (按索引)**：O(1) （因为它底层就是数组，直接通过下标访问，极快！）。
    *   **插入与删除**：O(n) **（注意：非常慢！）** 因为需要移动底层数组的元素。
    *   *细节*：如果你插入的数据恰好比当前所有 Key 都大（即追加到末尾），此时插入的时间复杂度退化为 O(1)。

---

## 二、 核心属性

### `Count` (实际包含的元素数)
*   **说明**：获取集合中当前的键值对数量。时间复杂度 O(1)。

### `Capacity` (内部容量)
*   **说明**：与 `List<T>` 极为相似，因为它底层也是数组。初始为 0，添加元素后扩容为 4，之后不够用时**容量翻倍**。
*   **最佳实践**：如果知道要存多少数据，`new` 的时候直接传入初始容量，避免频繁扩容导致两个数组都要重新分配内存。
```csharp
// 直接预分配 1000 的容量，拒绝扩容性能损耗
SortedList<int, string> list = new SortedList<int, string>(1000);
```

### `Keys` (键集合) 与 `Values` (值集合)
*   **说明**：获取包含所有键/值的集合。
*   **独家优势（对比字典）**：`SortedList` 的 `Keys` 和 `Values` 属性返回的是 `IList<T>` 类型！这意味着**你可以直接用索引器访问它们**！
*   **示例**：
```csharp
SortedList<int, string> ranks = new SortedList<int, string> {
    { 3, "Bronze" },
    { 1, "Gold" },
    { 2, "Silver" }
};
// 此时内部已自动按 Key 排序：1(Gold), 2(Silver), 3(Bronze)

// 高级操作：直接通过索引拿第一名和最后一名
int firstKey = ranks.Keys[0];        // 返回 1 (最小的键)
string firstValue = ranks.Values[0]; // 返回 "Gold"

int lastKey = ranks.Keys[ranks.Count - 1]; // 返回 3 (最大的键)
```

## 三、 索引器

### `this[TKey key]` (通过键访问)
*   **说明**：与 `Dictionary` 用法完全一致。
*   **读数据**：Key 必须存在，否则抛出 `KeyNotFoundException`。
*   **写数据**：Key 存在则覆盖 Value；不存在则**按顺序插入**新的键值对。
*   **示例**：
```csharp
SortedList<string, int> ages = new SortedList<string, int>();
ages["Charlie"] = 30; // 插入
ages["Alice"] = 25;   // 插入，此时底层数组重排：Alice 在前，Charlie 在后
ages["Alice"] = 26;   // 更新，Alice 的值变为 26
```

## 四、 添加元素

### `Add(TKey key, TValue value)`
*   **说明**：将带有所提供键和值的元素添加到集合中。
*   **时间复杂度**：O(n) （需要二分查找位置，并移动数组元素）。
*   **异常**：如果 Key 已存在，抛出 `ArgumentException`。
*   **示例**：
```csharp
SortedList<string, string> dict = new SortedList<string, string>();
dict.Add("B", "Banana");
dict.Add("A", "Apple");
// 此时顺序: [A, Apple], [B, Banana]
```

### `TryAdd(TKey key, TValue value)` 
*(.NET Core+ / C# 7+)*
*   **说明**：尝试添加。如果 Key 已存在，不报错，返回 `false`。
*   **示例**：
```csharp
bool added1 = dict.TryAdd("C", "Cherry"); // 返回 true
bool added2 = dict.TryAdd("A", "Avocado"); // 返回 false，不抛异常
```

## 五、 移除元素

### `Remove(TKey key)`
*   **说明**：移除带有指定键的元素。
*   **时间复杂度**：O(n) （移除后，后面的元素要整体向前平移）。
*   **返回值**：找到并移除返回 `true`，没找到返回 `false`。
*   **示例**：
```csharp
SortedList<int, string> tasks = new SortedList<int, string> { {2, "Eat"}, {1, "Code"} };
bool isRemoved = tasks.Remove(2); // true
```

### `RemoveAt(int index)`
*   **说明**：移除**指定索引**处的元素。
*   **这是字典做不到的**：因为字典是哈希表，没有顺序索引。而 `SortedList` 可以像操作 `List<T>` 一样，直接删掉“排在第3位”的元素。
*   **示例**：
```csharp
SortedList<string, double> scores = new SortedList<string, double> {
    {"Tom", 80.5}, {"Jerry", 99.0}, {"Spike", 60.0}
};
// 排序后: Jerry(99), Spike(60), Tom(80.5)  <-- 按字母 J, S, T 排序

// 移除排在第0位的元素 (Jerry)
scores.RemoveAt(0); 
```

### `Clear()`
*   **说明**：清空集合。时间复杂度 O(n)。Capacity 保持不变。

## 六、 查找与定位

### `ContainsKey(TKey key)`
*   **说明**：是否包含指定的键。
*   **时间复杂度**：O(log n) （二分查找，比字典的 O(1) 慢一点，但比 List 的 O(n) 快得多）。

### `ContainsValue(TValue value)`
*   **说明**：是否包含指定的值。
*   **时间复杂度**：O(n) （线性遍历 `values` 数组）。

### `TryGetValue(TKey key, out TValue value)`
*   **说明**：安全获取值。也是黄金法则：能用 TryGetValue 就绝不用 ContainsKey + 索引器。
*   **示例**：
```csharp
if (scores.TryGetValue("Tom", out double tomScore)) {
    Console.WriteLine($"Tom的成绩是 {tomScore}");
}
```

### `IndexOfKey(TKey key)`
*   **说明**：返回指定键的**从零开始的索引**。
*   **时间复杂度**：O(log n) （底层调用 Array.BinarySearch）。
*   **返回值**：找不到则返回 -1。
*   **应用场景**：你想知道某个 Key 在当前排好序的列表里“排第几名”。
*   **示例**：
```csharp
SortedList<int, string> leaderboard = new SortedList<int, string> {
    { 100, "PlayerA" }, { 300, "PlayerB" }, { 200, "PlayerC" }
};
// 内部排序: 100(A), 200(C), 300(B)
int rankIndex = leaderboard.IndexOfKey(200); // 返回 1 (排在第二位)
```

### `IndexOfValue(TValue value)`
*   **说明**：返回指定值的第一个匹配项的索引。
*   **时间复杂度**：O(n) （线性查找）。

## 七、高级特性


### 终极对决：`SortedList` vs `SortedDictionary` vs `Dictionary`

不要再瞎用集合了！请把下面这个表格刻在脑子里：

| 特性                   | `Dictionary<K,V>` (字典) | `SortedList<K,V>` (排序列表) | `SortedDictionary<K,V>` (排序字典) |
| :------------------- | :--------------------- | :----------------------- | :----------------------------- |
| **底层数据结构**           | 哈希表 (Hash Table)       | **双数组 (Twin Arrays)**    | **红黑树 (Red-Black Tree)**       |
| **是否排序**             | ❌ 无序                   | ✅ 按 Key 排序               | ✅ 按 Key 排序                     |
| **内存占用**             | 中等                     | **最少 (内存极度连续、紧凑)**       | **最大 (每个节点都需要额外指针)**           |
| **插入/删除 速度**         | O(1) (极快)              | **O(n) (最慢，要移动数组)**      | O(log n) (较快，调整树节点)            |
| **按 Key 查找速度**       | O(1) (极快)              | O(log n) (二分查找)          | O(log n) (树查找)                 |
| **索引访问 (`Keys[i]`)** | ❌ 不支持                  | **✅ 支持 O(1)**            | ❌ 不支持                          |

**架构师选型指南**：
*   **无脑选**：只要不需要排序，永远用 `Dictionary`。
*   **选 `SortedList` 的场景**：数据**一次性加载完毕后很少修改（读多写少）**，且内存吃紧，或者你频繁需要知道“某个 Key 排在第几位（需要按索引访问）”。
*   **选 `SortedDictionary` 的场景**：数据**频繁插入和删除（写多读多）**，且必须保持实时排序。

### 高级操作：自定义排序规则 (`IComparer<TKey>`)
默认情况下，`SortedList` 是按 Key 升序排列的（小的在前，大的在后）。如果你想降序排列怎么办？
**在构造函数中传入自定义的比较器！**

```csharp
// 默认是按 int 升序 (1, 2, 3...)
// 我们传入 Comparer<int>.Create 来反转排序规则，实现降序 (3, 2, 1...)
SortedList<int, string> descendingList = new SortedList<int, string>(
    Comparer<int>.Create((x, y) => y.CompareTo(x)) // 注意 y 和 x 互换了位置
);

descendingList.Add(1, "Level 1");
descendingList.Add(5, "Level 5");
descendingList.Add(3, "Level 3");

// 遍历输出，你会发现结果是: 5, 3, 1
foreach (var kvp in descendingList) {
    Console.WriteLine(kvp.Key);
}
```

### 容量修剪：`TrimExcess()`
因为 `SortedList` 底层是数组，如果你曾经存了 10000 个元素，后来删除了 9000 个，底层的 Capacity 依然是 10000，白白占用内存。
调用 `TrimExcess()` 可以让它的容量缩小到与当前 `Count` 匹配的大小，释放内存。
```csharp
sortedList.TrimExcess(); // 释放无用的双数组内存空洞
```

## 八、 总结提炼

1.  **身份认同**：它是披着字典外衣的**双核数组**。一切优缺点都来源于“数组”。
2.  **核心卖点**：既能按 Key 自动排序，又能像 List 一样通过 `[index]` 获取第几名的元素。
3.  **致命弱点**：增删极慢 O(n)，查读极快。典型的 **“适合做排行榜，不适合做高频交易系统”** 的数据结构。
4.  **选型口诀**：无序用 Dict，高频增删排序用 SortedDict，低频增删+索引排序用 SortedList！
