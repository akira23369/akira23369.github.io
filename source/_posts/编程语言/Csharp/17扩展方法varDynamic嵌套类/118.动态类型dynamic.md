# 动态类型dynamic

在 C# 4.0 中，随着动态语言运行时（DLR, Dynamic Language Runtime）的引入，C# 增加了 `dynamic` 关键字。这使得这门传统的静态强类型语言具备了类似于 Python 或 JavaScript 的动态类型特性。

## 核心概念：什么是 dynamic？

`dynamic` 关键字用于声明一个动态类型的变量。向编译器传递的核心信息是：**“请关闭对该变量的编译期类型检查，将所有的类型解析推迟到运行时（Runtime）。”**

当你对一个 `dynamic` 变量调用方法、访问属性或进行运算时，C# 编译器不会去验证这些成员是否存在，而是直接编译通过。真正的检查会在程序运行到该代码行时由 CLR（具体为 DLR）执行。

### 基本代码示例
```csharp
public class Student
{
    public string StudentName { get; set; }
}

public class Program
{
    public static void Main()
    {
        // 1. 不需要像 var 那样必须在声明时初始化
        dynamic x; 

        // 2. 可以在运行时随意更改所存储数据的类型
        x = 100;               // 此时是 int
        x = "Hello World";     // 现在变成了 string
        
        x = new Student { StudentName = "hachimi" }; // 最终变成了 Student 对象

        // 3. 访问属性：编译器不会检查 StudentName 是否存在，直接放行
        Console.WriteLine(x.StudentName); 

        // 4. 危险性：编译能通过，但运行时会抛出 RuntimeBinderException 异常
        // Console.WriteLine(x.SomeInvalidProperty); 
    }
}
```

## 深度对比：dynamic vs var vs object

理解 `dynamic` 的最佳方式是将它与 `var` 和 `object` 进行横向对比（参考《C# in Depth》与《CLR via C#》的深入解析）。

| 特性           | `var` (隐式类型)      | `object` (顶级基类)       | `dynamic` (动态类型)     |
| :----------- | :---------------- | :-------------------- | :------------------- |
| **类型解析时机**   | **编译期**（静态强类型）    | **编译期**（静态强类型）        | **运行期**（动态解析）        |
| **是否必须初始化**  | 必须                | 否                     | 否                    |
| **后续能否改变类型** | **不能**            | 能                     | 能                    |
| **成员访问**     | 直接访问（享有完整 IDE 提示） | 必须显式类型转换 (Cast) 后才能访问 | 直接访问（无 IDE 提示，运行时抛错） |
| **适用范围**     | 仅限局部变量            | 任何地方（字段、参数、返回值等）      | 任何地方（字段、参数、返回值等）     |

### 代码层面的直观对比
```csharp
// --- object 方式 ---
object obj = new Student { StudentName = "Alice" };
// obj.StudentName; // 编译错误！object 类型没有 StudentName 属性
string name1 = ((Student)obj).StudentName; // 必须强制转换

// --- dynamic 方式 ---
dynamic dyn = new Student { StudentName = "Bob" };
string name2 = dyn.StudentName; // 不需要强制转换，运行时自动解析成员
```

## 动态类型的代价与限制

享受动态特性带来的灵活性是有代价的，在《Effective C#》中明确指出，不应滥用 `dynamic`。

### 失去 IntelliSense (智能提示)
因为编译器在编译阶段不知道 `dynamic` 变量内部到底装的是什么对象，Visual Studio 等 IDE 无法提供成员的自动补全和智能提示。开发者必须完全依靠记忆和手动输入，极易拼错成员名称。

### 运行时的安全性风险
所有的拼写错误、类型不匹配、方法签名错误，都会从“编译期错误”（易于发现和修复）降级为“运行期异常”（隐蔽且危险）。开发者必须自己承担起类型检查的责任。

### 性能损耗
在底层机制中，CLR 并没有真正的 `dynamic` 类型。编译后，`dynamic` 变量实际上会被编译为 `System.Object`，并附加一个 `[Dynamic]` 特性。
当调用 `dynamic` 变量的方法时，DLR 需要在运行时使用反射机制（虽然 DLR 内部有极其复杂的缓存机制来优化性能）去查找目标方法，这会引发装箱（Boxing）以及动态分发的开销。性能远不及传统的静态调用。

## 推荐的实际应用场景

尽管有上述缺点，在特定的场景下，`dynamic` 能够极大地简化代码：

### **简化反射**
在处理未知类型的对象时，传统的反射代码极为冗长（需要 `GetType().GetProperty().GetValue()` 等）。使用 `dynamic` 可以直接用点操作符调用，使代码像静态调用一样干净。

```cs
// 反射方式
var method = type.GetMethod("Hello");
method.Invoke(obj, null);

// dynamic 方式
dynamic d = obj;
d.Hello(); // DLR 在后台帮你处理了反射
```

### **处理动态数据结构**
在解析结构不固定的 JSON 或 XML 时（例如使用 `Newtonsoft.Json` 的 `JObject`），结合 `dynamic` 可以直接通过属性名访问数据，无需定义繁琐的 DTO 类。

假设我们有这样一段从第三方 API 获取的 JSON，它的结构可能会变：
```json
{
  "user": {
    "name": "Gemini",
    "details": {
      "location": "Cloud",
      "version": 3.0
    }
  }
}
```

传统的 DTO 方案 (繁琐)
你需要预先定义好嵌套的类：
```cs
public class Root { public User User { get; set; } }
public class User { public string Name { get; set; } public Details Details { get; set; } }
public class Details { public string Location { get; set; } public double Version { get; set; } }

// 调用
var data = JsonConvert.DeserializeObject<Root>(jsonString);
Console.WriteLine(data.User.Details.Location);
```

Dynamic 方案 (极其简洁)
无需定义任何类，直接起飞：
```cs
// 只需要这一行，注意类型转换
dynamic data = JsonConvert.DeserializeObject(jsonString);

// 像访问普通对象属性一样直接点出来
Console.WriteLine(data.user.name);
Console.WriteLine(data.user.details.location);
```

### **与动态语言或 COM 组件交互**
C# 4.0 引入 `dynamic` 的初衷之一就是为了简化与 Python、Ruby（通过 IronPython/IronRuby）以及旧版 Office COM 组件（如 Excel 自动化）的互操作。使用 `dynamic` 可以省去大量繁琐的类型转换。
