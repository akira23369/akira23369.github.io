# 嵌套类 / 内部类

在 C# 官方术语中，“内部类”通常被称为**嵌套类（Nested Classes）** 或**嵌套类型（Nested Types）**。嵌套类是指声明在另一个类或结构体内部的类。

## 核心概念与应用场景

根据《代码大全》中关于封装和隐藏实现细节的原则，如果一个类（Class B）仅仅是为了协助另一个类（Class A）完成特定工作而存在，并且程序的其他部分完全不需要知道 Class B 的存在，那么将 Class B 定义为 Class A 的嵌套类是最优雅的设计。

**主要应用场景：**
*   **逻辑分组：** 将属于同一特定流程（如复杂的数学计算、特定的数据验证）的辅助类组织在一起。
*   **深度封装：** 隐藏不想对外暴露的辅助逻辑，防止命名空间污染。
*   **实现特定接口：** 在集合框架中经常使用嵌套类来实现迭代器（如 `IEnumerator` 的底层实现）。

## 访问修饰符与可见性

与顶级类（Top-level class，只能是 `public` 或 `internal`）不同，嵌套类可以应用所有的访问修饰符。

*   **默认可见性：** 嵌套类默认是 `private` 的。这意味着它只能在其外部类（Outer Class）的内部被实例化和使用。
*   **公开可见性：** 如果将嵌套类声明为 `public`，它就可以在外部类之外被访问。但在外部实例化时，必须使用**完全限定名**（即 `OuterClass.NestedClass`）。
*   **其他可见性：** 嵌套类同样可以使用 `protected`、`internal`、`protected internal` 和 `private protected`，其访问限制遵循标准的 C# 规则。


## 什么时候使用？
### A. 逻辑上的强关联

如果类 B 离开类 A 就没有任何存在的意义（比如 `List` 和它的 `Enumerator` 迭代器），那么 B 就应该嵌套在 A 里面。
> **例子：** `Car` 类内部定义一个 `Engine` 类。


### B. 隐藏实现细节（内部工具）

如果你需要一个复杂的辅助类，但不希望库的用户看到它，就把它设为 `private` 嵌套类。
> **例子：** 某个复杂的算法需要一个临时的“节点”结构，你可以把它藏在算法类内部。


### C. 命名空间保洁
如果你有很多类似的辅助类，把它们嵌套在主类中可以避免命名空间里出现一堆乱七八糟的小类文件。



## 实例化与成员访问规则 (核心重点)

参考《CLR via C#》中对嵌套类型的深度剖析，嵌套类与外部类之间的访问关系具有高度的特权：

1.  **外部类访问嵌套类：** 外部类不能直接调用嵌套类的实例成员。外部类必须先创建嵌套类的实例，然后通过该实例来访问。
2.  **嵌套类访问外部类：** 
    *   嵌套类**不能**在没有外部类实例的情况下直接访问外部类的实例成员。它必须拥有一个外部类的引用。
    *   **特权访问：** 这是嵌套类最强大的特性——嵌套类可以访问外部类的**所有成员**，包括 `private` 和 `protected` 成员。（就好像嵌套类是外部类的“密友”一样）。
    *   嵌套类可以直接访问外部类的 `static`（静态）成员，无论其访问级别如何。

嵌套类访问外部类所有成员
```cs
public class Container
{
    private string _secret = "核心机密";

    // 这是一个嵌套类
    private class Helper
    {
        public void Reveal(Container parent)
        {
            // 它可以直接访问父类的私有字段！
            Console.WriteLine("访问到了：" + parent._secret);
        }
    }

    public void DoWork()
    {
        var helper = new Helper();
        helper.Reveal(this);
    }
}
```


## 避免 StackOverflow 陷阱

在实际开发中，如果在外部类中实例化嵌套类，同时又在嵌套类中实例化外部类，极易引发无限递归的循环实例化，最终导致 `StackOverflowException`。

**错误示范：**
*   Outer 类的构造函数中包含 `new Inner()`。
*   Inner 类的构造函数中包含 `new Outer()`。
这样会导致调用栈瞬间爆满。应严格避免这种双向的自动实例化。

## 综合代码示例

以下代码展示了嵌套类的定义、实例化规则以及特权访问能力。

```csharp
using System;

// 外部类
public class MarksCalculator
{
    // 外部类的私有字段
    private double _baseMultiplier = 100.0;
    private CalculationHelper _helper;

    public MarksCalculator()
    {
        // 外部类内部可以直接实例化嵌套类
        _helper = new CalculationHelper();
    }

    public double CalculatePercentage(double securedMarks, double maxMarks)
    {
        // 调用嵌套类的方法，并将外部类自身的引用 (this) 传递给嵌套类
        return _helper.Calculate(this, securedMarks, maxMarks);
    }

    // --------------------------------------------------------
    // 嵌套类 (Inner / Nested Class)
    // --------------------------------------------------------
    public class CalculationHelper
    {
        // 接收外部类的实例，以此来访问外部类的成员
        public double Calculate(MarksCalculator outerInstance, double secured, double max)
        {
            double divisionResult = secured / max;

            // 【特权访问】：嵌套类直接访问了外部类的 private 字段 _baseMultiplier！
            return Multiply(divisionResult, outerInstance._baseMultiplier);
        }

        private double Multiply(double num1, double num2)
        {
            return num1 * num2;
        }
    }
}

public class Program
{
    public static void Main()
    {
        // --- 场景 1：通过外部类使用（最常见的封装场景） ---
        MarksCalculator calculator = new MarksCalculator();
        double percentage = calculator.CalculatePercentage(35, 50);
        Console.WriteLine($"Student Percentage: {percentage}%"); // 输出 70%

        // --- 场景 2：在外部类的外面，直接实例化 public 的嵌套类 ---
        // 必须使用 OuterClass.NestedClass 的语法
        MarksCalculator.CalculationHelper helper = new MarksCalculator.CalculationHelper();
        
        // 注意：这里需要传入一个 MarksCalculator 实例才能调用 Calculate 方法
        double manualCalc = helper.Calculate(calculator, 45, 50);
        Console.WriteLine($"Manual Calculation: {manualCalc}%"); // 输出 90%
    }
}
```

## 编译底层的理解

从 CLR（公共语言运行时）的角度来看，实际上并没有所谓的“嵌套类”。嵌套类和普通类在编译后的 IL（中间语言）代码中都会变成完全独立的类型。
C# 编译器只是通过命名重整（Name Mangling）和访问控制元数据，在逻辑上施加了可见性约束，并允许了私有成员的相互访问。因此，使用嵌套类并不会带来额外的运行时性能负担。
