### 扩展方法

#### 定义与核心价值
扩展方法允许开发者在不修改原始类型源代码、不创建派生类型（继承）且不重新编译原始程序集的情况下，向现有类型“添加”方法。虽然这些方法在物理上定义在外部类中，但在逻辑上，它们表现得就像是目标类型的实例成员。

**核心价值：**
*   **增强闭源库：** 即使只有 DLL 文件而没有源码（如第三方库或 .NET 内置库），也能为其增加功能。
*   **避免继承滥用：** 对于 `sealed`（密封）类或不适合通过继承扩展的场景（如基元类型 `int`, `string`），扩展方法是唯一且最佳的选择。
*   **代码可读性：** 支持链式调用（Fluent Interface），使代码流更自然，而非多层静态函数嵌套。

#### 实现规则与约束
要创建扩展方法，必须严格遵守以下 C# 语法规则：
1.  **静态类：** 方法必须定义在一个非嵌套的静态类（`static class`）中。
2.  **静态方法：** 方法本身必须声明为 `static`。
3.  **this 关键字：** 第一个参数必须包含 `this` 修饰符，紧跟要扩展的目标类型。
4.  **命名空间导入：** 调用方必须通过 `using` 指令导入扩展方法所在的命名空间，否则编译器无法在作用域内找到该方法。

#### 示例代码：扩展业务实体逻辑
假设我们有一个不可修改的 `Product` 类，需要为其添加计算折扣的功能。

```csharp
// 模拟第三方库中的类（不可修改）
namespace ThirdPartyLibrary
{
    public class Product
    {
        public double Cost { get; set; }
        public double DiscountPercentage { get; set; }
    }
}

// 我们的扩展定义
namespace MyApp.Extensions
{
    using ThirdPartyLibrary;

    public static class ProductExtensions
    {
        // 扩展方法：第一个参数指定目标类型
        public static double GetDiscountAmount(this Product product)
        {
            // 注意：由于在类外，只能访问 public 成员
            return (product.Cost * product.DiscountPercentage) / 100;
        }

        // 支持带额外参数的扩展方法
        public static double GetPriceAfterTax(this Product product, double taxRate)
        {
            double discount = product.GetDiscountAmount();
            return (product.Cost - discount) * (1 + taxRate);
        }
    }
}

// 使用端代码
using ThirdPartyLibrary;
using MyApp.Extensions; // 必须导入命名空间

var p = new Product { Cost = 1000, DiscountPercentage = 10 };
double amount = p.GetDiscountAmount(); // 像实例方法一样调用
```

#### 幕后原理：编译器的“语法糖”
根据《CLR via C#》的解析，扩展方法并不是真的将代码注入到了目标类中。当你写下 `p.GetDiscountAmount()` 时，C# 编译器在底层会将其转换为传统的静态方法调用：

`ProductExtensions.GetDiscountAmount(p);`

编译器会自动搜索所有作用域内的静态类，寻找带有 `ExtensionAttribute` 标记的方法（该标记由编译器在检测到 `this` 参数时自动生成）。

#### 进阶特性与最佳实践

*   **优先级冲突（Shadowing）：** 如果扩展方法的签名与目标类已有的实例方法完全一致，**实例方法永远优先**。扩展方法在冲突时会被编译器忽略。
*   **空引用的特殊性：** 这是一个关键点（在《C# in Depth》中有详细讨论）。与真正的实例方法不同，即使对象为 `null`，你依然可以调用扩展方法。因为本质是静态调用，你可以在方法内部安全地进行空值检查：

    ```csharp
    public static bool IsNotNull(this object? obj) => obj != null;

    string? s = null;
    s.IsNotNull(); // 不会抛出 NullReferenceException
    ```

*   **扩展接口：** 这是扩展方法最强大的应用场景。LINQ 的核心（如 `Where`, `Select`）就是通过为 `IEnumerable<T>` 接口定义扩展方法实现的。这允许任何实现该接口的集合自动获得这些功能。
*   **设计建议：** 
    *   不要过度为 `System.Object` 定义扩展，这会污染 IDE 的智能感知（IntelliSense）。
    *   如果拥有源代码，优先考虑修改类本身或使用接口，只有在确实无法修改原始代码或需要实现跨类型的横向逻辑时（如 LINQ），才使用扩展方法。

#### 局限性总结
*   **仅限方法：** 无法扩展属性（Properties）、字段（Fields）或事件（Events）。
*   **封装性限制：** 只能访问目标类型的公共（`public`）成员，无法访问 `private` 或 `protected` 成员。
*   **组织结构：** 扩展方法类不能是嵌套类，且必须位于非泛型静态类中。
