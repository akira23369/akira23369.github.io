# System.Object方法解析与重写

## System.Object 提供的四大基础方法概述

作为 .NET 类型系统中的终极基类，`System.Object` 为所有类型（无论是引用类型还是值类型）提供了一套基础的“行为契约”。这套契约由四个核心方法组成：

*   **三个虚方法 (Virtual Methods)**：允许子类根据自身业务逻辑进行重写 (Override)。
    *   `ToString()`
    *   `Equals(object obj)`
    *   `GetHashCode()`
*   **一个非虚方法 (Non-virtual Method)**：由 CLR 严格控制，绝对不允许重写。
    *   `GetType()`

---

## 深入剖析与重写实战

### `ToString()`：对象的字符串表示
*   **默认行为**：返回对象所属类的**完全限定名（命名空间.类名）**。
*   **重写意义**：在绝大多数业务类中，默认的类名输出毫无业务价值。重写 `ToString()` 可以返回包含关键业务属性的格式化字符串，这在**日志记录、异常排查和 UI 数据绑定**时极具价值（《Effective C#》强烈建议为所有自定义类型重写此方法）。

### `Equals(object obj)`：对象相等性判断
*   **默认行为（类/引用类型）**：执行**引用相等性 (Reference Equality)** 检查。即判断两个变量是否指向托管堆中的同一个内存地址。即使两个对象的各个属性值完全一样，只要它们是分别 `new` 出来的，默认的 `Equals` 也会返回 `false`。
*   **默认行为（结构体/值类型）**：执行**值相等性 (Value Equality)** 检查。底层通过反射逐个比较字段。
*   **重写意义**：当业务上需要基于对象的“内容”来判断相等时（例如，两个 `Person` 对象只要名字和邮箱一样，就被视为同一个人），必须重写 `Equals` 方法以实现“值语义”。

### `GetHashCode()`：哈希码生成器
*   **核心功能**：返回一个 32 位带符号整数（哈希码），用于在基于哈希表的集合（如 `Dictionary<TKey, TValue>` 或 `HashSet<T>`）中快速定位对象。
*   **黄金法则（极其重要）**：根据《CLR via C#》的规范，**如果重写了 `Equals`，就必须同时重写 `GetHashCode`**。
    *   **规则 1**：如果两个对象通过 `Equals` 判断为相等，它们的 `GetHashCode` 必须返回相同的整数。
    *   **规则 2**：如果两个对象不相等，它们的哈希码尽量不要相同（发生哈希冲突会降低集合的查询性能，但系统能容忍）。
    *   **后果**：如果不遵守上述规则，将该对象作为字典的 Key 时，会导致数据丢失（存入字典后，再也查询不到该对象）。

### 综合代码实战：重写三大虚方法

现代 C# 提供了极简的语法（如模式匹配和 `System.HashCode` 结构）来实现安全且高性能的重写。

```csharp
using System;

public class Person
{
    public string Name { get; set; }
    public string Email { get; set; }

    // 1. 重写 ToString()，提供易读的日志信息
    public override string ToString()
    {
        return $"[Person] Name: {Name}, Email: {Email}";
    }

    // 2. 重写 Equals，实现基于内容的比较（值语义）
    public override bool Equals(object obj)
    {
        // 使用 C# 现代模式匹配机制：
        // 1. 自动处理 obj 为 null 的情况
        // 2. 自动检查类型是否为 Person
        // 3. 自动将 obj 安全转换为 Person 类型的 other 变量
        if (obj is Person other)
        {
            return this.Name == other.Name && this.Email == other.Email;
        }
        return false;
    }

    // 3. 重写 GetHashCode，结合参与 Equals 比较的字段生成哈希码
    public override int GetHashCode()
    {
        // 现代 C# 推荐使用 HashCode.Combine，避免手动进行位运算
        return HashCode.Combine(Name, Email);
    }
}

public class Program
{
    public static void Main()
    {
        Person p1 = new Person { Name = "Scott", Email = "scott@test.com" };
        Person p2 = new Person { Name = "Scott", Email = "scott@test.com" };

        // 虽然是两个不同的内存对象，但因为重写了 Equals，返回 True
        Console.WriteLine(p1.Equals(p2)); 
        
        // 输出: [Person] Name: Scott, Email: scott@test.com
        Console.WriteLine(p1.ToString()); 
    }
}
```

## 绝对真实的反射镜：`GetType()`

*   **核心功能**：返回一个 `System.Type` 类的实例，该实例包含了当前对象的**精确运行时类型信息 (RTTI, Runtime Type Information)**。
*   **不可伪造性**：由于它是非虚方法 (Non-virtual)，任何类都无法重写它。它反映的是对象在 CLR 内存中的真实类型。
*   **经典应用场景**：当 `ToString()` 被子类重写，返回了各种花里胡哨的业务字符串时，如何确切知道这个对象到底是由哪个类实例化出来的？答案就是调用 `GetType().ToString()`。

```csharp
public class Program
{
    public static void Main()
    {
        // p 声明为 object 类型，但实际存储的是 Person 对象
        object p = new Person { Name = "Alice" };

        // 调用被重写的 ToString()，输出业务数据
        Console.WriteLine(p.ToString()); 
        // 输出: [Person] Name: Alice, Email: 

        // 获取底层的真实类型
        Console.WriteLine(p.GetType().ToString()); 
        // 输出: Person (或者是包含命名空间的全路径：YourNamespace.Person)
    }
}
```
