# 引入命名空间(using Namespaces)

## `using` 指令的核心作用
在代码中频繁使用“完全限定名（完全路径）”来实例化对象或声明变量会导致代码极其臃肿。C# 提供了 `using` 指令来引入命名空间。

其核心目的是**向 C# 编译器提供名称解析的上下文**。当遇到一个未加前缀的短类名（如 `Manager`）时，编译器会遍历所有通过 `using` 引入的命名空间，尝试找到匹配的类型。如果找到，编译通过；如果在多个命名空间中找到同名类型，则会报出歧义错误（Ambiguity Error）。

```csharp
// 引入命名空间
using HR.Mgr;
using FrontOffice;

public class Program
{
    public static void Main()
    {
        // 引入后，无需重复书写完全限定名
        // HR.Mgr.IManager imanager = new HR.Mgr.Manager();
        IManager manager = new Manager(); 
        CustomerInquiry inquiry = new CustomerInquiry();
    }
}
```

## 核心机制：嵌套命名空间不会被级联引入
这是一个开发者经常踩坑的地方。**引入一个父命名空间，绝对不会自动引入其子（嵌套）命名空间。**

从《CLR via C#》的底层视角来看，编译器将命名空间仅仅视为类型名称的“字符串前缀”。`HR` 和 `HR.Mgr` 在编译器眼中是两个完全独立的前缀，不存在物理或逻辑上的包含关系。

```csharp
using HR; // 仅引入了 HR 下的直接成员 (如 HR.Employee)

public class Program
{
    public static void Main()
    {
        // 错误！找不到 Manager。因为 Manager 属于 HR.Mgr
        // Manager m = new Manager(); 

        // 正确：必须明确引入子命名空间 using HR.Mgr; 
        // 或者使用完全限定名
        HR.Mgr.Manager m2 = new HR.Mgr.Manager(); 
    }
}
```
**最佳实践**：按需精准引入。需要用到哪一层的类型，就直接引入到那一层的命名空间。

## `using` 指令的作用域与位置规范

根据《Effective C#》的建议，`using` 指令放置的位置决定了它的作用域，常见的有两种方式：

### 文件顶部（最常见）
将 `using` 放在 `.cs` 文件的最顶端（在所有类和命名空间声明之上）。这样引入的命名空间对该文件内的所有代码都有效。

### 命名空间内部（避免污染）
将 `using` 放在某个特定的 `namespace` 块内部。这种做法的作用域仅限于该命名空间块内。在大型项目中，如果一个文件包含了多个命名空间声明，这种做法可以避免名称污染和潜在的命名冲突。

```csharp
namespace HR.Payroll
{
    // 这里的引入仅对 Payroll 命名空间有效
    using HR.Mgr; 

    public class SalaryCalculator
    {
        public void Calculate(Manager manager) { }
    }
}
```

## 全局引入`global using`(C# 10 及以上)

在现代 C#（包括 C# 13）的开发中，传统的 `using` 已经得到极大增强。


为了避免在项目的几百个文件中重复写 `using System;` 或 `using System.Collections.Generic;`，C# 10 引入了全局指令。只需在一个文件中加上 `global` 关键字，该命名空间就会在**整个项目**的所有文件中生效。

```csharp
// 通常集中放在一个名为 GlobalUsings.cs 的文件中
global using System;
global using HR.Mgr;
global using FrontOffice;
```

## 隐式全局引用
在 C# 10 (.NET 6) 及更高版本中，引入了**隐式全局引用（Implicit Global Usings）** 功能。这项功能通过在项目文件中进行简单配置，就可以让编译器自动为整个项目添加常用的 `using` 指令，从而减少每个 `.cs` 文件开头的重复代码。

---

### 如何启用或禁用

双击项目文件，打开`.csproj`
隐式导入是由项目文件 (`.csproj`) 中的 `<ImplicitUsings>` 属性控制的：

如果将其设置为 `disable`，则需要像以前一样在每个文件中手动编写 `using` 语句。
```xml
<Project Sdk="Microsoft.NET.Sdk">

  <PropertyGroup>
    <OutputType>Exe</OutputType>
    <TargetFramework>net8.0</TargetFramework>
    <!-- 使用最新的 C# 语言特性 -->
    <langversion>latest</langversion>
    <ImplicitUsings>enable</ImplicitUsings>
    <Nullable>enable</Nullable>
    <AllowUnsafeBlocks>True</AllowUnsafeBlocks>
  </PropertyGroup>

  <ItemGroup>
    <PackageReference Include="Newtonsoft.Json" Version="13.0.4" />
    <PackageReference Include="xunit.assert" Version="2.9.3" />
    <PackageReference Include="xunit.extensibility.core" Version="2.9.3" />
  </ItemGroup>

</Project>
```

### 默认导入的命名空间

具体导入哪些命名空间，取决于你使用的 **SDK 类型**。以下是常见 SDK 默认包含的列表：

#### **通用项目 (Microsoft.NET.Sdk)**

适用于控制台程序、类库等：

- `System`
- `System.Collections.Generic`
- `System.IO`
- `System.Linq`
- `System.Net.Http`
- `System.Threading`
- `System.Threading.Tasks`

#### **Web 项目 (Microsoft.NET.Sdk.Web)**

在通用项目的基础上增加了 ASP.NET Core 相关引用：

- `Microsoft.AspNetCore.Builder`
- `Microsoft.AspNetCore.Hosting`
- `Microsoft.AspNetCore.Http`
- `Microsoft.AspNetCore.Routing`
- `Microsoft.Extensions.Configuration`
- `Microsoft.Extensions.DependencyInjection`
- `Microsoft.Extensions.Hosting`
- `Microsoft.Extensions.Logging`

#### **Worker Service 项目 (Microsoft.NET.Sdk.Worker)**

- `Microsoft.Extensions.Configuration`
- `Microsoft.Extensions.DependencyInjection`
- `Microsoft.Extensions.Hosting`
- `Microsoft.Extensions.Logging`

---

### 它们存储在哪里？

当你构建项目时，编译器会自动生成一个名为 `[项目名].GlobalUsings.g.cs` 的文件。你可以在项目的 `obj` 目录下找到它：

`obj/Debug/netX.0/scopedFiles/[项目名].GlobalUsings.g.cs`

这个文件包含了所有的 `global using` 语句，例如：
```cs
// <auto-generated/>
global using System;
global using System.Collections.Generic;
global using System.IO;
global using System.Linq;
global using System.Net.Http;
global using System.Threading;
global using System.Threading.Tasks;
```


---

### 如何自定义隐式导入

如果你想在不修改每个文件的情况下添加自己的全局引用，或者删除某个默认的引用，可以直接修改 `.csproj` 文件：

```xml
<ItemGroup>
    <Using Include="MyProject.Shared" />
    <Using Remove="System.Net.Http" />  <!-- 移除默认引入的 -->
</ItemGroup>
```

---

### 优缺点对比

**小贴士：** 如果你更喜欢显式控制，可以在项目根目录手动创建一个 `GlobalUsings.cs` 文件，将常用的 `using` 冠以 `global` 前缀（例如 `global using System.Math;`），然后禁用 `<ImplicitUsings>`，这样既能保持代码整洁，又具备完全的可控性。

## 底层运行时的视角
**零性能损耗**：需要强调的是，`using` 指令纯粹是**编译时的语法糖**。在代码编译为中间语言（IL）后，所有的类型都会被还原为“完全限定名”。因此，写1个 `using` 还是写100个 `using`，对程序的运行速度和内存占用**没有任何影响**。不要为了所谓的“性能优化”而去精简必要的 `using` 指令。
