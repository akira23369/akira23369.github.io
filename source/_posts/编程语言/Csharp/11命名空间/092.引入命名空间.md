# 引入命名空间(using Namespaces)

## `using` 指令的核心作用
在代码中频繁使用“完全限定名（完全路径）”来实例化对象或声明变量会导致代码极其臃肿。C# 提供了 `using` 指令来引入命名空间。

其核心目的是**向 C# 编译器提供名称解析的上下文**。当遇到一个未加前缀的短类名（如 `Manager`）时，编译器会遍历所有通过 `using` 引入的命名空间，尝试找到匹配的类型。如果找到，编译通过；如果在多个命名空间中找到同名类型，则会报出歧义错误（Ambiguity Error）。

```csharp
// 引入命名空间
using HR.Mgr;
using FrontOffice;

public class Program
{
    public static void Main()
    {
        // 引入后，无需重复书写完全限定名
        // HR.Mgr.IManager imanager = new HR.Mgr.Manager();
        IManager manager = new Manager(); 
        CustomerInquiry inquiry = new CustomerInquiry();
    }
}
```

## 核心机制：嵌套命名空间不会被级联引入
这是一个开发者经常踩坑的地方。**引入一个父命名空间，绝对不会自动引入其子（嵌套）命名空间。**

从《CLR via C#》的底层视角来看，编译器将命名空间仅仅视为类型名称的“字符串前缀”。`HR` 和 `HR.Mgr` 在编译器眼中是两个完全独立的前缀，不存在物理或逻辑上的包含关系。

```csharp
using HR; // 仅引入了 HR 下的直接成员 (如 HR.Employee)

public class Program
{
    public static void Main()
    {
        // 错误！找不到 Manager。因为 Manager 属于 HR.Mgr
        // Manager m = new Manager(); 

        // 正确：必须明确引入子命名空间 using HR.Mgr; 
        // 或者使用完全限定名
        HR.Mgr.Manager m2 = new HR.Mgr.Manager(); 
    }
}
```
**最佳实践**：按需精准引入。需要用到哪一层的类型，就直接引入到那一层的命名空间。

## `using` 指令的作用域与位置规范

根据《Effective C#》的建议，`using` 指令放置的位置决定了它的作用域，常见的有两种方式：

### 文件顶部（最常见）
将 `using` 放在 `.cs` 文件的最顶端（在所有类和命名空间声明之上）。这样引入的命名空间对该文件内的所有代码都有效。

### 命名空间内部（避免污染）
将 `using` 放在某个特定的 `namespace` 块内部。这种做法的作用域仅限于该命名空间块内。在大型项目中，如果一个文件包含了多个命名空间声明，这种做法可以避免名称污染和潜在的命名冲突。

```csharp
namespace HR.Payroll
{
    // 这里的引入仅对 Payroll 命名空间有效
    using HR.Mgr; 

    public class SalaryCalculator
    {
        public void Calculate(Manager manager) { }
    }
}
```

## 全局引入`global using`(C# 10 及以上)

在现代 C#（包括 C# 13）的开发中，传统的 `using` 已经得到极大增强。


为了避免在项目的几百个文件中重复写 `using System;` 或 `using System.Collections.Generic;`，C# 10 引入了全局指令。只需在一个文件中加上 `global` 关键字，该命名空间就会在**整个项目**的所有文件中生效。

```csharp
// 通常集中放在一个名为 GlobalUsings.cs 的文件中
global using System;
global using HR.Mgr;
global using FrontOffice;
```

## 底层运行时的视角
**零性能损耗**：需要强调的是，`using` 指令纯粹是**编译时的语法糖**。在代码编译为中间语言（IL）后，所有的类型都会被还原为“完全限定名”。因此，写1个 `using` 还是写100个 `using`，对程序的运行速度和内存占用**没有任何影响**。不要为了所谓的“性能优化”而去精简必要的 `using` 指令。
