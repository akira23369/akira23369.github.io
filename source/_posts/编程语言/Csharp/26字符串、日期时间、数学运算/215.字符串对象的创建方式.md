# String 对象的内存分配与底层机制

## 字符串对象的创建与内存分布
在 C# 中，通过双引号（字面量）声明字符串时，CLR（公共语言运行时）会在内存中进行特定的操作。
作为引用类型，字符串的内存分配严格遵循“栈存引用，堆存对象”的规则：
*   **托管堆（Managed Heap）**：分配并存储真正的字符串对象（包含所有的字符数据）。
*   **线程栈（Thread Stack）**：分配变量名，并存储指向托管堆中该字符串对象的内存地址。

## 相同字面量的内存复用
根据《CLR via C#》的深层解释，CLR 为了优化内存并避免产生大量重复的字符串对象，内部维护了一个**字符串驻留池（String Intern Pool，本质是一个哈希表）**。

当代码中声明一个字符串字面量时，CLR 会首先在这个内部哈希表中查找是否已经存在相同字符内容的字符串对象：
*   如果**不存在**：在堆中创建一个新的字符串对象，并将其引用添加到驻留池中。
*   如果**已存在**：不再创建新对象，而是直接返回池中已有对象的内存地址。

这种机制彻底避免了相同字符串字面量带来的内存浪费。只要字符内容完全一致（大小写敏感），多个变量在底层实际上指向的是同一块物理内存。只要有一个字符不同（例如多了一个感叹号），就会被视为全新的对象并在堆中独立分配。

## 引用赋值的本质
对于所有的引用类型（不仅限于字符串），当把一个变量赋值给另一个变量时，传递的仅仅是**内存地址（引用）**，而不是复制整个对象本身。
如果声明 `string z = x;`，变量 `z` 会在栈中创建，但它内部存储的地址与 `x` 完全相同，两者共同指向堆中的同一个字符串对象。

## 重新赋值与不可变性的真实表现
理解字符串的关键在于区分“变量”和“对象”。
字符串对象是**绝对不可变（Immutable）**的。当对一个已经存在的字符串变量赋新值时，底层的执行逻辑如下：
1.  计算/读取等号右侧的新字符串内容。
2.  在托管堆中为一个全新的字符串对象分配内存（或者从驻留池中获取）。
3.  将新对象的内存地址覆盖掉变量原来存储的旧地址。

在这个过程中，**旧的字符串对象本身没有任何改变**。这也解释了为什么修改一个变量的值，绝对不会影响其他指向原对象的变量。原来指向旧对象的变量，依然会输出旧的内容。

## 综合代码论证：内存分配与地址追踪
以下代码通过 `object.ReferenceEquals` 方法（用于比较两个引用类型的内存地址是否相同）直观地证明了上述底层逻辑。

```csharp
using System;

class StringMemoryDemonstration
{
    static void Main()
    {
        // 1. 首次创建："hello world" 被分配在堆中，地址存入变量 x
        string x = "hello world";

        // 2. 驻留机制：CLR 发现 "hello world" 已存在，直接将相同的地址赋给 y
        string y = "hello world";
        
        // 验证 x 和 y 是否指向完全相同的内存地址
        bool isSameReferenceXY = object.ReferenceEquals(x, y); 
        Console.WriteLine($"x 和 y 指向同一内存地址: {isSameReferenceXY}"); // 输出: True

        // 3. 引用传递：将 x 的地址拷贝给 z，不创建新对象
        string z = x;
        bool isSameReferenceXZ = object.ReferenceEquals(x, z);
        Console.WriteLine($"x 和 z 指向同一内存地址: {isSameReferenceXZ}"); // 输出: True

        // 4. 重新赋值：看似"修改"了x，实际上是在堆中创建了全新的 "hello" 对象，x 的指针改变
        x = "hello";

        // 此时验证 x 和 y 的内存地址，已经不同了
        bool isNowSame = object.ReferenceEquals(x, y);
        Console.WriteLine($"重新赋值后，x 和 y 指向同一内存地址: {isNowSame}"); // 输出: False

        // 5. 最终输出：证明对象不可变，原对象依然存在且未受影响
        Console.WriteLine($"x 的值: {x}"); // 输出: hello
        Console.WriteLine($"y 的值: {y}"); // 输出: hello world
        Console.WriteLine($"z 的值: {z}"); // 输出: hello world
    }
}
```

## 开发建议
理解了上述内存行为后，在实际开发中应注意：由于每次重新赋值或拼接都会产生新对象，废弃的旧对象虽然没有变量指向它们，但依然停留在堆内存中，直到垃圾回收器（GC）触发回收。这也是为什么在循环或高频操作中应当避免使用 `+` 或 `=` 直接修改字符串，而必须依赖 `StringBuilder` 来避免内存碎片的产生。
