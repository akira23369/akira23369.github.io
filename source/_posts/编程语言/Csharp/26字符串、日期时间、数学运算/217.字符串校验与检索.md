# 字符串校验与检索机制

在开发中，字符串的验证和内容检索是最频繁的操作之一（如表单验证、路径解析、数据清洗）。`System.String` 类提供了一系列高效的方法来完成这些任务。

## 字符串相等性比对：`Equals` 与 `==`

在 C# 中，检查两个字符串的内容是否完全一致，可以使用 `Equals` 实例方法或 `==` 运算符。

**深度扩展（底层原理）：**
根据《CLR via C#》的讲解，字符串是**引用类型**。通常情况下，引用类型的 `==` 运算符比较的是**内存地址（引用相等性）**。然而，`System.String` 类在底层**重载（Overload）** 了 `==` 和 `!=` 运算符，并且**重写（Override）** 了 `Object.Equals` 方法。
因此，在 C# 中对字符串使用 `==` 或 `Equals`，底层都会逐一比较字符串的长度和每一个字符的值（值相等性），两者在结果上没有任何区别。

```csharp
string str1 = "Universe";
string str2 = new string(new char[] { 'U', 'n', 'i', 'v', 'e', 'r', 's', 'e' });

// 虽然 str1 和 str2 在堆中可能是两个不同的对象（内存地址不同）
// 但它们的内容比较会返回 True
bool isOperatorEqual = (str1 == str2); // True
bool isMethodEqual = str1.Equals(str2); // True
```

## 边界与内容校验：`StartsWith`, `EndsWith`, `Contains`

这些方法用于模式匹配，返回 `bool` 类型。
*   **StartsWith()**：检查字符串是否以指定的字符或子串开头。
*   **EndsWith()**：检查字符串是否以指定的字符或子串结尾。
*   **Contains()**：检查指定的字符或子串是否在源字符串中连续出现（位置不限）。

**深度扩展（最佳实践）：**
《Effective C#》中强调，进行字符串比较和匹配时，默认情况下这些方法是**文化敏感（Culture-sensitive）** 的。在处理系统级内部字符串（如验证文件后缀名、URL、注册表键）时，强烈推荐传入 `StringComparison.OrdinalIgnoreCase` 参数。它执行的是底层字节码级别的比较，忽略语言区域特性，既能忽略大小写，又能提供最高的执行性能。

```csharp
string fileName = "report.PDF";

// 基础用法：精确区分大小写，返回 False
bool check1 = fileName.EndsWith("pdf"); 

// 进阶最佳实践：忽略大小写的系统级比对，返回 True
bool check2 = fileName.EndsWith("pdf", StringComparison.OrdinalIgnoreCase);

bool hasPort = fileName.Contains("port"); // True
```

## 索引检索机制：`IndexOf` 与 `LastIndexOf`

当需要知道某个字符或子串在主字符串中的确切位置时，使用索引检索方法。返回值是目标首次出现的从 `0` 开始的索引；如果**未找到，则返回 `-1`**。

*   **IndexOf()**：从左向右（索引 0 到末尾）扫描，返回**第一次**匹配的索引。
*   **LastIndexOf()**：从右向左（末尾到索引 0）扫描，返回**最后一次**（从左数起的绝对位置）匹配的索引。

**处理多次出现的子串（重载应用）：**
这两个方法都支持传入 `startIndex` 参数，用于指定搜索的起点。
*   查找下一次出现的公式：`IndexOf(target, previousIndex + 1)`
*   `LastIndexOf(target, startIndex)` 则是从 `startIndex` 开始，向左（即向索引 0 的方向）进行反向搜索。

```csharp
string text = "developer";

// 1. 基础检索
int firstE = text.IndexOf('e'); // 返回 1
int notFound = text.IndexOf('z'); // 返回 -1 (代表未找到)

int lastE = text.LastIndexOf('e'); // 返回 7 (从右向左找，遇到的第一个'e'的绝对索引)

// 2. 获取第二次出现的索引
// 从第一次出现的索引 (1) 的下一个位置 (2) 开始向右查找
int secondE = text.IndexOf('e', firstE + 1); // 返回 3

// 3. 获取第三次出现的索引
int thirdE = text.IndexOf('e', secondE + 1); // 返回 7
```

## 极致的安全校验：处理 Null 与空白字符

在接收外部输入（如用户表单、API 请求）时，字符串可能处于三种无效状态：`null`（未分配内存）、`""`（空字符串，长度为0）、或 `"   "`（仅包含空格、制表符等）。

C# 提供了两个极其重要的**静态方法**来进行边界防御：

*   **string.IsNullOrEmpty(str)**：当字符串为 `null` 或长度为 `0` 的 `""` 时，返回 `True`。但它防不住用户输入纯空格。
*   **string.IsNullOrWhiteSpace(str)**：进一步增强，只要字符串是 `null`、`""` 或者**只包含任何形式的空白字符（空格、换行、制表符）**，就返回 `True`。

**深度扩展（架构规范）：**
在《代码大全》的防御性编程原则中，`string.IsNullOrWhiteSpace` 应当是拦截外部不可信输入的默认首选方法。它经常被用在属性的 `set` 访问器或方法的参数校验中。

```csharp
// 模拟用户可能输入的恶意/无效数据
string input1 = null;
string input2 = "";
string input3 = "   \t  "; // 包含空格和制表符

// IsNullOrEmpty 对 input3 会返回 False，存在安全隐患
// IsNullOrWhiteSpace 对这三种情况全部拦截，返回 True

class Customer
{
    private string _customerName;

    public string CustomerName
    {
        get { return _customerName; }
        set
        {
            // 防御性编程：在设值前进行严密校验
            if (string.IsNullOrWhiteSpace(value))
            {
                // 拒绝赋值或抛出异常
                throw new ArgumentException("Customer name cannot be null, empty, or just whitespace.");
            }
            // 通过校验后再去两端空格并赋值
            _customerName = value.Trim();
        }
    }
}
```
