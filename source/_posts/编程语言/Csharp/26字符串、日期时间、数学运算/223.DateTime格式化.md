# DateTime格式化

## 为什么需要处理 DateTime 的格式？
在实际开发中，日期和时间的应用场景主要分为**输入（解析）** 和**输出（展示）**：
*   **输入输出的不确定性**：用户输入的日期格式可能千奇百怪（如 `dd-MM-yyyy`、`yyyy/MM/dd` 等），而程序本身或数据库通常需要标准的 `DateTime` 对象。
*   **跨区域（跨文化）问题**：默认的日期转换依赖于当前计算机的操作系统的区域设置（Control Panel -> Region）。如果代码在具有不同区域设置的服务器上运行，依赖默认格式的转换往往会导致异常或数据解析错误。

因此，掌握自定义格式化输出和严格的字符串解析是 C# 开发者的基本功。

## 将 DateTime 格式化为字符串（输出控制）

将 `DateTime` 对象展示给用户时，可以通过不同的 API 控制输出结果。

### 依赖操作系统的内置快捷方法
以下方法会将日期格式化为字符串，但其结果**严格依赖于当前运行计算机的 Windows 区域设置**。

*   **`ToShortDateString()`**: 返回短日期格式（如：`12/31/2000`）。
*   **`ToLongDateString()`**: 返回长日期格式，通常包含完整的月份和星期名称（如：`Sunday, December 31, 2000`）。
*   **`ToShortTimeString()`**: 返回短时间格式，通常只包含时和分（如：`11:59 PM`）。
*   **`ToLongTimeString()`**: 返回长时间格式，包含时、分、秒（如：`11:59:59 PM`）。

```csharp
DateTime date = new DateTime(2000, 12, 31, 23, 59, 59);

Console.WriteLine(date.ToShortDateString()); // 示例输出: 12/31/2000
Console.WriteLine(date.ToLongTimeString());  // 示例输出: 11:59:59 PM
```

### 使用 `ToString()` 进行自定义格式化 (重点)
为了保证程序在任何机器上输出的日期格式高度一致，强烈建议向 `ToString()` 方法传递自定义格式字符串。这种方式可以灵活指定年月日时分秒的排列和分隔符。

它能自动识别常见的日期分隔符（`-`, `/`, `.`）。
```cs
DateTime date = DateTime.ParseExact("2026-03.08 12:54.16", "yyyy-M.d HH:mm.ss", null);
```

**常用格式占位符解析（严格区分大小写）：**
*   **日期部分**
    *   `dd`: 月份中的日期，补零（如 01 到 31）。
    *   `ddd`: 星期几的简写（如 Mon, Tue）。
    *   `dddd`: 星期几的全称（如 Monday）。
    *   `MM`: 月份数字，补零（如 01 到 12）。
    *   `MMM`: 月份简写（如 Jan, Feb）。
    *   `MMMM`: 月份全称（如 January）。
    *   `yyyy`: 四位数的年份（如 2023）。
*   **时间部分**
    *   `hh`: 12 小时制的小时，补零（01 到 12）。
    *   `HH`: 24 小时制的小时，补零（00 到 23）。
    *   `mm`: 分钟，补零（00 到 59）。
    *   `ss`: 秒数，补零（00 到 59）。
    *   `fff`: 毫秒数，三位。
    *   `tt`: AM 或 PM 指示符。

```csharp
DateTime myDate = new DateTime(2000, 12, 31, 23, 5, 9); // 注意时间是晚上 11点05分09秒

// 格式 1: 标准开发常用格式 (24小时制)
Console.WriteLine(myDate.ToString("yyyy-MM-dd HH:mm:ss")); 
// 输出: 2000-12-31 23:05:09

// 格式 2: 面向用户的友好展示 (12小时制 + AM/PM)
Console.WriteLine(myDate.ToString("dd-MMM-yyyy hh:mm:ss tt")); 
// 输出: 31-Dec-2000 11:05:09 PM

// 格式 3: 包含星期名称
Console.WriteLine(myDate.ToString("dddd, MMMM dd, yyyy")); 
// 输出: Sunday, December 31, 2000
```

## 解析非标准字符串为 DateTime（输入控制）

### `DateTime.Parse` 的局限性
`DateTime.Parse()` 只能识别符合常见标准（如 `yyyy-MM-dd`）或当前系统默认设置的日期字符串。如果用户输入的格式为 `dd/MM/yyyy`，而系统默认区域期望的是 `MM/dd/yyyy`，代码将抛出 `FormatException`。

### `DateTime.ParseExact` 详解 (进阶)
当你明确知道输入字符串的具体格式时（例如从特定报表或外部接口读取数据），使用 `DateTime.ParseExact` 是最安全、最精准的解析方式。

它能自动识别常见的日期分隔符（`-`, `/`, `.`）。
```cs
DateTime date = DateTime.ParseExact("2026-03.08 12:54.16", "yyyy-M.d HH:mm.ss", null);
```


**所需参数：**
1.  **输入字符串**：需要解析的日期数据。
2.  **期望格式**：与输入完全对应的格式字符串（参考 `ToString` 的占位符）。
3.  **`IFormatProvider`**：通常传入 `CultureInfo.InvariantCulture`。这是一个不依赖任何特定国家/地区的“中立”文化设置，可确保解析过程不被操作系统区域设置干扰。
4.  **`DateTimeStyles`**：用于定制解析规则，通常传入 `DateTimeStyles.None` 即可。


```csharp
using System;
using System.Globalization; // 必须引入此命名空间

class Program
{
    static void Main()
    {
        // 假设用户或系统传入了一个极其特殊的日期格式字符串
        string userInput = "31/12/2000 23:59:59"; 

        // 定义与输入严格匹配的格式模板
        string formatTemplate = "dd/MM/yyyy HH:mm:ss";

        // 使用 ParseExact 进行精确解析
        DateTime parsedDate = DateTime.ParseExact(
            userInput, 
            formatTemplate, 
            CultureInfo.InvariantCulture, 
            DateTimeStyles.None
        );

        Console.WriteLine($"解析成功，年份为: {parsedDate.Year}"); // 输出: 2000
    }
}
```

## DateTime 的其他常用进阶 API

除了格式化和解析，`DateTime` 还提供了一些直接实例化和验证的实用方法。

### 使用构造函数实例化（性能最佳）
在已知年、月、日等具体数值时，不要先拼接成字符串再去 Parse，而应该**直接使用带有多个整型参数的构造函数**。这避免了字符串解析的性能损耗，是最推荐的硬编码日期初始化方式。

```csharp
// 依次传入：年, 月, 日, 时, 分, 秒
DateTime explicitDate = new DateTime(2000, 12, 31, 23, 59, 0);
Console.WriteLine(explicitDate); 
```

### `DateTime.DaysInMonth` 静态方法
用于获取指定年份中某个月份的总天数。
**特点**：底层自动包含闰年逻辑计算（例如判断某年的 2 月是 28 天还是 29 天），无需开发者自己编写除以 4、除以 100 的闰年判断算法。

```csharp
// 获取 2022 年 7 月的天数
int daysInJuly2022 = DateTime.DaysInMonth(2022, 7);
Console.WriteLine(daysInJuly2022); // 输出: 31

// 获取 2024 年（闰年）2 月的天数
int daysInFeb2024 = DateTime.DaysInMonth(2024, 2);
Console.WriteLine(daysInFeb2024); // 输出: 29
```
