# StringBuilder

## 为什么需要 StringBuilder？（核心痛点）
我们在之前的笔记中明确过：`string` 是**绝对不可变**的。
如果您在循环中执行 `str += "a"` 10000 次，CLR 会在托管堆（Heap）上分配 10000 个全新的字符串对象，废弃 9999 个旧对象。这会导致极其严重的内存碎片，并疯狂触发垃圾回收器（GC），导致程序卡顿（GC Pause）。

**`StringBuilder` 的诞生就是为了解决“高频字符串修改”带来的内存爆炸问题。它是一个可变的（Mutable）字符序列。**

---

## 底层架构原理：它是如何工作的？
理解 `StringBuilder`，必须抛开“字符串”的概念，把它看作是一个**动态扩容的字符数组（`char[]`）**。

### A. 容量（Capacity）与扩容机制
当你 `new StringBuilder()` 时，它默认会在堆上分配一个长度为 **16** 的字符数组（这就是 `Capacity`）。
*   当你不断 `Append` 字符时，它直接在这个数组对应的物理内存中填入字符。**不产生任何新对象。**
*   **触发扩容**：当装满 16 个字符，再追加第 17 个时，它会触发扩容。早期的 .NET 会分配一个两倍大（32）的新数组，把旧数据拷过去。

### B. 现代 .NET 的“块链表”（Chunking）机制优化
在 .NET 4.0 及更高的版本中，微软对 `StringBuilder` 做了史诗级底层架构重构：
为了避免字符串过长时，申请连续的大数组触发 **大对象堆（LOH, Large Object Heap）** 导致严重的内存碎片，现代的 `StringBuilder` 内部其实是一个**链表（Linked List）**。
当当前字符数组装满时，它**不再拷贝旧数据**，而是**直接分配一个新的字符数组块（Chunk）**，并把旧块的指针指向新块。只有在最后调用 `ToString()` 时，它才会把所有块拼装成一个完整的不可变 `string` 对象。


| **特性**    | **老版本 (.NET 4.0 以前)** | **现代版本 (.NET Core / .NET 5+)** |
| --------- | --------------------- | ------------------------------ |
| **内部结构**  | **单一连续数组**            | **不连续的链表块 (Chunks)**           |
| **扩容动作**  | 申请双倍空间 + **全量拷贝**     | 申请一个新块 + **指针挂载**              |
| **内存连续性** | 内存是完全连续的              | 内存是物理碎片化、逻辑连续的                 |
| **性能瓶颈**  | 大数据量下扩容会导致明显的 CPU 尖峰  | 扩容极快，但 `ToString()` 略慢         |

## 核心 API 与 流式语法(Fluent API)

`StringBuilder` 的所有修改方法（增、删、改、插）都返回它**自身的引用 (`this`)**。这种设计模式被称为**流式接口（Fluent Interface）**，允许代码进行极度优雅的链式调用。

```csharp
using System;
using System.Text;

public class StringBuilderDemo
{
    public static void Run()
    {
        // 最佳实践：如果在创建时大概知道最终长度，务必预设初始容量！
        // 这样可以彻底避免底层扩容带来的微小性能损耗
        StringBuilder sb = new StringBuilder(500);

        // 链式调用 (Method Chaining)
        sb.Append("The developer ")
          .Append("is ")
          .AppendLine("coding.") // AppendLine 会自动加上系统换行符 (\r\n 或 \n)
          .Insert(13, " deeply") // 在索引 13 插入
          .Replace("coding", "debugging") // 替换所有匹配项
          .Remove(0, 4); // 从索引0开始，删除4个字符 ("The ")

        // 最终时刻：生成不可变的 String 对象 (整个生命周期中，仅在此时产生了一次新 string 对象的内存分配)
        string finalResult = sb.ToString(); 
        
        Console.WriteLine(finalResult);
        // 输出: developer deeply is debugging.
    }
}
```



在使用它之前，记得引入命名空间：`using System.Text;`
### 常用属性

#### Length

**作用：** 获取或设置当前 `StringBuilder` 对象中字符的长度。

> **注意：** 如果你把 `Length` 设置得比当前短，字符串会被截断。

```cs
StringBuilder sb = new StringBuilder("Hello World");
Console.WriteLine(sb.Length); // 输出: 11

sb.Length = 5; 
Console.WriteLine(sb.ToString()); // 输出: Hello
```

#### Capacity

**作用：** 获取或设置它能容纳的最大字符数。
`StringBuilder` 会预先分配一块内存。当字符长度超过 `Capacity` 时，它会自动翻倍扩容。

```cs
StringBuilder sb = new StringBuilder(10); // 初始容量设为 10
Console.WriteLine($"长度: {sb.Length}, 容量: {sb.Capacity}"); // 0, 10

sb.Append("This is a long string");
Console.WriteLine($"长度: {sb.Length}, 容量: {sb.Capacity}"); // 21, 22 (自动扩容了)
```

### 常用方法

#### 构造函数
```cs
StringBuilder()  // 默认构造，capacity 是16
StringBuilder( int capacity)
StringBuilder( string value)
StringBuilder( string value, int capacity)
```

#### Append()
**作用：** 在对象的末尾追加字符串、数字、对象等。它是最常用的方法。


```cs
StringBuilder sb = new StringBuilder("Price: ");
sb.Append(19.99);
sb.Append(" 元");
Console.WriteLine(sb.ToString()); // 输出: Price: 19.99 元
```

#### AppendLine()

**作用：** 在末尾追加内容，并自动加上一个**换行符**（根据操作系统自动选择 `\r\n` 或 `\n`）。

```cs
StringBuilder sb = new StringBuilder();
sb.AppendLine("第一行");
sb.AppendLine("第二行");
Console.WriteLine(sb.ToString());
/* 输出:
第一行
第二行
*/
```

#### Insert()

**作用：** 在指定的索引位置插入字符串。

```cs
StringBuilder sb = new StringBuilder("I Code");
sb.Insert(2, "Love "); 
Console.WriteLine(sb.ToString()); // 输出: I Love Code
```

#### Remove()

**作用：** 从指定索引开始，删除指定长度的字符。

```cs
StringBuilder sb = new StringBuilder("Hello Unwanted World");
sb.Remove(6, 9); // 从索引6开始，删除9个字符
Console.WriteLine(sb.ToString()); // 输出: Hello World
```

#### Replace()

**作用：** 将指定的字符或字符串全部替换为新的内容。

```cs
StringBuilder sb = new StringBuilder("C# is slow. C# is hard.");
sb.Replace("slow", "fast").Replace("hard", "easy"); 
Console.WriteLine(sb.ToString()); // 输出: C# is fast. C# is easy.
```

#### Clear()

**作用：** 清空对象中的所有字符，长度重置为 0。

> **技巧：** 如果你要在循环中重复利用同一个 `StringBuilder` 以节省开销，用 `Clear()` 比新建一个对象更专业。

```cs
StringBuilder sb = new StringBuilder("Content");
sb.Clear();
Console.WriteLine(sb.Length); // 输出: 0
```

#### ToString()

**作用：** 这是“收网”的一步，将 `StringBuilder` 转换回常规的 `string`。
```cs
StringBuilder sb = new StringBuilder("Finish");
string result = sb.ToString(); 
```

### api使用建议

| **场景**          | **推荐做法**                                   |
| --------------- | ------------------------------------------ |
| **少量拼接 (2-3个)** | 直接用 `string.Concat` 或 `$` 插值，简单优雅。         |
| **循环拼接 / 大量操作** | **必须**使用 `StringBuilder`，否则 GC (垃圾回收) 会忙死。 |
| **已知最终长度**      | 在构造函数里直接指定 `Capacity`，避免中途多次扩容带来的性能损耗。     |


## 现代 .NET 中的高级特性

随着 C# 版本的演进，`StringBuilder` 被赋予了极高的新特性支持，尤其是在配合 `Span<T>` 追求零内存分配（Zero Allocation）的场景中。

### A. `AppendJoin` (取代 `string.Join`)
以前拼接数组只能用 `string.Join`，但如果有大量集合需要依次拼接，`AppendJoin` 是性能之王。
```csharp
StringBuilder sb = new StringBuilder();
string[] frameworks = { "ASP.NET", "Entity Framework", "WPF" };

// 直接将数组元素拼接进缓冲区，无需产生临时的 string.Join 结果对象
sb.Append("Skills: ").AppendJoin(", ", frameworks);
```

### B. 高性能数值追加（Span 整合）
当你追加数字 `sb.Append(123)` 时，以前底层会隐式调用 `123.ToString()` 产生临时字符串。现代 .NET 中，`StringBuilder` 直接支持通过 `ISpanFormattable` 将数字**直接写入底层的 char[] 内存中**，彻底消灭了数字转字符串的 GC 压力。

### C. `GetChunks()` (底层切片读取)
如果你要处理长达 100MB 的日志字符串，直接调用 `ToString()` 会直接导致内存爆炸（突然需要连续的 100MB 内存）。你可以使用 `GetChunks()` 直接遍历底层内存块进行写文件等操作，实现流式处理。

```csharp
StringBuilder sb = new StringBuilder();
// ... 假设追加了海量数据 ...

// 遍历底层的 ReadOnlyMemory<char> 块，直接流式写入文件，不生成巨型 string
foreach (ReadOnlyMemory<char> chunk in sb.GetChunks())
{
    // 直接操作底层内存块
}
```

## 什么时候 **不要** 用 StringBuilder？

面试和高级开发中最常见的误区就是“只要拼接字符串就用 StringBuilder”。**这是绝对错误的！**

`StringBuilder` 本身的实例化（`new StringBuilder()`）以及内部结构的维护是**有固定开销的**。

*   **场景 1：极少量的硬编码拼接**
    ```csharp
    // 错误用法：完全是性能倒退，开销大于收益
    StringBuilder sb = new StringBuilder();
    sb.Append(firstName).Append(" ").Append(lastName);
    
    // 正确用法：编译器会对少量的 + 号或插值进行极致优化（直接预计算总长度并一次分配）
    string fullName = $"{firstName} {lastName}"; 
    ```
*   **场景 2：在确定的有限循环内拼接**
    如果是 3~5 次的拼接，直接使用 `string.Concat` 或 `$` 即可。

**终极定论（Rule of Thumb）：**
只有在**循环次数未知**（例如遍历数据库结果集生成 CSV），或者**预估拼接次数超过 10 次以上**时，才应该祭出 `StringBuilder`。

## 终极性能优化：StringBuilder 对象池

在高并发 Web 应用（如 ASP.NET Core API）中，如果每个 HTTP 请求都 `new StringBuilder()` 拼接 JSON 或日志，哪怕很快被 GC 回收，也会引发“GC 抖动”。

顶级框架底层的做法是：**循环使用现有的 `StringBuilder` 对象，而不是一直 `new`**。

```csharp
using Microsoft.Extensions.ObjectPool;

public class HighPerformanceLogger
{
    // 创建一个全局的对象池
    private static readonly ObjectPool<StringBuilder> _pool = 
        new DefaultObjectPoolProvider().CreateStringBuilderPool();

    public void LogData(string[] data)
    {
        // 1. 从池中借用一个闲置的 StringBuilder (可能是上个请求用完还回来的)
        StringBuilder sb = _pool.Get();

        try
        {
            foreach (var item in data)
            {
                sb.AppendLine(item);
            }
            Console.WriteLine(sb.ToString());
        }
        finally
        {
            // 2. 归还给池 (底层会自动调用 sb.Clear() 清空内容，但保留容量 Capacity)
            // 下次借用时就不需要重新分配底层数组了！
            _pool.Return(sb);
        }
    }
}
```

## 总结
1. `StringBuilder` 本质是**可变容量的字符数组/块链表**。
2. 永远优先使用链式调用（Fluent API）。
3. 如果预知大小，**始终在构造函数中传入初始容量** `new StringBuilder(capacity)`。
4. 少量拼接用 `$""`，未知循环或海量拼接必用 `StringBuilder`。
5. 高并发极速场景使用 `ObjectPool<StringBuilder>`。
