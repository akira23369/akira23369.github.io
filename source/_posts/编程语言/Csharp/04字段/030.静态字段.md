# 静态字段

## 核心概念：什么是静态字段？

在面向对象编程中，字段通常用于存储对象的状态。然而，并非所有的数据都专属于某一个具体的对象。当我们需要存储**属于整个类，且被该类的所有对象共享的数据**时，就需要使用**静态字段 (Static Fields)**。

*   **声明方式**：在字段声明时添加 `static` 关键字。
*   **归属权**：静态字段属于**类本身**，而不是属于类的某个具体实例（对象）。
*   **共享特性**：无论基于该类创建了多少个对象（即使创建了0个对象），静态字段在内存中始终只有一份拷贝，所有对象都共享这一份数据。

### 现实生活中的类比
1.  **银行账户 (Bank Account)**：
    *   实例字段（各不相同）：账号、账户持有人姓名、当前余额。
    *   静态字段（所有账户共享）：银行名称（假设这些账户都在同一家银行）。
2.  **学校教室 (Classroom)**：
    *   实例字段：学生学号、学生姓名、考试成绩。
    *   静态字段：授课教师姓名、所在教室的房间号。

## 内存管理与生命周期 (重要机制)

理解静态字段的关键在于理解它在内存中的运作方式。

*   **存储位置**：实例对象被存储在堆内存 (Heap) 中，每个对象都有自己独立的数据块。而静态字段**不会**存储在这些对象内部。CLR (公共语言运行时) 会在堆内存中为“类本身”分配一块单独的区域（类内存/类型对象指针区域），静态字段就存储在这里。
*   **分配时机**：实例字段的内存是在使用 `new` 关键字创建对象时分配的。而静态字段的内存是在**程序运行过程中，该类第一次被访问时**分配的。如果在整个程序生命周期中都没有使用到这个类，静态字段的内存就永远不会被分配。
*   **状态可变性（常见误区）**：`static` 不等于不可变！静态字段的值是可以在程序运行过程中随时被修改的（除非同时使用了 `readonly` 等修饰符）。它仅仅代表“全局共享”，不代表“常量”。

---

## 实例字段 vs 静态字段对比总结

| 特性         | 实例字段 (Instance Fields)         | 静态字段 (Static Fields)             |
| :--------- | :----------------------------- | :------------------------------- |
| **关键字**    | 无 `static` 修饰符                 | 使用 `static` 修饰符                  |
| **内存位置**   | 存储在具体的对象 (Object) 内部           | 存储在类内存 (Class Memory) 中          |
| **内存分配频率** | 每次使用 `new` 创建对象时都会分配一份         | 整个应用程序生命周期内只分配一次                 |
| **数据隔离性**  | 每个对象的数据相互独立 (隔离)               | 所有对象共享同一份数据                      |
| **外部访问方式** | 必须通过**对象引用变量**访问 (`obj.Field`) | 必须通过**类名**访问 (`ClassName.Field`) |

## 代码实现与访问规则

### 静态字段的声明与类内部访问

在类库或模型中定义静态字段。如果在类的内部访问自己的静态字段，可以直接写字段名，也可以加上类名前缀。

```csharp
namespace ClassLibrary1
{
    public class Product
    {
        // 实例字段
        public int productId;
        public string productName;

        // 静态字段：用于记录当前系统中总共创建了多少个产品
        // 默认值为 0
        public static int TotalNoOfProducts;

        // 类内部的方法
        public void PrintTotal()
        {
            // 在类内部，可以直接访问静态字段，或者使用 Product.TotalNoOfProducts
            int currentTotal = TotalNoOfProducts; 
        }
    }
}
```

### 类外部的访问与操作

在控制台应用程序（主程序）中，操作静态字段必须严格遵循访问规则：**不能使用对象引用变量来访问静态字段，必须使用类名。**

```csharp
using System;
using ClassLibrary1;

namespace FieldsExample
{
    class Program
    {
        static void Main(string[] args)
        {
            // 此时，Product类被首次访问，TotalNoOfProducts 在内存中被分配，初始值为0

            // 实例化第一个对象
            Product p1 = new Product();
            // p1.TotalNoOfProducts++; // 语法错误！不能通过对象实例访问静态字段
            Product.TotalNoOfProducts++; // 正确做法：通过类名访问并修改

            // 实例化第二个对象
            Product p2 = new Product();
            Product.TotalNoOfProducts++;

            // 实例化第三个对象
            Product p3 = new Product();
            Product.TotalNoOfProducts++;

            // 最终输出共享的静态字段结果
            Console.WriteLine("Total number of products: " + Product.TotalNoOfProducts);
            // 预期输出: 3
            
            Console.ReadLine();
        }
    }
}
```

**补充与完善：工程实践中的最佳方式**
笔记中的代码展示了在 `Main` 方法中手动递增 `TotalNoOfProducts`。但在实际的工程开发中，这种做法存在隐患：如果其他开发者 `new` 了一个新产品却忘记写 `Product.TotalNoOfProducts++;`，数据就会出错。

**最佳实践**是利用面向对象的**构造函数 (Constructor)** 机制。既然静态字段属于类，且作用是统计对象数量，那么每次对象被创建时，让类自己去维护这个计数器是最安全的：

```csharp
public class Product
{
    public static int TotalNoOfProducts = 0; // 显式初始化（可选）

    // 构造函数：每次使用 new Product() 时自动执行
    public Product()
    {
        // 每创建一个实例，静态计数器自动加 1
        TotalNoOfProducts++; 
    }
}
```
这样一来，在主程序中只需要专注于创建对象 `Product p = new Product();`，静态字段的累加将由类内部自动且可靠地完成，这更符合面向对象**高内聚**的设计原则。
