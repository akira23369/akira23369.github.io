# 只读字段

## 核心概念：什么是只读字段？

在 C# 中，**只读字段 (Readonly Fields)** 是一种特殊的实例字段，使用 `readonly` 关键字修饰。它的核心特性是：**一旦对象的初始化过程（构造阶段）完成，该字段的值就绝对不可再被修改。**

*   **实例归属**：默认情况下，只读字段是**实例字段**。这意味着它被存储在堆内存的具体对象中，每个对象都拥有一份独立的、与其他对象隔离的只读数据。
*   **运行时求值**：与常量 (`const`) 的编译期替换不同，只读字段的值是在**程序运行时 (Runtime)** 确定的。这意味着你可以使用动态生成的数据（如当前系统时间、方法的返回值、复杂的计算结果）来初始化它。

## 严格的初始化规则

只读字段的赋值权限被严格限制在以下两个位置。除了这两个地方，任何试图修改 `readonly` 字段的代码都会导致编译报错：

1.  **声明时直接初始化 (Inline Initialization)**：在定义字段的同一行赋初始值。
2.  **类的构造函数中 (Constructor)**：这是 `readonly` 字段最常用的初始化场所。在构造函数执行完毕之前，你可以多次修改 `readonly` 字段的值。但一旦构造函数的大括号 `}` 结束，该字段就彻底被“锁定”。

*注意：`readonly` 只能用于类的字段级别，不能在方法内部声明为局部变量（这与 `const` 不同）。*

## 代码实现与最佳实践

下面的代码展示了如何使用构造函数来初始化只读字段，并展示了如何通过**带参数的构造函数**，让不同的对象拥有不同的只读属性。

### 类的内部定义
```csharp
using System;

namespace ClassLibrary1
{
    public class Product
    {
        // 普通实例字段
        public string productName;

        // 只读字段声明
        public readonly string DateOfPurchase;
        public readonly string SerialNumber;

        // 无参构造函数
        public Product()
        {
            // 运行时动态获取当前时间，这是 const 做不到的
            DateOfPurchase = DateTime.Now.ToShortDateString();
            SerialNumber = "DEFAULT-0000";
        }

        // 扩展知识：带参数的构造函数
        // 这展示了只读字段最大的魅力：每个对象在创建时可以被赋予不同的只读值
        public Product(string targetSerialNumber)
        {
            DateOfPurchase = DateTime.Now.ToShortDateString();
            
            // 将外部传入的参数赋值给只读字段
            SerialNumber = targetSerialNumber;
            
            // 在构造函数内部，甚至可以多次赋值（尽管不常见）
            // SerialNumber = targetSerialNumber + "-VERIFIED"; 
        }

        public void AttemptToModify()
        {
            // DateOfPurchase = "2023-01-01"; // 编译错误！构造函数外绝对不允许修改
        }
    }
}
```

### 类外部的调用
因为是实例字段，外部必须通过**对象引用变量**来访问它。

```csharp
using System;
using ClassLibrary1;

namespace FieldsExample
{
    class Program
    {
        static void Main(string[] args)
        {
            // 使用无参构造函数
            Product p1 = new Product();
            Console.WriteLine("P1 Date: " + p1.DateOfPurchase);
            Console.WriteLine("P1 Serial: " + p1.SerialNumber);

            // 使用带参构造函数：赋予独一无二的只读值
            Product p2 = new Product("SN-998877");
            Console.WriteLine("P2 Date: " + p2.DateOfPurchase);
            Console.WriteLine("P2 Serial: " + p2.SerialNumber);

            // p2.SerialNumber = "NEW-SN"; // 编译错误！外部无法修改只读字段
            
            Console.ReadLine();
        }
    }
}
```

## 深度解析：四大字段类型对比矩阵

在实际工程设计中，选择正确的字段修饰符是衡量代码质量的重要标准。

| 特性 | 普通实例字段 | 静态字段 (`static`) | 常量 (`const`) | 只读字段 (`readonly`) |
| :--- | :--- | :--- | :--- | :--- |
| **数据归属** | 每个对象独有 | 所有对象共享 (类级别) | 所有对象共享 (类级别) | 每个对象独有 (默认) |
| **内存位置** | 堆内存 (对象内部) | 堆内存 (类内存区域) | 无分配 (编译期直接替换) | 堆内存 (对象内部) |
| **求值时机** | 运行时 | 运行时 | **编译期** | 运行时 |
| **赋值限制** | 随时随地可改 | 随时随地可改 | 仅限声明时，且必须是字面量 | **仅限声明时或构造函数中** |

## 进阶知识补充

### `static readonly` (静态只读字段)
如果一个数据既需要**被所有对象共享**，又需要**在运行时动态计算得出**（例如从配置文件中读取一个连接字符串，并且以后不准改），单纯的 `const` 或 `readonly` 都无法满足需求。
此时应组合使用：`public static readonly string ConnectionString;`
*   它只能在**静态构造函数 (Static Constructor)** 或声明时初始化。
*   它是实际开发中替代 `const` 的首选方案，因为它避免了跨程序集引用时的“硬编码替换”问题。

### `readonly` 的“浅层不可变性”陷阱
这是一个极容易踩坑的高级知识点。`readonly` 保证的是**引用的不可变**，而不是**对象内部状态的不可变**。

如果一个只读字段是**引用类型**（比如数组、集合或自定义类）：
```csharp
public class ShoppingCart
{
    // readonly 保证了 Items 变量永远指向内存中的这一个 List 实例
    public readonly List<string> Items = new List<string>();

    public ShoppingCart()
    {
        // Items = new List<string>(); // 构造函数内可以重新分配
    }

    public void AddItem()
    {
        // 编译通过！完全合法！
        // 我们没有修改 Items 的引用地址，只是修改了该集合内部的状态
        Items.Add("Laptop"); 
        
        // Items = new List<string>(); // 编译错误！试图修改引用地址
    }
}
```
**结论**：`readonly` 阻止你将变量指向一个新的对象，但**不阻止**你调用该对象内部的方法来修改其自身的数据。如果需要绝对的深度不可变集合，应该使用 C# 的 `IReadOnlyCollection` 或 `ReadOnlyCollection<T>` 类型。
