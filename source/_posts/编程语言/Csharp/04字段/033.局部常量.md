# 局部常量

## 核心概念：什么是局部常量？

在上一节探讨常量字段 (Constant Fields) 时，常量是声明在**类级别 (Class Level)** 的。而 **局部常量 (Local Constants)** 是声明在**方法内部 (Method Body)** 的常量。

*   **作用域限制**：局部常量的生命周期和可见性被严格限制在声明它的特定方法（或代码块）内部。一旦离开该方法，这个常量就不复存在，外部代码也绝对无法访问它。
*   **用途**：当某个固定值只在特定的计算过程或特定的方法逻辑中使用，不需要暴露给整个类或类的实例时，使用局部常量是最佳选择，这有助于缩小变量作用域，保持代码的整洁。

## 语法规则与特性

声明局部常量的语法和规则与常量字段有一些关键的区别：

1.  **禁止使用访问修饰符**：
    *   在声明常量字段时，可以使用 `public`、`private` 等。
    *   声明局部常量时，**绝不允许**使用任何访问修饰符。因为局部变量本身就受到方法作用域的保护，天生就是“私有”于该方法的。
2.  **必须立即初始化**：
    *   使用 `const` 关键字声明的同时，必须赋予初始的字面量 (Literal Value)。
3.  **绝对不可变**：
    *   在方法后续的任何代码中，试图重新给局部常量赋值都会导致编译失败。

## 数据类型与底层限制 (深度解析)

无论是常量字段还是局部常量，C# 对它们的数据类型都有极其严苛的限制：**只能是内置的原始值类型 (Primitive Types, 如 int, double, bool 等) 或者是 `string` 类型。**

**为什么不能是自定义的类对象 (Reference Types)？**

*   **编译期决定 vs 运行期决定**：`const` 的核心机制是**编译期直接替换**。编译器必须在将代码转换为中间语言 (IL) 之前，确切知道这个常量的具体值。
*   **对象的本质**：当我们使用 `new` 关键字创建一个类对象时（例如 `new Product()`），这个对象是在程序**运行期 (Runtime)** 在堆内存中动态分配的。编译器在编译阶段无法预知这个对象的内存地址或内部状态。
*   **唯一例外**：如果非要将引用类型声明为 `const`，它唯一允许被赋予的值是 `null`（字符串 `string` 除外，因为字符串在 C# 中具有特殊的驻留池机制，可以在编译期确定）。

## 代码示例与对比分析

以下代码展示了常量字段与局部常量的区别，以及在使用局部常量时常见的合法与非法操作。

```csharp
using System;

namespace LocalConstantsDemo
{
    // 定义一个普通的类用于测试
    public class Product
    {
        public string Name;
    }

    class Program
    {
        // 1. 常量字段 (Constant Field)：声明在类级别，可使用访问修饰符
        public const string AppVersion = "v1.0.0";

        static void Main(string[] args)
        {
            // 2. 局部常量 (Local Constant)：声明在方法内部，没有 public/private
            const string developerName = "Alice";
            const double taxRate = 0.08;

            // ---- 合法操作 ----
            // 可以多次读取并使用局部常量
            double price = 100.0;
            double finalPrice = price + (price * taxRate);
            
            Console.WriteLine("Developer: " + developerName);
            Console.WriteLine("Final Price: " + finalPrice);

            // ---- 非法操作 (会导致编译错误) ----
            
            // 错误 1：未在声明时初始化
            // const int maxUsers; 
            
            // 错误 2：试图修改局部常量的值
            // developerName = "Bob"; 
            
            // 错误 3：试图将实例化对象赋值给常量 (引用类型不能为 const)
            // const Product myProduct = new Product(); 

            // 特例：引用类型常量只能赋值为 null
            const Product emptyProduct = null; 
        }

        static void AnotherMethod()
        {
            // developerName 和 taxRate 在这里是不可见的
            // 局部常量的作用域仅限于 Main 方法内部
        }
    }
}
```

## 进阶认知：局部常量的内存占用

从内存分配的底层逻辑来看，局部常量与普通的局部变量 (Local Variables) 截然不同。

普通的局部变量在方法执行时，会被压入线程的**栈内存 (Stack)** 中。但是，由于局部常量使用了 `const`，触发了编译器的**硬编码替换机制**。

当上述代码被编译为 MSIL（微软中间语言）时，`developerName` 这个变量名会被直接抹除，底层的指令会变成直接打印 `"Alice"` 这个字符串字面量。因此，**局部常量在运行时通常不会在栈内存中占据额外的变量空间**，这使得它的执行效率极高。它更多的是作为一种“提升代码可读性”的工具，避免在代码中到处散落难以理解的“魔法数字 (Magic Numbers)”或硬编码字符串。
