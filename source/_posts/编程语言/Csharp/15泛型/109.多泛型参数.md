# 多泛型参数

## 为什么需要多泛型参数？

单泛型参数（如 `class User<T>`）能够极大地提升代码的复用性，但在复杂的业务模型中，一个类往往包含多个不同维度的状态或行为，它们的数据类型可能相互独立。

为了赋予类更加极致的灵活性，C# 允许在一个泛型声明中定义**两个或更多**的泛型参数（只需使用逗号分隔）。每个参数代表一个独立可变的类型占位符。

## 经典业务场景实战

一个非常实用的场景：用户注册信息模型。
*   **注册状态 (Registration Status)**：可能需要存储精准的应用程序编号（`int`），也可能仅仅是一个表示是否注册过的布尔标志（`bool`）。
*   **用户年龄 (Age)**：可能需要存储精确的年龄数值（`int`），也可能因为隐私原因只收集了年龄段范围，需要以字符串形式存储（`string`，如 "35-40"）。

这两个维度的类型变化没有任何必然联系。因此，我们需要使用双泛型参数来实现。

### 代码示例：双泛型参数类

```csharp
using System;

// 声明带有两个泛型参数的类：T1 和 T2
// 根据命名规范，更专业的命名应该是 TStatus, TAge
public class User<T1, T2>
{
    public string UserName { get; set; }
    
    // T1 用于注册状态的类型
    public T1 RegistrationStatus { get; set; }
    
    // T2 用于年龄的类型
    public T2 Age { get; set; }

    public void PrintDetails()
    {
        Console.WriteLine($"Name: {UserName}, Status: {RegistrationStatus}, Age: {Age}");
    }
}
```

### 实例化与类型绑定

在实例化多泛型参数类时，必须按照泛型参数**在尖括号中声明的顺序**，依次提供具体的类型。

```csharp
public class Program
{
    public static void Main()
    {
        // 场景 1：精准数据收集 (状态为编号 int，年龄为精准数值 int)
        // 这里的 <int, int> 分别替换了 <T1, T2>
        User<int, int> preciseUser = new User<int, int>();
        preciseUser.UserName = "Alice";
        preciseUser.RegistrationStatus = 88001;
        preciseUser.Age = 25;
        preciseUser.PrintDetails();

        // 场景 2：模糊数据收集 (状态为布尔标志 bool，年龄为范围字符串 string)
        // 这里的 <bool, string> 分别替换了 <T1, T2>
        User<bool, string> fuzzyUser = new User<bool, string>();
        fuzzyUser.UserName = "Bob";
        fuzzyUser.RegistrationStatus = false;
        fuzzyUser.Age = "35-40";
        fuzzyUser.PrintDetails();
    }
}
```

## BCL (基类库) 中的多泛型经典代表

在 .NET 框架的核心库中，多泛型参数被极其广泛地使用。理解多泛型参数是精通 C# 集合和委托的前提。

### 字典结构 (`Dictionary<TKey, TValue>`)
最著名的多泛型类莫过于哈希表字典。键（Key）和值（Value）的类型完全独立。
```csharp
// 键为 string，值为 int
Dictionary<string, int> ages = new Dictionary<string, int>();
ages.Add("Scott", 30);
```

### 泛型委托 (`Func<>` 与 `Action<>`)
C# 提供的高级泛型委托最多支持 16 个输入参数。
```csharp
// 接收两个泛型输入参数 T1, T2，并返回一个泛型结果 TResult
// Func<T1, T2, TResult>
Func<int, double, string> formatData = (count, price) => $"总计: {count * price}";
```

## 架构规范的建议

在设计自己的多泛型类时，应遵循微软官方的框架设计准则：

1.  **见名知意**：不要随意使用 `T1, T2, T3` 这种毫无意义的名称。如果一个类有多个泛型参数，必须给它们赋予描述性的名字。例如 `User<TStatus, TAge>` 远比 `User<T1, T2>` 更具可读性和可维护性。
2.  **避免过度泛型化**：泛型参数越多，调用方在实例化该类时的认知负担就越重。如果一个类的泛型参数超过 3 个，通常意味着该类承担了过多的职责，违背了单一职责原则（SRP），应当考虑对其进行重构或拆分。
