# 第16节：泛型

## 第一讲：泛型类

### 引言
**泛型**是 C#语言中最强大且最重要的特性之一。它允许您设计带有数据类型占位符（T）的类、接口和方法。这个占位符稍后由使用您代码的开发人员指定，使他们能够创建**类型安全且高性能**的数据结构，同时不牺牲可重用性。

要理解泛型为何如此关键，我们必须看看它们解决了什么问题。在泛型出现之前，创建可重用集合的唯一方法是使用 System.Object。例如，旧的 ArrayList 将所有内容存储为 object。这导致了两个主要问题：
1. **缺乏类型安全性**： 你可以向 ArrayList 添加任何类型的数据。可以先添加一个整数，然后添加一个字符串，再添加一个 Car 对象。之后在检索元素时，必须进行显式类型转换，并希望转换类型正确。这经常导致运行时出现 InvalidCastException 错误。
2. **性能低下（装箱问题）**： 当向 ArrayList 添加值类型（如 int 或 double）时，必须进行装箱操作（在堆上包装成对象）。检索时又需要进行拆箱操作。正如我们所知，这些操作计算开销大，会给垃圾回收器带来压力。

泛型优雅地解决了这两个问题。

### 工作原理：类型参数与 JIT 特化
通过类名后添加尖括号中的类型参数来创建泛型类。字母 T 是表示"类型"的常规占位符。

**语法**：`public class MyList<T> { ... }`

当开发者使用你的泛型类时，他们会指定具体类型，从而创建所谓的**封闭泛型类型**：`MyList<int>` 或 `MyList<string>`。

随后.NET 即时(JIT)编译器会执行特化过程：
- 对于**值类型**（如 int、double、struct），JIT 编译器会专门为该值类型创建一个全新且高度优化的类版本。`MyList<int>` 会生成一个将所有 T 替换为 int 的类，完全避免了装箱或拆箱操作。
- 对于**引用类型**（string、Car 等），JIT 能够为它们复用同一个底层实现，因为所有引用的大小都相同。

### 示例：可复用的仓储类
让我们创建一个简单的泛型 `Repository<T>` 类，它可以存储和检索任何类型的数据实体。

```csharp
// 'T' 是一个占位符，表示此仓储要处理的任意类型。
public class Repository<T>
{
    private List<T> _items = new List<T>();

    public void Add(T item)
    {
        _items.Add(item);
    }

    public T GetById(int index)
    {
        return _items[index];
    }
}

public class Employee { public string Name { get; set; } }
public class Product { public string Sku { get; set; } }

// --- 在 Main 方法中 ---
// 1. 创建专门用于 Employee 对象的仓储。
Repository<Employee> employeeRepo = new Repository<Employee>();
employeeRepo.Add(new Employee { Name = "John Doe" });
// employeeRepo.Add(new Product()); // 错误！编译器强制类型安全。

// 2. 创建另一个专门用于 Product 对象的仓储。
Repository<Product> productRepo = new Repository<Product>();
productRepo.Add(new Product { Sku = "XYZ-123" });

// 我们同时实现了类型安全和代码可重用性。
```

## 第二讲：多重泛型参数

### 引言
泛型类或方法并不局限于单一类型参数。当类需要处理多种类型的组合时，你可以为不同类型定义多个占位符。

### 工作原理：逗号分隔的类型参数
通过在尖括号内列出多个类型参数并用逗号分隔，可以声明多个类型参数。按照惯例，通常使用字母 T、U、V，或者更具描述性的名称如 TKey 和 TValue。

**语法**：`public class MyClass<T, U> { ... }`

### 为何及何时使用
在创建需要自然配对或关联两个及以上不同类型（这些类型可能互不相关）的类时，应使用多个泛型参数。.NET 框架中最著名的例子是 `Dictionary<TKey, TValue>`，它需要一个泛型类型表示键，另一个表示值。

### 示例：简单的 Pair 类
让我们创建一个能容纳任意两个项目的泛型 Pair 类。

```csharp
// 此类使用两个类型参数：TFirst 和 TSecond。
public class Pair<TFirst, TSecond>
{
    public TFirst First { get; set; }
    public TSecond Second { get; set; }

    public Pair(TFirst first, TSecond second)
    {
        this.First = first;
        this.Second = second;
    }
}

// --- 在 Main 方法中 ---
// 创建一个字符串和整数的配对。
Pair<string, int> nameAndAge = new Pair<string, int>("Alice", 30);
Console.WriteLine($"Name: {nameAndAge.First}, Age: {nameAndAge.Second}");

// 创建一个 Employee 对象和双精度浮点数的配对。
Employee emp = new Employee { Name = "Bob" };
Pair<Employee, double> employeeAndSalary = new Pair<Employee, double>(emp, 75000.50);
Console.WriteLine($"Employee: {employeeAndSalary.First.Name}, Salary: {employeeAndSalary.Second}");
```

## 第三讲：泛型约束

### 引言
**约束**是应用于泛型类型参数的规则，用于限制可用于泛型类或方法的类型。若无约束，编译器对类型参数 T 的唯一假设是其派生自 System.Object。这意味着你只能在 T 上调用 System.Object 中定义的方法（如 ToString()、Equals() 等）。

约束为编译器提供了关于 T 能力的更多信息，从而允许你调用其特定方法或访问特定属性。

### 工作原理：where 子句
通过在泛型类型参数列表后使用 where 关键字来应用约束。

**语法**：`public class MyClass<T> where T : ...`

### 常见的约束类型
- `where T : class`：类型参数必须是引用类型（类、接口、委托或数组）。
- `where T : struct`：类型参数必须是非空值类型（int、double、bool 或自定义 struct）。
- `where T : new()`：类型参数必须具有公共的无参数构造函数。这允许你在泛型类中创建 T 的新实例（`new T()`）。此约束必须位于约束列表的最后。
- `where T : <base class name>`：类型参数必须是指定的基类或派生自该基类。这允许你在 T 上安全地使用该基类的所有公共成员。
- `where T : <interface name>`：类型参数必须实现指定的接口。这是最常见且强大的约束之一，因为它允许你在 T 上调用该接口的方法。

### 示例：约束到接口
让我们创建一个通用的报告服务，该服务可以从任何对象生成报告，只要该对象具有 Name 属性。我们可以通过接口来强制执行这一要求。

```csharp
// 1. 定义契约（接口）。
public interface IEntityWithName
{
    string Name { get; }
}

// 2. 创建一些实现该接口的类。
public class Product : IEntityWithName
{
    public string Name { get; set; }
    public decimal Price { get; set; }
}
public class Customer : IEntityWithName
{
    public string Name { get; set; }
    public int Id { get; set; }
}

// 3. 创建带约束的泛型类。
public class ReportGenerator<T> where T : IEntityWithName
{
    public void GenerateReport(T item)
    {
        // 由于约束的存在，编译器知道 'item'
        // 会有 'Name' 属性，因此此代码是安全的。
        Console.WriteLine($"--- Report for {item.Name} ---");
        // ... 更多报告逻辑 ...
    }
}

// --- 在 Main 方法中 ---
var generator = new ReportGenerator<Product>();
generator.GenerateReport(new Product { Name = "Laptop", Price = 1200 });

// 这会导致编译器错误，因为 'int' 未实现 IEntityWithName。
// var intGenerator = new ReportGenerator<int>(); // 错误！
```

## 第四讲：泛型方法

### 引言
**泛型方法**是指声明了自身类型参数的方法。这使得单个方法能够对多种不同的数据类型执行相同的操作，同时仍保持完整的类型安全性。一个关键特性是泛型方法可以存在于非泛型类中。

### 工作原理：语法与类型推断
通过在方法名后紧接尖括号内放置类型参数来声明泛型方法。

**语法**：`access_modifier return_type MethodName<T>(T parameter) { ... }`

泛型方法最强大的特性之一是**类型推断**。在大多数情况下，C#编译器足够智能，能够从传递给方法的参数中推导出类型 T。这意味着在调用方法时，通常不需要在尖括号中显式指定类型。

### 为何及何时使用
当需要一个独立、通用的工具函数来执行不依赖特定数据类型的操作时，应使用泛型方法。这非常适合诸如交换、排序或比较项目等通用操作。经典的教科书示例就是 Swap 方法。

### 示例：可复用的 Swap 方法
若不使用泛型，您需要为整型、字符串、双精度浮点数等分别编写单独的 Swap 方法。而通过泛型方法，只需编写一次即可。

```csharp
public class Utilities
{
    // 这是一个泛型方法。'T' 可以是任何类型。
    public static void Swap<T>(ref T a, ref T b)
    {
        Console.WriteLine($"Swapping items of type: {typeof(T).Name}");
        T temp = a;
        a = b;
        b = temp;
    }
}

// --- 在 Main 方法中 ---
// --- 交换整数 ---
int x = 5;
int y = 10;
Console.WriteLine($"Before: x={x}, y={y}");
// 调用 Swap，而非 Swap<int>。编译器推断 T 是 int。
Utilities.Swap(ref x, ref y);
Console.WriteLine($"After: x={x}, y={y}");

Console.WriteLine("--------------------");

// --- 交换字符串 ---
string s1 = "Hello";
string s2 = "World";
Console.WriteLine($"Before: s1={s1}, s2={s2}");
// 此处编译器推断 T 是 string。
Utilities.Swap(ref s1, ref s2);
Console.WriteLine($"After: s1={s1}, s2={s2}");
```

**输出结果**：
```
Before: x=5, y=10
Swapping items of type: Int32
After: x=10, y=5
--------------------
Before: s1=Hello, s2=World
Swapping items of type: String
After: s1=World, s2=Hello
```

## 第五讲：重要知识点备忘

### 引言
本讲座整合了关于泛型最核心、最实用且最具面试价值的知识点。掌握这些概念能体现你对 C#的专业级理解。

### 泛型解决的两大核心问题
这是最重要的知识点，也是回答面试问题"C#为何需要泛型？"的理想答案。
- **类型安全**： 泛型将类型检查从运行时转移到了编译时。当你使用 `List<string>` 时，编译器会确保只能添加字符串，从而避免了在旧式非泛型集合中常见的 InvalidCastException 错误。
- **性能**： 泛型消除了在处理值类型（int、double、struct 等）时对装箱和拆箱的需求。`List<int>` 直接存储整数，而旧的 ArrayList 必须将每个整数"装箱"为堆上的对象，导致显著的性能下降和垃圾回收器的压力。

### `List<T>` 对比 `ArrayList`：经典示例
这个对比是解释泛型优势的典型方式。
- **ArrayList（旧式，非泛型）**：
  - 将所有内容存储为 object 类型。
  - 非类型安全： 可能会错误地将 int 和 string 添加到同一个列表中。
  - 需要类型转换： 取出元素时必须显式转换回原始类型，存在运行时错误风险。
  - 导致装箱操作： 对值类型会产生性能损耗。
- **`List<T>`（现代泛型实现）**：
  - 存储特定类型 T。
  - 类型安全： 编译器强制要求只能添加类型为 T 的项。
  - 无需类型转换： 检索项时，它已经是 T 类型。
  - 高性能： 值类型不会发生装箱操作。

> 在现代 C#代码中，应始终使用 `List<T>` 和其他泛型集合（`Dictionary<TKey, TValue>`、`Queue<T>` 等）。

### 约束条件解锁功能
请记住，当你的方法需要做的不仅仅是存储或传递数据时，就需要对泛型类型参数使用**约束**（`where T : ...`）。当你需要调用方法或访问属性时，就需要使用约束。最常见的约束包括：
- `where T : IMyInterface`：允许你调用 IMyInterface 中定义的方法。
- `where T : MyBaseClass`：允许你使用 MyBaseClass 中的成员。
- `where T : new()`：允许使用 `new T()` 创建该类型的新实例。

### 泛型方法 vs 泛型类
使用以下准则来决定创建哪种类型：
- **泛型类**： 当整个类被设计为特定占位类型的容器或管理器时使用。类的状态（其字段和属性）依赖于 T。例如：`List<T>`、`Repository<T>`。
- **泛型方法**： 适用于独立的工具函数，可对任意类型执行操作，且包含该方法的类本身不需要是泛型类。例如：`Swap<T>()`、`Sort<T>()`。

### 开放与封闭泛型类型（高级面试考点）
掌握这些术语能体现更深层次的理解。
- **开放泛型类型**： 类型定义中仍保留占位符的状态。无法创建开放类型的实例。例如：`typeof(List<>)`。
- **封闭泛型类型**： 已为占位符提供特定类型参数的类型。这是可以实例化的类型。示例：`typeof(List<int>)`。
