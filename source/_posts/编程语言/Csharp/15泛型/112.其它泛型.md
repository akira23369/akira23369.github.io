在 C# 中，泛型的应用范围远不止于**类 (Class)** 和**方法 (Method)**。由于泛型是在 CLR（公共语言运行时）底层原生支持的，它几乎渗透到了 C# 类型系统的每一个角落。

除了类和方法，C# 还支持以下几种重要的泛型结构。深入理解它们是编写高性能、类型安全代码的关键。

---

### 泛型接口

泛型接口允许我们为未知的类型定义统一的契约。在 .NET Framework 的早期版本（泛型引入之前），像 `IComparable` 这样的接口接收的都是 `object` 类型的参数。这导致在处理值类型（如 `int`, `struct`）时会发生严重的**装箱和拆箱 (Boxing/Unboxing)**，且缺乏编译期类型安全。

引入泛型后，`.NET` 提供了泛型版本的接口，如 `IComparable<T>`、`IEnumerable<T>`、`IEquatable<T>`。

**核心优势与代码解析：**
根据《Effective C#》的建议，**所有的值类型都应该实现 `IEquatable<T>` 接口**。这能彻底消除比较值类型时的装箱操作。

```csharp
// 泛型接口的定义
public interface IRepository<T>
{
    void Add(T entity);
    T GetById(int id);
}

// 泛型接口的实现：可以明确指定具体类型
public class UserRepository : IRepository<User>
{
    public void Add(User entity) { /* 具体的数据库插入逻辑 */ }
    public User GetById(int id) { return new User(); }
}

// 也可以由泛型类继续传递泛型参数
public class GenericRepository<T> : IRepository<T>
{
    public void Add(T entity) { /* 通用逻辑 */ }
    public T GetById(int id) { return default; }
}
```

**底层补充（协变与逆变）：**
《C# in Depth》中详细剖析了泛型接口独有的特性——**协变 (Covariance, `out T`)** 和 **逆变 (Contravariance, `in T`)**。
例如 `IEnumerable<out T>` 允许你将 `IEnumerable<string>` 赋值给 `IEnumerable<object>`，这在非泛型或普通泛型类中是无法做到的，极大增强了多态的灵活性。

### 泛型委托

委托本质上是类型安全的函数指针。泛型委托允许我们定义能够匹配各种参数类型和返回值类型的方法签名。

现今的 C# 开发中，我们很少再使用 `delegate` 关键字去自定义委托，因为 .NET BCL（基础类库）已经内置了极其强大的三大泛型委托：
*   **`Action<T1, T2...>`**：表示没有返回值的方法。
*   **`Func<T1, T2..., TResult>`**：表示有返回值的方法（最后一个泛型参数始终是返回值类型）。
*   **`Predicate<T>`**：专门用于返回 `bool` 值的条件判断。

**代码解析：**

```csharp
public class DataProcessor
{
    // 接收一个 Func 泛型委托作为参数，允许调用者自定义转换逻辑
    public TOutput Process<TInput, TOutput>(TInput input, Func<TInput, TOutput> transformer)
    {
        // 执行传入的方法
        return transformer(input);
    }
}

// 调用端：
var processor = new DataProcessor();
// 传入 lambda 表达式，编译器会自动推断 TInput 为 int, TOutput 为 string
string result = processor.Process(100, num => $"The number is {num}");
```

### 泛型结构体

不仅引用类型（Class）可以泛型化，值类型（Struct）同样可以。泛型结构体在内存布局上极为紧凑，完全分配在栈（Stack）上或内联在对象中，没有任何堆对象的额外开销。

最经典的泛型结构体是 **`Nullable<T>`**。在 C# 中，值类型（如 `int`, `DateTime`）不能为 null。为了解决数据库中可能存在的 null 值问题，C# 引入了可空值类型 `int?`，它在底层的真面目其实就是 `Nullable<int>` 这个泛型结构体。

另一个现代 C# 极常用的泛型结构体是 **`ValueTuple<T1, T2...>`**（元组），用于方法返回多个值。

**代码解析：**

```csharp
// 自定义一个简单的泛型结构体
public struct ResultValue<T>
{
    public T Value { get; }
    public bool HasValue { get; }

    public ResultValue(T value)
    {
        Value = value;
        HasValue = true;
    }
}
```
**底层补充：**
《CLR via C#》指出，当使用泛型结构体（如 `ResultValue<int>` 和 `ResultValue<double>`）时，JIT 编译器会在运行时为每一种泛型参数生成完全不同的本机代码。这意味着泛型结构体拥有与手写非泛型代码绝对一致的极致性能。

### 泛型记录-*C# 9.0 及更高版本*

`record` 是 C# 引入的旨在简化不可变数据模型（Immutable Data Models）的新引用类型，它天生自带基于值的相等性比较。`record` 同样可以与泛型完美结合。

在处理 API 响应、领域驱动设计（DDD）的值对象或 CQRS 的命令/查询对象时，泛型 Record 是最佳选择。

**代码解析：**

```csharp
// 定义一个泛型 Record 用于统一 API 返回格式
public record ApiResponse<T>(bool IsSuccess, string Message, T Data);

// 使用泛型 Record
var user = new User { Name = "Alice" };
var response = new ApiResponse<User>(true, "Success", user);

// Record 自带解构 (Deconstruct) 和基于值的 ToString() 输出
Console.WriteLine(response); 
// 输出类似于: ApiResponse`1 { IsSuccess = True, Message = Success, Data = User { ... } }
```

### 总结归纳

纵观整个 C# 类型系统，泛型几乎是“全能”的：
1.  **类 (Class) / 记录 (Record)**：封装泛型数据模型和业务逻辑。
2.  **方法 (Method)**：提供操作特定泛型类型参数的独立逻辑单元。
3.  **接口 (Interface)**：定义跨类型的泛型契约，支持协变与逆变。
4.  **委托 (Delegate)**：实现泛型化的回调机制和高阶函数（LINQ 的基石）。
5.  **结构体 (Struct)**：提供无内存开销的高性能泛型值类型（如 `Nullable<T>`, `ValueTuple`）。
