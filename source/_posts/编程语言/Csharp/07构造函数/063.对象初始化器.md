# C# 对象初始化器

## 核心概念与本质底层机制
对象初始化器（Object Initializer）是 C# 提供的一种声明式语法，允许在创建对象实例时，以极其简洁、直观的方式直接为对象的可访问字段（Fields）或属性（Properties）赋值。

在《C# in Depth》（Jon Skeet 著）中深入解析过，**对象初始化器本质上是编译器的“语法糖”（Syntactic Sugar）**。它并不产生任何新的 CLR 底层指令。当编写对象初始化器代码时，C# 编译器在后台会将其转换为标准的对象实例化步骤，然后逐一进行赋值操作。

## 严格的执行顺序

![](063.对象初始化器/file-20260319092614248.png)
对象初始化器**绝对不是构造函数的替代品**，而是构造函数的补充。其执行顺序有着极其严格的界定：
1.  **触发构造函数**：首先，根据 `new` 关键字后面指定的签名，调用匹配的实例构造函数（无论是无参还是参数化构造函数）。
2.  **执行构造逻辑**：构造函数内部的逻辑（包含硬编码的默认赋值）被完整执行。
3.  **执行初始化器**：构造函数执行完毕后，对象初始化器 `{ }` 块内的赋值语句按代码编写的顺序逐一执行。

**覆盖原则**：如果构造函数内部给某个字段赋了值，而对象初始化器中也给同一个字段赋了值，那么初始化器中的值将**覆盖**构造函数赋予的值，因为初始化器总是后执行的。

## 解决的核心痛点：避免“伸缩式构造函数反模式”
在《代码大全》和面向对象设计原则中，有一个常见的反模式叫作**伸缩式构造函数（Telescoping Constructors）**。
假设一个 `BankAccount` 或 `Employee` 类有 10 个字段，调用者可能只想初始化其中的第 3 个和第 7 个字段，也可能想初始化第 1、4、5 个字段。如果试图通过**构造函数重载**来满足所有这些组合，会导致类中出现无数个毫无意义的构造函数。

对象初始化器完美解决了这个问题：**类只需提供一个基础的构造函数，调用者在实例化时，通过对象初始化器按需、灵活地选择要赋值的字段即可。**

## 语法与代码示例
使用对象初始化器时，如果调用的是无参构造函数，甚至可以**省略括号 `()`**，使代码更加极简。

```csharp
public class Employee
{
    public int EmpId;
    public string EmpName;
    public string Job;

    // 无参构造函数
    public Employee()
    {
        EmpId = 1; // 默认值
    }

    // 参数化构造函数
    public Employee(int empId)
    {
        this.EmpId = empId;
    }
}

class Program
{
    static void Main()
    {
        // 场景 1：调用无参构造函数 + 对象初始化器（可省略小括号）
        // 执行顺序：先执行 Employee() 将 EmpId 设为 1，然后初始化器赋值 EmpName 和 Job
        Employee emp1 = new Employee { EmpName = "Scott", Job = "Manager" };

        // 场景 2：调用无参构造函数 + 对象初始化器（保留小括号）
        // 如果想覆盖构造函数里的默认值，可以直接在初始化器里写明
        Employee emp2 = new Employee() { EmpId = 102, EmpName = "Alan" };

        // 场景 3：调用参数化构造函数 + 对象初始化器
        // 结合使用：用构造函数传入核心标识，用初始化器设置可选数据
        Employee emp3 = new Employee(103) { EmpName = "Smith", Job = "Developer" };
    }
}
```

## 现代 C# 的关键补充 (C# 9.0 ~ C# 13)
虽然传统的对象初始化器非常灵活，但它要求字段或属性必须是 `public` 且可写的（有 `set` 访问器），这破坏了对象的**不可变性（Immutability）**。为了解决这个矛盾，现代 C# 对对象初始化器做出了两大重量级升级：

### `init` 访问器 (C# 9.0 引入)
使用 `init` 关键字替代传统的 `set`。被标记为 `init` 的属性，**只能在对象初始化器中被赋值**。一旦初始化块执行完毕，该属性就变成了只读的。这完美结合了初始化器的便利性与对象状态的安全性。

```csharp
public class Person
{
    public int Id { get; init; } // 只能在对象初始化器中赋值
    public string Name { get; set; }
}

// 合法
Person p = new Person { Id = 101, Name = "Alice" };
// 报错：Id 是 init-only，实例化后无法再次更改
// p.Id = 102; 
```

### `required` 修饰符 (C# 11 引入)
传统的对象初始化器是“可选的”，开发者可能会忘记初始化某些关键字段。在 C# 11 中，可以在字段或属性前加上 `required` 关键字，**强制要求调用者在使用对象初始化器时必须为该成员赋值**，否则编译器将直接报错。

```csharp
public class Configuration
{
    // 强制调用者在使用 new 时，必须在初始化器中给 ConnectionString 赋值
    public required string ConnectionString; 
    public int Timeout = 30; // 可选，有默认值
}

// 报错：必须初始化 ConnectionString
// Configuration config1 = new Configuration(); 

// 完美编译
Configuration config2 = new Configuration { ConnectionString = "Server=myServer..." };
```
