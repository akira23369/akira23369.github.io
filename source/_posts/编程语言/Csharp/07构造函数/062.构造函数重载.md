# C# 构造函数重载

## 核心概念与设计目的
构造函数重载是指在同一个类中定义多个实例构造函数。
从面向对象设计的角度来看，重载构造函数的主要目的是**为调用者（类的使用者）提供高度的灵活性**。在真实的项目场景中，实例化一个对象时所拥有的上下文数据往往是不同的：
*   有时拥有完整的数据（全量初始化）。
*   有时只有部分关键数据（部分初始化，其余数据留空或设为默认值）。
*   有时没有任何数据（创建一个具有默认状态的空对象，后续再逐步赋值）。

通过构造函数重载，类可以优雅地适配这些不同的初始化需求。

## 构造函数重载的签名规则
与普通方法重载一样，构造函数重载的核心前提是**方法签名必须不同**。
编译器在解析 `new` 关键字后面的代码时，会严格根据传入的参数列表来决定调用哪一个构造函数。签名的差异体现在：
*   参数的**数量**不同。
*   参数的**数据类型**不同。
*   参数类型的**声明顺序**不同。

*注：参数的名称不同不能构成重载。*

## 未初始化字段的底层行为
当调用一个接收较少参数的重载构造函数时（例如只传入了 `empId` 和 `empName`，没有传入 `job`），未被显式初始化的字段会自动保持为其类型的**默认值**。
正如《CLR via C#》中所述，当使用 `new` 实例化对象时，CLR 会首先将分配的内存块全部清零。因此：
*   对于引用类型（如 `string` 类），未赋值的字段默认为 `null`。
*   对于数值类型（如 `int`），未赋值的字段默认为 `0`。
*   对于布尔类型（如 `bool`），默认为 `false`。

如果业务上要求这些留空的字段不能为默认值，开发者必须在对象创建后，手动通过对象实例去为这些字段赋值。

## 进阶最佳实践：构造函数链
在实现多个构造函数重载时，初学者常常会在每个构造函数中重复编写赋值代码。**《Effective C#》强烈建议避免这种做法，因为这违背了 DRY (Don't Repeat Yourself) 原则**，增加了代码维护的成本。

**最佳实践**是使用 `this` 关键字实现**构造函数链**。
将包含最多参数的构造函数作为“主构造函数（Master Constructor）”，其他参数较少的构造函数通过 `: this(...)` 语法，将默认值或接收到的参数传递给主构造函数执行。这样所有的初始化逻辑都集中在一个地方。

### 代码示例：传统写法 vs 最佳实践写法

**不推荐的写法（代码重复）：**
```csharp
public class Employee
{
    public int EmpId;
    public string EmpName;
    public string Job;

    // 重载1：无参
    public Employee()
    {
        EmpId = 1; // 假设默认ID为1
    }

    // 重载2：两个参数
    public Employee(int empId, string empName)
    {
        this.EmpId = empId;
        this.EmpName = empName;
    }

    // 重载3：三个参数
    public Employee(int empId, string empName, string job)
    {
        this.EmpId = empId;
        this.EmpName = empName;
        this.Job = job;
    }
}
```

**推荐的写法（使用构造函数链）：**
```csharp
public class Employee
{
    public int EmpId;
    public string EmpName;
    public string Job;

    // 主构造函数：包含最全的初始化逻辑
    public Employee(int empId, string empName, string job)
    {
        this.EmpId = empId;
        this.EmpName = empName;
        this.Job = job;
    }

    // 重载2：调用主构造函数，未提供的参数传入默认值 null
    public Employee(int empId, string empName) : this(empId, empName, null)
    {
        // 方法体为空，实际赋值工作交给了主构造函数
    }

    // 重载1：调用重载2或主构造函数
    public Employee() : this(1, "Unknown", "Unassigned")
    {
    }
}
```

## 现代 C# 的替代方案：默认参数
在 C# 4.0 引入默认参数和命名参数之后，对于仅仅是因为参数数量不同而产生的构造函数重载，可以通过为一个构造函数提供默认值来大幅减少代码量。

```csharp
public class Employee
{
    public int EmpId;
    public string EmpName;
    public string Job;

    // 一个构造函数即可替代上面的三个重载
    public Employee(int empId = 1, string empName = "Unknown", string job = null)
    {
        this.EmpId = empId;
        this.EmpName = empName;
        this.Job = job;
    }
}
```
*调用方式：*
*   `new Employee()` -> 使用全部默认参数
*   `new Employee(102, "Alan")` -> 仅提供ID和名字
*   `new Employee(103, "Scott", "Manager")` -> 提供全部参数
*   `new Employee(empId: 104, job: "Developer")` -> 配合命名参数跨越跳过中间参数
