# C# 静态构造函数

## 核心概念与运行机制
静态构造函数（Static Constructor）用于初始化类级别的状态（即静态字段或属性），而不是对象实例的状态。

结合《CLR via C#》中的底层原理解析，静态构造函数在IL（中间语言）中被称为**类型构造器（Type Constructor，即 `.cctor`）**。
关于它的执行时机，CLR（公共语言运行时）提供了非常严格的保证：
*   **全局唯一性**：在整个应用程序域（AppDomain）的生命周期内，一个类的静态构造函数**最多只会执行一次**。
*   **自动触发**：开发者无法在代码中手动调用静态构造函数。它会在以下两种情况的**第一次**发生前，由CLR自动触发并执行：
    1.  创建该类的第一个实例对象时。
    2.  访问该类的任何静态成员（静态字段、静态属性、静态方法）时。
*   **线程安全**：CLR在底层自动加锁，确保静态构造函数的执行是绝对线程安全的。即使多个线程同时尝试首次访问该类，静态构造函数也只会被一个线程执行一次。

## 语法规则与严格限制
定义静态构造函数有着极其严格的语法限制，主要包括：
1.  **必须使用 `static` 关键字**：名称与类名相同。
2.  **绝对不允许使用访问修饰符**：不能添加 `public`、`private` 等任何访问控制符。由于它是被CLR自动调用的，对其设置访问权限毫无意义。
3.  **绝对不允许有参数**：它不能接收任何参数（即不支持重载）。因为是CLR自动在后台触发，开发者没有机会为其传递参数。
4.  **不能有返回类型**。

## 静态构造函数 vs 实例构造函数
| 特性        | 实例构造函数 (Instance Constructor)  | 静态构造函数 (Static Constructor) |
| :-------- | :----------------------------- | :-------------------------- |
| **执行时机**  | 每次使用 `new` 关键字创建新对象时都会执行。      | 在类被首次访问前自动执行，且**仅执行一次**。    |
| **初始化目标** | 初始化实例字段（属于特定对象的状态）。            | 初始化静态字段（属于整个类的共享状态）。        |
| **参数支持**  | 支持参数，支持方法重载（可定义多个）。            | 不支持参数，不可重载（每个类最多只能有一个）。     |
| **访问修饰符** | 可自定义（如 `public`, `private` 等）。 | 不允许存在任何访问修饰符。               |

## 代码示例解析

以下代码展示了如何在一个类中同时使用实例构造函数和静态构造函数，并观察它们的执行差异。

**类库定义 (Employee.cs)：**
```csharp
public class Employee
{
    // 实例字段
    public int EmpId;
    public string EmpName;
    
    // 静态字段（属于类，所有实例共享）
    public static string CompanyName;

    // 静态构造函数：仅执行一次，用于初始化静态资源
    static Employee()
    {
        // 模拟复杂的初始化逻辑，例如从配置文件或数据库读取公司名称
        CompanyName = "ABC Industries";
        Console.WriteLine("静态构造函数被调用。");
    }

    // 实例构造函数：每次 new 对象时执行
    public Employee(int empId, string empName)
    {
        this.EmpId = empId;
        this.EmpName = empName;
        Console.WriteLine($"实例构造函数被调用，员工：{empName}。");
    }
}
```

**控制台调用 (Program.cs)：**
```csharp
class Program
{
    static void Main(string[] args)
    {
        // 第一次访问 Employee 类（创建第一个实例）
        // 此时 CLR 会先调用静态构造函数，然后再调用实例构造函数
        Employee emp1 = new Employee(101, "Scott");

        // 第二次访问 Employee 类（创建第二个实例）
        // 此时仅调用实例构造函数，静态构造函数不会再次执行
        Employee emp2 = new Employee(102, "Smith");

        // 访问静态字段，验证数据
        Console.WriteLine($"公司名称: {Employee.CompanyName}");
    }
}
```

## 进阶拓展与避坑指南

*   **初始化器 vs 静态构造函数**：
    在《Effective C#》中建议，如果只是给静态字段赋一个简单的固定值，推荐直接使用静态字段初始化器（如 `public static int Count = 0;`），而不是专门写一个静态构造函数。只有当静态字段的初始化涉及复杂逻辑（如读取配置文件、建立数据库连接、异常处理）时，才使用静态构造函数。
*   **致命的异常 (`TypeInitializationException`)**：
    **务必确保静态构造函数中不会抛出未处理的异常！** 如果静态构造函数在执行期间抛出异常，CLR 将认为该类型初始化失败。随后在应用程序的整个生命周期内，任何试图访问该类的代码都会引发 `TypeInitializationException`，导致该类彻底陷入瘫痪状态无法使用。
