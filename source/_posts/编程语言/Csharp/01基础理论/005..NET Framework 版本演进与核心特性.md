**关于 .NET Framework 版本演进与核心特性的笔记**

# **一、 .NET Framework 发展时间线与生命周期**

.NET Framework 自 2002 年首次发布以来，经历了长达 20 年的持续迭代。
*   **初创与终局：** 1.0 版本发布于 2002 年，而最新的 4.8.1 版本发布于 2022 年。
*   **更新频率：** 微软通常保持每 1 到 2 年推出一个新版本的节奏。
*   **历史定位（补充补充）：** 4.8.x 系列被视为经典（仅限 Windows 的）.NET Framework 的最终代。微软目前的开发重心已经全面转移到了跨平台的 .NET（原 .NET Core）技术栈上。因此，了解这些历史版本的主要意义在于维护企业现有的遗留系统以及应对技术面试。

# **二、 框架版本与 CLR (运行库) 版本的映射关系**

这是一个非常高频的面试考点。底层的执行引擎（CLR）并没有随着每一个 .NET Framework 版本的发布而更新，而是呈现一种跨版本复用的状态。目前历史上只存在三个大版本的 CLR：

1.  **CLR 1.0：** 支撑早期版本
    *   对应框架：.NET Framework 1.0, 1.1
2.  **CLR 2.0：** 支撑中期版本
    *   对应框架：.NET Framework 2.0, 3.0, 3.5
    *   **深度解析（重要补充）：** 为什么不存在 CLR 3.0？因为 .NET 3.0 和 3.5 实际上并没有改变底层的运行机制，它们只是在 CLR 2.0 的基础上，向框架类库（FCL）中追加了大量的新组件（如 WPF、WCF、LINQ）。底层依然是 CLR 2.0。
3.  **CLR 4.0：** 支撑现代版本
    *   对应框架：.NET Framework 4.0 至最新的 4.8.1

# **三、 历代大版本核心特性演进**

每个大版本都引入了改变开发者编写代码方式的重量级特性，以下是核心脉络梳理：

*   **.NET 1.0 / 1.1 (基础构建期)**
    *   确立了基于面向对象编程（OOP）的体系，包含基础类型、类、对象、数组和集合。
    *   引入了 CAS（代码访问安全）、ODBC 数据连接以及针对移动设备的 .NET Compact Framework。

*   **.NET 2.0 (重大变革期)**
    *   **泛型 (Generics)：** 极大地提升了类型安全和代码性能，避免了频繁的装箱/拆箱操作。
    *   **分部类 (Partial Classes)：** 允许将一个类的代码拆分到多个文件中，为 UI 设计器（如 WinForms 的 Designer 文件）的代码分离奠定了基础。
    *   **匿名方法 (Anonymous Methods)：** 简化了委托的编写。

*   **.NET 3.0 (W 时代)**
    *   引入了三大核心框架：WPF（现代桌面 UI）、WCF（统一的通信与服务框架）、WWF（工作流引擎）。

*   **.NET 4.0 (并行与动态期)**
    *   **任务并行库 (TPL - Task Parallel Library)：** 引入了 `Task` 的概念，大幅简化了多核处理器下的多线程开发。
    *   引入了命名参数（Named Parameters）以及 DLR（动态语言运行时），支持 `dynamic` 关键字。

*   **.NET 4.5 (异步编程革命)**
    *   **`async` 和 `await` 关键字：** 彻底改变了异步编程的范式，使异步代码的书写和阅读如同同步代码一样直观，解决了以往由于回调地狱导致的代码难以维护的问题。
    *   支持 Windows Store 应用程序开发，以及前端静态资源打包压缩（Bundling and Minification）。

*   **.NET 4.6 / 4.7 / 4.8 (向 Core 的过渡期)**
    *   引入了更现代的加密 API 和 WPF 的打印 API。
    *   最重要的标志是：在这几代框架演进的同时，微软开始了 ASP.NET Core 和 .NET Core 的引入和并行发展，为后来的生态大一统做铺垫。

# **四、 C# 语言版本与框架的协同**

C# 语言的迭代是与 .NET 框架紧密绑定的。目前的 C# 已经发展到 C# 12 及以上版本。

*   **补充完善：** 需要注意的是，由于经典的 .NET Framework 生命周期已经锁定，它对最新 C# 特性的支持是有限的。官方规定，经典的 .NET Framework（如 4.8）默认最高完全支持到 **C# 7.3**。如果想要使用 C# 8.0 及以后引入的现代语法特性（如默认接口方法、记录类型 Record 等），必须迁移到 .NET Core / .NET 5+ 环境下。
