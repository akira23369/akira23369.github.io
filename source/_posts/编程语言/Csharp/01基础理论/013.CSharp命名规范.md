**关于 C# 命名规范 (Naming Conventions) 的深度笔记**

# **一、 为什么需要命名规范？**

在软件开发中，代码的“可读性”往往比“可写性”更重要。C# 拥有一套由微软官方确立并被全球开发者广泛遵守的命名规范。遵循这些规范不仅能让代码看起来整洁专业，还能让团队中的其他开发者（或几个月后的自己）仅通过变量名的大小写形式，就能瞬间判断出该元素的类型和作用域。

# **二、 C# 四大核心命名风格与适用场景**

**1. PascalCase (帕斯卡命名法 / 大驼峰命名法)**
*   **规则：** 标识符中的每一个单词的首字母都必须大写，包含第一个单词。
*   **示例：** `CustomerName`, `CalculateSalary`, `Main`
*   **适用对象（全局或高级别元素）：**
    *   **类名 (Classes)**：如 `Employee`, `DataAccess`
    *   **命名空间 (Namespaces)**：如 `System.Collections`, `University.Management`
    *   **方法名 (Methods)**：如 `StartEngine()`, `GetData()`
    *   **属性名 (Properties)**：如 `FirstName`, `Age`
    *   **结构体 (Structures)** 和 **记录类型 (Records)**
    *   *(补充)* **常量 (Constants)**：在 C# 中，常量通常也使用 PascalCase（如 `MaxItems`），而不是像 C++ 或 Java 那样使用全大写加下划线（`MAX_ITEMS`）。

**2. camelCase (小驼峰命名法)**
*   **规则：** 第一个单词的首字母小写，从第二个单词开始，后续每个单词的首字母大写。
*   **示例：** `customerName`, `totalPrice`
*   **适用对象（局部或短生命周期元素）：**
    *   **局部变量 (Local Variables)**：在方法内部声明的变量，如 `int loopCount = 0;`。
    *   **方法参数 (Method Parameters)**：方法签名中接收数据的变量，如 `void SetAge(int newAge)`。

**3. _camelCase (下划线 + 小驼峰命名法)**
*   **规则：** 在小驼峰命名法的基础之上，在最前面强制加一个下划线 `_`。
*   **示例：** `_customerName`, `_databaseConnection`
*   **适用对象（类内部状态）：**
    *   **私有字段 (Private Fields) / 支持字段 (Backing Fields)**：专门用于在类的内部存储数据，不对外公开的变量。加上下划线可以极大地避免与局部变量或方法参数产生命名冲突。

**4. IPascalCase (大写字母 'I' + 帕斯卡命名法)**
*   **规则：** 专为一种特定类型设计。首字母必须是大写的 `I`（代表 Interface），后面紧跟标准的 PascalCase 命名。
*   **示例：** `ICustomer`, `IEnumerable`, `IDisposable`
*   **适用对象：**
    *   **接口 (Interfaces)**：看到以 `I` 开头的类型，开发者立刻就能知道这是一个抽象的接口，而不是具体的实现类。

# **三、 综合代码说明：命名规范全景展示**

以下代码通过一个完整的业务类，直观展示了所有 C# 命名规范在实际工程中的应用位置：

```csharp
using System;

// 1. 命名空间：PascalCase
namespace ECommerceApp.Orders 
{
    // 2. 接口：大写 'I' + PascalCase
    public interface IOrderProcessor 
    {
        void ProcessOrder();
    }

    // 3. 类名：PascalCase
    public class OrderManager : IOrderProcessor 
    {
        // 4. 私有字段：下划线 + camelCase (类内部使用)
        private string _orderId;
        private decimal _discountRate;

        // 5. 常量：PascalCase (C# 推荐规范)
        public const int MaxOrderLimit = 100;

        // 6. 属性：PascalCase (对外公开的数据通道)
        public decimal TotalAmount { get; set; }

        // 7. 构造函数参数：camelCase
        public OrderManager(string orderId, decimal discountRate)
        {
            // 下划线字段与 camelCase 参数完美区分，无需使用 this 关键字
            _orderId = orderId;  
            _discountRate = discountRate;
        }

        // 8. 方法名：PascalCase
        public void ProcessOrder()
        {
            // 9. 局部变量：camelCase (仅在此方法内部有效)
            decimal calculatedDiscount = TotalAmount * _discountRate;
            decimal finalPrice = TotalAmount - calculatedDiscount;

            Console.WriteLine($"Order {_orderId} processed. Final Price: {finalPrice}");
        }
    }
}
```

**总结：**
严格遵守上述四套命名规则，能够让 C# 代码达到“代码即注释”的境界。这也是进入企业级开发环境、参与团队代码审查（Code Review）时最基本的前提要求。
