# 前置知识
Record 的一些前置知识，这些都是理解 Record 设计哲学的基础。
## **不可变类**
不可变对象一旦创建，其状态就不能被修改。任何"修改"操作都会返回一个新对象。
```cs
// 传统不可变类 - 需要大量样板代码
public class Person
{
    // 1. 只读字段或属性
    private readonly string _name;
    private readonly int _age;

    // 2. 只能通过构造函数初始化
    public Person(string name, int age)
    {
        _name = name;
        _age = age;
    }

    // 3. 只有 Getter，没有 Setter
    public string Name => _name;
    public int Age => _age;

    // 4. 想要"修改"必须创建新对象（With 模式的前身）
    public Person WithName(string newName) => new Person(newName, this._age);
    public Person WithAge(int newAge) => new Person(this._name, newAge);
}
```


**不可变类的优势**

| 优势       | 说明                    |
| -------- | --------------------- |
| **线程安全** | 无竞争条件，可安全共享           |
| **可预测性** | 状态不会意外改变，易于推理         |
| **哈希安全** | 适合作为 Dictionary 的 Key |
| **版本控制** | 天然支持快照、撤销功能           |


## Init-Only 访问器 (C# 9.0)

**问题背景**
传统不可变类只能在构造函数中初始化，对象初始化器 `{ Name = "Tom" }` 无法使用，这让代码变得冗长。

**Init 访问器登场**
```cs
public class Person
{
    // init 表示只能在对象初始化或构造函数中设置
    public string Name { get; init; }
    public int Age { get; init; }
}

// 使用方式
var person = new Person 
{ 
    Name = "Tom",      // ✅ 编译通过：在初始化阶段
    Age = 25 
};

person.Name = "Jerry";  // ❌ 编译错误：初始化完成后不可修改
```

**允许设置 init 属性的场景：**
对象初始化器 { Prop = value }
构造函数 this.Prop = value
另一个 init 访问器（属性之间互相初始化）
派生类的构造函数（通过 base 调用）

**禁止设置 init 属性的场景：**
普通方法中修改
初始化完成后任何修改

| 特性    | `readonly` 字段 | `init` 属性     |
| ----- | ------------- | ------------- |
| 语法    | 字段级别          | 属性级别          |
| 初始化位置 | 构造函数、声明时      | 构造函数 + 对象初始化器 |
| 灵活性   | 低             | 高（支持对象初始化器语法） |
| 适用场景  | 底层数据存储        | 公共 API 设计     |

## 无参结构体构造函数

在 C# 10 之前，结构体**强制要求**无参构造函数保持默认行为（将所有字段清零），你无法自定义：
```cs
// C# 9 及以前 - 这是非法的！
public struct Point
{
    public int X;
    public int Y;
    
    // ❌ 错误：不能定义无参构造函数
    public Point() 
    {
        X = 0; 
        Y = 0;
    }
}
```

**C# 10 的突破**
```cs
// C# 10 起 - 终于可以自定义无参构造函数了！
public struct Point
{
    public int X { get; set; }
    public int Y { get; set; }

    // ✅ 现在可以定义无参构造函数了
    public Point()
    {
        X = 0;
        Y = 0;
        Console.WriteLine("Point created");
    }

    // 有参构造函数依然支持
    public Point(int x, int y)
    {
        X = x;
        Y = y;
    }
}
```

**为什么这很重要？**
这与 Record 密切相关，因为 **Record Struct** 需要这个特性来保证一致性：
```cs
// Record Struct 会隐式生成无参构造函数
public record struct Point(int X, int Y);

// 编译器生成的代码类似于：
public struct Point
{
    public int X { get; set; } = 0;  // 需要无参构造函数支持
    public int Y { get; set; } = 0;
    
    public Point() {}  // 隐式无参构造函数
    
    public Point(int x, int y) 
    {
        X = x;
        Y = y;
    }
}
```

# Record 初探

## 前言：为什么我们需要Record？

在 C# 9.0 之前，当我们谈论“数据载体”时，我们几乎总是使用 `class`。无论是数据传输对象（DTO）、API 响应模型、配置项，还是简单的领域值对象，`class` 都是默认的选择。然而，随着软件架构的演进，特别是函数式编程思想的引入和 CQRS（命令查询职责分离）模式的普及，开发者们逐渐发现，使用传统的 `class` 来定义纯粹的数据结构存在诸多痛点：

1.  **样板代码（Boilerplate Code）过多**：为了定义一个包含 5 个属性的数据对象，你需要写构造函数、属性、`Equals` 方法、`GetHashCode` 方法、`ToString` 方法，甚至还要实现 `IEquatable<T>`。
2.  **引用相等性的陷阱**：`class` 默认基于引用相等性（Reference Equality）。这意味着即使两个对象的所有属性值都完全相同，如果它们不是同一个内存地址，`==` 或 `Equals` 就会返回 `false`。这在处理 DTO 或消息时往往不是我们想要的。
3.  **不可变性（Immutability）难以实现**：在并发编程或函数式风格的数据流中，我们希望数据是不可变的。但在 `class` 中实现不可变性需要大量的 `readonly` 修饰符和 `init` 访问器，且容易出错。

为了解决这些问题，微软在 C# 9.0 中引入了 **`record`（记录类型）**。它不仅仅是一个语法糖，更是一种**思维模式的转变**：从“关注对象身份（Identity）”转向“关注对象内容（Value）”。

本文将作为本系列的第一篇，带你深入理解 `record` 的基础概念、语法定义、底层原理以及与 `class` 的本质区别。

---

## 一、核心概念：引用相等性 vs 值相等性

要真正掌握 `record`，首先必须理解两种不同的相等性概念。这是理解 `record` 存在的基石。

### 引用相等性
这是传统 `class` 的默认行为。
*   **定义**：两个变量指向内存中的**同一个对象实例**。
*   **判断依据**：内存地址（Reference）。
*   **场景**：当你需要区分两个不同的实体，即使它们的数据完全一样。例如，数据库中的两条记录，虽然姓名、年龄相同，但 ID 不同，它们是两个不同的对象。

```csharp
// 传统 Class 示例
public class PersonClass
{
    public string Name { get; set; }
    public int Age { get; set; }
}

var p1 = new PersonClass { Name = "Alice", Age = 30 };
var p2 = new PersonClass { Name = "Alice", Age = 30 };
var p3 = p1;

Console.WriteLine(p1 == p2); // False (内存地址不同)
Console.WriteLine(p1 == p3); // True (内存地址相同)
```

### 值相等性
这是 `record` 的默认行为。
*   **定义**：两个对象包含**相同的数据内容**。
*   **判断依据**：所有公共属性的值（递归比较）。
*   **场景**：DTO、配置、消息、不可变数据。当你关心“是什么”而不是“是谁”时。

```csharp
// Record 示例
public record PersonRecord(string Name, int Age);

var r1 = new PersonRecord("Alice", 30);
var r2 = new PersonRecord("Alice", 30);
var r3 = r1;

Console.WriteLine(r1 == r2); // True (内容相同)
Console.WriteLine(r1 == r3); // True (引用相同)
```

**思维转变点**：
在使用 `class` 时，我们潜意识里认为 `p1` 和 `p2` 是“不同的人”，即使他们长得一样。
在使用 `record` 时，我们潜意识里认为 `r1` 和 `r2` 是“同一个人”，因为他们的身份特征（Name, Age）完全一致。这种思维转变对于编写无副作用的函数和简化数据比较逻辑至关重要。

## 二、Record 的基本语法与位置属性

C# 的 `record` 设计初衷就是简洁。它通过**位置属性（Positional Properties）** 极大地减少了样板代码。

### 定义 Record
定义一个 `record` 非常简单，只需将 `class` 关键字替换为 `record`。

```csharp
// 定义一个名为 Point 的 record
public record Point(int X, int Y);
```

### 位置属性与构造函数
在上面的例子中，`Point(int X, int Y)` 被称为**位置参数列表**。编译器会自动为你完成以下工作：
1.  生成一个公共构造函数，接受 `X` 和 `Y` 作为参数。
2.  生成公共的、只读的（init-only）属性 `X` 和 `Y`。
3.  生成 `Equals`、`GetHashCode`、`ToString` 等方法的实现。

```csharp
var p1 = new Point(10, 20);
Console.WriteLine(p1.X); // 输出 10
Console.WriteLine(p1.Y); // 输出 20
```

**注意**：虽然属性是 `init` 的（意味着不能在构造函数外修改），但 `record` 默认**不是**完全不可变的（除非你配合 `init` 访问器使用）。你仍然可以像修改普通属性一样修改它，除非你显式指定为 `init` 或使用 `record struct`。

### 自动生成的 ToString()
当你直接打印一个 `record` 对象时，它会自动调用 `ToString()` 并输出所有属性的名称和值，格式清晰易读，非常适合调试。

```csharp
var p = new Point(10, 20);
Console.WriteLine(p); 
// 输出: Point { X = 10, Y = 20 }
```

相比之下，普通的 `class` 如果不重写 `ToString()`，输出的是 `System.Namespace.ClassName`。

### 显式属性定义
你不需要把所有属性都放在位置参数列表中。你可以混合使用位置属性和普通属性。

```csharp
public record User(string Name, int Id)
{
    public string Email { get; init; } // 普通属性，但建议配合 init 使用
    public DateTime CreatedAt { get; } = DateTime.UtcNow;
}

var user = new User("Bob", 1) { Email = "bob@example.com" };
```

## 三、Record 与 Class 的深度对比

很多开发者认为 `record` 只是“不可变的 class"，这是一个巨大的误解。`record` 默认是 `class`（引用类型），但它改变了相等的行为。

| 特性           | Class | Record (默认)       | Record Struct (C# 10+) |
| :----------- | :---- | :---------------- | :--------------------- |
| **类型分类**     | 引用类型  | 引用类型              | 值类型                    |
| **相等性**      | 引用相等  | **值相等**           | 值相等                    |
| **构造函数**     | 需手动编写 | 位置参数自动生成          | 位置参数自动生成               |
| **ToString** | 默认类名  | 自动生成属性列表          | 自动生成属性列表               |
| **继承**       | 支持    | 支持                | 不支持                    |
| **可变性**      | 默认可变  | 默认可变 (但通常配合 init) | 默认可变 (值类型特性)           |
| **内存开销**     | 堆分配   | 堆分配               | 栈分配 (通常)               |


### 关键差异详解：
1.  **相等性实现**：
    *   `class` 的 `Equals` 比较的是内存地址。
    *   `record` 的 `Equals` 比较的是所有公共属性的值。如果属性是 `record` 类型，它会递归比较。
2.  **继承行为**：
    *   `record` 支持继承（只和record继承）。如果 `Derived` 继承自 `Base`，`Equals` 方法会自动包含基类的属性。
    *   位置属性在继承时必须保持顺序一致，否则相等性判断会出错。
3.  **`sealed` 默认行为**：
    *   虽然 `record` 可以被继承，但为了鼓励值相等性，通常建议将 `record` 标记为 `sealed` 或者确保继承链中的相等性逻辑清晰。

## 四、编译器魔法：Record 到底生成了什么？

理解 `record` 不是魔法，而是编译器生成的代码，有助于我们理解其性能开销。

当你写下：
```csharp
public record Person(string Name, int Age);
```

编译器实际上为你生成了类似以下的代码（简化版）：

```csharp
public class Person : IEquatable<Person>
{
    public Person(string name, int age)
    {
        this.Name = name;
        this.Age = age;
    }

    public string Name { get; init; } // 注意是 init
    public int Age { get; init; }

    public bool Equals(Person? other)
    {
        if (ReferenceEquals(null, other)) return false;
        if (ReferenceEquals(this, other)) return true;
        return this.Name == other.Name && this.Age == other.Age;
    }

    public override bool Equals(object? obj)
    {
        return obj is Person other && this.Equals(other);
    }

    public override int GetHashCode()
    {
        return HashCode.Combine(this.Name, this.Age);
    }

    public override string ToString()
    {
        return $"Person {{ Name = {this.Name}, Age = {this.Age} }}";
    }

    protected virtual void PrintMembers(System.Text.StringBuilder builder)
    {
        builder.Append($"Name = {this.Name}, ");
        builder.Append($"Age = {this.Age}");
    }
}
```

**重点分析**：
1.  **`IEquatable<T>`**：这是实现值相等性的核心接口。
2.  **`init` 访问器**：编译器默认将位置参数生成的属性设为 `init`。这意味着属性在构造函数初始化后，只能在 `with` 表达式中修改（见下篇），或者通过反射修改。这提供了某种程度的不可变性保障。
3.  **`PrintMembers`**：这是 `ToString` 的扩展方法。如果你想自定义 `ToString` 的输出格式（例如隐藏某些字段），只需重写 `PrintMembers` 即可。

## 五、常见误区与避坑指南

在学习 `record` 的初期，有几个常见的误区需要特别注意。

### Record 默认是可变还是不可变？
**误区**：`record` 就是不可变对象。
**真相**：`record` 默认生成的属性是 `init` 的，但这仅限于位置参数生成的属性。如果你在 `record` 内部定义了普通 `get; set;` 属性，它们依然是可变的。此外，`record` 本身是引用类型，如果属性是引用类型（如 `List<string>`），你仍然可以修改该引用指向的集合内容。
*   **建议**：在定义 `record` 时，习惯性地为所有属性加上 `init` 访问器，以实现真正的不可变性。

### 位置属性顺序的重要性
**误区**：继承 record 时，属性顺序不重要。
**真相**：当你继承一个 `record` 并添加位置参数时，**参数的顺序必须与基类一致**。
```csharp
// 错误示例：基类是 (Name, Age)，子类参数顺序乱了
public record Person(string Name, int Age);
public record Employee(string Name, int Age, string Job) : Person(Name, Age); // 正确
// 如果子类写成 (Job, Name, Age) 会导致编译错误或逻辑错误
```
编译器依赖参数顺序来生成 `Equals` 方法。如果顺序不一致，基类的属性可能无法正确参与比较。

### 集合中的 Record 行为
由于 `record` 实现了值相等性，它在 `HashSet` 和 `Dictionary` 中的行为与 `class` 不同。
```csharp
var set = new HashSet<PersonRecord>();
var p1 = new PersonRecord("Alice", 30);
var p2 = new PersonRecord("Alice", 30);

set.Add(p1);
Console.WriteLine(set.Contains(p2)); // True! 因为值相等
```
这对于缓存键、去重操作非常有用，但如果你期望的是引用唯一性，这可能会导致意外行为。

### 性能开销
`record` 会生成额外的方法（`Equals`, `GetHashCode` 等）。对于极其微小的对象，这可能比 `class` 略重。但在绝大多数业务场景中，这种开销微乎其微，换取的代码简洁性和安全性是值得的。
*   **注意**：如果追求极致性能（如高频计算循环中），可以考虑 `record struct`（见文章 04）。

## 六、实战演练：重构一个传统的 DTO

让我们通过一个实际的例子，展示如何用 `record` 重构传统的 `class` DTO。

### 重构前：Class 版本
```csharp
public class OrderDto
{
    public int Id { get; set; }
    public string CustomerName { get; set; }
    public decimal TotalAmount { get; set; }
    public DateTime OrderDate { get; set; }

    public override bool Equals(object obj)
    {
        if (obj is OrderDto other)
        {
            return Id == other.Id && CustomerName == other.CustomerName;
        }
        return false;
    }

    public override int GetHashCode()
    {
        return HashCode.Combine(Id, CustomerName);
    }
}
```
**问题**：代码冗长，容易忘记重写 `GetHashCode`，`Equals` 逻辑容易出错，且属性默认可变。

### 重构后：Record 版本
```csharp
public record OrderDto(int Id, string CustomerName, decimal TotalAmount, DateTime OrderDate);
```
**优势**：
1.  **代码量减少 90%**。
2.  **安全性提升**：`Id` 和 `CustomerName` 作为值相等性的核心，编译器保证逻辑正确。
3.  **调试友好**：直接打印对象即可看到所有字段。
4.  **不可变性暗示**：配合 `init`（默认行为），防止意外修改订单数据。

## 七、总结与展望

通过本文，我们完成了对 C# `record` 的初次探索。我们了解到：
1.  **Record 是引用类型**，但默认提供**值相等性**。
2.  **语法极其简洁**，位置属性自动处理构造函数和属性。
3.  **底层原理**是编译器自动实现了 `IEquatable<T>` 和 `GetHashCode`。
4.  **适用场景**主要是数据载体（DTO、消息、配置）。

**思维转变的核心**在于：当你定义一个 `record` 时，你是在告诉编译器和阅读代码的人：“这个对象的价值在于它的**数据内容**，而不是它的**内存地址**。”

然而，`record` 的强大不仅仅在于相等性。在下一篇文章中，我们将深入探讨 `record` 最迷人的特性——**不可变性**与 **`with` 表达式**。我们将学习如何在不修改原对象的情况下创建新对象，这是函数式编程在 C# 中的核心体现。

**课后练习**：
1.  创建一个 `Address` record，包含 `City`, `Street`, `ZipCode`。
2.  创建两个内容相同的 `Address` 实例，验证 `Equals` 和 `==` 的结果。
3.  尝试修改其中一个实例的属性，观察另一个实例是否受影响（验证引用类型特性）。
4.  将上述 `Address` 放入 `HashSet`，尝试添加重复内容，观察集合大小。

```cs
using System;
using System.Collections.Generic;

// 1. 创建一个 Address record，包含 City, Street, ZipCode
// 使用位置语法（Positional Syntax），默认属性为 init-only（不可变）
public record Address(string City, string Street, string ZipCode);

class Program
{
    static void Main()
    {
        Console.WriteLine("--- 2. 验证 Equals 和 == ---");
        // 创建两个内容完全相同的 Address 实例
        var address1 = new Address("北京市", "长安街", "100000");
        var address2 = new Address("北京市", "长安街", "100000");

        // 验证相等性
        Console.WriteLine($"address1.Equals(address2): {address1.Equals(address2)}"); // 输出: True
        Console.WriteLine($"address1 == address2: {address1 == address2}");         // 输出: True
        // 验证它们在内存中确实是两个不同的对象（引用类型特性）
        Console.WriteLine($"ReferenceEquals: {object.ReferenceEquals(address1, address2)}"); // 输出: False


        Console.WriteLine("\n--- 3. 验证修改及引用类型特性 ---");
        // 因为 record 默认是不可变的，直接修改 address1.City = "上海市" 会导致编译错误。
        // 我们需要使用 with 表达式来“修改”（实际上是创建了一个新副本）
        var address3 = address1 with { City = "上海市" };
        
        Console.WriteLine($"address1 的 City: {address1.City}"); // 输出: 北京市 (原实例不受影响)
        Console.WriteLine($"address3 的 City: {address3.City}"); // 输出: 上海市

        // 【补充验证引用传递】：如果我们将 address1 赋值给另一个变量
        var addressRefCopy = address1;
        Console.WriteLine($"addressRefCopy 和 address1 是否为同一引用: {object.ReferenceEquals(address1, addressRefCopy)}"); // 输出: True


        Console.WriteLine("\n--- 4. 验证 HashSet 集合行为 ---");
        var hashSet = new HashSet<Address>();
        
        // 放入第一个实例
        hashSet.Add(address1);
        Console.WriteLine($"添加 address1 后，集合大小: {hashSet.Count}"); // 输出: 1
```
