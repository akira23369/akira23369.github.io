# 继承、模式匹配与C#新特性深度解析

## 前言：从数据容器到逻辑处理器

在文章 01 和 02 中，我们掌握了 `record` 的基础语法和不可变性设计。然而，在实际的企业级开发中，数据模型往往不是孤立的。我们需要处理**继承体系**（如不同类型的支付订单）、复杂的**条件逻辑**（如根据状态执行不同操作）以及**数据校验**（确保关键数据不缺失）。

传统的 `class` 在这些场景下往往需要大量的 `if-else` 和样板代码。而 C# `record` 配合 **模式匹配（Pattern Matching）** 和 **C# 11/12 新特性**，可以将这些逻辑简化为声明式的代码，极大地提升可读性和安全性。

本文将深入探讨 `record` 的继承规则（这是最容易出错的地方）、如何利用模式匹配消除条件分支，以及如何使用 `required` 等现代特性构建健壮的模型。

---

## 一、Record 的继承体系：规则与陷阱

`record` 支持继承，但它的继承规则与 `class` 有微妙且关键的区别。理解这些区别对于设计多态的数据模型至关重要。
`record`只支持和`record`相互继承，不能与类有任何继承关系

### 继承语法与位置属性顺序
`record` 继承时，位置参数（Positional Parameters）的顺序必须**严格一致**。编译器利用参数顺序来生成 `Equals` 和 `GetHashCode` 方法。

**正确示例**：
```csharp
public record BaseRecord(string Id, DateTime CreatedAt);
public record DerivedRecord(string Id, DateTime CreatedAt, string Name) : BaseRecord(Id, CreatedAt);
```
在 `DerivedRecord` 中，`Id` 和 `CreatedAt` 必须排在 `Name` 之前，且顺序与基类完全一致。

**错误示例**（会导致编译错误或运行时行为异常）：
```csharp
// 警告：参数顺序打乱了
public record BrokenRecord(string Name, string Id, DateTime CreatedAt) : BaseRecord(Id, CreatedAt);
```
虽然编译器可能允许你这样写（取决于具体版本和配置），但 `Equals` 逻辑会混乱，因为基类的比较逻辑依赖于位置参数的映射。

### 值相等性的继承
`record` 的 `Equals` 方法是**递归**的。派生类的 `Equals` 会自动包含基类的属性。

```csharp
var base1 = new BaseRecord("1", DateTime.Now);
var base2 = new BaseRecord("1", DateTime.Now);
Console.WriteLine(base1.Equals(base2)); // True

var derived1 = new DerivedRecord("1", DateTime.Now, "Alice");
var derived2 = new DerivedRecord("1", DateTime.Now, "Alice");
Console.WriteLine(derived1.Equals(derived2)); // True

// 跨层级比较
Console.WriteLine(base1.Equals(derived1)); // False (类型不同，即使 ID 相同)
```
**注意**：`record` 的相等性比较通常要求**类型相同**。如果 `DerivedRecord` 试图与 `BaseRecord` 比较，即使基类部分属性相同，也会返回 `false`。这是为了确保值语义的严谨性。

### 自定义 `PrintMembers` 与 `ToString`
在继承链中，`ToString` 的输出会自动包含所有层级的属性。如果你需要自定义输出格式（例如隐藏敏感信息），需要重写 `PrintMembers` 方法。

```csharp
public record User(string Name, string Password)
{
    protected override void PrintMembers(System.Text.StringBuilder builder)
    {
        // 隐藏密码
        builder.Append($"Name = {Name}");
    }
}
```

### 继承的最佳实践：何时使用 `record` 继承？
虽然 `record` 支持继承，但**不建议过度使用**。
*   **推荐场景**：事件驱动架构中的事件类型（Event Hierarchy）。例如 `BaseEvent` 继承自 `record Event`，派生类为 `UserCreatedEvent`, `OrderPlacedEvent`。
*   **不推荐场景**：领域实体（Domain Entities）的多态。实体通常有复杂的业务逻辑和可变状态，更适合用 `class`。
*   **建议**：如果可能，尽量将 `record` 标记为 `sealed`，除非你确实需要多态行为。

## 二、模式匹配：消除 `if-else` 的利器

模式匹配是 C# 9.0 及以后版本的一大亮点。当它与 `record` 结合时，能够写出极其优雅的类型安全代码。
见前面，这里就讲个大概

{% post_link 267.模式匹配基础与发展脉络 模式匹配相关 %}
### 类型模式
在 `switch` 表达式中，可以直接判断 `record` 的具体类型。

```csharp
public record Payment;
public record CreditCardPayment(string CardNumber) : Payment;
public record PayPalPayment(string Email) : Payment;

public string ProcessPayment(Payment payment)
{
    return payment switch
    {
        CreditCardPayment { CardNumber: var cc } => $"处理信用卡 {cc}",
        PayPalPayment { Email: var email } => $"处理 PayPal {email}",
        _ => "未知支付方式"
    };
}
```
**优势**：编译器会检查所有情况是否覆盖（Exhaustiveness Check），避免遗漏分支。

### 属性模式
这是 `record` 的杀手锏。你可以直接匹配属性的值，无需先 `as` 转换。

```csharp
public record Order(string Status, decimal Amount);

public string GetOrderMessage(Order order)
{
    return order switch
    {
        // 匹配类型 AND 属性值
        { Status: "Paid", Amount: > 1000 } => "大额支付订单",
        { Status: "Paid" } => "普通支付订单",
        { Status: "Pending" } => "等待支付",
        _ => "未知状态"
    };
}
```
这种写法比传统的 `if (order.Status == "Paid" && order.Amount > 1000)` 更加直观且不易出错。

### 递归模式
当 `record` 内部包含嵌套的 `record` 时，可以递归匹配。

```csharp
public record Address(string City, string Street);
public record User(string Name, Address Address);

public string GetCity(User user)
{
    return user switch
    {
        // 直接解构嵌套属性
        { Address: { City: var city } } => city,
        _ => "Unknown"
    };
}
```

### 弃元模式
如果你只关心某些属性，可以使用 `_` 忽略其他。

```csharp
// 只要状态是 Paid，忽略金额
if (order is { Status: "Paid", Amount: _ })
{
    // 处理逻辑
}
```

## 三、C# 11/12 新特性：`required` 与集合表达式

随着 C# 版本的迭代，`record` 的功能变得更加强大。特别是 C# 11 引入的 `required` 修饰符，解决了 DTO 校验的痛点。

required 关键字的核心作用是：**强制调用者在创建对象时，必须通过对象初始化器（Object Initializer）为指定的属性或字段赋值。**

### `required` 修饰符（C# 11）
在定义 DTO 或配置对象时，我们经常需要确保某些属性在初始化时**必须**被赋值。以前这需要自定义构造函数或复杂的验证逻辑。现在，只需 `required`。

```csharp
// C# 11 之前
public record UserDto(string Name, string Email)
{
    public UserDto() : this("", "") { } // 为了支持反序列化
    // 验证逻辑写在构造函数里很繁琐
}

// C# 11 之后
public record UserDto(string Name, string Email)
{
    // 强制 Email 必须初始化，否则编译报错
    public string Email { get; init; } = required; 
    // 注意：位置参数默认就是 required 的，这里主要针对非位置参数
}

// 更常见的用法：非位置参数
public record CreateUserRequest
{
    public string Name { get; init; } = required;
    public string Email { get; init; } = required;
    public string? Note { get; init; } // 可选
}

// 使用
var req = new CreateUserRequest { Name = "Alice", Email = "a@b.com" }; // 正确
// var req2 = new CreateUserRequest { Name = "Alice" }; // 编译错误：Email 未初始化
```
**优势**：
*   **编译时安全**：忘记必填字段会在编译阶段报错，而不是运行时。
*   **JSON 反序列化支持**：`System.Text.Json` 会自动识别 `required` 并在反序列化缺失字段时抛出异常。

### 集合表达式（C# 12）
在 `with` 表达式中修改集合属性时，C# 12 的集合表达式让代码更简洁。

```csharp
public record Order(string Id, List<string> Items);

var order = new Order("1", new List<string> { "A" });

// C# 12 集合表达式
var newOrder = order with { Items = [.. order.Items, "B"] };
```
`[.. order.Items]` 比 `order.Items.ToList()` 更短，语义更清晰（展开列表）。

### `with` 表达式的改进
C# 12 允许在 `with` 表达式中省略属性名（如果类型推断足够），但通常建议保留属性名以提高可读性。更重要的是，`with` 现在能更好地处理 `required` 属性。

## 四、实战场景：构建健壮的 API 请求模型

结合上述特性，我们来看一个完整的 API 请求模型设计案例。

### 场景需求
1.  创建用户请求，`Name` 和 `Email` 必填。
2.  更新用户请求，所有字段可选，但更新时不能为空字符串。
3.  需要支持多态的事件处理。

### 代码实现

```csharp
using System.Collections.Generic;
using System.Text.Json.Serialization;

// 1. 基础基类（用于多态）
public record ApiRequest;

// 2. 创建用户请求（C# 11 required）
public record CreateUserRequest : ApiRequest
{
    public string Name { get; init; } = required;
    public string Email { get; init; } = required;
    public List<string> Roles { get; init; } = []; // 默认空列表
}

// 3. 更新用户请求（可选，但需校验）
public record UpdateUserRequest : ApiRequest
{
    public string? Name { get; init; }
    public string? Email { get; init; }
    
    // 自定义验证逻辑
    public void Validate()
    {
        if (Name == string.Empty) throw new ArgumentException("Name cannot be empty");
    }
}

// 4. 事件处理（模式匹配）
public record Event;
public record UserCreatedEvent(string UserId) : Event;
public record UserDeletedEvent(string UserId) : Event;

public class EventHandler
{
    public void Handle(Event e)
    {
        // 模式匹配处理
        switch (e)
        {
            case UserCreatedEvent { UserId: var id } when id.Length > 5:
                Console.WriteLine($"New long user: {id}");
                break;
            case UserCreatedEvent:
                Console.WriteLine("New user created");
                break;
            case UserDeletedEvent { UserId: var id }:
                Console.WriteLine($"User deleted: {id}");
                break;
        }
    }
}
```

### 分析
1.  **`required`** 确保了 `CreateUserRequest` 在创建时数据完整。
2.  **`List<string> Roles = []`** 避免了空引用异常（Null Reference）。
3.  **`switch` 表达式** 清晰地区分了不同的事件类型，无需 `if (e is UserCreatedEvent)` 嵌套。

## 五、常见陷阱与避坑指南

### 继承中的 `Equals` 性能
如果继承链过深，`Equals` 方法会递归调用每一层。对于包含大量属性的深层继承 `record`，性能会有轻微损耗。
*   **建议**：保持继承层级扁平。如果不需要多态，尽量使用组合（Composition）而非继承。

### `required` 与 反序列化
`System.Text.Json` 默认支持 `required`，但如果你使用 `Newtonsoft.Json`，需要额外配置 `JsonPropertyName` 和 `Required` 属性。
*   **建议**：优先使用 `System.Text.Json` 以获得最佳原生支持。

### 模式匹配的穷尽性检查
在 `switch` 表达式中，如果未覆盖所有情况，编译器会警告。但在 `switch` 语句中，如果没有 `default` 分支，编译器可能不会报错（取决于版本）。
*   **建议**：始终使用 `switch` **表达式**（返回值的）并加上 `_` 兜底，确保逻辑完整。

### 记录继承与 `IEquatable<T>`
如果你手动实现了 `IEquatable<T>`，请确保它符合 `record` 的默认行为，否则会导致 `HashSet` 或 `Dictionary` 行为异常。
*   **建议**：除非有极特殊需求，否则不要手动重写 `Equals` 和 `GetHashCode`，让编译器生成。

通过本文，我们深入到了 `record` 的高级领域：

2.  **模式匹配**：掌握了 `switch` 表达式和属性模式，能够编写声明式的业务逻辑。
3.  **新特性**：利用 `required` 实现了编译时级别的必填校验，利用集合表达式简化了集合操作。

**核心收获**：
`record` 不仅仅是数据容器，它通过**模式匹配**和**新特性**，正在成为 C# 中定义**领域逻辑**和**契约**的首选方式。它让代码更像“声明”，而不是“指令”。

**课后练习**：
1.  定义一个 `Shape` record 继承体系（`Circle`, `Rectangle`），包含面积计算属性。
2.  使用 `switch` 表达式计算不同形状的面积。
3.  定义一个 `LoginRequest` record，使用 `required` 确保用户名和密码必填。
4.  尝试使用 `System.Text.Json` 反序列化一个缺失必填字段的 JSON，观察异常行为。

```cs
using System;
using System.Text.Json;

namespace ModernCSharpDemo;

// ==========================================
// 1. 定义 Shape record 继承体系，包含面积计算属性
// ==========================================
public abstract record Shape
{
    // 定义抽象的面积计算属性
    public abstract double Area { get; }
}

// Circle 继承 Shape，使用主构造函数
public record Circle(double Radius) : Shape
{
    // 实现面积计算属性
    public override double Area => Math.PI * Radius * Radius;
}

// Rectangle 继承 Shape
public record Rectangle(double Width, double Height) : Shape
{
    // 实现面积计算属性
    public override double Area => Width * Height;
}

// ==========================================
// 3. 定义 LoginRequest record，使用 required
// ==========================================
public record LoginRequest
{
    // 使用 required 关键字确保在对象初始化时必须赋值
    public required string Username { get; init; }
    public required string Password { get; init; }
}

class Program
{
    static void Main()
    {
        Console.WriteLine("--- 1 & 2: Shape Record 与 Switch 表达式 ---");

        Shape myCircle = new Circle(5);
        Shape myRectangle = new Rectangle(4, 5);

        Console.WriteLine($"圆的面积: {CalculateAreaWithSwitch(myCircle):F2}");
        Console.WriteLine($"矩形的面积: {CalculateAreaWithSwitch(myRectangle)}");


        Console.WriteLine("\n--- 3 & 4: required 关键字与 JSON 反序列化 ---");

        // 模拟一个缺失了必填字段 "Password" 的 JSON 字符串
        string invalidJson = """
        {
            "Username": "admin"
        }
        """;

        Console.WriteLine($"尝试反序列化 JSON: {invalidJson}");

        try
        {
            // 4. 尝试反序列化缺失必填字段的 JSON
            var request = JsonSerializer.Deserialize<LoginRequest>(invalidJson);
            Console.WriteLine("反序列化成功！(这行不会被打印)");
        }
        catch (JsonException ex)
        {
            // 观察异常行为
            Console.ForegroundColor = ConsoleColor.Red;
            Console.WriteLine("\n[捕获到 JSON 异常]");
            Console.WriteLine(ex.Message);
            Console.ResetColor();
        }
    }

    // ==========================================
    // 2. 使用 switch 表达式计算不同形状的面积
    // ==========================================
    static double CalculateAreaWithSwitch(Shape shape)
    {
        // 使用 C# 的模式匹配 (Pattern Matching) 与 switch 表达式
        return shape switch
        {
            // 方式 A：直接调用多态的 Area 属性
            Circle c => c.Area,

            // 方式 B：展示解构(Destructuring)模式，直接在 switch 中提取属性计算
            Rectangle(var w, var h) => w * h,

            // 弃元模式，处理未知形状或 null
            _ => throw new ArgumentException("未知的形状类型", nameof(shape))
        };
    }
}
```
