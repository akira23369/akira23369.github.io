# 数组拷贝：CopyTo()与Clone()

在 C# 中，复制数组是一个极其常见的操作。`System.Array` 基类为此提供了两个主要的方法：`CopyTo()` 和 `Clone()`。虽然它们的目的都是复制数组，但在调用方式、行为表现和底层机制上有着显著的区别。

理解这两者的差异，特别是理解**浅拷贝（Shallow Copy）** 的本质，是避免 C# 内存管理陷阱的关键。

## 核心差异对比：CopyTo() vs Clone()

根据《CLR via C#》的解析，这两个方法在内存分配策略和目标受众上完全不同。

### CopyTo() 方法
*   **职责：** 将数据从一个**已经存在**的源数组，复制到一个**已经存在**的目标数组中。
*   **前提条件：** 目标数组必须已经被实例化，且其长度必须大于或等于（如果指定了偏移量，则需要加上偏移量）源数组的长度。否则会抛出 `ArgumentException`。
*   **灵活性：** 允许指定**起始索引（Start Index）**。这意味着你可以把源数组的数据“插入”到目标数组的中间位置。
*   **返回值：** `void`（不返回新数组，只修改现有的目标数组）。
*   **类型安全：** 强类型操作，不需要类型转换（Type Casting）。

### Clone() 方法
*   **职责：** 快速创建一个与源数组**完全一样大小**的**全新**数组，并将数据复制过去。
*   **前提条件：** 无需提前准备目标数组。`Clone()` 会自己在托管堆上分配新内存。
*   **灵活性：** 极低。不能指定起始索引，克隆出来的新数组的大小和元素顺序与源数组绝对一致。
*   **返回值：** 返回一个 `System.Object` 类型。因为 `Clone` 方法定义在非泛型的 `ICloneable` 接口中。
*   **类型安全：** 弱类型。调用后**必须强制向下转型（Downcasting）** 才能赋值给强类型的数组变量。

### 代码对比示例
```csharp
using System;

public class Program
{
    public static void Main()
    {
        int[] sourceArray = { 1, 2, 3 };

        // --- 使用 CopyTo() ---
        // 1. 必须提前创建目标数组 (容量可以更大)
        int[] targetArray1 = new int[5]; 
        
        // 2. 将数据复制到目标数组，从目标数组的索引 2 开始存放
        sourceArray.CopyTo(targetArray1, 2); 
        // 此时 targetArray1: { 0, 0, 1, 2, 3 }

        // --- 使用 Clone() ---
        // 1. 直接克隆，必须显式转换为 int[]
        int[] targetArray2 = (int[])sourceArray.Clone(); 
        // 此时 targetArray2: { 1, 2, 3 }
    }
}
```

## 深度陷阱：浅拷贝的本质

不论是 `CopyTo()` 还是 `Clone()`，它们在底层执行的都是**浅拷贝（Shallow Copy）**。这是 C# 初学者最容易踩坑的地方（特别是在《Effective C#》中被重点强调）。

要理解浅拷贝，必须区分数组内部存储的是**值类型**还是**引用类型**。

### 复制值类型数组 (如 int[])
如果数组里存的是值类型，浅拷贝会把每个元素的值（内存中的二进制位）原封不动地复制一份到新数组中。
**结果：** 两个数组彼此完全独立。修改其中一个数组的元素，**不会**影响另一个。

### 复制引用类型数组 (如 class)
如果数组里存的是自定义的类（Class，引用类型），数组的内存槽中实际存储的仅仅是**指向托管堆中对象的内存地址（指针 / References）**。

当执行浅拷贝时，`CopyTo()` 或 `Clone()` 仅仅复制了这些**内存地址**。
**结果：** 原数组和新数组内部的指针，**指向了托管堆中同一个共享的对象**。

### 代码实战：揭示浅拷贝陷阱
```csharp
using System;

public class Employee
{
    public string Name { get; set; }
}

public class Program
{
    public static void Main()
    {
        // 1. 创建源数组
        Employee[] teamA = new Employee[2];
        teamA[0] = new Employee { Name = "Alice" };
        teamA[1] = new Employee { Name = "Bob" };

        // 2. 使用 Clone() 进行浅拷贝
        Employee[] teamB = (Employee[])teamA.Clone();

        // 3. 陷阱演示：修改源数组中的对象状态
        // 我们通过 teamA 修改了 Alice 的名字
        teamA[0].Name = "Alice_Changed";

        // 4. 验证目标数组
        // teamB 里的 Alice 名字也跟着变了！
        // 因为 teamA[0] 和 teamB[0] 指向的是内存中的同一个 Employee 对象。
        Console.WriteLine(teamB[0].Name); // 输出: Alice_Changed
        
        // ---------------------------------------------------------
        // 补充说明：替换整个对象的引用是安全的
        // 如果把 teamA 的第一个槽位换成一个全新的对象
        teamA[0] = new Employee { Name = "Charlie" };
        
        // 这时 teamB[0] 不受影响，它仍然指向旧的 Alice_Changed 对象
        Console.WriteLine(teamB[0].Name); // 输出: Alice_Changed
    }
}
```

## 总结与架构建议

1.  如果你只需要把一个数组原封不动地复制一份，且数组内部是基本值类型（如 `int`, `double`），使用 `Clone()` 是最方便的。
2.  如果你需要将数据追加、插入到一个已经存在的大数组中，必须使用 `CopyTo()`（或者静态方法 `Array.Copy()`，它提供了更细粒度的控制，如复制指定长度的元素）。
3.  **极度警告：** 如果数组包含引用类型，并且你希望修改新数组中的对象属性而不影响老数组，`CopyTo()` 和 `Clone()` 都无法满足需求。你必须自己实现**深拷贝（Deep Copy）**，即遍历源数组，针对每个元素手动 `new` 一个新对象并赋值，或者依赖序列化（如 JSON 序列化）来完成对象的深度克隆。
