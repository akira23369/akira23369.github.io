# 交错数组

在上一节我们提到过多维数组（`[,]`），它是一个严格的矩形矩阵。但在很多现实场景中，数据的结构并不是完美对称的。为了处理这种“不规则”的数据集合，C# 提供了**交错数组（Jagged Arrays）**。

## 核心概念：数组的数组

交错数组的本质是 **“数组的数组”**。
在交错数组中，它的每一个元素本身又是一个独立的数组。因为每个子数组都是独立实例化的，所以**它们的长度可以完全不同**。这在视觉上形成了一个长短不一的“交错”或“锯齿状（Jagged）”的结构。

*   **声明语法：** 使用连续的空方括号（例如 `int[][]`）。
*   **内存分配：** 交错数组本身是一个一维数组，里面存储的是指向其他一维数组的引用（指针）。

## 声明、实例化与初始化

初始化交错数组时，**只能指定第一维（行）的长度**，不能在最外层直接指定第二维（列）的长度，因为每一行的列数可能是不同的。

**代码示例：交错数组的创建**

```csharp
// 1. 声明并指定行数（包含 3 行）
// 注意：此时只分配了存放 3 个数组引用的内存，内部的数组还未实例化（全为 null）
int[][] jaggedArray = new int[3][];

// 2. 必须为每一行分别实例化其内部的数组
jaggedArray[0] = new int[2]; // 第 0 行有 2 个元素
jaggedArray[1] = new int[4]; // 第 1 行有 4 个元素
jaggedArray[2] = new int[3]; // 第 2 行有 3 个元素

// 3. 赋值
jaggedArray[0][0] = 10;
jaggedArray[0][1] = 20;

// ----------------------------------------------------
// 极简语法糖：声明并直接内联初始化
int[][] scores = new int[][]
{
    new int[] { 85, 90 },             // 长度为 2
    new int[] { 70, 75, 80, 85 },     // 长度为 4
    new int[] { 95 }                  // 长度为 1
};
```

## 遍历交错数组

由于交错数组本质上是一维数组的嵌套，遍历时需要使用嵌套的 `for` 循环。
关键在于：**内层循环的长度必须通过当前行的 `.Length` 属性来动态获取。**

```csharp
using System;

public class Program
{
    public static void Main()
    {
        int[][] jagged = new int[][]
        {
            new int[] { 1, 2 },
            new int[] { 3, 4, 5, 6 },
            new int[] { 7, 8, 9 }
        };

        // 外层循环：遍历外层数组（即行数）
        for (int i = 0; i < jagged.Length; i++)
        {
            Console.Write($"Row {i}: ");
            
            // 内层循环：获取当前行 (jagged[i]) 的实际长度
            for (int j = 0; j < jagged[i].Length; j++)
            {
                // 使用双重方括号 [i][j] 进行寻址
                Console.Write($"{jagged[i][j]} ");
            }
            Console.WriteLine();
        }
    }
}
```

## 深度对比与性能考量
参考《CLR via C#》与《Effective C#》

在 C# 架构设计中，交错数组 `[][]` 和多维数组 `[,]` 经常被拿来比较。理解它们的底层差异是写出高性能代码的关键。

| 特性 | 交错数组 (Jagged `[][]`) | 多维数组 (Multidimensional `[,]`) |
| :--- | :--- | :--- |
| **数据结构** | 数组的引用数组（长短不一） | 单一连续内存块（严格的矩形） |
| **内存布局** | 离散的。外层数组和各内层数组分散在托管堆的不同位置。 | 连续的。所有元素紧密排列在托管堆的一整块内存中。 |
| **执行性能 (速度)** | **极快**。被 CLR 视为普通一维数组（SZArray），享有专用的 IL 指令优化和边界检查消除优化。 | 较慢。需要底层的偏移量计算公式，且 JIT 优化较难生效。 |
| **内存开销 (空间)** | 较大。除了数据本身，每个子数组都有额外的对象头（Type Pointer 和 Sync Block Index）开销。 | 极小。只有一个对象头。 |

**最佳实践建议**

在《Effective C#》中，推荐：**在绝大多数情况下，应当优先使用交错数组 `[][]`（或者 `List<List<T>>`），而不是多维数组 `[,]`。**

1.  **性能优势：** 尽管交错数组由于对象头的原因会浪费一点点内存，但在绝大多数企业应用中，CPU 的执行速度比微小的内存消耗更重要。交错数组享受了 CLR 对一维数组的终极性能优化。
2.  **灵活性：** 交错数组允许动态替换整行数据（例如：`jagged[0] = newArray;`），而多维数组是刚性的，无法单独替换某一行。
3.  **CLS 兼容性：** 并非所有的 .NET 语言都支持多维数组（例如早期的某些语言规范），但交错数组是公共语言规范（CLS）完全兼容的，跨语言调用时更安全。
