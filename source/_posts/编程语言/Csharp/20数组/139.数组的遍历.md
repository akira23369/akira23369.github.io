# 遍历数组：使用 for 循环

在 C# 中，虽然我们可以通过硬编码索引（如 `arr[0]`, `arr[1]`）来逐个访问数组元素，但这在实际开发中是不可行的。当数组的长度未知或者可能在未来发生变化时，硬编码会导致代码极其脆弱且难以维护。

为了动态、安全地遍历数组中的所有元素，最经典且性能最高的方式就是使用 **`for` 循环**。

## 核心结构与边界控制

使用 `for` 循环遍历数组的黄金准则是：**利用数组的 `.Length` 属性来控制循环的边界。**

**标准 for 循环解剖**
```csharp
for (int i = 0; i < array.Length; i++)
{
    // 使用 array[i] 访问元素
}
```

*   **初始化 (`int i = 0`)：** 数组的索引永远从 `0` 开始，因此循环变量 `i` 的初始值设定为 `0`。这个变量 `i` 的作用域被严格限制在 `for` 循环的代码块 `{ }` 内。
*   **循环条件 (`i < array.Length`)：** 这是最关键的一步。因为合法索引的范围是 `0` 到 `Length - 1`。使用严格小于号 `<` 可以完美保证当 `i` 等于数组长度时循环会终止，从而避免抛出 `IndexOutOfRangeException`。
    *   *注：新手常犯的错误是写成 `i <= array.Length`。由于长度为 5 的数组最大索引只有 4，当 `i` 等于 5 时去访问 `array[5]` 会直接导致程序崩溃。*
*   **迭代器 (`i++`)：** 每次循环结束时，将索引值加 1，移动到下一个元素。

## 代码重构对比：硬编码 vs for 循环

通过对比可以直观看出 `for` 循环在处理集合数据时的绝对优势。

**糟糕的做法：硬编码访问**
如果我们在未来将数组扩展为包含 100 个元素，这种写法需要手动添加 95 行 `Console.WriteLine`，这违背了代码的开闭原则（OCP）。
```csharp
int[] numbers = { 10, 20, 30, 40, 50 };

Console.WriteLine(numbers[0]);
Console.WriteLine(numbers[1]);
Console.WriteLine(numbers[2]);
Console.WriteLine(numbers[3]);
Console.WriteLine(numbers[4]);
```

**优雅的做法：for 循环遍历**
无论数组中有 5 个元素还是 500 万个元素，这段代码都不需要做任何修改。
```csharp
int[] numbers = { 10, 20, 30, 40, 50 };

// i 表示当前正在访问的索引
for (int i = 0; i < numbers.Length; i++)
{
    Console.WriteLine($"索引 {i} 的值为: {numbers[i]}");
}
```

## 进阶探讨：性能与 JIT 优化

在 C# 中，使用标准的 `for` 循环遍历数组（即条件严格写为 `i < array.Length` 且在循环体内使用 `array[i]`）不仅是规范的写法，还能获得**极致的性能优化**。

通常情况下，每次执行 `array[i]` 时，CLR 都会执行一次边界检查，以确保 `i` 没有越界。但 .NET 的 JIT（即时编译器）非常智能，当它识别到以下标准模式时：
`for (int i = 0; i < array.Length; i++)`
JIT 编译器能从数学逻辑上断定：在整个循环过程中，`i` 绝对不可能小于 `0`，也绝对不可能大于或等于 `array.Length`。

因此，**JIT 会在编译生成的机器码中彻底移除针对该数组的内部边界检查。** 这使得 C# 在遍历数组时的性能可以与 C/C++ 媲美。


**破坏 JIT 优化的反模式：**
如果你用非标准的写法来控制循环，JIT 将无法进行上述优化，从而导致每次访问数组时都会产生边界检查的性能开销：

```csharp
// 糟糕的写法 1：将长度提取到外部变量。JIT 无法保证 length 在循环内部不被改变。
int length = numbers.Length;
for (int i = 0; i < length; i++) { ... }

// 糟糕的写法 2：使用了复杂的边界计算
for (int i = 0; i <= numbers.Length - 1; i++) { ... }
```

## for 循环的扩展应用场景

虽然下一节会介绍更简单的 `foreach` 循环，但 `for` 循环在以下场景中仍然是**不可替代**的：

1.  **需要修改数组中的元素：** `for` 循环允许你重新赋值，如 `numbers[i] = numbers[i] * 2;`。
2.  **需要跳跃遍历：** 例如只遍历偶数索引 `for (int i = 0; i < arr.Length; i += 2)`。
3.  **需要倒序遍历：** `for (int i = arr.Length - 1; i >= 0; i--)`。
4.  **需要同时访问多个平行的数组。**



# 遍历数组：使用 foreach 循环

在 C# 中，遍历集合和数组最优雅且最具可读性的方式是使用 `foreach` 循环。它通过极简的语法隐藏了底层迭代的复杂性，使开发者能够将注意力集中在业务逻辑上。

## 核心概念与语法结构

`foreach` 循环专为**从头到尾、顺序遍历**集合而设计。与 `for` 循环不同，它不需要显式声明索引变量，也不需要控制边界和步长。

**标准语法解剖**
```csharp
int[] numbers = { 10, 20, 30, 40, 50 };

// 语法：foreach (数据类型 迭代变量 in 目标数组)
foreach (int item in numbers)
{
    Console.WriteLine(item);
}
```
*   **迭代变量 (`item`)：** 在每次循环迭代时，数组中的当前元素会被赋值给该变量。它的作用域仅限于 `foreach` 循环块内部。
*   **类型推断：** 在现代 C# 中，通常建议使用 `var` 关键字来代替显式的数据类型声明（如 `foreach (var item in numbers)`），让编译器自动推断类型。

## 深度辟谣：foreach 遍历数组的性能问题 (CLR 视角)

很多初学者甚至部分教程会认为：“`foreach` 循环底层使用了迭代器（`IEnumerator`），因此在遍历数组时性能比 `for` 循环慢”。**这是一个普遍的误解。**

根据《CLR via C#》和《C# in a Nutshell》中对编译器行为的深度剖析：
在 C# 中，编译器针对**一维从零开始的数组（SZArray）** 进行了极其深度的特化优化。

当你编写一个针对数组的 `foreach` 循环时，C# 编译器在底层**并不会**生成调用 `IEnumerable` 或 `IEnumerator` 的 IL（中间语言）代码。相反，**编译器会直接将其翻译为一个标准的 `for` 循环。**

```csharp
// 你写的 C# 代码：
foreach (int item in numbers) { Console.WriteLine(item); }

// 编译器底层实际生成的 IL 等效逻辑：
for (int i = 0; i < numbers.Length; i++) 
{ 
    int item = numbers[i];
    Console.WriteLine(item); 
}
```
**结论：** 对于原生数组而言，`foreach` 和 `for` 循环在运行时的**性能是完全一模一样的**。没有任何额外的内存分配，也没有虚方法调用的开销。

*(注：如果遍历的是 `List<T>` 或自定义集合，`foreach` 确实会获取枚举器对象，但对于数组，编译器做了特殊豁免。)*

## foreach 的严格约束：只读性

《Effective C#》中强调了 `foreach` 循环的一个重要安全设计：**迭代变量是只读的。**

在 `foreach` 循环体内，你不能修改迭代变量的值。如果你需要修改数组中的元素，必须使用 `for` 循环通过索引进行重新赋值。

```csharp
int[] scores = { 80, 90, 100 };

foreach (int score in scores)
{
    // 编译错误：不能向 'foreach' 迭代变量赋值，因为它是一个只读变量
    // score = score + 5; 
}

// 如果需要修改，必须使用 for 循环
for (int i = 0; i < scores.Length; i++)
{
    scores[i] = scores[i] + 5; // 正确：通过索引修改数组内存中的原始值
}
```

## 场景抉择：foreach vs for

在实际开发中，应该根据具体的业务需求在两者之间做出选择。

### 优先使用 `foreach` 的场景：
1.  **全量顺序遍历：** 需要从头到尾读取数组的每一个元素。
2.  **追求代码可读性：** 语法更干净，没有繁琐的边界条件，天然避免了 `IndexOutOfRangeException`（越界异常）。

### 必须使用 `for` 循环的场景：
由于 `foreach` 的设计极其封闭，它放弃了灵活性。如果遇到以下需求，必须退回使用 `for` 循环：

1.  **需要知道当前元素的索引：** 比如需要打印“第 N 名学生的成绩”。
2.  **局部遍历：** 只需要遍历数组的前一半，或者跳过某些特定索引。
3.  **跳跃遍历：** 需要每隔 2 个元素读取一次（`i += 2`）。
4.  **倒序遍历：** 从数组尾部向头部遍历。
5.  **修改元素：** 需要直接修改数组中某个位置的值。

### 代码实战：使用 for 循环实现倒序遍历
```csharp
string[] names = { "Alice", "Bob", "Charlie", "David" };

// 倒序遍历：起始值为 Length - 1，结束条件为 >= 0，步长为递减
for (int i = names.Length - 1; i >= 0; i--)
{
    Console.WriteLine($"倒序输出: {names[i]}");
}
// 输出顺序为: David, Charlie, Bob, Alice
```

## 最佳实践总结

《代码大全》提倡“使用最能表达意图的结构”。
在处理数组或集合时，**默认首选 `foreach`**。它能极其清晰地向阅读代码的人传达：“我只是想把这里面的所有东西过一遍”。只有当 `foreach` 无法满足特殊需求（如修改、倒序、多维数组的复杂寻址）时，才考虑使用原生的 `for` 循环。
