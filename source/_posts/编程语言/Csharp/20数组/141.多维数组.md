# 多维数组

在 C# 中，数组不仅可以是线性的（一维），还可以扩展到多维空间。虽然多维数组在现代企业级应用中不如泛型集合（如 `List<T>`）常见，但在图形学处理、矩阵运算或科学计算等特定领域，它们依然是不可或缺的数据结构。

## 核心概念与严格的术语纠正

必须在概念上做一个极其严格的区分（参考《C# 核心技术指南 / C# in a Nutshell》）：
*   **多维数组 (Multidimensional Arrays)：** 使用逗号 `,` 声明（如 `int[,]`）。它在内存中是一个**严格的矩形矩阵 (Rectangular Array)**，每一行必须具有完全相同数量的列。它是一块连续分配的内存。
*   **交错数组 (Jagged Arrays)：** 使用多个方括号声明（如 `int[][]`）。它才是真正的“数组的数组”，每一行可以是一个长度完全不同的独立数组。

## 声明、实例化与初始化

多维数组的维度由方括号内的**逗号数量**决定：
*   1 个逗号 `[,]` 代表二维数组（矩阵：行 x 列）。
*   2 个逗号 `[,,]` 代表三维数组（立体：X x Y x Z）。
*   N 个逗号代表 N+1 维数组。

**代码示例：二维数组的创建与初始化**

```csharp
// 1. 仅声明并分配内存 (4 行，3 列的矩阵，共 12 个元素，默认全为 0)
int[,] matrix1 = new int[4, 3];

// 2. 声明并同时初始化 (编译器会自动推断尺寸为 3行 x 3列)
int[,] matrix2 = new int[,]
{
    { 10, 20, 30 }, // 第 0 行
    { 40, 50, 60 }, // 第 1 行
    { 70, 80, 90 }  // 第 2 行
};

// 3. 极简语法糖
int[,] matrix3 = 
{
    { 1, 2 },
    { 3, 4 },
    { 5, 6 }
};
```
*注意：在初始化多维数组时，内部嵌套的每个 `{ }` 代表一行，且每个大括号内包含的元素数量必须绝对一致，否则会导致编译错误。*

## 遍历多维数组 (最佳实践)

在遍历多维数组时，绝不能像一维数组那样简单地使用 `.Length` 属性（因为多维数组的 `.Length` 返回的是**所有维度元素的总和**，例如一个 4x3 的数组，`.Length` 是 12）。

为了安全且动态地遍历多维数组，必须使用 `System.Array` 提供的 **`GetLength(int dimension)`** 方法来获取特定维度的长度。
*   `GetLength(0)`：获取第一维（行）的长度。
*   `GetLength(1)`：获取第二维（列）的长度。

### 代码示例：标准嵌套 for 循环遍历

```csharp
using System;

public class Program
{
    public static void Main()
    {
        int[,] grid = 
        {
            { 11, 12, 13 },
            { 21, 22, 23 },
            { 31, 32, 33 },
            { 41, 42, 43 }
        };

        // 获取行数 (第一维的长度)
        int rows = grid.GetLength(0); 
        // 获取列数 (第二维的长度)
        int cols = grid.GetLength(1); 

        // 外层循环：遍历每一行
        for (int i = 0; i < rows; i++)
        {
            // 内层循环：遍历当前行的每一列
            for (int j = 0; j < cols; j++)
            {
                // 使用 [i, j] 语法通过横纵坐标精准寻址
                Console.Write($"{grid[i, j]} \t");
            }
            // 每打印完一行后换行
            Console.WriteLine();
        }
    }
}
```

## 底层性能剖析

在实际的业务开发中，我们极少使用 `[,]` 这样的多维数组，通常会优先使用 `List<T>` 或者交错数组 `[][]`。这不仅是因为集合的灵活性更高，更是出于**底层性能**的考量。

《CLR via C#》中对数组底层的分析指出：
1.  **一维从零开始的数组 (SZArray)：** CLR 为这种最常见的一维数组（如 `int[]`）提供了极其深度的特化优化，使用了专门的 IL 指令（如 `newarr`, `ldelem`, `stelem`），且 JIT 编译器能够轻松消除其边界检查，性能达到极致。
2.  **多维数组 (MDArray)：** 对于 `int[,]` 这样的多维数组，CLR 并没有提供专用的 IL 指令。每次访问 `grid[i, j]` 时，底层都需要调用计算方法来计算真实的内存偏移量：`(i * 每行元素数) + j`，并且 JIT 编译器在多维数组上进行边界检查消除（Bounds Check Elimination）的难度极大。

**架构设计建议：** 
如果对性能有极其严苛的要求，或者不确定每行的数据是否一样长，建议使用**交错数组 (Jagged Arrays，即 `int[][]`)** 代替多维数组。交错数组本质上是一个一维数组（SZArray），其元素是另一个一维数组的引用，因此能够享受到 CLR 针对一维数组的所有底层优化。
