# OrderBy (升序排序)
## 方法名与分类
*   **方法名**：`OrderBy` （同族包含 `OrderByDescending` 降序、`ThenBy` 次级升序、`ThenByDescending` 次级降序）
*   **分类**：排序操作符 (Sorting / Ordering)

## 签名
`OrderBy` 方法有两个常用的重载版本：
*   **默认比较版本：根据指定的键进行升序排序**
```csharp
public static IOrderedEnumerable<TSource> OrderBy<TSource, TKey>(
    this IEnumerable<TSource> source, 
    Func<TSource, TKey> keySelector // 指定按什么字段/条件排序
);
```
*   **参数**：`keySelector` 是一个提取排序键的委托。比如传入 `u => u.Age` 表示按年龄排序。
*   **返回**：`IOrderedEnumerable<TSource>`。注意它返回的是一个特殊的接口，这个接口允许你继续链式调用 `ThenBy` 进行多级排序。

*   **自定义比较器版本：使用指定的规则比较**
```csharp
public static IOrderedEnumerable<TSource> OrderBy<TSource, TKey>(
    this IEnumerable<TSource> source, 
    Func<TSource, TKey> keySelector, 
    IComparer<TKey> comparer // 传入自定义的比较规则
);
```
*   **参数**：`comparer` 决定了键值大小的比较方式（如：特定文化的字符串比较，或特殊业务规则大小比较）。

## 核心逻辑
*   **执行方式：延迟执行 (Deferred Execution)**。但需要特别注意的是，它是**非流式 (Non-streaming)** 的。这意味着在开始遍历结果集之前，它必须把原集合的所有元素都读入内存并完成排序。
*   **是否短路：否**。排序必须统筹全局，无法短路。
*   **排序稳定性：是稳定排序 (Stable Sort)**。如果两个元素的排序键相等，它们在排序后的集合中**将保持与原集合相同的先后顺序**。（注意：这与 `List<T>.Sort()` 的不稳定排序不同）。

## 实战代码
**场景 1：基础单级排序（正序与降序）**
```csharp
var numbers = new List<int> { 5, 2, 8, 1, 9 };

// 正序 (从小到大): 1, 2, 5, 8, 9
var ascending = numbers.OrderBy(n => n); 

// 降序 (从大到小): 9, 8, 5, 2, 1
var descending = numbers.OrderByDescending(n => n); 
```

**场景 2：对象按属性排序**
```csharp
class Employee { public string Name; public int Salary; }

var employees = new List<Employee>
{
    new Employee { Name = "Alice", Salary = 8000 },
    new Employee { Name = "Bob", Salary = 12000 },
    new Employee { Name = "Charlie", Salary = 5000 }
};

// 找出工资最低的员工排在前面
var sortedBySalary = employees.OrderBy(e => e.Salary);
```

**场景 3：多级排序（先按部门排，部门内部按工资降序排）**
```csharp
// 注意：第二级排序必须用 ThenBy 或 ThenByDescending！
var multiSorted = employees
    .OrderBy(e => e.Department)            // 第一级：部门首字母升序
    .ThenByDescending(e => e.Salary);      // 第二级：同部门内，工资降序
```

## 避坑/性能指南
**致命避坑 1：连续使用两个 `OrderBy` 会覆盖排序结果**
*   **现象**：新手想实现“先按A排序，再按B排序”，写成了 `list.OrderBy(x => x.A).OrderBy(x => x.B)`。
*   **后果**：第二个 `OrderBy` 会**彻底打乱并覆盖**第一个 `OrderBy` 的结果。最终结果等同于只写了 `OrderBy(x => x.B)`。
*   **正确做法**：第一级排序后，后续的所有级别**必须**使用 `ThenBy` 或 `ThenByDescending`。

**致命避坑 2：为了获取最大/最小值而滥用排序**
*   **现象**：需要找集合中工资最高的人，写成了 `employees.OrderByDescending(e => e.Salary).First()`。
*   **后果**：极大的性能浪费！`OrderBy` 的时间复杂度是 **O(N log N)**，还要分配额外内存来缓存整个集合。
*   **正确做法**：如果仅仅是为了找最值，请使用 `Max()` / `Min()` 或者 `MaxBy()` / `MinBy()`（.NET 6+ 支持）。它们的时间复杂度是 **O(N)** 且无需额外内存。
    ```csharp
    // .NET 6 之前的极速写法：自定义循环 或 借助聚合函数
    // .NET 6+ 的优雅极速写法：
    var richest = employees.MaxBy(e => e.Salary); 
    ```

**性能指南：数据库查询 (IQueryable) 中的 OrderBy**
*   当 `OrderBy` 用于 EF Core 或其他 ORM 时，它会被翻译成 SQL 的 `ORDER BY` 语句。
*   如果不加 `OrderBy`，数据库返回的数据顺序是**不可预测的**。如果你在使用 `.Skip().Take()` 做分页，**必须**在分页前加上 `OrderBy`，否则翻页时会出现数据重复或丢失的严重 Bug。
