# Min / Max (最小值与最大值)
## 方法名与分类
*   **方法名**：`Min` / `Max`
*   **分类**：聚合操作符

## 签名
`Min` 和 `Max` 的用法完全对称，底层有很多针对具体数值类型（如 `int`, `double`, `decimal`）的重载以优化性能。最核心的泛型签名有两个版本：

*   **无参版本：直接获取集合中的最小/最大值**
```csharp
// 要求 TSource 必须实现 IComparable 接口（大多数基础类型都实现了）
public static TSource Min<TSource>(this IEnumerable<TSource> source);
public static TSource Max<TSource>(this IEnumerable<TSource> source);
```
*   **参数**：仅扩展当前集合本身。
*   **返回**：集合中的最小或最大元素。

*   **带选择器 (Selector) 版本：获取集合元素中某个指定属性的最小/最大值**
```csharp
public static TResult Min<TSource, TResult>(
    this IEnumerable<TSource> source, 
    Func<TSource, TResult> selector // 提取要比较的值
);
// Max 同理
```
*   **参数**：`selector` 是一个委托，用于把集合中的复杂对象映射/提取为一个可比较的值（例如 `u => u.Age`）。
*   **返回**：提取出的属性的最小/最大值。

## 核心逻辑
*   **执行方式：立即执行**。
*   **是否短路：否**。为了找出真正的最值，必须完整遍历整个集合，时间复杂度为 **O(N)**。
*   **空集处理**：**（极度重要！）** 
    *   如果提取的值是**不可为空的值类型**（如 `int`, `double`, `DateTime`），对空集调用 `Min`/`Max` 会**直接抛出 `InvalidOperationException`** (Sequence contains no elements)。
    *   如果提取的值是**引用类型或可空值类型**（如 `string`, `int?`），对空集调用会**返回 `null`**。

## 实战代码
**场景 1：基础用法（获取基础集合的最值）**
```csharp
int[] temperatures = { 32, 15, 40, -5, 22 };

int highestTemp = temperatures.Max();
int lowestTemp = temperatures.Min();

Console.WriteLine($"最高温: {highestTemp}, 最低温: {lowestTemp}"); 
// 输出: 最高温: 40, 最低温: -5
```

**场景 2：带选择器用法（获取对象集合中某个属性的最值）**
```csharp
class Product { public string Name; public decimal Price; }

var products = new List<Product>
{
    new Product { Name = "鼠标", Price = 50.0m },
    new Product { Name = "键盘", Price = 150.0m },
    new Product { Name = "显示器", Price = 800.0m }
};

// 找出所有商品中的最高价格
decimal maxPrice = products.Max(p => p.Price);

Console.WriteLine($"最贵的价格是: {maxPrice}"); // 输出: 800.0
```

## 避坑/性能指南
**致命避坑 1：空集合引发的“序列不包含任何元素”异常**
*   **现象**：`List<int> emptyList = new List<int>(); emptyList.Max();` 会导致程序崩溃。
*   **正确做法 1（使用 DefaultIfEmpty 保底）**：
    ```csharp
    // 如果集合为空，先给个默认值 0，就不会报错了
    int max1 = emptyList.DefaultIfEmpty(0).Max(); 
    ```
*   **正确做法 2（强转为可空类型，推荐）**：
    ```csharp
    // 把 int 强转为 int?，如果是空集就会返回 null 而不是报错
    int? max2 = emptyList.Max(x => (int?)x); 
    int finalMax = max2 ?? 0; // null 的话自己给个默认值
    ```

**致命避坑 2：想要获取“拥有最大值的那个对象”，而不是“最大值本身”**
*   **现象**：上面的场景 2 中，你拿到了最高价格 `800.0`，但你其实想知道**哪个商品**是 800 块钱（想拿到“显示器”这个对象）。
*   **错误/低效做法**：
    *   `products.OrderByDescending(p => p.Price).First()` （浪费性能去排序，**O(N log N)**）。
    *   `products.Where(p => p.Price == products.Max(x => x.Price)).First()` （遍历了两遍集合，极度低效）。
*   **最佳做法 (.NET 6+)：使用 `MinBy` / `MaxBy`**：
    ```csharp
    // .NET 6 引入的神器，直接返回符合条件的“对象本身”，时间复杂度 O(N) 极速
    Product mostExpensiveProduct = products.MaxBy(p => p.Price);
    
    Console.WriteLine(mostExpensiveProduct.Name); // 输出: 显示器
    ```

- 或者也可以实现`IComparable<Student>`接口然后在.Max();

**性能指南：`Min/Max` 远胜于 `OrderBy().First()`**
*   如上所述，如果你仅仅需要找最大或最小值，**绝对不要使用排序**。`Min` 和 `Max` 在底层只需要记录一个临时变量，遍历一次即可完成（O(N) 时间复杂度，O(1) 空间复杂度），是最优解。
