# Contains(包含特定元素)
## 方法名与分类
*   **方法名**：`Contains`
*   **分类**：量词操作符 (Quantifiers) / 元素判定

## 签名
`Contains` 方法有两个常用的重载版本：
*   **默认比较版本：判断集合中是否包含某个特定值**
```csharp
public static bool Contains<TSource>(
    this IEnumerable<TSource> source, 
    TSource value
);
```
*   **参数**：`value` 是你要在集合中寻找的特定元素。
*   **返回**：`bool`。只要集合中找到与 `value` 相等的元素，就返回 `true`；若没有找到或是空集，返回 `false`。

*   **自定义比较器版本：使用指定的规则比较**
```csharp
public static bool Contains<TSource>(
    this IEnumerable<TSource> source, 
    TSource value, 
    IEqualityComparer<TSource> comparer // 传入自定义的相等比较规则
);
```
*   **参数**：`comparer` 决定了“什么样才算相等”。常用于忽略字符串大小写，或比较自定义对象。

## 核心逻辑
*   **执行方式：立即执行**
*   **是否短路：是**。在遍历过程中，只要遇到**第一个**相等的元素，就会立刻停止遍历并返回 `true`。
*   **空集处理**：直接返回 `false`，不会报错（但如果集合本身是 `null` 会抛出 `ArgumentNullException`）。

## 实战代码
**场景 1：基础用法（检查名单/白名单机制）**
```csharp
int[] validIds = { 101, 204, 309 };

// 检查传入的 ID 是否在白名单中
bool isAuthorized = validIds.Contains(204); 

Console.WriteLine(isAuthorized); // 输出: True
```

**场景 2：使用比较器（忽略字符串大小写的检查）**
```csharp
string[] roles = { "Admin", "Moderator", "User" };

// 默认情况区分大小写，下面会找不到
// bool hasAdmin = roles.Contains("admin"); // 返回 False

// 传入 StringComparer.OrdinalIgnoreCase 忽略大小写
bool hasAdmin = roles.Contains("admin", StringComparer.OrdinalIgnoreCase);

Console.WriteLine(hasAdmin); // 输出: True
```

## 避坑/性能指南
**致命避坑 1：自定义对象的“引用比较”陷阱**
*   **现象**：对于类（引用类型），`Contains` 默认比较的是**内存地址**。如果你 `new` 了一个属性完全相同的对象去查，会返回 `false`。
*   **错误示例**：
    ```csharp
    class User { public int Id; }
    var users = new List<User> { new User { Id = 1 } };
    
    // 返回 False！因为查的是一个新的内存对象
    bool hasUser = users.Contains(new User { Id = 1 }); 
    ```
*   **正确做法**：
    1. 使用 `Any` 代替：`users.Any(u => u.Id == 1)` （**最推荐，代码最简单**）。
    2. 让 `User` 类实现 `IEquatable<User>` 接口并重写 `Equals` 方法。(或者实现`IEqualityComparer<Pet>`接口重写Equals，GetHashCode)

**性能指南 1：`IEnumerable.Contains` (O(N)) vs `HashSet.Contains` (O(1))**
*   **底层逻辑**：针对普通的 `List<T>` 或数组，`Contains` 会从头到尾挨个比对，时间复杂度是 **O(N)**。如果是大数据量且要频繁查询，性能极差。
*   **高级优化**：如果你在一个大循环里频繁调用 `Contains` 检查白名单/黑名单，请**务必先将集合转为 `HashSet<T>`**。
    ```csharp
    List<string> hugeList = GetMillionsOfData();
    
    // 性能极差的写法（如果在循环内这样调用）
    // bool exists = hugeList.Contains(target); 
    
    // 性能极速的写法（先转为哈希表）
    HashSet<string> fastLookup = hugeList.ToHashSet();
    // O(1) 极速查询
    bool exists = fastLookup.Contains(target); 
    ```

**性能指南 2：底层优化机制**
*   和 `Count()` 类似，`Contains` 底层也很聪明。如果它检测到你的集合实现了 `ICollection<T>` 接口（比如 `List<T>`），它会直接调用该集合自身的 `Contains` 方法，而不是使用 LINQ 自己的迭代器，这能省去一小部分开销。
