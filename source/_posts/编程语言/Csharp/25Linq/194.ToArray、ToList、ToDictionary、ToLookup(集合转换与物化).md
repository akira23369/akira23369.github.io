# ToArray / ToList / ToDictionary / ToLookup (集合转换与物化)

## 方法名与分类
*   **方法名**：`ToArray` / `ToList` / `ToDictionary` / `ToLookup`
*   **分类**：转换操作符 (Conversion Operators) / 物化操作符 (Materialization)

## 签名
这四个方法用于将延迟执行的 `IEnumerable<T>` 转换为具体的、驻留在内存中的集合。

*   **线性集合：ToArray / ToList**
```csharp
public static TSource[] ToArray<TSource>(this IEnumerable<TSource> source);
public static List<TSource> ToList<TSource>(this IEnumerable<TSource> source);
```

*   **键值对字典：ToDictionary (一对一)**
```csharp
// 仅指定 Key，Value 默认是元素本身
public static Dictionary<TKey, TSource> ToDictionary<TSource, TKey>(
    this IEnumerable<TSource> source, 
    Func<TSource, TKey> keySelector
);

// 同时指定 Key 和 Value 的提取规则
public static Dictionary<TKey, TElement> ToDictionary<TSource, TKey, TElement>(
    this IEnumerable<TSource> source, 
    Func<TSource, TKey> keySelector, 
    Func<TSource, TElement> elementSelector
);
```

*   **多值字典：ToLookup (一对多)**
```csharp
// 签名与 ToDictionary 几乎一样，但返回值是 ILookup<TKey, TElement>
public static ILookup<TKey, TSource> ToLookup<TSource, TKey>(
    this IEnumerable<TSource> source, 
    Func<TSource, TKey> keySelector
);
```

## 核心逻辑 (极其重要：物化 / 立即执行)
*   **执行方式：全部为 立即执行 (Immediate Execution)**。
    *   这是 LINQ 中**最重要**的转折点！只要调用了这四个方法中的任何一个，LINQ 状态机就会**立刻启动**，从头到尾完整遍历源数据，并把数据**全部拉取到内存中**，构建成对应的数据结构。这在术语上称为“物化 (Materialization)”。
*   **ToDictionary vs ToLookup 的核心区别**：
    *   **`ToDictionary`** 是严格的**一对一**映射。如果你指定的 Key 在源数据中有**重复项**，或者 Key 为 `null`，它会当场**抛出异常**导致程序崩溃。
    *   **`ToLookup`** 是宽容的**一对多**映射。如果 Key 有重复，它会把拥有相同 Key 的所有元素放进一个列表里。它允许 Key 为 `null`。创建后，`ILookup` 是只读的，不能再添加/删除元素。

## 实战代码
**场景 1：防重复求值 (ToList/ToArray 缓存查询结果)**
```csharp
// 假设这是一个耗时的数据库查询或远程 API 调用 (此时并未执行)
IEnumerable<User> query = dbContext.Users.Where(u => u.Age > 18);

// 【物化】立刻触发 SQL 查询，把数据拉到内存的 List 中
List<User> activeUsers = query.ToList(); 

// 后面怎么用 activeUsers 都极快，全是读内存，不会再发 SQL
int count = activeUsers.Count; 
var first = activeUsers.FirstOrDefault();
```

**场景 2：构建 O(1) 极速查询字典 (ToDictionary)**
```csharp
class Employee { public string EmpId; public string Name; public string Dept; }

var emps = new List<Employee> 
{ 
    new Employee { EmpId = "E001", Name = "Alice", Dept = "IT" },
    new Employee { EmpId = "E002", Name = "Bob", Dept = "HR" }
};

// 场景 A：将 ID 作为 Key，对象本身作为 Value
Dictionary<string, Employee> empDict = emps.ToDictionary(e => e.EmpId);
Console.WriteLine(empDict["E001"].Name); // 输出: Alice

// 场景 B：将 ID 作为 Key，仅仅把名字作为 Value 提取出来
Dictionary<string, string> nameDict = emps.ToDictionary(e => e.EmpId, e => e.Name);
Console.WriteLine(nameDict["E002"]); // 输出: Bob
```

**场景 3：按类别分组并构建多值字典 (ToLookup)**
```csharp
var emps2 = new List<Employee> 
{ 
    new Employee { EmpId = "E001", Name = "Alice", Dept = "IT" },
    new Employee { EmpId = "E002", Name = "Bob", Dept = "HR" },
    new Employee { EmpId = "E003", Name = "Charlie", Dept = "IT" } // 注意：Dept 重复了！
};

// 如果用 ToDictionary(e => e.Dept)，因为有两个 "IT"，会直接抛出 ArgumentException 崩溃！

// 完美方案：用 ToLookup，按部门分类，一个部门下有多个人
ILookup<string, Employee> deptLookup = emps2.ToLookup(e => e.Dept);

// 提取 IT 部门的所有人
foreach(var emp in deptLookup["IT"]) 
{
    Console.WriteLine(emp.Name); // 输出: Alice, Charlie
}

// 查找不存在的 Key 不会报错，只会返回一个空的 IEnumerable
int salesCount = deptLookup["Sales"].Count(); // 返回 0
```

## 避坑/性能指南
**致命避坑 1：提前物化引发的性能/内存灾难 (最常见的 EF Core 惨案)**
*   **现象**：
    ```csharp
    // 灾难代码：查出数据库所有 100 万个用户到内存，然后在内存里找叫张三的人
    var target = dbContext.Users.ToList().Where(u => u.Name == "张三").FirstOrDefault();
    ```
*   **危害**：`.ToList()` 写在了 `.Where()` 前面！这会导致 EF Core 执行 `SELECT * FROM Users`（没有任何 WHERE 条件），把几百万条数据全部加载到应用的内存里，瞬间撑爆内存 (OOM)，甚至把数据库 IO 打满。
*   **正确做法**：**永远把 `.ToList()` 或 `.ToArray()` 放在 LINQ 链式调用的【最后面】！**
    ```csharp
    // ✅ 极速代码：翻译成 SELECT TOP 1 ... WHERE Name='张三'
    var target = dbContext.Users.Where(u => u.Name == "张三").FirstOrDefault();
    ```

**致命避坑 2：`ToDictionary` 的“重复键”连环炸弹**
*   **现象**：你以为数据库里的 `UserId` 是唯一的，开心地写下 `.ToDictionary(x => x.UserId)`。几个月后，由于出现了脏数据导致 `UserId` 重复，程序在线上频繁抛出 `ArgumentException: An item with the same key has already been added`。
*   **解决方案**：
**容错保底法 (.NET 6+)**：先去重，再转字典。
```csharp
var safeDict = users.DistinctBy(u => u.UserId).ToDictionary(u => u.UserId);
```
**保留最后一个覆盖法**：不使用 LINQ 的 `ToDictionary`，自己 `foreach`，利用字典索引器的覆盖特性：
```csharp
var dict = new Dictionary<int, User>();
foreach(var u in users) { dict[u.UserId] = u; } // 重复的会被覆盖，绝不报错
```
**转为 ToLookup**：如果你其实需要保留所有的重复项。

**性能指南 1：`ToArray` vs `ToList` 该选哪个？**
*   **选 `ToList()`**：如果你拿到这个集合后，后续**还需要向里面 `Add` 或 `Remove` 元素**，请用 `ToList()`。
*   **选 `ToArray()`**：如果你的集合是**只读的、固定大小的**（仅仅为了把数据固化下来传递给其他方法遍历），请用 `ToArray()`。它的内存开销略小于 `List`（因为 `List` 内部会有预留空间的扩容机制，可能会多占用一些未使用的内存）。

**性能指南 2：`ToLookup` vs `GroupBy`**
*   这两个方法长得几乎一样（功能都是按条件分组），区别在哪？
*   **`GroupBy` 是延迟执行的**。它只创建一个分组的查询计划，直到你真正去 `foreach` 它的结果时，它才开始流式地分组。适合后续紧跟着做聚合计算（如：按部门分组后直接求平均工资，不需要把部门所有人存下来）。
*   **`ToLookup` 是立即执行的**。它会立刻遍历所有数据，在内存中把完整的分组字典树构建出来。适合你需要反复根据 Key 去快速查询某个分组的场景。
