# Sum (求和)
## 方法名与分类
*   **方法名**：`Sum`
*   **分类**：聚合操作符 (Aggregation)

## 签名
与 `Average` 类似，`Sum` 针对所有基础数值类型（`int`, `long`, `float`, `double`, `decimal`）及其可空类型（`int?` 等）提供了重载。

*   **无参版本：直接计算数值集合的总和**
```csharp
// 以 int 和 decimal 为例
public static int Sum(this IEnumerable<int> source);
public static decimal Sum(this IEnumerable<decimal> source);
```
*   **参数**：仅扩展当前集合本身（集合元素必须是数值类型）。
*   **返回**：集合元素的累加总和。返回类型与集合的数值类型保持一致。

*   **带选择器 (Selector) 版本：计算对象集合中某个数值属性的总和**
```csharp
public static int Sum<TSource>(
    this IEnumerable<TSource> source, 
    Func<TSource, int> selector // 提取要累加的数值
);
```
*   **参数**：`selector` 是一个提取数值的委托（例如 `order => order.Amount`）。
*   **返回**：提取出的属性的累加总和。

## 核心逻辑
*   **执行方式：立即执行**。
*   **是否短路：否**。必须完整遍历整个集合，将所有元素依次累加。时间复杂度为 **O(N)**。
*   **空集处理**：**（极其友好！）** 与 `Min`、`Max` 和 `Average` 不同，**对空集合调用 `Sum` 非常安全**。无论源数据是不可空类型（如 `int`）还是可空类型（如 `int?`），空集合的 `Sum` **永远返回 `0`**（或 `0.0`, `0m`），**绝对不会抛出异常**。

## 实战代码
**场景 1：基础用法（简单数组求和）**
```csharp
int[] points = { 10, 20, 30 };

// 内部计算：10 + 20 + 30
int totalPoints = points.Sum(); 

Console.WriteLine($"总积分: {totalPoints}"); // 输出: 总积分: 60
```

**场景 2：带选择器用法（计算购物车总价，结合简单的计算逻辑）**
```csharp
class CartItem { public string Name; public decimal Price; public int Quantity; }

var cart = new List<CartItem>
{
    new CartItem { Name = "苹果", Price = 5.0m, Quantity = 3 },  // 15.0
    new CartItem { Name = "香蕉", Price = 3.5m, Quantity = 2 }   // 7.0
};

// 可以在 Lambda 表达式中直接进行乘法运算后再求和
decimal totalPrice = cart.Sum(item => item.Price * item.Quantity);

Console.WriteLine($"购物车总价: {totalPrice}"); // 输出: 购物车总价: 22.0
```

## 避坑/性能指南
**致命避坑 1：沉默的杀手 —— 累加溢出异常 (OverflowException)**
*   **现象**：`Sum` 的返回类型与你选择的属性类型**完全一致**。如果你对一个包含很多大数字的 `List<int>` 求和，累加结果很容易超过 `int.MaxValue`（约 21.4 亿），此时运行时会直接抛出 `OverflowException` 导致程序崩溃。
*   **错误写法**：
    ```csharp
    List<int> hugeNumbers = GetHugeNumbers();
    // 如果总和超过 21亿，这里直接炸
    int total = hugeNumbers.Sum(); 
    ```
*   **正确做法（向上转型，扩大容量）**：在累加前，将提取的值强转为容量更大的类型（如 `long` 或 `decimal`）。
    ```csharp
    // 把 int 强转为 long，Sum 的重载会自动匹配返回 long 类型
    long safeTotal = hugeNumbers.Sum(x => (long)x);
    ```

**致命避坑 2：财务计算中的浮点数精度丢失**
*   **现象**：如果你用 `double` 或 `float` 来表示金额并求和，由于计算机二进制浮点数的底层缺陷，多次累加后可能会出现 `0.1 + 0.2 = 0.30000000000000004` 这样的诡异精度丢失。
*   **正确做法**：凡是涉及金额、财务、严谨数据的求和，**数据类型必须是 `decimal`**。LINQ 对 `decimal` 的 `Sum` 重载能保证绝对的十进制精度，不会丢失哪怕一分钱。

**性能指南：`Sum` 中的 `null` 值处理**
*   当你的集合元素是可空类型（如 `int?`）时，`Sum` 在底层累加时会**自动忽略** `null` 值，只对有值的元素求和。
    ```csharp
    int?[] nullableNumbers = { 10, null, 20 };
    // 结果是 30，不会因为 null 报错，也不需要你手动去 Where(x => x != null)
    int total = nullableNumbers.Sum() ?? 0; 
    ```
