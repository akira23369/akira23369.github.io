# Aggregate (自定义聚合 / 归约)

## 方法名与分类
*   **方法名**：`Aggregate`
*   **分类**：聚合操作符 (Aggregation Operators)
*   **学名**：在函数式编程中，它被称为 **Fold (折叠)** 或 **Reduce (归约)**。

> **💡 核心认知**：`Aggregate` 是 LINQ 中所有聚合函数的**终极 Boss**。你之前学过的 `Sum`, `Min`, `Max`, `Average`, `Count`，在底层全部都可以用 `Aggregate` 来实现。当你遇到了内置聚合函数搞不定的复杂统计规则时，就轮到它出场了。

## 签名
`Aggregate` 有三个层层递进的重载版本，极其重要：

*   **版本 1：无种子 (累加器类型必须与元素类型相同)**
```csharp
public static TSource Aggregate<TSource>(
    this IEnumerable<TSource> source, 
    Func<TSource, TSource, TSource> func // 参数1: 累加器(上次的结果), 参数2: 当前遍历到的元素
);
```

*   **版本 2：带初始种子 (累加器可以是全新的类型！)**
```csharp
public static TAccumulate Aggregate<TSource, TAccumulate>(
    this IEnumerable<TSource> source, 
    TAccumulate seed, // 初始种子 (累加器的初始状态)
    Func<TAccumulate, TSource, TAccumulate> func 
);
```

*   **版本 3：带种子 + 最终结果转换器 (极其强大)**
```csharp
public static TResult Aggregate<TSource, TAccumulate, TResult>(
    this IEnumerable<TSource> source, 
    TAccumulate seed, 
    Func<TAccumulate, TSource, TAccumulate> func, 
    Func<TAccumulate, TResult> resultSelector // 遍历完所有元素后，对累加器执行最后一次"易容"
);
```

## 核心逻辑 (滚雪球效应)
*   **执行方式：立即执行 (Immediate Execution)**。
*   **是否短路：否**。必须从头到尾完整遍历整个集合，时间复杂度为 **$O(N)$**。
*   **运行机制（形象比喻：滚雪球）**：
    *   **无种子版**：把集合的**第 1 个元素**当成最初的雪球。然后从第 2 个元素开始遍历。每遇到一个新元素（地上的雪），就调用你的 `func` 规则，把新雪压进雪球里，形成一个**更大的新雪球**。最后返回这个大雪球。
    *   **有种子版**：把你传进来的 **`seed`** 当成最初的雪球。从集合的**第 1 个元素**开始遍历。每遇到一个元素，就用 `func` 把它压进种子雪球里，更新种子的状态。

## 实战代码
**场景 1：无种子版本（把单词拼成一句话，理解滚雪球）**
```csharp
string[] words = { "Hello", "LINQ", "is", "awesome" };

// 内部执行过程：
// 1. acc = "Hello", next = "LINQ" -> 返回 "Hello LINQ"
// 2. acc = "Hello LINQ", next = "is" -> 返回 "Hello LINQ is"
// 3. acc = "Hello LINQ is", next = "awesome" -> 返回 "Hello LINQ is awesome"
string sentence = words.Aggregate((acc, next) => acc + " " + next);

Console.WriteLine(sentence); // 输出: Hello LINQ is awesome
```

**场景 2：带种子版本（不同类型的累加。比如：计算银行账户最终余额）**

|**步骤**|**处理的对象 (tx)**|**计算逻辑 (balance, tx)**|**当前余额 (Accumulated Value)**|
|---|---|---|---|
|**初始状态**|-|-|**500**|
|**Step 1**|`{ Amount = 100, Type = "收入" }`|`500 + 100`|**600**|
|**Step 2**|`{ Amount = 30, Type = "支出" }`|`600 - 30`|**570**|
|**Step 3**|`{ Amount = 50, Type = "收入" }`|`570 + 50`|**620**|

```csharp
class Transaction { public decimal Amount; public string Type; } // 充值或扣款

var transactions = new List<Transaction>
{
    new Transaction { Amount = 100, Type = "收入" },
    new Transaction { Amount = 30, Type = "支出" },
    new Transaction { Amount = 50, Type = "收入" }
};

decimal initialBalance = 500m; // 初始余额 500 元 (这就是种子)

// TAccumulate 是 decimal, TSource 是 Transaction
decimal finalBalance = transactions.Aggregate(
    initialBalance, // 种子
    (balance, tx) => tx.Type == "收入" ? balance + tx.Amount : balance - tx.Amount
);

Console.WriteLine($"最终余额: {finalBalance}"); // 输出: 620
```


**场景 3：带种子 + 最终转换器（一次遍历，同时求出总分和平均分）**
```csharp
int[] scores = { 80, 90, 100 };

// 我们用一个 Tuple (int Sum, int Count) 作为雪球（种子）
// 这样在遍历时，我们能同时记录总分和人数
// seed: func: resultSelector: 是命名参数。给方法传参可以打乱顺序
string report = scores.Aggregate(
    seed: (Sum: 0, Count: 0), // 初始雪球：总分0，人数0
    
    // 每遇到一个分数，总分累加，人数+1
    func: (acc, score) => (acc.Sum + score, acc.Count + 1), 
    
    // 遍历结束后，雪球变成了 (Sum: 270, Count: 3)
    // 触发 resultSelector，把这坨雪球最终加工成一份字符串报告
    resultSelector: finalAcc => $"总分: {finalAcc.Sum}, 平均分: {finalAcc.Sum / finalAcc.Count}" 
);

Console.WriteLine(report); // 输出: 总分: 270, 平均分: 90
```

## 避坑/性能指南
**致命避坑 1：无种子版本面对“空集合”直接崩溃**
*   **现象**：
    ```csharp
    List<int> emptyList = new List<int>();
    // 💣 直接抛出 InvalidOperationException: Sequence contains no elements
    int result = emptyList.Aggregate((acc, next) => acc + next); 
    ```
*   **原因**：因为无种子版本是拿集合的“第一个元素”作为初始雪球的。如果是空集，它连初始雪球都捏不出来，只能崩溃。
*   **解决方案**：如果集合可能为空，**绝对要使用带种子的重载版本**。带种子的版本面对空集时，会非常安全地直接返回你传入的种子。
    ```csharp
    // ✅ 安全：空集直接返回种子 0
    int safeResult = emptyList.Aggregate(0, (acc, next) => acc + next); 
    ```

**致命避坑 2：性能灾难 —— 滥用 `Aggregate` 进行字符串拼接**
*   **现象**：就像场景 1 中演示的那样，新手觉得用 `Aggregate` 拼接字符串非常酷炫。
*   **危害**：在 C# 中，`string` 是**不可变的 (Immutable)**。如果你的集合里有 1000 个单词，`acc + " " + next` 会在内存的堆区丢弃并重新创建 1000 个新的字符串对象！这会引发恐怖的 GC (垃圾回收) 风暴，导致性能直线下降。
*   **正确做法**：如果只是为了拼接字符串，**永远使用 `string.Join()` 或 `StringBuilder`**。
    ```csharp
    // ✅ 极速且节省内存的最佳实践
    string sentence = string.Join(" ", words); 
    ```

**性能/思维指南：不要重新发明轮子**
*   `Aggregate` 虽然强大，但它的代码阅读门槛很高。
*   如果你只是想求和，请用 `.Sum()`。
*   如果你只是想找最大值，请用 `.Max()`。
*   **核心法则**：只有当你需要在一个循环中**累加多种不同的状态**（如场景3，同时累加 Sum 和 Count），或者进行**复杂的自定义状态推演**（如状态机推演、权限叠加计算）时，才是 `Aggregate` 真正大显身手的时候。
