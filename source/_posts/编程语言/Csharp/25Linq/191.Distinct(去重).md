# Distinct (去重)

## 方法名与分类
*   **方法名**：`Distinct`
*   **分类**：集合操作符 (Set Operators)

## 签名
`Distinct` 方法用于返回序列中的**非重复**元素。它有两个常用的重载版本：

*   **默认比较版本：使用元素类型的默认相等比较器去重**
```csharp
public static IEnumerable<TSource> Distinct<TSource>(
    this IEnumerable<TSource> source
);
```
*   **参数**：仅扩展当前集合本身。
*   **返回**：一个包含了原集合中所有唯一元素的**新序列**。

*   **自定义比较器版本：使用指定的规则判断元素是否“重复”**
```csharp
public static IEnumerable<TSource> Distinct<TSource>(
    this IEnumerable<TSource> source, 
    IEqualityComparer<TSource> comparer // 传入自定义的相等比较规则
);
```
*   **参数**：`comparer` 决定了“什么样才算重复”。

## 核心逻辑
*   **执行方式：延迟执行 (Deferred Execution)**。但在遍历时，它的行为是**半非流式 (Semi-streaming) / 状态保留 (Stateful)** 的。
    *   **底层机制**：当开始遍历 `Distinct` 的结果时，它会在内存中偷偷维护一个 `HashSet<T>`（哈希集合）。
    *   每从源集合读取一个元素，它就去哈希集合里查：
        *   如果查不到（说明是第一次见），就把它加入哈希集合，并**立刻作为结果输出给下游**（流式特征）。
        *   如果查到了（说明重复了），就**直接丢弃**，继续读下一个（不输出）。
*   **是否流式处理：是，也不是**。它可以源源不断地输出不重复的元素，不需要等待整个源集合遍历完。但它**必须在内存中记住所有已经输出过的元素**，这就意味着它会消耗 $O(N)$ 的内存空间（$N$ 是唯一元素的数量）。
*   **顺序保留**：`Distinct` 返回的元素顺序，**严格按照它们在原集合中首次出现的顺序**排列。

## 实战代码
**场景 1：基础用法（基础数据类型去重）**
```csharp
int[] numbers = { 1, 2, 2, 3, 1, 4, 5, 5 };

// 去掉重复的数字，保留首次出现的顺序
var uniqueNumbers = numbers.Distinct(); 

Console.WriteLine(string.Join(", ", uniqueNumbers)); 
// 输出: 1, 2, 3, 4, 5
```

**场景 2：使用内置比较器（忽略字符串大小写去重）**
```csharp
string[] words = { "apple", "APPLE", "Banana", "banana", "Cherry" };

// 默认区分大小写，下面会输出 5 个单词
// var defaultDistinct = words.Distinct(); 

// 传入 StringComparer.OrdinalIgnoreCase 忽略大小写，把 "apple" 和 "APPLE" 视为重复
var uniqueWords = words.Distinct(StringComparer.OrdinalIgnoreCase);

Console.WriteLine(string.Join(", ", uniqueWords)); 
// 输出: apple, Banana, Cherry
```

## 避坑/性能指南
**致命避坑 1：自定义对象的“引用比较”陷阱 (Distinct 无效)**
*   **现象**：对于类（引用类型），`Distinct` 默认比较的是**内存地址**。如果你有两个属性完全相同的对象，`Distinct` 会认为它们是**不重复**的，从而导致去重失败。
*   **错误示例**：
    ```csharp
    class User { public int Id; public string Name; }
    var users = new List<User> 
    { 
        new User { Id = 1, Name = "Alice" }, 
        new User { Id = 1, Name = "Alice" } // 内存地址不同
    };
    
    // 结果依然是 2 个元素！去重失败！
    var uniqueUsers = users.Distinct(); 
    ```
*   **解决方案 (神级避坑)**：
    *   **做法 1 (传统/笨重)**：让 `User` 类实现 `IEquatable<User>` 接口并重写 `Equals` 和 `GetHashCode`。
    *   **做法 2 (麻烦)**：写一个独立的类实现 `IEqualityComparer<User>`，然后传给 `Distinct`。
    *   **做法 3 (.NET 6+ 极速优雅解法：DistinctBy)**：
        这是目前最推荐的做法！直接指定按哪个属性去重，底层帮你搞定一切。
        ```csharp
        // .NET 6+ 新增神器：明确告诉它，只要 Id 相同就算重复！
        var uniqueUsers = users.DistinctBy(u => u.Id); 
        ```
    *   **做法 4 (.NET 6 之前的黑科技：GroupBy + Select)**：
        ```csharp
        // 按 Id 分组，然后每组只拿第一个元素，完美实现去重
        var uniqueUsers = users.GroupBy(u => u.Id).Select(g => g.First());
        ```

**致命避坑 2：内存溢出 (OOM) 风险**
*   **现象**：如果你对一个包含几千万条唯一数据的超大集合或无限流调用 `Distinct()`。
*   **危害**：如核心逻辑所述，`Distinct` 必须在内存的 `HashSet` 中**记住每一个它见过的不重复元素**。如果唯一数据量极大，这个隐藏的哈希表会疯狂膨胀，最终导致 `OutOfMemoryException` 内存溢出导致程序崩溃。
*   **解决方案**：如果在处理极大数据流去重，不能单靠内存里的 LINQ，应该考虑将数据分批落库，利用数据库的 `DISTINCT` 或唯一索引来处理；或者使用布隆过滤器 (Bloom Filter) 等概率数据结构进行近似去重。

**性能指南：`Distinct` 之后的 `Count()` 极其低效**
*   **现象**：想要知道集合中有多少个不重复的元素，写出了 `list.Distinct().Count()`。
*   **危害**：LINQ 在执行这句代码时，会先在内存里建一个 `HashSet`，把所有数据塞进去去重，然后再遍历这个 `HashSet` 去数个数（O(N) 时间，O(N) 空间）。
*   **终极优化**：直接把集合传给 `HashSet` 的构造函数，然后直接读取它的 `.Count` 属性（极速 O(1) 读取，且无需 LINQ 的状态机开销）。
    ```csharp
    // 性能最好、最专业的写法：
    int uniqueCount = new HashSet<int>(list).Count;
    ```
