# Concat / Union (拼接与并集)

## 方法名与分类
*   **方法名**：`Concat` (拼接) / `Union` (并集)
*   **分类**：拼接操作符 (Concatenation) / 集合操作符 (Set Operators)

## 签名
这两个方法都用于将两个集合“合二为一”，但处理重复元素的行为完全不同。

*   **Concat：简单粗暴地首尾拼接（保留所有重复项）**
```csharp
public static IEnumerable<TSource> Concat<TSource>(
    this IEnumerable<TSource> first, 
    IEnumerable<TSource> second
);
```
*   **参数**：`first` 为第一个集合，`second` 为要拼接到后面的第二个集合。
*   **返回**：包含第一个集合的所有元素，随后紧跟第二个集合的所有元素的新序列。

*   **Union：数学意义上的求并集（自动去重）**
```csharp
// 默认比较版本
public static IEnumerable<TSource> Union<TSource>(
    this IEnumerable<TSource> first, 
    IEnumerable<TSource> second
);

// 自定义比较器版本
public static IEnumerable<TSource> Union<TSource>(
    this IEnumerable<TSource> first, 
    IEnumerable<TSource> second, 
    IEqualityComparer<TSource> comparer
);

// .NET 6+ 新增极速去重合并神器
public static IEnumerable<TSource> UnionBy<TSource, TKey>(
    this IEnumerable<TSource> first, 
    IEnumerable<TSource> second, 
    Func<TSource, TKey> keySelector // 指定按什么属性去重
);
```

## 核心逻辑 (极其重要的区别)
*   **执行方式：两者均为延迟执行 (Deferred Execution)**。
*   **`Concat` (流式，极速)**：
    *   **是否流式**：是。
    *   **机制**：它内部没有任何缓存。遍历时，它先依次把 `first` 里的元素返回；`first` 遍历完后，接着依次把 `second` 里的元素返回。
    *   **复杂度**：时间复杂度 O(N+M)，额外空间复杂度 **O(1)**。
*   **`Union` (状态保留，耗内存)**：
    *   **是否流式**：半流式。
    *   **机制**：类似于 `Distinct`，它在底层悄悄维护了一个 `HashSet<T>`。遍历时，无论是读 `first` 还是 `second` 的元素，都要先去哈希表里查一下。如果哈希表里没有（没重复），就加入哈希表并输出；如果有（重复了），就直接丢弃。
    *   **复杂度**：时间复杂度 O(N+M)，额外空间复杂度 **O(U)**（U 为两个集合中不重复元素的总数）。

Concat的实现逻辑和Addpend很相似，都是在后面直接yield return。
**调用过程**（非遍历过程）性能表现如下：
**时间复杂度：$O(1)$**
调用 `Concat` 时，它只是把两个引用塞进了一个新的迭代器对象里，不涉及对任何一个序列的计数或复制。
**空间复杂度：$O(1)$**
它只创建了一个极小的迭代器状态机对象，其大小与参与拼接的集合长度无关。

**遍历时间复杂度**：**遍历**时的时间复杂度是 $O(N+M)$。

```cs
public static IEnumerable<T> MyConcat<T>(this IEnumerable<T> first, IEnumerable<T> second)
{
    // 同样是延迟执行
    foreach (var item in first)
    {
        yield return item;
    }

    foreach (var item in second)
    {
        yield return item;
    }
}
```


## 实战代码
**场景 1：基础值类型的拼接与并集比对**
```csharp
int[] listA = { 1, 2, 3 };
int[] listB = { 3, 4, 5 };

// Concat (保留重复项)：1, 2, 3, 3, 4, 5
var concatResult = listA.Concat(listB);

// Union (剔除重复项)：1, 2, 3, 4, 5
var unionResult = listA.Union(listB);
```

**场景 2：.NET 6+ 使用 UnionBy 合并对象集合（处理不同来源的数据）**
```csharp
class Product { public int Id; public string Name; }

var localProducts = new List<Product> { new Product { Id = 1, Name = "A" } };
var remoteProducts = new List<Product> { 
    new Product { Id = 1, Name = "A_Updated" }, // ID 冲突
    new Product { Id = 2, Name = "B" } 
};

// 场景：合并本地和远程商品，如果 ID 重复，以本地(first)为准
var mergedProducts = localProducts.UnionBy(remoteProducts, p => p.Id);

foreach(var p in mergedProducts)
{
    Console.WriteLine($"{p.Id}: {p.Name}");
}
// 输出:
// 1: A  (保留了 local 的数据，remote 中 Id=1 的被作为重复项丢弃了)
// 2: B
```

## 避坑/性能指南
**致命避坑 1：滥用 `Union` 导致性能与内存双重灾难**
*   **现象**：新手只要遇到“把两个列表合起来”的需求，就喜欢用 `Union`。
*   **危害**：如果这两个列表本来就**不可能有重复项**（例如：一个是“男生列表”，一个是“女生列表”），或者你的业务**根本不在乎重复项**，使用 `Union` 会导致 LINQ 在后台白白创建一个巨大的 `HashSet` 进行毫无意义的查重计算，严重浪费 CPU 和内存。
*   **黄金法则**：**默认永远使用 `Concat`。只有当你明确知道数据有交集，且业务严格要求“合并后绝对不能有重复数据”时，才使用 `Union`。**

**致命避坑 2：复杂对象的 `Union` 无效（引用地址陷阱）**
*   **现象**：和 `Distinct` 完全一样，对自定义类（引用类型）使用普通的 `Union` 时，由于底层比较的是内存地址，哪怕两个对象的属性完全一样，`Union` 也会认为它们不重复，最终结果等同于 `Concat`。
*   **正确做法**：
    1.  (.NET 6+) 首选 `UnionBy(..., x => x.Id)`。
    2.  (.NET 6 之前) 自己造一个类实现`IEqualityComparer<T>`，或者重写类的 `Equals` 和 `GetHashCode`，或者改用 `.Concat().GroupBy().Select(First)` 的黑科技。

**性能指南：绝对不要在 `for/while` 循环中不断使用 `Concat`**
*   **现象**：
    ```csharp
    IEnumerable<int> allData = new List<int>();
    for (int i = 0; i < 1000; i++)
    {
        var pageData = GetPage(i);
        // 灾难操作！
        allData = allData.Concat(pageData); 
    }
    // 最终使用时：可能会抛出 StackOverflowException，或者卡死！
    var list = allData.ToList(); 
    ```
*   **危害**：`Concat` 并没有把数据加进去，而是生成了一个包含了原序列和新序列的**链式迭代器**。如果在循环里调用 1000 次，就会生成一个深度为 1000 的对象调用树。当你最终 `.ToList()` 触发求值时，极深的递归调用会直接撑爆栈内存（StackOverflow）或者带来恐怖的性能损耗。
*   **正确做法**：
    *   如果是把多个集合拍平，请使用 **`SelectMany`**。
    *   如果要在循环里不断追加数据，请老老实实 `new List<T>()` 然后使用 **`List.AddRange(pageData)`**。
