# OfType (按类型筛选与转换)

## 方法名与分类
*   **方法名**：`OfType`
*   **分类**：筛选/类型转换操作符 (Filtering / Conversion Operators)

## 签名
`OfType` 是 LINQ 中极其特殊且强大的一个方法，它的扩展目标**不是**泛型的 `IEnumerable<T>`，而是**非泛型**的 `IEnumerable`。

*   **唯一版本：过滤出指定类型的元素，并隐式转换为该类型**
```csharp
public static IEnumerable<TResult> OfType<TResult>(
    this IEnumerable source // 注意：这里是非泛型的 IEnumerable
);
```
*   **参数**：`source` 可以是任何集合（包括老旧的 `ArrayList`，或是包含多种派生类的 `List<BaseClass>`）。
*   **返回**：`IEnumerable<TResult>`。返回一个全新的泛型序列，里面**只包含**能够成功转换为 `TResult` 类型的元素。

## 核心逻辑
*   **执行方式：延迟执行 (Deferred Execution)**。返回迭代器，只有在 `foreach` 或 `.ToList()` 时才会真正去遍历。
*   **是否流式处理：是 (Streaming)**。读一个，测一个，如果是指定的类型就返回给下游，否则直接丢弃，继续测下一个。
*   **安全转换机制 (神级特性)**：
    *   在底层，它对集合中的每一个元素执行类似于 `if (item is TResult result)` 的安全类型检查。
    *   如果类型匹配，就将其**强转并返回**。
    *   如果类型**不匹配**，或者该元素是 `null`，它会**直接忽略/跳过**这个元素，**绝对不会抛出异常**。

## 实战代码
**场景 1：面向对象中的多态过滤（提取特定子类）**
这是 `OfType` 在现代 C# 开发中最常见的用法。当你有一个父类集合，但只想处理其中的某一种特定子类时。
```csharp
abstract class Animal { public string Name; }
class Dog : Animal { public void Bark() => Console.WriteLine($"{Name} 汪汪!"); }
class Cat : Animal { public void Meow() => Console.WriteLine($"{Name} 喵喵!"); }

var animals = new List<Animal>
{
    new Dog { Name = "旺财" },
    new Cat { Name = "小黑" },
    new Dog { Name = "大黄" },
    null // 混入一个 null
};

// 神奇的操作：只把 Dog 挑出来，并且结果直接变成了 IEnumerable<Dog>
var dogs = animals.OfType<Dog>();

foreach (Dog d in dogs)
{
    d.Bark(); // 可以直接调用子类特有的方法！
}
// 输出:
// 旺财 汪汪!
// 大黄 汪汪!
// (Cat 和 null 被完美地悄悄跳过了)
```

**场景 2：处理非泛型的历史遗留集合（如 ArrayList、UI 控件集合）**
在 WinForms、WPF 或旧版 .NET 代码中，很多集合是 `object[]` 或非泛型的（比如窗体上的 `Controls` 集合）。
```csharp
object[] mixedThings = { 1, "Hello", 2.5, "World", 3 };

// 从一堆乱七八糟的对象中，仅仅把字符串挑出来
var stringsOnly = mixedThings.OfType<string>();

Console.WriteLine(string.Join(", ", stringsOnly)); 
// 输出: Hello, World
```

## 避坑/性能指南
**致命避坑 1：混淆 `OfType<T>` 和 `Cast<T>`（面试必考，实战必踩）**
*   **现象**：新手经常在这两个方法之间选错，导致程序在线上直接崩溃。
*   **核心区别**：
    *   **`OfType<T>()`（安全过滤）**：遇到类型不对的，**直接丢弃**。结果集合的数量可能**小于**原集合。永远不会报错。
    *   **`Cast<T>()`（野蛮强转）**：遇到类型不对的，**当场抛出 `InvalidCastException` 导致程序崩溃**！结果集合的数量一定**等于**原集合。
*   **错误示例**：
```csharp
object[] items = { "Apple", "Banana", 100 }; // 混入了一个数字

// 灾难：执行到第三个元素时，无法把 int 转成 string，直接抛出 InvalidCastException 崩溃！
var badStrings = items.Cast<string>().ToList(); 

// 正确：安全地提取出前两个字符串，忽略那个数字 100。
var goodStrings = items.OfType<string>().ToList();
```

**致命避坑 2：`OfType` 只能做引用转换和拆箱，不能做“数值隐式转换”**
*   **现象**：
```csharp
double[] doubles = { 1.0, 2.5, 3.0 };

// 新手以为：这会把 double 截断成 int 返回 1, 2, 3 吧？
// 实际结果：返回一个空的集合！！(Count == 0)
var ints = doubles.OfType<int>(); 
```
*   **原因**：`OfType<T>` 底层使用的是 `is T` 指令。在 C# 中，`box(1.0) is int` 是 `false`。它不会帮你做像 `(int)1.5` 那样的数值截断或数据类型强制转换（Convert）。
*   **正确做法**：如果需要做数值类型的转换，请老老实实用 `Select`：
```csharp
var ints = doubles.Select(d => (int)d); // 返回 1, 2, 3
```

**性能/常识指南：天然的 `null` 过滤器**
*   因为在 C# 中，`null is T` 永远返回 `false`。
*   所以，当你对一个集合使用 `OfType<T>()` 时，它不仅过滤了类型，还**顺手帮你把所有的 `null` 元素都剔除了**。你不需要再额外写 `.Where(x => x != null)`。
