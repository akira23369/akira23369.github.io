# orderby (查询语法中的排序)

## 语法格式与映射
*   **关键字**：`orderby`
*   **修饰符**：`ascending` (升序，默认可省略) / `descending` (降序)
*   **多级排序**：用逗号 `,` 分隔多个排序表达式
*   **底层映射**：
    *   第一个排序条件 $\rightarrow$ 映射为 `OrderBy` 或 `OrderByDescending`
    *   逗号后面的所有条件 $\rightarrow$ 依次映射为 `ThenBy` 或 `ThenByDescending`

## 核心逻辑
*   **执行方式**：**延迟执行 (Deferred Execution)**，且**非流式 (Non-streaming)**。这意味着它会在内存中缓冲所有前面的查询结果，执行完整的稳定排序后，再将数据流向下一个操作（如 `select`）。
*   **位置要求**：在查询语法中，`orderby` 必须出现在 `from` 之后，且必须在 `select` 或 `group by` 之前。通常紧跟在 `where` 之后。

## 实战代码
**场景 1：单字段排序 (默认升序与显式降序)**
```csharp
class Employee { public string Name; public int Salary; public int Age; }

var emps = new List<Employee>
{
    new Employee { Name = "Alice", Salary = 8000, Age = 25 },
    new Employee { Name = "Bob", Salary = 12000, Age = 30 },
    new Employee { Name = "Charlie", Salary = 5000, Age = 22 }
};

// 需求 1：按工资从低到高排序 (升序，省略 ascending)

IEnumerable<string> ascQuery = from e in emps
                               orderby e.Salary
                               select e.Name;
// 输出: Charlie, Alice, Bob

// 需求 2：按工资从高到低排序 (显式声明 descending)
var descQuery = 
    from e in emps
    orderby e.Salary descending 
    select e.Name;
// 输出: Bob, Alice, Charlie
```

**场景 2：多级混合排序 (查询语法的绝对优势领域)**
在方法语法中，多级排序需要连续链式调用 `OrderBy().ThenByDescending().ThenBy()`，很容易写错或者漏掉 `ThenBy` 导致覆盖排序。而在查询语法中，只需要用**逗号分隔**，逻辑清晰得如同 SQL。
```csharp
var emps2 = new List<Employee>
{
    new Employee { Name = "Alice", Salary = 8000, Age = 25 },
    new Employee { Name = "Bob", Salary = 8000, Age = 30 }, // 和 Alice 工资一样，但年龄大
    new Employee { Name = "Charlie", Salary = 5000, Age = 22 }
};

// 需求：先按工资降序排；如果工资相同，则按年龄升序排 (年轻人优先)
var multiSortQuery = 
    from e in emps2
    // 极其直观的 SQL 风格多级排序！
    orderby e.Salary descending, e.Age ascending 
    select new { e.Name, e.Salary, e.Age };

foreach (var e in multiSortQuery)
{
    Console.WriteLine($"{e.Name} - 工资:{e.Salary}, 年龄:{e.Age}");
}
// 输出:
// Alice - 工资:8000, 年龄:25  (工资并列第一，但年龄小，排在前面)
// Bob - 工资:8000, 年龄:30
// Charlie - 工资:5000, 年龄:22
```

**场景 3：结合 `let` 进行基于计算结果的排序**
```csharp
// 需求：计算出每个人的“性价比” (年龄/工资比例)，并按性价比降序排列
var calcSortQuery = 
    from e in emps
    // 神技：用 let 算出性价比存起来
    let costPerformance = (double)e.Age / e.Salary 
    // 后面的 orderby 直接使用这个计算结果！
    orderby costPerformance descending 
    select new { e.Name, Ratio = costPerformance };
```

## 避坑/进阶指南
**致命避坑 1：排序条件中的 `null` 值处理**
*   **现象**：如果你的排序字段是可空类型（如 `int?`）或者是引用类型（如 `string`），在排序时如果遇到 `null`，它会排在哪里？
*   **规则**：在 C# 的默认比较器中，**`null` 永远被认为是“最小的”**。
    *   如果是 `orderby x ascending`：所有 `null` 值的对象都会排在**最前面**。
    *   如果是 `orderby x descending`：所有 `null` 值的对象都会排在**最后面**。
*   **防坑策略**：如果业务要求把没有工资的人（`Salary` 为 `null`）放在最后面，你不能只写 `orderby e.Salary descending`。必须显式处理：
    ```csharp
    // 先按“是否有工资”布尔值降序(true排前面)，再按工资数值降序
    orderby e.Salary.HasValue descending, e.Salary descending
    ```

**进阶对比：方法语法 `ThenBy` vs 查询语法 `,`**
了解编译器是如何工作的，能让你更放心地使用语法糖：
```csharp
// 你在查询语法中写的这行代码：
orderby e.Salary descending, e.Age ascending, e.Name descending

// 编译器会 100% 忠实地把它翻译成下面这串方法链：
.OrderByDescending(e => e.Salary)
.ThenBy(e => e.Age)               // 注意：升序被翻译成了普通的 ThenBy
.ThenByDescending(e => e.Name)
```
*   **警示**：永远不要在方法语法中连续写两个 `.OrderBy()`（第二个会覆盖第一个）。如果用查询语法，编译器会自动帮你防呆（用逗号分隔一定会被正确翻译成 `ThenBy` 链）。
