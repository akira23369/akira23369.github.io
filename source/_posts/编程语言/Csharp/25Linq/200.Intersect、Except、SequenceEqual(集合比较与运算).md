# Intersect / Except / SequenceEqual (集合比较与运算)

## 方法名与分类
*   **方法名**：`Intersect` (交集) / `Except` (差集) / `SequenceEqual` (序列相等比较)
*   **分类**：集合操作符 (Set Operators) / 相等比较操作符 (Equality Operators)

## 签名
这三个方法都用于处理**两个集合之间的关系**。它们都提供了使用默认比较器和自定义比较器的重载版本。

*   **Intersect (交集)：找出两个集合中“都有”的元素**
```csharp
// 默认比较版本
public static IEnumerable<TSource> Intersect<TSource>(
    this IEnumerable<TSource> first, 
    IEnumerable<TSource> second
);

// .NET 6+ 极速神器：按指定属性求交集
public static IEnumerable<TSource> IntersectBy<TSource, TKey>(
    this IEnumerable<TSource> first, 
    IEnumerable<TKey> second, // 注意：这里只需要提供 Key 的集合！
    Func<TSource, TKey> keySelector  // 指定需要比较的key
);
```

*   **Except (差集)：找出在第一个集合中，但不在第二个集合中的元素（A 减去 B）**
```csharp
// 默认比较版本
public static IEnumerable<TSource> Except<TSource>(
    this IEnumerable<TSource> first, 
    IEnumerable<TSource> second
);

// .NET 6+ 极速神器：按指定属性求差集
public static IEnumerable<TSource> ExceptBy<TSource, TKey>(
    this IEnumerable<TSource> first, 
    IEnumerable<TKey> second, 
    Func<TSource, TKey> keySelector
);
```

*   **SequenceEqual (序列相等)：判断两个集合是否“一模一样”**
```csharp
// 默认比较版本
public static bool SequenceEqual<TSource>(
    this IEnumerable<TSource> first, 
    IEnumerable<TSource> second
);
```
*   **返回**：`bool`。只有当两个集合**长度相同**，且对应位置上的元素**一一相等**时，才返回 `true`。

## 核心逻辑
*   **`Intersect` 和 `Except`**：
    *   **执行方式：延迟执行 (Deferred Execution)**。
    *   **是否流式处理：半流式 (Stateful)**。
    *   **底层机制（极其重要）**：当开始遍历结果时，LINQ 底层会**先把第二个集合 (second) 完整遍历一遍**，将其所有元素放入一个 `HashSet<T>` 内存哈希表中。然后，它开始流式地遍历第一个集合 (first)，拿着每一个元素去哈希表里查：
        *   **Intersect**：如果哈希表里**有**，就输出，并把哈希表里的这个元素删掉（防止 first 中有重复元素导致输出多次）。
        *   **Except**：如果哈希表里**没有**，就输出，并把输出过的元素记录在一个新的哈希表里（同样为了给 first 去重）。
    *   **去重特性**：这两个方法在输出结果时，都会**自动去除第一个集合中的重复项**。

*   **`SequenceEqual`**：
    *   **执行方式：立即执行 (Immediate Execution)**。
    *   **是否流式处理：是 (Streaming)**。它同时获取两个集合的迭代器，一步一步平行往下走，一边走一边比对。只要发现有一个元素不一样，或者其中一个集合提前走完了（长度不同），就立刻短路返回 `false`。

## 实战代码
**场景 1：基础值类型的交集与差集 (Intersect / Except)**
```csharp
int[] listA = { 1, 2, 3, 4, 5 };
int[] listB = { 4, 5, 6, 7 };

// 找出共有的元素 (交集)：4, 5
var common = listA.Intersect(listB);

// 找出 listA 独有，且排除了 listB 的元素 (差集)：1, 2, 3
var onlyInA = listA.Except(listB);

// 找出 listB 独有，且排除了 listA 的元素 (差集)：6, 7
var onlyInB = listB.Except(listA);
```

**场景 2：.NET 6+ 使用 IntersectBy / ExceptBy 处理复杂对象源（极其常见的数据同步场景）**
```csharp
class User { public int Id; public string Name; }

var localUsers = new List<User> 
{ 
    new User { Id = 1, Name = "Alice" },
    new User { Id = 2, Name = "Bob" }
};
var remoteUserIds = new List<int> { 2, 3 }; // 远程只返回了存活的 ID 列表

// 需求 1：找出本地和远程都存在的完整 User 对象（交集）
var existingUsers = localUsers.IntersectBy(remoteUserIds, u => u.Id);
// 结果: 包含 Id=2, Name="Bob" 的完整对象

// 需求 2：找出本地有，但远程已经被删除了的 User 对象（差集），准备执行本地物理删除
var usersToDelete = localUsers.ExceptBy(remoteUserIds, u => u.Id);
// 结果: 包含 Id=1, Name="Alice" 的完整对象
```

**场景 3：判断两个集合是否完全一致 (SequenceEqual)**
```csharp
int[] arr1 = { 1, 2, 3 };
int[] arr2 = { 1, 2, 3 };
int[] arr3 = { 3, 2, 1 };

Console.WriteLine(arr1.SequenceEqual(arr2)); // 输出: True
Console.WriteLine(arr1.SequenceEqual(arr3)); // 输出: False (因为顺序不同！)
```

## 避坑/性能指南
**致命避坑 1：对象数组比较的引用陷阱 (又来了！)**
*   **现象**：如果你对两个包含自定义类（引用类型）的集合调用无 `By` 后缀的 `Intersect`、`Except` 或 `SequenceEqual`，由于它们比较的是内存地址，结果永远会出乎你的意料（交集永远为空，差集永远是全部，相等永远是 false）。
*   **解决方案**：
    1.  首选 .NET 6+ 的 `IntersectBy` 和 `ExceptBy` 指定比较属性。
    2.  如果没升级 .NET 6，请重写类的 `Equals`，或者使用类似 `.Where(a => listB.Any(b => a.Id == b.Id))` 的笨重语法。
    3.  对于 `SequenceEqual` 没有 `By` 后缀的版本，可以自己实现一个 `IEqualityComparer<T>` 传进去，或者先 `Select` 出属性再去比对（如 `listA.Select(x=>x.Id).SequenceEqual(listB.Select(x=>x.Id))`）。

**致命避坑 2：`Intersect` / `Except` 的隐藏去重特性**
*   **现象**：
    ```csharp
    int[] a = { 1, 1, 2 };
    int[] b = { 1 };
    
    // 你以为交集会保留 a 中的两个 1？
    var result = a.Intersect(b); 
    // 实际结果只有 1 个 "1"！因为 Intersect 会在输出时给 a 去重。
    ```
*   **原因**：这在数学集合论中是正确的，因为“集合”本身就不应该有重复元素。LINQ 忠实地实现了这一数学特性。
*   **解决方案**：如果你的业务场景要求“**保留左侧集合的重复项**”，你**绝对不能用** `Intersect` 或 `Except`。必须使用 `Where`。
    ```csharp
    // 保留重复项的交集写法（使用 HashSet 优化性能）
    var hashB = new HashSet<int>(b);
    var keepDuplicatesIntersect = a.Where(x => hashB.Contains(x)); 
    // 结果: 1, 1
    ```

**性能指南：小集合放左边还是右边？**
*   在使用 `Intersect` 或 `Except` 时，性能上有一个极其重要的细节：
*   **核心法则：把“较小的集合”或“你希望构建成哈希表的集合”放在右边 (second参数)！**
    *   因为 LINQ 底层是**先把 `second` 集合读入内存构建 `HashSet`**。如果 `second` 极其庞大（比如一千万条数据），它会瞬间吃掉大量内存，并且构建哈希表的过程很耗时。
    *   把小集合放右边，大集合放左边。大集合 (first) 是流式遍历的，内存开销极小。
    *   *注：`Except` 的逻辑是固定的（A 减去 B），无法左右互换。但对于可交换的 `Intersect`（A 交 B 等于 B 交 A），一定要把小集合作为参数传进去。*
