# Append / Prepend (追加与前置)
## 方法名与分类
* **方法名**：`Append` (在末尾添加) / `Prepend` (在开头添加)
* **分类**：生成操作符 (Generation Operators)

## 签名
* **Append：在集合末尾追加一个元素**
```csharp
public static IEnumerable<TSource> Append<TSource>(
    this IEnumerable<TSource> source, 
    TSource element
);
```

* **Prepend：在集合开头插入一个元素**
```csharp
public static IEnumerable<TSource> Prepend<TSource>(
    this IEnumerable<TSource> source, 
    TSource element
);
```
* **参数**：`source` 为原集合；`element` 为要添加的元素。
* **返回**：`IEnumerable<TSource>`。返回一个包含原元素以及新添加元素的新序列。

## 核心逻辑
* **执行方式：延迟执行 (Deferred Execution)**。
* **是否流式处理：是 (Streaming)**。非常轻量，它并不会把数据放到内存里重新建集合，而是仅仅在原有的迭代器链条上，多串联了一个节点。时间复杂度和空间复杂度均为 **O(1)**。
* **不可变性**：不会修改原集合！它会生成一个新的迭代器链，原集合的数据完整性 100% 得到保留。

当你调用 `Append` 时，LINQ 实际上是创建了一个新的迭代器对象。在较新的 .NET 版本中，这个类通常叫 `AppendPrependIterator<TSource>`。

它的结构大致如下：
- 它持有对**原始序列**（`IEnumerable<TSource>`）的引用。
- 它持有你新加的**那个元素**（`TSource item`）。
- 它内部维护一个简单的**枚举状态**（State Machine）。

它是在原有的迭代器外层套了一个**逻辑壳子**。

```cs
public static class MyLinqExtensions
{
    public static IEnumerable<T> MyAppend<T>(this IEnumerable<T> source, T element)
    {
        // 1. 这里仅仅是创建了一个状态机对象，没有进行循环
        // 2. 空间复杂度 O(1)：只额外存储了 element 和 source 的引用
        // 3. 时间复杂度 O(1)：创建对象的过程与 source 的长度无关
        foreach (var item in source)
        {
            yield return item;
        }

        // 当源序列走完后，最后产出这个新元素
        yield return element;
    }
}
```


## 实战代码
**场景 1：在下拉列表数据源中快速插入一个 "全部" 选项**
```csharp
class City { public string Name; }
IEnumerable<City> cities = GetCitiesFromDatabase(); // 耗时查询，返回 IEnumerable<City>

// 不改变原数据库查询，直接在列表头尾增加选项，极度优雅！
var cityOptions = cities
    .Prepend(new City { Name = "全部" })
    .Append(new City { Name = "其他" });

foreach(var city in cityOptions)
{
    Console.WriteLine(city.Name);
}
// 输出: 全部, (数据库里的城市), 其他
```

## 避坑/性能指南
**致命避坑 1：误以为它们会修改原集合**
* **现象**：新手以为写了 `list.Append(item)` 后，`list` 里就多了个元素。
* **后果**：`list.Append(item)` 会返回一个新的 `IEnumerable`。原来的 `list` 内部没有任何变化。如果直接调用 `list.Append(item)` 而不接收返回值，这行代码没有任何意义。

**性能指南 1：绝对不要用 `Concat(new [] { item })` 来替代它们**
* **旧式写法**：`cities.Concat(new List<City> { new City { Name = "其他" } })`
* **危害**：上述写法每次调用都会隐式 `new` 一个数组/集合，会引发额外的堆内存分配，增加 GC 压力。
* **最佳实践**：凡是单个元素前置/后置，**全部使用 `Prepend()` / `Append()`**。它们底层实现极其精简，复用了迭代器链（就是加一个yield return），不会产生多余的集合对象。

**思维指南：与 `List<T>.Add()` 和 `List<T>.Insert()` 的区别**
* `List.Add()` / `List.Insert()` 是**即时操作**，它们会真正的去修改原集合，并且如果是在头部插入 (`Insert(0, item)`)，整个数组会发生内存移动，时间复杂度为 **O(N)**。
* `Append()` / `Prepend()` 是**延迟流式操作**，它们不触碰原有内存，时间复杂度 **O(1)**。
* **选择指南**：如果你本身需要对一个集合进行频繁修改，使用 `List<T>` 原生方法；如果你是为了给前端/UI展示提供数据流，绝对使用 `Append/Prepend`。
