# group by (查询语法中的分组)

## 语法格式与映射
*   **关键字**：`group [要放进组里的元素] by [分组的 Key]`
*   **底层映射**：编译器会将其 100% 翻译为方法语法中的 **`GroupBy`**。
*   **返回类型**：`IEnumerable<IGrouping<TKey, TElement>>`。

## 核心逻辑
*   **执行方式**：**延迟执行 (Deferred Execution)**，但在遍历时是**非流式 (Stateful)** 的。
*   **作为查询结尾**：在 LINQ 查询语法中，一个查询语句**只能以 `select` 或 `group by` 结尾**。一旦你使用了 `group by`，这个查询的“主干”就结束了。

## 实战代码
**场景 1：最基础的分组（只按部门分，保留整个对象）**
```csharp
class Emp { public string Dept; public string Name; public int Salary; }
var emps = new List<Emp> 
{ 
    new Emp { Dept = "IT", Name = "Alice", Salary = 8000 },
    new Emp { Dept = "HR", Name = "Bob", Salary = 6000 },
    new Emp { Dept = "IT", Name = "Charlie", Salary = 7000 }
};

// 需求：按部门将员工分组
// 语法：group [原封不动的员工对象 e] by [部门名 e.Dept]
var query = 
    from e in emps
    group e by e.Dept; 

// 返回的是 IEnumerable<IGrouping<string, Emp>>
foreach (var g in query)
{
    Console.WriteLine($"部门: {g.Key}, 人数: {g.Count()}");
    foreach (var emp in g) // 遍历组内的员工
    {
        Console.WriteLine($"  - {emp.Name}");
    }
}
// 输出:
// 部门: IT, 人数: 2
//   - Alice
//   - Charlie
// 部门: HR, 人数: 1
//   - Bob
```

**场景 2：分组并塑形元素（抽屉里不放整个对象，只放名字）**
```csharp
// 需求：按部门分组，但组里只存放员工的名字字符串
// 语法：group [只要名字 e.Name] by [部门名 e.Dept]
var nameGroups = 
    from e in emps
    group e.Name by e.Dept;

// 返回的是 IEnumerable<IGrouping<string, string>>
foreach (var g in nameGroups)
{
    Console.WriteLine($"{g.Key} 部门的名单: {string.Join(", ", g)}");
}
// 输出: 
// IT 部门的名单: Alice, Charlie
// HR 部门的名单: Bob
```

## 避坑/进阶指南：`into` 关键字的续命魔法

在方法语法中，我们经常在 `GroupBy` 之后紧接着调用 `Select` 来直接计算总数、平均分（如：`emps.GroupBy(e=>e.Dept).Select(g => new { g.Key, Avg = g.Average(x=>x.Salary) })`）。

但是！正如前面所说，**查询语法在遇到 `group by` 时就必须强行结束了**，你没法在后面再接 `select`。这就导致了非常严重的局限性。

为了解决这个问题，C# 引入了极其重要的关键字：**`into`（查询延续）**。

### 神技：`into` 关键字 (给查询“续命”)
`into` 的作用是：把刚刚 `group by` 出来的结果（那个 `IGrouping` 集合），**装进一个新的临时变量里，然后重新开启一个全新的查询！**

**场景 3：分组后立即进行聚合计算（报表统计极速写法，必须掌握）**
```csharp
// 需求：直接统计出每个部门的人数和平均工资，不需要看具体有谁
var statsQuery = 
    from e in emps
    group e by e.Dept into deptGroup // 1. 分组结束，把结果塞进新变量 deptGroup 里续命！
    
    // 2. 此时，上下文已经完全变了！
    // 你再也无法访问原本的变量 'e' 了。
    // 你现在能操作的只有 'deptGroup' (它代表一个 IGrouping 组，有 Key 属性，本身是个集合)
    
    select new 
    {
        DeptName = deptGroup.Key,
        TotalCount = deptGroup.Count(),
        AvgSalary = deptGroup.Average(x => x.Salary) // 注意：这里的 x 是组内的 Emp 对象
    };

foreach (var stat in statsQuery)
{
    Console.WriteLine($"{stat.DeptName}: {stat.TotalCount}人, 平均工资:{stat.AvgSalary}");
}
/* 输出:
IT: 2人, 平均工资:7500
HR: 1人, 平均工资:6000
*/
```

**致命避坑：`into` 之后的“失忆症”**
*   **现象**：新手在使用 `into` 后，经常会在后续的 `select` 中试图访问原来 `from` 声明的变量，导致编译报错。
    ```csharp
    // 💣 编译报错！
    var badQuery = 
        from e in emps
        group e by e.Dept into g
        select new { e.Name, g.Key }; // 错误！'e' 已经不存在于当前上下文中了！
    ```
*   **核心法则**：`into` 就像是一道**失忆之门**。跨过这道门，你之前的局部变量（如 `e`）**全部失效销毁**。你手里只剩下那个装满分组数据的新篮子（如 `g`）。
*   **正确做法**：一切基于新变量 `g` 进行操作。

**进阶技巧：多字段分组（匿名类）**
在查询语法中，多字段分组和方法语法一样，使用匿名类即可，写起来非常清晰。
```csharp
// 需求：按部门 AND 职位同时分组
var multiGroupQuery = 
    from e in emps
    // 神技：只要属性名、类型完全一致，匿名对象就能作为复合 Key
    group e by new { e.Dept, e.Role } into g
    select new 
    {
        Department = g.Key.Dept,
        Position = g.Key.Role,
        Headcount = g.Count()
    };
```
