C# 12 引入的**集合表达式（Collection Expressions）**，可以说是整个 C# 12 中**最令人极度舒适、最能提升代码颜值的特性**，没有之一。

简单来说，它引入了一对方括号 `[...]`。 它的出现，终结了 C# 十几年以来初始化各种集合时“群魔乱舞”的混乱语法。

我们从它的**解决的痛点、核心用法、以及底层的性能优化**三个方面来把它讲透。

---

### 解决的痛点：以前的 C# 有多乱？

在 C# 12 之前，你要初始化不同的集合，需要死记硬背不同的语法。不仅写起来啰嗦，看起来也不统一：

**C# 12 之前的“乱象”：**
```csharp
// 1. 数组
int[] array = new int[] { 1, 2, 3 }; 

// 2. List
List<int> list = new List<int> { 1, 2, 3 };

// 3. Span (高性能场景)
Span<int> span = stackalloc int[] { 1, 2, 3 };

// 4. 空集合 (写法极其不统一)
int[] emptyArray = Array.Empty<int>();
List<int> emptyList = new List<int>();
```

### C# 12 的大一统：集合表达式 `[...]`

现在，只要看到集合，不管是啥类型，无脑用 `[...]` 就完事了。**编译器会根据左边的变量类型，自动推断并生成正确的代码（Target-typed）。**

**C# 12 的清爽写法：**
```csharp
int[] array = [1, 2, 3];
List<int> list = [1, 2, 3];
Span<int> span = [1, 2, 3]; // 甚至不需要写 stackalloc 了！

// 空集合的终极优雅写法
int[] emptyArray = [];
List<int> emptyList = [];
IEnumerable<int> emptyEnum = []; // 编译器底层会智能使用 Array.Empty<int>()
```
这就叫“语法糖”的最高境界：**符合直觉，降低心智负担**。

---

### 杀手级功能：展开运算符（Spread Operator `..`）

这是集合表达式里最强大的功能。以前我们要拼接两个数组或集合，通常要借助 LINQ 的 `.Concat()`，或者手动建一个大数组慢慢 `CopyTo()`，性能和代码量都很感人。

现在，用两个点 `..` 就能把集合“炸开”并平铺进去：

```csharp
int[] array1 = [1, 2, 3];
int[] array2 = [4, 5, 6];

// 将 array1, array2 和单一元素 7 拼成一个新的集合
int[] combined = [..array1, ..array2, 7]; 

// combined 的结果就是: [1, 2, 3, 4, 5, 6, 7]
```

这在处理配置合并、参数拼接时简直不要太爽：
```csharp
string[] defaultFilters = ["Auth", "Logging"];
string[] userFilters = GetUserFilters();

// 轻松拼接
string[] allFilters = [..defaultFilters, ..userFilters];
```

---

### 底层揭秘：它只是简单的语法糖吗？

**不！它是带有“极端性能优化”的语法糖。**

当你写出 `List<int> list = [..a, ..b, 1];` 时，编译器底层**绝对不是**简单地去调用 `list.Add()` 或者 `LINQ.Concat()`。

微软的编译器团队在这个特性上做了极深的优化：

#### 预计算容量，消除内存浪费
编译器在编译时（或运行时动态地）会计算出总长度。
比如上面那个拼接，编译器知道长度是 `a.Length + b.Length + 1`。所以它底层生成的代码相当于：
```csharp
// 编译器底层的伪代码
List<int> list = new List<int>(a.Length + b.Length + 1); // 直接一次性分配好容量！
// 然后通过底层的高效内存复制 (如 Span.CopyTo 或直接内存操作) 把数据塞进去
```
**好处**：完全避免了传统的 `List.Add()` 在扩容时产生的**多次数组复制和垃圾回收（GC）**。

#### Span 极其安全和高效
当你写 `ReadOnlySpan<byte> span = [1, 2, 3];` 时，编译器甚至不会在堆（Heap）上分配内存！它会把它直接放进 `DLL` 的数据段里（类似硬编码的常量），运行时直接指向那块内存，**零分配，性能拉满**。

#### 智能选择最优实例化方案
当你写 `int[] empty = [];` 时，编译器绝对不会去 `new int[0]`，而是自动帮你替换成效率最高的 `Array.Empty<int>()`。

---

### 它可以自定义吗？
想要让自定义的类（比如你写的某个 `MyContainer<T>`）也支持 `[]` 这种集合表达式语法，C# 提供了两种路径。一种是“传统路径”（靠约定），另一种是“高性能路径”（靠特性）。

---

#### 传统路径：`IEnumerable` + `Add` 方法
这是最简单的方法。只要你的类满足以下两个条件，编译器就能识别：
- 实现了 `System.Collections.IEnumerable` 接口。
- 拥有一个可以调用的 `Add` 方法（或者能通过扩展方法找到 `Add`）。


```cs
using System.Collections;

public class MyList<T> : IEnumerable
{
    private readonly List<T> _storage = [];

    public void Add(T item) => _storage.Add(item);

    public IEnumerator GetEnumerator() => _storage.GetEnumerator();
}

// 使用：
MyList<int> myItems = [1, 2, 3]; 
```

**原理：** 编译器看到 `[]` 时，会先创建一个 `new MyList<int>()`，然后连续调用 `Add` 方法。这和之前的集合初始化器语法底层是一样的。

---

#### 高性能路径：`CollectionBuilder` 特性
如果你追求极致性能（比如想避免多次调用 `Add` 导致的扩容），或者你的类型是**不可变**的（没有 `Add` 方法），那么 C# 12 引入了 `[CollectionBuilder]` 特性。
这种方式允许你定义一个“工厂方法”来处理 `[]` 里的数据。

**第一步：创建静态工厂方法**
这个方法必须接受一个 `ReadOnlySpan<T>` 类型的参数，并返回你的集合类型。

**第二步：在类上标注特性**
指向你的工厂方法。

```cs
using System.Runtime.CompilerServices;

[CollectionBuilder(typeof(MyBufferBuilder), nameof(MyBufferBuilder.Create))]
public class MyBuffer<T>
{
    private readonly T[] _data;
    public MyBuffer(ReadOnlySpan<T> items) => _data = items.ToArray();
}

// 工厂类
public static class MyBufferBuilder
{
    public static MyBuffer<T> Create<T>(ReadOnlySpan<T> values) => new MyBuffer<T>(values);
}

// 使用：
MyBuffer<int> buffer = [1, 2, 3, 4, 5];
```

---

#### 为什么优先推荐第二种？

虽然第一种写起来快，但第二种在性能和灵活性上更胜一筹：
1. **内存友好：** 编译器会将 `[]` 中的所有元素先放入一个 `ReadOnlySpan<T>`。这意味着你的工厂方法可以直接知道总长度（`values.Length`），从而一次性分配好内存，避免了 `Add` 方法可能导致的多次重新分配内存。
2. **支持 `Spread` 运算符：** 当你使用 `[.. other]` 时，第二种方式通常能产生更高效的指令。
3. **支持不可变类型：** 很多高性能集合（如 `ImmutableArray`）在构造后是不允许修改的，没有 `Add` 方法。这种情况下只能用 `CollectionBuilder`。

#### 甚至可以“欺骗”编译器

如果你想给一个你无法修改源码的第三方类（假设叫 `ThirdPartyStack<T>`）增加 `[]` 支持，你可以写一个**扩展方法**叫 `Add`。编译器在处理 `[]` 时也会尝试查找扩展方法。不过这种方式仅限“传统路径”。


**避坑指南：**
如果你自定义的类型同时拥有 `Add` 方法和 `CollectionBuilder` 特性，编译器会优先选择 **`CollectionBuilder`**，因为它更现代且通常更高效。
你现在是有具体的自定义集合类想要升级语法吗？还是在设计一套新的底层库？


### 总结

C# 12 的集合表达式：
1.  **表面上：** 统一了数组、List、Span、字典（C# 13 支持字典表达式）的初始化语法，代码变短了。
2.  **功能上：** 引入了 `..` 展开运算符，让集合拼接变得像 JavaScript/Python 一样简单。
3.  **底层里：** 编译器做了疯狂的性能优化，帮你预分配内存、使用 Span，性能通常比你自己手写的还要好。

这是 C# 近年来对日常业务开发体验提升最大的特性之一，**强烈建议全面抛弃以前的 `new List<T>{}` 写法，拥抱 `[...]`**。
