在 C# 12 之前，Lambda 表达式一直有一个让人很难受的限制：**不能给参数设置默认值**。如果你想要默认参数，你要么得老老实实写一个普通的局部方法（Local Function），要么在 Lambda 内部自己写一堆 `if (x == null)` 的判断逻辑。

C# 12 终于把这个短板补齐了。引入 **Lambda 表达式默认参数**后，Lambda 在语法层面上和普通方法平起平坐了。

我们来看看这个特性的**具体表现、底层陷阱（非常重要！）以及它的核心应用场景**。

---

### 极简语法：怎么用？

语法非常直观，和普通方法的默认参数一模一样：在参数名后面加 `= 默认值`。

```csharp
// C# 12 之前：如果想要默认值，只能在内部处理，且参数没法省略
var greetOld = (string name) => {
    name = string.IsNullOrEmpty(name) ? "匿名用户" : name;
    return $"Hello, {name}!";
};

// C# 12 之后：直接写在签名里
var greet = (string name = "匿名用户") => $"Hello, {name}!";

// 调用
Console.WriteLine(greet());        // 输出: Hello, 匿名用户!
Console.WriteLine(greet("张三"));   // 输出: Hello, 张三!
```

---

### 核心陷阱：为什么有时候调用会报错？（底层机制揭秘）

这里有一个极其重要、很多新手都会踩坑的底层逻辑：**默认参数是绑定在“委托类型（Delegate Type）”上的，而不是单单绑定在 Lambda 本身上的。**

看看下面这两行代码，猜猜结果：

```csharp
// 写法 1：使用 var (天然类型推断)
var add1 = (int x, int y = 1) => x + y;
Console.WriteLine(add1(5)); // ✅ 编译成功，输出 6

// 写法 2：强类型声明 Func
Func<int, int, int> add2 = (int x, int y = 1) => x + y;
Console.WriteLine(add2(5)); // ❌ 编译报错！提示缺少参数 'y'
```

**为什么写法 2 会报错？！**
因为 `Func<T1, T2, TResult>` 是 .NET 底层早就定义好的委托类型，它的签名里**没有默认参数**。
当你把 Lambda 赋值给 `Func` 时，编译器在调用时看的是 `Func` 的脸皮，`Func` 说必须传两个参数，你传一个就会报错。

**底层是怎么解决写法 1 的？**
当你使用 `var` 时（得益于 C# 10 引入的 Lambda 自然类型推断），编译器在底层为你**偷偷生成了一个全新的、匿名的委托类型**，并在那个生成的委托签名上加上了 `[Optional]` 和 `[DefaultParameterValue]` 特性。

**结论**：要完美享受 Lambda 默认参数，**请务必搭配 `var` 使用**，或者把它传递给那些会自动反射解析签名的框架（比如下面的 Minimal API）。

---

### 杀手级应用场景：为什么微软要加这个功能？

微软之所以在 C# 12 加上这个看似不起眼的特性，最核心的驱动力是为了 **ASP.NET Core Minimal APIs（极简 API）**。

在以前写 Minimal API 时，处理分页、默认参数非常繁琐：

#### Web API 的默认参数
**以前的折磨写法：**
```csharp
// 你必须接收一个可空的 int?，然后在内部自己判断并赋默认值
app.MapGet("/users", (int? page, int? pageSize) => 
{
    int actualPage = page ?? 1;
    int actualPageSize = pageSize ?? 10;
    return db.GetUsers(actualPage, actualPageSize);
});
```

**C# 12 的终极优雅写法：**
```csharp
// 直接写在 Lambda 签名里！Minimal API 框架会自动解析并绑定。
app.MapGet("/users", (int page = 1, int pageSize = 10) => 
{
    return db.GetUsers(page, pageSize);
});
```
*（注：ASP.NET Core 底层利用了反射 `MethodInfo` 来读取 Lambda 的默认值，所以就算框架底层把它当成 `Delegate` 存起来，依然能正确识别 `page=1`）。*

这不仅让代码少了几行废话，更重要的是，**生成的 Swagger/OpenAPI 文档会自动识别出这两个参数有默认值 1 和 10！** 这是极其巨大的体验提升。

#### LINQ 数据处理
在做数据聚合或者处理时，偶尔需要一个带默认值的内联小函数：

```csharp
var calculateScore = (int baseScore, int bonus = 0) => baseScore + bonus;

var total = users.Select(u => calculateScore(u.Score)).Sum();
```

---

### 默认参数支持 `params` 数组吗？

支持的！除了默认值，C# 12 的 Lambda 现在也支持 `params` 关键字了（这也是一起打包发布的功能）：

```csharp
var sum = (params int[] numbers) => numbers.Sum();

Console.WriteLine(sum());         // 0
Console.WriteLine(sum(1, 2, 3));  // 6
```
*(注：结合前面讲的集合表达式，在 C# 13 中 `params` 还能支持 `params ReadOnlySpan<int>`，性能会更加变态)。*

### 总结

C# 12 的 Lambda 默认参数：
1.  **本质**：补齐了 Lambda 和普通方法的语法差距。
2.  **坑点**：不要把它赋给传统的 `Func/Action`，**用 `var` 来声明**。
3.  **最大赢家**：**ASP.NET Core Minimal APIs 开发**，让路由处理函数的代码极其干净、直观，且能自动生成完美的 API 文档。
