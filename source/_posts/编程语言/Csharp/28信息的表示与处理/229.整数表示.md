# 整数表示

## 整型数据类型：内存中的“容器尺寸”

不同的大小的整数类型，本质上就是分配给它们的“内存抽屉（字节）”数量不同。

在 C 语言（CSAPP的语境）中，`long`、`int` 等类型的具体大小会根据机器（32位还是64位）发生变化。但**在 C# 中，为了保证绝对的跨平台一致性，整数类型的大小是被定死的！**

*   `short` (C#): 永远 16 位 (2 字节)
*   `int` (C#): 永远 32 位 (4 字节)
*   `long` (C#): 永远 64 位 (8 字节)

### 一个非常反直觉的现象（非对称性）
如果你观察有符号整数（能表示负数的整数）的取值范围，你会发现一个奇怪的现象：**负数总是比正数多一个！**

### C# 代码演示：探测整数的边界
```csharp
using System;

public class IntegerRangeDemo
{
    public static void Run()
    {
        Console.WriteLine("=== 1. 整型数据类型与取值范围 ===");
        
        Console.WriteLine($"short 占用 {sizeof(short)} 字节:");
        Console.WriteLine($"  范围: {short.MinValue} 到 {short.MaxValue}");
        
        Console.WriteLine($"int   占用 {sizeof(int)} 字节:");
        Console.WriteLine($"  范围: {int.MinValue} 到 {int.MaxValue}");
        // 仔细看：int.MinValue 是 -2147483648
        //        int.MaxValue 是  2147483647 (尾数是7，比负数少1)
        
        // 为什么正负不对称？
        // 因为 0 占用了正数这一半的“名额”。
    }
}
```

## 无符号编码

$B2U$ 的意思是把二进制（Binary）翻译成无符号数（Unsigned）。这是最符合人类直觉的编码方式。

假设我们有一个 $w$ 位的容器（比如 $w=4$）。
在无符号的世界里，**没有任何位被浪费，每一位都代表正的权重**。就像古人用天平称重，每个砝码只能增加重量。

*   第 $0$ 位（最右）的权重是 $2^0 = 1$
*   第 $1$ 位的权重是 $2^1 = 2$
*   第 $2$ 位的权重是 $2^2 = 4$
*   第 $3$ 位（最左）的权重是 $2^3 = 8$

**计算公式：**
一个二进制串 `1011` 的十进制值是多少？
就是把所有为 `1` 的位的权重加起来：$8 + 0 + 2 + 1 = 11$。
极其简单，这就是 $B2U$。最大能表示的是 `1111`，即 $8+4+2+1 = 15$。

## 补码编码

接下来是重头戏。计算机硬件设计者面临一个棘手的问题：**CPU 的电路只有加法器，没有减法器！** 
怎么才能在不增加额外“负号电路”的情况下，让计算机优雅地处理负数和减法？

天才的科学家发明了**补码 (Two's-Complement)**，简称 $B2T$。

### 核心思想：最高位是“超级债务”
在补码的世界里，大部分位和无符号数一样，都代表正的资产。
**唯独最高位（MSB，最左边的那一位），被称为符号位，它代表一个巨大的“负数权重（债务）”！**

我们还是以 $4$ 位二进制为例：
*   第 $0$ 位的权重是 $1$（资产）
*   第 $1$ 位的权重是 $2$（资产）
*   第 $2$ 位的权重是 $4$（资产）
*   **第 $3$ 位的权重是 $-8$！（超级债务）**

### 让我们来算几个数：
*   **如何表示 `0`？** `0000` = $0+0+0+0 = 0$。
*   **如何表示正数 `7`？** `0111` = $0 + 4 + 2 + 1 = 7$。
    *(注意：只要最高位是0，它就没有债务，跟无符号数一模一样！)*
*   **如何表示负数 `-8`？** `1000` = $-8 + 0 + 0 + 0 = -8$。
    *(这是能表示的最小负数，只有一笔死债，没有任何资产。)*
*   **如何表示负数 `-1`？** 负一是一个非常特殊的数字。
    你需要借最大的债务，然后用所有的资产去抵消它！
    `1111` = $-8 + 4 + 2 + 1 = -1$。
    **重点：在任何字长下，全 `1` 的二进制 (`0xFFFFFFFF`) 永远代表 `-1`！**

这就是为什么负数的范围比正数多 1。因为 `1000` 代表 `-8`，而正数最大只能到 `0111` (`7`)。

### 时钟模型：模的概念

想象一个普通的 12 小时制时钟。
- **模（Module）：** 这里的“模”就是 **12**。
- **等价性：** 如果现在是 6 点，你想让它指回 4 点，有两种拨法：
    1. **减法：** 逆时针拨 2 小时 ($6 - 2 = 4$)。
    2. **加法：** 顺时针拨 10 小时 ($6 + 10 = 16 \rightarrow 16 \pmod{12} = 4$)。
在模 12 的系统中，**-2** 和 **+10** 是等价的。我们称 10 是 -2 对模 12 的**补数**。

### 将减法转为加法

计算机的运算器（ALU）本质上只会做加法。为了处理减法，我们需要找到一种方法，用**正数加法**来模拟**负数减法**。

**核心公式**
在模为 $M$ 的系统中，对于任意负数 $-X$，它的补数 $Y$ 满足：
$$Y = M - |X|$$
这样，计算 $A - B$ 就可以转换为计算 $(A + \text{补码}_B) \pmod M$。
### 为什么补码是“取反加一”？

你可能学过补码的口诀：“取反加一”。这其实是计算 $M - |X|$ 的简便方法。
以 4 位系统为例，$M = 16$，也就是二进制的 `10000`。
要计算 $16 - X$，可以拆解为：
$$(1111 - X) + 1$$

- $(1111 - X)$：这步就是**按位取反**（每一位 0 变 1，1 变 0）。
- $+ 1$：补回刚才减掉的那个 1。

> **底层逻辑：** 这种设计让计算机不需要专门的减法电路，只需要一套加法器和一套取反电路，极大地简化了 CPU 的结构。

## 有符号与无符号的转换：人格分裂的 CPU

**这是 C/C++中最容易导致严重 Bug 的地方。**

我们前面强调了黄金定律：比特不变，视角改变。
当你在代码中把一个 `int` (有符号) 强转为 `uint` (无符号) 时，底层究竟发生了什么？
**答案是：什么都没有发生！内存里的 0 和 1 原封不动，CPU 只是换了一副“无符号的眼镜”重新审视这串数据。**

### 数值突变的原理
假设内存里存着一段 32 位的全 `1`：`1111 1111 ... 1111`
*   戴上**有符号（补码）** 眼镜看：最高位的 `1` 是巨大的债务 ($-2147483648$)，后面的 `1` 是资产，两两相抵，结果是 **`-1`**。
*   摘下眼镜，换上**无符号**眼镜看：没有债务！最高位的 `1` 瞬间变成了巨大的正资产 ($+2147483648$)，所有的权重加在一起，结果是一个极其庞大的正数：**`4294967295`**！

### C# 代码演示：无检查上下文 (`unchecked`) 揭示真相
在 C# 中，默认情况下编译器很聪明也很保守，如果你试图把 `-1` 塞给无符号整数，它会直接报错并抛出溢出异常。为了重现 CSAPP 里 C 语言的行为，我们必须使用 C# 的 **`unchecked`** 关键字，强行关闭安全检查。

```csharp
using System;

public class CastingDemo
{
    public static void Run()
    {
        Console.WriteLine("\n=== 4. 有符号与无符号的相互转换 ===");
        
        int signedMinusOne = -1;
        Console.WriteLine($"有符号数 (int): {signedMinusOne}");
        
        // 强行关闭 C# 的溢出检查，模仿 C 语言的底层行为
        unchecked 
        {
            // 将 int 强转为 uint，内存比特不发生任何改变！
            uint unsignedHugeNumber = (uint)signedMinusOne;
            
            Console.WriteLine($"转换后的无符号数 (uint): {unsignedHugeNumber}");
            
            // 让我们打印出它们的二进制，看看是不是一模一样
            string binSigned = Convert.ToString(signedMinusOne, 2);
            string binUnsigned = Convert.ToString(unsignedHugeNumber, 2);
            
            Console.WriteLine($"signedMinusOne 的二进制: {binSigned}");
            Console.WriteLine($"unsignedHugeNumber 的二进制: {binUnsigned}");
            Console.WriteLine("你看！底层 0 和 1 完全没有变，仅仅是‘解释方式’变了！");
        }
    }
}
```

**灾难案例：**
在 C 语言中，如果你写 `if (-1 < 0U)` (把 `-1` 和无符号的 `0` 比较)。C 语言会隐式地把 `-1` 转换成无符号数（变成了 `4294967295`），然后判断 `4294967295 < 0`，结果居然是 **False**！这种隐式转换导致了无数著名的安全漏洞。

## 扩展：从小容器搬到大容器

有时候，我们需要把一个短小的数字（比如 16位的 `short`）塞进一个巨大的容器里（比如 32位的 `int`）。
原来的 16 位放到新抽屉的右边，那**左边空出来的 16 位该填什么？** 填 `0` 还是填 `1`？

CSAPP 给出了两种极其严谨的策略：

### 零扩展 —— 适用于无符号数
如果是无符号数（`ushort` 转 `uint`），说明它没有负数，不需要操心符号。
左边空出来的地方，**简单粗暴，全部填 `0`**。数字的值绝对不会变。

### 符号扩展 —— 适用于有符号数
如果是有符号数（`short` 转 `int`），那就大有学问了！
假设你有一个 16 位的 `-1`，它的二进制是 `1111 1111 1111 1111` (16个1)。
如果你把它搬到 32 位的抽屉里，左边填了 `0`：`0000...0000 1111 1111 1111 1111`。
完了！最高位的超级债务没有了（最高位变成0了），这个数瞬间变成了一个正数 `65535`！

**怎么办？**
为了保证负数扩充后依然是同一个负数，必须采用**符号扩展**：**复制原来的最高位（符号位），填满所有新增的空位！**
*   如果原来最高位是 `0`（正数），左边全填 `0`。
*   如果原来最高位是 `1`（负数），左边全填 `1`。

在数学上，$-8 + 4 + 2 + 1 = -1$。如果你增加一位，变成了 $-16 + 8 + 4 + 2 + 1$，结果依然是 $-1$！**这就是补码最美丽的数学特性。**

### C# 代码演示：见证扩展魔法

```csharp
using System;

public class ExtensionDemo
{
    public static void Run()
    {
        Console.WriteLine("\n=== 5. 扩展 (Extension): short -> int ===");
        
        short smallNegative = -12345;
        // 把 16 位有符号整数强转为 32 位无符号整数，以便用 X8 查看完整的内存结构
        Console.WriteLine($"原始 16位 short: {smallNegative} [内存: 0x{(ushort)smallNegative:X4}]");
        
        // 隐式转换为 32 位 int。因为是负数，C# 自动触发“符号扩展”
        int largeNegative = smallNegative;
        Console.WriteLine($"扩展为 32位 int: {largeNegative} [内存: 0x{(uint)largeNegative:X8}]");
        
        // 观察输出的十六进制：
        // 16位时是 0xCFC7 (最高位 C 的二进制是 1100，所以符号位是 1)
        // 32位时变成了 0xFFFFCFC7 (前面硬生生多出来了四个 F，也就是 16 个 1！)
        // 计算机通过无限复制符号位，维持了数值的不变。
    }
}
```

## 截断：大抽屉强行塞进小抽屉

如果扩展是宽容的，那截断就是残忍的。
当你把一个 32 位的 `int` 强行塞进一个 16 位的 `short` 时，放不下怎么办？
**计算机的逻辑是：犹如希腊神话中的普罗克拉斯提斯之床，直接挥刀把高位砍掉！**

### 截断的数学本质与灾难后果
截断的数学本质是取模（求余数）。把 32 位截断为 16 位，等价于原数值 $mod\ 2^{16}$。

这会产生极其严重的后果：
1. **大数字变小**：因为高位的权重丢失了。
2. **正数变负数**：如果砍掉高位后，剩下部分的最左边那一位恰好是 `1`，那么在补码机制下，它瞬间就从正资产变成了超级债务！

### C# 代码演示：截断带来的数值大乱斗

依然需要使用 `unchecked`，否则 C# 会像负责任的保镖一样拦住你，不让你把大数塞进小类型里。

```csharp
using System;

public class TruncationDemo
{
    public static void Run()
    {
        Console.WriteLine("\n=== 6. 截断 (Truncation): int -> short ===");
        
        // 假设我们有一个普通的正数，它恰好比 short 能装的最大值 (32767) 大一点
        int bigNumber = 50000; 
        
        Console.WriteLine($"原始 32位 int: {bigNumber}");
        // 50000 的十六进制是 0x0000C350，二进制是 0000 0000 0000 0000 1100 0011 0101 0000
        
        unchecked
        {
            // 强行砍掉前 16 位，只保留后 16 位
            short truncatedNumber = (short)bigNumber;
            
            Console.WriteLine($"强行砍断成 16位 short 之后: {truncatedNumber}");
            
            // 发生了什么？
            // 砍掉高位后，剩下的是 0xC350 (二进制: 1100 0011 0101 0000)
            // 请注意，这 16 位数字的最左边（最高位）变成了 1！
            // 在 short 的眼里，最高位是债务！
            // 于是这个数字被解释成了负数：-15536
        }
    }
}
```

## 终极总结与执行入口

1. **补码法则**：最高位是唯一的负权（债务），其他位都是正权（资产）。全 `1` 永远是 `-1`。
2. **类型转换法则**：有符号转无符号，**改变的是灵魂（解释方式），而不是肉体（内存里的比特）**。
3. **扩展法则**：往大变，无符号补 `0`，有符号疯狂复制最高位。
4. **截断法则**：往小变，直接挥刀砍高位，可能会引发正负号突变的“血案”。
