# 信息的存储 —— 计算机世界的原子与物理法则

在开始之前，请在脑海中建立一个模型：**内存是一个无比巨大的中药柜。**
每一格抽屉只能装一样东西：**8个开关（8个比特位 = 1个字节）**。
每一个抽屉都有一个独一无二的编号，这个编号就是**内存地址（Address）**。
计算机世界上发生的一切——你玩的高清游戏、听的无损音乐、写的 C# 代码，本质上都是 CPU 在飞速地拉开这些抽屉，拨动里面的开关。

## 十六进制表示法：为什么科学家这么喜欢它？

### 痛点：二进制太长，十进制不搭
计算机只认识 `0` 和 `1`。如果我们在代码里全写二进制，比如一个普通的整数 `2024`，写成二进制是 `0000 0111 1110 1000`。这太反人类了，眼睛容易看瞎。
那为什么不用我们熟悉的十进制呢？因为**十进制和二进制的转换非常麻烦，它们之间没有“按位对齐”的天然关系**。

### 解决方案：十六进制（二进制的“速记法”）
计算机科学家发明了 $16$ 进制（$0-9, A-F$）。为什么是 $16$？因为 $16 = 2^4$。
这意味着：**每 $4$ 个二进制位，完美地对应 $1$ 个十六进制位！**
1个字节（Byte）是 8个比特（bit）。所以，**1个字节刚好可以用 2 个十六进制字符表示。**

*   `0000` = `0`
*   `1111` = `F` (十进制的 15)
*   比如字节 `0101 1010`，前四个 `0101` 是 `5`，后四个 `1010` 是 `A`，合起来就是 `0x5A`（`0x`是编程语言中表示十六进制的前缀）。

### C# 代码演示：进制之间的转换
在 C# 中，我们可以非常直观地观察这种对应关系。

```csharp
using System;

public class HexDemo
{
    public static void Run()
    {
        Console.WriteLine("=== 1. 十六进制与二进制的完美对应 ===");
        
        int number = 2024; // 十进制
        
        // 转换为二进制字符串，按 32 位补齐
        string binaryStr = Convert.ToString(number, 2).PadLeft(32, '0');
        // 转换为十六进制字符串，按 8 位补齐
        string hexStr = number.ToString("X8");
        
        Console.WriteLine($"十进制: {number}");
        Console.WriteLine($"二进制: {binaryStr}");
        Console.WriteLine($"十六进制: 0x{hexStr}");  // `hexStr` 已经是一个转换好的十六进制字符串了，所以可以在{}前写0x
        
        // 观察对应关系：
        // 二进制：0000 0000 0000 0000 0000 0111 1110 1000
        // 十六进制：   0    0    0    0    0    7    E    8
        // 你看！每4个二进制位，严丝合缝地对应1个十六进制字母！这就是科学家爱它的原因。
    }
}
```

## 字数据大小：32位与64位系统的鸿沟

### 什么是“字”？
在 CSAPP 中，“字长”指的是**CPU 一次性处理数据的最大宽度**，也决定了**指针（内存地址）的大小**。
还记得我们的“中药柜”比喻吗？
*   **32位系统**：CPU 找抽屉的编号条（地址）最多只有 32 位长（4个字节）。
*   **64位系统**：CPU 找抽屉的编号条有 64 位长（8个字节）。

### 这意味着什么？（内存寻址极限）
*   如果编号条只有 32 位，最多能写出 $2^{32}$ 个不同的编号。
*   $2^{32}$ 个抽屉 = $4,294,967,296$ 个字节 $\approx$ **4 GB**。
*   这就是为什么十年前的老电脑装 32 位 Windows 系统，就算你插 8GB 的内存条，系统也只认 4GB！因为剩下的抽屉，CPU **没有足够的编号去命名它们**！
*   换成 64 位系统，理论上可以寻址 $2^{64}$ 字节（约 16 EB），足够用到人类星辰大海了。

### C# 代码演示：探测你的系统字长
在 C# 中，指针的大小由 `IntPtr` (Integer Pointer) 结构体表示。

```csharp
using System;

public class WordSizeDemo
{
    public static void Run()
    {
        Console.WriteLine("\n=== 2. 字数据大小 (Word Size) ===");
        
        // IntPtr.Size 返回当前进程中指针占用的字节数
        int pointerSize = IntPtr.Size;
        int bits = pointerSize * 8;
        
        Console.WriteLine($"当前系统的指针占用 {pointerSize} 个字节。");
        Console.WriteLine($"因此，你正在运行一个 {bits} 位的进程。");
        
        if (pointerSize == 4) {
            Console.WriteLine("你的内存地址最大只能表示到 4GB。");
        } else if (pointerSize == 8) {
            Console.WriteLine("你的内存地址空间极其广阔，这是64位系统的优势。");
        }
    }
}
```

## 寻址和字节顺序：大端法 vs 小端法

### 一个对象跨越多个抽屉
前面说了，一个抽屉（内存地址）只能装 1 个字节（8位）。
但是在 C# 中，一个 `int` 整数需要占用 **4个字节**（32位）。
比如：十六进制数 `0x01234567`。
为了存下这个数字，CPU 需要在内存里找 **4个连续的抽屉**。假设这四个抽屉的编号（地址）是 `0x100`, `0x101`, `0x102`, `0x103`。

问题来了：这四个字节 (`01`, `23`, `45`, `67`)，**谁放前面，谁放后面？**

### 两种哲学：大端法 与 小端法
*   **最高有效字节 (MSB)**：数字里代表最大数量级的字节。比如 `0x01234567` 中，`01` 就是最高有效字节（就像十进制 `1234` 里的 `1` 代表一千，最重要）。
*   **最低有效字节 (LSB)**：`67` 是最低有效字节（代表个位数，最不重要）。

**大端法 (Big Endian) - 顺着人类的阅读习惯：**
最高有效字节存放在最低的内存地址处。
*   地址 `0x100` 存 `01`
*   地址 `0x101` 存 `23`
*   地址 `0x102` 存 `45`
*   地址 `0x103` 存 `67`
（网络传输协议通常强制使用大端法，所以又叫“网络字节序”）。

**小端法 (Little Endian) - 反着来，但对 CPU 友好：**
最低有效字节存放在最低的内存地址处。
*   地址 `0x100` 存 `67`
*   地址 `0x101` 存 `45`
*   地址 `0x102` 存 `23`
*   地址 `0x103` 存 `01`
（Intel 和 AMD 的 CPU（x86架构）全是小端法，你的 Windows 电脑 99.9% 是小端法）。

### C# 代码实战：像黑客一样扒开内存看端序
在日常写 C# 时你感觉不到大小端，因为 C# 替你封装好了。为了看到真相，我们需要开启 C# 宇宙的“上帝模式”：**`unsafe` 关键字和指针**。

*(注意：运行此代码需在项目设置中开启“允许不安全代码 / Allow unsafe code”)*

```csharp
using System;

public class EndiannessDemo
{
    // 使用 unsafe 关键字允许我们使用 C/C++ 风格的指针
    public static unsafe void Run()
    {
        Console.WriteLine("\n=== 3. 字节顺序：大端法 vs 小端法 ===");
        
        // 我们定一个普通的整数
        int magicNumber = 0x01234567;
        Console.WriteLine($"原始数字 (十六进制): 0x{magicNumber:X8}");
        Console.WriteLine($"当前系统是否为小端法: {BitConverter.IsLittleEndian}");

        // 获取 magicNumber 在内存中的首地址
        // & 取地址符，表示“把装 magicNumber 的抽屉编号给我”
        int* ptrToInt = &magicNumber;
        
        // 关键一步：把 int 类型的指针，强行转换成 byte 类型的指针。
        // 这意味着我们告诉 CPU：“不要把它当成一个完整的 4字节块看待，把它当成 4个独立的 1字节抽屉看待！”
        byte* ptrToByte = (byte*)ptrToInt;

        Console.WriteLine("\n扒开内存，逐字节观察：");
        for (int i = 0; i < sizeof(int); i++)
        {
            // ptrToByte[i] 等价于 *(ptrToByte + i)
            // 意思是：以首地址为基准，往后数第 i 个抽屉里的内容
            Console.WriteLine($"内存地址 [{(long)(ptrToByte + i):X}] 存放的字节是: 0x{ptrToByte[i]:X2}");
        }
        
        // 如果你的电脑是小端法（Intel/AMD/Apple Silicon），输出一定是：
        // 存放的字节是: 0x67  <- 最低有效字节放在了最低地址！
        // 存放的字节是: 0x45
        // 存放的字节是: 0x23
        // 存放的字节是: 0x01
    }
}
```
**CSAPP 核心感悟：** 当你把一个 `int` 发送到网络上给另一台计算机时，如果对方是大端法机器，它收到 `67 45 23 01` 后，会解析成 `0x67452301`，数字全变了！这就是为什么网络通信前必须统一字节序。

## 表示字符串：ASCII 与字节流

### 字符串只是戴着面具的字节数组
计算机根本不知道什么是字母 `A`、什么是汉字 `中`。它只认识数字。
为了显示文字，人类制定了“密码本”。最古老、最著名的密码本就是 **ASCII 码表**。
在 ASCII 中，字母 `A` 对应十进制数字 `65`（十六进制 `0x41`）。

在 C 语言中，字符串就是一个字节数组，最后一个字节永远是 `0x00`（表示字符串结束）。
在 C# 中，字符串稍微复杂一点（使用 UTF-16 编码），但为了演示 CSAPP 的底层逻辑，我们将其转换为 ASCII 字节流来看。

### C# 代码演示：透视字符串的真面目

```csharp
using System;
using System.Text;

public class StringDemo
{
    public static void Run()
    {
        Console.WriteLine("\n=== 4. 字符串的本质：ASCII 字节流 ===");
        
        string text = "CSAPP";
        Console.WriteLine($"字符串: \"{text}\"");
        
        // 获取该字符串对应的 ASCII 字节流
        byte[] bytes = Encoding.ASCII.GetBytes(text);
        
        Console.Write("内存中的字节流 (十六进制): ");
        foreach (byte b in bytes)
        {
            Console.Write($"0x{b:X2} ");
        }
        Console.WriteLine();
        
        // 输出结果：0x43 0x53 0x41 0x50 0x50 
        // 查字典：
        // 0x43 = 67 = 'C'
        // 0x53 = 83 = 'S'
        // 0x41 = 65 = 'A'
        // 0x50 = 80 = 'P'
        // 0x50 = 80 = 'P'
        
        Console.WriteLine("注意：文本数据是与字节顺序（大小端）无关的！");
        // 因为每个字符刚好占 1 个字节，不存在跨多个字节存储的“顺序”问题。
        // 这就解释了为什么 .txt 文本文件在所有电脑上打开都不会乱码（假设编码一致）。
    }
}
```

## 表示代码：机器指令也是一串字节

这一段在 CSAPP 中是非常震撼的概念：**数据和代码，在内存中没有任何区别。它们都是一堆字节。**

冯·诺依曼架构的核心思想就是 **“存储程序”**。
当你写下 `int a = 1 + 2;` 并编译后，编译器会把这句代码翻译成 CPU 认识的机器指令（比如一系列十六进制数字 `48 83 C0 03...`）。

如果你让 CPU 把内存里的 `0x43 0x53` 当作**数据**去读，它就是字符串 `"CS"`。
如果你让 CPU 把内存里的 `0x43 0x53` 强行当成**代码**去执行，它可能就是一条汇编指令 `inc ebx; push ebx`！

**为什么你编译好的 `.exe` 程序不能拷贝到 Mac 或者手机上运行？**
1. **指令集不同**：你的电脑是 x86 架构（说英语），手机通常是 ARM 架构（说法语）。同样的字节流 `0x55`，x86 认为是“推入栈指令”，ARM 可能认为是“加法指令”，直接崩溃。
2. **操作系统不同**：Windows 的 `.exe` 和 Mac 的无后缀执行文件，打包这些机器码的“包装盒（格式）”不一样，系统加载器不知道怎么拆包。

*(由于 C# 运行在虚拟机 CLR 上，这一步很难直接用 C# 展示纯粹的机器码，但理解这个概念对后续学习 CSAPP 第三章汇编语言至关重要。)*

## 布尔代数与位级运算：(AND, OR, NOT, XOR)

欢迎来到计算机的心脏！CPU 的底层电路全部是由逻辑门（Logic Gates）组成的。我们要学会像电路一样思考：**一次只处理一个比特（0或1）**。

### 四大天王介绍
*   **AND (`&`, 按位与)**：极其严格。必须两人都同意（都是1），结果才是 1。否则为 0。
    *   `1 & 1 = 1`
    *   `1 & 0 = 0`
*   **OR (`|`, 按位或)**：极其宽容。只要有一人同意（一个是1），结果就是 1。
    *   `1 | 0 = 1`
    *   `0 | 0 = 0`
*   **NOT (`~`, 按位取反)**：叛逆者。是 1 就变 0，是 0 就变 1。
    *   `~1 = 0`
*   **XOR (`^`, 按位异或)**：找茬专家是不进位加法。两人**不一样**结果就是 1，**一样**就是 0。
    *   `1 ^ 0 = 1` (不一样)
    *   `1 ^ 1 = 0` (一样)

### C# 代码演示：位级运算
在 CSAPP 中，最常用的技巧叫 **掩码 (Masking)**。掩码就像一块镂空的纸板，盖在数据上，让你只看到你想看的位，或者修改特定的位。

```csharp
using System;

public class BitwiseDemo
{
    public static void Run()
    {
        Console.WriteLine("\n=== 6. 布尔代数与位级运算 ===");
        
        // 假设我们有一个权限系统（8位），用二进制表示
        // 从右到左：读权限(第0位)，写权限(第1位)，执行权限(第2位)
        byte READ = 0b_0000_0001;    // 1
        byte WRITE = 0b_0000_0010;   // 2
        byte EXECUTE = 0b_0000_0100; // 4
        
        // 1. 使用 OR (|) 组合权限
        byte myPermission = (byte)(READ | WRITE); // 0000_0011 (拥有读和写)
        Console.WriteLine($"我的权限 (二进制): {Convert.ToString(myPermission, 2).PadLeft(8, '0')}");
        
        // 2. 使用 AND (&) 检查是否有某个权限 (掩码操作)
        // 思想：用想要检查的位去 AND 目标数据。如果结果不是0，说明有权限。
        bool hasWrite = (myPermission & WRITE) != 0; // 0011 & 0010 = 0010 (不为0)
        bool hasExecute = (myPermission & EXECUTE) != 0; // 0011 & 0100 = 0000 (为0)
        Console.WriteLine($"有写权限吗？ {hasWrite}");
        Console.WriteLine($"有执行权限吗？ {hasExecute}");
        
        // 3. 使用 NOT (~) 和 AND (&) 移除权限
        // 思想：~WRITE 是 1111_1101。用它去 AND 权限，就能强行把第1位变成0，其他位保持不变！
        myPermission = (byte)(myPermission & ~WRITE); 
        Console.WriteLine($"移除写权限后 (二进制): {Convert.ToString(myPermission, 2).PadLeft(8, '0')}");

        // 4. 使用 XOR (^) 实现不需要中间变量的交换 (非常经典的面试题)
        int a = 10, b = 20;
        Console.WriteLine($"\n交换前: a={a}, b={b}");
        a = a ^ b;
        b = a ^ b; // 此时 b 变成了 10
        a = a ^ b; // 此时 a 变成了 20
        Console.WriteLine($"XOR魔法交换后: a={a}, b={b}");
    }
}
```

**深入理解 XOR 魔法：**
异或有极其优美的数学性质：
1. $X \oplus 0 = X$ （任何数异或0等于自己）
2. $X \oplus X = 0$ （任何数异或自己等于0）
3. 满足交换律。
所以 `a = a ^ b`; `b = a ^ b` (等价于 `(a^b)^b` = `a^(b^b)` = `a^0` = `a`)。

## 逻辑运算 (&&, ||, !) vs 位级运算 (&, |, ~) 的天壤之别

**很多初学者死在这里：少写了一个 `&` 符号，导致整个程序逻辑大乱。**

### 核心区别
*   **位级运算 (`&`, `|`, `~`)**：是**瞎子**。它们不管数字代表什么意思，只把数字拆成一个个的 `0` 和 `1`，然后一位一位地去死磕。
*   **逻辑运算 (`&&`, `||`, `!`)**：是**大局观者**。在它们眼里，世界非黑即白。**任何非0的值都是 `TRUE`，只有全0才是 `FALSE`。** 它们只返回 `TRUE` 或 `FALSE`。

*(注：C/C++ 中没有 bool 类型，0 就是 false，非 0 比如 100 也是 true。C# 是强类型语言，严格区分 `bool` 和 `int`，所以在 C# 中你不能写 `if(100)`，必须写 `if(100 != 0)`。)*

### 短路特性
逻辑运算还有一个终极绝招：**短路**。
*   对于 `A && B`：如果 A 是假，它**绝对不会去执行 B**，直接判定为假。
*   对于 `A & B` (位运算)：它头铁，A 和 B 都要算出来，然后再按位计算。

### C# 代码演示：致命的笔误

```csharp
using System;

public class LogicVsBitwiseDemo
{
    private static bool DoSomethingRisky()
    {
        Console.WriteLine("警告：执行了高风险操作！");
        return true;
    }

    public static void Run()
    {
        Console.WriteLine("\n=== 7. 逻辑运算 vs 位运算的区别 ===");
        
        bool isSafe = false;

        Console.WriteLine("场景 1：使用逻辑与 (&&)");
        // 因为 isSafe 是 false，&& 发生“短路”，后面的 DoSomethingRisky() 根本不会运行！
        if (isSafe && DoSomethingRisky()) 
        {
            Console.WriteLine("条件成立");
        }
        
        Console.WriteLine("\n场景 2：使用位与 (&) - 假设手滑少敲了一个 &");
        // & 没有短路功能，它一定会强行把两边都计算出来！导致高风险代码被意外执行！
        if (isSafe & DoSomethingRisky()) 
        {
            Console.WriteLine("条件成立");
        }
    }
}
```
**忠告：** 永远不要把 `&` 和 `&&` 搞混。特别是在指针操作时，比如 `if (p != null && p->value == 1)`，如果写成 `&`，当 `p` 是空指针时依然会强行去读取 `p->value`，导致程序直接闪退（段错误 Segmentation Fault）。

## 移位运算：乘除法的“降维打击”

最后，我们来看移位。
为什么 CSAPP 花大篇幅讲移位？因为**在 CPU 里做乘法和除法是非常昂贵、极其耗时的操作**。如果能用移位代替，程序的性能会起飞。

### 左移 (`<<`)：乘以 2 的次方
左移很简单，就是把所有二进制位向左推。右边空出来的位，**永远补 0**。
*   `0000 0011` (十进制 3) 左移 1 位 (`3 << 1`) -> `0000 0110` (十进制 6)
*   左移 $k$ 位，等价于原数乘以 $2^k$。

### 右移 (`>>` 和 `>>>`)：逻辑 vs 算术
右移比较复杂。当我们把所有位向右推时，**左边空出来的位该补什么？**
CSAPP 给出了两种答案，这取决于数字是无符号（全是正数）还是有符号（包含负数）。

1.  **逻辑右移 (Logical Right Shift)**：**左边永远填 0**。
    *   适用于无符号数（C语言里的 `unsigned int`，C#里的 `uint`）。
2.  **算术右移 (Arithmetic Right Shift)**：**左边填充原本的符号位（最高位）**。
    *   为什么？为了保持正负号不变！
    *   在二进制补码中，如果最高位是 1，代表这是个负数。如果你右移后左边强行塞一个 0 进去，负数瞬间就变成正数了，这就乱套了。
    *   适用于有符号数（C语言里的 `int`，C#里的 `int`）。

### C# 代码演示：C# 11 中的无符号右移运算符 `>>>`

在 C# 11 之前，要把 `int` 进行逻辑右移很麻烦（得强转成 `uint`）。从 C# 11 开始，引入了直接的逻辑右移操作符 `>>>`

```csharp
using System;

public class ShiftDemo
{
    public static void Run()
    {
        Console.WriteLine("\n=== 8. 移位运算：逻辑 vs 算术 ===");
        
        // 我们用一个负数来演示。在32位整数中，-4 的二进制补码是：
        // 1111 1111 1111 1111 1111 1111 1111 1100
        int negativeNumber = -4; 
        
        Console.WriteLine($"原始数字: {negativeNumber}");
        Console.WriteLine($"二进制表示: {Convert.ToString(negativeNumber, 2).PadLeft(32, '0')}");

        // 1. 算术右移 (>>)
        // C# 中的 >> 对有符号整数默认执行算术右移。最高位是1，所以左边全补1。
        int arithmeticShift = negativeNumber >> 1; 
        Console.WriteLine($"\n算术右移 1 位 (>>): {arithmeticShift}"); // 变成了 -2 (除以2)
        Console.WriteLine($"二进制表示: {Convert.ToString(arithmeticShift, 2).PadLeft(32, '0')}");
        // 观察二进制：1111...1110，左边补进来的是 1，保住了它负数的身份！

        // 2. 逻辑右移 (>>>) (要求 C# 11 及以上)
        // 强行无视符号，左边只补 0。
        int logicalShift = negativeNumber >>> 1; 
        Console.WriteLine($"\n逻辑右移 1 位 (>>>): {logicalShift}"); // 变成了一个巨大的正数: 2147483646
        Console.WriteLine($"二进制表示: {Convert.ToString(logicalShift, 2).PadLeft(32, '0')}");
        // 观察二进制：0111...1110，左边补进来的是 0，瞬间负变正！
        
        // 3. 左移代替乘法
        int x = 5;
        Console.WriteLine($"\n计算 {x} * 8 (等价于左移 3 位):");
        Console.WriteLine($"5 << 3 = {x << 3}");
    }
}
```

## 终极总结与执行代码

这就是 CSAPP 第二章前半部分的核心灵魂。让我们总结一下你刚刚学到的东西：
1. **内存观念**：内存是一维的字节数组，指针就是数组的索引。
2. **进制思维**：十六进制是二进制的亲密外衣。
3. **空间观念**：字长决定了系统能访问多大的内存。
4. **存储思维**：大端小端决定了多字节数据在内存里的排列顺序（网络通信必考）。
5. **本质还原**：字符串和机器指令在内存里都只是一堆毫无感情的字节。
6. **逻辑与位思维**：通过掩码操作控制每一颗晶体管的状态，永远不要搞混 `&` 和 `&&`。
7. **优化思维**：移位操作是降维打击，算术右移保符号，逻辑右移补零。
