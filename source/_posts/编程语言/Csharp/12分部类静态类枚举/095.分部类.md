# 分部类：类型的物理拆分与编译时合并

## 核心概念

分部类（Partial Class）允许将一个类、结构体或接口的定义物理拆分到多个不同的源文件中。尽管在开发阶段代码分布在多个文件中，但在**编译时（Compile Time）**，C# 编译器会将具有相同名称和相同命名空间的所有分部定义合并为一个完整的单一类型。

从《CLR via C#》的底层视角来看：**分部类纯粹是 C# 编译器提供的一种语法糖，公共语言运行时（CLR）对其一无所知。** 编译生成的中间语言（IL）代码中不存在分部类的概念，最终生成的程序集（DLL/EXE）中只有一个完整的类型。调用方在实例化和使用该类时，与使用普通类没有任何区别。

## 分部类的声明与合并规则

要成功定义和使用分部类，必须遵循一系列严格的编译器规则：

1.  **强制使用 `partial` 关键字**：所有参与合并的类定义都必须显式声明为 `partial class`。
2.  **相同的命名空间与名称**：所有的部分必须位于完全相同的命名空间中，且类名必须绝对一致。
3.  **同一程序集**：分部类只能在同一个项目（程序集）内跨文件合并，不能跨越不同的 DLL。
4.  **无重复成员**：由于最终会合并为一个类，因此不能在不同的部分中定义同名的字段或方法（方法的重载除外）。

**代码示例：跨文件定义 Product 类**

**文件 1：Product.Properties.cs**
```csharp
namespace Warehouse.Models;

// 第一部分：定义数据结构和属性
public partial class Product
{
    public int ProductId { get; set; }
    public string ProductName { get; set; }
    public decimal Cost { get; set; }
}
```

**文件 2：Product.Methods.cs**
```csharp
namespace Warehouse.Models;

// 第二部分：定义行为和方法
public partial class Product
{
    // 在这里可以直接访问在另一个文件中定义的 Cost 属性
    public decimal GetTax()
    {
        return Cost * 0.10m; // 假设税率为10%
    }
}
```

**消费者调用：**
```csharp
using Warehouse.Models;

public class Program
{
    public static void Main()
    {
        // 调用方视其为一个完整的类
        Product p = new Product 
        { 
            ProductId = 1, 
            ProductName = "Laptop", 
            Cost = 1000m 
        };
        
        decimal tax = p.GetTax(); // 输出 100
    }
}
```

## 核心应用场景

虽然将一个类拆分成多个文件可以让多名开发者在不产生源代码版本冲突的情况下并行开发，但结合《代码大全》和现代工程实践，分部类最核心的应用场景通常是**分离自动生成的代码与开发者手写的代码**。

*   **代码生成器隔离**：在 Windows Forms、WPF、早期 Entity Framework 以及现代的 .NET Source Generators 中，工具会根据 UI 设计器或数据库元数据自动生成大量代码（如控件的初始化代码）。这些代码会被放在一个分部类文件中（如 `Form1.designer.cs`）。开发者可以在另一个文件（如 `Form1.cs`）中编写业务逻辑。即使工具重新生成了代码，开发者手写的部分也不会被覆盖丢失。
*   **避免上帝类（God Object）的临时妥协**：当一个类因为历史原因变得极其庞大时，将其拆分为分部类可以暂时缓解代码导航的困难。但从面向对象设计的角度来看，更推荐的做法是通过重构（提取类、使用设计模式）来遵循单一职责原则（SRP）。

## 深入剖析机制：修饰符与继承的合并

当编译器合并多个分部类时，还会合并它们身上的修饰符、基类和接口。

### 修饰符的累加效应
如果一个分部类部分被标记为 `abstract`，而另一部分没有标记，那么合并后的最终类就是 `abstract` 的。同理适用于 `sealed`。
*注意：不能在不同部分使用冲突的访问修饰符（如一个部分是 `public`，另一部分是 `internal`，这会导致编译错误）。*

### 基类与接口的合并
*   **接口合并**：如果 Part A 实现了 `IComparable`，Part B 实现了 `IDisposable`，则最终的类同时实现这两个接口。
*   **基类一致性**：如果分部类需要继承自某个基类，可以在一个部分中声明，也可以在多个部分中声明。但如果多个部分都声明了基类，**它们声明的基类必须完全相同**（C# 不支持多重继承）。

```csharp
public partial class Employee : Person, IWorker { }
public partial class Employee : IManager { }

// 编译后的等效结果：
// public class Employee : Person, IWorker, IManager { }
```

## 扩展：分部类的适用范围

除了 `class` 之外，`partial` 关键字同样适用于：
*   **分部结构体 (`partial struct`)**
*   **分部接口 (`partial interface`)**
*   **分部记录类型 (`partial record`)** (C# 9.0 引入)

在所有这些类型中，物理拆分和编译时合并的原则与分部类完全一致。
