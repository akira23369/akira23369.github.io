# 分部方法 ：为自动生成代码预留的“钩子”

## 核心概念

分部方法（Partial Method）是建立在分部类（Partial Class）基础之上的一种机制。它允许在一个分部类文件中仅**声明**方法签名，而在另一个分部类文件中提供该方法的**具体实现**。

在实际的工程协作或代码生成场景中，它的主要作用是提供一种“轻量级的事件钩子（Hook）”。例如，代码生成工具（第一开发者）可以声明并调用一个分部方法，而让使用该工具的业务开发人员（第二开发者）决定是否要去实现这个方法。

## 传统分部方法的严格规则 (C# 3.0 - C# 8.0)

在早期的 C# 版本中，分部方法有着非常严格的限制。如果不加任何访问修饰符，分部方法默认遵循以下传统规则：

1.  **隐式私有 (Implicitly Private)**：不能显式添加 `public`、`protected` 等访问修饰符，方法只能在声明它的类内部被调用。
2.  **必须返回 void**：不能有任何返回值（即必须是 `void`）。
3.  **不能有 `out` 参数**：因为如果方法没有被实现，`out` 参数将无法被初始化。
4.  **实现是可选的 (Optional Implementation)**：这是分部方法最核心的魔法。

### 编译器魔法：零成本抽象
根据《深入理解 C#》(C# in Depth) 与 《CLR via C#》的解析，如果一个传统分部方法被声明并调用了，但没有任何开发者去实现它，**C# 编译器会在编译时直接将该方法的声明以及所有调用该方法的代码行全部抹除。**

这意味着在运行时（IL 级别），未实现的分部方法完全不存在，不会带来任何性能损耗（连空方法调用的开销都没有）。

**代码示例：传统分部方法**

**文件 1：自动生成的代码 (Auto-generated)**
```csharp
public partial class TaxCalculator
{
    // 1. 仅声明分部方法（作为钩子）
    partial void OnTaxCalculated(double taxAmount);

    public void ProcessTax(double cost)
    {
        double tax = cost * 0.10;
        
        // 2. 调用分部方法
        // 编译器魔法：如果没有任何文件实现此方法，这一行代码在编译后将被直接删除！
        OnTaxCalculated(tax); 
    }
}
```

**文件 2：开发者手写的代码 (Developer written)**
```csharp
public partial class TaxCalculator
{
    // 3. 实现该分部方法
    partial void OnTaxCalculated(double taxAmount)
    {
        Console.WriteLine($"计算完成，产生的税额为: {taxAmount}");
    }
}
```

## 现代 C# 的扩展分部方法 (C# 9.0 及以上)

传统分部方法由于“必须返回 `void`”和“必须私有”的限制，在现代 .NET 的**源生成器 (Source Generators)** 技术面前显得力不从心。因为有时候，我们需要自动生成的代码返回一个特定的值，或者允许外部调用。

为此，C# 9.0 引入了**扩展分部方法 (Extended Partial Methods)**。

### 扩展规则
只要为分部方法添加了**显式的访问修饰符**（即使是 `private`），该方法就会升级为扩展分部方法，并遵循全新的规则：

1.  **支持所有访问修饰符**：可以是 `public`、`internal` 等。
2.  **允许非 `void` 返回类型**：可以返回 `int`、`string` 等任何类型。
3.  **允许 `out` 参数**。
4.  **实现变成强制性 (Mandatory Implementation)**：一旦加了访问修饰符，编译器就会要求必须在某个地方实现该方法，否则会直接报编译错误。抹除魔法不再适用。

**代码示例：现代扩展分部方法**

```csharp
// 文件 1：开发者定义签名
public partial class Product
{
    // 显式添加了 public，这是一个扩展分部方法，返回类型为 double
    public partial double GetDiscountRate();
}

// 文件 2：代码生成器或另一个开发者提供实现
public partial class Product
{
    // 强制必须实现，否则无法通过编译
    public partial double GetDiscountRate()
    {
        return 0.15; // 返回 15% 的折扣
    }
}
```

## 最佳实践与应用场景

结合《代码大全》中的解耦思想，分部方法极其适合以下场景：

*   **大型类库或框架的二次开发**：框架提供者在关键生命周期节点声明分部方法（如 `OnCreated`, `BeforeSave`），业务开发者根据需要选择性实现，无需使用复杂的委托或事件机制。
*   **配合 Source Generators**：在现代 .NET 开发中（如高性能的正则表达式生成、System.Text.Json 序列化生成），开发者编写扩展分部方法的签名，由 Source Generator 自动生成包含复杂逻辑的实现体。这极大地提升了运行时的执行效率（避免了反射）。
