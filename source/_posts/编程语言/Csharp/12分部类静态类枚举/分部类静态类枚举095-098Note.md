# 第13节：分部类、静态类与枚举

## 第一讲：分部类

### 引言
**partial 类**是 C#中的一项特殊功能，它允许将单个类的定义拆分到多个物理 .cs 文件中。当编译应用程序时，C#编译器会找到分部类的所有独立部分，并将它们组合成一个完整的类。这纯粹是**编译时的特性**；在运行时，常规类和分部类没有任何区别。

### 工作原理：partial 关键字
要创建分部类，你需要在定义类部分的每个文件中，在 class 关键字前使用 partial 关键字。所有部分必须：
- 使用 partial 关键字。
- 具有完全相同的类名。
- 位于同一命名空间中。
- 位于同一项目（程序集）中。

编译器会将所有分部文件中的成员（字段、属性、方法等）合并到最终的类定义中。

### 为何及何时使用
1. **与源生成器配合使用（主要用例）**： 这是现代 C#中分部类**最重要且最常见**的用途。许多.NET 框架（如 ASP.NET Core、WPF、WinForms）使用代码生成工具。这些工具会根据您的定义（例如从 UI 设计或 Web 端点）自动生成代码，并将这些机器生成的代码放在分部类的一个部分中（例如 MyPage.g.cs）。这使得开发者可以在同一类的另一个单独文件中编写自己的逻辑（例如 MyPage.cs）。这种分离至关重要，因为它意味着您可以自由修改代码，而不用担心代码生成器在再次运行时覆盖您的更改。
2. **管理超大型类**： 在一些遗留系统或极其庞大的类中，可以使用 partial 关键字将类拆分到多个文件中以便更好地组织。例如，一个巨型类可以将字段和属性放在一个文件中，公共方法放在另一个文件中，私有辅助方法则放在第三个文件中。

**最佳实践提示**： 虽然这种做法可行，但需要拆分类通常意味着违反了**单一职责原则**。这往往表明该类承担了过多功能，应该重构为多个更小、更专注的类。

### 示例
让我们将 User 类定义拆分到两个文件中。

**文件 1：User.Data.cs**
```csharp
namespace MyWebApp
{
    // User 类的第一部分，专注于数据。
    public partial class User
    {
        public int Id { get; set; }
        public string Username { get; set; }
        public string Email { get; set; }
    }
}
```

**文件 2：User.Logic.cs**
```csharp
namespace MyWebApp
{
    // User 类的第二部分，专注于行为。
    public partial class User
    {
        public void SendWelcomeEmail()
        {
            // 此方法可以访问另一个文件中定义的 'Email' 属性。
            Console.WriteLine($"Sending welcome email to {this.Email}...");
        }
    }
}
```

在编译时，这两个部分会被合并成一个包含全部四个成员的 User 类。

## 第二讲：分部方法

### 引言
**分部方法**是一种特殊的方法类型，其定义可以与实现分离。方法的签名（声明）可以在分部类的一个部分中定义，而实现（方法体）可以在同一分部类的另一个部分中选择性提供。

### 运作原理 & 未实现方法的"魔法"
分部方法使用 partial 关键字声明，必须具有 void 返回类型，并且隐式地为 private。

**文件1（例如，一个生成的文件）：《声明》**
```csharp
public partial class MyComponent
{
    // 定义分部方法的签名。这是一个"钩子"。
    partial void OnNameChanged(string newName);

    public void SetName(string name)
    {
        // ... 设置名称的逻辑 ...
        
        // 生成器可以安全地调用该分部方法。
        OnNameChanged(name);
    }
}
```

**关键特性**： 如果 MyComponent 类的其他部分没有为 OnNameChanged 提供实现，C#编译器会**完全移除该方法声明及其所有调用**。调用语句 `OnNameChanged(name);` 会从最终编译代码中彻底删除。这意味着对于未实现的 partial 方法存在**零性能开销**。

### 为何及何时使用
该功能几乎专为源代码生成器设计。生成器将分部方法定义为"可选钩子"，开发者可选择是否实现。这使得生成的代码能提供可定制的入口点，同时不强制开发者在不需要时实现它们。

### 示例：实现分部方法
**文件2（例如手写文件）：可选实现**
```csharp
public partial class MyComponent
{
    // 在这里为分部方法提供实现。
    // 因为实现存在，编译器会保留 SetName() 中的调用。
    partial void OnNameChanged(string newName)
    {
        Console.WriteLine($"Notification: Name was changed to '{newName}'.");
    }
}
```

## 第三讲：静态类

### 引言
一个**静态类**是不能被实例化且不能被继承的类。它只能包含 static 成员（字段、属性和方法）。它充当了一组不依赖任何对象状态的相关实用函数或常量的简单容器。

### 工作原理：编译时构造
将类标记为 static 主要是告诉编译器强制执行两条严格规则：
1. 该类的所有成员必须也被声明为 static。如果尝试在静态类中声明实例成员，编译器将报错。
2. 无法通过 new 关键字创建该类的实例，且其他类也不能继承它。

无需创建对象，可直接通过类名访问其成员。

### 为何及何时使用
当您有一组逻辑相关但不需要与特定对象状态关联的辅助方法或实用工具方法时，应使用静态类。

#### .NET 框架中的实际示例
- **System.Math**：包含数学运算方法，如 Sqrt()、Max()、Sin()。计算平方根时不需要创建 Math 对象。
- **System.Console**：包含控制台窗口交互方法，如 WriteLine() 和 ReadKey()。
- **System.IO.File**：包含文件操作实用方法，如 ReadAllText() 和 Exists()。

### 示例：自定义工具类
```csharp
// 'static' 确保此类不能被实例化。
public static class UnitConverter
{
    private const double KmsInAMile = 1.60934;
    
    // 所有成员也必须是静态的。
    public static double KilometersToMiles(double km)
    {
        return km / KmsInAMile;
    }

    public static double MilesToKilometers(double miles)
    {
        return miles * KmsInAMile;
    }
}

// --- 在 Main 方法中 ---
// 直接通过类名调用方法。
double miles = UnitConverter.KilometersToMiles(10);
Console.WriteLine($"10km is approximately {miles:F2} miles.");
```

## 第四讲：枚举类型

### 引言
一个**枚举（或称 enum）** 是一种特殊的值类型，它允许您定义一组命名的整型常量。它提供了一种创建独特类型的方式，用于表示一组固定的相关值，从而使代码更具**可读性、可维护性和类型安全性**。

### 为何及何时使用
枚举的主要目的是避免 **"魔法数字"**  并提高代码可读性。与其编写像 `if (userStatus == 2)` 这样缺乏上下文意义的代码，您可以使用 `if (status == UserStatus.Suspended)`。这种方式具有自解释性且更不易出错。它将变量限制在一组已知的允许值范围内，防止因赋值无效整数而导致的错误。

### 工作原理：基础值
默认情况下，枚举的底层数据类型是 int。编译器会从 0 开始为成员分配值，并逐个递增。
```csharp
public enum DayOfWeek // 从 0 开始
{
    Sunday,    // 0
    Monday,    // 1
    Tuesday,   // 2
    Wednesday, // 3
    Thursday,  // 4
    Friday,    // 5
    Saturday   // 6
}
```

您可以自定义此行为：
1. **更改起始数字**：
```csharp
public enum Month { January = 1, February = 2, /* ... */ }
```
2. **更改基础类型**（改为 byte、long 等）：
```csharp
public enum ErrorCode : ushort { NotFound = 404, ServerError = 500 }
```

### 示例
```csharp
public enum ShippingStatus
{
    Ordered,
    Processing,
    Shipped,
    InTransit,
    Delivered
}

public class Order
{
    public int OrderId { get; set; }
    public ShippingStatus Status { get; set; }
}

public class ShippingService
{
    public void ProcessOrder(Order order)
    {
        // 在 switch 语句中使用枚举非常简洁且可读性高。
        switch (order.Status)
        {
            case ShippingStatus.Ordered:
                Console.WriteLine("Processing the order...");
                order.Status = ShippingStatus.Processing;
                break;
            case ShippingStatus.Processing:
                Console.WriteLine("Shipping the order...");
                order.Status = ShippingStatus.Shipped;
                break;
            // ... 其他情况
        }
    }
}
```

## 第五讲：重要知识点备忘

1. **partial 是编译时特性**： 这是最重要的要点。分部类和分部方法是用于在不同文件中组织源代码的工具。编译器会在程序运行前将它们"缝合"成一个完整的类。在运行时，CLR 并没有"分部类"的概念。
2. **使用 partial 的主要场景是代码生成**： 在现代 C# 中，遇到分部类的主要原因是使用自动生成代码的框架（如 ASP.NET Core、WPF、Entity Framework）。它提供了机器生成代码和开发者编写代码之间的清晰分离。
3. **一个 static class 是密封的抽象容器**： 这样理解会很有帮助。说它"抽象"是因为不能创建实例，说它"密封"是因为不能继承。它的唯一目的是容纳一组静态成员。
4. **static class 与单例模式的对比**： 这是个很好的面试话题。
   - 静态类完全不能被实例化。它仅作为其成员的单一容器存在，且不能实现接口。
   - 单例模式是一种设计模式，通过将常规类设计为只能创建**唯一实例**。该唯一实例可作为对象传递、可实现接口，并且可被继承（若未密封）。
5. **使用 enum 确保类型安全与可读性**： 当变量需要限定在固定的小型命名值集合时，始终优先使用枚举而非整数或字符串常量。这能预防错误并使代码具备自解释性。
6. **enum 类型转换**： 可将整型显式转换为枚举类型，反之亦然。这在需要与数据库或存储枚举数值的 API 交互时特别有用。`ShippingStatus status = (ShippingStatus)2; // status 现在是 'Shipped'` . `int statusValue = (int)ShippingStatus.Shipped; // statusValue 是 2`。
