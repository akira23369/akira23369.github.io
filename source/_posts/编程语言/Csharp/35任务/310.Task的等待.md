# Task的等待

## 一、为什么要等待？（场景举例）

**场景1**：主线程要拿到子线程的计算结果才能继续  
**场景2**：等所有下载任务完成再合并文件  
**场景3**：等任意一个任务完成就继续（比如多个接口同时请求，谁快用谁）

**大白话**：等待就是"**我先歇会儿，你干完了叫我**"。

---

## 二、阻塞式等待（卡主线程）

### `task.Wait()` —— 死等一个任务
```csharp
Task task = Task.Run(() => Thread.Sleep(2000));
Console.WriteLine("等待任务完成...");
task.Wait(); // 主线程卡住，直到任务跑完
Console.WriteLine("任务完成了！");
```

### `Task.WaitAll()` —— 死等所有任务
```csharp
Task t1 = Task.Run(() => Thread.Sleep(2000));
Task t2 = Task.Run(() => Thread.Sleep(3000));

Console.WriteLine("等待所有任务...");
Task.WaitAll(t1, t2); // 等最慢的那个（3秒）
Console.WriteLine("都完成了！");
```

### `Task.WaitAny()` —— 死等任意一个
```csharp
Task t1 = Task.Run(() => Thread.Sleep(2000));
Task t2 = Task.Run(() => Thread.Sleep(1000));

Console.WriteLine("等最快的任务...");
int index = Task.WaitAny(t1, t2); // t2先完成，返回1
Console.WriteLine($"任务{index}先完成了！");
```

### 带超时等待（等太久就不等了）
```csharp
Task task = Task.Run(() => Thread.Sleep(5000));

// 只等2秒，超时返回false
bool finished = task.Wait(2000); 
Console.WriteLine(finished ? "完成了" : "超时了");
```

---

## 三、非阻塞等待（不卡主线程）

### `async/await` —— 最佳方式
```csharp
async void Main()
{
    Console.WriteLine("主线程：提交任务");
    Task task = Task.Run(() => Thread.Sleep(2000));
    
    Console.WriteLine("主线程：任务提交了，我干别的");
    await task; // 不卡！任务完成后自动回来继续
    
    Console.WriteLine("主线程：任务完成了，继续执行");
}
```

**特点**：
- `await` 不会卡住调用线程，线程去干别的
- 任务完成后，**自动回到原来的上下文**继续执行

### `task.ConfigureAwait(false)` —— 优化版
```csharp
await task.ConfigureAwait(false); // 告诉await不用回到原上下文，性能更好
```

---

## 四、组合等待（更灵活）

### `Task.WhenAll()` —— 等所有（返回Task，可await）
```csharp
Task t1 = Task.Run(() => Thread.Sleep(2000));
Task t2 = Task.Run(() => Thread.Sleep(3000));

await Task.WhenAll(t1, t2); // await 不卡，等所有完成
Console.WriteLine("都完成了！");
```

### `Task.WhenAny()` —— 等任意一个
```csharp
Task t1 = Task.Run(() => Thread.Sleep(2000));
Task t2 = Task.Run(() => Thread.Sleep(1000));

Task first = await Task.WhenAny(t1, t2); // 等最快的
Console.WriteLine($"任务 {first.Id} 先完成");
```

---

## 五、选择指南

| 等待方式             | 是否卡线程 | 适用场景                     | 推荐度   |
| ---------------- | ----- | ------------------------ | ----- |
| `task.Wait()`    | ✅ 卡   | 控制台程序、需要强制同步             | ⭐⭐    |
| `Task.WaitAll()` | ✅ 卡   | 等所有任务完成（阻塞）              | ⭐⭐    |
| `Task.WaitAny()` | ✅ 卡   | 等任意一个完成（阻塞）              | ⭐⭐    |
| `await task`     | ❌ 不卡  | **WIN/WPF/ASP.NET**、UI不卡 | ⭐⭐⭐⭐⭐ |
| `Task.WhenAll()` | ❌ 不卡  | 等所有任务完成（非阻塞）             | ⭐⭐⭐⭐⭐ |
| `Task.WhenAny()` | ❌ 不卡  | 等任意一个完成（非阻塞）             | ⭐⭐⭐⭐  |

---

## 六、一句话总结

- **Wait**：卡死等，适合控制台
- **await**：不卡等，适合UI程序
- **WhenAll/WhenAny**：返回Task，可继续await链

**新手记住**：**用 `await`**，别用 `Wait()`，除非写控制台。

---

## 七、新手陷阱

### 陷阱1：`Wait()` 在UI线程导致界面卡死
```csharp
// WPF按钮事件（错误）
private void Button_Click(object sender, EventArgs e)
{
    Task.Run(() => Thread.Sleep(5000)).Wait(); // 界面卡死5秒！
}

// 正确
private async void Button_Click(object sender, EventArgs e)
{
    await Task.Run(() => Thread.Sleep(5000)); // 界面不卡
}
```

### 陷阱2：`await` 不在 async 方法里
```csharp
void Main()
{
    await Task.Run(() => {}); // 编译错误：await 必须在 async 方法里
}
```

---

## 八、总结

**核心区别**：
- **Wait**：**阻塞**当前线程，线程干啥都干不了
- **await**：**释放**当前线程，线程去干别的，干完自动回来

**使用口诀**：
```csharp
// 控制台程序
task.Wait();

// UI/ASP.NET程序
await task;
```
