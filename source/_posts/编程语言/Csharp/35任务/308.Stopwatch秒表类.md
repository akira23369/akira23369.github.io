# C# Stopwatch

老王，今天咱们聊一个**测时间**的神器——`Stopwatch`。想象一下你跑步时用的秒表，按一下开始，跑完按一下停，就能知道用了多久。C#里的`Stopwatch`就是干这个的，专门用来精确测量代码执行时间。

---

## 一、是什么？—— 程序员的秒表

**大白话定义**：`Stopwatch`是.NET里专门用来**高精度计时**的类，比`DateTime`那种"看手表"的方式准100倍。

**生活中的例子**：
- 普通手表（DateTime）：看个大概时间，误差几秒很正常
- 专业秒表（Stopwatch）：精确到毫秒甚至微秒，运动员比赛都用这个

**代码定位**：
```csharp
// 它在这个命名空间里，一般项目都默认引用了
using System.Diagnostics;

// 核心作用：精确测量"一段代码"的执行耗时
```

---

## 二、为什么用它？—— 告别"土办法"

### ❌ 新手常犯的"土办法"
```csharp
// 错误示范！不要用DateTime测性能
DateTime start = DateTime.Now;
DoSomething(); // 要测试的代码
DateTime end = DateTime.Now;
double seconds = (end - start).TotalSeconds; // 误差巨大！
```

**为什么不好？**：
1. **精度太低**：`DateTime`最小单位是"Tick"（100纳秒），但系统更新频率可能只有15毫秒
2. **受系统时间影响**：如果中途有人改了电脑时间，结果就废了
3. **不专业**：就像用厨房秤称黄金，不是不能称，是不精准

### ✅ Stopwatch的优势
```csharp
// 专业做法
Stopwatch sw = new Stopwatch();
sw.Start();
DoSomething();
sw.Stop();
double ms = sw.ElapsedMilliseconds; // 精确到毫秒
```

**优点**：
1. **高精度**：用CPU内部的"高频计时器"，误差在微秒级
2. **不受系统时间干扰**：只测量流逝的时间
3. **功能丰富**：可以暂停、继续、重置
4. **零成本**：启动/停止几乎不消耗性能

## 三、怎么用？—— 四步上手

### 场景：测量"睡觉1秒"需要多久
```csharp
using System;
using System.Diagnostics; // 千万别忘了这个
using System.Threading;   // 用于Thread.Sleep

class Program
{
    static void Main()
    {
        // 第1步：创建秒表对象
        Stopwatch stopwatch = new Stopwatch();

        // 第2步：开始计时
        stopwatch.Start();
        Console.WriteLine("秒表启动...");

        // 第3步：执行你要测量的代码
        Thread.Sleep(1000); // 让程序睡1秒

        // 第4步：停止计时
        stopwatch.Stop();
        Console.WriteLine("秒表停止...");

        // 第5步：读取结果（这一步最重要）
        Console.WriteLine($"耗时：{stopwatch.ElapsedMilliseconds} 毫秒");
        Console.WriteLine($"耗时：{stopwatch.Elapsed.TotalSeconds} 秒");
        Console.WriteLine($"耗时：{stopwatch.ElapsedTicks} Ticks");
    }
}
```

**运行结果**：
```
秒表启动...
秒表停止...
耗时：1021 毫秒
耗时：1.0212849 秒
耗时：10212849 Ticks
```

## 四、核心成员全解析—— 每个API都讲透

### 构造函数（怎么生出来）

```csharp
// 方式1：new出来（最常用）
Stopwatch sw1 = new Stopwatch(); // 创建时默认是停止状态

// 方式2：静态方法创建并立即启动（一行代码搞定）
Stopwatch sw2 = Stopwatch.StartNew(); // 创建+启动，懒人福音

// 方式3：检查系统是否支持高精度计时
bool isSupported = Stopwatch.IsHighResolution; // 现在几乎所有电脑都支持
Console.WriteLine($"你的电脑支持高精度计时: {isSupported}");

// 方式4：获取每秒的Tick数（了解即可）
long frequency = Stopwatch.Frequency; // 比如10,000,000（每秒1000万Tick）
Console.WriteLine($"每秒Tick数: {frequency}");
```

**常见频率值**：
- 普通PC：`10,000,000`（每秒1000万Tick，1 Tick = 100纳秒）
- 高性能服务器：可能更高

---

### 重要属性（查看状态）

```csharp
Stopwatch sw = new Stopwatch();

// 属性1：IsRunning - 秒表是否在跑？
Console.WriteLine($"是否运行中: {sw.IsRunning}"); // False

sw.Start();
Console.WriteLine($"是否运行中: {sw.IsRunning}"); // True

sw.Stop();
Console.WriteLine($"是否运行中: {sw.IsRunning}"); // False

// 属性2：Elapsed - 最推荐！返回TimeSpan对象，啥格式都有
sw.Restart();
Thread.Sleep(1234);
sw.Stop();
TimeSpan ts = sw.Elapsed;
Console.WriteLine($"天: {ts.Days}");
Console.WriteLine($"时: {ts.Hours}");
Console.WriteLine($"分: {ts.Minutes}");
Console.WriteLine($"秒: {ts.Seconds}");
Console.WriteLine($"毫秒: {ts.Milliseconds}");
Console.WriteLine($"总秒数: {ts.TotalSeconds:F4}"); // 带小数点的总秒数

// 属性3：ElapsedMilliseconds - 最常用的懒人属性
long ms = sw.ElapsedMilliseconds; // 直接拿毫秒（长整型）

// 属性4：ElapsedTicks - 最容易踩坑的属性！
long ticks = sw.ElapsedTicks; // 这是Stopwatch的Tick，不是TimeSpan的Tick！
```

 **⚠️ 常见陷阱警告**  ：
 `ElapsedTicks` 和 `TimeSpan.Ticks` 是两回事！
 ```csharp
 // 错误示范：
 TimeSpan wrong = TimeSpan.FromTicks(sw.ElapsedTicks); // 别这么干！
 
 // 正确做法：
 TimeSpan correct = sw.Elapsed; // 直接用Elapsed属性
 ```

---

### 核心方法（操控秒表）

```csharp
Stopwatch sw = new Stopwatch();

// 方法1：Start() - 开始或继续计时
sw.Start(); // 第一次启动
// ... 测一段代码 ...
sw.Stop();

sw.Start(); // 再次Start，会从前面的时间继续累加！
// ... 再测一段代码 ...
sw.Stop();
Console.WriteLine($"总耗时: {sw.ElapsedMilliseconds} ms"); // 是两段代码的总和

// 方法2：Stop() - 暂停计时
sw.Stop(); // 暂停，但不归零

// 方法3：Reset() - 归零（停止+清零）
sw.Reset(); // 秒表回到初始状态（停止，时间归零）
Console.WriteLine($"重置后毫秒数: {sw.ElapsedMilliseconds}"); // 0

// 方法4：Restart() - 归零并立即开始（比Reset+Start快）
sw.Restart(); // 相当于 sw.Reset(); sw.Start(); 但更快！
Console.WriteLine($"重启后是否运行: {sw.IsRunning}"); // True

// 方法5：StartNew() - 静态方法，创建+启动
Stopwatch newSw = Stopwatch.StartNew(); // 等价于 new Stopwatch() + Start()
// 这方法在.NET 4.5+才有，特别常用！
```

**性能小提示**：`Restart()`比先`Reset()`再`Start()`快一点点，因为少一次方法调用。

## 五、实战例子

### 场景1：测量一个方法执行时间（最常用）

```csharp
public void 测试订单生成性能()
{
    // 最佳实践：使用StartNew，代码最少
    Stopwatch sw = Stopwatch.StartNew();
    
    // 被测试的代码

    {
        生成订单($"订单号{i}");
    }
    
    sw.Stop();
    
    // 格式化输出
    Console.WriteLine($"生成10000个订单耗时: {sw.ElapsedMilliseconds} ms");
    Console.WriteLine($"平均每个订单: {sw.ElapsedMilliseconds / 10000.0:F4} ms");
}

private void 生成订单(string id)
{
    // 模拟一些工作
    Thread.Sleep(1); // 模拟耗时1毫秒
}
```

### 场景2：测量循环的每次迭代（高级技巧）

```csharp
public void 测试每次循环耗时()
{
    Stopwatch sw = new Stopwatch();
    int[] 数据 = new int[1000];
    
    for (int i = 0; i < 数据.Length; i++)
    {
        sw.Restart(); // 每次循环都重置
        
        // 执行工作
        数据[i] = i * i;
        
        sw.Stop();
        
        // 如果某次特别慢，就警告
        if (sw.ElapsedMilliseconds > 10)
        {
            Console.WriteLine($"警告: 第{i}次循环耗时{sw.ElapsedMilliseconds}ms");
        }
    }
}
```

### 场景4：生产环境的最佳实践（带异常安全）

```csharp
public long 安全地测量(Action 要测量的代码)
{
    Stopwatch sw = Stopwatch.StartNew();
    
    try
    {
        要测量的代码(); // 执行传入的方法
    }
    catch (Exception ex)
    {
        // 即使出错了，也要记录时间
        sw.Stop();
        Console.WriteLine($"代码执行失败，但耗时: {sw.ElapsedMilliseconds}ms");
        Console.WriteLine($"错误: {ex.Message}");
        throw; // 继续抛出异常
    }
    
    sw.Stop();
    return sw.ElapsedMilliseconds;
}

// 使用方式：
public void 生产环境调用示例()
{
    long 耗时 = 安全地测量(() => {
        // 你的业务代码
        处理大额转账("账户A", "账户B", 1000000);
    });
    
    Console.WriteLine($"转账耗时: {耗时}ms");
}
```

## 六、常见陷阱—— 新手必看

### 陷阱1：Stopwatch不是线程安全的

```csharp
// ❌ 错误：多线程共享一个Stopwatch会乱套
Stopwatch sharedSw = new Stopwatch();
Parallel.For(0, 100, i => {
    sharedSw.Start(); // 多个线程同时调用，结果不可预测
    // ...
    sharedSw.Stop();
});

// ✅ 正确：每个线程用自己的Stopwatch
Parallel.For(0, 100, i => {
    Stopwatch localSw = Stopwatch.StartNew();
    // ...
    localSw.Stop();
    Console.WriteLine($"线程{i}耗时: {localSw.ElapsedMilliseconds}ms");
});
```

**原因**：`Start()`和`Stop()`内部会修改状态，多线程同时改会打架。

---

### 陷阱2：多次Start会累加时间

```csharp
Stopwatch sw = new Stopwatch();
sw.Start();
Thread.Sleep(500);
sw.Stop();

Console.WriteLine(sw.ElapsedMilliseconds); // 约500

sw.Start(); // 继续计时，不是重新开始！
Thread.Sleep(300);
sw.Stop();

Console.WriteLine(sw.ElapsedMilliseconds); // 约800，不是300！
```

**解决方案**：想重新开始用`Restart()`，而不是再次`Start()`。

---

### 陷阱3：忘记Stop就读取时间

```csharp
Stopwatch sw = Stopwatch.StartNew();
Thread.Sleep(1000);
// 忘记写 sw.Stop();

// 此时读取的时间还在增加！
Console.WriteLine(sw.ElapsedMilliseconds); // 可能是1001、1002、1003...
Thread.Sleep(100);
Console.WriteLine(sw.ElapsedMilliseconds); // 又变了！
```

**建议**：养成习惯，测量完立即`Stop()`。

---

### 陷阱4：在循环里频繁创建Stopwatch

```csharp
// ❌ 性能较差：每次循环都new
for (int i = 0; i < 100000; i++)
{
    Stopwatch sw = Stopwatch.StartNew();
    // 测一点点代码
    sw.Stop();
}

// ✅ 性能好：复用一个Stopwatch
Stopwatch sw = new Stopwatch();
for (int i = 0; i < 100000; i++)
{
    sw.Restart(); // 重置并启动
    // 测一点点代码
    sw.Stop();
}
```

**原理**：`new Stopwatch()`虽然开销小，但循环次数多了也有影响。`Restart()`几乎零成本。

## 七、底层原理浅析—— 高级知识

### Stopwatch vs DateTime 的本质区别

| 特性 | Stopwatch | DateTime.Now |
|------|-----------|--------------|
| **计时方式** | CPU高频计时器（QueryPerformanceCounter） | 系统时钟 |
| **精度** | 微秒级（0.000001秒） | 毫秒级（0.01-0.1秒） |
| **是否受系统时间修改影响** | ❌ 完全不受 | ✅ 会受影响 |
| **开销** | 极低（几纳秒） | 较高（涉及系统调用） |

**大白话解释**：
- `DateTime.Now`就像问墙上的挂钟"现在几点了"，问两次做减法。如果中途有人把钟拨快了，结果就错了。
- `Stopwatch`就像按下一个独立计时器，它自己内部数数，不管外面几点，只数自己经历了多少"滴答"。

### 硬件支持
现代CPU都有**高精度事件计时器（HPET）** 或**时间戳计数器（TSC）**，`Stopwatch`就是直接读取这些硬件计数器，所以超级快、超级准。

## 八、总结与最佳实践

### 黄金法则
1. **简单测量**：用`Stopwatch.StartNew()`，一行代码搞定
2. **反复测量**：用一个实例+`Restart()`，别频繁new
3. **读取结果**：优先用`Elapsed.TotalSeconds`或`ElapsedMilliseconds`
4. **多线程**：每个线程一个Stopwatch，别共享
5. **生产环境**：测量前后加try-finally，确保一定Stop

### 万能模板（收藏这个就够了）

```csharp
// 模板1：快速测量一个方法
public static long 测量(Action 方法)
{
    var sw = Stopwatch.StartNew();
    方法();
    sw.Stop();
    return sw.ElapsedMilliseconds;
}

// 模板2：测量并自动打印
public static void 测量并打印(string 名称, Action 方法)
{
    var sw = Stopwatch.StartNew();
    方法();
    sw.Stop();
    Console.WriteLine($"[{名称}] 耗时: {sw.ElapsedMilliseconds}ms | {sw.Elapsed.TotalSeconds:F3}s");
}

// 使用：
测量并打印("数据库查询", () => {
    // 你的代码
});
```

## 九、面试加分题

**面试官可能会问**：`Stopwatch`的`IsHighResolution`是什么？什么时候会是false？

**标准答案**：
> 这个属性表示是否使用系统的高性能计数器。在1995年之后的几乎所有PC和服务器上都是true。唯一可能false的情况是：
> 1. 非常老的Windows 95/98系统
> 2. 某些虚拟机或容器环境（但现代云主机都支持）
> 3. 嵌入式系统或特殊硬件平台

所以**实际开发中基本可以忽略**，默认当它是true就行。
