# 原始线程的缺点

## 一、先回顾一下我们怎么手动用 Thread

前面我们学了用 `new Thread()` 创建线程：
```csharp
for (int i = 0; i < 10; i++)
{
    new Thread(() => {
        Console.WriteLine("干活");
    }).Start();
}
```

看起来简单是吧？但等你写复杂程序时，就会发现这玩意儿到处是坑。就像你开饭馆，每来一个客人就招一个新服务员，客人吃完就开除服务员——听起来就不靠谱。

---

## 二、缺点1：创建和销毁太费钱（资源开销大）

**大白话**：线程不是"免费"的。每个线程要占 1MB 内存（栈空间），还要向操作系统注册身份。频繁创建销毁就像每送一次外卖就招一个外卖员，招人的成本比送外卖还贵。

**代码感受一下**：
```csharp
// 短时间内创建1000个线程
for (int i = 0; i < 1000; i++)
{
    new Thread(() => Thread.Sleep(1000)).Start();
}
// 后果：内存飙升到 1GB+，程序卡死，可能直接崩溃
```

**实际痛点**：
- 创建线程要 1-2 毫秒，销毁要 0.5 毫秒
- 开太多线程，CPU 都花在线程切换上，不干正事
- 默认一个进程最多开几千个线程就崩了

---

## 三、缺点2：生娃不管娃（管理复杂）

**大白话**：`new Thread()` 就像生完娃就不管了。线程什么时候跑完、跑完怎么通知你、跑崩了怎么办，全部得你自己操心。

**代码噩梦**：
```csharp
// 问题1：怎么知道所有线程都跑完了？
void DoWork()
{
    for (int i = 0; i < 10; i++)
    {
        new Thread(() => {
            // 干活
        }).Start(); // 线程跑哪去了？啥时候跑完？不知道！
    }
    // 这里怎么等？难道写10个 Join？太蠢了
}
```

**实际要操的心**：
- 线程跑完了怎么通知主线程？（手动写回调）
- 线程跑崩了怎么办？（默认直接崩整个程序）
- 线程太多怎么限流？（自己写信号量）
- 线程顺序怎么控制？（手动写同步逻辑）

---

## 四、缺点3：同步噩梦（死锁、竞态条件）

**大白话**：多个线程抢共享资源，就像俩小孩抢玩具，抢不好就打起来（死锁），或者抢出内伤（竞态条件）。

### 竞态条件
```csharp
static int _counter = 0;

// 10个线程各+1000
Parallel.For(0, 10, i => {
    for (int j = 0; j < 1000; j++)
    {
        _counter++; // 看似一行，实际分3步：读-改-写
        // 两个线程可能同时读、同时改，结果覆盖，最后
        // _counter 不是 10000，而是 8000、9000 等随机数
    }
});
```

**结果**：每次运行结果都不一样，bug 随机出现，根本查不出来。

### 死锁
```csharp
static object lockA = new object();
static object lockB = new object();

// 线程1：先锁A，再锁B
new Thread(() => {
    lock (lockA) {
        Thread.Sleep(100);
        lock (lockB) { /* ... */ }
    }
}).Start();

// 线程2：先锁B，再锁A
new Thread(() => {
    lock (lockB) {
        Thread.Sleep(100);
        lock (lockA) { /* ... */ }
    }
}).Start();
// 结果：线程1等B，线程2等A，永远互相等下去
```

**特征**：程序卡死，CPU 空转，重启才能解决。

---

## 五、缺点4：调试等于抓鬼（随机性 bug）

**大白话**：多线程 bug 最可怕的地方：**无法复现**。你本地调试 10 次都正常，一到生产环境就崩。因为线程调度是随机的，每次运行顺序都不一样。

**真实场景**：
```csharp
// 这段代码 90% 的时间正常运行，10% 崩溃
if (_list.Count > 0) // ① 判断有元素
{
    // ② 另一个线程在这行删了元素
    var item = _list[0]; // ③ boom！IndexOutOfRangeException
}
```

**调试噩梦**：
- 断点一设，线程跑不起来，bug 不出现了
- log 打不出来，因为 log 本身就打乱了时序
- 工具（VS 调试器）看到的状态，不一定是真实状态

---

## 六、缺点5：不能取消（一旦启动，失控）

**大白话**：`new Thread()` 启动后，你无法中途叫停。线程里写个死循环，你只能眼睁睁看着它占CPU。

```csharp
Thread t = new Thread(() => {
    while (true) { /* 死循环 */ }
});
t.Start();

// 现在你想停？没办法！
// t.Abort()? 已废弃，不推荐
// t.Interrupt()? 不一定有用
// 你只能杀进程
```

**实际后果**：
- 用户点"取消"按钮，后台线程还在跑，界面卡死
- 程序退出，线程还在后台跑，进程杀不掉
- 线程泄露，越跑越多，内存爆炸

---

## 七、缺点6：无法返回值（异步结果拿不到）

**大白话**：线程就像一个"无返回值的函数"。你想让线程算个数返回给你？没门！只能手动写回调或者用共享变量。

**丑陋代码**：
```csharp
static int result; // 全局变量

void Calculate()
{
    new Thread(() => {
        result = 42; // 算完写全局
    }).Start();
    
    Thread.Sleep(1000); // 怎么知道算完了？只能瞎等！
    Console.WriteLine(result);
}
```

**问题**：
- 等多久？不知道，睡1秒可能线程还没跑完
- 睡太久，程序变慢
- 用 `Join` 等？那主线程也卡死，失去意义

---

## 八、总结：原始线程 = 手动挡汽车

**用一个比喻总结所有缺点**：

用 `new Thread()` 写多线程程序，就像开**手动挡汽车**：
- 离合、挂挡、油门全手动，操作稍有不慎就熄火（管理复杂）
- 换挡慢了，车就抖（性能差）
- 坡道起步，可能溜车滑坡（死锁）
- 半路故障，只能跳车（无法取消）
- 没有导航，全靠猜（调试困难）
- 拉不了货（无法返回值）
