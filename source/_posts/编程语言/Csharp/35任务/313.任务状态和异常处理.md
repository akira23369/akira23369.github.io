# 任务状态和异常处理

TPL 相较于传统线程处理的一个重大改进是其结构化的异常处理方式。当任务内部发生未处理异常时，它不会立即导致应用程序崩溃（除非异常发生在主线程且未被捕获）。相反，异常会被"捕获"并与任务本身关联。




## 一、任务有哪些状态？

Task 从创建到完成，会经历几个状态。你可以随时查看 `task.Status` 属性，就像查快递物流。

**状态列表**

| 状态 | 含义 | 类比 |
|------|------|------|
| **`WaitingToRun`** | 任务在队列里排队，还没轮到 | 快递已下单，等待揽收 |
| **`Running`** | 正在执行 | 快递运输中 |
| **`RanToCompleted`** | **成功完成** | 快递已签收 |
| **`Faulted`** | **失败**（抛异常了） | 快递丢了/坏了 |
| **`Canceled`** | **被取消** | 用户主动退货 |

**代码演示**：
```csharp
Task task = Task.Run(() => Thread.Sleep(1000));
Console.WriteLine(task.Status); // Running 或 WaitingToRun

task.Wait();
Console.WriteLine(task.Status); // RanToCompleted
```

## 二、如何判断状态？（3个方便的布尔属性）

不用记住所有状态值，Task 提供了三个 `bool` 属性，直接判断。

### `IsCompleted` —— 任务是否结束（不管成功/失败/取消）
```csharp
Task task = Task.Run(() => Thread.Sleep(1000));

if (task.IsCompleted)
{
    Console.WriteLine("任务结束了（可能成功、失败或取消）");
}
```

### `IsCompletedSuccessfully` —— 是否**成功**完成
```csharp
Task task = Task.Run(() => { /* 干活 */ });

task.Wait();

if (task.IsCompletedSuccessfully)
{
    Console.WriteLine("任务圆满完成！");
}
else
{
    Console.WriteLine("任务没成功（失败或被取消）");
}
```

### `IsFaulted` —— 是否**失败抛异常**
```csharp
Task task = Task.Run(() => {
    throw new Exception("出错了");
});

try
{
    task.Wait();
}
catch
{
    // 忽略 Wait 的异常
}

if (task.IsFaulted)
{
    Console.WriteLine($"任务失败了: {task.Exception.Message}");
}
```

### `IsCanceled` —— 是否**被取消**
```csharp
CancellationTokenSource cts = new CancellationTokenSource();
Task task = Task.Run(() => {
    while (true) { } // 死循环
}, cts.Token);

cts.Cancel(); // 取消任务

try
{
    task.Wait();
}
catch
{
    // 忽略
}

if (task.IsCanceled)
{
    Console.WriteLine("任务被取消了");
}
```

## 三、异常处理（重点）

**任务异常处理机制：**

1. 异常捕获：当任务抛出未处理的异常时，任务状态会变为 Faulted。
2. AggregateException：单个任务中抛出的所有异常（如果存在多个异常）或通过 Task.WhenAll 等待的多个任务抛出的异常，都会被封装在 System.AggregateException 中。这种异常类型专门设计用于包含一个或多个内部异常。
3. 异常观察机制：只有当调用代码"观察到"任务的结果或完成状态时，异常才会被重新抛出。观察可以通过以下几种方式实现：
    - 访问 Task.Result 属性（针对 `Task<TResult>`类型）。
    - 调用 Task.Wait()、Task.WaitAll()或 Task.WaitAny()方法。
    - 等待任务（首选且非阻塞方式）。
    - 访问 Task.Exception 属性。

**Task.Exception 属性：**

- 该属性返回一个包含任务抛出的所有未处理异常的 AggregateException。
- 如果任务成功完成（RanToCompletion）或被取消（Canceled），则该属性为 null。
- 重要提示：必须"观察"异常。如果出错任务的 Exception 属性从未被访问，且该任务从未被等待或阻塞等待，那么 AggregateException 最终会被视为"未观察"。在.NET Framework 中，默认情况下这将终止进程。而在.NET Core 和.NET 5+中，默认情况下未观察的任务异常不再导致进程崩溃，仅会被记录。但最佳实践仍然是始终观察任务异常。


### Task 异常的包裹机制（AggregateException）

**关键规则**：Task 里抛的异常，不会立即崩程序，而是**被包裹**在 `AggregateException` 里。

**代码演示**：
```csharp
Task task = Task.Run(() => {
    throw new Exception("任务内部出错了");
});

// 主线程继续跑，不会崩
Console.WriteLine("任务已提交");

task.Wait(); // 当你 Wait 时，异常才会抛出来

// Wait() 或 Result 会抛出 AggregateException
// 而不是原始的 Exception
```

### 如何捕获 Task 异常

#### 方式1：`Wait()` 捕获
```csharp
Task task = Task.Run(() => {
    throw new Exception("boom");
});

try
{
    task.Wait(); // 这里会抛 AggregateException
}
catch (AggregateException ae)
{
    // 拿到原始异常
    Console.WriteLine($"任务失败: {ae.InnerException.Message}");
}
```

#### 方式2：`task.Result` 捕获
```csharp
Task<int> task = Task.Run<int>(() => {
    throw new Exception("计算失败");
    return 42;
});

try
{
    int result = task.Result; // 这里也会抛 AggregateException
}
catch (AggregateException ae)
{
    Console.WriteLine($"异常: {ae.InnerException.Message}");
}
```

#### 方式3：`await` 捕获（自动解包）
```csharp
Task task = Task.Run(() => {
    throw new Exception("boom");
});

try
{
    await task; // await 会自动解包 AggregateException
}
catch (Exception ex) // 直接捕获原始异常
{
    Console.WriteLine($"异常: {ex.Message}");
}
```

**重要区别**：
- `Wait()` / `Result`：抛出 `AggregateException`，需要 `.InnerException` 拿原始异常
- `await`：自动解包，直接捕获原始异常，更简洁

## 四、延续任务中的异常处理（异常会传递）

**规则**：如果任务 A 失败，延续任务 B 默认还是会执行，但 B 的 `Result` 会抛出异常。

```csharp
Task<int> taskA = Task.Run<int>(() => {
    throw new Exception("A失败");
    return 42;
});

// 延续任务B想拿A的结果
Task<int> taskB = taskA.ContinueWith(antecedent => {
    Console.WriteLine("B会执行吗？"); // 会执行！
    return antecedent.Result * 2; // 这里会抛异常
});

try
{
    Console.WriteLine(taskB.Result);
}
catch (AggregateException ae)
{
    Console.WriteLine($"B也失败了: {ae.InnerException.Message}");
}
```

**输出**：
```
B会执行吗？
B也失败了: One or more errors occurred. (A失败)
```
**详细解析**
**Task A：异常的源头**
当 `taskA` 执行时，它直接抛出了一个普通的 `Exception`。
- TPL 会捕获这个异常，并将其包装在一个 `AggregateException` 中，存放在 `taskA.Exception` 属性里。
- 此时 `taskA` 的状态变为 `Faulted`。

**Task B：异常的传播**
`taskB` 使用了 `ContinueWith`，在默认情况下，**无论父任务（antecedent）成功还是失败，延续任务都会执行**。
1. **B 执行了**：控制台会打印出 “B会执行吗？”。
2. **触发异常**：当代码运行到 `antecedent.Result` 时，.NET 内部会检查 `taskA` 的状态。由于 `taskA` 是 `Faulted`，调用 `.Result` 会**重新抛出** `taskA` 持有的异常。
3. **双重包装**：
    - `taskA.Result` 抛出的是一个 `AggregateException`（包含“A失败”）。
    - 由于这个异常发生在 `taskB` 的执行体内，TPL 再次捕获它，并将其包装在 `taskB` 自己的 `AggregateException` 中。

> **结果：** 如果你查看 `taskB.Exception`，你会发现它的 `InnerException` 是一个 `AggregateException`，而那个 `AggregateException` 里面才包裹着真正的 `Exception("A失败")`。这就是所谓的**嵌套异常**。



**为什么这很重要？**
在实际开发中，如果不注意这种区别，会导致**异常处理失效**：
- **糟糕的处理方式**： 如果你在 `catch` 块中只检查 `ae.InnerException is Exception`，对于 `taskB` 可能会失败，因为它的 `InnerException` 实际上又是另一个 `AggregateException`。
- **正确的处理方式**： 使用 `ae.Flatten()` 方法。它会将所有嵌套的 `AggregateException` “拍平”成一个单一的集合。


**如何让 B 不在这种情况下执行？**
如果你希望只有在 A 成功时才运行 B，你应该使用 `TaskContinuationOptions`：

## 五、让延续只处理异常（OnlyOnFaulted）

```csharp
static void Main()
{
	Task<int> taskA = Task.Run<int>(() => {
		throw new Exception("A失败");
		return 42;
	});

	// 只有A失败时才执行的延续（错误处理链）
	Task taskErrorHandler = taskA.ContinueWith(antecedent => {
		Console.WriteLine($"处理A的错误: {antecedent.Exception.InnerException.Message}");
	}, TaskContinuationOptions.OnlyOnFaulted);

	// 只有A成功时才执行的延续
	Task taskSuccessHandler = taskA.ContinueWith(antecedent => {
		Console.WriteLine($"A成功了: {antecedent.Result}");
	}, TaskContinuationOptions.OnlyOnRanToCompletion);

	Thread.Sleep(1000); // 等待任务完成
}
```

**输出**：
```
处理A的错误: A失败
```

**注意**：只有符合条件的延续才会执行，另一个会被跳过。

## 六、总结

### 状态判断口诀
```csharp
if (task.IsCompletedSuccessfully) { /* 成功 */ }
else if (task.IsFaulted) { /* 失败 */ }
else if (task.IsCanceled) { /* 取消 */ }
```

### 异常处理口诀
```csharp
try
{
    await task; // 推荐，自动解包
}
catch (Exception ex) { /* 处理原始异常 */ }
```

或

```csharp
try
{
    task.Wait(); // 阻塞等待
}
catch (AggregateException ae) 
{ 
    /* 处理 ae.InnerException */ 
}
```
