# 延续任务

## 一、为什么需要延续任务？（场景引入）

**场景**：下载文件完成后，自动解压；解压完成后，自动删除原文件。用原始线程怎么写？

```csharp
// 丑陋的回调地狱
new Thread(() => {
    DownloadFile();
    new Thread(() => {
        Unzip();
        new Thread(() => {
            DeleteZip();
        }).Start();
    }).Start();
}).Start();
```

**延续任务**：把"做完A自动做B"的逻辑，优雅地串起来。

**大白话**：延续任务就是"**任务流水线**"。任务A干完，自动把结果传给任务B继续干，像工厂流水线一样。

---

## 二、ContinueWith()——基本用法

非阻塞性：与 Wait()或 Result 不同，ContinueWith 不会阻塞当前线程。


### 最简单的延续
```csharp
Task taskA = Task.Run(() => {
    Console.WriteLine("任务A：下载文件");
    Thread.Sleep(1000);
});

// 等任务A完成，自动执行任务B
Task taskB = taskA.ContinueWith(_ => {
    Console.WriteLine("任务B：解压文件");
    Thread.Sleep(1000);
});

Console.WriteLine("主线程：任务已安排，A→B自动执行");
taskB.Wait(); // 实际等待的是B（B等A，主线程等B）
```

**输出**：
```
主线程：任务已安排，A→B自动执行
任务A：下载文件
任务B：解压文件
```

**关键点**：
- `ContinueWith()` 返回**新任务B**，B的执行依赖于A
- B会在**线程池的某个线程**上执行（不一定是A的线程）
- `taskB.Wait()` 实际等待的是整个链完成（A+B）

---

### 延续任务中获取前一个任务的结果

```csharp
Task<int> taskA = Task.Run(() => {
    Console.WriteLine("任务A：计算结果");
    return 42;
});

// 在延续中拿到结果
Task taskB = taskA.ContinueWith(antecedent => {
    // antecedent 就是前一个任务A
    int result = antecedent.Result; // 拿到A的结果
    Console.WriteLine($"任务B：拿到结果 {result}，开始处理");
});

taskB.Wait();
```

**输出**：
```
任务A：计算结果
任务B：拿到结果 42，开始处理
```

---

### 延续的延续（链式调用）

```csharp
Task.Run(() => {
    Console.WriteLine("第1步：下载");
}).ContinueWith(_ => {
    Console.WriteLine("第2步：解压");
}).ContinueWith(_ => {
    Console.WriteLine("第3步：删除原文件");
}).Wait(); // 等整个链完成
```

## 三、TaskContinuationOptions——控制延续时机

**场景**：任务A失败了，你还要解压吗？肯定不要。可以用选项控制"什么情况下才延续"。

### 常用选项
```csharp
Task taskA = Task.Run(() => {
    Console.WriteLine("任务A：下载文件");
    throw new Exception("下载失败"); // 模拟失败
});

// 只有任务A成功完成才执行B
Task taskB = taskA.ContinueWith(antecedent => {
    Console.WriteLine("任务B：解压文件"); // 不会执行！
}, TaskContinuationOptions.OnlyOnRanToCompletion);
```

**选项列表**：
- `None`：默认，A完成（无论成功失败）就执行B
- `OnlyOnRanToCompletion`：只有A**成功**才执行B
- `OnlyOnFaulted`：只有A**失败抛异常**才执行B（用于错误处理）
- `OnlyOnCanceled`：只有A**被取消**才执行B
- `ExecuteSynchronously`：B**在同一个线程**执行（性能优化，少用）

**完整示例**：
```csharp
Task<int> taskA = Task.Run(() => {
    // return 42; // 测试成功
    throw new Exception("下载失败"); // 测试失败
});

// 成功延续
taskA.ContinueWith(antecedent => {
    Console.WriteLine($"成功延续：结果={antecedent.Result}");
}, TaskContinuationOptions.OnlyOnRanToCompletion);

// 失败延续（必须设置 OnlyOnFaulted）
taskA.ContinueWith(antecedent => {
    Console.WriteLine($"失败延续：异常={antecedent.Exception.InnerException.Message}");
}, TaskContinuationOptions.OnlyOnFaulted);

taskA.Wait();
```

## 四、多个任务的延续组合

### `Task.WhenAll()`——所有任务完成再延续

```csharp
static void Main()
{
	Task<int> task1 = Task.Run(() => { Thread.Sleep(1000); return 1; });
	Task<int> task2 = Task.Run(() => { Thread.Sleep(1500); return 2; });
	// 等 task1 和 task2 都完成
	Task<int[]> allTask = Task.WhenAll(task1, task2);

	// 延续：所有任务完成后自动执行
	Task sumTask = allTask.ContinueWith(_ =>  { 
		int sum = task1.Result + task2.Result;
		int sum2 = allTask.Result[0] + allTask.Result[1];
		Console.WriteLine($"task1 + task2 = {sum}");
		Console.WriteLine($"allTask.Result[0] + allTask.Result[1] = {sum2}");
	});

	sumTask.Wait(); // 等待 sumTask 完成
}
```

### `Task.WhenAny()`——任意任务完成就延续
```csharp
Task<int> task1 = Task.Run(() => { Thread.Sleep(2000); return 1; });
Task<int> task2 = Task.Run(() => { Thread.Sleep(1000); return 2; });

Task<Task<int>> anyTask = Task.WhenAny(task1, task2);

Task winnerTask = anyTask.ContinueWith(_ => {
    Task<int> first = anyTask.Result; // 拿到先完成的任务
    Console.WriteLine($"任务 {first.Id} 先完成，结果: {first.Result}");
});

winnerTask.Wait();
```

## 五、延续任务中的异常处理（上篇）

**延续任务里抛的异常，会传给下一个延续**

```csharp
Task<int> taskA = Task.Run(() => {
    return 42;
});

Task<int> taskB = taskA.ContinueWith(antecedent => {
    Console.WriteLine($"拿到 {antecedent.Result}");
    throw new Exception("B处理失败"); // B失败
});

Task taskC = taskB.ContinueWith(antecedent => {
    // 只有B失败才执行
    Console.WriteLine($"B失败了: {antecedent.Exception.Message}");
}, TaskContinuationOptions.OnlyOnFaulted);

taskC.Wait();
```

**注意**：延续链中任何一个任务失败，后续 `OnlyOnRanToCompletion` 的延续不会执行，但 `OnlyOnFaulted` 的会执行。

## 六、与 await 的关系（预告）

**`await` 是 `ContinueWith()` 的语法糖**

```csharp
// 这两行等价
await Task.Run(() => Download());
// 等价于
Task.Run(() => Download()).ContinueWith(_ => { /* 后续代码 */ });
```

**区别**：
- `ContinueWith()`：代码啰嗦，但灵活，可以精确控制选项
- `await`：代码简洁，是编译器自动帮你写 ContinueWith

**下下篇会专门讲 await**，现在先学会手动写延续，再学语法糖就理解了。

## 七、总结

**延续任务的核心**：
- **自动串行**：A 完成 → 自动执行 B
- **结果传递**：B 可以拿到 A 的结果
- **条件执行**：可以控制 A 在什么状态下才触发 B

**典型模式**：
```csharp
Task.Run(第一步)
    .ContinueWith(第二步) // 第一步成功才执行
    .ContinueWith(第三步); // 第二步成功才执行
```

**适用于**：
- 任务有明确先后顺序
- 需要根据前一步结果做不同处理
- 错误处理链

**不适用于**：
- 并行任务（用 WhenAll/WhenAny）
- 简单异步（用 await 更简洁）
