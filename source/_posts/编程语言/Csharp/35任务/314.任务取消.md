# 任务取消

## 一、为什么需要任务取消？（场景引入）

**场景**：用户点"下载"按钮，下到一半想取消，怎么办？
- Thread 时代：无法取消，只能 abort，危险且已废弃
- Task 时代：优雅取消，任务自己检查标志，安全退出

**大白话**：`CancellationToken` 就是一个"**停止信号灯**"，任务跑着跑着看到红灯，就主动停下来。

---

## 二、取消的核心组件（两个类）

### `CancellationTokenSource` —— **信号灯控制器**
```csharp
// 创建控制器
CancellationTokenSource cts = new CancellationTokenSource();

// 3秒后自动亮红灯（取消）
cts.CancelAfter(TimeSpan.FromSeconds(3));

// 手动亮红灯
cts.Cancel(); // 调用后，所有关联的令牌都会触发取消
```

### `CancellationToken` —— **信号灯本身**
```csharp
// 从控制器获取令牌
CancellationToken token = cts.Token;

// 检查是否亮了红灯
if (token.IsCancellationRequested) // true 表示该取消了
{
    // 停止工作，退出
}
```

**关系**：一个 `CancellationTokenSource` 可以生成多个 `CancellationToken`，所有令牌共享同一个"红灯"状态。

---

## 三、创建可取消的任务

### 方式1：Task.Run() 传递令牌
```csharp
CancellationTokenSource cts = new CancellationTokenSource();

Task task = Task.Run(() => {
    for (int i = 0; i < 10; i++)
    {
        // 检查是否亮红灯
        if (cts.Token.IsCancellationRequested)
        {
            Console.WriteLine("收到取消信号，停止下载");
            return; // 安全退出
        }
        
        Console.WriteLine($"下载进度: {(i + 1) * 10}%");
        Thread.Sleep(500);
    }
}, cts.Token); // 把令牌传给 Task

// 主线程：2秒后取消
Thread.Sleep(2000);
Console.WriteLine("用户点击取消按钮！");
cts.Cancel(); // 亮红灯

task.Wait(); // 等待任务退出
Console.WriteLine("任务已取消");
```

**输出**：
```
下载进度: 10%
下载进度: 20%
下载进度: 30%
下载进度: 40%
用户点击取消按钮！
收到取消信号，停止下载
任务已取消
```

---

### 方式2：抛出异常取消（更标准）

```csharp
CancellationTokenSource cts = new CancellationTokenSource();

Task task = Task.Run(() => {
	for (int i = 0; i < 10; i++)
	{
		// 主动检查，如果被取消就抛异常
		cts.Token.ThrowIfCancellationRequested();

		Console.WriteLine($"下载进度: {(i + 1) * 10}%");
		Thread.Sleep(500);
	}

}, cts.Token);

// 取消后，任务会抛 OperationCanceledException
Task.Delay(2000).Wait();
cts.Cancel();

try
{
	task.Wait();
}
catch (AggregateException ae)
{
	// 异常类型是 OperationCanceledException
	if (ae.InnerException is OperationCanceledException)
	{
		Console.WriteLine("任务被优雅地取消了");
	}
}
```

**特点**：
- `ThrowIfCancellationRequested()`：如果被取消，自动抛异常
- 这是一种**标准取消模式**，调用方可以明确知道是取消了

## 四、取消后的任务状态

```csharp
CancellationTokenSource cts = new CancellationTokenSource();
Task task = Task.Run(() =>
{
	cts.Token.ThrowIfCancellationRequested();
}, cts.Token);

cts.Cancel();
try
{
	task.Wait();
}
catch (AggregateException ex)
{
	// 判断状态
	Console.WriteLine($"IsCanceled: {task.IsCanceled}");      // True
	Console.WriteLine($"IsFaulted: {task.IsFaulted}");        // False
	Console.WriteLine($"IsCompleted: {task.IsCompleted}");    // True
}
```

**关键**：取消的任务 `IsCanceled = true`，不是 `IsFaulted`。取消不算失败，是**用户主动行为**。

## 五、取消的超时设置

### CancelAfter() —— 自动取消
```csharp
// 5秒后自动亮红灯
CancellationTokenSource cts = new CancellationTokenSource();
cts.CancelAfter(TimeSpan.FromSeconds(5));

Task task = Task.Run(() => {
    while (true)
    {
        cts.Token.ThrowIfCancellationRequested();
        Console.WriteLine("工作中...");
        Thread.Sleep(1000);
    }
}, cts.Token);

try
{
    task.Wait();
}
catch (AggregateException)
{
    Console.WriteLine("5秒超时，任务自动取消");
}
```

### 带超时的 Wait
```csharp
CancellationTokenSource cts = new CancellationTokenSource();

Task task = Task.Run(() => {
    Thread.Sleep(10000); // 任务要10秒
}, cts.Token);

// 主线程只等2秒，再取消
bool finished = task.Wait(2000);
if (!finished)
{
    cts.Cancel(); // 2秒后取消
    Console.WriteLine("任务执行太慢，手动取消");
}
```

## 六、多个任务共享同一个取消信号

```csharp
CancellationTokenSource cts = new CancellationTokenSource();

// 3个任务共享同一个令牌
Task t1 = Task.Run(() => Work(1, cts.Token), cts.Token);
Task t2 = Task.Run(() => Work(2, cts.Token), cts.Token);
Task t3 = Task.Run(() => Work(3, cts.Token), cts.Token);

Thread.Sleep(3000);
Console.WriteLine("主线程：全部取消！");
cts.Cancel(); // 一个 Cancel，全部任务收到信号

Task.WaitAll(t1, t2, t3);
Console.WriteLine("所有任务已取消");

static void Work(int id, CancellationToken token)
{
    try
    {
        for (int i = 0; i < 100; i++)
        {
            token.ThrowIfCancellationRequested();
            Console.WriteLine($"任务{id}: 进度 {i}%");
            Thread.Sleep(100);
        }
    }
    catch (OperationCanceledException)
    {
        Console.WriteLine($"任务{id}: 收到取消信号，退出");
    }
}
```

## 七、注意事项和陷阱

### 陷阱1：不检查令牌，任务无法取消
```csharp
Task task = Task.Run(() => {
    // 错误：不检查 token，cts.Cancel() 无效
    Thread.Sleep(5000);
}, cts.Token);

cts.Cancel(); // 任务继续睡5秒，停不下来
```

**教训**：任务必须**主动检查** `token.IsCancellationRequested` 或调用 `ThrowIfCancellationRequested()`。

### 陷阱2：取消后访问 Result 会抛异常
```csharp
Task<int> task = Task.Run(() => {
    cts.Token.ThrowIfCancellationRequested();
    return 42;
}, cts.Token);

cts.Cancel();

try
{
    int result = task.Result; // 会抛 AggregateException
}
catch (AggregateException ae)
{
    Console.WriteLine("取消的任务没有结果");
}
```

### 陷阱3：忘记传递令牌给 Task
```csharp
// 错误：任务没传 token，无法响应取消
Task task = Task.Run(() => {
    /* ... */
}); // 没传 cts.Token

cts.Cancel(); // 无效
```

## 八、总结

**取消任务三步曲**：
1. **创建控制器**：`var cts = new CancellationTokenSource();`
2. **传递令牌**：`Task.Run(() => {...}, cts.Token);`
3. **检查取消**：`token.ThrowIfCancellationRequested();`
4. **触发取消**：`cts.Cancel();`

**一句话记忆**：**任务自己看灯，红灯停绿灯行**。

**优点**：
- **协作式取消**：任务主动检查，安全退出
- **资源不泄漏**：任务能清理资源再退出
- **代码清晰**：明确知道是取消还是失败
