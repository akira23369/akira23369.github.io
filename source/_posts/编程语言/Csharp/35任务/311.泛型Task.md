# 泛型 Task

## 一、为什么需要 `Task<T>`？（从 Thread 无法返回值说起）

**回忆 Thread 的痛点**：线程干完活，结果怎么拿出来？

```csharp
// Thread 版本：手动用回调或共享变量
int result = 0;
new Thread(() => {
    result = 42; // 计算结果
}).Start();

Thread.Sleep(1000); // 瞎等，不知道啥时候算完
Console.WriteLine(result);
```

**Task\<T\> 的优雅**：任务干完活，自动把结果包好给你。

**Task vs Task\<T\>**：
- `Task`：干活的任务，**不返回结果**（相当于 `void` 方法）
- `Task<T>`：干活的任务，**返回一个 T 类型的结果**（相当于 `T` 方法）

---

## 二、创建带返回值的任务

### 方式1：`Task.Run()` 直接返回
```csharp
// Task<int> 表示"将来会返回 int 的任务"
Task<int> task = Task.Run(() => {
    Thread.Sleep(1000); // 模拟计算
    return 42; // 返回 int
});

Console.WriteLine("任务已提交，我干别的...");
```

### 方式2：`Task.Factory.StartNew()` 返回
```csharp
Task<int> task = Task.Factory.StartNew(() => {
    return 100;
});
```

---

## 三、获取返回值（两种方式）

### 方式1：`task.Result` —— 阻塞获取（卡线程）
```csharp
Task<int> task = Task.Run(() => {
    Thread.Sleep(1000);
    return 42;
});

Console.WriteLine("等待结果...");
int result = task.Result; // 主线程卡住，等任务完成
Console.WriteLine($"结果: {result}"); // 输出 42
```

**特点**：
- 如果任务还没完成，`Result` **会卡住当前线程**，直到任务返回
- **适合控制台程序**，不适合 UI 程序（会卡界面）

### 方式2：`await task` —— 非阻塞获取（不卡线程）
```csharp
async void Main()
{
    Task<int> task = Task.Run(() => {
        Thread.Sleep(1000);
        return 42;
    });

    Console.WriteLine("任务已提交，我干别的...");
    int result = await task; // 不卡！任务完成后自动赋值
    Console.WriteLine($"结果: {result}");
}
```

**特点**：
- `await` **不卡线程**，线程去干别的，任务完成后自动回来
- **适合 UI/ASP.NET 程序**，界面不卡死

## 四、完整示例：并行计算求和

```csharp
using System;
using System.Threading;
using System.Threading.Tasks;

class Program
{
    static void Main()
    {
        Console.WriteLine("主线程：启动3个计算任务...");

        // 3个任务分别计算
        Task<int> task1 = Task.Run(() => Calculate(1, 1000));
        Task<int> task2 = Task.Run(() => Calculate(1001, 2000));
        Task<int> task3 = Task.Run(() => Calculate(2001, 3000));

        // 等所有任务完成
        Task.WaitAll(task1, task2, task3);

        // 取结果
        int sum = task1.Result + task2.Result + task3.Result;
        Console.WriteLine($"总和: {sum}");
    }

    static int Calculate(int start, int end)
    {
        int sum = 0;
        for (int i = start; i <= end; i++)
        {
            sum += i;
        }
        Console.WriteLine($"线程 {Thread.CurrentThread.ManagedThreadId}: {start}-{end} 的和 = {sum}");
        return sum;
    }
}
```

**输出**：
```
主线程：启动3个计算任务...
线程 5: 1-1000 的和 = 500500
线程 6: 1001-2000 的和 = 1500500
线程 7: 2001-3000 的和 = 2500500
总和: 4501500
```

## 五、`Task` vs `Task<T>` 对比速查

| 特性 | Task | Task\<int\> |
|------|------|-------------|
| **返回类型** | void | int |
| **获取结果** | `task.Wait()` | `task.Result` / `await task` |
| **适用场景** | 只干活不返回 | 干活并返回结果 |
| **创建方式** | `Task.Run(() => {})` | `Task.Run(() => 42)` |

---

## 六、一句话总结

**Task\<T\> 就是"能返回值的 Task"**，解决了 Thread 无法返回值的痛点。用 `Task.Run()` 创建，`await` 获取结果，代码简洁，性能强大。

**记住**：
- **Task**：干活的（void 方法）
- **Task\<T\>**：干活并返回结果的（T 方法）
