# C# 面向对象编程笔记：深入解析封装 (Encapsulation)

## 核心概念：什么是封装？

**封装 (Encapsulation)** 是面向对象编程（OOP）的四大基本支柱之一（其余为继承、多态、抽象）。它是一种将数据和行为打包并进行访问控制的设计哲学。

理解封装，必须从它的两个核心维度来剖析：

### 维度一：数据模块化 (Data Modularity) —— “打包”
封装的第一层含义是将**状态（字段）** 和 **行为（方法）**  作为一个不可分割的**单一逻辑单元（类）** 组合在一起。
*   **字段**负责存储对象的个体数据（如：姓名、邮箱、价格、库存）。
*   **方法**负责操作这些数据（如：验证输入、计算税率、保存到数据库）。
*   **意义**：高内聚。与某个实体相关的所有数据和操作逻辑都集中在同一个地方，而不是散落在程序的各个角落。

### 维度二：隐藏实现细节 (Hiding Implementation Details) —— “保护”
封装的第二层含义，也是更为关键的含义，是**数据保护与访问控制（数据完整性）**。
*   对象的内部状态不应该被外部世界随意触碰或篡改。
*   对外只暴露必要的、经过严格定义的“接口”（公共方法），隐藏内部复杂的实现机制和脆弱的私有数据。

## 为什么要隐藏数据？(数据完整性的重要性)

假设我们有一个 `BankAccount`（银行账户）类，里面有一个 `Balance`（余额）字段。

**如果没有封装（直接暴露 public 字段）：**
```csharp
public class BankAccount 
{
    public decimal Balance; // 危险！
}
```
外部代码可以随意执行 `account.Balance = -100000;`。这种随意的赋值会导致系统出现严重错误（余额变成了负数），因为字段本身没有任何逻辑验证能力。

**有了封装（私有字段 + 公共方法）：**
```csharp
public class BankAccount 
{
    private decimal _balance; // 隐藏的真实数据

    // 对外提供的存款方法
    public void Deposit(decimal amount) 
    {
        if (amount <= 0) 
            throw new Exception("Deposit amount must be positive.");
        _balance += amount;
    }

    // 对外提供的取款方法
    public void Withdraw(decimal amount) 
    {
        if (amount > _balance)
            throw new Exception("Insufficient funds.");
        _balance -= amount;
    }

    // 对外提供的查询余额方法
    public decimal GetBalance() 
    {
        return _balance;
    }
}
```
通过这种方式，类本身重新夺回了对其内部数据的控制权。外部代码无法直接篡改 `_balance`，必须遵守 `BankAccount` 类制定的业务规则。

## 封装的经典实现模式：Get 和 Set 方法

在许多传统的面向对象语言（如 Java，以及早期的 C# 开发中），实现封装的标准做法是：
1.  **将所有实例字段声明为 `private`**。
2.  **为需要被外部访问的字段，编写一对 `public` 方法：**
    *   **Set 方法 (Setter)**：用于接收外部传入的参数（`value`），进行业务验证后，赋值给私有字段。命名规范通常为 `SetXXX()`。
    *   **Get 方法 (Getter)**：用于读取私有字段的当前值，并返回给外部调用者。命名规范通常为 `GetXXX()`。

### 传统 Get/Set 方法代码示例

**业务类定义：**
```csharp
public class Product
{
    // 1. 数据隐藏：将字段私有化
    private int _productId;
    private decimal _cost;

    // 2. 提供 Set 方法
    public void SetProductId(int value)
    {
        // 这里可以加入逻辑，例如：验证 ID 是否大于 0
        if(value <= 0) return; 
        _productId = value;
    }

    // 3. 提供 Get 方法
    public int GetProductId()
    {
        return _productId;
    }

    public void SetCost(decimal value)
    {
        if(value < 0) return; // 成本不能为负数
        _cost = value;
    }

    public decimal GetCost()
    {
        return _cost;
    }
}
```

**主程序调用：**
```csharp
class Program
{
    static void Main()
    {
        Product p = new Product();
        
        // p._productId = 1001; // 编译错误！无法访问私有字段
        
        // 通过公开的方法间接操作数据
        p.SetProductId(1001);
        p.SetCost(500m);

        Console.WriteLine($"Product ID: {p.GetProductId()}");
        Console.WriteLine($"Cost: {p.GetCost()}");
    }
}
```

## 深度进阶：C# 现代演进 —— 属性 (Properties)

虽然编写显式的 `SetXXX` 和 `GetXXX` 方法是理解封装本质的绝佳途径，但在现代 C# 开发中，**我们极少会手工编写这样的方法**。

C# 提供了一种更优雅、更符合语言特性的语法糖：**属性 (Properties)**。属性在本质上就是 Get 和 Set 方法的结合体，但在语法使用上却像访问公开字段一样自然。

### 使用 C# 属性重构封装代码

```csharp
public class Product
{
    // 后台私有字段 (Backing field)
    private decimal _cost;

    // 属性 (Property)：C# 实现封装的标准方式
    public decimal Cost
    {
        get 
        { 
            // 相当于 GetCost() 方法
            return _cost; 
        }
        set 
        { 
            // 相当于 SetCost(decimal value) 方法
            // 'value' 是 C# 属性中 setter 的内置隐式参数
            if (value >= 0) 
            {
                _cost = value; 
            }
        }
    }
}
```

**主程序的调用会变得极其简洁：**
```csharp
Product p = new Product();

// 调用属性的 set 块 (底层依然执行了验证逻辑)
p.Cost = 500m; 

// 调用属性的 get 块
Console.WriteLine(p.Cost); 
```

### 极简主义：自动实现的属性 (Auto-Implemented Properties)
如果你仅仅需要封装数据，而暂时不需要在 set 或 get 中编写任何复杂的验证逻辑，C# 提供了自动属性：

```csharp
public class Product
{
    // C# 编译器会在后台自动为你创建一个隐式的 private 字段，
    // 并自动生成 get 和 set 方法。
    public int ProductId { get; set; }
    
    public string ProductName { get; set; }
}
```

**总结与工程启示**：
无论你使用传统的 Get/Set 方法还是现代的 C# 属性，其背后的哲学是完全一致的：**永远不要将字段暴露为 `public`，永远通过受控的通道（方法或属性）来管理对象状态。** 这是编写健壮、可维护的企业级代码的第一步。
