# C# 面向对象编程笔记：将对象引用作为方法参数 (Object Reference as Arguments)

## 一、 核心概念

在 C# 中，方法的参数不仅可以是基础的数据类型（如 `int`, `double`, `string` 等），还可以是**自定义的类类型（引用类型）**。

当我们将一个对象传递给方法时，实际传递的是该对象的**引用（内存地址）**，而不是对象本身的数据拷贝。这意味着，方法的调用者（如 `Main` 方法）和被调用的方法，共享同一个对象实例。

## 二、 底层内存机制剖析（深入理解）

理解引用传递的关键在于清晰地区分**栈内存 (Stack)** 和**堆内存 (Heap)** 的工作方式：

1.  **堆内存 (Heap)**：实际的对象数据（如产品的 ID、名称、价格等）始终只存在于堆内存中，且只有一份。
2.  **栈内存 (Stack)**：
    *   在调用者的方法栈帧（例如 `Main` 方法）中，存在一个引用变量（如 `product1`），它保存了堆中对象的内存地址。
    *   当调用目标方法并传入该对象时，系统会为目标方法创建一个新的栈帧。在这个新栈帧中，会创建一个新的局部参数变量（形参）。
    *   **核心机制**：系统会将调用者变量中的“内存地址”复制给方法中的参数变量。因此，这两个位于不同栈帧的变量，**同时指向了堆内存中的同一个对象**。

## 三、 代码实战示例

为了实现高内聚，将多对象的业务逻辑（如计算多个产品的总库存）从主程序移动到类内部，我们可以利用静态方法并传入对象引用作为参数。

### 业务类中的静态方法定义
```csharp
public class Product
{
    private int _quantityInStock;

    // 获取库存的实例方法 (Get Method)
    public int GetQuantityInStock()
    {
        return _quantityInStock;
    }

    // 设置库存的实例方法 (Set Method)
    public void SetQuantityInStock(int quantity)
    {
        _quantityInStock = quantity;
    }

    // 静态方法：接收三个 Product 对象的引用作为参数
    // 注意参数类型是 Product 类名
    public static int GetTotalQuantity(Product p1, Product p2, Product p3)
    {
        // 声明局部变量来暂存总和
        int total = 0;

        // 通过传入的引用变量，调用各个对象的实例方法
        total += p1.GetQuantityInStock();
        total += p2.GetQuantityInStock();
        total += p3.GetQuantityInStock();

        return total; // 返回计算结果
    }
}
```

### 主程序中的调用
```csharp
class Program
{
    static void Main(string[] args)
    {
        // 1. 在堆内存中创建三个独立的对象
        Product product1 = new Product();
        product1.SetQuantityInStock(1200);

        Product product2 = new Product();
        product2.SetQuantityInStock(3400);

        Product product3 = new Product();
        product3.SetQuantityInStock(800);

        // 2. 调用静态方法，并将三个对象的引用作为实参传递
        int totalQuantity = Product.GetTotalQuantity(product1, product2, product3);

        // 3. 输出结果
        Console.WriteLine("Total Quantity: " + totalQuantity); // 输出: 5400
    }
}
```

## 四、 补充与完善：进阶开发中的核心认知

在实际的工程开发中，将对象作为参数传递时，需要特别注意以下两个高级行为和架构规范：

### 状态修改的副作用 (Side Effects)
因为方法内部的参数和外部的变量指向同一个对象，如果在方法内部**修改了对象的属性或字段**，这种修改是全局可见的，外部的原始对象也会随之改变。
*   *例如*：如果在 `GetTotalQuantity` 方法内部执行了 `p1.SetQuantityInStock(0);`，那么 `Main` 方法中的 `product1` 的库存也会变成 0。在设计方法时，如果该方法的语义仅仅是“读取/计算”，应绝对避免修改传入对象的状态。

### 引用重新赋值的限制
默认情况下，虽然你可以修改对象内部的数据，但你**不能改变外部变量指向的对象**。
*   *例如*：如果在方法内部执行 `p1 = new Product();`，这仅仅是将方法内部的局部参数变量 `p1` 指向了一个全新的堆内存地址。`Main` 方法中的 `product1` 依然指向原来的老对象，不受任何影响。
*   （*注：如果确实需要连“指向哪个对象”这个行为也一起修改，C# 提供了 `ref` 或 `out` 关键字，这通常属于更高级的参数修饰符范畴。*）

### 架构优化：使用集合代替硬编码参数
在上述示例中，静态方法硬编码了三个 `Product` 参数 (`p1, p2, p3`)。在真实的商业项目中，产品的数量通常是动态的。为了代码的弹性和可扩展性，行业标准做法是**传递对象的集合（如数组或 List）** 作为参数，而不是罗列单个对象：

```csharp
// 进阶重构：接收一个 Product 类型的数组或列表
public static int GetTotalQuantity(Product[] products)
{
    int total = 0;
    foreach (Product p in products)
    {
        total += p.GetQuantityInStock();
    }
    return total;
}
```
这种设计完全解耦了对象的数量限制，是面向对象设计中“应对变化”的典型实践。
