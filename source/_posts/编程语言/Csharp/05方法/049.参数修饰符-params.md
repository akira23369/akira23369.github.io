# 参数修饰符-params(可变数量参数)

## 一、 核心概念：什么是 params 修饰符？

在 C# 中，**`params` (Parameter Array)** 是一个非常实用且强大的参数修饰符。它的核心作用是**允许方法接受动态数量（可变数量）的同类型参数**。

当你设计一个方法时，如果无法提前确定调用者会传入多少个参数（可能是 0 个、1 个、5 个甚至是 100 个），传统的方式是要求调用者先创建一个数组，然后把数组传进来。而使用了 `params` 关键字后，调用者可以直接像传递普通参数一样，用逗号分隔连续传入多个值，C# 编译器会在幕后自动将这些离散的值打包成一个数组，再交由方法内部处理。

*   **极佳的用户体验 (Developer Experience)**：`params` 纯粹是为了让 API 调用者的代码更简洁、更直观而设计的。最著名的例子就是 `Console.WriteLine("Name: {0}, Age: {1}", name, age)`，其底层就使用了 `params object[] args`。

## 二、 语法规则与底层机制

要正确使用 `params`，必须严格遵守以下 C# 编译器规则：

1.  **必须是数组类型**：`params` 关键字后面跟着的参数类型**必须**是一个一维数组（如 `int[]`, `string[]`, `object[]`）。
2.  **必须是最后一个参数**：在一个方法的参数列表中，`params` 参数必须放置在**最后面**。
    *   *合法*：`void Method(int a, string b, params double[] c)`
    *   *非法*：`void Method(params int[] a, string b)` (编译报错，因为编译器无法判断前面的可变参数何时结束)
3.  **唯一性**：一个方法**最多只能有一个** `params` 参数。

**底层原理解析 (Under the Hood)**：
当你写下 `student.DisplaySubjects("Math", "Physics", "Chemistry");` 时，C# 编译器在编译阶段会拦截这段代码，并自动将其重写为：
`student.DisplaySubjects(new string[] { "Math", "Physics", "Chemistry" });`
这说明 `params` 仅仅是**编译器的语法糖**，在运行时 (Runtime)，它就是一个普普通通的数组传递。

## 三、 代码实战示例：动态课程列表与变长参数求和

### 示例 1：打印任意数量的课程名称

这个例子展示了如何使用 `params` 接收不定数量的字符串，并使用 `foreach` 循环（比 `for` 循环更简洁安全）遍历它们。

```csharp
using System;

public class Student
{
    // 方法定义：使用 params 关键字修饰字符串数组
    public void DisplaySubjects(params string[] subjects)
    {
        // 边界情况处理：如果调用者一个参数都没传，数组长度将为 0
        if (subjects == null || subjects.Length == 0)
        {
            Console.WriteLine("No subjects enrolled.");
            return;
        }

        Console.WriteLine("Enrolled Subjects:");
        // 使用 foreach 遍历编译器打包好的数组
        foreach (string subject in subjects)
        {
            Console.WriteLine($"- {subject}");
        }
        Console.WriteLine("-------------------");
    }
}

class Program
{
    static void Main()
    {
        Student s = new Student();

        // 场景 1：传入 3 个零散的字符串
        s.DisplaySubjects("Math", "Physics", "Chemistry");

        // 场景 2：传入 1 个字符串
        s.DisplaySubjects("History");

        // 场景 3：什么都不传 (完全合法！此时 subjects 数组长度为 0)
        s.DisplaySubjects(); 

        // 场景 4：直接传入一个已经建好的数组 (也是完全兼容的)
        string[] existingArray = new string[] { "Art", "Music" };
        s.DisplaySubjects(existingArray);
    }
}
```

### 示例 2：实现一个通用的变长参数数学求和方法

```csharp
public class MathUtility
{
    // 第一个参数是前缀字符串，第二个是变长的整数数组
    public static int CalculateSum(string prefixMessage, params int[] numbers)
    {
        int sum = 0;
        foreach (int num in numbers)
        {
            sum += num;
        }
        Console.WriteLine($"{prefixMessage} {sum}");
        return sum;
    }
}

// 调用示例：
// MathUtility.CalculateSum("Total is:", 10, 20, 30, 40, 50);
```

## 四、 进阶认知与架构思考 (参考《Effective C#》)

### `params` 与性能
正如前文剖析，`params` 会导致编译器在后台隐式地执行 `new [] { ... }` 操作。这意味着**每一次调用都会在堆内存 (Heap) 中分配一个新的数组对象**。
如果在极高频的循环中（例如游戏引擎每秒 60 帧的更新函数中）调用带有 `params` 的方法，会产生大量的临时数组，从而引发频繁的**垃圾回收 (GC, Garbage Collection)**，导致程序卡顿。

**架构优化建议**：
如果你的方法大部分情况下只接收 1~3 个参数，为了极致的性能，你应该提供重载版本来避免数组分配，仅将 `params` 作为最后的兜底方案：

```csharp
// 性能优化：为高频场景提供无数组分配的重载
public void Log(string a) { /* 内部逻辑 */ }
public void Log(string a, string b) { /* 内部逻辑 */ }
public void Log(string a, string b, string c) { /* 内部逻辑 */ }

// 兜底方案：给 4 个以上的参数使用
public void Log(params string[] messages) { /* 内部逻辑 */ }
```
（你可以去翻阅 .NET 源码中 `string.Concat` 或 `string.Format` 的实现，微软就是采用这种策略来压榨性能的。）

### `params object[]` 的终极灵活性
如果你希望你的方法能够接收**数量不限，且类型也不限**的参数，可以将参数声明为 `params object[] args`。这是因为在 C# 中，所有的类型都隐式继承自基类 `object`。
这种做法在日志记录组件、字符串格式化工具中极其常见，但代价是值类型（如 `int`）会被**装箱 (Boxing)**，带来额外的性能开销。
