# 方法重载

## 一、 核心概念：什么是方法重载？

**方法重载 (Method Overloading)** 是面向对象编程中实现**多态性 (Polymorphism)** （具体来说是编译时多态/静态多态）的重要机制。

简单来说，方法重载允许你在**同一个类**中，定义**多个名称完全相同**的方法。但是，为了让 C# 编译器能够区分你到底想调用哪一个方法，这些同名方法的**参数签名 (Parameter Signature)** 必须互不相同。

## 二、 构成重载的规则与底层限制

### 决定重载合法的条件（必须满足）
只有当参数签名不同时，重载才是合法的。参数签名不同包括以下三种情况（满足其一即可）：
*   **参数的数量不同**：例如 `Method(int a)` 和 `Method(int a, int b)`。
*   **参数的类型不同**：例如 `Method(int a)` 和 `Method(string a)`。
*   **参数类型的顺序不同**：例如 `Method(int a, string b)` 和 `Method(string a, int b)`。

### 无法构成重载的情况（会导致编译错误）
初学者极易踩坑的地方在于：**仅凭以下不同，不能构成方法重载！**
*   **仅返回类型不同**：`public int Method(int a)` 和 `public void Method(int a)` 属于冲突定义。因为在调用时写 `Method(5)`，编译器无法通过返回值来推断你要调用哪一个。
*   **仅参数名称不同**：`public void Method(int x)` 和 `public void Method(int y)` 是非法的，因为它们都接收一个 `int`，对调用方来说毫无区别。
*   **仅修饰符不同 (如 `params` 或部分修饰符)**：在此不做深度展开，但规则依然围绕“调用时的不可歧义性”。

## 三、 工程设计思想：为什么需要方法重载？

重载的核心目的是为了**提升代码的可用性 (Usability) 和灵活性**，减轻 API 调用者的认知负担。

设想如果我们没有方法重载，想要打印不同的数据类型，我们可能需要定义：`PrintInt(int)`、`PrintString(string)`、`PrintDouble(double)`。调用者必须记住大量不同的方法名。
有了重载，我们只需要提供一个方法名 `Print(数据)`，编译器会自动根据传入的数据类型，将执行流路由到对应的实现上去（这就是大名鼎鼎的 `Console.WriteLine()` 的底层设计思路，它拥有多达 18 个重载版本）。

## 四、 代码实战示例：税率计算的多态实现

在上一节，我们使用**默认参数**优化了税率计算。现在我们来看，如果不使用默认参数，而是想根据传入的不同数据组合提供**截然不同**的计算逻辑，该如何使用方法重载。

### 业务类中的多版本实现

```csharp
public class Product
{
    private decimal _cost;
    private decimal _tax;

    public void SetCost(decimal cost) { _cost = cost; }
    public decimal GetTax() { return _tax; }

    // 重载版本 1：只接收一个百分比参数，基于对象的 _cost 字段计算
    public void CalculateTax(decimal percentage)
    {
        if (_cost <= 20000m)
            _tax = _cost * 0.10m;
        else
            _tax = _cost * (percentage / 100m);
    }

    // 重载版本 2：接收独立的成本金额和百分比，忽略对象自身的 _cost 字段
    // 这代表了一种全新的计算策略
    public void CalculateTax(decimal customCost, decimal percentage)
    {
        if (customCost <= 50000m)
            _tax = customCost * 0.05m; // 完全不同的税率规则
        else
            _tax = customCost * (percentage / 100m);
    }
}
```

### 客户端调用时的动态路由

当我们使用现代 IDE（如 Visual Studio 或 Rider）调用重载方法时，智能提示会显示 `1 of 2` 或类似的信息，提示我们有多个可用版本。

```csharp
class Program
{
    static void Main()
    {
        Product p = new Product();
        p.SetCost(30000m);

        // 场景 1：传入 1 个参数。
        // 编译器在编译期就会将此调用绑定到 "重载版本 1"
        p.CalculateTax(9.2m); 
        // 逻辑： _cost(30000) > 20000 -> tax = 30000 * 9.2% = 2760
        Console.WriteLine($"Tax 1: {p.GetTax()}"); 

        // 场景 2：传入 2 个参数。
        // 编译器精确匹配，将调用绑定到 "重载版本 2"
        p.CalculateTax(10000m, 3.4m); 
        // 逻辑： customCost(10000) <= 50000 -> tax = 10000 * 5% = 500
        // 注意：此时完全忽略了对象本身的 _cost (30000) 和传入的 percentage(3.4)
        Console.WriteLine($"Tax 2: {p.GetTax()}"); 
    }
}
```

## 五、 方法重载vs方法重写

这是 C# 面试中的超高频考点，必须清晰区分：

*   **重载 (Overloading)**：发生在**同一个类**内部。方法名相同，参数签名不同。属于**编译时多态**（编译器在编译代码时就能确定具体调用的版本）。
*   **重写 (Overriding)**：发生在**父类与子类**之间（涉及继承和 `virtual/override` 关键字）。方法名相同，参数签名也完全相同。属于**运行时多态**（程序运行起来后，根据实际对象的类型决定调用父类还是子类的方法）。
