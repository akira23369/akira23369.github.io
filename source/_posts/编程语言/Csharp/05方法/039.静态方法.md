# 静态方法

## 一、 核心概念：什么是静态方法？

在面向对象编程中，方法分为两大阵营：**实例方法 (Instance Methods)** 和 **静态方法 (Static Methods)**。

*   **声明方式**：使用 `static` 修饰符声明的方法。
*   **归属权**：与静态字段一样，静态方法属于**类本身**，而不属于类的某个具体实例（对象）。
*   **核心使命**：静态方法设计的初衷，是为了执行那些**不依赖于特定对象状态**的逻辑操作。它最典型的工作是操作静态字段，或者执行通用的工具类计算（例如 `Math.Round()`, `Console.WriteLine()` 都是标准的静态方法）。

---

## 二、 实例方法 vs 静态方法：全方位深度对比

理解这两种方法的边界和访问权限，是 C# 架构设计的核心基石。

| 对比维度           | 实例方法 (Instance Methods)         | 静态方法 (Static Methods)         |
| :------------- | :------------------------------ | :---------------------------- |
| **修饰符**        | 无 `static`                      | 必须有 `static`                  |
| **逻辑归属**       | 属于具体的**对象实例**                   | 属于**类全局**                     |
| **调用方式 (外部)**  | **必须通过对象引用变量** (`obj.Method()`) | **必须通过类名** (`Class.Method()`) |
| **`this` 关键字** | **完全可用** (指向调用该方法的当前对象)         | **绝对禁用** (编译报错，因为没有实例上下文)     |
| **操作自身字段权限**   | 可以读写**实例字段**，也可以读写**静态字段**      | **只能**读写**静态字段**，绝对不能直接访问实例字段 |
| **调用自身方法权限**   | 可以调用**实例方法**，也可以调用**静态方法**      | **只能**调用**静态方法**，绝对不能直接调用实例方法 |

### 深度剖析：为什么静态方法不能直接访问实例成员？
这是初学者最容易踩坑的报错点：*“非静态字段要求对象引用” (An object reference is required for the non-static field)*。

**底层原理解释**：
假设类中有一个实例字段 `Cost` 和一个静态方法 `PrintCost()`。
当你通过 `Product.PrintCost()` 调用静态方法时，由于你是用类名调用的，内存中此时**可能存在0个对象，也可能存在100个对象**。
如果允许 `PrintCost()` 内部直接去读取 `Cost`，CLR (运行时) 根本无法知道你究竟想读的是这100个对象中的哪一个对象的 `Cost`！因为静态方法内部没有 `this` 指针来锁定当前的上下文。
因此，C# 编译器在编译阶段就会严格阻断这种“无源之水”的访问。

## 三、 代码实战：封装静态字段

在上一节关于“封装”的讨论中，我们了解到实例字段需要通过实例级别的 Set/Get 属性或方法来封装。同理，**静态字段也应该被封装，并且必须使用静态方法（或静态属性）来封装。**

### 业务类定义 (类库项目)
```csharp
public class Product
{
    // ----------------- 实例级别成员 -----------------
    private int _productId; // 实例字段

    public void SetProductId(int id) // 实例方法
    {
        this._productId = id;
    }

    // ----------------- 静态级别成员 -----------------
    
    // 私有静态字段：全局共享的计数器
    private static int _totalProducts = 0;

    // 静态方法：操作静态字段
    public static void SetTotalProducts(int total)
    {
        // 错误：this._totalProducts = total; (static 中不能用 this)
        
        // 正确：静态方法中可以直接访问静态字段，或者使用类名 Product._totalProducts
        _totalProducts = total; 
    }

    // 静态方法：获取静态字段的值
    public static int GetTotalProducts()
    {
        return _totalProducts;
    }
}
```

### 主程序调用 (控制台项目)
```csharp
using System;

class Program
{
    static void Main()
    {
        // 1. 调用静态方法 (使用类名调用)
        Product.SetTotalProducts(1);
        
        // 2. 调用实例方法 (必须先 new 对象，再通过引用变量调用)
        Product p1 = new Product();
        p1.SetProductId(1001);
        
        // Product.SetProductId(1001); // 编译错误！不能用类名调用实例方法
        // p1.SetTotalProducts(2);     // 编译错误！不能用对象调用静态方法
        
        // 3. 递增静态计数器
        int currentTotal = Product.GetTotalProducts();
        Product.SetTotalProducts(currentTotal + 1);
        
        Console.WriteLine($"Total Products: {Product.GetTotalProducts()}");
    }
}
```

## 四、 进阶避坑指南：`NullReferenceException` 危机

笔记中提到了一个极高频的运行时异常：`NullReferenceException` (空引用异常，俗称“对象为空”)。

**发生条件**：当你声明了一个引用变量，但没有使用 `new` 为其分配堆内存（此时它的默认值为 `null`），然后你试图通过这个 `null` 变量去调用**实例方法**或访问**实例字段**时，就会引发系统崩溃。

```csharp
Product p2 = null; // 声明了变量，但没有实例化对象

// 运行时系统会直接崩溃抛出 NullReferenceException
// 因为 p2 并没有指向堆内存中的任何真实对象，无法执行实例方法
p2.SetProductId(1002); 
```

**为什么静态方法没有这个风险？**
因为静态方法的调用压根不需要对象引用！你直接使用类名（如 `Product.GetTotalProducts()`）来调用，只要类被正确编译，这个调用就一定安全，永远不会报出“对象为空”的错误。
