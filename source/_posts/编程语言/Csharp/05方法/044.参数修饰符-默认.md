# C# 面向对象编程笔记：深入解析参数修饰符 (Parameter Modifiers) - 默认行为 (按值传递)

## 一、 核心概念：什么是参数修饰符？

在 C# 中，**参数修饰符 (Parameter Modifiers)** 决定了方法调用者（外部实参）与方法接收者（内部形参）之间**数据的传递方式**。它定义了：
1.  数据是如何从外部流向内部的。
2.  在方法内部对形参的修改，**是否会反向影响**外部的实参。

C# 支持 5 种参数传递模式（由修饰符决定）：
*   **默认 (无修饰符)**：按值传递 (Pass by Value) - *最常用，本节重点*。
*   `ref`：按引用传递 (Pass by Reference)。
*   `out`：输出参数 (Output Parameter)。
*   `in`：输入参数 (Input Parameter, C# 7.2 引入)。
*   `params`：参数数组 (Parameter Array)。

---

## 二、 深度解析：默认的参数修饰符 (按值传递 / Pass by Value)

如果我们在声明方法的参数时，没有在参数类型前面添加任何特殊的关键字（如 `ref`, `out` 等），那么这个参数就是**默认参数修饰符**。
*注意：这里的“默认”指的是传递机制，不要与上一节讲解的“指定了默认值的可选参数 (Default Arguments)”混淆。*

### 底层内存机制：值拷贝 (Value Copying)
当使用默认方式（按值传递）调用方法时，底层发生的事情是**拷贝 (Copy)**。

*   **对于值类型 (Value Types, 如 `int`, `double`, `bool`, `struct`)**：
    1. 调用者在自己的栈帧 (Stack Frame) 中有一个变量（实参）。
    2. 当调用方法时，系统会为目标方法创建一个新的栈帧。
    3. 系统将实参的**具体数值 (Value)** 复制一份，存入目标方法的栈帧中（赋给形参）。
    4. **结论**：外部实参和内部形参是**内存中完全独立的两块区域**。在方法内部对形参做的任何修改（如 `x = 10;`），修改的仅仅是那个副本，**绝对不会**影响外部的原始变量。

### 代码实战与验证

通过以下代码，我们可以清晰地看到“按值传递”的数据隔离特性：

```csharp
using System;

public class TaxCalculator
{
    // 方法的参数 percentage 没有使用任何修饰符，因此是“按值传递”
    public void CalculateTax(decimal cost, decimal percentage)
    {
        // 1. 尝试在方法内部强行修改形参的值
        percentage = 10.45m; 
        
        // 2. 内部的修改生效了，这里的输出将是 10.45
        Console.WriteLine($"[Inside Method] Percentage changed to: {percentage}");
        
        // ...执行计算逻辑...
    }
}

class Program
{
    static void Main()
    {
        TaxCalculator calc = new TaxCalculator();
        
        // 1. 定义外部的实参变量
        decimal p = 7.4m; 
        Console.WriteLine($"[Before Call] Value of p: {p}"); // 输出 7.4
        
        // 2. 调用方法。系统将 7.4 复制了一份交给了方法内部的 percentage
        calc.CalculateTax(1000m, p);
        
        // 3. 验证外部实参是否被污染
        // 结论：完全不受影响！依然是 7.4
        Console.WriteLine($"[After Call] Value of p: {p}"); 
    }
}
```
**运行结果：**
```text
[Before Call] Value of p: 7.4
[Inside Method] Percentage changed to: 10.45
[After Call] Value of p: 7.4
```

## 三、 进阶与避坑：当“按值传递”遇到“引用类型” (The Reference Type Trap)

这是 C# 面试和实际开发中最容易产生严重 Bug 的地方。

如果在方法参数中传递的不是 `int` 或 `double`，而是一个**类对象 (Class Object, 引用类型)** 呢？
**规则依然是“按值传递”，但传递的“值”是对象的内存地址 (Reference/Pointer)。**

### 剖析“引用类型的按值传递”行为：

1.  **实参和形参是两个独立的变量（都在栈中）**。
2.  系统把实参保存的**内存地址**复制给了形参。
3.  **结果**：这两个独立的变量，现在指向了堆内存 (Heap) 中的**同一个对象**。

**关键结论：**
*   **可以修改对象内部状态**：如果你在方法内部通过形参修改了对象的字段（例如 `product.Cost = 999;`），因为大家指向同一个对象，外部也能看到这个修改。
*   **不能替换整个对象**：如果你在方法内部对形参本身重新赋值（例如 `product = new Product();`），你只是改变了内部副本（形参）的指向，让它指向了一个新对象。外部的实参**完全不受影响**，依然指向老对象。

```csharp
public void ModifyProduct(Product p) 
{
    // 1. 这种操作会影响外部！因为操作的是堆内存中的共享数据。
    p.ProductName = "Changed Name"; 
    
    // 2. 这种操作绝对不会影响外部！
    // 因为 p 是按值传递的引用变量副本，你只是让副本指向了新地址。
    p = new Product() { ProductName = "Brand New" }; 
}
```

理解了这一点，就能彻底弄懂 C# 默认参数传递机制的精髓。如果要突破“不能替换整个对象”的限制，或者要让值类型的修改反向影响外部，就需要用到下一节将要介绍的 `ref` 或 `out` 修饰符。
