**目标类型 `new` 表达式 (Target-Typed `new` Expressions)** 同样是 **C# 9.0** 引入的一个极具幸福感的语法糖。它的核心目的就是**消除冗余代码，让代码更清爽**。

# 目标类型 `new`

## 什么是目标类型 `new`？
**定义**：如果编译器能从上下文（等号左边，或者方法参数）明确推断出你要实例化的具体类型，你就可以在 `new` 关键字后面**省略类型名称**，直接写 `new()`。

**引入版本**：C# 9.0

**核心价值**：符合 DRY（Don't Repeat Yourself）原则，避免在等号两边写两遍又长又复杂的类型名。

---

## 代码对比

面对复杂的泛型类型，这个特性的优势极其明显。

**❌ 以前的写法（C# 8.0 及之前，类型名写了两遍）：**
```csharp
Dictionary<string, List<int>> map = new Dictionary<string, List<int>>();
```

**✅ 现在的写法（C# 9.0+，清爽无比）：**
```csharp
Dictionary<string, List<int>> map = new();
```

*(注意：如果有构造函数参数，可以直接写在括号里，如 `new(100)`)*

---

## 常见的高效使用场景

不仅仅是局部变量，`new()` 在以下场景中非常有用：

### 场景 A：字段和属性的初始化
在类中初始化私有集合或对象时，极其简洁。
```csharp
public class Order
{
    // 属性初始化
    public DateTime CreatedAt { get; set; } = new(); 
    
    // 字段初始化
    private readonly List<OrderItem> _items = new(); 
}
```

### 场景 B：方法参数传递
当方法需要一个对象作为参数时，不需要写出完整的类名。
```csharp
void ProcessData(DataOptions options) { /*...*/ }

// 调用时：
ProcessData(new()); // 编译器知道你需要 DataOptions
ProcessData(new() { RetryCount = 3 }); // 还可以配合对象初始化器 {}
```

### 场景 C：集合内部元素的初始化
在初始化 List 或 Array 时，可以省略元素的类型。
```csharp
List<Person> people = new()
{
    new() { Name = "Alice", Age = 25 },
    new() { Name = "Bob", Age = 30 }
};
```

## 严格的限制与易错点

编译器必须能**100%确定**目标类型，否则会报错。

1. **绝对不能和 `var` 一起使用！**
   ```csharp
   var dict = new(); // ❌ 编译报错：无法推断类型！左边是盲盒，右边也是盲盒。
   ```

2. **目标类型不能是接口 (Interface) 或 抽象类 (Abstract Class)**
   ```csharp
   IList<string> list = new(); // ❌ 编译报错：IList<T> 是接口，编译器不知道你要 new List 还是 new 数组。
   // 必须老老实实写：IList<string> list = new List<string>();
   ```

3. **方法重载时的歧义**
   如果一个方法有多个重载版本，使用 `new()` 可能会导致编译器不知道该调用哪个。
   ```csharp
   void Print(Person p) { }
   void Print(Animal a) { }
   
   Print(new()); // ❌ 编译报错：不知道你要 new Person 还是 new Animal。
   ```

## 最佳实践争论：`var` vs `new()`

在局部变量声明时，我们有了两种简化代码的选择，到底用哪个？
微软官方并没有强制规定，通常取决于你的团队规范和**可读性**：

* **流派 1：类型在右边（习惯用 `var`）**
  ```csharp
  var user = new UserProfile();
  // 适合：看重变量名，类型名在右边一目了然。
  ```

* **流派 2：类型在左边（习惯用 `new()`）**
  ```csharp
  UserProfile user = new();
  // 适合：强类型爱好者，一眼看到变量的确切类型。
  ```
**总结建议**：局部变量可以用 `var`，但如果是**类的字段(Field)**、**属性(Property)** 或 **方法参数**（这些地方不能用 `var`），果断使用 `new()`！
