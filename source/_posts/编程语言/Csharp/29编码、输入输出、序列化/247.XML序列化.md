## 第一章：XML 基础概论

在深入 C# 代码之前，我们必须牢固掌握 XML 本身的理论基础。你已經熟悉了 JSON，这有助于理解，但 XML 有着完全不同的设计哲学。

### 什么是 XML？

XML，全称 **Extensible Markup Language**（可扩展标记语言），是一种用于存储和传输数据的标记语言。它由万维网联盟（W3C）于 1998 年发布推荐标准。

**核心定义：**
XML 被设计用来**传输和存储数据**，其焦点是**数据的内容**。相比之下，HTML 被设计用来**显示数据**，其焦点是**数据的外观**。

**关键特性：**
1.  **自描述性：** XML 标签没有被预先定义。你需要自己定义标签（如 `<Book>`, `<Price>`）。这使得它具有极强的可扩展性。
2.  **平台无关性：** XML 是纯文本格式，任何硬件、软件平台都可以读取和生成。
3.  **层次结构：** XML 数据天然呈现树状结构（DOM 树），适合表示具有层级关系的数据。
4.  **严格语法：** XML 对语法要求非常严格，标签必须闭合，大小写敏感，属性值必须加引号等。

### XML 的历史与设计目标

在 90 年代末期，互联网快速发展，SGML（Standard Generalized Markup Language）虽然功能强大但过于复杂，不适合 Web 使用。HTML 虽然简单，但混用了内容与表现，且缺乏数据描述能力。

XML 的设计目标是在 SGML 的灵活性和 HTML 的易用性之间找到平衡。它最初被寄予厚望，成为 Web 服务（Web Services）、配置文件、文档存储的标准格式。虽然现在 JSON 在 Web API 领域占据了主导地位，但 XML 在企业级应用、配置文件（如 .csproj, .xml config）、文档格式（Office Open XML, PDF 内部结构）以及遗留系统中依然不可或缺。

### XML 与 HTML 的区别

很多初学者容易混淆两者，以下是关键区别笔记：

| 特性 | XML | HTML |
| :--- | :--- | :--- |
| **目的** | 存储和传输数据 | 显示数据 |
| **标签** | 自定义（用户定义） | 预定义（浏览器识别） |
| **语法严格性** | 极高（标签必须闭合，区分大小写） | 较低（容错性强，某些标签可不闭合） |
| **空标签** | `<img />` 必须闭合 | `<img>` 通常可接受 |
| **大小写** | 敏感 (`<Book>` != `<book>`) | 不敏感 |
| **属性值** | 必须加引号 | 有时可省略引号 |

**重点：** 在 C# 序列化中，我们生成的是 XML，必须严格遵守 XML 语法规范，否则解析器会抛出异常。

### XML 与 JSON 的对比分析

既然你已经学过 JSON，对比学习能加深理解。

| 特性        | XML                        | JSON                                              |
| :-------- | :------------------------- | :------------------------------------------------ |
| **体积**    | 较大（重复的标签名）                 | 较小（键名重复少）                                         |
| **可读性**   | 较好（标签语义清晰）                 | 好（结构紧凑）                                           |
| **数据类型**  | 所有数据本质是字符串，需 Schema 定义类型   | 原生支持 String, Number, Boolean, Null, Array, Object |
| **元数据**   | 支持属性（Attributes）作为元数据      | 只能通过额外的键值对表示                                      |
| **注释**    | 支持 `<!-- -->`              | 不支持标准注释                                           |
| **命名空间**  | 原生支持 xmlns                 | 不支持                                               |
| **解析速度**  | 相对较慢（结构复杂）                 | 相对较快                                              |
| **C# 支持** | 多种序列化器（XmlSerializer, DCS） | Newtonsoft, System.Text.Json                      |

**何时选择 XML？**
1.  需要文档标记（如混合内容：文本中包含标签）。
2.  需要严格的 Schema 验证（XSD）。
3.  需要命名空间支持（避免标签冲突）。
4.  对接遗留系统（SOAP Web Services, 银行接口，政府接口）。
5.  配置文件（.NET 传统 config 文件）。

### XML 文档结构详解

一个标准的 XML 文档由以下部分组成：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!-- 这是一条注释 -->
<Root xmlns="http://example.com/ns">
    <Element Attribute="Value">
        <![CDATA[一些不需要转义的特殊字符 < > &]]>
        Text Content
    </Element>
</Root>
```

**详细拆解：**

1.  **XML 声明 (Prolog):** `<?xml version="1.0" encoding="UTF-8"?>`
    *   必须位于文档第一行（此前不能有空白）。
    *   声明版本和编码。UTF-8 是最常用的编码。
2.  **根元素 (Root Element):** 整个文档必须有一个且仅有一个根元素。所有其他元素都是它的子元素。
3.  **元素 (Elements):** 由开始标签 `<Book>`、内容和结束标签 `</Book>` 组成。
4.  **属性 (Attributes):** 位于开始标签内，提供关于元素的额外信息。如 `id="123"`。
    *   在序列化设计中，通常建议简单数据用元素，元数据用属性。
5.  **文本内容 (Text Content):** 元素之间的数据。
6.  **CDATA 节:** `<![CDATA[ ... ]]>` 用于包裹不需要解析器转义的内容（如包含大量 `<` 的代码片段）。
7.  **实体引用 (Entity References):** XML 中有 5 个预定义实体：
    *   `&lt;` (<)
    *   `&gt;` (>)
    *   `&amp;` (&)
    *   `&quot;` (")
    *   `&apos;` (')
    *   *注意：* 序列化器会自动处理这些转义，但手动编写 XML 时需注意。
8.  **命名空间声明 (Namespace Declaration):** `xmlns="..."` 或 `xmlns:prefix="..."`。

### 命名空间（Namespace）的核心概念

这是 XML 中最难理解但也最重要的部分之一。

**问题背景：**
假如有两个不同的系统，都定义了 `<Table>` 标签。一个指“数据库表”，一个指“家具桌子”。当这两个 XML 合并时，就会发生冲突。

**解决方案：**
使用 URI（统一资源标识符）来唯一标识标签的来源。

**语法：**
```xml
<Root xmlns="http://default.namespace.com" 
      xmlns:book="http://book.namespace.com">
    <Table>默认命名空间的表</Table>
    <book:Table>书籍命名空间的表</book:Table>
</Root>
```

**在 C# 序列化中的意义：**
.NET 的序列化器允许你控制生成的 XML 是否包含命名空间。默认情况下，`XmlSerializer` 可能会生成冗长的 `xmlns:xsi` 和 `xmlns:xsd` 声明。在生产环境中，为了减小体积和兼容性，我们通常需要移除或自定义这些默认命名空间。

### XML Schema (XSD) 与 DTD

**DTD (Document Type Definition):**
较老的标准，语法非 XML 格式，功能有限，不支持数据类型（除了枚举等基础）。现在较少使用。

**XSD (XML Schema Definition):**
当前标准。它本身也是一个 XML 文件，用于定义 XML 文档的结构、数据类型、约束。
*   可以定义元素必须是整数、日期或特定字符串格式。
*   可以定义必填项、可选项。
*   C# 可以通过 `xsd.exe` 工具根据 XSD 生成 C# 类，或根据 C# 类生成 XSD。

在企业级集成中，通常先约定 XSD，再生成代码，确保双方数据结构一致。

## 第二章：.NET 中的 XML 技术栈概览

.NET 框架经过二十多年的发展，提供了多种处理 XML 的方式。选择合适的工具是成功的关键。

### .NET XML 类库演变史

1.  **.NET Framework 1.0/1.1:** 引入了 `System.Xml` 和 `System.Xml.Serialization`。这是最经典的 XML 处理方式，基于 DOM 和 SAX 模式。
2.  **.NET Framework 2.0:** 增强了 `XmlSerializer`，引入了 `DataContractSerializer` 的雏形（为 WCF 准备）。
3.  **.NET Framework 3.5:** 引入了 **LINQ to XML** (`System.Xml.Linq`)。这是一次革命，使得 XML 操作像查询数据库一样简单，支持函数式构造。
4.  **.NET Core / .NET 5+:** 大部分 XML 库被保留并优化，但移除了部分旧的王牌技术（如 WCF 客户端部分功能），强调跨平台兼容性。`System.Text.Json` 崛起，但 XML 领域依然依赖传统库。

### System.Xml.Serialization (XmlSerializer)

*   **定位：** 最常用的 XML 序列化器，用于将 public 字段和属性转换为 XML。
*   **优点：** 配置灵活，支持丰富的属性控制，社区资料多。
*   **缺点：** 性能一般（首次启动慢，因为动态生成程序集），要求类必须有公共无参构造函数，只能序列化 public 成员。
*   **适用场景：** 一般的数据持久化、Web Service 数据交换。

### System.Runtime.Serialization (DataContractSerializer)

*   **定位：** WCF (Windows Communication Foundation) 的默认序列化器。
*   **优点：** 性能优于 `XmlSerializer`，支持非 public 成员（通过属性），版本控制能力强。
*   **缺点：** 控制粒度不如 `XmlSerializer` 精细（例如很难控制属性变元素），与 WCF 绑定较深。
*   **适用场景：** WCF 服务内部，或对性能有较高要求的 XML 交换。

### System.Xml.Linq (LINQ to XML)

*   **定位：** 内存中的 XML 树表示，侧重于**操作**而非单纯的序列化。
*   **优点：** API 现代简洁，支持 LINQ 查询，支持函数式构造（直接 new XElement）。
*   **缺点：** 不是直接的“对象转 XML"序列化器，需要手动映射（虽然可以自己写扩展方法）。
*   **适用场景：** 需要灵活读取、修改 XML 结构，或 XML 结构不固定时。

### System.Xml (XmlReader/XmlWriter)

*   **定位：** 底层的流式读写器。
*   **优点：** 性能最高，内存占用最低（不回溯，不加载整个文档）。
*   **缺点：** 使用复杂，代码量大，容易出错。
*   **适用场景：** 超大文件处理（GB 级别），高性能中间件。

### 技术选型指南

| 需求场景 | 推荐技术 | 理由 |
| :--- | :--- | :--- |
| 简单对象存为 XML 文件 | `XmlSerializer` | 简单，属性控制多 |
| WCF 服务通信 | `DataContractSerializer` | 框架集成好，性能优 |
| 灵活查询/修改 XML | `LINQ to XML` | 语法友好，功能强 |
| 超大文件流式处理 | `XmlReader/Writer` | 内存效率最高 |
| 需要复杂验证 | `XSD + XmlSerializer` | 生态完善 |
| .NET Core 新项目 | `XmlSerializer` 或 `LINQ to XML` | 兼容性好 |

在本教程的后续章节，我们将重点攻克 `XmlSerializer`，因为它是通用性最强、学习曲线最适合从 JSON 过渡过来的开发者。

## 第三章：XmlSerializer 深度解析（核心）

这是本文的核心部分。`System.Xml.Serialization.XmlSerializer` 是 C# 中处理 XML 序列化的主力军。

### XmlSerializer 的工作原理

理解原理有助于调试。
1.  **反射 (Reflection):** `XmlSerializer` 首先通过反射分析你要序列化的类型（Class）。
2.  **动态程序集 (Dynamic Assembly):** 为了提高后续性能，它会动态生成一个临时的序列化程序集（Serialization Assembly）。这个程序集包含专门针对该类型的读写代码。
    *   *注意：* 这就是为什么第一次序列化某个类型时会比较慢。
    *   *注意：* 在 AOT (Ahead-of-Time) 编译环境（如 .NET Native 或某些 Xamarin 场景）中，动态生成可能受限，需要预生成序列化程序集。
3.  **缓存:** 生成的序列化器会被缓存，后续针对同一类型的操作会直接使用缓存，速度变快。
4.  **约束:** 由于它动态生成代码访问成员，所以被序列化的字段或属性必须是 **public** 的，且类必须有 **public 无参构造函数**。

### 基本序列化与反序列化

让我们从一个最简单的例子开始。

**定义类：**
```csharp
using System;
using System.Xml.Serialization;

public class Book
{
    // 默认情况下，public 属性会被序列化为 XML 元素
    public string Title { get; set; }
    public string Author { get; set; }
    public decimal Price { get; set; }
}
```

**序列化代码：**
```csharp
using System;
using System.IO;
using System.Text;
using System.Xml.Serialization;

public class Program
{
    public static void Main()
    {
        Book book = new Book
        {
            Title = "C# 高级编程",
            Author = "李四",
            Price = 99.00m
        };

        XmlSerializer serializer = new XmlSerializer(typeof(Book));

        // 使用 StringWriter 将 XML 输出到字符串，方便查看
        using (StringWriter writer = new StringWriter())
        {
            serializer.Serialize(writer, book);
            string xmlString = writer.ToString();
            Console.WriteLine(xmlString);
        }
    }
}
```

**生成的 XML 输出：**
```xml
<?xml version="1.0" encoding="utf-16"?>
<Book xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" xmlns:xsd="http://www.w3.org/2001/XMLSchema">
  <Title>C# 高级编程</Title>
  <Author>李四</Author>
  <Price>99.00</Price>
</Book>
```

**反序列化代码：**
```csharp
public static Book DeserializeBook(string xml)
{
    XmlSerializer serializer = new XmlSerializer(typeof(Book));
    using (StringReader reader = new StringReader(xml))
    {
        return (Book)serializer.Deserialize(reader);
    }
}
```

**要点：**
1.  `encoding="utf-16"`: 注意 `StringWriter` 默认使用 UTF-16。如果需要 UTF-8，需要自定义 `TextWriter` 或使用 `FileStream`。
2.  `xmlns:xsi` 和 `xmlns:xsd`: 这是默认携带的命名空间声明。如果不需要，可以通过 `XmlSerializerNamespaces` 移除。
3.  异常处理：如果 XML 结构与类不匹配（例如缺少必填元素，或类型转换失败），`Deserialize` 会抛出 `InvalidOperationException`。

### 控制 Xml 元素名称与顺序

默认情况下，元素名等于属性名。但在实际项目中，我们经常需要自定义名称（例如符合第三方接口规范）。

**属性：** `[XmlElement]`

```csharp
public class Book
{
    [XmlElement(ElementName = "BookTitle"), Orderr = 0] // 自定义元素名
    public string Title { get; set; }
    
    [XmlElement(ElementName = "Cost", Order = 2)] 
    public decimal Price { get; set; }
    
    [XmlElement(ElementName = "Writer", Order = 1)] // 自定义顺序
    public string Author { get; set; }
}
```

**生成的 XML：**
```xml
<Book>
  <BookTitle>C# 高级编程</BookTitle>
  <Writer>李四</Writer>
  <Cost>99.00</Cost>
</Book>
```


### 属性序列化 vs 元素序列化

在 XML 中，数据可以放在元素内容中，也可以放在属性中。
*   元素：`<Price>99.00</Price>`
*   属性：`<Book Price="99.00" />`

**属性：** `[XmlAttribute]`

```csharp
public class Book
{
    [XmlAttribute("isbn")] // 序列化为属性，名为 isbn
    public string ISBN { get; set; }

    [XmlElement] // 显式声明为元素（默认也是元素）
    public string Title { get; set; }
}
```

**生成的 XML：**
```xml
<Book isbn="978-7-121-12345-6">
  <Title>C# 高级编程</Title>
</Book>
```

*   属性通常用于元数据（ID、类型、版本）。
*   元素用于主要数据内容。
*   属性不能包含复杂结构（如子元素）。
*   属性值中不能包含换行符等复杂字符。

### 集合与数组的处理

C# 中的 `List<T>` 或数组如何映射到 XML？

**场景 1：默认集合**
```csharp
public class Library
{
    public List<Book> Books { get; set; }
}
```
**生成的 XML：**
```xml
<Library>
  <Books>
    <Book>...</Book>
    <Book>...</Book>
  </Books>
</Library>
```
注意中间多了一层 `<Books>` 包装元素。

**场景 2：扁平化集合 (XmlElement)**
如果你希望 `<Book>` 直接位于 `<Library>` 下，去掉中间的 `<Books>` 层。
```csharp
public class Library
{
    [XmlElement("Book")] // 指定每个项的元素名
    public List<Book> Books { get; set; }
}
```
**生成的 XML：**
```xml
<Library>
  <Book>...</Book>
  <Book>...</Book>
</Library>
```

**场景 3：数组**
数组的处理方式与 List 类似，`XmlSerializer` 天然支持数组。

**场景 4：字典 (Dictionary)**
`XmlSerializer` **不直接支持** `Dictionary<TKey, TValue>`。
*   *解决方案 1:* 将 Dictionary 转换为 `List<KeyValuePair>` 进行序列化。
*   *解决方案 2:* 实现 `IXmlSerializable` 接口手动控制。
*   *建议:* 在数据传输对象 (DTO) 中尽量避免使用 Dictionary，改用列表。

### 处理 null 值与可选元素

在 XML Schema 中，元素可以是可选的（minOccurs="0"）。在 C# 中，引用类型 null 默认不序列化（或序列化为空元素，视配置而定）。值类型（如 int）不能为 null。

**问题：** 如何区分“值为 0"和“值未设置”？
**解决方案：** `Specified` 模式。

```csharp
public class Product
{
    public string Name { get; set; }
    
    public int Count { get; set; }
    
    // 特殊属性：属性名 + "Specified"
    // 如果 CountSpecified 为 false，则 Count 元素不会被序列化
    [XmlIgnore] 
    public bool CountSpecified { get; set; } 
}
```

**逻辑：**
*   序列化时：检查 `CountSpecified`。如果为 true，写入 `<Count>...</Count>`；如果为 false，忽略 Count。
*   反序列化时：如果 XML 中有 Count 元素，`CountSpecified` 自动设为 true；否则为 false。

**另一种方案：使用可空类型**
```csharp
public int? Count { get; set; }
```
`XmlSerializer` 支持可空类型。如果为 null，默认不生成元素（或生成 xsi:nil="true"，取决于配置）。

### 继承与多态序列化处理

这是 XML 序列化的高级难点。假设有一个基类 `Animal` 和子类 `Dog`, `Cat`。

```csharp
public class Zoo
{
    // 这里声明为基类，但运行时可能是子类
    [XmlElement(typeof(Dog))]
    [XmlElement(typeof(Cat))]
    public Animal Animal { get; set; }
}
```

**生成的 XML：**
```xml
<Zoo>
  <Animal xsi:type="Dog">
    <BarkVolume>10</BarkVolume>
  </Animal>
</Zoo>
```
*注意：* `xsi:type` 属性会被自动添加，用于告诉反序列化器实际类型是什么。

*   必须在基类属性上用 `[XmlElement(typeof(SubClass))]` 显式告知序列化器可能的子类类型。
*   否则反序列化时会失败，因为它不知道实例化哪个类。
*   如果使用 `DataContractSerializer`，则使用 `[KnownType]` 属性。

### 自定义命名空间控制

默认生成的 `xmlns:xsi` 和 `xmlns:xsd` 往往是不需要的，而且根元素的默认命名空间可能也不是我们想要的。

**代码示例：**
```csharp
XmlSerializer serializer = new XmlSerializer(typeof(Book));

// 创建命名空间对象
XmlSerializerNamespaces ns = new XmlSerializerNamespaces();
// 添加空命名空间，消除默认的 xmlns:xsi 和 xmlns:xsd
ns.Add("", ""); 
// 或者自定义默认命名空间
// ns.Add("", "http://mycompany.com/schema");

using (StringWriter writer = new StringWriter())
{
    serializer.Serialize(writer, book, ns); // 传入 ns 参数
    Console.WriteLine(writer.ToString());
}
```

**生成的 XML：**
```xml
<?xml version="1.0" encoding="utf-16"?>
<Book>
  <Title>...</Title>
</Book>
```
这样看起来更干净，适合大多数数据交换场景。

### 实现 IXmlSerializable 接口

当默认的 attribute 配置无法满足需求时（例如需要完全控制 XML 结构，或处理复杂字典），可以实现 `System.Xml.Serialization.IXmlSerializable` 接口。

**接口成员：**
1.  `XmlSchema GetSchema()`: 通常返回 null。
2.  `void ReadXml(XmlReader reader)`: 手动反序列化逻辑。
3.  `void WriteXml(XmlWriter writer)`: 手动序列化逻辑。

**示例：自定义字典序列化**
```csharp
using System;
using System.Collections.Generic;
using System.Xml;
using System.Xml.Schema;
using System.Xml.Serialization;

public class MyDictionary<TKey, TValue> : Dictionary<TKey, TValue>, IXmlSerializable
{
    // 返回 null 即可，通常不需要自定义架构
    public XmlSchema GetSchema() => null;

    // 反序列化：从 XML 读取数据并填充到 Dictionary
    public void ReadXml(XmlReader reader)
    {
        XmlSerializer keySerializer = new XmlSerializer(typeof(TKey));
        XmlSerializer valueSerializer = new XmlSerializer(typeof(TValue));

        bool wasEmpty = reader.IsEmptyElement;
        reader.Read(); // 移动到根元素内部

        if (wasEmpty) return;

        while (reader.NodeType != XmlNodeType.EndElement)
        {
            reader.ReadStartElement("item");

            reader.ReadStartElement("key");
            TKey key = (TKey)keySerializer.Deserialize(reader);
            reader.ReadEndElement();

            reader.ReadStartElement("value");
            TValue value = (TValue)valueSerializer.Deserialize(reader);
            reader.ReadEndElement();

            this.Add(key, value);

            reader.ReadEndElement(); // 结束 item
            reader.MoveToContent(); // 跳过空白字符
        }
        reader.ReadEndElement(); // 结束根元素
    }

    // 序列化：将 Dictionary 的内容写入 XML
    public void WriteXml(XmlWriter writer)
    {
        XmlSerializer keySerializer = new XmlSerializer(typeof(TKey));
        XmlSerializer valueSerializer = new XmlSerializer(typeof(TValue));

        foreach (TKey key in this.Keys)
        {
            writer.WriteStartElement("item");

            writer.WriteStartElement("key");
            keySerializer.Serialize(writer, key);
            writer.WriteEndElement();

            writer.WriteStartElement("value");
            valueSerializer.Serialize(writer, this[key]);
            writer.WriteEndElement();

            writer.WriteEndElement();
        }
    }
}

// 使用
var dic = new MyDictionary<string, int>();
dic["hello"] = 0;
dic["world"] = 666;



```
实现此接口工作量较大，且容易出错，仅在必要时使用。

生成的xml
```xml

  <item>
    <key>
      <string>hello</string>
    </key>
    <value>
      <int>0</int>
    </value>
  </item>
  <item>
    <key>
      <string>world</string>
    </key>
    <value>
      <int>666</int>
    </value>
  </item>
</MyDictionaryOfStringInt32>
```

## 第四章：DataContractSerializer 深度解析

### WCF 时代的遗产

`DataContractSerializer` (DCS) 是随着 WCF (Windows Communication Foundation)  introduced 的。它的设计目标是比 `XmlSerializer` 更快、更严格、更适合服务通信。虽然 WCF 在现代 .NET Core 中地位下降，但 DCS 依然存在于 `System.Runtime.Serialization` 命名空间中。

### 与 XmlSerializer 的核心差异

1.  **成员可见性：** `XmlSerializer` 只能序列化 public 属性/字段。DCS 可以序列化 private 字段（只要属性有 getter/setter 且标记了 `[DataMember]`）。
2.  **顺序控制：** `XmlSerializer` 按字母或 Order 属性。DCS 严格依赖 `[DataMember(Order = n)]`。
3.  **名称控制：** DCS 使用 `[DataContract(Name = "...")]` 和 `[DataMember(Name = "...")]`。
4.  **性能：** DCS 通常比 `XmlSerializer` 快 10% 左右，因为它不使用动态程序集生成，而是使用反射缓存。
5.  **版本容忍度：** DCS 对未知数据更宽容（默认忽略未知元素），而 `XmlSerializer` 可能会报错或需要额外配置。

### DataContract 与 DataMember 属性

```csharp
using System.Runtime.Serialization;

[DataContract(Name = "ProductInfo")] // 类映射
public class Product
{
    [DataMember(Name = "ID", Order = 1)] // 属性映射
    public int Id { get; set; }

    [DataMember(Name = "ProductName", Order = 2)]
    public string Name { get; set; }

    // 没有 DataMember 属性的字段不会被序列化
    public string InternalCode { get; set; } 
}
```

### 版本控制与兼容性

DCS 提供了更好的版本控制支持。
*   **`IsRequired = false`**: 表示该字段在反序列化时如果缺失，不会报错，保持默认值。
*   **`EmitDefaultValue = false`**: 如果值是默认值（如 int 0, string null），则不序列化该元素，减小体积。

```csharp
[DataMember(EmitDefaultValue = false)]
public string Description { get; set; }
```
如果 Description 为 null，XML 中将不会出现 `<Description>` 节点。

### 已知类型（Known Types）处理

与 `XmlSerializer` 的 `[XmlElement(typeof...)]` 类似，DCS 处理多态需要使用 `[KnownType]`。

```csharp
[DataContract]
[KnownType(typeof(Dog))]
[KnownType(typeof(Cat))]
public class Animal { }
```
这告诉序列化器，当遇到 `Animal` 类型时，要注意可能是 `Dog` 或 `Cat` 的实例。

## 第五章：LINQ to XML (XDocument/XElement)

如果你不需要严格的“对象 <-> XML"映射，而是需要灵活地处理 XML 文档，LINQ to XML 是最佳选择。它位于 `System.Xml.Linq` 命名空间。

### 函数式构造的优势

传统的 `XmlDocument` 需要创建节点、追加子节点，代码繁琐。LINQ to XML 支持函数式构造，可以在一行代码中构建整个树。

```csharp
using System.Xml.Linq;

XDocument doc = new XDocument(
    new XDeclaration("1.0", "utf-8", "yes"),
    new XElement("Books",
        new XElement("Book", 
            new XAttribute("id", 1),
            new XElement("Title", "C# Guide"),
            new XElement("Price", 50)
        ),
        new XElement("Book",
            new XAttribute("id", 2),
            new XElement("Title", "Python Guide"),
            new XElement("Price", 60)
        )
    )
);
```
这种写法非常直观，代码结构与 XML 结构完全对应。

对应xml
```xml
<Books>
  <Book id="1">
    <Title>C# Guide</Title>
    <Price>50</Price>
  </Book>
  <Book id="2">
    <Title>Python Guide</Title>
    <Price>60</Price>
  </Book>
</Books>
```


### 加载与保存 XML

```csharp
// 从文件加载
XDocument doc = XDocument.Load("data.xml");

// 从字符串加载
string xmlStr = "<Root>...</Root>";
XDocument doc = XDocument.Parse(xmlStr);

// 保存到文件
doc.Save("output.xml");

// 保存到字符串
string result = doc.ToString();
```

### 查询 XML 数据

结合 LINQ 查询表达式，可以方便地筛选数据。

```csharp
// 查询所有价格大于 55 的书名
var titles = from book in doc.Root.Elements("Book")
             where (decimal)book.Element("Price") > 55
             select (string)book.Element("Title");

// 或使用 Lambda 表达式
var titles2 = doc.Root.Elements("Book")
    .Where(b => (decimal)b.Element("Price") > 55)
    .Select(b => (string)b.Element("Title"));
```
**类型转换：** `XElement` 支持显式转换为 string, int, decimal 等类型，如果转换失败会抛出异常，也可以使用 `(int?)element` 进行可空转换。

**`b.Element("Title").Value`和`(string)b.Element("Title")`是不是一样？**
在 C# 的 **LINQ to XML** (`System.Xml.Linq`) 中，这两者在**结果**上通常是一样的，但在**安全性（健壮性）** 上有着本质的区别。
简单来说：**推荐使用强制转换 `(string)`，因为它能优雅地处理空引用。**

### 修改与更新 XML

LINQ to XML 支持直接修改树结构。

```csharp
// 修改第一个 Book 的价格
var firstBook = doc.Root.Element("Book");
if (firstBook != null)
{
    firstBook.Element("Price").SetValue(99.99m);
}

// 添加新书
doc.Root.Add(new XElement("Book", ...));
```

### 与序列化的结合使用

你可以手动编写扩展方法，将对象转换为 `XElement`，然后再保存。这种方式比 `XmlSerializer` 更灵活，适合 XML 结构不规则的场景。

```csharp
public static XElement ToXml(this Book book)
{
    return new XElement("Book",
        new XAttribute("id", book.Id),
        new XElement("Title", book.Title)
    );
}
```

## 第六章：底层读写 (XmlReader/XmlWriter)

### 流式处理的优势

`XmlSerializer` 和 `XDocument` 都需要将整个 XML 加载到内存中（DOM 模型）。如果 XML 文件有 1GB，内存就会爆炸。
`XmlReader` 和 `XmlWriter` 是流式的（Forward-only）。它们一次只读取一个节点，内存占用恒定。

### XmlReader 的使用模式

```csharp
using (XmlReader reader = XmlReader.Create("largefile.xml"))
{
    while (reader.Read())
    {
        if (reader.NodeType == XmlNodeType.Element && reader.Name == "Book")
        {
            string title = reader.ReadElementContentAsString();
            // 处理数据，不保存到内存树中
        }
    }
}
```
使用 `XmlReader` 需要仔细管理状态，确保读取位置正确。

### XmlWriter 的使用模式

```csharp
XmlWriterSettings settings = new XmlWriterSettings 
{ 
    Indent = true, 
    Encoding = Encoding.UTF8 
};

using (XmlWriter writer = XmlWriter.Create("output.xml", settings))
{
    writer.WriteStartDocument();
    writer.WriteStartElement("Books");
    
    writer.WriteStartElement("Book");
    writer.WriteElementString("Title", "Test");
    writer.WriteEndElement();
    
    writer.WriteEndElement();
    writer.WriteEndDocument();
}
```

### 高性能场景下的应用

在日志系统、大数据导出工具中，推荐使用 `XmlWriter`。它避免了反射开销和内存分配开销。

## 第七章：高级主题与最佳实践

### 性能优化策略

1.  **缓存 XmlSerializer 实例：** 不要每次序列化都 `new XmlSerializer(typeof(T))`。因为首次初始化成本高，应该将其定义为 `static readonly`。
    ```csharp
    private static readonly XmlSerializer _serializer = new XmlSerializer(typeof(Book));
    ```
2.  **预生成序列化程序集 (SGen.exe)：** 在大型项目中，使用 SGen 工具预先生成序列化程序集，避免运行时动态编译，提高启动速度。
3.  **避免不必要的命名空间：** 如 3.8 节所述，移除默认 xmlns 可以减少字符串处理开销。
4.  **使用 XmlWriter 替代 Serialize：** 对于极高性能需求，手动编写 XmlWriter 代码比反射快得多。

### 安全性考虑（XXE 攻击防护）

**XXE (XML External Entity)** 是一种严重的安全漏洞。攻击者可以通过定义外部实体来读取服务器本地文件。

**危险代码：**
```csharp
// 默认情况下，某些 XmlReader 设置可能允许实体解析
XmlReaderSettings settings = new XmlReaderSettings();
// 错误配置：允许 DTD 处理
settings.DtdProcessing = DtdProcessing.Parse; 
```

**安全实践：**
1.  **禁用 DTD 处理：**
    ```csharp
    XmlReaderSettings settings = new XmlReaderSettings();
    settings.DtdProcessing = DtdProcessing.Prohibit; // 禁止
    settings.XmlResolver = null; // 禁用外部实体解析
    ```
2.  **在使用 XmlSerializer 时：** 虽然 `XmlSerializer` 默认相对安全，但如果配合自定义 `XmlReader` 使用，务必传入安全的 settings。
3.  **验证输入：** 永远不要信任客户端传来的 XML 字符串，先进行 Schema 验证或长度限制。

### 编码与 BOM 问题

*   **UTF-8 vs UTF-16:** .NET 内部字符串是 UTF-16。`StringWriter` 默认输出 UTF-16。Web 通常期望 UTF-8。
*   **解决方案：** 使用 `StreamWriter` 指定编码。
    ```csharp
    using (var stream = new FileStream("data.xml", FileMode.Create))
    using (var writer = new StreamWriter(stream, Encoding.UTF8))
    {
        serializer.Serialize(writer, obj);
    }
    ```
*   **BOM (Byte Order Mark):** 某些旧系统要求 UTF-8 带 BOM，某些严格要求不带。`new UTF8Encoding(false)` 可以去掉 BOM。

### 异步序列化支持

传统的 `XmlSerializer.Serialize` 是同步的。在 .NET Core 2.1+ 中，`XmlWriter` 支持异步写入，但 `XmlSerializer` 本身没有直接的 `SerializeAsync` 方法。
**变通方案：**
使用 `Task.Run` 包裹同步方法，或者使用 `LINQ to XML` 的 `SaveAsync` 方法（如果使用的是 `XDocument` 配合 `XmlWriter` 异步）。
对于高并发 Web 应用，避免阻塞 IO 线程很重要。

### 跨平台互操作性

*   **大小写敏感：** XML 元素名是大小写敏感的。确保 C# 属性名与合同一致。
*   **日期格式：** XML Schema 默认日期格式是 `yyyy-MM-ddTHH:mm:ss`。C# `DateTime` 序列化通常符合此标准。但要注意时区问题（Kind=Utc vs Local）。建议统一使用 UTC 时间序列化。
*   **换行符：** Windows 是 `\r\n`，Linux 是 `\n`。XML 标准化了换行符，但在生成文本文件时需注意。

## 第八章：实战案例

### 配置文件读写

很多 .NET 传统应用使用 XML 作为配置文件。

**场景：** 保存用户设置。
```csharp
public class UserSettings
{
    [XmlElement]
    public string Theme { get; set; }
    [XmlElement]
    public int FontSize { get; set; }
}

// 保存
public void SaveSettings(UserSettings settings, string path)
{
    var serializer = new XmlSerializer(typeof(UserSettings));
    using (var fs = new FileStream(path, FileMode.Create))
    {
        serializer.Serialize(fs, settings);
    }
}

// 加载
public UserSettings LoadSettings(string path)
{
    var serializer = new XmlSerializer(typeof(UserSettings));
    using (var fs = new FileStream(path, FileMode.Open))
    {
        return (UserSettings)serializer.Deserialize(fs);
    }
}
```
**注意：** 需要处理文件不存在或损坏的异常。

### 遗留系统 SOAP 接口对接

虽然 SOAP 已过时，但银行、政府接口仍大量使用。
通常这些接口会提供 WSDL 文件。
**工具：** 使用 `wsdl.exe` 或 Visual Studio 的 "Add Service Reference" 自动生成 C# 类。
**手动调整：** 自动生成的类通常包含大量 `[XmlElement]`, `[SoapHeader]` 属性。理解这些属性有助于调试接口调用失败的问题。
**常见问题：** 命名空间不匹配。需要仔细检查生成的代码中的 `Namespace` 属性是否与对方要求一致。

### 大数据量 XML 导出

**场景：** 导出 100 万条记录为 XML。
**错误做法：** 将所有对象放入 `List`，然后 `XmlSerializer.Serialize`。会导致 OOM (Out Of Memory)。
**正确做法：** 使用 `XmlWriter` 流式写入。
```csharp
using (var writer = XmlWriter.Create("export.xml"))
{
    writer.WriteStartElement("Records");
    foreach (var record in database.Query()) // 假设是 enumerable 流式查询
    {
        writer.WriteStartElement("Record");
        writer.WriteElementString("Id", record.Id.ToString());
        writer.WriteElementString("Name", record.Name);
        writer.WriteEndElement();
    }
    writer.WriteEndElement();
}
```
这样内存占用极低，只取决于单条记录的大小。

## 第九章：常见陷阱与调试技巧

### 默认构造函数缺失问题

**错误：** `System.InvalidOperationException: 无法生成临时类。`
**原因：** 被序列化的类没有 public 无参构造函数。
**解决：** 添加 `public MyClass() {}`。即使你有带参构造函数，也必须保留无参的。

### 循环引用问题

**错误：** 栈溢出或序列化异常。
**场景：** A 类包含 B，B 类包含 A。
**解决：** `XmlSerializer` 不支持对象图循环引用。
*   方法 1：打破循环（使用 ID 引用而不是对象引用）。
*   方法 2：使用 `[XmlIgnore]` 忽略其中一方的属性。
*   方法 3：改用 JSON 序列化器（如 Newtonsoft.Json 支持 ReferenceLoopHandling）。

### 特殊字符转义

**现象：** XML 中出现非法字符。
**原因：** 字符串中包含控制字符（如 ASCII 0-31）。
**解决：** 在序列化前清洗字符串。XML 1.0 对字符集有严格限制。
```csharp
// 简单清洗示例
string CleanXmlString(string input)
{
    if (string.IsNullOrEmpty(input)) return input;
    return new string(input.Where(c => 
        c == 0x9 || c == 0xA || c == 0xD || 
        (c >= 0x20 && c <= 0xD7FF) || 
        (c >= 0xE000 && c <= 0xFFFD) || 
        (c >= 0x10000 && c <= 0x10FFFF)
    ).ToArray());
}
```

### 调试工具推荐

1.  **Visual Studio 编辑器：** 打开 .xml 文件会自动格式化，方便查看结构。
2.  **XML 验证器：** 在线工具或 VS 插件，用于验证 XML 是否符合 XSD。
3.  **Fiddler / Wireshark：** 如果 XML 用于网络传输，抓包查看原始 XML 报文是调试接口问题的关键。
4.  **即时窗口：** 在调试时，使用 `serializer.Serialize` 输出到 Debug 窗口查看中间结果。

*   **配置领域：** Java Maven (pom.xml), .NET Project (.csproj) 依然使用 XML。
*   **企业集成：** 金融、医疗、政府行业的标准数据交换格式（HL7, FIPS 等）大量基于 XML。
*   **SVG/ XHTML:** 矢量图形和富文本依然依赖 XML 结构。

作为 C# 开发者，掌握 XML 序列化是处理企业级遗留系统、底层配置文件和复杂文档结构的必备技能。

**附录：常见异常对照**

| 异常类型                          | 可能原因          | 解决方案                      |
| :---------------------------- | :------------ | :------------------------ |
| `InvalidOperationException`   | 类无默认构造函数      | 添加 public 无参构造函数          |
| `InvalidOperationException`   | 权限不足 (AOT 环境) | 预生成序列化程序集 (SGen)          |
| `XmlException`                | XML 格式错误      | 检查输入字符串是否合法               |
| `UnauthorizedAccessException` | 文件路径无权限       | 检查文件读写权限                  |
| `NotSupportedException`       | 尝试序列化不支持的类型   | 移除该属性或实现 IXmlSerializable |
