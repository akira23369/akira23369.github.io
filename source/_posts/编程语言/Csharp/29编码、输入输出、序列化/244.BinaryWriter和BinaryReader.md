## BinaryWriter和BinaryReader
我们已经掌握了“底层字节（FileStream）”和“人类可读的文本（StreamReader/Writer）”。

现在，让我们进入第三种极其重要的情况：**二进制数据读写 —— `BinaryWriter` 和 `BinaryReader`。**

### 核心概念：为什么要用它们？

假设你要把一个整数 `123456` 存入文件：
*   **`StreamWriter` (文本方式)**：会把它转成 6 个字符 `'1', '2', '3', '4', '5', '6'`，占用 6 个字节。别人用记事本打开能看懂。
*   **`BinaryWriter` (二进制方式)**：会直接把它作为 32 位整数存进去（在内存中长啥样，在文件里就长啥样，占用固定的 **4个字节**）。别人用记事本打开会看到一堆乱码。

**适用场景**：游戏存档（Save files）、自定义文件格式、图片/模型解析、网络协议数据包。
**优势**：文件体积小、读写速度极快（不需要进行字符串与数字的互相转换）、保密性稍好（普通人看不懂）。

> **⚠️ 必须知道的前提**：`BinaryWriter` 和 `BinaryReader` **不能直接接受文件路径**作为参数。它们像是一套“工具包”，必须套在另一个底层流（比如 `FileStream` 或 `MemoryStream`）的外面才能工作。

---

### 第一部分：二进制打包器 —— `BinaryWriter`

负责把 C# 的基础数据类型（如 `int`, `float`, `bool`, `string`）直接打包成紧凑的二进制字节写入流中。

#### 常用构造函数

| 构造函数签名                                                           | 详细说明                                                                                                                  |
| :--------------------------------------------------------------- | :-------------------------------------------------------------------------------------------------------------------- |
| `BinaryWriter(Stream output)`                                    | **最常用。** 传入一个打开的底层流（如 `FileStream`）。默认使用 UTF-8 编码来处理内部的字符串。                                                           |
| `BinaryWriter(Stream output, Encoding encoding)`                 | 传入底层流，并明确指定字符串的编码格式。                                                                                                  |
| `BinaryWriter(Stream output, Encoding encoding, bool leaveOpen)` | **进阶用法。** 默认情况下，当你 `Dispose` 关闭 BinaryWriter 时，它会顺便把你传进去的底层流也关掉。如果你设置 `leaveOpen` 为 `true`，则关闭 Writer 时，**底层流仍保持开启**。 |

#### 常用属性

| 属性名 | 类型 | 详细说明 |
| :--- | :--- | :--- |
| `BaseStream` | `Stream` | 获取 `BinaryWriter` 正在操作的底层流。通过它可以获取到 `BaseStream.Position`（当前光标位置）或 `BaseStream.Length`（文件总长）。 |

#### 常用方法

`BinaryWriter` 有几十个 `Write` 方法的重载，专门对应 C# 的各种基础类型：

| 方法签名 | 详细说明 |
| :--- | :--- |
| `Write(int value)` | 写入一个 32 位有符号整数（固定占用 4 字节）。 |
| `Write(double value)` | 写入一个双精度浮点数（固定占用 8 字节）。 |
| `Write(bool value)` | 写入一个布尔值（`true` 为 1，`false` 为 0，占用 1 字节）。 |
| `Write(string value)` | **非常特殊！** 它不仅会把字符串变成字节，还会在字符串前面**自动加上一个长度前缀**，这样读取的时候才知道该读多少个字节。 |
| `Write(byte[] buffer)` | 直接将一个字节数组原封不动地写入。 |
| `Seek(int offset, SeekOrigin origin)`| 直接操作底层流的光标位置（与 FileStream 的 Seek 类似）。 |
| `Flush()` / `Close()` | 刷新缓冲区 / 关闭写入器及底层流。 |

### 第二部分：二进制解析器 —— `BinaryReader`

负责从流中按指定的类型提取出二进制数据，还原成 C# 的基础类型。

#### 常用构造函数
与 `BinaryWriter` 完全对称：
*   `BinaryReader(Stream input)`
*   `BinaryReader(Stream input, Encoding encoding)`
*   `BinaryReader(Stream input, Encoding encoding, bool leaveOpen)`

#### 常用属性

| 属性名 | 类型 | 详细说明 |
| :--- | :--- | :--- |
| `BaseStream` | `Stream` | 获取底层流。**注意：BinaryReader 没有 `EndOfStream` 属性！** 如果想知道是否读到了结尾，通常通过判断 `BaseStream.Position < BaseStream.Length` 来实现。 |

#### 常用方法
你需要明确知道当前光标位置的数据是什么类型，然后调用对应的方法：

| 方法签名                          | 详细说明                                                                                |
| :---------------------------- | :---------------------------------------------------------------------------------- |
| `int ReadInt32()`             | 连续读取 4 个字节，并将其组合解析成一个 `int`。                                                        |
| `double ReadDouble()`         | 连续读取 8 个字节，解析成 `double`。                                                            |
| `bool ReadBoolean()`          | 读取 1 个字节，解析成 `bool`。                                                                |
| `string ReadString()`         | **智能读取！** 它会先读取隐藏的“长度前缀”，然后再根据这个长度精确读取相应的字节数，组合成字符串。                                |
| `byte[] ReadBytes(int count)` | 从流中直接抓取指定数量的 `byte` 数组。                                                             |
| `int PeekChar()`              | 偷看下一个字符是什么（但不移动光标）。如果到了文件末尾会返回 -1。（有时用作结束判断，但处理纯二进制时不太准，更推荐比对 BaseStream 的 Length）。 |

### 第三部分：实战代码示例 —— 制作一个游戏存档系统

假设我们需要保存玩家的状态：名字（`string`），等级（`int`），血量（`double`），是否活着（`bool`）。

#### 示例 1：使用 BinaryWriter 写入存档 (Save)

```csharp
using System;
using System.IO;

class Program
{
    static void Main()
    {
        string savePath = "SaveGame.dat"; // 后缀名随便起，因为不是给人看的文本

        // 玩家数据
        string playerName = "DragonSlayer";
        int level = 99;
        double hp = 1500.50;
        bool isAlive = true;

        // 1. 先创建 FileStream (底层苦力)
        using (FileStream fs = new FileStream(savePath, FileMode.Create, FileAccess.Write))
        // 2. 将 BinaryWriter 套在 FileStream 外面 (高级打包员)
        using (BinaryWriter bw = new BinaryWriter(fs))
        {
            // 开始写入（注意：写入顺序极其重要！）
            bw.Write(playerName); // 写入字符串 (自带长度前缀)
            bw.Write(level);      // 写入 int (4字节)
            bw.Write(hp);         // 写入 double (8字节)
            bw.Write(isAlive);    // 写入 bool (1字节)

            Console.WriteLine("存档保存成功！用记事本打开是乱码哦~");
        }
    }
}
```

#### 示例 2：使用 BinaryReader 读取存档 (Load)

**黄金法则：怎么写进去的，就必须按严格一模一样的顺序读出来！** 如果顺序乱了，或者类型错了（把 int 当 double 读），数据就会彻底错乱（导致游戏出现血量几千万的 Bug）。

```csharp
using System;
using System.IO;

class Program
{
    static void Main()
    {
        string savePath = "SaveGame.dat";

        if (!File.Exists(savePath)) return;

        using (FileStream fs = new FileStream(savePath, FileMode.Open, FileAccess.Read))
        using (BinaryReader br = new BinaryReader(fs))
        {
            // 严格按照写入时的顺序读取： string -> int -> double -> bool
            string playerName = br.ReadString();
            int level = br.ReadInt32();
            double hp = br.ReadDouble();
            bool isAlive = br.ReadBoolean();

            Console.WriteLine("--- 存档加载成功 ---");
            Console.WriteLine($"玩家昵称: {playerName}");
            Console.WriteLine($"等级: {level}");
            Console.WriteLine($"血量: {hp}");
            Console.WriteLine($"存活状态: {isAlive}");
        }
    }
}
```

### 总结与排坑指南

1. **没有 `EndOfStream`**：如果你往文件里写了一大堆 `int`，想要循环读取它们，应该这样写：
   ```csharp
   // 当底层流的当前光标位置 < 底层流的总长度时，说明还有数据
   while (br.BaseStream.Position < br.BaseStream.Length)
   {
       int data = br.ReadInt32();
       // 处理 data...
   }
   ```
2. **读写顺序即协议**：二进制文件里**没有标签也没有分隔符**，数据都是无缝紧贴在一起的。你读入 4 个字节，如果你用 `ReadInt32()`，它就认为这是个整数；如果你用 `ReadSingle()`，它就认为这是个浮点数。所以开发者自己必须非常清楚第几个字节到第几个字节代表什么意思。
3. **版本控制**：如果你给游戏增加了新功能，需要存“魔法值(MP)”，建议在存档的最开头先写一个 `bw.Write(version_number)`（版本号）。读取时先读出版本号，根据版本号决定用旧逻辑还是新逻辑读取后面的数据。
