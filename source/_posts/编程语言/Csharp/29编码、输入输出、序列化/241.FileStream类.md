# System.IO.FileStream简洁版
欢迎来到 C# I/O 的学习！在 C# 中，`System.IO.FileStream` 是处理文件 I/O（输入/输出）最核心、最底层的类之一。

简单来说，**`FileStream` 允许你把文件当作一串“字节流（Byte Stream）”来进行读取、写入、打开和关闭操作。** 它不关心文件是文本、图片还是视频，在它眼里全都是 `byte`。

为了让你清晰掌握，我将按照**核心枚举参数**、**构造函数**、**常用属性**、**常用方法**以及**代码示例**的顺序为你详细拆解。

---

## 一、 实例化前必知的三个重要枚举

在创建 `FileStream` 之前，你必须了解这三个枚举，因为构造函数严重依赖它们来决定“如何”打开文件。

1.  **`FileMode` (文件模式)：决定如何打开或创建文件。**
    *   `CreateNew`：创建新文件。如果文件已存在，则抛出异常。
    *   `Create`：创建新文件。如果文件已存在，会被**覆盖**（清空原内容）。
    *   `Open`：打开现有文件。如果文件不存在，则抛出异常。
    *   `OpenOrCreate`：打开文件，如果不存在则创建它。
    *   `Truncate`：打开现有文件并清空其内容（文件大小变为0字节）。
    *   `Append`：打开文件并将内部光标直接移到文件末尾（常用于写日志），如果文件不存在则创建。**只能配合 `FileAccess.Write` 使用。**

2.  **`FileAccess` (访问权限)：决定你打开文件后能干什么。**
    *   `Read`：只读。
    *   `Write`：只写。
    *   `ReadWrite`：可读可写。

3.  **`FileShare` (文件共享)：决定当你打开这个文件时，其他程序（或其他线程）能不能同时访问这个文件。**
    *   `None`：独占文件。在你关闭文件前，任何人都打不开它。
    *   `Read`：允许别人以只读方式打开它。
    *   `Write`：允许别人以只写方式打开它。
    *   `ReadWrite`：允许别人读写。

## 二、 常用构造函数

`FileStream` 有非常多的重载，以下是日常开发中最常用的三种：

| 构造函数签名                                                                       | 详细说明                                                                                               |
| :--------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------- |
| `FileStream(string path, FileMode mode)`                                     | 最简单的构造。以指定的**模式**打开路径下的文件。默认给的是 `FileAccess.ReadWrite` (除了 Append 模式默认为 Write) 和 `FileShare.Read`。 |
| `FileStream(string path, FileMode mode, FileAccess access)`                  | **最常用**。明确指定打开的**模式**（如打开还是创建）以及**权限**（读还是写）。默认共享模式为 `FileShare.Read`。                             |
| `FileStream(string path, FileMode mode, FileAccess access, FileShare share)` | 最严谨的构造。同时指定路径、模式、权限，以及**是否允许其他程序共享访问**。用于高并发或日志文件读取时非常有用。                                          |

## 三、 常用属性

当你实例化了一个 `FileStream` 对象（假设叫 `fs`），你可以通过它的属性了解文件的状态。

| 属性名        | 类型       | 详细说明                                                                |
| :--------- | :------- | :------------------------------------------------------------------ |
| `CanRead`  | `bool`   | 获取一个值，指示当前流是否支持读取（基于你传入的 `FileAccess`）。                             |
| `CanWrite` | `bool`   | 获取一个值，指示当前流是否支持写入。                                                  |
| `CanSeek`  | `bool`   | 获取一个值，指示当前流是否支持查找（即能否移动内部光标位置）。对于本地文件通常为 `true`。                    |
| `Length`   | `long`   | 获取整个文件的长度（**总字节数**）。                                                |
| `Position` | `long`   | **极度重要！** 获取或设置当前流中的**光标位置**（当前读/写到了第几个字节）。每次 Read/Write 后，此值会自动增加。 |
| `Name`     | `string` | 获取传递给构造函数的绝对路径名。                                                    |

## 四、 常用方法

`FileStream` 的方法主要围绕字节数组 (`byte[]`) 展开。

### 同步方法 (阻塞当前线程)

| 方法签名                                               | 详细说明                                                                                                                                                          |
| :------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `int Read(byte[] buffer, int offset, int count)`   | **读取数据。**<br>- `buffer`: 把读到的字节存入这个数组。<br>- `offset`: 从数组的第几个位置开始存（通常为 0）。<br>- `count`: 打算最多读取多少个字节。<br>- **返回值**: 实际读到的字节数（如果返回 0，说明读到文件末尾了）。               |
| `void Write(byte[] buffer, int offset, int count)` | **写入数据。**<br>- `buffer`: 包含要写入的数据的字节数组。<br>- `offset`: 从数组的哪个位置开始取数据。<br>- `count`: 打算写入多少个字节。                                                                |
| `long Seek(long offset, SeekOrigin origin)`        | **移动内部光标位置。**<br>- `offset`: 偏移量（字节）。可以为正或负。<br>- `origin`: 基准点（`SeekOrigin.Begin` 起点, `SeekOrigin.Current` 当前位置, `SeekOrigin.End` 终点）。<br>- **返回值**: 新的光标位置。 |
| `void Flush()`                                     | **清空缓冲区。** 将系统内存缓冲区中的数据强制立刻写入物理磁盘。                                                                                                                            |
| `void Close()` / `Dispose()`                       | **关闭流并释放资源。** 极度重要！操作完文件必须调用，或者使用 `using` 语句自动调用，否则文件会被一直锁死（占用）。                                                                                              |

### 异步方法 (现代 C# 推荐使用，不阻塞线程)
*   `Task<int> ReadAsync(byte[] buffer, int offset, int count)`
*   `Task WriteAsync(byte[] buffer, int offset, int count)`
*(参数含义与同步方法完全一致，但返回 Task，需配合 `await` 使用，适合处理大文件以防界面卡死。)*

## 五、 实战代码示例

### 示例 1：使用 FileStream 写入文件
因为 `FileStream` 只认 `byte`，我们要把文字转换成 `byte[]`。**请注意 `using` 关键字的使用，它会自动帮你调用 `Dispose()` 关闭文件。**

```csharp
using System;
using System.IO;
using System.Text;

class Program
{
    static void Main()
    {
        string filePath = "test.txt";
        string content = "Hello, FileStream! 你好，世界！";

        // 将字符串转换为字节数组 (使用 UTF8 编码)
        byte[] data = Encoding.UTF8.GetBytes(content);

        // 实例化 FileStream: 创建新文件或覆盖旧文件，只写权限，不共享
        using (FileStream fs = new FileStream(filePath, FileMode.Create, FileAccess.Write, FileShare.None))
        {
            // 参数: 写入的数据源数组，从索引0开始取，写入总长度
            fs.Write(data, 0, data.Length);
            
            Console.WriteLine($"文件写入成功！文件大小: {fs.Length} 字节");
        } // 离开 using 块时，fs.Dispose() 会被自动调用，文件被释放
    }
}
```

### 示例 2：使用 FileStream 读取文件

```csharp
using System;
using System.IO;
using System.Text;

class Program
{
    static void Main()
    {
        string filePath = "test.txt";

        // 实例化 FileStream: 打开已有文件，只读权限
        using (FileStream fs = new FileStream(filePath, FileMode.Open, FileAccess.Read))
        {
            // 创建一个和文件一样大小的字节数组来接收数据
            byte[] buffer = new byte[fs.Length];

            // 开始读取
            int bytesRead = fs.Read(buffer, 0, buffer.Length);

            // 将读取到的字节数组转回字符串
            string result = Encoding.UTF8.GetString(buffer, 0, bytesRead);

            Console.WriteLine("读取到的内容是：");
            Console.WriteLine(result);
        }
    }
}
```

## 六、 学习 FileStream 的核心建议
1. **它是底层设施**：在实际开发中，如果我们只处理**纯文本**，通常会用 `StreamReader` / `StreamWriter` 或者 `File.ReadAllText()`，因为它们在内部包装了 `FileStream`，帮我们处理了字符到字节的转换，更方便。
2. **何时必须用 FileStream**：处理非文本文件（如复制图片、解析 MP4 文件头），或者处理几个 G 的超大文件（不能一次性读进内存，需要用一个小的 `byte[]` 循环分块读取）。
3. **永远记住释放**：操作完文件一定要 `Dispose` 或放进 `using` 块中，这是新手最常踩的“文件正被另一个进程使用”异常的坑。

# System.IO.FileStream类 详细版

由于 `FileStream` 是 C# I/O 体系中最底层、最核心、也是最为复杂的一个类，理解它不仅仅是理解几个 API，更是理解**操作系统文件句柄、内存缓冲机制、多线程并发控制以及异步 I/O (IOCP)** 的过程。


## 什么是 Stream？

在学习 `File.ReadAllText` 时，我们是把文件当作一个 **“整体”**。就像用一个大水桶去井里打水，一次性把一桶水（整个文件）提上来（加载到内存）。如果水桶比井里的水小（内存够大），这没问题；但如果井里有 10 吨水（一个 10GB 的日志文件），你的水桶（内存）就会瞬间被撑爆，抛出 `OutOfMemoryException`。

**`Stream`（流）的思想不同，它是“管道”。**
`FileStream` 就像是在内存和硬盘之间接了一根自来水管。水（字节 Byte）源源不断地从硬盘流向内存，或者从内存流向硬盘。
*   你可以控制水管的**阀门大小**（缓冲区 Buffer）。
*   你可以随时**暂停**水流。
*   你不需要一个 10GB 的大桶，你只需要一个 4KB 的小碗（`byte[]`），接满一碗水，处理掉，再接下一碗。**因此，无论文件有多大，`FileStream` 占用的内存都可以维持在极低且恒定的水平。**

## 拆解构造函数

`FileStream` 的构造函数极其强大，最多可以接收 6 个参数。很多初学者因为没有传对参数，导致“文件被占用”、“内容被清空”、“权限不足”等各种奇怪的报错。

让我们拆解这个最复杂的构造函数：
```csharp
public FileStream(
    string path,           // 1. 路径
    FileMode mode,         // 2. 打开模式（怎么建水管）
    FileAccess access,     // 3. 访问权限（水往哪流）
    FileShare share,       // 4. 共享权限（别人能不能碰这个水龙头）
    int bufferSize,        // 5. 缓冲区大小（水池大小）
    FileOptions options    // 6. 高级选项（底层黑科技）
)
```

### `FileMode` (文件模式) —— 决定了文件的生死存亡
这个枚举决定了当目标文件存在或不存在时，操作系统该如何应对。

| 枚举值                | 文件存在时           | 文件不存在时     | 内部指针初始位置 | 适用场景              |
| :----------------- | :-------------- | :--------- | :------- | :---------------- |
| **`Create`**       | 💥 **清空/覆盖**原文件 | 创建新文件      | 0（开头）    | 重新生成配置文件、保存新下载的文件 |
| **`CreateNew`**    | ❌ **抛出异常**      | 创建新文件      | 0        | 严格要求不能覆盖别人的文件（安全） |
| **`Open`**         | 正常打开            | ❌ **抛出异常** | 0        | 读取现有配置、打开现有文档     |
| **`OpenOrCreate`** | 正常打开            | 创建新文件      | 0        | 写本地缓存（有就读，没有就建）   |
| **`Append`**       | 正常打开            | 创建新文件      | **文件末尾** | **极其常用的写日志模式**    |
| **`Truncate`**     | 💥 **清空/覆盖**原文件 | ❌ **抛出异常** | 0        | 比较罕见，重置现有文件但禁止新建  |

### `FileAccess` (访问权限) —— 决定流的方向
*   **`Read`**：只能读。如果你试图调用 `Write()`，会抛出异常。
*   **`Write`**：只能写。如果你试图调用 `Read()`，会抛出异常。
*   **`ReadWrite`**：又读又写。

> **最佳实践**：遵循“最小权限原则”。如果你只是读文件，务必只给 `FileAccess.Read`。这在处理只读属性的文件时，或者在权限受限的服务器上非常关键。

### `FileShare` (共享权限) —— 解决“文件正由另一进程使用”的罪魁祸首
当你用 `FileStream` 打开一个文件时，操作系统会给这个文件加锁。如果此时别的程序也想打开这个文件，操作系统就会去检查你设置的 `FileShare`。

*   **`None`**：(独占) 我打开期间，天王老子来了也不能碰这个文件！（默认行为，极容易引发被占用报错）。
*   **`Read`**：允许别人用**只读**方式打开。*(例如：你的程序正在生成一份报告，你允许用户同时用记事本打开看，但不能改)*。
*   **`Write`**：允许别人写入。*(极为罕见，容易导致数据错乱)*。
*   **`ReadWrite`**：完全开放，谁都可以来读写。*(用于高级的多进程并发控制场景)*。
*   **`Delete`**：允许别人在我读写期间把文件删掉或重命名。

> **避坑指南**：如果你在写日志，希望用户能随时用记事本或者 `Tail` 命令查看日志，你**必须**这样实例化：
> `new FileStream("log.txt", FileMode.Append, FileAccess.Write, FileShare.Read);`

### `bufferSize` (缓冲区大小) —— 性能调节器
硬盘的读写速度远远低于内存（甚至相差几千倍）。如果每读一个字节都要去敲一下硬盘，硬盘会崩溃。
因此 `FileStream` 在内存中建立了一个“中转站”（Buffer）。
*   默认值是 **4096 字节 (4KB)**。
*   当你调用 `Read` 时，它会一次性从硬盘吸入 4KB 到内存，然后把你需要的部分给你。
*   当你在进行大量连续的磁盘顺序读写时，把 Buffer 设置为 **65536 (64KB)** 或 **1048576 (1MB)**，能显著提升 I/O 吞吐量！

### `FileOptions` (高级选项) —— 操作系统的黑魔法
*   **`None`**：默认常规操作。
*   **`Asynchronous`**：**极为重要**！开启**真正的**操作系统级异步 I/O (IOCP)。如果你打算使用 `ReadAsync` 和 `WriteAsync`，必须在构造函数开启此选项，否则你的异步本质上还是在后台线程跑同步，并没有真正释放线程池！
*   **`DeleteOnClose`**：临时文件神器！当 `FileStream` 调用 `Close/Dispose` 时，**操作系统会自动把这个文件从硬盘上彻底删掉**。极其适合用来做下载缓存、解压临时目录。
*   **`SequentialScan`**：告诉操作系统：“我打算从头到尾顺序读这个文件”。操作系统听懂后，会在后台开启**预读机制 (Prefetch)**，极大提升大文件的顺序读取速度。
*   **`RandomAccess`**：告诉操作系统：“我一会读开头，一会读结尾”。操作系统会关闭预读，优化磁头寻道。
*   **`WriteThrough`**：绕过操作系统的缓存，直接将数据硬写入磁盘的物理盘片。速度极慢，但断电绝不丢失数据。（金融级安全要求使用）。

## 核心游标与状态（属性）

`FileStream` 内部维护着一个 **“游标（指针）”**，就像录音机里的磁头。

*   **`Length`** (`long`)：文件当前的总字节数。
*   **`Position`** (`long`)：当前磁头所在的位置（从 0 开始计数）。**每次你调用 Read 或 Write，Position 都会自动向后移动。**
*   **`CanRead` / `CanWrite` / `CanSeek`** (`bool`)：判断当前流是否支持读/写/移动指针。比如你如果是 `FileAccess.Read` 打开的，`CanWrite` 就是 `false`。

**一个小陷阱：**
```csharp
using FileStream fs = new FileStream("test.txt", FileMode.Create);
byte[] data = Encoding.UTF8.GetBytes("Hello");
fs.Write(data, 0, data.Length); 
// 此时 fs.Position 已经变成了 5

// 如果你现在紧接着去 Read，你会什么都读不到！
// 因为指针已经在末尾了，必须手动把指针拨回开头：
fs.Position = 0; 
```

## 基础操作（同步读写）

注意：`FileStream` **不认识字符串，不认识整数，它只认识 `byte` (字节)**。任何数据在进入 `FileStream` 之前，必须先序列化为 `byte[]`。

### 经典的分块读取模式
这是所有高级 I/O 操作的母版代码，也是**应对几个G的大文件而不撑爆内存的终极写法**。

```csharp
public void ReadHugeFile(string path)
{
    // 使用 using 确保异常时也能释放句柄
    using FileStream fs = new FileStream(path, FileMode.Open, FileAccess.Read);
    
    // 准备一个 4KB 的小碗 (缓冲区)
    byte[] buffer = new byte[4096]; 
    int bytesRead; // 记录每次实际盛到了多少水

    // Read 方法的含义：往 buffer 里倒水，从第 0 个位置开始倒，最多倒 4096 滴。
    // 它会返回【实际倒了多少滴】。如果返回 0，说明井里没水了（读到文件末尾了）。
    while ((bytesRead = fs.Read(buffer, 0, buffer.Length)) > 0)
    {
        // 🚨 极其容易犯错的警告：
        // 在最后一次循环时，可能文件只剩下 10 个字节，
        // 此时 bytesRead = 10，但 buffer 的长度依然是 4096！
        // buffer 中后面的 4086 个字节是【上一次循环残留的旧数据/脏数据】！
        // 
        // 所以，处理数据时，绝对不能用 buffer.Length，
        // 必须严格限制处理长度为 bytesRead！
        
        // （假设文件是 UTF-8 文本）将本次真正读取到的字节转为字符串
        string chunkText = Encoding.UTF8.GetString(buffer, 0, bytesRead);
        
        Console.Write(chunkText); // 逐步输出
    }
}
```

### 写入操作
写入相对简单，把准备好的字节数组推入流即可。

```csharp
using FileStream fs = new FileStream("output.dat", FileMode.Create, FileAccess.Write);

string myText = "C# FileStream 万字长文";
byte[] textBytes = Encoding.UTF8.GetBytes(myText);

// 参数：数据源，从数据源的哪个索引开始拿，拿多少个字节
fs.Write(textBytes, 0, textBytes.Length);
```

## Seek 与文件截断

如果你要处理包含固定格式的二进制文件（如 BMP 图片、MP4 视频），你通常不需要从头读到尾，而是要 **“跳跃”** 到特定位置提取特定的数据块。

### `Seek(long offset, SeekOrigin origin)` 方法
*   `SeekOrigin.Begin`：以**文件开头**为基准起跳。
*   `SeekOrigin.Current`：以**当前游标位置**为基准起跳（可前可后）。
*   `SeekOrigin.End`：以**文件末尾**为基准起跳。

**实战：读取文件的最后 100 个字节**
```csharp
using FileStream fs = new FileStream("huge_data.bin", FileMode.Open);

// 把磁头定位到：从末尾 (End) 往回退 (-100) 个字节的位置
fs.Seek(-100, SeekOrigin.End);

byte[] lastBytes = new byte[100];
fs.Read(lastBytes, 0, 100);
```

### `SetLength(long value)` 方法 —— 神奇的文件截断
如果你想把一个 10MB 的文件瞬间变成 5MB（丢弃后半部分），或者把一个 1KB 的文件瞬间占位到 1GB（里面填满 0 空字节），可以用这个方法。

```csharp
using FileStream fs = new FileStream("test.dat", FileMode.OpenOrCreate);
// 将文件大小强制设置为 1024 字节。
// 如果原文件大，末尾会被截断删除；如果原文件小，系统会用 \0 (空字节) 填充补齐。
fs.SetLength(1024); 
```
*场景：很多下载软件（如迅雷）在下载开始时，会瞬间在硬盘生成一个和目标文件一样大的全 0 空文件，用的就是底层类似 `SetLength` 的机制来提前霸占磁盘空间，防止下载到 99% 时硬盘满了。*

## 释放与刷入（资源管理的生死线）

### `Flush()` 与 `Flush(true)` 的区别
前面提到了 Buffer（缓冲区）。当你调用 `fs.Write()` 时，数据其实并没有立刻写进硬盘，而是停留在了内存的 Buffer 里。
只有当 Buffer 满了，或者你调用 `Close/Dispose` 时，系统才会把数据写进硬盘。

*   **`fs.Flush()`**：命令 `FileStream` 把自己的 Buffer 清空，将数据交给**操作系统 (OS) 的文件系统缓存**。
*   **`fs.Flush(true)`**：这是一个极其强硬的命令。它不仅清空自身的 Buffer，还强制要求操作系统绕过系统的缓存，将数据立刻、马上写入**硬盘的物理磁盘片/闪存颗粒**上。（性能很差，但即使下一秒机房停电，数据也绝对不会丢）。

### `Close()` 与 `Dispose()`
在 `FileStream` 中，调用 `Close()` 实际上内部就是在调用 `Dispose()`。它们的作用是：
1.  调用 `Flush()` 将残留数据刷入硬盘。
2.  释放**操作系统级别的文件句柄 (File Handle)**。如果不释放，这个文件将永远处于“被占用”状态。

> **绝对铁律：永远使用 `using` 语句块或 `using` 变量声明。**
```csharp
// 现代 C# 的写法 (C# 8.0+)
public void WriteLog()
{
    // 方法执行完毕（哪怕中间抛出严重异常）
    // 变量离开作用域时，会自动且绝对安全地调用 fs.Dispose()
    using FileStream fs = new FileStream("log.txt", FileMode.Append);
    fs.Write(new byte[] { 65 });
}
```

## 高性能与现代 C#（异步与 Span）

在服务器端开发（如 ASP.NET Core）中，如果有 1000 个用户同时下载文件，如果你使用同步的 `fs.Read`，会导致 1000 个服务器线程被卡死在等待硬盘转圈上，瞬间耗尽线程池（Thread Starvation）。

### 开启真正的 IOCP 异步
记住前面讲的，一定要在构造函数传入 `FileOptions.Asynchronous`，然后再调用 `ReadAsync` 和 `WriteAsync`。

```csharp
// 必须带有 Asynchronous 标志！
using FileStream fs = new FileStream(
    "large_video.mp4", 
    FileMode.Open, 
    FileAccess.Read, 
    FileShare.Read, 
    4096, 
    FileOptions.Asynchronous); // <--- 关键点！

byte[] buffer = new byte[4096];
// 异步读取：在等待硬盘读取数据的期间，当前线程会被释放回线程池，去服务其他用户！
int bytesRead = await fs.ReadAsync(buffer, 0, buffer.Length);
```

### C# 现代黑科技：`Span<byte>` 与零内存分配
在过去，我们要么不断 `new byte[]`，要么预先申请一个大数组。
C# 7.2 引入了 `Span<T>` 和 `Memory<T>`，极大地提升了 `FileStream` 在高性能场景下的表现。

使用 `ValueTask` + `Memory<byte>` 进行极限性能读取：

```csharp
public async Task HighPerfReadAsync(string path)
{
    using FileStream fs = new FileStream(path, FileMode.Open, FileAccess.Read, FileShare.Read, 65536, FileOptions.Asynchronous);
    
    // 申请一块内存，整个生命周期只申请一次
    byte[] buffer = new byte[65536]; 
    
    // 使用 Memory 包装数组
    Memory<byte> memoryBuffer = new Memory<byte>(buffer);

    int bytesRead;
    // 现代 API：直接传入 Memory，返回 ValueTask。
    // 这比传统的 Task 避免了对象分配，极大减轻了 GC (垃圾回收器) 的压力
    while ((bytesRead = await fs.ReadAsync(memoryBuffer)) > 0)
    {
        // 利用 Span 进行切片处理，绝对安全且零额外内存分配
        ReadOnlySpan<byte> actualData = memoryBuffer.Span.Slice(0, bytesRead);
        
        // ...处理 actualData (例如计算 MD5, 解析二进制协议等)...
    }
}
```

## 高阶实战场景与笔试题解析

为了将前面的理论融会贯通，这里提供两个在企业级开发中极具价值的实战代码。

### 实战一：完美的大文件拷贝（带有进度条和取消功能）
如果让你自己写一个将 D 盘的 10GB 电影拷贝到 E 盘的方法，要求低内存、不卡界面、能随时点击取消、还能实时汇报进度。

```csharp
/// <summary>
/// 高性能且带进度汇报的异步文件拷贝
/// </summary>
public async Task CopyFileWithProgressAsync(string sourcePath, string destPath, IProgress<int> progress, CancellationToken cancellationToken)
{
    // 源文件：异步读取、允许别人同时读、开启顺序预读优化
    using FileStream sourceStream = new FileStream(sourcePath, FileMode.Open, FileAccess.Read, FileShare.Read, 81920, FileOptions.Asynchronous | FileOptions.SequentialScan);
    
    // 目标文件：异步写入
    using FileStream destStream = new FileStream(destPath, FileMode.Create, FileAccess.Write, FileShare.None, 81920, FileOptions.Asynchronous);

    long totalBytes = sourceStream.Length;
    long totalCopied = 0;
    
    // 80KB 的缓冲区 (这是一个在现代系统上拷贝文件的甜点容量)
    byte[] buffer = new byte[81920];
    int bytesRead;

    // 经典的分块读取架构，加上了取消令牌的检查
    while ((bytesRead = await sourceStream.ReadAsync(buffer, 0, buffer.Length, cancellationToken)) > 0)
    {
        // 写入目标流
        await destStream.WriteAsync(buffer, 0, bytesRead, cancellationToken);
        
        // 累加进度
        totalCopied += bytesRead;
        
        // 计算百分比并报告给 UI 线程
        if (totalBytes > 0)
        {
            int percentage = (int)((double)totalCopied / totalBytes * 100);
            progress?.Report(percentage);
        }
    }
    // using 结束时会自动调用 Flush 和 Dispose 关流
}
```
*注：如果你不需要汇报进度，直接调用现代 API：`await sourceStream.CopyToAsync(destStream);` 即可，底层实现与此类似。*

### 实战二：高并发下的多线程安全日志写入 (避免独占报错)
在多线程程序中，如果多个线程同时使用 `new FileStream` 往同一个日志文件写数据，肯定会抛出“文件被占用”的异常。
解决方式有两派：
1. **进程内**：使用 `lock` 语句，排队写入同一个全局静态的 `FileStream` 对象。
2. **进程间**：利用 `FileShare.ReadWrite` 配合文件锁定机制 (`fs.Lock()`)。

这里展示最轻量级的**进程内单例流锁定写法**：

```csharp
public class SafeLogger : IDisposable
{
    private readonly FileStream _fs;
    private readonly object _lockObj = new object();

    public SafeLogger(string logPath)
    {
        // 提前打开一根长期存在的水管，并允许其他程序只读查看
        _fs = new FileStream(logPath, FileMode.Append, FileAccess.Write, FileShare.Read);
    }

    public void Log(string message)
    {
        byte[] data = Encoding.UTF8.GetBytes($"[{DateTime.Now:HH:mm:ss}] {message}\n");
        
        // 无论多少个线程同时调用 Log 方法，到了这里都必须乖乖排队，保证日志不交叉重叠
        lock (_lockObj)
        {
            _fs.Write(data, 0, data.Length);
            _fs.Flush(); // 写入后立即刷入硬盘，防止程序突然崩溃导致最后几条日志丢失
        }
    }

    public void Dispose()
    {
        _fs?.Dispose();
    }
}
```

## 总结

如果你能耐心看到这里，你对 C# `FileStream` 的理解已经超越了至少 80% 的普通开发者。

请把这几句话当作 I/O 编程的“武林秘籍”印在脑子里：
1.  **处理大文件，永远用 `Stream`。**
2.  **创建流时，搞清楚你的 `FileMode` 是不是会意外删掉原来的数据。**
3.  **遇到被占用，优先检查你的 `FileShare` 有没有设置为允许共享。**
4.  **循环 `Read` 后，截取真实数据的长度绝对是 `bytesRead`，千万别用 `buffer.Length`！**
5.  **在 Web/后台服务开发中，开启 `FileOptions.Asynchronous` 并使用 `ReadAsync/WriteAsync` 才是真正的非阻塞王道。**
6.  **`using` 语句是流的护身符，不写它，你的程序早晚会内存泄漏或文件死锁。**
