# 一、JSON 与序列化的基本概念

## 什么是 JSON
**JSON (JavaScript Object Notation)** 是一种轻量级的数据交换格式，基于 **键值对 (Key-Value)** 的方式来表示数据。它广泛用于后端与前端通信、配置文件、数据存储等场景。结构清晰、语法简单、可读性强。

例如：

```json
{
    "name": "张三",
    "age": 25,
    "isStudent": false,
    "courses": ["数学", "物理", "化学"],
    "address": {
        "city": "北京",
        "zipCode": "100000"
    },
    "score": null
}
```

## JSON 的数据类型
JSON 支持的数据类型包括：

| 类型 | 示例 | 对应 C# 类型 |
|------|------|-------------|
| 字符串 | `"hello"` | `string` |
| 数值 | `123.45` | `int`, `double`, `decimal` |
| 布尔 | `true` / `false` | `bool` |
| 数组 | `["A", "B", "C"]` | `List<T>`, `T[]` |
| 对象 | `{"key": "value"}` | `class`, `struct`, `Dictionary<string, object>` |
| null | `null` | `null` |

## 什么是序列化与反序列化

- **序列化 (Serialization)：**  
  将 C# 对象转换为 JSON 字符串或字节流，用于存储或传输。

- **反序列化 (Deserialization)：**  
  将 JSON 字符串还原为 C# 对象，用于程序内部使用。

例如：

```csharp
// 序列化：对象 → JSON
string json = JsonSerializer.Serialize(person);

// 反序列化：JSON → 对象
Person person2 = JsonSerializer.Deserialize<Person>(json);
```

# 二、C# 中常用的 JSON 序列化库对比

目前 C# 有多个 JSON 序列化库：

| 名称 | 所属 | 特点 | 适用场景 |
|------|------|--------|-----------|
| `System.Text.Json` | .NET 官方库 | 性能高、轻量但功能不如 Newtonsoft | .NET Core 3.0+ 推荐 |
| `Newtonsoft.Json` | 第三方（Json.NET） | 功能强大、兼容性好 | 传统项目、复杂场景 |
| `DataContractJsonSerializer` | System.Runtime.Serialization | 较老，功能有限 | 兼容旧系统 |
| `JsonNode`, `JsonDocument` | `System.Text.Json` 系列 | 提供 DOM 风格操作 | 动态 JSON 操作 |

我们之后重点讲解前两者：  
**System.Text.Json（官方库）**  
**Newtonsoft.Json（历史上最流行的库）**

# 三、System.Text.Json —— 官方 JSON 序列化库详解

## 基本使用

### （1）命名空间
首先确保引用：

```csharp
using System.Text.Json;
```

### （2）简单序列化与反序列化

```csharp
var person = new Person { Name = "张三", Age = 28 };
string json = JsonSerializer.Serialize(person);
Console.WriteLine(json); // 输出：{"Name":"张三","Age":28}

Person p2 = JsonSerializer.Deserialize<Person>(json);
Console.WriteLine(p2.Name); // 张三
```

### （3）JSON 字符串格式化输出（Pretty Print）

```csharp
var options = new JsonSerializerOptions { WriteIndented = true };
string jsonFormatted = JsonSerializer.Serialize(person, options);
Console.WriteLine(jsonFormatted);
```

输出：

```json
{
  "Name": "张三",
  "Age": 28
}
```


```cs
using System.Text.Json;

// 定义模型
public class Product
{
    public int Id { get; set; }
    public string Name { get; set; }
    public decimal Price { get; set; }
    public DateTime CreateTime { get; set; }
}

// ========== 序列化 ==========
Product product = new Product
{
    Id = 1,
    Name = "笔记本电脑",
    Price = 5999.99m,
    CreateTime = DateTime.Now
};

string json = JsonSerializer.Serialize(product);
Console.WriteLine(json);
// 输出: {"Id":1,"Name":"笔记本电脑","Price":5999.99,"CreateTime":"2026-04-10T09:04:00"}

// ========== 反序列化 ==========
string jsonString = "{\"Id\":1,\"Name\":\"手机\",\"Price\":2999.00}";
Product parsed = JsonSerializer.Deserialize<Product>(jsonString);
```

## 常用配置项与序列化选项

`JsonSerializerOptions` 提供丰富的控制能力：

| 属性                            | 功能                 |
| ----------------------------- | ------------------ |
| `WriteIndented`               | 是否格式化输出            |
| `PropertyNamingPolicy`        | 控制属性命名（如驼峰）        |
| `Encoder`                     | 控制字符编码，例如防止中文被转义   |
| `DefaultIgnoreCondition`      | 忽略空值或默认值           |
| `PropertyNameCaseInsensitive` | 反序列化时忽略大小写         |
| `Converters`                  | 添加自定义类型转换器         |
| `IgnoreReadOnlyProperties`    | 忽略只读属性             |
| `AllowTrailingCommas`         | 允许尾随逗号（解析时更宽松）     |
| `NumberHandling`              | 数字处理，允许 "123" 转数字  |
| `MaxDepth`                    | 最大深度（防止循环引用导致的栈溢出） |

示例：

```csharp
var options = new JsonSerializerOptions
{
    // 格式化输出（带缩进，便于阅读）
    WriteIndented = true,
    
    // 属性名大小写策略
    PropertyNamingPolicy = JsonNamingPolicy.CamelCase,  // 驼峰命名：userName
    // 其他选项：SnakeCaseLower（下划线：user_name）、KebabCaseLower（短横线：user-name）
    
    // 忽略 null 值（不序列化为 null 的属性）
    DefaultIgnoreCondition = JsonIgnoreCondition.WhenWritingNull,
    
    // 忽略只读属性
    IgnoreReadOnlyProperties = false,
    
    // 允许尾随逗号（解析时更宽松）
    AllowTrailingCommas = true,
    
    // 数字处理
    NumberHandling = JsonNumberHandling.AllowReadingFromString, // 允许 "123" 转数字
    
    // 最大深度（防止循环引用导致的栈溢出）
    MaxDepth = 64
};

string prettyJson = JsonSerializer.Serialize(product, options);
```

## 常用特性

### `[JsonPropertyName]`修改json键名
用于指定 JSON 中的属性名。

```csharp
public class Person
{
    [JsonPropertyName("full_name")]
    public string Name { get; set; }

    public int Age { get; set; }
}
```

序列化结果：

```json
{"full_name":"张三","Age":28}
```

### `[JsonIgnore]`屏蔽属性
在序列化或反序列化时忽略某个属性。
适用于敏感数据（如密码）或程序内部使用的临时状态变量。

```csharp
public class User
{
    public string Name { get; set; }

    [JsonIgnore]
    public string Password { get; set; }
}
```

结果中不会包含 `Password`。

### `[JsonInclude]`包含非标准成员
强制包含字段（Fields）或非公开属性。
默认情况下，`System.Text.Json` 只序列化 **公共属性 (Public Properties)**。如果你想序列化一个公共字段或私有属性，就需要它。
```cs
public class Weather
{
    [JsonInclude]
    public string note; // 默认情况下字段是不被序列化的，加上此特性后会被包含
}
```

### `[JsonConstructor]`指定构造函数
指定反序列化时使用的构造函数。
当你的类有多个构造函数，或者你使用了**不可变模型（Immutable models）** 时，这个特性告诉转换器该调用哪一个。
```cs
public class Product
{
    public string Name { get; }
    public decimal Price { get; }

    [JsonConstructor]
    public Product(string name, decimal price)
    {
        Name = name;
        Price = price;
    }
}
```


### `[JsonNumberHandling]`宽容数字/字符串转换
处理数字与字符串之间的强制转换。
有时候前端传回来的数字是字符串格式（如 `"42"`），或者你需要把 NaN 序列化，这个特性非常管用。
```cs
public class Measurement
{
    // 允许从 JSON 字符串读取数字，同时也允许将数字写为字符串
    [JsonNumberHandling(JsonNumberHandling.AllowReadingFromString | JsonNumberHandling.WriteAsString)]
    public int Value { get; set; }
}

// 输入可以是 {"Value": "100"}，输出将是 {"Value": "100"}
```


### `[JsonPropertyOrder]`控制字段顺序
指定属性在生成的 JSON 中的先后顺序。 
默认顺序通常是属性定义的顺序，使用此特性可以显式排序（数值越小越靠前）。

```cs
public class OrderedData
{
    [JsonPropertyOrder(2)]
    public string Last { get; set; }

    [JsonPropertyOrder(1)]
    public string First { get; set; }
}

// 序列化结果: {"First": "...", "Last": "..."}
```

### `[JsonConverter]`
使用自定义转换器处理复杂类型。 
当你需要特殊处理某种格式（例如日期格式 `yyyy-MM-dd` 或特殊的枚举映射）时使用。
```cs
public class Event
{
    public string Name { get; set; }

    [JsonConverter(typeof(JsonStringEnumConverter))]
    public Status Category { get; set; } // 将枚举序列化为字符串 "Active" 而不是数字 1
}

public enum Status { Active, Inactive }
```

## 自定义类型转换器（Converter）

### 核心概念
在C#中，JSON序列化和反序列化是我们与外部系统（如Web API、前端、配置文件）交互时的家常便饭。虽然内置的序列化工具能处理大部分标准情况，但当遇到**非标准数据格式**、**遗留系统API**或**复杂的多态类型**时，默认行为就力不从心了。

这时，我们就需要编写**自定义类型转换器（Custom Converter）**。

自定义 Converter 需要继承 `JsonConverter<T>` 抽象类，重写三个关键方法：
```cs
public class MyCustomConverter : JsonConverter<MyType>
{
    // 1. 读取 JSON 转换为对象
    public override MyType Read(
        ref Utf8JsonReader reader,           // JSON 读取器，指向当前要解析的位置
        Type typeToConvert,                  // 目标类型（通常是 typeof(MyType)）
        JsonSerializerOptions options)       // 序列化选项配置
    {
        // 实现反序列化逻辑
    }

    // 2. 将对象写入 JSON
    public override void Write(
        Utf8JsonWriter writer,               // JSON 写入器，用于输出
        MyType value,                        // 要序列化的对象
        JsonSerializerOptions options)       // 序列化选项配置
    {
        // 实现序列化逻辑
    }
}
```
### 完整实战示例
#### 示例 1：DateTime 自定义格式（yyyy-MM-dd）
```cs
public class DateTimeYmdConverter : JsonConverter<DateTime>
{
    private const string Format = "yyyy-MM-dd";

    public override DateTime Read(ref Utf8JsonReader reader, Type typeToConvert, JsonSerializerOptions options)
    {
        // 读取字符串值
        string? dateString = reader.GetString();
        
        if (DateTime.TryParseExact(
            dateString, 
            Format, 
            CultureInfo.InvariantCulture, 
            DateTimeStyles.None, 
            out DateTime date))
        {
            return date;
        }
        
        throw new JsonException($"无法解析日期: {dateString}，期望格式: {Format}");
    }

    public override void Write(Utf8JsonWriter writer, DateTime value, JsonSerializerOptions options)
    {
        // 写入自定义格式字符串
        writer.WriteStringValue(value.ToString(Format));
    }
}
```

#### 示例 2：枚举转为字符串（带描述）
```cs
public enum Status
{
    [Description("进行中")]
    InProgress,
    [Description("已完成")]
    Completed
}

// 泛型转换器，T 必须是枚举类型
public class EnumDescriptionConverter<T> : JsonConverter<T> where T : struct, Enum
{
    // 反序列化：将 JSON 字符串（描述名）转回枚举成员
    public override T Read(ref Utf8JsonReader reader, Type typeToConvert, JsonSerializerOptions options)
    {
        // 获取当前 JSON 节点的值（预期为字符串）
        string? description = reader.GetString();

        // 遍历枚举的所有成员，对比描述信息
        foreach (T enumValue in Enum.GetValues(typeof(T)))
        {
            if (GetDescription(enumValue) == description)
                return enumValue;
        }
        
        throw new JsonException($"未知枚举值: {description}");
    }

    // 序列化：将枚举成员转为 JSON 字符串（描述名）
    public override void Write(Utf8JsonWriter writer, T value, JsonSerializerOptions options)
    {
        // 写入获取到的 Description 特性文本
        writer.WriteStringValue(GetDescription(value));
    }

    // 辅助方法：通过反射获取枚举字段上的 DescriptionAttribute 内容
    private static string GetDescription(T value)
    {
        var field = typeof(T).GetField(value.ToString());
        var attr = field?.GetCustomAttribute<DescriptionAttribute>();
        // 如果有特性则返回描述，否则返回枚举变量名的字符串
        return attr?.Description ?? value.ToString();
    }
}
```

#### 示例 3：复杂对象自定义结构
```cs
public class Point
{
    public int X { get; set; }
    public int Y { get; set; }
}

// 将 Point 序列化为 "x,y" 字符串，而不是 {"x":1,"y":2}
public class PointConverter : JsonConverter<Point>
{
    public override Point Read(ref Utf8JsonReader reader, Type typeToConvert, JsonSerializerOptions options)
    {
        string? coords = reader.GetString();
        var parts = coords?.Split(',');
        
        if (parts?.Length != 2 || 
            !int.TryParse(parts[0], out int x) || 
            !int.TryParse(parts[1], out int y))
        {
            throw new JsonException($"无效坐标格式: {coords}，期望格式: x,y");
        }
        
        return new Point { X = x, Y = y };
    }

    public override void Write(Utf8JsonWriter writer, Point value, JsonSerializerOptions options)
    {
        writer.WriteStringValue($"{value.X},{value.Y}");
    }
}
```

### 注册和使用 Converter
#### 方式 1：全局注册（推荐）
```cs
var options = new JsonSerializerOptions
{
    PropertyNamingPolicy = JsonNamingPolicy.CamelCase,
    WriteIndented = true
};

// 添加自定义 Converter
options.Converters.Add(new DateTimeYmdConverter());
options.Converters.Add(new PointConverter());
options.Converters.Add(new EnumDescriptionConverter<Status>());

// 使用
var json = JsonSerializer.Serialize(myObject, options);
var obj = JsonSerializer.Deserialize<MyClass>(json, options);
```

#### 方式 2：特性标记（针对特定属性）
```cs
public class MyClass
{
    [JsonConverter(typeof(DateTimeYmdConverter))]
    public DateTime CreatedAt { get; set; }

    [JsonConverter(typeof(PointConverter))]
    public Point Location { get; set; }
    
    // 其他属性使用默认序列化
    public string Name { get; set; }
}

// 使用时无需额外配置
var json = JsonSerializer.Serialize(myObject);
```

#### 方式 3：注册泛型 Converter（处理所有枚举）

`JsonConverter<T>` 只能处理固定的类型 T。如果你的类型是泛型（比如 `Result<T>、List<T>`），或者是 `Enum` 这种基础类型，你需要使用 `JsonConverterFactory`。

工厂的作用是：**在运行时检查类型，并动态创建具体的 Converter。**

比如，你想写一个针对**所有枚举类型**都将其转换为字符串的 Converter（虽然官方已经内置了 JsonStringEnumConverter，但这是一个很好的例子）：

```cs
public class CustomEnumConverterFactory : JsonConverterFactory
{
    // 判断该工厂是否能处理这个类型
    public override bool CanConvert(Type typeToConvert)
    {
        return typeToConvert.IsEnum;
    }

    // 为该类型创建一个具体的 Converter 实例
    public override JsonConverter CreateConverter(Type typeToConvert, JsonSerializerOptions options)
    {
        // 动态创建一个具体的泛型 Converter
        Type converterType = typeof(CustomEnumConverter<>).MakeGenericType(typeToConvert);
        return (JsonConverter)Activator.CreateInstance(converterType)!;
    }
}

// 具体的枚举处理逻辑
public class CustomEnumConverter<T> : JsonConverter<T> where T : struct, Enum
{
    public override T Read(ref Utf8JsonReader reader, Type typeToConvert, JsonSerializerOptions options)
    {
        string enumString = reader.GetString();
        return Enum.Parse<T>(enumString, ignoreCase: true);
    }

    public override void Write(Utf8JsonWriter writer, T value, JsonSerializerOptions options)
    {
        writer.WriteStringValue(value.ToString());
    }
}


// 使用
var options = new JsonSerializerOptions
{
    // 将工厂添加到转换器列表
    Converters = { new CustomEnumConverterFactory() },
    WriteIndented = true // 顺便让 JSON 格式化好看点
};

// 模拟一个带枚举的对象
var myObj = new { MyStatus = Status.InProgress };

// 序列化
string json = JsonSerializer.Serialize(myObj, options);

// 反序列化
var decoded = JsonSerializer.Deserialize<MyClass>(json, options);
```

## 文档对象模型（DOM）：JsonDocument和JsonNode

C#处理JSON时，最标准的方法是**定义对应的C#实体类（POCO）并进行反序列化**。

但是，在实际开发中，我们经常会遇到以下尴尬情况：

1. **只需要一个字段**：JSON有几百个字段，但我只需要其中的 status 字段，专门建个类太麻烦。
2. **结构未知/动态生成**：JSON的结构不固定，可能是 { "a": 1 }，也可能是 { "b": "test" }。
3. **需要局部修改**：拿到一个JSON，只想把里面的某一个值改掉，然后原样发回去。

这时候，我们就需要用到 **文档对象模型 (DOM)**，也就是 JsonDocument 和 JsonNode。

简单来说，它们能让你像**操作字典/树形结构**一样去直接操作 JSON，而不需要预先定义具体的C#类。

### JsonDocument：只读、超高性能的解析器

JsonDocument 是伴随 System.Text.Json 最早推出来的。它的核心设计理念是：**绝对的性能和极低的内存占用**。

**有什么用？**
用于**只读**场景。当你需要从一个未知的 JSON 字符串中提取某几个值，且不需要修改它时，用 JsonDocument 是性能最好的。

**特点与坑（重要）**
- **只读**：一旦解析完成，你无法修改里面的任何值。
- **必须释放**：它底层使用了共享内存池（ArrayPool）来提升性能，所以**必须配合 using 语句使用**，否则会导致内存泄漏！

**怎么用？**
```cs
using System;
using System.Text.Json;

string jsonString = @"{
    ""Name"": ""张三"",
    ""Age"": 25,
    ""Skills"": [""C#"", ""SQL""],
    ""Address"": { ""City"": ""北京"" }
}";

// 【注意这里的 using】
using (JsonDocument document = JsonDocument.Parse(jsonString))
{
    // 获取根节点
    JsonElement root = document.RootElement;

    // 1. 读取普通属性
    string name = root.GetProperty("Name").GetString();
    int age = root.GetProperty("Age").GetInt32();

    // 2. 嵌套读取
    string city = root.GetProperty("Address").GetProperty("City").GetString();

    // 3. 读取数组
    JsonElement skills = root.GetProperty("Skills");
    Console.WriteLine($"掌握技能数: {skills.GetArrayLength()}");
    foreach (JsonElement skill in skills.EnumerateArray())
    {
        Console.WriteLine(skill.GetString());
    }
    
    // 4. 容错处理 (判断属性是否存在)
    if (root.TryGetProperty("Salary", out JsonElement salaryElement))
    {
        Console.WriteLine(salaryElement.GetDouble());
    }
}
```

### JsonNode：可读可写、灵活的动态节点（.NET 6 引入）

虽然 JsonDocument 性能好，但它不能修改 JSON，且 GetProperty().GetProperty() 的写法太啰嗦。很多开发者怀念以前 Newtonsoft 时代的 JObject 和 JToken。
于是，微软在 **.NET 6** 引入了 System.Text.Json.Nodes 命名空间，核心就是 JsonNode。

**有什么用？**
用于**动态读取、修改、添加或删除** JSON 数据。完美替代 Newtonsoft 中的 JObject / JArray。

**结构组成**
JsonNode 是基类，它有三个具体的实现：
- JsonObject：对应 JSON 对象 { } (类似于字典)
- JsonArray：对应 JSON 数组 [ ] (类似于列表)
- JsonValue：对应 基础值 (数字、字符串、布尔等)

**怎么用？**

**场景 A：动态读取（语法极其简练）**
```cs
using System.Text.Json.Nodes;

string jsonString = @"{
    ""Name"": ""李四"",
    ""Address"": { ""City"": ""上海"" },
    ""Scores"": [85, 90, 100]
}";

// 解析 (不需要 using，因为它由 GC 自动回收)
JsonNode node = JsonNode.Parse(jsonString);

// 像字典一样使用索引器读取，非常方便！
string name = node["Name"].GetValue<string>();
string city = node["Address"]["City"].GetValue<string>();
int firstScore = node["Scores"][0].GetValue<int>();

// 强转为具体对象（如果需要遍历数组）
JsonArray scoresArray = node["Scores"].AsArray();
```

**场景 B：动态修改与创建（写操作）**
```cs
using System.Text.Json.Nodes;

// 1. 修改已有的 JSON
JsonNode node = JsonNode.Parse(@"{""Name"": ""李四"", ""Age"": 20}");
node["Age"] = 21; // 直接修改值
node["Name"] = "王五";

// 2. 新增节点
node["Gender"] = "男"; // 动态添加新属性

// 3. 从零手捏一个 JSON
JsonObject newObj = new JsonObject
{
    ["Title"] = "工程师",
    ["IsActive"] = true,
    ["Tags"] = new JsonArray("C#", "后端", "云原生")
};

// 4. 将节点转换回 JSON 字符串输出
string finalJson = newObj.ToJsonString();
Console.WriteLine(finalJson);
// 输出: {"Title":"工程师","IsActive":true,"Tags":["C#","后端","云原生"]}
```


在日常 C# 开发中处理 JSON 时，你可以按照以下优先级来选择：


| 场景需求            | 推荐方案                                        | 说明                                                                   |
| --------------- | ------------------------------------------- | -------------------------------------------------------------------- |
| **首选方案：结构固定**   | **实体类反序列化 (JsonSerializer.Deserialize<T>)** | 强类型，有智能提示，易于维护。这是 90% 情况下的最佳选择。                                      |
| **性能敏感 + 只读提取** | **JsonDocument**                            | 比如网关层只提取 Header 或某个 ID，不需要改动内容，且并发量巨大。**注意必须释放内存**。                  |
| **结构动态 + 读写修改** | **JsonNode**                                | 需要临时修改几个值、拼接 JSON，或者 API 返回结果非常不规则时使用。（这是 Newtonsoft JObject 的完美平替）。 |

**一句话速记：**

- 建类太烦就用 DOM。
- 只看不改用 JsonDocument（快，省内存，记得 using）。
- 又看又改用 JsonNode（方便，写起来爽，像字典）。

## 常用特性

```csharp
using Newtonsoft.Json;

public class Product
{
    // [JsonProperty] - 自定义 JSON 中的属性名
    [JsonProperty("product_name")]
    public string Name { get; set; }

    // [JsonIgnore] - 忽略该属性，不参与序列化
    [JsonIgnore]
    public string InternalCode { get; set; }

    // [JsonConverter] - 使用自定义转换器
    [JsonConverter(typeof(StringEnumConverter))]
    public ProductStatus Status { get; set; }

    // [JsonRequired] - 反序列化时该属性必须存在
    [JsonRequired]
    public decimal Price { get; set; }

    // [JsonProperty] 更多用法：指定默认值、是否可空等
    [JsonProperty("stock_count", DefaultValueHandling = DefaultValueHandling.Ignore)]
    public int StockCount { get; set; }

    // [JsonObject] 可以自定义整个类的序列化行为
}

public enum ProductStatus
{
    Available,
    OutOfStock,
    Discontinued
}
```

### 基础映射与忽略
这是日常开发中最常用的一类，用于控制 JSON 键名和 C# 属性名之间的映射关系，或者隐藏不需要的数据。
**`[JsonProperty]`**：指定序列化后的 JSON 字段名，或强制序列化私有字段。
**`[JsonIgnore]`**：在序列化和反序列化时，完全忽略该字段/属性。
```cs
public class User
{
    // 1. 修改映射名称：C# 中叫 Id，JSON 中叫 user_id
    [JsonProperty("user_id")]
    public int Id { get; set; }

    // 2. 忽略属性：密码不输出到 JSON 中
    [JsonIgnore]
    public string Password { get; set; }

    // 3. 强制序列化私有字段（默认私有字段是不序列化的）
    [JsonProperty("internal_code")]
    private string _internalCode = "XYZ123";
}
```

### 必填验证
用于反序列化时的校验。如果前端/调用方漏传了关键字段，直接在解析阶段抛出异常，不用等进了业务逻辑才发现。
**`[JsonRequired]`**：强制 JSON 中必须包含此键，且不能为 undefined（但可以是 null）。
等同于 `[JsonProperty(Required = Required.Always)]`。
```cs
public class Order
{
    // 如果 JSON 里没有 "OrderNo" 这个字段，反序列化时会直接抛出 JsonSerializationException
    [JsonRequired]
    public string OrderNo { get; set; }

    // 也可以通过 JsonProperty 来设置 Required
    [JsonProperty(Required = Required.DisallowNull)] 
    public string Status { get; set; } // 必须有该字段，且明确不能传 null 进来
}
```

### 空值与默认值过滤

通常我们会配置全局设置来忽略 null 值，但如果只想针对某个特定实体或特定字段进行精细化控制，就可以用特性配置。
- **NullValueHandling**：控制当属性值为 null 时是否输出到 JSON。
- **DefaultValueHandling**：控制当属性值为默认值（如 int 是 0，bool 是 false）时是否输出。
- **`[DefaultValue]`**：（位于 System.ComponentModel 命名空间，但 Newtonsoft 原生支持）定义字段的默认值。
```cs
using System.ComponentModel;

public class Product
{
    public string Name { get; set; }

    // 如果 Description 为 null，则不在 JSON 中生成 "Description": null 这个键值对
    [JsonProperty(NullValueHandling = NullValueHandling.Ignore)]
    public string Description { get; set; }

    // 定义该属性的默认值是 1。
    [DefaultValue(1)]
    // 如果当前 Stock 的值是 1（即默认值），则忽略，不生成到 JSON 中。
    [JsonProperty(DefaultValueHandling = DefaultValueHandling.Ignore)]
    public int Stock { get; set; } = 1; 
}
```


### 未知字段收集兜底
这是 Newtonsoft.Json 中一个**极其强大的特性**。当外部传来的 JSON 包含一些你在 C# 类中没有定义的额外字段时，为了不丢失这些数据（或者用于动态透传），你可以把它们收集到一个字典里。

**`[JsonExtensionData]`**：打在 `IDictionary<string, JToken>` 类型的字段或属性上。
```cs
public class DeviceData
{
    public string DeviceId { get; set; }

    // 当 JSON 中出现了 DeviceId 以外的任何字段，都会被塞进这个字典里
    [JsonExtensionData]
    public IDictionary<string, JToken> AdditionalData { get; set; }
}

/*
输入 JSON:
{
    "DeviceId": "MAC-001",
    "Temperature": 25.5,
    "Battery": 90
}

解析后：
DeviceId = "MAC-001"
AdditionalData 字典里包含两个键值对：["Temperature"]=25.5, ["Battery"]=90
*/
```

### 构造与反序列化控制

如果你在使用**不可变对象**（Immutable Objects，只有 getter，没有 public setter），或者类里有多个构造函数，你需要告诉 Json.NET 在反序列化时该调用哪一个。

**`[JsonConstructor]`**：标记在构造函数上，指定反序列化时使用此构造函数。
```cs
public class Point
{
    public int X { get; } // 只有 Get，无法通过属性赋值
    public int Y { get; }

    // 告诉 Json.NET，用这个构造函数，把 JSON 里的 x 和 y 传进来
    [JsonConstructor]
    public Point(int x, int y)
    {
        X = x;
        Y = y;
    }
}
```


### 局部转换器与类级别策略
当你不想搞全局配置，只想对某个字段或者某个类施加特殊规则时使用。

**`[JsonConverter]`**：单独为某个属性或类指定 JsonConverter（例如枚举转字符串）。
**`[JsonObject]`**：用于类级别，控制该类中成员的序列化策略（是默认全序列化，还是只序列化打了标签的）。

```cs
// 1. 类级别控制：OptIn 表示“必须手动打 [JsonProperty] 的才会序列化，没打的全部忽略”
[JsonObject(MemberSerialization.OptIn)]
public class SecretConfig
{
    [JsonProperty]
    public string PublicUrl { get; set; } // 会被序列化

    public string SecretKey { get; set; } // 不会被序列化，因为没有打标签
}

// 2. 局部转换器
public class Employee
{
    public string Name { get; set; }

    // 默认枚举转 JSON 是数字(如 0, 1)，打上此标签后，会转成字符串(如 "Developer", "Manager")
    [JsonConverter(typeof(Newtonsoft.Json.Converters.StringEnumConverter))]
    public RoleType Role { get; set; }
}

public enum RoleType { Developer, Manager }
```

| 分类      | 特性 (Attribute)         | 核心作用                        |
| ------- | ---------------------- | --------------------------- |
| **映射**  | [JsonProperty("name")] | 改名、强制序列化                    |
| **忽略**  | [JsonIgnore]           | 不参与序列化和反序列化                 |
| **兜底**  | [JsonExtensionData]    | 把实体没定义的 JSON 字段收集到字典里       |
| **校验**  | [JsonRequired]         | 强制要求 JSON 必须有该字段            |
| **空值**  | NullValueHandling      | 设置该属性为 null 时不输出            |
| **构造**  | [JsonConstructor]      | 指定反序列化时用哪个构造函数（常用于无 set 属性） |
| **转换**  | [JsonConverter]        | 对该字段使用指定的规则转换（如枚举转文本）       |
| **类策略** | [JsonObject]           | 控制类的全局行为，如 OptIn 模式（白名单模式）  |

## 高级动态序列化控制
之前讲的特性（Attribute，比如 `[JsonIgnore]`）是**静态的**（写死在代码里的）。但在真实业务中，我们经常遇到**动态需求**：

- “如果这个用户的状态是离职，就不要输出他的工资信息。”
- “我引用了一个第三方的 DLL，我没法在它的类上打 `[JsonIgnore]` 标签，但我就是不想序列化它的某个字段。”

这两个痛点，就是由 ShouldSerialize{PropertyName} 和 IContractResolver 来解决的。

### ShouldSerialize{PropertyName}：局部的动态开关

**是什么？**  
它**不是**一个特性（Attribute），也**不是**一个接口，而是 Newtonsoft.Json 内部约定的一种 **“魔法命名规则”（Convention）**。

**怎么用？**  
如果你在类中定义了一个返回 bool 类型的方法，并且方法名正好是 ShouldSerialize 加上 你的属性名，那么在序列化时，Json.NET 就会去调用这个方法。

- 如果返回 true，就序列化该属性。
- 如果返回 false，就忽略该属性。

**业务场景：根据对象自身的状态，决定是否输出某个字段。**
```cs
using Newtonsoft.Json;
using System;

public class Employee
{
    public string Name { get; set; }
    
    // 假设这是一个非常敏感的字段
    public decimal Bonus { get; set; }
    
    public bool IsManager { get; set; }

    // 【核心点】：这是一个约定好的方法名 ShouldSerialize + Bonus
    // Json.NET 序列化 Bonus 属性前，会自动调用这个方法
    public bool ShouldSerializeBonus()
    {
        // 业务逻辑：只有是经理，才允许把奖金字段输出到 JSON 中
        // 如果是普通员工，Bonus 字段在 JSON 中直接消失
        return IsManager == true;
    }
}

// ---- 测试代码 ----
Employee emp1 = new Employee { Name = "张三", Bonus = 5000, IsManager = false };
Employee emp2 = new Employee { Name = "李总", Bonus = 50000, IsManager = true };

Console.WriteLine(JsonConvert.SerializeObject(emp1)); 
// 输出: {"Name":"张三","IsManager":false}  <- Bonus 消失了！

Console.WriteLine(JsonConvert.SerializeObject(emp2)); 
// 输出: {"Name":"李总","Bonus":50000.0,"IsManager":true} <- 李总有 Bonus
```


### IContractResolver：全局的上帝视角

**是什么？**  
它是 Newtonsoft.Json 中最核心的接口之一（契约解析器）。它决定了 Json.NET **“如何理解一个类”**。  
通过自定义 IContractResolver，你可以全局修改任何类的序列化行为，**即使这个类是第三方库提供的、你无法修改其源码的类**。

**怎么用？**  
我们通常不会从头实现接口，而是继承它默认的实现类 DefaultContractResolver，然后重写里面的 CreateProperty 方法，动态地修改属性的规则。

**业务场景 1：统一修改命名风格（驼峰命名）**  
其实官方已经内置好了一个：
```cs
var settings = new JsonSerializerSettings
{
    // 全局把所有的属性名变成驼峰命名 (UserName -> userName)
    ContractResolver = new CamelCasePropertyNamesContractResolver() 
};
```

**业务场景 2：动态忽略第三方类的某个字段**  
假设你用了一个第三方的类 WeatherResult，里面有个 DebugInfo 字段特别巨大，你想在序列化时砍掉它，但你又不能修改别人的源码加 `[JsonIgnore]`。
```cs
using Newtonsoft.Json;
using Newtonsoft.Json.Serialization;
using System;
using System.Reflection;

// 1. 假设这是第三方的类，你改不了代码
public class WeatherResult
{
    public string City { get; set; }
    public string DebugInfo { get; set; } // 我们想干掉这个字段
}

// 2. 编写自定义的 ContractResolver
public class DynamicIgnoreResolver : DefaultContractResolver
{
    private readonly string _propertyToIgnore;

    public DynamicIgnoreResolver(string propertyToIgnore)
    {
        _propertyToIgnore = propertyToIgnore;
    }

    // Json.NET 在解析类的每个属性时，都会调用这个方法
    protected override JsonProperty CreateProperty(MemberInfo member, MemberSerialization memberSerialization)
    {
        // 先调用基类方法，获取默认的属性定义（契约）
        JsonProperty property = base.CreateProperty(member, memberSerialization);

        // 如果属性名匹配了我们要忽略的名字，直接在内存里把它标记为 Ignored
        if (property.PropertyName == _propertyToIgnore)
        {
            property.Ignored = true; 
        }

        return property;
    }
}

// ---- 测试代码 ----
WeatherResult data = new WeatherResult { City = "北京", DebugInfo = "一堆没用的日志堆栈..." };

// 如果不用解析器，默认全输出：
// {"City":"北京","DebugInfo":"一堆没用的日志堆栈..."}

// 3. 使用解析器：
var settings = new JsonSerializerSettings
{
    // 告诉 Json.NET：全局干掉叫 "DebugInfo" 的字段
    ContractResolver = new DynamicIgnoreResolver("DebugInfo")
};

string json = JsonConvert.SerializeObject(data, settings);
Console.WriteLine(json); 
// 输出: {"City":"北京"}  <- 完美忽略！
```

### 我该用哪种方式来控制序列化？

在开发时，你可以按照这个逻辑图来做选择：
1. **能不能改这个类的源码？**
    - 不能改（如第三方库）用 `IContractResolver`
    - 能改看第 2 步
2. **忽略规则是静态的还是动态的？**
    - 永远都忽略这个字段打`[JsonIgnore]` 特性
    - 有时候忽略，有时候不忽略（基于自身的某个状态）写 `ShouldSerialize{Name}()` 方法
    - 复杂的全局策略（比如：对 A 客户端输出全部，对 B 客户端隐藏 3 个字段）用 `IContractResolver`

## LINQ to JSON：动态解析与修改
在 `Newtonsoft.Json`（通常被称为 Json.NET）中，**LINQ to JSON** 是一个极其强大的功能。它提供了一种类似于 XML DOM（文档对象模型）的方式来操作 JSON 数据。

当你**不知道 JSON 的具体结构**，或者 JSON 结构**非常复杂且频繁变化**，以至于为其编写对应的强类型 C# 类（POCO）显得非常麻烦时，LINQ to JSON 就是你的最佳选择。

下面我将从核心概念、动态解析、动态修改、动态创建以及高级查询（JSONPath）五个方面来为你详细讲解。
### 核心概念：JToken 家族

在 LINQ to JSON 中，所有的 JSON 元素都继承自基类 `JToken`。理解以下几个核心类是关键：
- **`JObject`**: 代表一个 JSON 对象（即 `{ ... }` 包裹的部分）。类似于一个字典。
- **`JArray`**: 代表一个 JSON 数组（即 `[ ... ]` 包裹的部分）。类似于一个列表。
- **`JProperty`**: 代表 `JObject` 中的一个键值对（例如 `"name": "Alice"`）。
- **`JValue`**: 代表 JSON 中的基本值（字符串、数字、布尔值、null 等）。
### 动态解析与读取
如果你有一段 JSON 字符串，你可以直接将其解析为 `JObject` 或 `JArray`，然后像操作字典一样去读取它。

```cs
using System;
using Newtonsoft.Json.Linq;

string jsonString = @"{
  'name': '张三',
  'age': 28,
  'isActive': true,
  'skills': ['C#', 'SQL', 'JavaScript'],
  'address': {
    'city': '北京',
    'zip': '100000'
  }
}";

// 1. 解析 JSON 字符串
JObject json = JObject.Parse(jsonString);

// 2. 读取基础属性 (推荐使用强制类型转换提取 C# 基本类型)
string name = (string)json["name"];
int age = (int)json["age"];
bool isActive = (bool)json["isActive"];

// 3. 读取嵌套对象
string city = (string)json["address"]["city"];

// 4. 读取数组
JArray skills = (JArray)json["skills"];
string firstSkill = (string)skills[0];

Console.WriteLine($"{name} 住在 {city}，他的第一技能是 {firstSkill}。");

```

### 动态修改
修改现有的 JSON 数据非常直观，你可以直接对节点进行重新赋值、添加新节点或删除现有节点。
```cs
JObject json = JObject.Parse(jsonString); // 使用上面的 jsonString

// 1. 修改现有值
json["age"] = 29;
json["address"]["city"] = "上海";

// 2. 添加新属性
json["email"] = "zhangsan@example.com"; // 直接赋值添加
json.Add("phone", "13800138000");       // 使用 Add 方法添加

// 3. 向数组中添加新元素
JArray skills = (JArray)json["skills"];
skills.Add("Python");

// 4. 删除属性
json.Remove("isActive");           // 从当前 JObject 中移除属性
json["address"]["zip"].Parent.Remove(); // 获取 JToken 的父节点(JProperty)并移除它

// 5. 将修改后的 JObject 转回 JSON 字符串
string updatedJson = json.ToString();
Console.WriteLine(updatedJson);

```


### 动态创建 JSON

除了修改，你还可以完全不依赖 C# 类，通过代码从头构建一个复杂的 JSON 结构。LINQ to JSON 支持一种非常优雅的**声明式语法**：
```cs
JObject newJson = new JObject(
    new JProperty("productName", "MacBook Pro"),
    new JProperty("price", 14999.00),
    new JProperty("tags", new JArray("Laptop", "Apple", "M3")),
    new JProperty("specs", new JObject(
        new JProperty("ram", "16GB"),
        new JProperty("storage", "512GB SSD")
    ))
);

Console.WriteLine(newJson.ToString());

```

###  高级查询：结合 LINQ 与 JSONPath

这才是 "LINQ to JSON" 名字的真正来源。你可以使用标准 LINQ 方法（如 `.Where()`, `.Select()`）来查询 JToken，也可以使用更强大的 **JSONPath** 语法。
#### 使用标准 LINQ 查询
```cs
string storeJson = @"{
  'books': [
    { 'title': 'C# 入门', 'price': 50 },
    { 'title': '深入理解 JVM', 'price': 80 },
    { 'title': '设计模式', 'price': 45 }
  ]
}";

JObject store = JObject.Parse(storeJson);

// 查找所有价格小于 60 的书名
var cheapBookTitles = store["books"]
    .Where(b => (double)b["price"] < 60)
    .Select(b => (string)b["title"]);

Console.WriteLine(string.Join(", ", cheapBookTitles)); // 输出: C# 入门, 设计模式

```

#### 使用 SelectToken (JSONPath) 提取数据

如果 JSON 嵌套极深，连续使用 `[]` 很容易报空引用异常。`SelectToken` 配合 JSONPath 可以完美解决这个问题。
```cs
// 1. 深度查找单个属性（即使嵌套很深）
// ?. 语法（JSONPath 中的点号）
JToken priceToken = store.SelectToken("$.books[1].price"); 
int price = priceToken != null ? (int)priceToken : 0;

// 2. 使用 JSONPath 过滤语法筛选多个对象
// $.books[?(@.price > 50)] 表示在 books 数组中查找 price 大于 50 的元素
IEnumerable<JToken> expensiveBooks = store.SelectTokens("$.books[?(@.price > 50)]");

foreach (var book in expensiveBooks)
{
    Console.WriteLine((string)book["title"]); // 输出: 深入理解 JVM
}

```

## 自定义序列化规则

通过 `JsonSerializerSettings` 设置全局策略：

```csharp
using Newtonsoft.Json;
using Newtonsoft.Json.Converters;
using Newtonsoft.Json.Serialization;

// ============================================
// JsonSerializerSettings 常用配置项完整示例
// ============================================

var settings = new JsonSerializerSettings
{
    // ============================================
    // 1. 命名策略（最常用）
    // ============================================

    // 驼峰命名（camelCase）：首字母小写，如 userName
    // 输出示例：{"userName":"张三","userAge":25}
    ContractResolver = new CamelCasePropertyNamesContractResolver(),

    // 其他命名策略选项：
    // ContractResolver = new DefaultContractResolver(),      // 保持原样（PascalCase）
    // ContractResolver = new SnakeCaseNamingStrategy(),      // 下划线命名：user_name
    // ContractResolver = new KebabCaseNamingStrategy(),      // 短横线命名：user-name


    // ============================================
    // 2. Null 值处理
    // ============================================

    // 忽略所有 Null 值的属性，不序列化到 JSON
    // 输出示例：{"Name":"张三"}  （Age 为 null 时被忽略）
    NullValueHandling = NullValueHandling.Ignore,

    // 其他选项：
    // NullValueHandling = NullValueHandling.Include,   // 包含 null（默认）：{"Name":"张三","Age":null}


    // ============================================
    // 3. 默认值处理
    // ============================================

    // 忽略默认值（0, false, "" 等），减少 JSON 体积
    // int 默认 0, bool 默认 false, string 默认 null（配合 NullValueHandling）
    DefaultValueHandling = DefaultValueHandling.Ignore,

    // 其他选项：
    // DefaultValueHandling = DefaultValueHandling.Include,           // 包含默认值（默认）
    // DefaultValueHandling = DefaultValueHandling.IgnoreAndPopulate, // 反序列化时填充默认值


    // ============================================
    // 4. 循环引用处理（重要！防止堆栈溢出）
    // ============================================

    // 忽略循环引用：遇到循环引用时跳过该属性
    // 示例：A 引用 B，B 引用 A，序列化 A 时 B 的 BackReference 被忽略
    ReferenceLoopHandling = ReferenceLoopHandling.Ignore,

    // 其他选项：
    // ReferenceLoopHandling = ReferenceLoopHandling.Error,      // 抛出异常（默认，生产环境慎用）
    // ReferenceLoopHandling = ReferenceLoopHandling.Serialize,  // 强制序列化（可能死循环）

    // 替代方案：使用 $id 和 $ref 标记对象引用（保留完整结构）
    // PreserveReferencesHandling = PreserveReferencesHandling.Objects,


    // ============================================
    // 5. 日期时间格式
    // ============================================

    // 自定义日期格式（默认 ISO 8601 格式）
    DateFormatString = "yyyy-MM-dd HH:mm:ss",

    // 日期时区处理
    DateTimeZoneHandling = DateTimeZoneHandling.Local,           // 转换为本地时区（默认）
    // DateTimeZoneHandling = DateTimeZoneHandling.Utc,          // 转换为 UTC
    // DateTimeZoneHandling = DateTimeZoneHandling.Unspecified,  // 不指定时区
    // DateTimeZoneHandling = DateTimeZoneHandling.RoundtripKind, // 保留原始 DateTimeKind

    // 日期解析处理
    DateParseHandling = DateParseHandling.DateTime,              // 解析为 DateTime（默认）
    // DateParseHandling = DateParseHandling.DateTimeOffset,     // 解析为 DateTimeOffset
    // DateParseHandling = DateParseHandling.None,               // 不解析，保持字符串


    // ============================================
    // 6. 枚举序列化
    // ============================================

    // 将枚举序列化为字符串（可读性更好）
    // 输出示例：{"Status":"Active"}  而非 {"Status":1}
    Converters = new List<JsonConverter> { new StringEnumConverter() },

    // StringEnumConverter 高级配置：
    // new StringEnumConverter(new CamelCaseNamingStrategy())  // 驼峰命名：active
    // new StringEnumConverter() { AllowIntegerValues = false }  // 禁止整数，强制字符串


    // ============================================
    // 7. 空字符串处理
    // ============================================

    // 空字符串视为 Null（影响反序列化）
    // 示例：JSON {"Name":""} 反序列化后 Name 为 null
    NullValueHandling = NullValueHandling.Ignore,  // 配合此设置，空字符串也会被忽略


    // ============================================
    // 8. 数字精度与特殊值
    // ============================================

    // 浮点数特殊值处理
    FloatFormatHandling = FloatFormatHandling.String,           // NaN, Infinity 转为字符串
    // FloatFormatHandling = FloatFormatHandling.Symbol,         // 使用符号表示（默认）
    // FloatFormatHandling = FloatFormatHandling.DefaultValue,   // 转为默认值 0

    // 浮点数精度控制
    FloatParseHandling = FloatParseHandling.Decimal,            // 高精度 decimal（推荐金融）
    // FloatParseHandling = FloatParseHandling.Double,           // 双精度（默认，性能更好）


    // ============================================
    // 9. 字符串转义
    // ============================================

    // HTML 特殊字符转义（防止 XSS）
    StringEscapeHandling = StringEscapeHandling.EscapeHtml,     // 转义 < > & ' "
    // StringEscapeHandling = StringEscapeHandling.Default,      // 仅转义必要字符（默认）
    // StringEscapeHandling = StringEscapeHandling.EscapeNonAscii, // 转义非 ASCII


    // ============================================
    // 10. 缩进与格式化（调试 vs 生产）
    // ============================================

    // 格式化输出（缩进，换行）—— 调试友好，体积大
    Formatting = Formatting.Indented,

    // 紧凑输出（单行）—— 生产环境推荐，体积小
    // Formatting = Formatting.None,


    // ============================================
    // 11. 反序列化严格性
    // ============================================

    // 忽略 JSON 中存在但 C# 类中没有的属性（防止异常）
    MissingMemberHandling = MissingMemberHandling.Ignore,

    // 其他选项：
    // MissingMemberHandling = MissingMemberHandling.Error,      // 抛出异常（严格模式）


    // ============================================
    // 12. 类型信息处理（多态序列化）
    // ============================================

    // 包含 .NET 类型信息（用于多态反序列化）
    // TypeNameHandling = TypeNameHandling.Auto,      // 自动（仅当需要时）
    // TypeNameHandling = TypeNameHandling.Objects,   // 所有对象包含 $type
    // TypeNameHandling = TypeNameHandling.All,       // 所有类型信息

    // ⚠️ 安全警告：All/Objects 可能引发反序列化漏洞，建议配合 SerializationBinder 使用
    // TypeNameHandling = TypeNameHandling.None,      // 不包含（默认，最安全）


    // ============================================
    // 13. 自定义转换器注册
    // ============================================

    // 全局注册自定义转换器（按顺序匹配）
    Converters = new List<JsonConverter>
    {
        new StringEnumConverter(),                    // 枚举转字符串
        new IsoDateTimeConverter(),                   // ISO 8601 日期
        new JavaScriptDateTimeConverter(),            // JavaScript 日期格式 /Date(1234567890)/
        // new CustomConverter()                       // 自定义转换器
    },


    // ============================================
    // 14. 最大深度限制（防止恶意 JSON）
    // ============================================

    // 最大嵌套深度（默认 64，设为 null 表示无限制）
    MaxDepth = 128,


    // ============================================
    // 15. 跟踪调试信息
    // ============================================

    // 序列化/反序列化路径跟踪（调试时用）
    // TraceWriter = new MemoryTraceWriter(),


    // ============================================
    // 16. 错误处理委托
    // ============================================

    // 遇到错误时的回调（可记录日志或跳过错误）
    Error = (sender, args) =>
    {
        Console.WriteLine($"序列化错误: {args.ErrorContext.Error.Message}");
        args.ErrorContext.Handled = true;  // 标记为已处理，继续序列化其他属性
    },


    // ============================================
    // 17. 序列化回调（高级）
    // ============================================

    // 序列化前/后回调（需类实现 ISerializable 或标记特性）
    // SerializationBinder = new CustomSerializationBinder(),


    // ============================================
    // 18. 构造函数处理
    // ============================================

    // 使用非公共构造函数
    // ConstructorHandling = ConstructorHandling.AllowNonPublicDefaultConstructor,

    // 默认：仅使用公共无参构造函数
    ConstructorHandling = ConstructorHandling.Default,
};


// ============================================
// 使用示例
// ============================================

// 序列化
string json = JsonConvert.SerializeObject(myObject, settings);

// 反序列化
var obj = JsonConvert.DeserializeObject<MyClass>(json, settings);


// ============================================
// 全局默认设置（影响所有序列化操作）
// ============================================

JsonConvert.DefaultSettings = () => new JsonSerializerSettings
{
    ContractResolver = new CamelCasePropertyNamesContractResolver(),
    NullValueHandling = NullValueHandling.Ignore,
    ReferenceLoopHandling = ReferenceLoopHandling.Ignore,
    Converters = new List<JsonConverter> { new StringEnumConverter() }
};

```

# 五、System.Text.Json 与 Newtonsoft.Json 对比总结

| 对比项目 | System.Text.Json | Newtonsoft.Json |
|-----------|------------------|-----------------|
| 开发团队 | Microsoft 官方 | James Newton-King |
| 性能 | 高性能 | 较慢 |
| 功能丰富度 | 中等 | 非常高 |
| 支持框架 | .NET Core/.NET 5+ 原生 | 全版本兼容 |
| 日期/枚举处理 | 较严格 | 灵活 |
| 动态 JSON | 较弱 (`JsonDocument`) | 强（JObject） |
| 适合场景 | 性能敏感的服务端 | 灵活复杂的场景 |

建议：
- 若项目为 .NET 6+、追求性能 → **System.Text.Json**
- 若需要强大灵活的操作 → **Newtonsoft.Json**

# 六、常见错误与调试技巧

1. **属性命名不匹配**
   - 解决：启用 `PropertyNameCaseInsensitive = true`
2. **日期格式不符**
   - 使用自定义转换器控制格式。
3. **空引用或默认值丢失**
   - 控制 `DefaultIgnoreCondition`。
4. **循环引用**
   - Json.NET 提供 `ReferenceLoopHandling.Ignore`。
5. **文本编码问题（中文转义）**
   - System.Text.Json：设置 `UnsafeRelaxedJsonEscaping`。
