## StreamWriter和StreamReader
如果说 `FileStream` 是搬运数据的“底层苦力”（只懂 `byte`），那么 **`StreamWriter` 和 `StreamReader` 就是专门处理文本的“高级翻译官”**。

在实际开发中，如果你要读写的**全都是纯文本（如 .txt, .csv, .json, .log 等）**，直接使用这两个类会让你如沐春风，因为它们直接和我们熟悉的 `string` 打交道，自动帮你在内部处理了繁琐的“字符串 <=> 字节数组”的转换。

为了保持清晰，我们将它们分开，详细拆解其构造函数、属性和方法。

---

### 第一部分：文本写入利器 —— `StreamWriter`

`StreamWriter` 专门负责向流（或文件）中**写入字符/字符串**。

#### 常用构造函数

你可以直接给它一个文件路径，也可以给它一个现成的 `FileStream`。

| 构造函数签名 | 详细说明 |
| :--- | :--- |
| `StreamWriter(string path)` | **最基础用法。** 直接给出文件路径。如果文件不存在则创建；如果存在，**会覆盖**原文件。默认使用 UTF-8 编码。 |
| `StreamWriter(string path, bool append)` | **写日志最常用。** `append` 为 `true` 表示在文件末尾**追加**内容；为 `false` 则表示**覆盖**原内容。 |
| `StreamWriter(string path, bool append, Encoding encoding)` | **解决乱码必备。** 除了指定是否追加，还能指定具体的文本编码（如 `Encoding.UTF8` 或 `Encoding.GetEncoding("GB2312")`），防止中文乱码。 |
| `StreamWriter(Stream stream)` | **包装模式。** 传入一个现成的流（比如你先用 `FileStream` 进行了复杂的权限设置，然后再传给它）。 |

#### 常用属性

| 属性名          | 类型         | 详细说明                                                                                                                             |
| :----------- | :--------- | :------------------------------------------------------------------------------------------------------------------------------- |
| `AutoFlush`  | `bool`     | **非常重要。** 默认是 `false`。如果设为 `true`，每次调用 Write 方法后，它会自动把内存里的数据强制刷入磁盘；如果不设，数据会先积攒在内存缓冲区里，直到调用 Close 或 Flush 才写入磁盘。（开启会降低一点性能，但更安全）。 |
| `Encoding`   | `Encoding` | 获取当前写入器使用的字符编码格式（只读）。                                                                                                            |
| `BaseStream` | `Stream`   | 获取 `StreamWriter` 内部正在操作的那个底层流（通常是 `FileStream`）。                                                                                |


#### 常用方法

| 方法签名                           | 详细说明                                             |
| :----------------------------- | :----------------------------------------------- |
| `void Write(string value)`     | **连续写入。** 将字符串写入文件，**不换行**。光标停在刚写完的字符后面。         |
| `void WriteLine(string value)` | **换行写入。** 将字符串写入文件，并**在末尾自动添加一个回车换行符**。这是最常用的方法。 |
| `void Flush()`                 | **手动刷新。** 将当前缓冲区里的字符串立刻写入底层存储（物理磁盘）。             |
| `void Close()` / `Dispose()`   | 关闭写入器并释放底层流。**使用 `using` 语句可自动调用。**              |
| `Task WriteLineAsync(...)`     | 异步版本的换行写入，防止大批量写入时卡死主线程。                         |

### 第二部分：文本读取利器 —— `StreamReader`

`StreamReader` 专门负责从流（或文件）中**读取字符/字符串**。

#### 常用构造函数

| 构造函数签名 | 详细说明 |
| :--- | :--- |
| `StreamReader(string path)` | 打开指定路径的文件进行读取。它非常聪明，默认会尝试根据文件头（BOM）自动检测编码，通常为 UTF-8。 |
| `StreamReader(string path, Encoding encoding)` | **解决读取乱码必备。** 明确告诉读取器这个文件是用什么编码写的（比如强制用 `Encoding.GetEncoding("GBK")` 去读旧版 Windows 生成的 txt）。 |
| `StreamReader(Stream stream)` | 传入一个现成的流进行读取解析。 |

#### 常用属性

| 属性名 | 类型 | 详细说明 |
| :--- | :--- | :--- |
| `EndOfStream` | `bool` | **极其常用！** 判断是否已经读到了文件的最末尾。返回 `true` 表示读完了，返回 `false` 表示还有数据没读。常用于 `while` 循环条件。 |
| `CurrentEncoding` | `Encoding` | 获取当前读取器正在使用的编码格式。 |

#### 常用方法

| 方法签名 | 详细说明 |
| :--- | :--- |
| `string ReadLine()` | **逐行读取（最常用）。** 读到换行符为止，返回这一行的纯文本（不含换行符本身）。如果已经读到文件末尾，会返回 `null`。 |
| `string ReadToEnd()` | **全部读取。** 一口气把从当前光标位置到文件末尾的**所有内容**读成一个巨大的字符串。仅适用于不太大的文件，如果文件有几个 G，会导致内存爆炸（OutOfMemory）。 |
| `int Read()` | **读取单个字符。** 读取下一个字符，并返回其 ASCII/Unicode 整数值。如果读到末尾返回 -1。（需要自己强转成 `(char)`）。 |

### 第三部分：实战代码示例

#### 示例 1：使用 StreamWriter 写入/追加日志
```csharp
using System;
using System.IO;

class Program
{
    static void Main()
    {
        string filePath = "log.txt";

        // 参数 true 表示“追加模式 (Append)”。
        // 如果文件不存在，会自动创建；如果存在，就在旧内容末尾接着写。
        using (StreamWriter sw = new StreamWriter(filePath, true))
        {
            // 写一行文本，自动加换行
            sw.WriteLine($"[{DateTime.Now}] 系统启动...");
            sw.WriteLine($"[{DateTime.Now}] 正在处理数据...");
            
            // 写一段文本，不换行
            sw.Write("处理进度：");
            sw.Write("100% ");
            sw.WriteLine("完成！"); // 这句写完后才会换行
            
            Console.WriteLine("日志写入成功！");
        } // 离开 using 块，自动调用 Dispose() -> 内部触发 Flush() -> 彻底存入磁盘
    }
}
```

#### 示例 2：使用 StreamReader 逐行读取文件 (推荐做法)
```csharp
using System;
using System.IO;

class Program
{
    static void Main()
    {
        string filePath = "log.txt";

        if (!File.Exists(filePath))
        {
            Console.WriteLine("文件不存在！");
            return;
        }

        // 实例化 StreamReader
        using (StreamReader sr = new StreamReader(filePath))
        {
            Console.WriteLine("开始读取文件内容：");
            Console.WriteLine("-----------------------");

            // 经典写法：只要还没到文件末尾 (EndOfStream == false)，就一直循环
            while (!sr.EndOfStream)
            {
                // 每次只读一行，内存占用极小，适合读取超大文本文件！
                string line = sr.ReadLine();
                Console.WriteLine(line);
            }
        }
    }
}
```

### 总结与进阶建议

1. **底层机制**：你传入 `string path` 给 `StreamWriter` 时，它其实在内部偷偷帮你 `new` 了一个 `FileStream`，只是它把底层细节隐藏了，让你专心处理文本。
2. **内存友好（逐行读取）**：面对一个 2GB 的日志文件，**千万不要**用 `sr.ReadToEnd()`，也尽量别用 `File.ReadAllText()`。正确做法是像上面【示例2】一样，用 `sr.ReadLine()` 配合 `while` 循环**逐行读取**。这样无论文件多大，你的程序内存占用始终只有几 MB，这就是 Stream（流）设计的初衷！
3. **乱码杀手**：如果你发现读写中文字符变成了 `???` 或者乱七八糟的符号，99% 的情况是编码没对齐。在构造函数里显式指定 `Encoding.UTF8` 就能解决大部分问题。
