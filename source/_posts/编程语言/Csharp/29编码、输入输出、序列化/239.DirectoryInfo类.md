## System.IO.DirectoryInfo类
`System.IO.DirectoryInfo` 是 C# 中专门用于处理单个**文件夹（目录）** 的**实例类**。

---

### 什么时候用 `DirectoryInfo`？

与 `Directory`（静态类）相比，选择 `DirectoryInfo`（实例类）的场景如下：

1.  **多次操作**：如果你需要对同一个文件夹进行多次打探（获取它的名字、父级目录、创建时间、里面的文件），实例化一个 `DirectoryInfo` 性能更好，因为它会缓存状态。
2.  **获取对象而非字符串**：`Directory.GetFiles()` 返回的是**一堆字符串路径**；而 `DirectoryInfo.GetFiles()` 返回的是一堆 **`FileInfo` 对象**，这让你后续直接读取文件大小、时间变得极其方便。
3.  **目录树漫游**：由于它具有 `.Parent` 和 `.Root` 属性，非常适合在文件夹的层级结构中上下“攀爬”。

---

### 构造函数

只需要传入文件夹的路径即可。

```csharp
// 实例化一个 DirectoryInfo 对象
DirectoryInfo di = new DirectoryInfo(@"C:\MyApp\Logs");

// ⚠️ 注意：仅仅 new 出来，如果硬盘上没有这个文件夹，它也不会报错，更不会自动创建。
// 此时 di 只是一个驻留在内存里的代表。
```

---

### 核心属性 (获取文件夹的“身份证”)

在读取这些属性前，最好先判断 `di.Exists`。

| 属性名 | 返回值类型 | 描述说明 |
| :--- | :--- | :--- |
| **`Exists`** | `bool` | 文件夹在硬盘上是否真实存在。 |
| **`Name`** | `string` | 获取文件夹的名称（不含路径，例如 `"Logs"`）。 |
| **`FullName`** | `string` | 获取文件夹的**绝对路径**（例如 `"C:\MyApp\Logs"`）。 |
| **`Parent`** | `DirectoryInfo`| **极度常用**。获取父目录的对象。允许无限向上追溯（如 `di.Parent.Parent`）。 |
| **`Root`** | `DirectoryInfo`| 获取路径的根部分（如 `"C:\"`）。 |
| **`CreationTime`** | `DateTime` | 获取/设置创建时间。 |
| **`LastWriteTime`**| `DateTime` | 获取/设置最后修改时间（文件夹里增删文件会改变此时间）。 |

**代码示例：目录树“攀爬”**
```csharp
DirectoryInfo di = new DirectoryInfo(@"C:\A\B\C");

Console.WriteLine($"当前文件夹: {di.Name}");                 // 输出: C
Console.WriteLine($"父文件夹: {di.Parent.Name}");          // 输出: B
Console.WriteLine($"爷爷文件夹: {di.Parent.Parent.Name}"); // 输出: A
Console.WriteLine($"根目录: {di.Root.Name}");              // 输出: C:\
```

### 核心方法 (获取内容与执行动作)

这是 `DirectoryInfo` 最强大的地方，它获取子项时直接返回**对象数组**。

#### 获取内部内容 (查询)
*   **`GetFiles()`**: 返回 `FileInfo[]` 数组。获取该目录下的所有文件对象。
*   **`GetDirectories()`**: 返回 `DirectoryInfo[]` 数组。获取子文件夹对象。
*   **`GetFileSystemInfos()`**: 返回 `FileSystemInfo[]` 数组。**一口气把文件和文件夹全拿出来**（`FileSystemInfo` 是 `FileInfo` 和 `DirectoryInfo` 的共同父类）。

*注意：以上三个方法都支持传入 `("*.txt")` 通配符和 `SearchOption.AllDirectories` (递归搜索)。*

#### 物理管理 (操作)
*   **`Create()`**: 按照实例化的路径，在硬盘上真实创建这个文件夹（如果父目录不存在也会一并创建）。
*   **`Delete()`**: 删除当前空文件夹。
*   **`Delete(bool recursive)`**: 传入 `true`，**强制连带里面所有的文件和子文件夹一起删除**（极度危险，不进回收站）。
*   **`MoveTo(string destDirName)`**: 将文件夹移动到新路径（可用于重命名）。

### 实战场景一：计算整个文件夹的大小

你可能注意到了，C# 没有任何一个 API 可以直接获取“文件夹大小”。因为文件夹本身不占多大空间，大小是里面所有文件加起来的总和。

使用 `DirectoryInfo.GetFiles()` 配合 LINQ，可以极其优雅地算出文件夹大小：

```csharp
DirectoryInfo di = new DirectoryInfo(@"C:\MyPhotos");

if (di.Exists)
{
    // 获取该目录下【所有文件】，包括子文件夹里的文件
    FileInfo[] allFiles = di.GetFiles("*.*", SearchOption.AllDirectories);

    // 遍历累加所有文件的 Length 属性
    long totalBytes = 0;
    foreach (FileInfo fi in allFiles)
    {
        totalBytes += fi.Length;
    }

    Console.WriteLine($"文件夹总大小: {totalBytes / 1024 / 1024} MB");
}
```

### 实战场景二：清空文件夹内的所有内容（保留文件夹本身）

有时候我们需要清空一个缓存文件夹，但不想把这个文件夹本身删掉。可以使用 `GetFileSystemInfos()`。

```csharp
DirectoryInfo cacheDir = new DirectoryInfo(@"C:\Temp\Cache");

if (cacheDir.Exists)
{
    // 拿到里面所有的东西（文件 + 子文件夹）
    foreach (var item in cacheDir.GetFileSystemInfos())
    {
        // 无论是文件还是文件夹，直接干掉
        item.Delete(); 
    }
    Console.WriteLine("缓存清空完毕！");
}
```

### 高级避坑指南

#### 缓存陷阱 `Refresh()`
和 `FileInfo` 完全一样，`DirectoryInfo` 的时间戳属性（如 `CreationTime`）会被**缓存**。如果你在程序运行期间，其他程序修改了这个文件夹，你需要调用 **`di.Refresh()`** 来刷新缓存。

#### 大目录下的性能问题 `Enumerate...`
和 `Directory` 类一样，如果文件夹里有几十万个文件，调用 `GetFiles()` 会导致内存爆炸和程序卡死。
`DirectoryInfo` 也提供了延迟加载的迭代器方法，极其推荐用于大文件夹：
*   **`EnumerateFiles()`** -> 返回 `IEnumerable<FileInfo>`
*   **`EnumerateDirectories()`** -> 返回 `IEnumerable<DirectoryInfo>`

```csharp
DirectoryInfo hugeDir = new DirectoryInfo(@"D:\MassiveData");

// 即使有百万级文件，内存占用也很低，速度极快
foreach (FileInfo file in hugeDir.EnumerateFiles("*.log", SearchOption.AllDirectories))
{
    if (file.Length > 1024 * 1024 * 100) // 找出大于 100MB 的日志文件
    {
         Console.WriteLine($"发现大文件: {file.FullName}");
    }
}
```

#### 有趣的冷知识：为什么没有 CopyTo()？
你会发现 `FileInfo` 有 `CopyTo`（复制），但是 `DirectoryInfo` **没有提供任何 Copy 方法**！
这是因为 C# 原生 API 不提供直接复制整个文件夹的功能（可能涉及复杂的权限、文件锁、递归层级深等问题）。如果你需要复制整个文件夹，需要自己写一个递归方法，逐个创建子文件夹并把文件 `FileInfo.CopyTo` 过去。
