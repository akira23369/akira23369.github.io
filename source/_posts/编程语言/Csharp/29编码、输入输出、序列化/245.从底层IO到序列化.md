# 从底层IO到序列化的前世今生

## 第一部分：到底什么是“序列化”与“反序列化”？

### 核心概念
在C#中，我们操作的都是**对象（Object）**（比如玩家、订单、武器），这些对象是存在于**内存（RAM）** 里的立体结构。内存有个致命缺点：**断电即清空，程序关闭即销毁。**

为了把这些立体、复杂的对象永久保存到硬盘上（或者通过网络发给别人），我们必须把它们“拍扁”，变成一维的、连续的**字节流（Byte Stream）** 或**字符流（Text Stream）**。

序列化的本质是不是就是给内存数据（c#对象等）设定一个格式以便持久化或者网络传输，反序列化就是将这些格式还原成内存对象以便程序处理

- **序列化：** 把椅子拆掉，每一颗螺丝、每一块板子按顺序装进一个纸箱，并附上一份**组装说明书**。
- **传输：** 把纸箱快递给朋友（通过网络或硬盘存储）。
- **反序列化：** 朋友收到纸箱，按照说明书把板子和螺丝重新拼成一把椅子（在对方的内存里重建对象）。
### 为什么不用纯IO直接写？
你可能会问：“我学了IO，我直接用 `File.WriteAllText` 把玩家的血量写进 txt 文件不就行了？”
**可以，但极度痛苦。** 如果你有100个属性呢？如果属性里还包含一个列表呢？每次存取都要手动去算换行符、逗号截取，这不仅容易出错，而且毫无复用性可言。

**序列化框架的作用，就是自动化这个“拆解和组装”的过程。** 但在学习现成框架前，我们先**自己当一次框架作者**，手写序列化器！

## 第二部分：青铜时代 —— 手动写一个简单的定制化序列化

我们先用最朴素的IO操作（`FileStream` + `StreamWriter/StreamReader`），为一个特定的类写死一套序列化逻辑。

### 定义实体类
假设我们有一个游戏玩家类：

```csharp
using System;
using System.IO;

public class Player
{
    public string Name { get; set; }
    public int Level { get; set; }
    public double HP { get; set; }

    public override string ToString()
    {
        return $"[Player] Name:{Name}, Level:{Level}, HP:{HP}";
    }
}
```

### 手动实现简单序列化（纯文本拼接）
我们要把对象变成 `Key=Value` 的纯文本格式写入文件。

```csharp
public class SimplePlayerSerializer
{
    // 【序列化】把对象写进硬盘
    public static void Serialize(Player player, string filePath)
    {
        // 刚学过的IO：创建文件流并包装成写入流
        using (FileStream fs = new FileStream(filePath, FileMode.Create, FileAccess.Write))
        using (StreamWriter writer = new StreamWriter(fs))
        {
            // 手动把属性变成文本
            writer.WriteLine($"Name={player.Name}");
            writer.WriteLine($"Level={player.Level}");
            writer.WriteLine($"HP={player.HP}");
        }
        Console.WriteLine($"[简单序列化] 玩家 {player.Name} 数据已保存到 {filePath}");
    }

    // 【反序列化】从硬盘读取并还原对象
    public static Player Deserialize(string filePath)
    {
        if (!File.Exists(filePath)) throw new FileNotFoundException("存档丢失！");

        Player newPlayer = new Player();

        using (FileStream fs = new FileStream(filePath, FileMode.Open, FileAccess.Read))
        using (StreamReader reader = new StreamReader(fs))
        {
            string line;
            while ((line = reader.ReadLine()) != null)
            {
                // 解析每一行："Name=张三"
                string[] parts = line.Split('=');
                if (parts.Length != 2) continue;

                string key = parts[0];
                string value = parts[1];

                // 手动映射（非常繁琐）
                switch (key)
                {
                    case "Name":
                        newPlayer.Name = value;
                        break;
                    case "Level":
                        newPlayer.Level = int.Parse(value);
                        break;
                    case "HP":
                        newPlayer.HP = double.Parse(value);
                        break;
                }
            }
        }
        Console.WriteLine($"[简单反序列化] 玩家存档加载成功！");
        return newPlayer;
    }
}
```

### 测试运行
```csharp
Player p1 = new Player { Name = "Arthur", Level = 50, HP = 999.5 };
string path = "player_save.txt";

// 序列化
SimplePlayerSerializer.Serialize(p1, path);

// 反序列化
Player loadedPlayer = SimplePlayerSerializer.Deserialize(path);
Console.WriteLine(loadedPlayer.ToString());
```

**痛点分析：**
这段代码能跑，但它是 **“硬编码”（Hard-coded）** 的。如果 `Player` 类加了一个 `MP` 属性，你不仅要改类，还要去改 `Serialize` 和 `Deserialize` 方法里长长的 `switch` 语句。如果有一个 `Monster` 类，你要把上面的代码再重写一遍。这简直是灾难！

## 第三部分：黄金时代 —— 手写一个复杂且通用的二进制序列化器

为了解决上面的痛点，我们要写一个**通用（Generic）** 的序列化器：不管丢进来的是 `Player`、`Monster` 还是 `Item`，它都能自动解析并保存！

这里我们需要用到C#的一把神兵利器：**反射（Reflection）**。它可以让程序在运行的时候，自己去“看”一个类里到底有哪些属性。

结合你学过的 **`BinaryWriter`** 和 **`BinaryReader`**（处理二进制IO的利器），我们来手写一个属于你自己的通用二进制序列化引擎！

### 核心思路设计：自定义二进制文件格式
我们不能随便乱写字节，必须定义好“协议”：
1. 文件开头写入类的全名（方便反序列化时知道要创建什么对象）。
2. 写入属性的总数量。
3. 循环遍历每个属性：
    * 写入属性名（String）。
    * 写入属性类型（String）。
    * 写入属性的值（根据类型写入不同格式的字节）。

### 复杂通用序列化代码
```csharp
using System;
using System.IO;
using System.Reflection;

public class MyUniversalBinarySerializer
{
    // ==========================================
    // 复杂通用序列化：对象 -> 自定义二进制文件
    // ==========================================
    public static void Serialize<T>(T obj, string filePath)
    {
        if (obj == null) throw new ArgumentNullException(nameof(obj));

        Type type = obj.GetType(); // 获取对象的真实类型信息（反射）
        PropertyInfo[] properties = type.GetProperties(); // 获取所有公开属性

        using (FileStream fs = new FileStream(filePath, FileMode.Create, FileAccess.Write))
        using (BinaryWriter writer = new BinaryWriter(fs))
        {
            // 1. 写文件头：写入类的完整名称（例：Player）
            writer.Write(type.FullName);
            
            // 2. 写入属性的数量
            writer.Write(properties.Length);

            // 3. 遍历并写入所有属性
            foreach (var prop in properties)
            {
                // 写入属性名
                writer.Write(prop.Name);
                
                // 写入属性数据类型的名称 (例如：Int32, String)
                writer.Write(prop.PropertyType.Name);
                
                // 获取该属性在当前对象上的值
                object value = prop.GetValue(obj);

                // 根据不同类型，调用对应的底层IO写入方法
                if (value == null)
                {
                    writer.Write("NULL"); // 简单处理null
                    continue;
                }

                switch (prop.PropertyType.Name)
                {
                    case "String":
                        writer.Write((string)value);
                        break;
                    case "Int32":
                        writer.Write((int)value);
                        break;
                    case "Double":
                        writer.Write((double)value);
                        break;
                    case "Boolean":
                        writer.Write((bool)value);
                        break;
                    default:
                        // 真正的商业框架会在这里处理嵌套对象、数组等复杂情况，这里我们做简化
                        throw new NotSupportedException($"暂时不支持的数据类型: {prop.PropertyType.Name}");
                }
            }
        }
        Console.WriteLine($"[通用二进制序列化] {type.Name} 对象已保存至 {filePath}");
    }

    // ==========================================
    // 复杂通用反序列化：自定义二进制文件 -> 对象
    // ==========================================
    public static T Deserialize<T>(string filePath)
    {
        if (!File.Exists(filePath)) throw new FileNotFoundException();

        T obj = Activator.CreateInstance<T>(); // 通过反射创建一个空的实例对象
        Type type = typeof(T);

        using (FileStream fs = new FileStream(filePath, FileMode.Open, FileAccess.Read))
        using (BinaryReader reader = new BinaryReader(fs))
        {
            // 1. 验证文件头（确保读的二进制文件和我们要还原的类型匹配）
            string savedTypeName = reader.ReadString();
            if (savedTypeName != type.FullName)
            {
                throw new InvalidDataException($"类型不匹配！文件记录的是 {savedTypeName}，但要求还原为 {type.FullName}");
            }

            // 2. 读取属性数量
            int propCount = reader.ReadInt32();

            // 3. 循环读取属性还原
            for (int i = 0; i < propCount; i++)
            {
                string propName = reader.ReadString();
                string propTypeName = reader.ReadString();

                // 找到对象身上对应的属性
                PropertyInfo prop = type.GetProperty(propName);

                object value = null;
                // 根据记录的类型，调用底层的Reader去读取特定字节数
                switch (propTypeName)
                {
                    case "String":
                        string strVal = reader.ReadString();
                        if (strVal != "NULL") value = strVal;
                        break;
                    case "Int32":
                        value = reader.ReadInt32();
                        break;
                    case "Double":
                        value = reader.ReadDouble();
                        break;
                    case "Boolean":
                        value = reader.ReadBoolean();
                        break;
                }

                // 如果找到了这个属性，并且可以写入，就把读到的值塞进对象里
                if (prop != null && prop.CanWrite && value != null)
                {
                    prop.SetValue(obj, value);
                }
            }
        }
        Console.WriteLine($"[通用二进制反序列化] {type.Name} 对象还原成功！");
        return obj;
    }
}
```

### 测试这个强大的通用框架
我们不但可以存 `Player`，还可以马上定义一个全新的 `Monster` 类，**完全不用改一行序列化的代码！**

```csharp
public class Monster
{
    public string Name { get; set; }
    public int Damage { get; set; }
    public bool IsBoss { get; set; }

    public override string ToString() => $"[Monster] Name:{Name}, Damage:{Damage}, IsBoss:{IsBoss}";
}

// ========== 测试代码 ==========
class Program
{
    static void Main()
    {
        // 1. 存取Player
        Player p = new Player { Name = "Geralt", Level = 99, HP = 1500.5 };
        string pPath = "universal_player.bin";
        MyUniversalBinarySerializer.Serialize(p, pPath);
        Player loadedP = MyUniversalBinarySerializer.Deserialize<Player>(pPath);
        Console.WriteLine(loadedP);

        Console.WriteLine("-------------------");

        // 2. 存取Monster（体现通用性）
        Monster m = new Monster { Name = "Dragon", Damage = 500, IsBoss = true };
        string mPath = "universal_monster.bin";
        MyUniversalBinarySerializer.Serialize(m, mPath);
        Monster loadedM = MyUniversalBinarySerializer.Deserialize<Monster>(mPath);
        Console.WriteLine(loadedM);
    }
}
```

## 第四部分：总结与通向未来

### 笔记总结（干货提炼）：
1. **IO是基础**：无论多么高级的序列化，最终都要调用 `FileStream`、`StreamWriter`、`BinaryWriter` 等IO操作落盘。序列化是**内容组织方式**，IO是**搬运工**。
2. **硬编码的局限**：手动拼接字符串容易维护灾难，缺乏扩展性。
3. **反射是魔法**：通用序列化框架的底层几乎都用到了**反射（Reflection）**，它允许代码动态探索类型的结构，从而实现“一次编写，到处适用”。
4. **格式协议**：序列化时写入什么顺序，反序列化时必须按同样顺序读取（先进先出）。

### 剧透：微软帮你写好的“外挂”
刚才我们洋洋洒洒写了上百行代码做出来的通用序列化器，其实在现代C#开发中，你**几乎永远不需要手写**。
因为业界已经制定了标准格式（比如 `JSON`, `XML`），并且微软已经写好了性能极高、支持各种复杂嵌套、泛型集合的内置框架。

当你学到后面，你会发现刚才的通用功能，只需一行代码：
```csharp
using System.Text.Json;

// 内置JSON序列化，直接把对象变成带格式的字符串，然后用你学的IO写入文件
string jsonStr = JsonSerializer.Serialize(player); 
File.WriteAllText("player.json", jsonStr);

// 内置JSON反序列化，用IO读出来，一行代码还原
string readJson = File.ReadAllText("player.json");
Player p = JsonSerializer.Deserialize<Player>(readJson);
```

**既然有一行代码的解决方案，为什么今天还要教你手写一遍？**
因为如果不经历纯手工用IO流去 `writer.Write`、去处理类型映射、去体验“读写顺序必须严格一致”的痛苦，你就永远只会是一个“调用API的熟练工”，而无法真正理解底层 JSON 框架、Protobuf 框架是如何通过 IO 流操作硬件的。
