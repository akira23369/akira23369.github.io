# 结构体：轻量级的值类型容器

## 核心分类：值类型与引用类型

在深入结构体之前，必须明确 C# 中的类型系统。C# 的数据类型在底层内存管理上被严格分为两类：

*   **值类型 (Value Types)**：包括所有的数值类型（`int`, `double` 等）、布尔型、**结构体 (struct)** 和 枚举 (enum)。
    *   **内存分配**：通常分配在**线程栈 (Stack)** 上。当方法执行结束时，栈帧弹出，内存立即被自动释放，无需垃圾回收器 (GC) 介入。
    *   **实例称呼**：值类型的实例通常被称为“实例 (Instance)”或“值”，在严格的 CLR 语境下，较少使用“对象 (Object)”一词。
*   **引用类型 (Reference Types)**：包括类 (class)、字符串 (string)、接口 (interface)、委托 (delegate) 和数组。
    *   **内存分配**：实例（对象）分配在**托管堆 (Managed Heap)** 上。栈上只保存一个指向该堆内存地址的“引用 (Reference)”。由 GC 负责内存回收。

*(注：参考《CLR via C#》的严谨定义，值类型并不总是分配在栈上。如果一个结构体是某个类的字段，那么该结构体实例将伴随类的对象一起分配在堆上。栈分配仅适用于局部变量和方法参数。)*

## 结构体的声明与基本使用

结构体与类在语法上非常相似，都可以包含字段、属性、方法、事件等成员。其主要用于封装少量相关的数据。

### 定义结构体
使用 `struct` 关键字定义。

```csharp
public struct Category
{
    // 私有字段
    private int _categoryId;
    private string _categoryName;

    // 公共属性
    public int CategoryId
    {
        get => _categoryId;
        set 
        { 
            if (value >= 1 && value <= 100) 
                _categoryId = value; 
        }
    }

    public string CategoryName
    {
        get => _categoryName;
        set 
        { 
            if (!string.IsNullOrEmpty(value) && value.Length <= 40) 
                _categoryName = value; 
        }
    }

    // 方法
    public int GetCategoryNameLength()
    {
        return _categoryName?.Length ?? 0;
    }
}
```

### 实例化与 `new` 关键字的本质差异
在结构体中，`new` 关键字的底层行为与类完全不同：
*   **对于类**：`new` 会在堆上分配内存，调用构造函数，并返回引用。
*   **对于结构体**：`new` **不会**在堆上分配内存。它仅仅是告诉编译器调用结构体的构造函数，将栈上已分配内存块中的所有字段初始化为默认值（数值为 `0`，布尔为 `false`，引用类型为 `null`）。

```csharp
public class Program
{
    public static void Main()
    {
        // 声明一个结构体变量。此时在栈上已预留内存，但字段处于未分配状态
        Category category; 

        // 必须初始化所有字段才能使用。
        // new 在这里的作用仅仅是清零内存并调用无参构造函数
        category = new Category(); 
        
        category.CategoryId = 20;
        category.CategoryName = "General";
        
        Console.WriteLine(category.GetCategoryNameLength()); // 输出: 7
    }
}
```

## 深入对比：结构体与类的核心差异

### 继承体系
*   **类**：支持单继承和多层继承。默认继承自 `System.Object`。
*   **结构体**：**绝对不支持继承**。结构体不能继承其他类或结构体，也不能被其他类型继承（结构体在底层被隐式标记为 `sealed`）。
*   **底层父类**：所有结构体隐式继承自 `System.ValueType`，而 `System.ValueType` 继承自 `System.Object`。
*   **接口**：虽然不支持类型继承，但结构体**可以实现接口**（Interfaces）。

### 修饰符与多态限制
因为结构体不支持继承：
*   不能使用 `protected` 或 `protected internal` 访问修饰符。
*   不能声明 `abstract`（抽象）或 `virtual`（虚）方法。
*   不能包含析构函数 (Destructors / Finalizers)，因为它们不受 GC 管理。

### 可空性
*   类变量默认可以赋值为 `null`。
*   结构体是值类型，**不能被赋值为 `null`**。如果需要表示缺失状态，必须使用泛型 `Nullable<T>`（语法糖为 `T?`，例如 `Category?`）。

## 现代 C# 针对结构体的重要演进 (C# 10 补充)

随着语言的演进，早期针对结构体的一些严苛限制已经被打破。结合现代 C# 规范（C# 10 及以上），需要补充以下关键更新：

### 无参构造函数
在 C# 9 及更早版本中，结构体严禁声明开发者自定义的无参构造函数。
**从 C# 10 开始，结构体允许声明显式的无参构造函数**。

### 字段初始值设定项
在 C# 9 及更早版本中，不能在声明非静态字段时直接赋初始值。
**从 C# 10 开始，允许在结构体中直接初始化非静态字段和属性**（但这必须与显式声明的构造函数配合使用）。

```csharp
// C# 10 及以上版本的合法代码
public struct ModernConfig
{
    // C# 10 允许字段/属性直接初始化
    public int Timeout { get; set; } = 30; 
    public string Environment { get; set; } = "Production";

    // C# 10 允许自定义无参构造函数
    public ModernConfig() 
    {
        // 即使有默认初始值，自定义无参构造函数中也必须确保所有字段被初始化
    }
}
```

## 架构级思考：何时使用结构体？

根据微软官方的《Framework Design Guidelines》(框架设计准则) 以及《Effective C#》的建议，选择结构体而非类必须**同时满足以下所有条件**：

1.  **逻辑上代表单个值**：例如坐标 (`Point`)、复数 (`Complex`)、全球唯一标识符 (`Guid`)。
2.  **实例极其微小**：实例的内存占用通常应**小于 16 字节**。如果结构体过大，作为方法参数按值传递（发生内存拷贝）时的性能损耗将远超栈分配带来的优势。
3.  **不可变性 (Immutability)**：强烈建议将结构体设计为**只读 (Read-Only)** 的。改变一个值类型的内部状态极易引发难以察觉的 Bug（因为修改的往往是栈上的一个临时副本）。
4.  **不需要频繁的装箱操作 (Boxing)**：如果结构体实例需要频繁被转换为 `System.Object` 或接口类型，会引发“装箱”，在堆上重新分配内存，这反而会严重拖累性能。
