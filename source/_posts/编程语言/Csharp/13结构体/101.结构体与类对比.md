# 结构体与类对比：值语义与引用语义

## 核心差异：赋值操作的本质

在 C# 中，结构体（值类型）和类（引用类型）最根本的差异体现在**赋值操作符（`=`）的行为**上。这种差异决定了数据在内存中是如何被复制和共享的。

*   **值语义 (Value Semantics)**：当把一个结构体变量赋值给另一个结构体变量时，发生的是**数据的全量拷贝（按值传递）**。两个变量在栈上拥有各自独立的内存空间，互不干扰。
*   **引用语义 (Reference Semantics)**：当把一个类的引用变量赋值给另一个引用变量时，发生的是**内存地址的拷贝（按引用传递）**。两个变量指向托管堆（Managed Heap）中的同一个对象，修改其中一个，另一个也会受到影响。

## 代码实战解析

以下代码直观地展示了两者在内存层面的运作差异：

```csharp
using System;

// 1. 定义一个结构体（值类型）
public struct PointStruct
{
    public int X;
    public int Y;
}

// 2. 定义一个类（引用类型）
public class PointClass
{
    public int X;
    public int Y;
}

public class Program
{
    public static void Main()
    {
        Console.WriteLine("--- 结构体（值类型）测试 ---");
        // 分配在栈上
        PointStruct struct1 = new PointStruct(); 
        struct1.X = 10;
        struct1.Y = 20;

        // 【关键点】发生数据拷贝！struct2 是一个全新的独立副本
        PointStruct struct2 = struct1; 
        
        // 修改 struct2 不会影响 struct1
        struct2.X = 100;
        struct2.Y = 200;

        Console.WriteLine($"struct1: X={struct1.X}, Y={struct1.Y}"); // 输出: 10, 20
        Console.WriteLine($"struct2: X={struct2.X}, Y={struct2.Y}"); // 输出: 100, 200

        Console.WriteLine("\n--- 类（引用类型）测试 ---");
        // class1 存储在栈上，实际对象存储在堆上
        PointClass class1 = new PointClass();
        class1.X = 10;
        class1.Y = 20;

        // 【关键点】发生引用拷贝！class2 和 class1 指向堆上的同一个对象
        PointClass class2 = class1; 
        
        // 修改 class2，实际上修改的是共享的堆内存对象
        class2.X = 100;
        class2.Y = 200;

        Console.WriteLine($"class1: X={class1.X}, Y={class1.Y}"); // 输出: 100, 200
        Console.WriteLine($"class2: X={class2.X}, Y={class2.Y}"); // 输出: 100, 200
    }
}
```

## 内存视角深度剖析

### 结构体的按位拷贝
当执行 `struct2 = struct1;` 时，CLR 会在当前线程的栈（Stack）上为 `struct2` 开辟一块新的内存。接着，将 `struct1` 内存区域中的数据进行**按位复制（Bitwise Copy）** 填充到 `struct2` 的内存中。此时，它们是两个完全物理隔离的数据块。

### 类的指针拷贝
当执行 `class2 = class1;` 时，由于它们是引用类型，栈上存储的仅仅是一个指向堆内存的内存地址（在 64 位系统上是 8 个字节的指针）。赋值操作仅仅将这 8 个字节的地址复制给了 `class2`。堆（Heap）上的实际对象没有任何变化，也没有被复制。

## 工程实践警示：可变结构体的陷阱

结合《Effective C#》中关于值类型的指导原则，上述实验揭示了 C# 开发中极其容易踩坑的一个反模式：**可变的结构体（Mutable Structs）**。

如果在代码中随意修改结构体的字段，极其容易因为发生隐式拷贝而导致逻辑错误。例如，将一个结构体作为参数传递给方法时：

```csharp
public void UpdatePoint(PointStruct p)
{
    // 错误预期：开发者可能以为这会修改传入的原始数据
    // 实际情况：p 只是原始数据的一份栈拷贝，修改 p 对外部毫无影响
    p.X = 999; 
}
```

**最佳实践**：
这就是为什么业界强烈建议**结构体必须是不可变的（Immutable）**。如果结构体通过 `readonly struct` 定义，从根本上杜绝了对内部字段的修改，开发者就必须通过创建新实例来改变数据，从而彻底消除了“修改了副本却以为修改了原件”的逻辑隐患。
