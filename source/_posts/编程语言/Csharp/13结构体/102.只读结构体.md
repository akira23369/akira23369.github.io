# 只读结构体：不可变性与极致性能

## 核心概念与设计哲学

只读结构体 (`readonly struct`) 是一种强制实现**不可变性 (Immutability)** 的数据类型（该特性在 C# 7.2 引入，并在后续版本中持续增强）。当使用 `readonly` 修饰 `struct` 关键字时，编译器会强制要求该结构体内部的所有状态在初始化之后绝对不能被修改。

在复杂系统（如高并发的电商系统或游戏引擎）中，不可变的数据结构天然具备**线程安全 (Thread-Safe)** 的特性，因为没有线程可以修改它的状态，从而彻底消除了竞态条件 (Race Conditions)。

## 严格的编译期规则

一旦结构体被声明为 `readonly struct`，编译器将施加以下严格的限制：

1.  **字段必须只读**：所有的实例字段（包括私有字段）都必须使用 `readonly` 修饰符。
2.  **属性仅限 Get**：所有的属性只能是只读属性（只有 `get` 访问器，或者使用 C# 9+ 的 `init` 访问器）。
3.  **方法禁止变异**：结构体内的任何普通方法都只能读取数据，绝不允许对任何字段重新赋值。
4.  **唯一的赋值窗口**：唯独在**构造函数**中，允许对这些只读字段或属性进行初始化赋值。

### 代码实战：声明与使用只读结构体

以下代码展示了一个标准只读结构体的定义规则。假设我们需要在一个电商系统中定义一个不可变的“折扣活动”或“游戏角色”。

```csharp
using System;

// 声明为 readonly struct
public readonly struct MarvelCharacter
{
    // 1. 字段必须标记为 readonly
    private readonly string _characterName;

    // 2. 属性只能有 get 访问器
    public string CharacterName => _characterName;

    // 3. 构造函数是唯一合法的赋值入口
    public MarvelCharacter(string name)
    {
        _characterName = name;
    }

    // 4. 方法只能读取，不能修改状态
    public void PrintInfo()
    {
        // 如果这里尝试 _characterName = "hachimi"; 会导致编译失败
        Console.WriteLine($"Character: {CharacterName}");
    }
}

public class Program
{
    public static void Main()
    {
        // 初始化后，状态被永久冻结
        MarvelCharacter thanos = new MarvelCharacter("Thanos");
        thanos.PrintInfo();
    }
}
```

## 内存与性能剖析 (深入底层机制)

视频中提到“只读结构体能提升性能”，但其实际的底层原理值得结合《Effective C#》与《C# in Depth》进行深入剖析。其核心性能优势在于**消除了防御性复制 (Defensive Copies)**。

### 什么是防御性复制？
在 C# 中，如果我们把一个普通的（非 readonly）结构体声明为类的 `readonly` 字段，或者将其作为 `in` 参数传递给方法，编译器为了保证原本的数据不被意外篡改，在调用该结构体的任何方法或属性时，都会在栈上**隐式地创建一份克隆副本（防御性复制）**，然后在副本上执行方法。

这种隐藏的内存拷贝操作在高性能场景（如循环处理大量物理坐标）中会带来灾难性的性能损耗。

### `readonly struct` 的真正威力
当我们明确将结构体声明为 `readonly struct` 时，等于向编译器做出了“这个类型绝对不会改变自身状态”的担保。此时，编译器在将其作为 `in` 参数按引用传递，或者调用其只读字段的方法时，**不再需要创建防御性副本**。它能够直接通过指针访问原数据，从而实现内存的零分配和极高的执行效率。

## 补充进阶：只读成员(C# 8.0 特性)

有时候，由于要兼容老旧代码，我们无法将整个结构体声明为 `readonly struct`（因为它可能包含一些必须可变的字段）。为了在非只读结构体中也获得类似的安全性和部分性能提升，C# 8.0 引入了**只读成员**。

我们可以将结构体中的某一个具体方法或属性单独标记为 `readonly`，向编译器保证这个特定方法不会修改任何状态。

```csharp
public struct Point
{
    public double X { get; set; } // 可变属性
    public double Y { get; set; }

    // C# 8.0 特性：仅将特定方法标记为 readonly
    public readonly double GetDistance()
    {
        // 保证该方法只读不写
        return Math.Sqrt(X * X + Y * Y);
    }

    public readonly override string ToString() => $"({X}, {Y})";
}
```
**架构级建议**：在开发现代 C# 应用时，只要值类型的语义在逻辑上代表一个一旦生成就不应改变的单一值（如：颜色值、坐标、配置项），就应当毫不犹豫地将其设计为 `readonly struct`。
