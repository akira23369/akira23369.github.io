# 结构体构造函数

## 结构体中 `new` 关键字的底层逻辑

在类（引用类型）中，`new` 关键字负责在托管堆（Managed Heap）上分配内存并返回对象的内存地址。然而，在结构体（值类型）中使用 `new` 关键字调用构造函数时，底层行为完全不同。

根据《CLR via C#》的解析，对于结构体，`new` 关键字**绝对不会在堆上分配任何内存**。它的真实作用仅仅是：
1. 在当前线程栈（Stack）上为该结构体划分出一块内存区域。
2. 将这块内存区域“清零”（所有数值类型设为 0，引用类型设为 null）。
3. 执行调用的构造函数内部的代码。

因此，在结构体中使用 `new` 关键字仅仅是显式调用构造函数的语法要求，不涉及任何垃圾回收（GC）开销。

## 参数化构造函数

结构体通常用于封装小型的、相关联的数据集。通过定义参数化构造函数，可以在声明结构体实例的同时完成数据的初始化，避免在实例化后逐个调用属性赋值的繁琐操作。

### 传统的强制赋值规则 (C# 10 及更早版本)
在早期的 C# 规范中，编译器对结构体的构造函数有一项极其严格的规则：**在构造函数执行结束前，必须对结构体内的每一个字段（包括自动属性背后的隐藏字段）进行明确赋值 (Definite Assignment)。** 如果遗漏了任何一个字段，将导致编译期错误。

```csharp
public struct Category
{
    private int _categoryId;
    private string _categoryName;

    // 参数化构造函数
    public Category(int id, string name)
    {
        _categoryId = id;
        
        // 早期 C# 编译器报错：控制离开构造函数前，未对字段 "_categoryName" 赋值
        // _categoryName = name; 
    }
}
```

## 现代 C# 针对结构体构造函数的重大革新

随着 C# 语言的演进（特别是 C# 10 和 C# 11 的发布），上述传统的严格限制已经被大幅度放宽，这极大地改善了开发体验。

### 允许显式无参构造函数 (C# 10+)
在早期版本中，结构体严禁包含开发者自定义的无参构造函数（编译器会强行提供一个默认的）。从 C# 10 开始，允许显式定义无参构造函数，以便在类型初始化时执行特定逻辑。

```csharp
public struct Category
{
    public int CategoryId { get; set; }
    public string CategoryName { get; set; }

    // C# 10 引入：允许显式无参构造函数
    public Category()
    {
        CategoryId = 1;
        CategoryName = "Uncategorized";
    }
}
```

### 自动初始化未赋值字段 (C# 11+)
从 C# 11 开始，编译器**取消了**“构造函数必须明确赋值所有字段”的严苛要求。如果在构造函数中遗漏了对某个字段的赋值，编译器会自动将其初始化为该类型的默认值（`default`）。

```csharp
public struct Category
{
    public int CategoryId;
    public string CategoryName;

    // C# 11 开始，这段代码完全合法！
    public Category(int id)
    {
        CategoryId = id;
        // CategoryName 未被赋值，编译器会自动将其安全地设为 null
    }
}

public class Program
{
    public static void Main()
    {
        // 实例化，调用参数化构造函数
        Category cat = new Category(101);
    }
}
```

## 架构最佳实践：《Effective C#》指南

在实际的工程开发中，为结构体编写构造函数时，强烈建议结合**不可变性 (Immutability)** 来进行设计。

根据《Effective C#》以及微软的《框架设计准则》，**结构体应该被设计为只读的（Read-Only）**。可变的值类型在作为参数传递、装箱/拆箱或者在多线程环境下极易引发难以排查的 Bug。

现代 C# 推荐直接使用 `readonly struct`，并通过构造函数一次性完成不可变数据的初始化：

```csharp
// 最佳实践：使用 readonly 强制结构体不可变
public readonly struct Category
{
    // 使用只读属性（仅包含 get）
    public int CategoryId { get; }
    public string CategoryName { get; }

    // 唯一的数据写入入口：构造函数
    public Category(int id, string name)
    {
        CategoryId = id;
        CategoryName = name;
    }
}
```
通过这种方式，一旦 `Category` 被实例化，其内部状态就永远无法被修改。任何对数据的变更都需要通过构造函数创建一个全新的结构体实例。这保证了代码的绝对安全性和高可预测性。
