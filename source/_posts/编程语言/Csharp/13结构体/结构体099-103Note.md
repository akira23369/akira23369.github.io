# 第14节：结构体

## 第一讲：结构体简介与使用

### 引言
**struct（结构体）** 是一种复合数据类型，允许将一组相关变量组合在单一名称下。结构体最重要的特性在于它是**值类型**，这从根本上将其与作为引用类型的 class 区分开来。这种差异决定了结构体在内存中的存储方式、在方法间的传递方式以及在赋值时的行为表现。

结构体通常用于创建轻量级的小型对象，这些对象在逻辑上表示单一值，例如坐标点、颜色或一对相关联的数字。

### 工作原理：值类型语义与内存
由于结构体是值类型，结构体类型的变量持有的是**实际数据本身**，而非对数据的引用（或指针）。

- **内存分配**： 结构体几乎总是分配在**栈上**——这是一个非常快速高效的内存区域。当方法调用结束时，其中创建的所有结构体会随着栈帧弹出而立即释放。这避免了堆上类对象所需的垃圾回收开销。
- **赋值行为**： 当将一个结构体变量赋值给另一个时，会创建数据的**完整副本**。每个变量都将拥有自己独立的实例。

### 示例：演示赋值时复制行为
让我们创建一个简单的 Point 结构体来观察这一行为。

```csharp
public struct Point
{
    // 默认情况下，结构体中的字段应该设为公共以方便访问，
    // 因为结构体主要用作简单的数据容器。
    public int X;
    public int Y;
}

public class Program
{
    public static void Main(string[] args)
    {
        // point1 直接持有自己的 X 和 Y 值。
        Point point1 = new Point();
        point1.X = 10;
        point1.Y = 20;

        // 当我们将 point1 赋值给 point2 时，会创建数据的完整副本。
        // point2 现在是一个新的、独立的实例，拥有相同的值。
        Point point2 = point1;

        Console.WriteLine($"Before change: point1=({point1.X}, {point1.Y}), point2=({point2.X}, {point2.Y})");

        // 现在，修改第一个点的 X 值。
        point1.X = 99;
        Console.WriteLine("\n--- Changed point1.X to 99 ---");

        // 更改仅影响 point1。point2 完全不受影响，
        // 因为它是一个独立的副本。
        Console.WriteLine($"After change: point1=({point1.X}, {point1.Y}), point2=({point2.X}, {point2.Y})");
    }
}
```

**输出结果**：
```
Before change: point1=(10, 20), point2=(10, 20)

--- Changed point1.X to 99 ---
After change: point1=(99, 20), point2=(10, 20)
```

## 第二讲：带构造器的结构体

### 引言
和类一样，结构体也可以声明构造函数来初始化其字段。使用构造函数是创建结构体实例的首选方式，它能确保实例从一开始就处于有效且可预测的状态，而不是在创建后手动设置每个字段。

### 工作原理与规则
结构体构造函数有一些与类构造函数不同的特定规则：
1. **带参构造函数**： 可以定义接收参数的构造函数。在带参构造函数中，你**必须初始化结构体的所有实例字段**。C#编译器会强制执行此规则以确保结构体完全初始化。
2. **隐式无参构造函数**： 每个结构体始终有一个内置的无参构造函数，它会将所有字段初始化为系统默认值（0、false、null）。你不能删除或覆盖这个默认行为。
3. **显式无参构造函数（C# 10+）**： 在现代 C#（10 及以上版本）中，您现在可以显式声明自己的公共无参构造函数，以提供不同的默认初始化逻辑。不过，隐式无参构造函数在幕后仍然存在。

### 示例
让我们为 Point 结构体添加构造函数，使初始化更加简洁。

```csharp
public struct Point
{
    public int X;
    public int Y;

    // 一个公共的带参构造函数。
    public Point(int x, int y)
    {
        // 必须在此构造函数中初始化所有字段。
        // 如果注释掉任意一行，都会导致编译器错误。
        this.X = x;
        this.Y = y;
    }

    public void Display()
    {
        Console.WriteLine($"({X}, {Y})");
    }
}

public class Program
{
    public static void Main(string[] args)
    {
        // 1. 使用默认的无参构造函数创建点。
        // X 和 Y 都将初始化为 0。
        Point origin = new Point();
        Console.Write("Origin point: ");
        origin.Display(); // 输出: (0, 0)

        // 2. 使用自定义的带参构造函数创建点。
        Point p1 = new Point(15, 25);
        Console.Write("Custom point: ");
        p1.Display(); // 输出: (15, 25)
    }
}
```

## 第三讲：结构体与类

### 引言
掌握何时使用 struct 而非 class 是每个 C#开发者必备的关键技能。这是最基础且最常被问到的面试题之一，因为这一选择对内存管理、性能和程序行为有着重大影响。核心区别在于**结构体是值类型**，而**类是引用类型**。

### 详细对比
| 维度    | 类                                     | 结构体                                   |
| ----- | ------------------------------------- | ------------------------------------- |
| 类型与内存 | 引用类型。对象创建在**堆内存**（由垃圾回收器管理）中，变量仅保存引用。 | 值类型。对象通常创建在**栈上**（快速临时内存），变量直接持有实际数据。 |
| 赋值行为  | 赋值时复制**引用**，两个变量指向同一个对象。              | 赋值时复制**全部数据**，创建新的独立实例。               |
| 方法传参  | 传递引用的副本，方法可修改原始对象状态。                  | 传递结构体的完整副本，方法内修改不影响原始结构体。             |
| 继承    | 支持单继承，可继承另一个类。                        | 不支持继承（仅隐式继承自 System.ValueType）。       |
| 默认值   | 默认值为 null（不引用任何对象）。                   | 默认值是字段全为默认值的结构体实例，永远不为 null。          |

### 实用示例：方法传递测试
此示例清晰地展示了将类与结构体传递给方法时行为上的根本差异。

```csharp
// 类（引用类型）
public class ClassPoint { public int X; }

// 结构体（值类型）
public struct StructPoint { public int X; }

public class Program
{
    // 此方法尝试修改接收到的对象的 X 值。
    public static void TryToChangeValue(ClassPoint cp, StructPoint sp)
    {
        cp.X = 100;
        sp.X = 100;
    }

    public static void Main(string[] args)
    {
        ClassPoint myClassPoint = new ClassPoint();
        myClassPoint.X = 10;

        StructPoint myStructPoint = new StructPoint();
        myStructPoint.X = 10;

        Console.WriteLine($"Before method call: ClassPoint.X = {myClassPoint.X}, StructPoint.X = {myStructPoint.X}");

        // 将两者都传递给方法。
        TryToChangeValue(myClassPoint, myStructPoint);

        Console.WriteLine($"After method call:  ClassPoint.X = {myClassPoint.X}, StructPoint.X = {myStructPoint.X}");
    }
}
```

**输出结果**：
```
Before method call: ClassPoint.X = 10, StructPoint.X = 10
After method call:  ClassPoint.X = 100, StructPoint.X = 10
```

**结论**： 对 ClassPoint 的修改得以保留，因为方法接收的是原始对象的引用。而对 StructPoint 的修改丢失了，因为方法仅操作了一个临时副本。

### 面试视角：何时应该使用结构体？
**理想答案**： "默认情况下应使用 class。仅当类型满足以下多个条件时才考虑使用 struct：逻辑上表示**单一值**（如数字或坐标），**体积小**（通常小于 16 字节），**不可变**（创建后不会改变），且不会频繁进行'装箱'或拆箱操作。"

## 第四讲：只读结构体

### 引言
**readonly struct** 是一种特殊结构体类型，被声明为**不可变**。这意味着结构体实例一旦创建，在其整个生命周期内状态都不可改变。这为不可变性提供了强大的编译时保证。

### 工作原理
当在结构体声明中添加 readonly 修饰符时，C#编译器会强制执行两条规则：
1. 结构体中的所有实例字段都必须声明为 readonly。
2. 由于所有字段都是 readonly，它们只能在声明时或在结构体的构造函数中赋值。

这确保了结构体真正成为一份不可更改的数据"快照"。

### 为何及何时使用
当需要创建小型、轻量级且保证不可变的数据中心类型时，使用 readonly struct。这在以下场景中特别有用：
- 创建可预测且安全的代码，特别是在多线程应用中，因为不可变类型天生具备线程安全性。
- 防止数据被意外修改。
- 明确传达设计意图：该对象仅作为"值"使用，其状态不应被改变。

### 示例
Color 或 RgbValue 是 readonly struct 的完美候选类型。

```csharp
public readonly struct RgbColor
{
    // 所有字段必须是 readonly。
    public readonly byte R;
    public readonly byte G;
    public readonly byte B;

    public RgbColor(byte r, byte g, byte b)
    {
        // 值只能在构造函数中设置。
        this.R = r;
        this.G = g;
        this.B = b;
    }

    public void ChangeRed(byte newRed)
    {
        // 以下行会导致编译器错误，因为 R 是 readonly。
        // this.R = newRed; // 错误！无法赋值给 'R'，因为它是只读字段。
    }
}

// --- 在 Main 方法中 ---
RgbColor myColor = new RgbColor(255, 165, 0); // 橙色
// 'myColor' 现在是不可变的。其状态无法被更改。
```

## 第五讲：原始类型即结构

### 引言
本讲座揭示了 C#类型系统的一个基本事实，这澄清了我们目前所见的大部分行为。我们认为是内置关键字的大多数基本类型，实际上只是 C#为 .NET 的 System 命名空间中定义的 struct 类型提供的**便捷别名**。

### 工作原理：关键词作为别名
以下是一些最常见的基元类型及其对应结构的列表：
- int 是 System.Int32 的别名
- double 是 System.Double 的别名
- bool 是 System.Boolean 的别名
- char 是 System.Char 的别名
- long 是 System.Int64 的别名
- decimal 是 System.Decimal 的别名

### 其含义
由于这些基础类型是结构体，因此它们都是值类型。这一关键事实解释了它们的核心行为：
- 它们存储在栈上，这使得操作速度更快。
- 当你将一个 int 变量赋值给另一个时，会复制该值。
- 当你将 int 传递给方法时，传递的是值的副本。
- 它们不能为 null（因为它们不是引用类型）。
- 由于它们是功能完备的结构体，你甚至可以在它们上调用方法。

```csharp
int myNumber = 123;

// 我们正在调用 System.Int32 结构体的 ToString() 方法。
string myString = myNumber.ToString(); 

// 甚至可以直接对字面量值调用方法！
Console.WriteLine(123.ToString());
```

### 面试视角
**问题**："C# 中的 int 是基本类型还是对象？"

**理想答案**："在 C# 中，int 是 System.Int32 结构体的别名。由于它是结构体，因此属于值类型。但所有 .NET 中的结构体都隐式继承自 System.ValueType，而后者又继承自 System.Object，所以在需要时可以像对象一样处理（这个过程称为装箱），从而拥有诸如 ToString() 之类的方法。"

## 第六讲：需要记住的重要知识点

1. **结构体是值类型，类是引用类型**： 这是最重要的区别。它决定了它们在内存中的存储方式（栈 vs 堆）、赋值时的行为（复制 vs 引用）以及传递给方法的方式。
2. **结构体的性能优势**： 由于结构体通常分配在栈上，它们不会产生需要垃圾回收器清理的"垃圾"。对于需要创建和销毁数百万个小对象的应用程序，使用结构体可以带来显著的性能提升。
3. **复制行为是一把双刃剑**： 结构体在赋值时会被复制，这可以防止代码的某一部分意外改变另一部分使用的值。但如果你期望的是引用行为，这可能会成为 bug 的来源。在将结构体传递给方法时，请始终注意这一点。
4. **默认选择 class**： 这是微软的官方建议。C#语言和运行时对类进行了高度优化。只有当你有特定的性能相关原因，并且创建的类型符合以下标准时，才应选择使用 struct：它很小，逻辑上表示单个值，并且最好是不可变的。
5. **拥抱 readonly struct 的不可变性**： readonly struct 是创建安全、可预测值类型的强大功能。当一个类型在创建后没有理由改变其状态时，将其设为 readonly struct 是一个绝佳的设计选择。
6. **所有"基元类型"都是结构体**： 记住 int、double、bool 等类型本质上都是结构体，这为理解 C#的类型系统提供了一个统一的心智模型。
