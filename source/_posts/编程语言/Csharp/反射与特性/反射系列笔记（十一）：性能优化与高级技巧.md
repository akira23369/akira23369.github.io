# C# 反射系列笔记（十一）：性能优化与高级技巧

> **学习目标**：全面掌握 C# 中反射性能的瓶颈与优化技术，深入理解从装箱拆箱到元数据查找的各种反射开销。掌握使用委托缓存（Delegate）、表达式树（Expression Tree）以及底层动态指令生成（IL Emit）等高级黑科技，最终在高频调用场景下，将反射执行的性能优化至几乎与原生硬编码调用齐平的境界。

---

## 一、反射的性能问题根源

在深入优化之前，我们必须先做“病理分析”。许多开发者只知道“反射慢”，却不知道究竟慢在哪个环节。理解这些底层机制，是进行针对性优化的前提。

### 为什么反射慢？

反射之所以慢，是因为它绕过了编译器的静态检查阶段，将许多原本在编译期完成的工作（如地址绑定、类型安全验证）推迟到了运行期。以下是反射操作中主要的性能消耗大户：

| 开销来源          | 原理说明                                                                             | 性能影响级别          |
| ------------- | -------------------------------------------------------------------------------- | --------------- |
| **参数装箱与拆箱**   | 当反射调用传递值类型（如 `int`, `struct`）时，由于 `Invoke` 方法接收的是 `object`，必须在堆上分配内存进行装箱，返回时再拆箱。 | 🔴 极高（引发频繁 GC）  |
| **数组内存分配**    | `MethodInfo.Invoke` 强制要求传入 `object[]` 作为参数，每次调用都会在堆上 `new` 一个新数组。                | 🔴 极高           |
| **动态安全与类型检查** | CLR 必须在运行时验证你是否有权限访问该私有成员，以及传入的参数类型是否与方法签名绝对匹配。                                  | 🟡 中            |
| **元数据字符串匹配**  | 使用 `GetMethod("Name")` 时，CLR 需要遍历程序集元数据表，进行低效的字符串比对。                             | 🟡 中（但极易通过缓存消除） |
| **阻断 JIT 优化** | 编译器无法预知反射调用的具体目标，因此无法进行方法内联（Inlining）等高级机器码优化。                                   | 🔴 极高           |

### 基准测试：各种调用方式对比

为了直观感受不同调用方式的性能落差，我们编写一个基准测试。我们将模拟一个电商场景中的 `ShoppingCart`（购物车），对其进行上千万次的金额计算操作，观察不同反射手段的耗时。

```csharp
using System;
using System.Diagnostics;
using System.Reflection;
using System.Linq.Expressions;

public class ReflectionPerformanceTest
{
    private const int RunCount = 10_000_000; // 一千万次迭代
    
    // 模拟测试用的业务类
    public class ShoppingCart
    {
        public double TotalAmount;
        // 实例方法
        public double CalculateDiscount(double price, double discountRate) => price * discountRate;
    }
    
    public static void ExecuteBenchmarks()
    {
        var cart = new ShoppingCart();
        var type = typeof(ShoppingCart);
        var methodInfo = type.GetMethod(nameof(ShoppingCart.CalculateDiscount));
        var fieldInfo = type.GetField(nameof(ShoppingCart.TotalAmount));
        
        Console.WriteLine($"====== 测试开始 (迭代: {RunCount:N0} 次) ======\n");
        
        // 1. 原生直接调用（性能天花板基准）
        Benchmark("1. 原生直接调用", () => 
        {
            for (int i = 0; i < RunCount; i++) cart.CalculateDiscount(100.0, 0.8);
        });
        
        // 2. 纯反射调用（每次都分配 object[] 和装箱）
        Benchmark("2. MethodInfo 反射调用", () => 
        {
            // 注意：参数 { 100.0, 0.8 } 每次循环都在隐式创建 object[] 并装箱 double
            for (int i = 0; i < RunCount; i++) methodInfo.Invoke(cart, new object[] { 100.0, 0.8 });
        });
        
        // 3. 提取委托调用（强类型，无装箱，无数组分配）
        var strongDelegate = (Func<ShoppingCart, double, double, double>)Delegate.CreateDelegate(
            typeof(Func<ShoppingCart, double, double, double>), methodInfo);
        Benchmark("3. 强类型委托调用", () => 
        {
            for (int i = 0; i < RunCount; i++) strongDelegate(cart, 100.0, 0.8);
        });
        
        // 4. 表达式树编译调用（动态生成最优执行代码）
        var instanceParam = Expression.Parameter(typeof(ShoppingCart), "cart");
        var p1 = Expression.Parameter(typeof(double), "price");
        var p2 = Expression.Parameter(typeof(double), "rate");
        var callExpr = Expression.Call(instanceParam, methodInfo, p1, p2);
        var compiledFunc = Expression.Lambda<Func<ShoppingCart, double, double, double>>(
            callExpr, instanceParam, p1, p2).Compile();
            
        Benchmark("4. 表达式树编译调用", () => 
        {
            for (int i = 0; i < RunCount; i++) compiledFunc(cart, 100.0, 0.8);
        });

        Console.WriteLine("\n--- 字段访问性能对比 ---");
        
        Benchmark("A. 直接字段赋值", () => { for (int i = 0; i < RunCount; i++) cart.TotalAmount = i; });
        Benchmark("B. 反射字段赋值", () => { for (int i = 0; i < RunCount; i++) fieldInfo.SetValue(cart, (double)i); });
    }
    
    // 简易性能测试计时器包装
    static void Benchmark(string name, Action action)
    {
        // 先执行一次，预热 JIT 编译器
        action.Invoke(); 
        var sw = Stopwatch.StartNew();
        action.Invoke();
        sw.Stop();
        Console.WriteLine($"{name,-20} 耗时: {sw.ElapsedMilliseconds,4} ms");
    }
}
```

**深入分析结果：**
你会发现，原生调用的耗时仅在几十毫秒。而 `MethodInfo.Invoke` 的耗时可能高达数千毫秒，差距在数十倍以上。然而，**强类型委托**和**表达式树**的耗时却能做到与原生调用几乎持平（只有极其微小的委托调用自身开销）。这证明了：反射本身查找元数据的开销是一次性的，只要避免了运行时的动态调度和参数装箱，动态执行可以极其高效。

**关于Delegate.CreateDelegate的疑惑：**
C# 允许你把实例方法的第一个参数"腾出来"，让**实例本身作为委托的第一个参数**。
```cs
// 场景：要调用 1000 个 ShoppingCart 的 CalculateDiscount

// ❌ 低效：创建 1000 个封闭委托
foreach (var cart in carts)
{
    var del = (Func<double,double,double>)Delegate.CreateDelegate(
        typeof(Func<double,double,double>), cart, method);  // 每次新建委托
    del(price, rate);
}

// ✅ 高效：只创建 1 个开放委托，复用调用所有实例
var openDel = (Func<ShoppingCart,double,double,double>)Delegate.CreateDelegate(
    typeof(Func<ShoppingCart,double,double,double>), method);  // 只创建一次
    
foreach (var cart in carts)
{
    openDel(cart, price, rate);  // 复用委托，只传不同实例
}
```

## 二、高性能反射策略

了解了性能瓶颈后，我们开始对症下药。日常开发中，根据你的封装深度和泛型使用情况，可以选择不同层级的优化策略。

### 策略一：缓存一切 (元数据缓存)

最基础也是最有效的优化第一步，就是避免重复遍历元数据。`typeof(T).GetProperties()` 底层会克隆数组，极其浪费资源。我们应当使用线程安全的字典将查找到的 `MethodInfo`、`PropertyInfo` 等缓存起来。

```csharp
using System;
using System.Collections.Concurrent;
using System.Reflection;

public static class MetaDataCache
{
    // 使用 ConcurrentDictionary 保证高并发场景下的线程安全
    // 键通常为类型的句柄或 FullName，值为属性信息的数组
    private static readonly ConcurrentDictionary<Type, PropertyInfo[]> _typePropertiesCache = new();
    
    // 复合键：类型 + 方法名
    private static readonly ConcurrentDictionary<string, MethodInfo> _methodCache = new();

    /// <summary>
    /// 获取类型的全部公共实例属性（带缓存）
    /// </summary>
    public static PropertyInfo[] GetCachedProperties(Type type)
    {
        // GetOrAdd：如果缓存存在则直接返回，不存在则执行后面的 lambda 进行反射查找并存入缓存
        return _typePropertiesCache.GetOrAdd(type, t => 
            t.GetProperties(BindingFlags.Public | BindingFlags.Instance));
    }

    /// <summary>
    /// 获取指定方法（带缓存）
    /// </summary>
    public static MethodInfo GetCachedMethod(Type type, string methodName)
    {
        // 构造唯一键。注意：若存在重载方法，键名需包含参数类型
        string cacheKey = $"{type.FullName}::{methodName}";
        
        return _methodCache.GetOrAdd(cacheKey, _ => 
            type.GetMethod(methodName, BindingFlags.Public | BindingFlags.NonPublic | BindingFlags.Instance));
    }
}

// 业务调用示例
// 即使在一个一万次的循环中调用，真实反射操作也只发生第一次
var props = MetaDataCache.GetCachedProperties(typeof(DateTime));
```

### 策略二：委托缓存工厂 (Delegate Factory)

缓存了 `MethodInfo` 依然不能解决 `Invoke` 带来的装箱和数组分配问题。如果我们在编译时知道方法的泛型签名，最好的办法是使用 `Delegate.CreateDelegate` 将 `MethodInfo` 转换为真正的 C# 委托。

```csharp
using System;
using System.Collections.Concurrent;
using System.Reflection;

public static class FastDelegateBuilder
{
    // 缓存生成的强类型委托
    private static readonly ConcurrentDictionary<string, Delegate> _delegateCache = new();

    /// <summary>
    /// 为实例方法创建高性能委托（签名：TTarget -> TParam -> TResult）
    /// </summary>
    public static Func<TTarget, TParam, TResult> BuildInstanceMethod<TTarget, TParam, TResult>(string methodName)
    {
        string key = $"InstMethod_{typeof(TTarget).Name}_{methodName}";

        return (Func<TTarget, TParam, TResult>)_delegateCache.GetOrAdd(key, _ =>
        {
            // 1. 查找元数据
            var methodInfo = typeof(TTarget).GetMethod(methodName, new[] { typeof(TParam) });
            if (methodInfo == null) throw new MissingMethodException(typeof(TTarget).Name, methodName);

            // 2. 将 MethodInfo 包装为 Func 委托
            // 注意：对于实例方法，委托的第一个参数必须是实例对象本身 (TTarget)
            return Delegate.CreateDelegate(typeof(Func<TTarget, TParam, TResult>), methodInfo);
        });
    }

    /// <summary>
    /// 为属性 Getter 创建读取委托
    /// </summary>
    public static Func<TTarget, TProperty> BuildPropertyGetter<TTarget, TProperty>(string propName)
    {
        string key = $"Getter_{typeof(TTarget).Name}_{propName}";

        return (Func<TTarget, TProperty>)_delegateCache.GetOrAdd(key, _ =>
        {
            var propInfo = typeof(TTarget).GetProperty(propName);
            // 属性的 Get 操作本质上就是调用 get_PropertyName 方法
            return Delegate.CreateDelegate(typeof(Func<TTarget, TProperty>), propInfo.GetMethod);
        });
    }
}

// 业务调用示例：
public class MathService { public int Square(int x) => x * x; }

// 建立委托（仅发生一次反射开销）
var fastSquare = FastDelegateBuilder.BuildInstanceMethod<MathService, int, int>("Square");

// 后续调用如同直接调用，无性能损耗
var service = new MathService();
int result = fastSquare(service, 5); // 输出 25
```

### 策略三：表达式树编译 (Expression Trees)

策略二虽然快，但它要求你必须在编译期通过泛型（如 `TTarget`, `TParam`）确切知道类型。如果你在开发一个完全动态的框架（如 JSON 序列化器或 ORM），你拿到的是未知数量的 `object[]` 参数。此时，**表达式树（Expression Tree）** 是最佳选择，它允许我们在运行时动态拼装一段 C# 逻辑，然后将其编译成机器码。

```csharp
using System;
using System.Linq.Expressions;
using System.Reflection;

public static class DynamicExpressionCompiler
{
    /// <summary>
    /// 万能对象实例化器：生成规避 Activator.CreateInstance 性能损耗的委托
    /// 返回签名：Func<object[], object>
    /// </summary>
    public static Func<object[], object> BuildConstructor(Type targetType)
    {
        // 获取所有构造函数，为了演示，这里简单取参数最多的一个
        var ctor = targetType.GetConstructors().OrderByDescending(c => c.GetParameters().Length).First();
        var parameters = ctor.GetParameters();

        // 定义传入的参数：object[] args
        var argsParameter = Expression.Parameter(typeof(object[]), "args");
        
        // 构造参数读取表达式，例如：(string)args[0], (int)args[1]
        var argsExpressions = new Expression[parameters.Length];
        for (int i = 0; i < parameters.Length; i++)
        {
            // 读取 args[i]
            var arrayAccess = Expression.ArrayIndex(argsParameter, Expression.Constant(i));
            // 拆箱/强制类型转换，转换为构造函数需要的真实类型
            argsExpressions[i] = Expression.Convert(arrayAccess, parameters[i].ParameterType);
        }

        // 构造 new TargetType(...) 表达式
        var newExpression = Expression.New(ctor, argsExpressions);
        
        // 由于返回类型必须是 object，如果是值类型或者需要统一接口，在此做向上转型
        var castToObject = Expression.Convert(newExpression, typeof(object));

        // 包装为 Lambda 并编译为可执行委托
        var lambda = Expression.Lambda<Func<object[], object>>(castToObject, argsParameter);
        return lambda.Compile();
    }
}

// 业务调用示例：
public class Employee 
{ 
    public Employee(string name, int age) { /*...*/ } 
}

// 生成委托（耗时操作，需缓存）
var fastActivator = DynamicExpressionCompiler.BuildConstructor(typeof(Employee));

// 极速创建对象，比 Activator.CreateInstance 快数倍
object newEmp = fastActivator(new object[] { "Alice", 28 });
```

## 三、高级技巧：IL Emit

如果你追求极致到连表达式树的微小开销都不想忍受，或者需要动态创建全新的类（而不仅仅是执行方法），你就需要踏入 C# 魔法的禁区——**IL Emit (中间语言发射器)**。

### IL Emit 简介

IL (Intermediate Language) 是 C# 编译后的底层指令（类似汇编）。使用 Emit，我们直接将操作码（OpCodes）写入内存并构建成可执行代码。它的执行速度等于原生代码，但编写和调试难度极高，写错一个压栈弹栈指令就会导致程序崩溃（`InvalidProgramException`）。

```csharp
using System;
using System.Reflection;
using System.Reflection.Emit;

public static class ILGeneratorMagic
{
    /// <summary>
    /// 使用 Emit 动态生成极其暴力的属性 Getter 委托
    /// </summary>
    public static Func<object, object> CreateFastGetterViaIL(PropertyInfo property)
    {
        // 1. 定义一个轻量级的动态方法 (DynamicMethod)
        var dynamicMethod = new DynamicMethod(
            name: $"EmitGet_{property.Name}",
            returnType: typeof(object),           // 返回 object
            parameterTypes: new[] { typeof(object) }, // 参数是实例的 object
            owner: property.DeclaringType,        
            skipVisibility: true);                // 核心：设为 true 可以无视 private/protected 访问权限！

        // 2. 获取 IL 生成器
        ILGenerator il = dynamicMethod.GetILGenerator();

        // 3. 开始写 "汇编"
        // 步骤 1: 将第一个参数 (object) 压入执行栈
        il.Emit(OpCodes.Ldarg_0);
        
        // 步骤 2: 将 object 强转为实际类型 (例如 User)
        il.Emit(OpCodes.Castclass, property.DeclaringType);
        
        // 步骤 3: 调用属性的底层 get 方法。Callvirt 用于调用实例方法
        il.EmitCall(OpCodes.Callvirt, property.GetMethod, null);
        
        // 步骤 4: 处理返回值。如果属性是值类型 (如 int)，必须装箱(Box)成 object 才能返回
        if (property.PropertyType.IsValueType)
        {
            il.Emit(OpCodes.Box, property.PropertyType);
        }
        
        // 步骤 5: 将栈顶元素返回
        il.Emit(OpCodes.Ret);

        // 4. 将动态方法烘焙成委托
        return (Func<object, object>)dynamicMethod.CreateDelegate(typeof(Func<object, object>));
    }
}
```

### 动态类型生成（TypeBuilder）

当我们需要在运行时无中生有地创造一个**类**时（比如 Entity Framework 中的延迟加载代理类，或者 RPC 框架的客户端代理），`DynamicMethod` 就不够用了。我们需要用到 `AssemblyBuilder` 和 `TypeBuilder`。

```csharp
using System;
using System.Reflection;
using System.Reflection.Emit;

public static class AopProxyGenerator
{
    /// <summary>
    /// 为指定接口动态生成一个实现类（拦截器雏形）
    /// </summary>
    public static Type BuildInterfaceProxy(Type interfaceType)
    {
        // 定义动态程序集和模块
        var assemblyName = new AssemblyName($"DynamicAssembly_{Guid.NewGuid():N}");
        var assemblyBuilder = AssemblyBuilder.DefineDynamicAssembly(assemblyName, AssemblyBuilderAccess.Run);
        var moduleBuilder = assemblyBuilder.DefineDynamicModule("MainModule");

        // 定义一个新类，实现目标接口
        var typeBuilder = moduleBuilder.DefineType(
            $"{interfaceType.Name}Proxy",
            TypeAttributes.Public | TypeAttributes.Class);
        typeBuilder.AddInterfaceImplementation(interfaceType);

        // 遍历接口的所有方法，为其提供具体实现
        foreach (var method in interfaceType.GetMethods())
        {
            var methodBuilder = typeBuilder.DefineMethod(
                method.Name,
                MethodAttributes.Public | MethodAttributes.Virtual,
                method.ReturnType,
                Array.ConvertAll(method.GetParameters(), p => p.ParameterType));

            var il = methodBuilder.GetILGenerator();
            
            // 这里为了演示，生成的方法体仅仅是输出一段话并返回 null/默认值
            il.EmitWriteLine($"[Proxy Log] Executing {method.Name} at runtime!");
            
            if (method.ReturnType == typeof(void))
            {
                il.Emit(OpCodes.Ret);
            }
            else
            {
                // 如果需要返回值，粗暴地返回 default(T)
                var local = il.DeclareLocal(method.ReturnType);
                il.Emit(OpCodes.Ldloca_S, local);
                il.Emit(OpCodes.Initobj, method.ReturnType);
                il.Emit(OpCodes.Ldloc, local);
                il.Emit(OpCodes.Ret);
            }
            
            // 显式绑定接口方法
            typeBuilder.DefineMethodOverride(methodBuilder, method);
        }

        // 创建并返回这个全新的类型
        return typeBuilder.CreateType();
    }
}
```

## 四、AOT 环境下的反射限制

在云原生和移动端时代，反射遇到了它一生中最大的敌人——AOT 编译。

### AOT 是什么？

AOT (Ahead-Of-Time Compilation，预先编译) 是与传统 JIT (Just-In-Time，即时编译) 相对的概念。
在 JIT 模式下（标准的 .NET Core / .NET Framework），代码编译成 IL 带着完整的元数据发布，运行时按需编译。
在 AOT 模式下（如 .NET 8 Native AOT, Unity IL2CPP, iOS Xamarin），代码在发布前直接被编译成了机器码（二进制）。为了减小体积，AOT 编译器（Trimmer 裁剪器）会**删除所有看似未被调用的代码**。

### AOT 反射限制

既然元数据被删除了，或者没有 JIT 引擎，传统的反射就会出现致命错误：

```csharp
// ❌ 在 AOT 环境下，如果 "Calculator" 没有被静态代码显式调用过，
// 它可能在编译期被当做垃圾删除了，这里返回 null 或抛出异常。
Type type = Type.GetType("MyApp.Calculator"); 

// ❌ AOT 环境下无法在运行时动态创建新的泛型实例化，因为缺少对应的机器码。
Type genericType = typeof(List<>).MakeGenericType(typeof(MyCustomClass));

// ❌ IL Emit 完全失效！因为 AOT 环境移除了 JIT 编译器，不允许在运行时生成新的机器码。
var dynamicMethod = new DynamicMethod(...); 
```

### .NET 8 Native AOT 解决方案

为了让反射在 AOT 环境下存活，我们需要使用特定的 Attribute 来“警告”编译器不要删掉我们需要反射的成员。

```csharp
using System.Diagnostics.CodeAnalysis;

public class DependencyInjector
{
    // [DynamicallyAccessedMembers] 告诉 AOT 裁剪器：
    // 只要 type 被传入，就必须保留该类型所有的公共构造函数，不可删除！
    public object CreateInstance(
        [DynamicallyAccessedMembers(DynamicallyAccessedMemberTypes.PublicConstructors)] Type type)
    {
        return Activator.CreateInstance(type);
    }
}

public class PluginLoader
{
    // [DynamicDependency] 强制保留某一个具体的方法
    [DynamicDependency("Initialize", typeof(ThirdPartyPlugin))]
    public void LoadPlugin()
    {
        typeof(ThirdPartyPlugin).GetMethod("Initialize")?.Invoke(null, null);
    }
}
```

### Source Generator 替代方案

对于 AOT，微软推崇的终极解决方案是 **Source Generator (源生成器)**。
它摒弃了运行时反射，转而在**写代码的编译期**，由 Roslyn 语法树分析器读取你的代码，然后自动生成一大堆硬编码的 C# 文件加入到你的项目中。
例如 `System.Text.Json` 在 .NET 8 中就提供了源生成器版本，它会生成类似 `if(prop.Name == "Age") obj.Age = ...` 这样的强类型代码，从而实现 **零反射、零分配、AOT 绝对安全** 的序列化。

## 五、完整实战：高性能 ORM 映射器

掌握了前面的武功秘籍，我们现在来实战演练：写一个像 AutoMapper 或是 Dapper 内部那样的极速对象转换器。我们将使用**表达式树**技术，动态生成源对象到目标对象的属性赋值代码。

```csharp
using System;
using System.Collections.Concurrent;
using System.Collections.Generic;
using System.Linq;
using System.Linq.Expressions;
using System.Reflection;

public static class LightningMapper
{
    // 缓存转换委托的字典：键为 (源类型，目标类型) 的元组
    private static readonly ConcurrentDictionary<(Type, Type), Delegate> _mapperCache = new();

    /// <summary>
    /// 高性能映射入口：将 TSource 对象的同名属性赋值给 TTarget
    /// </summary>
    public static TTarget Map<TSource, TTarget>(TSource source) where TTarget : new()
    {
        if (source == null) return default;

        var key = (typeof(TSource), typeof(TTarget));
        
        // 从缓存获取或动态生成委托
        var mapperDelegate = (Func<TSource, TTarget>)_mapperCache.GetOrAdd(key, _ => BuildMapperFunc<TSource, TTarget>());
        
        // 执行委托（性能极高，无反射损耗）
        return mapperDelegate(source);
    }

    /// <summary>
    /// 核心逻辑：使用表达式树编译赋值过程
    /// </summary>
    private static Func<TSource, TTarget> BuildMapperFunc<TSource, TTarget>()
    {
        var sourceType = typeof(TSource);
        var targetType = typeof(TTarget);

        // 1. 定义传入参数: source (TSource 类型)
        var sourceParam = Expression.Parameter(sourceType, "source");
        
        // 2. 声明局部变量: TTarget target;
        var targetVar = Expression.Variable(targetType, "target");
        
        // 3. 实例化目标对象: target = new TTarget();
        var newTargetExpr = Expression.Assign(targetVar, Expression.New(targetType));

        var assignmentExpressions = new List<Expression> { newTargetExpr };

        // 4. 获取源和目标的属性进行比对
        var sourceProps = sourceType.GetProperties(BindingFlags.Public | BindingFlags.Instance).Where(p => p.CanRead);
        var targetProps = targetType.GetProperties(BindingFlags.Public | BindingFlags.Instance).Where(p => p.CanWrite).ToDictionary(p => p.Name);

        // 5. 遍历匹配同名且类型兼容的属性
        foreach (var sourceProp in sourceProps)
        {
            if (targetProps.TryGetValue(sourceProp.Name, out var targetProp))
            {
                if (targetProp.PropertyType.IsAssignableFrom(sourceProp.PropertyType))
                {
                    // 构建赋值表达式: target.Property = source.Property
                    var propertyAssign = Expression.Assign(
                        Expression.Property(targetVar, targetProp),    // 左值
                        Expression.Property(sourceParam, sourceProp)   // 右值
                    );
                    assignmentExpressions.Add(propertyAssign);
                }
            }
        }

        // 6. 加上返回值: return target;
        assignmentExpressions.Add(targetVar);

        // 7. 将所有语句组合成一个代码块 (Block)
        var block = Expression.Block(
            variables: new[] { targetVar }, // 注册局部变量
            expressions: assignmentExpressions
        );

        // 8. 编译为 Lambda：(source) => { target = new ...; target.A = source.A; return target; }
        var lambda = Expression.Lambda<Func<TSource, TTarget>>(block, sourceParam);
        
        return lambda.Compile();
    }
}

// ============== 测试实战 ==============
public class DataBaseRecord
{
    public int UserId { get; set; }
    public string UserName { get; set; }
    public DateTime CreatedAt { get; set; }
}

public class UserDto
{
    public int UserId { get; set; }
    public string UserName { get; set; }
}

// 首次调用，花费几毫秒在后台构建并编译表达式树
var dbData = new DataBaseRecord { UserId = 1001, UserName = "Neo", CreatedAt = DateTime.Now };
UserDto dto = LightningMapper.Map<DataBaseRecord, UserDto>(dbData); 

// 后续调用，速度等同于直接写：
// var dto = new UserDto { UserId = dbData.UserId, UserName = dbData.UserName };
```

## 六、本篇速查表

在面对不同的性能和架构需求时，请参考此表选择合适的反射优化方案：

| 优化技术策略 | 适用最佳场景 | 性能提升幅度 | 缺点与限制 |
|----------|----------|----------|-----------|
| **缓存元数据** (`PropertyInfo`) | 大范围读取类型结构，简单工具类 | 🟡 中等 (消除查找耗时) | 依然无法避免 `Invoke` 装箱 |
| **强类型委托缓存** (`Delegate`) | 泛型已知的组件，如特定的数据处理器 | 🟢 极高 (约 50x) | 无法处理参数类型完全动态的方法 |
| **表达式树** (`Expression`) | ORM映射、序列化器、依赖注入容器 | 🟢 极高 (约 50x) | 首次编译时间较长，内存占用稍大 |
| **IL Emit** (`DynamicMethod`) | 需要极致压榨性能的基础设施框架 | 🔵 满分 (与原生持平)| 学习曲线陡峭，调试犹如噩梦 |
| **Source Generator** | 移动端、AOT 环境、追求零运行时开销 | ✨ 降维打击 (编译期解决) | 代码编写模式完全改变，调试受限 |
