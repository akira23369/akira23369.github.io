# 并行编程异常处理与取消机制的协作

## 引言

在并行编程中，C# 主要提供了两个强大的工具：`Parallel` 类（包含 `Parallel.For` 和 `Parallel.ForEach`）以及 PLINQ（并行 LINQ）。

与 `async/await` 会将异常“悄悄”藏在 `Task` 中不同，并行操作是同步阻塞调用线程的（即主线程会一直等待所有并发循环执行完毕）。因此，当并行循环中发生异常时，它的表现形式和捕获逻辑有着自己独特的一套哲学。

---

## Parallel.For / ForEach：循环中的异常行为与聚合

### 并行循环的崩溃逻辑：不会立刻停止
当你使用 `foreach` 进行普通的单线程循环时，一旦某次迭代抛出异常，整个循环会立刻中断，后面的元素将不再被处理。

但在 `Parallel.ForEach` 中，情况截然不同。C# 并行库的设计理念是：**尽可能多地完成任务**。
如果某个工作线程在处理元素时抛出了异常：
1. 抛出异常的那个具体迭代会失败。
2. **底层调度器会停止向线程池分配新的尚未开始的迭代任务。**
3. **但是，那些已经分配给其他线程、并且正在执行的迭代，会被允许继续执行完毕。**

这意味着，在并行操作最终抛出异常并返回主线程之前，可能已经有多个迭代同时发生了异常！

### 捕获 AggregateException 与 Flatten() 魔法
因为同时可能会产生多个异常，`Parallel.ForEach` 最终向主线程抛出的，必定是我们上一篇提到过的“大麻袋”——`System.AggregateException`。

**代码演示：捕获并行循环中的所有异常**

```csharp
using System;
using System.Collections.Generic;
using System.Threading.Tasks;

public class ParallelExceptionDemo
{
    public static void ProcessData()
    {
        var numbers = new List<int> { 1, 2, 0, 4, 0, 6 };

        try
        {
            // 启动并行循环处理数据
            Parallel.ForEach(numbers, num =>
            {
                Console.WriteLine($"开始处理数字: {num}");
                
                // 模拟业务逻辑：除法运算
                // 当 num 为 0 时，这里会抛出 DivideByZeroException
                int result = 100 / num; 
                
                Console.WriteLine($"数字 {num} 处理成功。");
            });
        }
        catch (AggregateException agEx)
        {
            // Parallel 操作必定抛出 AggregateException
            Console.WriteLine("\n[系统警告] 并行处理过程中发生了错误！");

            // 核心技巧：调用 Flatten() 方法
            // 因为如果并行内部还嵌套了并行，异常麻袋里可能还套着小麻袋。
            // Flatten() 可以把所有嵌套的异常全部拍平，变成一个一维数组。
            foreach (var innerEx in agEx.Flatten().InnerExceptions)
            {
                // 输出具体的原始异常
                Console.WriteLine($"-> 捕获到错误: {innerEx.GetType().Name} - {innerEx.Message}");
            }
        }
    }
}
```

**运行结果分析：**
如果你运行这段代码，你会发现输出的结果里，捕获到了**两个** `DivideByZeroException`。这证实了我们的理论：即使遇到了第一个 0 报错了，其他线程正在处理的第二个 0 依然会执行并报错。最终，这两人一起被装进 `AggregateException` 的麻袋里抛了出来。

## PLINQ：并行查询中的异常处理模式

PLINQ（Parallel LINQ）允许你通过简单地添加 `.AsParallel()`，将一个普通的 LINQ 查询转化为多线程并发执行的查询。

### 延迟执行的陷阱
LINQ 最核心的特性是延迟执行：当你写下查询语句时，什么都不会发生；只有当你调用 `.ToList()`、`.ToArray()` 或者使用 `foreach` 去遍历它时，代码才会真正开始计算。

因此，**在 PLINQ 中，异常永远是在“消费（枚举）”结果的时候抛出，而不是在定义查询的时候抛出。**

### PLINQ 的异常处理演示
和 `Parallel.ForEach` 完全一样，PLINQ 抛出的也是 `AggregateException`。

```csharp
public void ProcessPLINQ()
{
    var data = new string[] { "10", "20", "XXX", "40", "YYY" };

    // 定义查询，此时不会报错
    var query = data.AsParallel()
                    .Select(str => int.Parse(str));

    try
    {
        // 触发实际的枚举操作，此时并发开始，异常将在此时爆发
        var results = query.ToList();
    }
    catch (AggregateException agEx)
    {
        Console.WriteLine("数据转换失败的项数：" + agEx.InnerExceptions.Count);
        
        foreach (var ex in agEx.InnerExceptions)
        {
            // 这里会捕获到属于 "XXX" 和 "YYY" 的 FormatException
            if (ex is FormatException)
            {
                Console.WriteLine("数据格式非法，无法转换为整数。");
            }
        }
    }
}
```
**避坑指南：** 如果你在使用 PLINQ，请务必确保包裹 `try-catch` 的地方，是触发枚举的那行代码（比如 `ToList()`），而不是定义查询的那行代码！

## CancellationToken：取消机制与异常的结合使用

在执行耗时的并行任务时，我们通常需要提供一个“取消”按钮。比如用户觉得等待时间太长了，点击“取消”，后台的几百个并发线程应该立刻停下来。

在 C# 中，取消操作是通过 `CancellationTokenSource` 和 `CancellationToken`（取消令牌）来实现的。而“取消”这个动作本身，**在底层是依靠抛出一个特定的异常来完成流转的。**

### 协作式取消
C# 的取消机制是“协作式”的。这意味着你不能粗暴地直接“杀死”一个线程（这会导致资源无法回收、文件锁死等严重后果）。
正确的做法是：主线程发出取消信号（修改令牌的状态），而工作线程在循环中不断检查令牌的状态；如果发现被取消了，主动抛出异常退出。

### 完整实战：带取消和异常处理的并行任务
当并行任务被取消时，`Parallel` 类会抛出一个名为 `OperationCanceledException` 的特殊异常。
此时，我们需要极度小心 `catch` 块的顺序，因为“用户主动取消”和“程序发生 Bug 崩溃”是两种完全不同的业务场景！

```csharp
using System;
using System.Threading;
using System.Threading.Tasks;

public class CancellationDemo
{
    public static void Run()
    {
        // 1. 创建取消令牌源
        var cts = new CancellationTokenSource();
        
        // 模拟：2秒后用户点击了取消按钮
        cts.CancelAfter(TimeSpan.FromSeconds(2));

        // 2. 配置并行选项，传入令牌
        var parallelOptions = new ParallelOptions
        {
            CancellationToken = cts.Token,
            MaxDegreeOfParallelism = Environment.ProcessorCount // 最大并发度
        };

        try
        {
            Console.WriteLine("开始海量数据处理...");
            
            Parallel.For(0, 100, parallelOptions, i =>
            {
                // 模拟耗时操作
                Thread.Sleep(500); 

                // 选项 A：如果某些数据有问题，抛出常规业务/系统异常
                if (i == 50) 
                {
                    throw new InvalidOperationException($"处理第 {i} 项时发生系统错误！");
                }

                // 选项 B：工作线程主动检查是否被取消
                // 如果 cts.Cancel() 被调用，这里会立刻抛出 OperationCanceledException
                parallelOptions.CancellationToken.ThrowIfCancellationRequested();
                
                Console.WriteLine($"任务 {i} 完成");
            });
        }
        catch (OperationCanceledException)
        {
            // 第一优先级拦截：处理用户的取消操作
            // 注意：当并行被取消时，抛出的是单独的 OperationCanceledException
            Console.WriteLine("\n[通知] 用户中止了操作，任务已安全取消。");
        }
        catch (AggregateException agEx)
        {
            // 第二优先级拦截：处理真正的代码错误或业务异常
            Console.WriteLine("\n[警告] 代码执行中发生了未预期的异常：");
            foreach (var ex in agEx.Flatten().InnerExceptions)
            {
                Console.WriteLine($"错误详情: {ex.Message}");
            }
        }
        catch (Exception ex)
        {
            // 第三优先级拦截：兜底
            Console.WriteLine($"发生未知致命错误：{ex.Message}");
        }
        finally
        {
            // 释放令牌源资源
            cts.Dispose();
            Console.WriteLine("资源清理完毕。");
        }
    }
}
```

**核心知识点总结：**
1. **取消不是错误：** 虽然取消是通过异常（`OperationCanceledException`）传递的，但它属于正常的业务流程分支。必须将它与代表“代码崩溃”的 `AggregateException` 分开捕获！
2. **ThrowIfCancellationRequested：** 这是响应取消信号最标准、最优雅的做法。一旦调用，底层的调用栈会立刻响应并展开。
3. **安全退出：** 这种基于异常的协作式取消，能完美保证 `finally` 块（或 `using` 语句）中的资源释放代码被正常执行，绝不会留下烂摊子。

## 结语：给 C# 开发者的异常处理箴言

历经十篇长文，我们终于从最基础的 `try-catch` 语法，一路走到了高阶的异步、并发与资源管理机制。

异常处理，往往是区分“能写出运转的代码（Make it work）”和“能写出坚如磐石的工业级系统（Make it robust）”的分水岭。在结束本系列之际，让我们再次重温 C# 异常处理的四大核心哲学：

1. **绝对不要吞咽异常：** `catch (Exception)` 后什么都不做，等于在你的代码里埋下了一颗不知何时会爆炸的地雷。
2. **只捕获你能处理的异常：** 如果你在当前层级不知道拿这个错误怎么办，请原封不动地 `throw;`，把它交给有能力处理的上层。
3. **保持业务逻辑与错误处理的分离：** 善用自定义异常和 `when` 过滤器，让你的正常流程代码保持整洁。
4. **永远负责你的资源：** 不论发生什么意外，`finally` 和 `using` (Dispose) 是你作为一个程序员对系统资源做出的最庄严的承诺。
