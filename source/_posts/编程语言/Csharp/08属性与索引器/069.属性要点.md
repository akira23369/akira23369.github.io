# C# 属性的核心要点与架构设计准则

## 核心架构准则：永远优先使用属性而非公开字段

在商业级项目和类库设计中，**绝不应该暴露公开字段（Public Fields）**。所有需要对外部公开的内部状态，都必须通过属性（包含自动属性）来进行封装。

根据《Effective C#》条款1（始终使用属性代替可访问的数据成员），这样做的根本原因包括：

*   **数据绑定支持**：.NET 框架中的数据绑定机制（如 WPF、WinForms、MAUI 等）完全依赖于反射来查找属性，它们**不支持字段**。
*   **二进制兼容性（ABI 兼容）**：如果最初暴露了一个公开字段，后期为了添加验证逻辑将其改为属性，这在 C# 源码层面看似无缝（调用代码依然是 `obj.Name = "A"`），但在**编译后的 IL（中间语言）层面是完全破坏性的**。访问字段使用的是 `ldfld/stfld` 指令，而访问属性使用的是 `callvirt` 方法调用指令。这意味着所有引用该类库的程序集都必须重新编译，否则会在运行时崩溃。
*   **未来扩展性**：属性允许在不改变外部调用方式的前提下，随时注入线程同步（锁机制）、数据校验、日志记录或事件通知（如 `INotifyPropertyChanged`）。

## 属性的底层本质：它只是“方法”的语法糖

属性本身**不占用对象实例的内存**。
对象实例在托管堆（Managed Heap）中占用的内存仅仅来源于类中定义的**字段（Fields）**。

根据《CLR via C#》的解析：
*   属性本质上是编译器生成的一对方法（`get_PropertyName` 和 `set_PropertyName`）。这些方法指令存储在类型的**方法表（Method Table）** 中，属于元数据，而不是对象实例的状态数据。
*   **性能零损耗**：很多开发者担心使用属性比直接访问字段慢。实际上，.NET 的 JIT（即时编译器）通常会将简单的属性访问（尤其是自动属性）进行**内联优化（Method Inlining）**。在运行时的机器码层面，访问简单属性和直接访问字段的性能是完全相同的。

## 读写控制与封装边界

通过对 `get` 和 `set` 访问器的组合，可以严格控制数据的读写权限：

*   **只读属性 (Read-Only)**：只有 `get` 访问器。外部无法赋值，但**类内部依然可以自由读取和修改其底层的私有字段**。
*   **只写属性 (Write-Only)**：只有 `set` 访问器。
    *   *设计警告*：根据《.NET 框架设计准则》，**应极力避免创建只写属性**。如果某个行为仅仅是写入数据而不能读取，使用方法（例如 `SetPassword(string pwd)`）能比属性更清晰地表达意图，且符合开发者的直觉。

## `value` 关键字与参数限制

在 `set` 访问器中，包含一个隐式的、由编译器自动生成的参数，名为 `value`。

*   `value` 是一个上下文关键字（Contextual Keyword），它的数据类型严格等同于属性所声明的数据类型。
*   **无参数限制**：常规的 C# 属性不能带有额外的参数（除了隐式的 `value`）。如果需要像调用方法一样向属性传递参数，必须使用 C# 的另一个特性——**索引器（Indexers）**，它本质上是带有参数的属性（背后生成 `get_Item` 和 `set_Item` 方法）。

```csharp
public class User
{
    private int _age;
    public int Age
    {
        get { return _age; }
        set 
        { 
            // value 的类型自动为 int
            if (value < 0 || value > 120)
                throw new ArgumentOutOfRangeException(nameof(value), "年龄不合法");
            _age = value; 
        }
    }
}
```

## 面向对象中类成员的职责划分 (职责单一原则)

在构建健壮的 C# 类时，四大核心成员应当各司其职。建立清晰的心理模型有助于编写出高内聚的代码：

1.  **字段 (Fields)**：专职负责**存储数据**。应始终保持 `private`。
2.  **属性 (Properties)**：专职负责**数据的验证、计算与暴露**。它是字段的保护层（Outer Layer）。
3.  **方法 (Methods)**：专职负责**行为与操作**。用于执行业务逻辑、状态转换或操作多个字段/属性。
4.  **构造函数 (Constructors)**：专职负责对象的**状态初始化**。确保对象在被使用前，所有的字段和属性都处于合法、可用的初始状态。
