# 自动实现属性初始化器 

## 核心概念与语法

**自动实现属性初始化器**是自 C# 6.0 引入的一项语法特性。它允许开发者在声明自动属性的同时，直接为其赋予一个初始（默认）值。

在 C# 6.0 之前，如果使用了自动属性并希望它拥有一个非默认的初始值，开发者必须显式编写一个构造函数来进行赋值。C# 6.0 的这一特性极大地简化了代码结构。

**代码示例：**

```csharp
public class Employee
{
    // C# 6.0 语法：直接在声明时初始化
    public string NativePlace { get; set; } = "New York";
    
    // 初始化引用类型，极大地避免了 NullReferenceException
    public List<string> Skills { get; set; } = new List<string>();
}
```

在上述代码中，任何新实例化的 `Employee` 对象，其 `NativePlace` 属性默认都会是 `"New York"`。当然，由于该属性包含 `set` 访问器，这个默认值在对象实例化后依然可以被覆盖修改（例如修改为 `"hachimi"`）。

## 编译器底层机制

从《CLR via C#》和《C# in Depth》的底层视角来看，属性初始化器本质上是编译器提供的语法糖。

1. **构造函数注入**：当编译器遇到属性初始化器时，它实际上会将这段赋值代码**移动到类的构造函数中**。
2. **执行时机**：这些初始化代码会被插入到构造函数体的最前面（在调用基类构造函数 `base()` 之前）。
3. **针对隐藏字段赋值**：编译器不仅生成了隐藏的支持字段（Backing Field），还会将初始化器的值直接赋给这个隐藏字段，而不是通过调用 `set` 访问器。

**等效的 C# 5.0（及更早版本）底层实现：**

```csharp
public class Employee
{
    // 编译器自动生成的隐藏字段
    private string <NativePlace>k__BackingField;

    public string NativePlace
    {
        get { return <NativePlace>k__BackingField; }
        set { <NativePlace>k__BackingField = value; }
    }

    // 编译器将初始化逻辑放入构造函数
    public Employee()
    {
        <NativePlace>k__BackingField = "New York"; 
    }
}
```

## 结合只读自动属性的强大用法

属性初始化器最强大的应用场景之一是与**只读自动属性**（同样是 C# 6.0 引入）结合使用。

如果一个属性只有 `get` 访问器，它被称为只读自动属性。这种属性只能在两个地方被赋值：
1. 类的构造函数中。
2. **通过属性初始化器**。

这种模式非常适合用来构建**不可变类型（Immutable Types）**，确保对象一旦创建，其核心状态就不会被改变。

**代码示例：**

```csharp
public class Employee
{
    // 只能在初始化时赋值，之后绝对不可变（即使在类内部也无法修改）
    public Guid Id { get; } = Guid.NewGuid();
    
    // 只读的创建时间戳
    public DateTime CreatedAt { get; } = DateTime.UtcNow;
}
```

## 默认值行为规则

如果不使用属性初始化器显式赋值，自动属性将遵循 CLR 的标准默认值规则，分配其底层数据类型的默认值：
*   **数值类型**（int, double, decimal 等）：`0`
*   **布尔类型**（bool）：`false`
*   **引用类型**（string, object, 自定义类等）：`null`
*   **结构体**（struct）：所有成员被设置为各自的默认值。

## 最佳实践

综合《Effective C#》和现代 C# 编码规范，使用属性初始化器时应遵循以下实践：

1. **消除构造函数臃肿**：如果一个属性的初始值不依赖于外部传入的参数，应优先使用属性初始化器。这可以使构造函数保持整洁，专注于处理依赖注入或复杂的构建逻辑。
2. **预防空引用异常**：对于集合类型的属性（如 `List<T>`、`Dictionary<TKey, TValue>`），**强烈建议**使用属性初始化器赋初值。这样调用者可以直接使用 `obj.List.Add()`，而不需要先检查集合是否为 `null`。
    ```csharp
    // 推荐做法
    public List<Order> Orders { get; set; } = new List<Order>();
    ```
3. **避免复杂的初始化逻辑**：属性初始化器只支持单一表达式。如果初始化需要多行代码、异常处理或复杂的逻辑判断，请将初始化逻辑移回构造函数中。不要试图在初始化器中编写难以阅读的嵌套三元表达式或调用庞大的工厂方法。
4. **访问修饰符的协同**：当通过跨程序集（如类库提供给控制台应用调用）暴露属性时，确保属性的可见性（如 `public`）设计合理。即使属性具有 `public get` 和 `internal set`，初始化器依然能够在对象创建时正常赋予默认值。
