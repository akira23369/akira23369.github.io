# 属性与索引器

## 第1讲：属性简介与属性操作

### 引言

在现代 C# 编程中，属性是类暴露数据的首选方式。属性作为类成员，提供了一种灵活可控的机制来读取、写入或计算私有字段的值。对外部而言，属性看起来和使用起来都像公共字段（如 `myObject.Name = "Test"`），但其内部实际上是一对特殊的方法，称为**访问器（get 和 set）**。这种设计既保留了字段的易用性，又具备方法的功能性和安全性，完美体现了封装原则。

### 属性解决的问题：传统实现方式

在属性出现之前，若想保护私有字段，必须显式编写"getter"和"setter"方法。

```cs
public class Student  
{  
    private string _name; // 私有数据字段  
​  
    // 读取字段值的方法（Getter方法）  
    public string GetName()  
    {  
        return _name;  
    }  
​  
    // 设置字段值的方法（Setter方法）  
    public void SetName(string name)  
    {  
        if (!string.IsNullOrEmpty(name))  
        {  
            _name = name;  
        }  
    }  
}  
// 使用方式：student.SetName("John"); string name = student.GetName();
```


这种方式虽然可行，但显得冗长且不够直观。属性为这种模式提供了更为简洁的语法。

### 工作原理：后备字段与访问器

一个完整实现的属性包含两个核心部分：

1. **私有后备字段**：这是实际在堆上存储数据的变量。
    
2. **公共属性**：包含控制访问后备字段的 `get` 和/或 `set` 访问器。
    

- `get` 访问器：无参数方法，读取属性值时执行，必须返回该属性类型的值。
    
- `set` 访问器：赋值属性时执行的方法，包含隐式参数 `value`（存储赋值运算符右侧的值）。
    

### 示例：现代属性语法

重构 Student 类以使用属性：

```cs
public class Student  
{  
    // 1. 私有后备字段：用于存储实际数据  
    private string _name;  
​  
    // 2. 公共属性：控制对后备字段的访问  
    public string Name  
    {  
        // 读取属性时执行get访问器  
        get  
        {  
            // 直接返回后备字段的值  
            return _name;  
        }  
​  
        // 为属性赋值时执行set访问器  
        set  
        {  
            // value是关键字，存储赋值时传入的值  
            // 可在此添加数据验证逻辑，保障数据安全  
            if (string.IsNullOrEmpty(value))  
            {  
                Console.WriteLine("错误：姓名不能为空或空字符串。");  
            }  
            else  
            {  
                // 验证通过则更新后备字段  
                _name = value;  
            }  
        }  
    }  
}  
​  
// --- 主方法中使用 ---  
Student student = new Student();  
​  
// 赋值操作会调用set访问器，"John"会作为value参数传入  
student.Name = "John";   
​  
// 读取操作会调用get访问器  
string currentName = student.Name;   
Console.WriteLine(currentName); // 输出：John  
​  
// 此赋值会触发验证逻辑  
student.Name = ""; // 输出：错误：姓名不能为空或空字符串。
```


## 第二讲：只读属性

### 引言

**只读属性**是指可从类外部读取但无法修改的属性，适用于暴露应保持不可变的数据。

### 工作原理

创建只读属性的常见方式：

1. 省略 `set` 访问器：外部代码无赋值入口。
    
2. **表达式主体成员**（简洁语法）：使用 `=>` 表示仅含 `get` 访问器且返回单个表达式结果的属性。
    

### 使用场景与实际案例

- **计算值**：属性值由对象其他数据计算得出（如拼接姓和名的 FullName 属性）。
    
- **暴露内部状态**：允许外部查看私有字段，但禁止修改。
    

### 示例
```cs
public class Person  
{  
    private string _firstName;  
    private string _lastName;  
    public readonly DateTime DateOfBirth; // 只读字段  
​  
    public Person(string firstName, string lastName, DateTime dob)  
    {  
        _firstName = firstName;  
        _lastName = lastName;  
        DateOfBirth = dob;  
    }  
​  
    // 只读属性（计算值）：使用表达式主体语法  
    // 无后备字段，值实时计算  
    public string FullName => $"{_firstName} {_lastName}";  
​  
    // 只读属性：计算年龄  
    public int Age  
    {  
        get  
        {  
            int age = DateTime.Today.Year - DateOfBirth.Year;  
            // 未到生日则年龄减1  
            if (DateTime.Today.DayOfYear < DateOfBirth.DayOfYear)  
            {  
                age--;  
            }  
            return age;  
        }  
    }  
}  
​  
// --- 主方法中使用 ---  
Person p = new Person("Jane", "Doe", new DateTime(1990, 5, 15));  
Console.WriteLine(p.FullName); // 输出：Jane Doe  
Console.WriteLine($"年龄: {p.Age}");  
​  
// 以下代码会编译报错：FullName是只读属性  
// p.FullName = "John Smith"; // 错误！属性或索引器无法赋值，因为它是只读的。
```


## 第三讲：只写属性

### 引言

**只写属性**与只读属性相反：可从外部写入值，但无法读取其值。

### 工作原理

仅提供 `set` 访问器、省略 `get` 访问器，即可创建只写属性。

### 为何及何时使用

只写属性极为罕见，通常视为设计问题（违背对象应报告自身状态的直觉）。唯一有效场景：存储**永远不应回读的敏感数据**（如密码）——set 访问器接收密码后哈希存储，不提供 get 访问器防止原始密码泄露。

### 示例
```cs
public class PasswordManager  
{  
    private string _hashedPassword; // 存储哈希后的密码  
​  
    // 只写属性  
    public string Password  
    {  
        set  
        {  
            // 密码验证：非空且长度≥8  
            if (string.IsNullOrEmpty(value) || value.Length < 8)  
            {  
                Console.WriteLine("错误：密码长度至少8个字符。");  
            }  
            else  
            {  
                // 实际项目中应使用强哈希算法（如BCrypt）  
                _hashedPassword = $"HASHED({value})";  
                Console.WriteLine("密码设置成功。");  
            }  
        }  
    }  
}  
​  
// --- 主方法中使用 ---  
PasswordManager pm = new PasswordManager();  
pm.Password = "MySecret123!"; // 调用set访问器  
​  
// 以下代码编译报错：无get访问器  
// string myPass = pm.Password; // 错误！属性缺少get访问器，无法在此上下文中使用。
```


## 第四讲：自动实现属性

### 引言

**自动实现属性（自动属性）** 是 C# 简化属性声明的特性，适用于 get/set 无自定义逻辑、仅简单读写后备字段的场景。可单行声明属性，无需显式定义私有后备字段。

### 工作原理：编译器魔法

编写自动属性时：

`public string Name { get; set; }`

编译器会自动生成以下代码（幕后执行，不可直接操作）：
```cs
private string _name_backingField; // 隐藏的私有后备字段（名称被编译器混淆）  
​  
public string Name  
{  
    get  
    {  
        return this._name_backingField;  
    }  
    set  
    {  
        this._name_backingField = value;  
    }  
}
```


### 使用场景

自动属性是现代 C# 创建属性的**标准默认方式**。建议优先使用，仅当需要为 get/set 添加验证/计算逻辑时，再扩展为带显式后备字段的完整属性。

### 示例

数据传输对象（DTO）/简单模型类是自动属性的理想场景（仅作为数据容器）：
```cs
public class Product  
{  
    // 自动属性：编译器为每个属性生成隐藏后备字段  
    public int Id { get; set; }  
    public string Name { get; set; }  
    public decimal Price { get; set; }  
    public string Sku { get; set; }  
}  
​  
// --- 主方法中使用 ---  
Product laptop = new Product();  
laptop.Id = 101;  
laptop.Name = "SuperBook Pro";  
laptop.Price = 1299.99M;  
laptop.Sku = "SBP-2025-BL";  
​  
Console.WriteLine($"产品: {laptop.Name} (ID: {laptop.Id}) 价格: {laptop.Price:C}");
```


## 第五讲：自动实现属性的访问器可访问性

### 引言

即使使用自动属性的简洁语法，仍可为 get/set 访问器分别指定不同访问修饰符，精细控制属性读写权限，实现安全的数据模式。

### 工作原理与规则

可在 get/set 关键字前添加访问修饰符（private/protected/internal），核心规则：

单个访问器的修饰符必须比属性本身的访问级别更严格。

例如：`public` 属性可搭配 `private set`，但 `private` 属性不能搭配 `public set`。

### 使用场景：private set 模式

最常用且强大的用法：创建 `public get + private set` 的属性：

​  
`public int Id { get; private set; }`

该模式下，属性**对外只读、类内部可写**，适用于对象创建后需保持不可变的字段（如 ID，通常在构造函数中赋值）。

### 示例

重构 Product 类（ID 创建后不可修改）：
```cs
public class Product  
{  
    // 外部可读取，但仅类内部可设置  
    public int Id { get; private set; }  
  
    public string Name { get; set; }  
    public decimal Price { get; set; }  
  
    // 构造函数中设置private set的属性  
    public Product(int id)  
    {  
        this.Id = id;  
    }  
  
    public void ChangeName(string newName)  
    {  
        // 类内部可修改普通属性  
        this.Name = newName;  
    }  
}  
  
// --- 主方法中使用 ---  
Product phone = new Product(202);  
phone.Name = "SuperPhone 12";  
  
// 外部可读取Id  
Console.WriteLine($"创建的产品ID: {phone.Id}");  
  
// 外部无法修改Id（编译报错）  
// phone.Id = 203; // 错误！set访问器不可访问。

```

#### 面试视角

**问题**：如何创建一个对外部只读但类内部可设置的属性？

**理想答案**：使用带公共 get 访问器和私有 set 访问器的自动属性（如 `public string Name { get; private set; }`）。该方式允许在类内部（通常是构造函数）设置值，对外表现为只读，是实现封装的最佳方式。

## 第六讲：自动实现的属性初始化器

### 引言

C# 6.0 引入的特性，允许在自动属性声明处直接设置默认值，无需在构造函数中初始化，让代码更简洁易读。

### 工作原理

这是语法糖，例如：

  
`public string Status { get; set; } = "Active";`

编译器会确保对象创建时，Status 属性的隐藏后备字段被初始化为 "Active"（初始化过程在构造函数执行前完成，是设置默认值的可靠方式）。

### 使用场景

当属性需要非系统默认值（0、false、null）的初始值时，使用属性初始化器，让对象创建时就具备合理的初始状态。

### 示例

Customer 类（新客户默认状态为 Active，默认加入时间为当前UTC时间）：

```cs
public class Customer  
{  
    public int Id { get; private set; }  
  
    // 自动属性初始化器：设置默认值  
    public string Status { get; set; } = "Active";  
  
    // 初始化器调用静态方法获取默认值  
    public DateTime MemberSince { get; private set; } = DateTime.UtcNow;  
  
    public string Name { get; set; }  
  
    public Customer(int id, string name)  
    {  
        this.Id = id;  
        this.Name = name;  
        // 无需在此设置Status/MemberSince，初始化器已完成  
    }  
}  
  
// --- 主方法中使用 ---  
Customer newCustomer = new Customer(1, "Jane Doe");  
  
Console.WriteLine($"客户: {newCustomer.Name}");  
Console.WriteLine($"状态: {newCustomer.Status}"); // 输出：Active  
Console.WriteLine($"加入时间: {newCustomer.MemberSince}"); // 输出：当前UTC时间
```  


## 第七讲：关于属性的重要知识点总结

### 引言

整合属性使用的核心要点（面试高频考点）：

### 1. 属性是伪装成字段的方法

最基础且重要的概念：属性不是直接变量，而是对 get/set 方法的**语法糖**。理解这一点就能明白：为何属性可添加逻辑、控制访问权限；为何公共字段 vs 公共属性的核心区别是——属性通过访问器提供抽象层和控制逻辑，而公共字段无任何保护。

### 2. 自动属性是标准做法

现代 C# 中，优先使用自动属性：

  
`public string Name { get; set; }`

仅需添加自定义逻辑时，再扩展为带显式后备字段的完整属性，保持代码简洁。

### 3. `public { get; private set; }` 模式是封装机制的基石

该模式极为常见且强大，可创建“对外只读、内部可写”的属性，适用于 ID、创建日期等对象生命周期内需保持不可变的字段。

### 4. 属性 vs 方法：指导原则

**面试问题**：什么时候用属性而非方法？

- **使用属性**：
    
    - 成员代表对象的数据项/属性（如 Name、Color、Age）；
        
    - 获取值是快速、简单的操作，无显著副作用。
        
- **使用方法**：
    
    - 成员执行动作/动词（如 Save()、Calculate()、Convert()）；
        
    - 操作复杂、缓慢或有明显副作用；
        
    - 操作需要参数（属性无参数，索引器有）。
        

## 索引器简介与使用索引器

### 引言

**索引器**是特殊的类成员，允许通过方括号 `[]` 访问类对象（类似数组/字典）。当类逻辑上表示集合/列表时，索引器能提供更自然的访问语法（如 `myTeam[0]` 替代 `myTeam.GetPlayer(0)`）。

### 工作原理：语法与机制

索引器与属性相似，但有两个关键区别：

1. 使用 `this` 关键字声明；
    
2. 方括号内接收一个/多个参数（作为索引/键）。
    

索引器同样包含 get/set 访问器：

- 读取索引器（`var player = myTeam[0];`）：执行 get 访问器，索引值传入参数；
    
- 赋值索引器（`myTeam[0] = "New Player";`）：执行 set 访问器，接收索引值和隐式参数 `value`。
    

### 使用场景

当类的核心目的是封装/管理内部集合（数组、列表、字典）时，实现索引器——为复杂的后端存储提供简化的前端接口。

### 示例

Team 类（内部用 `List<string>` 存储球员姓名，通过索引器访问并添加边界检查）：

```cs
using System;  
using System.Collections.Generic;  
  
public class Team  
{  
    // 私有后备集合  
    private List<string> _players = new List<string>();  
  
    // 索引器声明：接收整数类型索引  
    public string this[int index]  
    {  
        // 读取球员姓名的get访问器  
        get  
        {  
            // 添加边界验证，避免越界错误  
            if (index >= 0 && index < _players.Count)  
            {  
                return _players[index];  
            }  
            // 索引越界时返回null（也可抛出异常）  
            return null;   
        }  
  
        // 添加/更新球员姓名的set访问器  
        set  
        {  
            if (index >= 0 && index < _players.Count)  
            {  
                // 索引有效：更新现有球员  
                _players[index] = value;  
            }  
            else if (index == _players.Count)  
            {  
                // 特殊规则：索引等于集合长度时，添加新球员  
                _players.Add(value);  
            }  
        }  
    }  
  
    // 只读属性：获取球员数量（表达式主体语法）  
    public int PlayerCount => _players.Count;  
}  
  
// --- 主方法中使用 ---  
Team myTeam = new Team();  
  
// 使用索引器的set访问器添加球员  
myTeam[0] = "Alice";  
myTeam[1] = "Bob";  
myTeam[2] = "Charlie";  
  
// 使用索引器的get访问器读取球员姓名  
Console.WriteLine($"索引1的球员是: {myTeam[1]}"); // 输出：Bob  
  
// 使用set访问器更新球员  
myTeam[0] = "Alicia";  
Console.WriteLine($"索引0的球员现在是: {myTeam[0]}"); // 输出：Alicia  
  
// 访问无效索引  
Console.WriteLine($"索引5的球员是: {myTeam[5] ?? "不存在"}"); // 输出：不存在
```



## 索引器重载

### 引言

与方法类似，索引器也可**重载**——同一个类中声明多个索引器，只要签名（参数数量/类型）不同即可。编译器会根据方括号内的索引类型，决定调用哪个索引器。

### 工作原理

C# 编译器根据索引的数据类型匹配对应索引器，允许为集合提供多种查找方式（如 int 索引按位置查找、string 索引按名称查找）。

### 使用场景

适用于复杂集合类（项目可通过多种方式标识），常见模式：同时提供 int 索引器（位置访问）和 string 索引器（键访问），让类兼具数组和字典的特性。

### 示例

增强 Team 类（存储 Player 对象，提供 int/string 两种索引器）：
```cs
using System;  
using System.Collections.Generic;  
using System.Linq;  
  
public class Player  
{  
    public string Name { get; set; }  
    public int JerseyNumber { get; set; }  
}  
  
public class Team  
{  
    private List<Player> _players = new List<Player>();  
  
    // 添加球员的方法  
    public void AddPlayer(Player player)  
    {  
        _players.Add(player);  
    }  
  
    // --- 索引器重载1：接收整数索引 ---  
    public Player this[int index]  
    {  
        get  
        {  
            if (index >= 0 && index < _players.Count)  
            {  
                return _players[index];  
            }  
            return null;  
        }  
    }  
  
    // --- 索引器重载2：接收字符串姓名 ---  
    public Player this[string name]  
    {  
        get  
        {  
            // 使用LINQ查找第一个匹配姓名的球员（忽略大小写）  
            return _players.FirstOrDefault(p => p.Name.Equals(name, StringComparison.OrdinalIgnoreCase));  
        }  
    }  
}  
  
// --- 主方法中使用 ---  
Team myTeam = new Team();  
myTeam.AddPlayer(new Player { Name = "Alice", JerseyNumber = 10 });  
myTeam.AddPlayer(new Player { Name = "Bob", JerseyNumber = 7 });  
  
// 使用int类型索引器  
Player firstPlayer = myTeam[0];  
Console.WriteLine($"索引0的球员是 {firstPlayer.Name}，球衣号 #{firstPlayer.JerseyNumber}");  
  
// 使用string类型索引器  
Player bob = myTeam["Bob"];  
Console.WriteLine($"按姓名查找Bob，球衣号 #{bob.JerseyNumber}");  
  
Player charlie = myTeam["Charlie"];  
Console.WriteLine($"Charlie是否在队中？ {charlie == null}"); // 输出：True
```
  


## 第10讲：关于属性与索引器的核心要点总结

### 引言

整合属性和索引器的核心知识点（面试高频）：

### 属性是伪装成字段的方法

属性不是直接变量，而是 get/set 方法的**语法糖**。这解释了为何属性可添加逻辑、控制访问权限，是实现封装的核心。

### 自动属性是标准做法

现代 C# 中，**优先使用自动属性**（`public string Name { get; set; }`），仅需自定义逻辑时，再扩展为带显式后备字段的完整属性。

### `public { get; private set; }` 模式是封装机制的基石

该模式创建“对外只读、内部可写”的属性，适用于 ID、创建日期等对象创建后需保持不可变的字段。

### 索引器提供“类数组”语法

索引器是语法糖，让表示集合的类具备数组/字典的访问方式，提升代码直观性。

### 属性 vs 索引器：关键面试区别

| 维度   | 属性                 | 索引器                  |
| ---- | ------------------ | -------------------- |
| 访问方式 | 静态名称（如 `obj.Name`） | 动态索引/键（如 `obj[key]`） |
| 静态成员 | 可声明为 static        | 必须是实例成员              |
| 参数   | 无参数                | 至少一个索引参数             |
