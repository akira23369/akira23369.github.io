# C# 索引器重载

## 核心概念

索引器（Indexer）允许对象像数组一样通过索引进行访问（即使用 `[]` 语法）。**索引器重载**是指在同一个类中定义多个索引器，只要这些索引器的**参数签名（参数的类型或数量）不同**即可。

这为类的调用者提供了极大的灵活性，允许使用者根据不同的上下文，通过不同的键（Key）去检索或修改对象内部集合中的数据。例如，既可以通过整数索引（如 `0, 1, 2`）访问，也可以通过字符串键（如 `"first", "second"`）访问。

## 编译器底层机制

从《CLR via C#》的视角来看，CLR 本身并没有“索引器”这个概念。索引器完全是 C# 编译器提供的一颗语法糖。

1. **本质是带参数的属性**：当在 C# 中定义一个索引器 `public string this[int index]` 时，编译器会在底层生成一个名为 `Item` 的属性，并为其生成对应的 `get_Item(int index)` 和 `set_Item(int index, string value)` 方法。
2. **重载的本质是方法重载**：因为索引器最终会被编译为方法，所以索引器的重载，在底层完全等价于**方法的重载（Method Overloading）**。
    * 整数参数的索引器对应：`get_Item(int)`
    * 字符串参数的索引器对应：`get_Item(string)`
3. 编译器还会自动为该类贴上 `[DefaultMember("Item")]` 特性，告诉运行时这是该类的默认成员。

## 代码实战与健壮性优化

以下代码演示了如何在一个类中重载索引器。在实现通过字符串查找索引时，使用了 `Array.IndexOf` 方法。

> **最佳实践补充**：在真实的工程中，`Array.IndexOf` 如果找不到匹配项会返回 `-1`。直接使用 `-1` 去访问数组会导致 `IndexOutOfRangeException`。更优雅的做法是捕获这种异常边界，并抛出语义更明确的 `KeyNotFoundException`。

```csharp
using System;
using System.Collections.Generic;

public class CarShowroom
{
    // 内部数据存储
    private string[] _brands = { "BMW", "Audi", "Nissan" };
    // 字符串映射表
    private string[] _names = { "first", "second", "third" };

    // 1. 基于整数的索引器
    public string this[int index]
    {
        get 
        {
            // 依赖底层数组的边界检查
            return _brands[index]; 
        }
        set 
        {
            _brands[index] = value; 
        }
    }

    // 2. 基于字符串的索引器 (索引器重载)
    public string this[string name]
    {
        get
        {
            int index = Array.IndexOf(_names, name);
            if (index == -1)
            {
                throw new KeyNotFoundException($"The key '{name}' was not found.");
            }
            return _brands[index];
        }
        set
        {
            int index = Array.IndexOf(_names, name);
            if (index == -1)
            {
                throw new KeyNotFoundException($"The key '{name}' was not found.");
            }
            _brands[index] = value;
        }
    }
}
```

**调用方式：**
```csharp
CarShowroom showroom = new CarShowroom();

// 调用第一个索引器
string car1 = showroom[0]; // 返回 "BMW"

// 调用重载的第二个索引器
string car2 = showroom["second"]; // 返回 "Audi"
```

## 真实场景应用

在 .NET 框架自身的设计中，索引器重载被大量且广泛地使用。理解这一点有助于编写符合 .NET 规范的代码：

*   **ADO.NET DataRow**：在处理数据库返回的数据时，既可以通过列的索引获取数据 `row[0]`，也可以通过列名获取数据 `row["ColumnName"]`。
*   **ASP.NET Core HttpContext**：获取集合数据时（如请求头、查询字符串等），往往支持重载索引器。
*   **多维参数重载**：除了改变类型，还可以改变参数数量。例如实现一个简单的矩阵类，可以定义 `public double this[int row, int col]`。

## 架构设计准则

综合《Effective C#》和微软 API 设计指南，使用索引器重载时应遵循以下原则：

1. **符合使用直觉**：索引器的操作应当具有类似数组的极快响应时间。如果在字符串类型的索引器中（如 `this[string name]`）需要执行极其耗时的数据库查询或复杂的网络调用，**不应该使用索引器**，而应该将其设计为一个方法（如 `FindByName(string name)`）。
2. **逻辑一致性**：无论调用哪个版本的重载索引器，如果它们指向的是同一个逻辑实体，它们获取到的结果和引发的副作用必须保持完全一致。
3. **不要滥用**：只在你的类在逻辑上“表现得像一个集合、容器或字典”时，才使用索引器及其重载。如果类仅仅是包含了几个属性，不要为了“少写代码”而使用索引器代替常规的属性暴露。
