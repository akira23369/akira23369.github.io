# C# 只读与只写属性核心解析

在面向对象设计中，并非所有的数据都应该被外部随意读写。通过灵活省略属性的 `get` 或 `set` 访问器，可以精确控制数据的访问权限，从而构建更加安全和健壮的类。

## 只读属性 (Read-only Properties)

### 核心概念
只读属性是指**仅包含 `get` 访问器、没有 `set` 访问器**的属性。
外部代码可以随时随地读取该属性的值（用于展示或参与其他计算），但绝对无法通过属性来修改底层数据。

### 内部赋值机制
虽然外部无法通过属性赋值，但类内部依然需要对底层字段进行初始化。通常的做法是：
1. 声明一个私有字段（Backing Field）。
2. 在类的**构造函数 (Constructor)** 中为该私有字段赋初始值。
3. 类的内部方法可以直接读写该私有字段，但对外只暴露只读属性。

### 代码实现
以下是一个员工薪水（Salary）的经典场景：薪水可以被外部读取并用于报表展示，但绝不允许外部随意修改。

```csharp
public class Employee
{
    // 私有字段存储真实数据
    private double _salary;

    // 只读属性：仅提供 get 访问器
    public double Salary
    {
        get { return _salary; }
    }

    // 在构造函数中进行初始化
    public Employee()
    {
        _salary = 1000; 
    }

    public Employee(double initialSalary)
    {
        _salary = initialSalary;
    }
}
```

### 进阶拓展
*   **强制不可变性 (Immutability)**：根据《CLR via C#》的最佳实践，如果一个字段在对象实例化后就不应该再被改变，应该使用 `readonly` 关键字修饰私有字段（即 `private readonly double _salary;`）。这会在编译器层面防止类内部的方法意外修改该字段，进一步增强代码的安全性。
*   **现代 C# 的只读自动属性**：从 C# 6.0 开始，可以直接声明只读的自动实现属性，编译器会在后台自动生成一个 `readonly` 的私有字段：
    ```csharp
    // 现代简写方式
    public double Salary { get; } 
    ```
*   **`init` 访问器 (C# 9.0+)**：在现代 C# 开发中，经常需要配合对象初始化器（Object Initializer）来创建不可变对象。此时可以使用 `init` 替代 `set`。它允许在对象**创建的瞬间**进行赋值，一旦初始化完成，属性就变成了严格的只读状态。

## 只写属性 (Write-only Properties)

### 核心概念
只写属性是指**仅包含 `set` 访问器、没有 `get` 访问器**的属性。
外部代码可以向该属性持续输入数据，但无法通过该属性读取当前的值。

### 典型应用场景
只写属性通常用于接收外部参数，经过 `set` 内部的逻辑校验后，存储到私有字段中，专供**类内部的其他方法**进行计算或处理。
例如：税率（Tax）允许外部设置，但不允许外部直接读取，最终由类内部的计算方法直接消费这个税率字段。

### 代码实现

```csharp
public class Employee
{
    private double _salary = 1000;
    private double _tax;

    // 只写属性：仅提供 set 访问器
    public double Tax
    {
        set
        {
            // 校验逻辑：税率必须在 0 到 100 之间
            if (value >= 0 && value <= 100)
            {
                _tax = value;
            }
        }
    }

    // 类内部的方法消费 _tax 字段
    public double CalculateNetSalary()
    {
        // 净薪水 = 实际薪水 - 税
        //return _salary - Tax;   // 错误：无法访问 Tax，因为它是只写属性
        return _salary - _tax;
    }
}

// 调用端
Employee emp = new Employee();
emp.Tax = 50; // 允许写入
// double currentTax = emp.Tax; // 编译错误！无法读取只写属性
Console.WriteLine($"Net Salary: {emp.CalculateNetSalary()}"); // 输出: 950
```

### 经典名著与架构设计箴言
*   **谨慎使用只写属性**：在《Framework Design Guidelines》（微软框架设计准则）和《C# in a Nutshell》中，都明确提出了**强烈不建议创建只写属性**的警告。
*   **设计哲学背后的原因**：
    属性在语义上代表对象的“状态”或“特征”。如果一个特征存在（可以被设置），那么在逻辑上它通常也应该能够被观察（读取）。只写属性违背了这种直觉，常常让调用者感到困惑（例如：我刚刚把 Tax 设为 50，但我没有任何办法验证它是否真的被设为了 50）。
*   **最佳替代方案：使用方法 (Method)**
    如果确实存在只允许输入不允许输出的场景，业界标准的做法是将其重构为一个方法（Method）。方法在语义上代表一个“动作”，传入参数而不返回值是非常自然的设定。
    ```csharp
    // 推荐的替代设计：将只写属性重构为方法
    public void SetTax(double taxValue)
    {
        if (taxValue >= 0 && taxValue <= 100)
        {
            _tax = taxValue;
        }
        else
        {
            throw new ArgumentOutOfRangeException(nameof(taxValue), "税率必须在0到100之间");
        }
    }
    ```

## 总结
*   **只读属性** (`get` only) 是构建安全、不可变数据模型的利器，在日常开发中极其常见且被广泛推荐。
*   **只写属性** (`set` only) 虽然在语法上完全合法，但在严谨的软件架构工程中应尽量避免。优先考虑使用显式的 `SetXxx()` 方法来替代只写属性，以提升代码的可读性和意图的清晰度。
