# C# 学习笔记：索引器

## 什么是索引器?
索引器允许类或结构的实例像数组一样进行直接索引。在类的内部，可能封装了数组、列表、逗号分隔的字符串等数据结构。通过提供索引器，可以极大简化类外部对这些内部数据的访问操作，提供一种快捷、直观的语法。

从本质上讲，索引器可以被理解为**带参数的属性**。

## 核心语法与代码实现
索引器的声明语法与属性非常相似，都包含 `get` 和 `set` 访问器。不同之处在于，索引器强制使用 `this` 关键字作为名称，并在方括号 `[]` 中定义传入的参数（通常是索引值或键值）。

以下是典型的索引器实现示例：

```csharp
public class Car
{
    // 类内部封装的数组，存储品牌列表
    private string[] _brands = new string[] { "BMW", "Audi", "Mercedes" };

    // 定义公开的索引器
    // 返回类型为 string，参数类型为 int
    public string this[int index]
    {
        get
        {
            // 根据传入的 index，返回对应的数组元素
            return _brands[index];
        }
        set
        {
            // value 是隐式关键字，代表用户赋的值
            // 将 value 写入到指定的 index 位置
            _brands[index] = value;
        }
    }
}
```

在调用端（如控制台应用程序中），可以通过对象引用直接使用方括号语法：

```csharp
class Program
{
    static void Main()
    {
        Car myCar = new Car();
        
        // 1. 获取值：自动调用 get 访问器
        // 传入参数 0，返回 "BMW"
        Console.WriteLine(myCar[0]); 
        
        // 2. 设置值：自动调用 set 访问器
        // 传入参数 0 和 value "Nissan"，将覆盖原有的 "BMW"
        myCar[0] = "Nissan";
        
        // 再次获取，输出 "Nissan"
        Console.WriteLine(myCar[0]); 
    }
}
```

## 索引器的关键特性与约束
- **名称固定**：索引器的定义名称始终是 `this`。
- **必须是实例成员**：索引器**不能**被声明为 `static`。由于它的设计初衷是让对象实例具备类似数组的行为，因此必须通过对象的引用变量进行访问。
- **参数要求**：必须至少具有一个参数。但参数类型不局限于 `int`（例如在 `Dictionary<TKey, TValue>` 中，索引器参数是键的类型，可以是 `string` 或 `Guid` 等）。
- **参数限制**：索引器的参数不能使用 `ref` 或 `out` 修饰符。
- **支持重载**：同一个类中可以定义多个索引器，只要它们的参数类型或参数个数不同即可（即索引器重载）。
- **多态与继承支持**：与普通属性或方法一样，索引器可以应用各种访问修饰符（如 `public`、`private` 等），并且支持面向对象的修饰符（如 `virtual`、`abstract`、`override`、`new` 和 `sealed`）。

## 进阶原理与最佳实践（补充知识）

结合《CLR via C#》、《C# in a Nutshell》与《Effective C#》等经典著作，以下是关于索引器的深度理解：

### 编译器的底层实现
在 CLR (公共语言运行时) 层面，原生并没有“索引器”这一概念。索引器完全是 C# 编译器提供的一种语法糖。
当我们在 C# 中定义了一个索引器后，编译器会在底层自动生成一个默认名称为 `Item` 的属性，并伴随生成 `get_Item` 和 `set_Item` 两个方法。
上面的 `Car` 类索引器在编译为 IL（中间语言）后，其实质相当于：

```csharp
// 编译器在底层生成的伪代码表示
public string get_Item(int index) { return _brands[index]; }
public void set_Item(int index, string value) { _brands[index] = value; }
```

### 更改默认名称特性
如果为了与其他支持参数化属性的 .NET 语言（如 VB.NET）进行更好的互操作，或者想在反射时使用更具业务意义的名字，可以通过 `[IndexerName]` 特性覆盖编译器默认生成的 `Item` 名称：

```csharp
using System.Runtime.CompilerServices;

public class Car
{
    private string[] _brands = new string[10];

    [IndexerName("Brand")]
    public string this[int index]
    {
        get { return _brands[index]; }
        set { _brands[index] = value; }
    }
}
```

### 现代 C# 语法的简化
对于简单的读取逻辑，可以利用现代 C#（C# 6.0 及以上）的表达式主体定义来极大简化索引器的代码：

```csharp
public class Car
{
    private string[] _brands = new string[] { "BMW", "Audi", "Mercedes" };

    // 只读索引器的简写形式
    public string this[int index] => _brands[index];
}
```

### 设计理念考量
根据《Effective C#》的建议：
1. **符合直觉**：只有当你的类在逻辑上“表现为一个集合、序列或字典”时，才应该为其添加索引器。如果一个类本身不是为了容纳一组数据而设计的，滥用索引器会破坏代码的语义和可读性。
2. **健壮性**：在 `get` 和 `set` 内部，应该时刻注意数组越界问题。在工业级代码中，应当对传入的 `index` 进行参数范围验证，并在非法调用时抛出 `ArgumentOutOfRangeException`，以避免引发不可预期的底层异常。
