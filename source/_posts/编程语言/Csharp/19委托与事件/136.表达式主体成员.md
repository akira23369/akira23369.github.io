# 表达式主体成员

在现代 C# 编程中，减少样板代码（Boilerplate Code）以提高代码的信噪比是语言演进的重要方向。**表达式主体成员（Expression-Bodied Members）** 提供了一种极其精简的语法糖，用于替代传统的仅包含单行语句的方法或属性体。

## 核心概念与语法特征

当一个类成员（如方法、属性、构造函数）的逻辑仅仅是一个**单一的表达式**或**单行语句**时，可以省略传统的大括号 `{ }` 以及 `return` 关键字，改用箭头运算符 `=>` 直接连接成员声明与逻辑实现。

*注：这里的 `=>` 虽然与 Lambda 表达式使用的是同一个符号，但它们在语言规范中属于不同的特性。{% post_link 130.内联Lambda表达式#的各种省略 Lambda 用于内联匿名方法 %}，而表达式主体成员用于简化类级别的具名成员声明。*



## 演进历史与适用范围

该特性是分阶段引入 C# 的：
*   **C# 6.0 引入：** 支持**方法（Methods）**、**只读属性（Read-only Properties）** 和**索引器（Indexers）** 。
*   **C# 7.0 扩展：** 进一步支持了**构造函数（Constructors）**、**析构函数/终结器（Destructors/Finalizers）** 以及属性的 `get` 和 `set` 访问器 。

## 典型代码对比与应用

以下代码展示了如何使用表达式主体成员来重构传统的类成员定义：

```csharp
using System;

public class Student
{
    private string _studentName;

    // ==========================================
    // 1. 构造函数 (C# 7.0+)
    // ==========================================
    // 传统写法：
    // public Student(string name) { _studentName = name; }
    
    // 表达式主体写法：
    public Student(string name) => _studentName = name;

    // ==========================================
    // 2. 属性的 Get/Set 访问器 (C# 7.0+)
    // ==========================================
    // 传统写法：
    // public string StudentName 
    // { 
    //     get { return _studentName; } 
    //     set { _studentName = value; } 
    // }
    
    // 表达式主体写法：
    public string StudentName
    {
        get => _studentName;
        set => _studentName = value;
    }

    // ==========================================
    // 3. 只有 Get 访问器的只读属性 (C# 6.0+)
    // ==========================================
    // 极端简化的写法，连 get 关键字都省略了
    public int NameLength => _studentName?.Length ?? 0;

    // ==========================================
    // 4. 返回值方法 (C# 6.0+)
    // ==========================================
    // 自动推断返回值，省略 return 关键字
    public string GetGreeting() => $"Hello, {_studentName}!";

    // ==========================================
    // 5. Void 方法 (C# 6.0+)
    // ==========================================
    public void PrintInfo() => Console.WriteLine($"Student Name: {_studentName}");
}
```

### 方法
C#6.0
这是最常见的用法，直接省掉大括号。
```cs
// 传统写法
public int Add(int a, int b) { return a + b; }

// 表达式主体写法
public int Add(int a, int b) => a + b;

// 即使没有返回值也可以
public void Log(string msg) => Console.WriteLine(msg);
```


### 只读属性
C#6.0
如果你只需要获取一个值，不需要复杂的 `set` 逻辑，这是最优雅的写法。

```cs
// 传统写法
public string FullName { get { return $"{FirstName} {LastName}"; } }

// 表达式主体写法 (隐式包含 get)
public string FullName => $"{FirstName} {LastName}";
```

### 属性访问器
自 C# 7.0 起
如果你需要同时写 `get` 和 `set`，但逻辑都很简单，也可以分别对它们使用 `=>`。
```cs
private string _name;
public string Name
{
    get => _name;
    set => _name = value ?? "未命名"; // 配合 ?? 运算符非常香
}
```

### 构造函数
C# 7.0 
通常用于给属性赋初始值。
```cs
public class User
{
    public string Name { get; }
    // 传统写法：public User(string name) { Name = name; }
    
    public User(string name) => Name = name; 
}
```

### 析构函数
C# 7.0
虽然现在很少手动写析构函数，但它确实支持这个语法。
```cs
class ResourceHolder
{
    // 释放资源时的简写
    ~ResourceHolder() => Console.WriteLine("资源已回收");
}
```

### 索引器
C# 7.0 
当你的类像数组一样可以用 `[]` 取值时。
```cs
public class MyCollection
{
    private string[] _data = new string[10];

    // 只读索引器
    public string this[int i] => _data[i];

    // 或者带 get/set 的索引器
    /*
    public string this[int i]
    {
        get => _data[i];
        set => _data[i] = value;
    }
    */
}
```

### 本地函数
C# 7.0
在方法内部定义的小函数。
```cs
public void ProcessData()
{
    // 定义一个内部小工具
    int Square(int x) => x * x;

    Console.WriteLine(Square(5));
}
```




## 底层机制与编译行为
参考《CLR via C#》

理解表达式主体成员的关键在于：**它纯粹是编译器的语法糖（Syntactic Sugar）。**

从 CLR（公共语言运行时）的视角来看，表达式主体成员和使用 `{ }` 编写的常规成员在生成的 IL（中间语言）代码上是**完全一模一样**的。
例如，`public int GetLength() => _studentName.Length;` 在编译后，编译器会自动为其加上方法体块和 `return` 指令。

因此，使用表达式主体成员**不会带来任何运行时的性能损耗**，也不会改变程序的底层执行逻辑，它仅仅是为了提升开发者的编码体验和代码的视觉简洁度。

## 最佳实践与滥用防范
参考《代码大全》与 Clean Code

虽然 `=>` 语法非常优雅，但《Effective C#》等经典著作通常建议在此特性的使用上保持克制，遵循以下原则：

### 推荐使用的场景：
*   简单的字段赋值（如简单的构造函数）。
*   简单的属性封装（Getter / Setter）。
*   单行的方法转发（将调用委托给内部的其他对象）。
*   简单的单行数学计算或字符串拼接。

### 严禁滥用的场景：
不能因为追求“一行代码解决问题”，而将复杂的逻辑强行塞入表达式主体成员中。
如果表达式内部包含复杂的嵌套三元运算符 `?:`、长链式 LINQ 查询或复杂的逻辑判断，将其写成一行会导致代码的**可读性急剧下降**。

**反面教材（不推荐）：**
```csharp
// 强行使用表达式主体，导致难以阅读
public string GetStatus() => Age < 18 ? "Teen" : Score > 90 ? "Excellent" : "Normal";
```

**正确做法：**
当逻辑由于太过复杂以至于跨越多行才能舒服地阅读时，请果断退回到使用大括号 `{ }` 和普通的方法体结构。代码的清晰度永远优先于语法上的简写。
