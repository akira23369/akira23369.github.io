# 多播委托

在 C# 中，委托不仅可以指向单个方法，还可以同时指向多个方法。这种能够持有多个方法引用的委托被称为**多播委托（Multicast Delegate）**。多播委托是 C# 中实现观察者模式（Observer Pattern）以及事件（Events）体系的底层基础。

## 核心概念：单播与多播的对比

*   **单播委托 (Single-cast Delegate)：** 委托对象内部只包含一个方法的引用。调用该委托时，只执行这一个方法。
*   **多播委托 (Multicast Delegate)：** 委托对象内部维护了一个“调用列表（Invocation List）”，包含多个方法的引用。当调用该委托时，会按照方法添加的顺序，**依次同步执行**列表中的所有方法。

**硬性约束：** 无论是单播还是多播，所有被挂载到委托上的方法，其签名（参数数量、类型、顺序）必须与委托定义的签名完全一致。

## 多播委托的创建与使用

在 C# 中，构建多播委托极其简单，主要通过重载的 `+=` 和 `-=` 运算符来实现方法的追加与移除。

### 代码示例
```csharp
using System;

// 1. 声明委托（推荐使用 void 返回类型，稍后解释原因）
public delegate void MathOperation(double a, double b);

public class Calculator
{
    public void Add(double x, double y)
    {
        Console.WriteLine($"Add: {x} + {y} = {x + y}");
    }

    public void Multiply(double x, double y)
    {
        Console.WriteLine($"Multiply: {x} * {y} = {x * y}");
    }
}

public class Program
{
    public static void Main()
    {
        Calculator calc = new Calculator();

        // 2. 初始化委托（此时是单播）
        MathOperation operations = calc.Add;

        // 3. 使用 += 追加方法（转变为多播委托）
        operations += calc.Multiply;

        // 4. 执行多播委托
        // 会依次输出 Add 的结果，然后输出 Multiply 的结果
        Console.WriteLine("--- 第一次调用 ---");
        operations.Invoke(10, 5); 

        // 5. 使用 -= 移除方法
        operations -= calc.Add;

        Console.WriteLine("--- 第二次调用 ---");
        // 此时列表中只有 Multiply，只输出 Multiply 的结果
        operations.Invoke(10, 5); 
    }
}
```

## 返回值丢失陷阱(核心注意事项)

在设计多播委托时，**强烈建议将委托的返回类型设计为 `void`**。

如果在多播委托中定义了非 `void` 的返回值（如 `int` 或 `string`），当委托被调用并依次执行内部的多个方法时，**只有调用列表中最后一个被执行的方法的返回值会被接收到，前面所有方法的返回值都会被直接覆盖并丢弃。**

```csharp
public delegate int Calculation(int a, int b);

public static int Add(int a, int b) { return a + b; }
public static int Multiply(int a, int b) { return a * b; }

// 调用示例：
Calculation calc = Add;
calc += Multiply;

// 实际执行了 Add(2, 3) 得到 5，但被丢弃；
// 然后执行 Multiply(2, 3) 得到 6。
// 最终 result 的值只有 6。
int result = calc(2, 3); 
```

## 底层机制与不可变性
参考《CLR via C#》与《C# in Depth》

要真正掌握多播委托，必须理解其在 CLR 层面的运作机制：

1.  **委托是不可变的 (Immutable)：** 类似于 C# 中的 `string`，委托对象一旦创建，其内部的调用列表就不能再改变。
2.  **`+=` 和 `-=` 的语法糖：** 
    当你写下 `operations += calc.Multiply;` 时，底层实际上是调用了 `System.Delegate.Combine()` 方法。该方法会创建一个**全新**的委托对象，将原来的方法和新追加的方法组合到这个新对象的调用列表中，然后将新对象的引用重新赋值给 `operations` 变量。
    同理，`-=` 对应的是 `System.Delegate.Remove()` 方法。

## 进阶：异常处理与 GetInvocationList
参考《Effective C#》

多播委托在默认的顺序调用机制下存在一个致命的隐患：**如果调用列表中的某一个方法抛出了未处理的异常，委托的执行链会立即中断，排在后面的所有方法将永远不会被执行。**

为了打造健壮的程序（尤其是在发布-订阅模式下，不能因为一个订阅者的错误导致其他订阅者收不到消息），我们需要手动接管多播委托的执行流程。可以通过调用 `GetInvocationList()` 获取底层的委托数组，并逐一安全地调用它们。

### 安全调用多播委托的健壮代码

```csharp
public delegate void Notify();

public static void MethodThatThrows() { throw new Exception("Error!"); }
public static void MethodSafe() { Console.WriteLine("Safe method executed."); }

public static void Main()
{
    Notify myDelegate = MethodThatThrows;
    myDelegate += MethodSafe;

    // 危险做法：如果直接调用 myDelegate()，程序会崩溃，MethodSafe 永远不执行

    // 安全做法：手动遍历调用列表
    Delegate[] invocationList = myDelegate.GetInvocationList();
    
    foreach (Notify handler in invocationList)
    {
        try
        {
            handler.Invoke();
        }
        catch (Exception ex)
        {
            // 记录日志并吞咽异常，确保后续方法继续执行
            Console.WriteLine($"Caught exception: {ex.Message}");
        }
    }
}
```

## 总结与延伸

多播委托直接使用的场景在现代 C# 开发中并不多见，因为直接暴露委托字段会破坏类的封装性（外部类可以随意使用 `=` 清空整个调用列表，或者直接调用该委托）。

为了解决这个封装性问题，C# 引入了 **事件（Events）**。事件本质上就是对多播委托的一层安全封装，它只向外暴露了 `+=`（订阅）和 `-=`（取消订阅）操作，屏蔽了直接赋值和外部调用的能力。
