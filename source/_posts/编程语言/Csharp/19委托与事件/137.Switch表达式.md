# Switch表达式

在 C# 8.0 中，微软引入了 **Switch 表达式（Switch Expressions）**。这是 C# 语言向函数式编程（Functional Programming）风格演进的又一重要标志。它提供了一种极为精简的语法，用于替代传统的、基于语句的（Statement-based）`switch` 结构，专门解决 **“基于不同条件映射并返回一个值”** 的场景。

## 核心概念：语句 vs 表达式

理解 Switch 表达式的前提是区分“语句”和“表达式”：
*   **传统 Switch 语句：** 负责控制程序的执行流。每个 `case` 分支内部可以包含多行代码、赋值操作或方法调用，最后必须通过 `break` 跳出。
*   **Switch 表达式：** 负责计算并返回一个单一的值。它没有执行流控制的概念，整个 `switch` 结构本身就会被运算为一个结果，然后直接赋值给目标变量。

## 语法演进与代码对比

通过对比传统的 `switch` 语句和现代的 `switch` 表达式，可以直观感受到样板代码（Boilerplate Code）的急剧减少。

假设我们需要根据操作码（1到4）返回对应的角色名称。

### 传统的 Switch 语句（繁琐）
```csharp
int operation = 2;
string result;

switch (operation)
{
    case 1:
        result = "Customer";
        break;
    case 2:
        result = "Employee";
        break;
    case 3:
        result = "Supplier";
        break;
    case 4:
        result = "Distributor";
        break;
    default:
        result = "No case available";
        break;
}
```

### 现代的 Switch 表达式（极简）
```csharp
int operation = 2;

// 直接将 switch 表达式的结果赋值给 result 变量
string result = operation switch
{
    1 => "Customer",
    2 => "Employee",
    3 => "Supplier",
    4 => "Distributor",
    _ => "No case available"
};

Console.WriteLine(result); // 输出: Employee
```

## 核心语法规则解析

从上述代码可以总结出 Switch 表达式的几个关键语法变化：

1.  **关键字后置：** `switch` 关键字放在待匹配的变量名（即源变量）**之后**。这种设计更符合从左到右的阅读直觉（"operation 匹配..."）。
2.  **消灭 case 与 break：** 不再使用 `case` 关键字声明分支，也完全废弃了 `break` 关键字（因为表达式天然只会返回一个值，不存在贯穿 Fall-through 的问题）。
3.  **使用箭头运算符 (`=>`)：** 匹配模式和返回值之间使用 `=>` 连接。
4.  **弃元 (`_`) 替代 default：** 传统的 `default` 关键字被下划线 `_`（弃元符号 / Discard）取代，表示“匹配其他所有未列出的情况”。
5.  **逗号分隔：** 各个分支之间使用逗号 `,` 分隔，而不是分号。

## 进阶原理与最佳实践

### 穷尽性检查
在《C# 9.0 in a Nutshell》中特别强调了 Switch 表达式的安全性优势。编译器会对 Switch 表达式进行**穷尽性检查**。
如果编译器发现你的分支没有覆盖所有可能的值（例如缺少了 `_` 弃元分支），它会发出一个编译期警告。如果在运行时传入了一个没有匹配项的值，程序不会默默失败，而是会抛出 `System.Runtime.CompilerServices.SwitchExpressionException` 异常。这种严格的检查极大地提高了代码的健壮性。

### 终极组合：结合表达式主体成员
《Effective C#》推荐将 Switch 表达式与表达式主体成员（`=>` 方法）结合使用，这是现代 C# 中编写数据转换方法的最优雅范式。

```csharp
// 极其优雅的数据映射方法
public string GetRoleName(int operationId) => operationId switch
{
    1 => "Customer",
    2 => "Employee",
    3 => "Supplier",
    4 => "Distributor",
    _ => throw new ArgumentException("未知的操作码", nameof(operationId)) // 现代 C# 允许在表达式中直接 throw
};
```

### 结合模式匹配
Switch 表达式不仅能匹配简单的常量（如 1, 2, 3），它真正的威力在于结合 C# 8.0+ 的**模式匹配**（如关系模式、属性模式等），处理复杂的对象逻辑。

```csharp
public string GetTemperatureStatus(int temp) => temp switch
{
    < 0 => "Freezing",        // 关系模式匹配
    >= 0 and < 30 => "Normal",// 逻辑模式组合
    >= 30 => "Hot"
};
```

## 适用场景与局限性

**推荐使用的场景：**
*   纯粹的数据映射、状态机转换。
*   根据不同的枚举值或特定条件，返回不同的计算结果或字符串。

**不能/不建议使用的场景：**
*   **需要执行副作用（Side Effects）：** 如果在某个条件匹配时，你需要去调用一个返回 `void` 的方法、修改外部变量或向数据库写入数据，**不能**使用 Switch 表达式，必须退回使用传统的 `switch` 语句或 `if-else`。
*   **多行复杂逻辑：** Switch 表达式的分支右侧只能是单一表达式，不支持大括号 `{ }` 的代码块。如果某个分支需要执行几十行复杂的逻辑计算，强行塞入表达式会导致代码可读性彻底崩溃。
