# 预定义泛型委托：Func

在深入学习了委托和事件之后，我们会发现一个痛点：每次为了定义一个方法签名，都需要使用 `delegate` 关键字在类的外部声明一个新的委托类型。这不仅增加了代码的冗余，还会导致项目中充斥着大量仅仅是为了传递方法签名而存在的一次性委托类型。

为了解决这个问题，微软在 .NET Framework 3.5（伴随 C# 3.0 和 LINQ）中引入了一套极其强大的**预定义泛型委托（Predefined Generic Delegates）**，其中最核心的成员之一就是 `Func`。

## 核心概念：什么是 Func？

`Func` 是定义在 `System` 命名空间下的一个内置泛型委托大家族。它的核心职责是封装一个**有返回值**的方法。

**使用 `Func` 的两大硬性条件：**
1. 目标方法可以包含 **0 到 16 个输入参数**。
2. 目标方法**必须且只能有一个返回值**（不能是 `void`）。

### 语法结构解析

`Func` 委托有 17 个重载版本（从没有参数到 16 个参数）。其泛型签名的最后位置**永远**代表方法的**返回类型**，前面的所有泛型参数代表方法的**输入参数类型**。

*   `Func<TResult>`：无输入参数，返回 `TResult` 类型。
*   `Func<T, TResult>`：接收 1 个 `T` 类型参数，返回 `TResult` 类型。
*   `Func<T1, T2, TResult>`：接收 2 个参数，返回 `TResult` 类型。
*   ...以此类推，最多到 `Func<T1, T2, ... T16, TResult>`。

## 为什么要使用 Func？(消灭自定义委托)

参考《Effective C#》的最佳实践：**在现代 C# 编程中，除非有极其特殊的理由（例如需要使用 `ref`/`out` 参数，或者为了给参数起具有强业务语义的名称），否则应全面使用 `Func`、`Action` 等内置委托来替代自定义委托。**

### 代码演进对比

**旧时代的代码（使用自定义委托）：**
```csharp
// 1. 必须先声明一个委托类型，仅仅是为了定义签名
public delegate double CalculateAreaDelegate(double radius);

public class CircleProcessor
{
    // 2. 使用自定义委托声明事件或字段
    public event CalculateAreaDelegate OnCalculateArea;
}
```

**现代 C# 的代码（使用 Func）：**
```csharp
using System;

public class CircleProcessor
{
    // 1. 直接使用 Func 声明事件。接收 double 参数，返回 double 结果。
    // 彻底消灭了外部的 delegate 声明代码。
    public event Func<double, double> OnCalculateArea;
}
```

## 常见实战场景代码示例

`Func` 最常见的搭档就是 **Lambda 表达式**。它在 LINQ 查询、策略模式注入和事件订阅中无处不在。

```csharp
using System;

public class Program
{
    public static void Main()
    {
        // 场景 1：无参数，有返回值
        Func<string> getGreeting = () => "Hello, World!";
        Console.WriteLine(getGreeting()); // 输出: Hello, World!

        // 场景 2：多个参数，有返回值 (结合 Lambda 表达式)
        // 接收两个 int，返回一个 string
        Func<int, int, string> formatAddition = (a, b) => 
        {
            int sum = a + b;
            return $"{a} + {b} = {sum}";
        };
        Console.WriteLine(formatAddition(5, 7)); // 输出: 5 + 7 = 12

        // 场景 3：将 Func 作为方法的参数传递 (高阶函数)
        // 这是 LINQ 底层 Where, Select 等扩展方法的核心原理
        int[] numbers = { 1, 2, 3, 4, 5 };
        int[] squaredNumbers = ProcessArray(numbers, x => x * x);
        
        Console.WriteLine(string.Join(", ", squaredNumbers)); // 输出: 1, 4, 9, 16, 25
    }

    // 接收一个整型数组和一个 Func 委托（定义了如何处理单个元素的逻辑）
    public static int[] ProcessArray(int[] input, Func<int, int> processor)
    {
        int[] result = new int[input.Length];
        for (int i = 0; i < input.Length; i++)
        {
            // 通过委托执行外部传入的逻辑
            result[i] = processor(input[i]);
        }
        return result;
    }
}
```

## Func 的局限性与注意事项

虽然 `Func` 极其方便，但它并不是万能的。根据《C# in Depth》的解析，在以下场景中不能使用 `Func`：

1.  **返回值为 `void` 的情况：** `Func` 的泛型参数类型不能是 `void`（泛型参数必须是具体的类型）。如果方法不需要返回值，必须使用 `Action` 委托。
2.  **包含 `ref` 或 `out` 参数：** 预定义的 `Func` 签名不支持 `ref` 和 `out` 修饰符。如果你的方法有这样的参数，你依然需要像以前一样手动声明自定义委托。
3.  **丧失了参数的语义：** 在自定义委托 `delegate int Compare(int left, int right)` 中，你可以清楚地通过参数名 `left` 和 `right` 知道各自的含义。但使用 `Func<int, int, int>` 时，这种自我描述的语义就丢失了。在极度复杂的 API 设计中，有时为了文档清晰度，保留自定义委托是值得的。
