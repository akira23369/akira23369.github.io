# Lambda表达式

在 C# 3.0 中引入的 **Lambda 表达式** 是 C# 语言进化史上的一个重要里程碑。它不仅彻底改变了开发者编写委托和事件处理程序的方式，更是整个 LINQ (Language Integrated Query) 架构的语法基石。

## 核心概念与演进

Lambda 表达式在逻辑上与 C# 2.0 的**匿名方法（Anonymous Methods）** 完全相同：它们都是没有名称的内联方法，必须被赋值给一个委托或事件才能执行。

相比于匿名方法，Lambda 表达式提供了更加现代、简洁且富有表现力的语法。在《Effective C#》中，强烈建议开发者**全面使用 Lambda 表达式来替代匿名方法**。

### 语法演进对比

假设我们有一个定义了两个参数并返回整数的委托：
`public delegate int MathOperation(int x, int y);`

*   **匿名方法 (C# 2.0)：** 必须使用 `delegate` 关键字，且必须显式声明参数类型。
    ```csharp
    MathOperation add = delegate(int a, int b) { return a + b; };
    ```
*   **Lambda 表达式 (C# 3.0+)：** 抛弃了 `delegate` 关键字，引入了 **Lambda 运算符 `=>`**（读作 "goes to"）。
    ```csharp
    MathOperation add = (a, b) => { return a + b; };
    ```

## 强大的类型推断

参考《C# in Depth》中对 C# 编译器智能化的剖析，Lambda 表达式最大的优势之一在于**类型推断**。

在上面的例子中，我们写的是 `(a, b)` 而不是 `(int a, int b)`。因为编译器在等号左边看到了 `MathOperation` 委托的定义，它清楚地知道这个委托需要两个 `int` 类型的参数。因此，编译器在后台自动为 `a` 和 `b` 赋予了 `int` 类型。这极大地减少了冗余的样板代码。

## Lambda表达式的语法变体

根据参数的数量和方法体的复杂程度，Lambda 表达式有多种极其简洁的变体：

### 参数列表的变体
*   **多个参数：** 必须使用括号将参数括起来。
    `(a, b) => a + b`
*   **零个参数：** 必须使用一对空括号 `()` 表示。
    `() => Console.WriteLine("Hello")`
*   **单个参数：** 如果只有一个参数，且类型可以推断，**括号可以省略**（这是最常见的 LINQ 写法）。
    `x => x * x`

### 方法体的变体 (语句 vs 表达式)
*   **语句 Lambda (Statement Lambda)：**
    如果方法体包含多条语句，必须使用大括号 `{ }` 将它们括起来。如果有返回值，必须显式使用 `return` 关键字。
    ```csharp
    MathOperation complexOp = (a, b) => 
    {
        int temp = a * 2;
        int result = temp + b;
        return result;
    };
    ```
*   **表达式 Lambda (Expression Lambda)：**
    如果方法体只有**单个表达式**，可以省略大括号 `{ }` 和 `return` 关键字。编译器会自动计算该表达式并返回其结果。
    ```csharp
    MathOperation simpleAdd = (a, b) => a + b;
    ```

## 结合事件与Lambda返回值的完整示例

Lambda 表达式非常适合用于快速订阅事件。以下代码展示了如何使用 Lambda 表达式订阅事件，并且演示了如何从 Lambda 表达式中返回值并将其打印出来。

```csharp
using System;

// 1. 定义带有返回值的委托
public delegate int CalculationDelegate(int num1, int num2);

public class Publisher
{
    // 2. 自动实现的事件
    public event CalculationDelegate OnCalculate;

    public void RaiseEvent(int x, int y)
    {
        // 确保有订阅者
        if (OnCalculate != null)
        {
            // 触发事件并接收返回值
            int result = OnCalculate.Invoke(x, y);
            Console.WriteLine($"事件触发成功，接收到订阅者的计算结果: {result}");
        }
    }
}

public class Program
{
    public static void Main()
    {
        Publisher pub = new Publisher();

        // 3. 使用 Lambda 表达式订阅事件 (语句 Lambda)
        pub.OnCalculate += (a, b) =>
        {
            Console.WriteLine($"[订阅者 1] 正在计算 {a} + {b}...");
            return a + b;
        };

        // 触发事件
        pub.RaiseEvent(10, 20); // 输出: 30

        // ----------------------------------------------------
        
        // 覆盖订阅：使用更简洁的表达式 Lambda 进行乘法计算
        // 注意：事件是多播委托，这里为了演示返回值，先清空之前的订阅
        pub.OnCalculate -= null; // (演示逻辑，实际应按需移除)
        Publisher pub2 = new Publisher();

        pub2.OnCalculate += (a, b) => a * b; // 极致简洁

        pub2.RaiseEvent(14, 2); // 输出: 28
    }
}
```

## 底层机制与闭包（补充）

与匿名方法一样，从 CLR（公共语言运行时）的视角来看，Lambda 表达式并不存在特殊的数据结构。

在《CLR via C#》中明确指出，编译 C# 代码时，编译器会自动将 Lambda 表达式提取为一个隐藏的常规方法。
*   如果 Lambda 表达式没有使用任何外部变量，它会被编译为一个**私有静态方法 (private static method)**，以获得最高性能。
*   如果 Lambda 表达式捕获了其外部作用域的局部变量（即形成了**闭包 Closure**），编译器会自动生成一个隐藏的类，将这些局部变量作为该类的字段，以延长这些变量的生命周期，防止它们随外部方法的结束而被栈销毁。

在 C# 中，**闭包（Closure）** 是一个非常强大且常用的特性，尤其是在使用 Lambda 表达式和 LINQ 时。

简单来说：**闭包允许一个函数（通常是匿名方法或 Lambda 表达式）“记住”并访问它被定义时所在外部作用域中的变量，即使这个外部作用域的代码已经执行完毕。**

为了让你彻底明白，我们从“现象”到“底层原理”一步步来看。

---

### 闭包的现象（代码演示）

我们先来看一个经典的闭包例子：创建一个计数器。

```csharp
using System;

public class Program
{
    // 这个方法返回一个 Func<int> 委托（即返回一个函数）
    public static Func<int> CreateCounter()
    {
        int count = 0; // 局部变量

        // 返回一个 Lambda 表达式。这个 Lambda 使用了外部的变量 count
        return () => 
        {
            count++;
            return count;
        };
    }

    public static void Main()
    {
        // 拿到计数器函数
        Func<int> myCounter = CreateCounter();

        // 此时 CreateCounter 方法已经执行完毕，
        // 按理说局部变量 count 应该在栈上被销毁了。
        // 但是看下面的输出：
        
        Console.WriteLine(myCounter()); // 输出 1
        Console.WriteLine(myCounter()); // 输出 2
        Console.WriteLine(myCounter()); // 输出 3
    }
}
```

**疑问：** 为什么 `CreateCounter` 方法已经执行完了，`count` 变量不但没有死，反而还能继续累加？
**答案：** 因为 C# 编译器为你创建了一个**闭包**。

---

### 闭包的底层原理（编译器施的魔法）

在 C# 中，闭包并不是 CLR（公共语言运行时）原生的机制，而是**编译器（Roslyn）提供的一种语法糖**。

当编译器发现你的 Lambda 表达式使用（捕获）了外部的局部变量时，它会在后台默默地做以下几件事：

1.  **创建一个隐藏的类**（通常命名类似于 `<>c__DisplayClass`）。
2.  将你捕获的局部变量，提升为**这个隐藏类的公共字段**。
3.  将你的 Lambda 表达式，变成**这个隐藏类里的一个方法**。
4.  在你原来的方法中，实例化这个隐藏类，并用类的字段替换原来的局部变量。

我们把上面的代码用 **“编译器视角”** 还原一下，它大概等价于下面这样：

```csharp
// 1. 编译器生成的隐藏类
private sealed class CompilerGeneratedDisplayClass
{
    public int count; // 被捕获的局部变量变成了类的字段！

    // Lambda 表达式变成了类的方法
    internal int AnonymousMethod()
    {
        this.count++;
        return this.count;
    }
}

public static Func<int> CreateCounter()
{
    // 2. 编译器重写了你的方法
    // 实例化那个隐藏类
    CompilerGeneratedDisplayClass displayClass = new CompilerGeneratedDisplayClass();
    
    // 初始化字段
    displayClass.count = 0; 

    // 返回那个对象的实例方法（构成委托）
    return displayClass.AnonymousMethod;
}
```

**原理解析：**
本来 `count` 只是分配在**栈（Stack）** 上的局部变量，方法结束就被回收了。
但是因为闭包，编译器把它塞进了一个类的实例中，而类的实例是分配在**堆（Heap）** 上的。只要 `myCounter` 这个委托还在被引用，这个隐藏类的实例就不会被垃圾回收（GC），`count` 的生命周期就被硬生生延长了。

---

### 闭包最经典的陷阱：循环变量捕获

了解了原理后，我们来看 C# 中由于闭包引发的最高频的 Bug：在 `for` 循环中捕获变量。

#### 错误示范：
```csharp
using System;
using System.Collections.Generic;

public class Program
{
    public static void Main()
    {
        List<Action> actions = new List<Action>();

        for (int i = 0; i < 3; i++)
        {
            // 将打印 i 的操作加入列表
            actions.Add(() => Console.WriteLine(i)); 
        }

        // 执行所有操作
        foreach (var action in actions)
        {
            action();
        }
    }
}
```
**期望输出：** 0, 1, 2
**实际输出：** 3, 3, 3

#### 为什么会这样？（用原理来解释）
因为 `for` 循环中的变量 `i` 在整个循环过程中只有**一个**。编译器在背后只创建了**一个**隐藏类实例。
等效代码如下：
```csharp
CompilerGeneratedDisplayClass displayClass = new CompilerGeneratedDisplayClass();
for (displayClass.i = 0; displayClass.i < 3; displayClass.i++)
{
    actions.Add(displayClass.AnonymousMethod);
}
```
当循环结束时，`displayClass.i` 的值已经是 3 了。之后你遍历执行 `action()` 时，它们都去读这同一个实例里的 `i`，自然全都打印 3。

#### 正确做法：
在循环内部引入一个**块级作用域的局部变量**，这样每次循环都会创建一个全新的隐藏类实例。

```csharp
for (int i = 0; i < 3; i++)
{
    int temp = i; // 关键：每次循环都声明一个新的局部变量
    actions.Add(() => Console.WriteLine(temp)); 
}
// 这样就能正确输出 0, 1, 2 了
```

*(注：C# 5.0 针对 `foreach` 循环修复了这个“反直觉”的问题，在 `foreach` 中捕获迭代变量现在是安全的，但 `for` 循环由于语义原因依然保留上述行为。)*

---

### 总结

1.  **闭包本质**：闭包捕获的是变量的**引用**，而不是变量当时的值。
2.  **底层实现**：编译器通过生成隐藏的**类**，将栈上的局部变量转移到堆上，延长了变量的生命周期。
3.  **内存注意**：因为闭包会把局部变量提升到堆上并保持引用，如果闭包的生命周期很长（比如注册为全局事件），可能会导致它捕获的变量（哪怕是个很大的对象）无法被 GC 回收，从而造成**内存泄漏**。
4.  **循环陷阱**：在 `for` 循环里使用闭包时，一定要注意把循环变量赋值给循环体内的临时变量再捕获。
