# Lambda表达式

在 C# 3.0 中引入的 **Lambda 表达式** 是 C# 语言进化史上的一个重要里程碑。它不仅彻底改变了开发者编写委托和事件处理程序的方式，更是整个 LINQ (Language Integrated Query) 架构的语法基石。

## 核心概念与演进

Lambda 表达式在逻辑上与 C# 2.0 的**匿名方法（Anonymous Methods）** 完全相同：它们都是没有名称的内联方法，必须被赋值给一个委托或事件才能执行。

相比于匿名方法，Lambda 表达式提供了更加现代、简洁且富有表现力的语法。在《Effective C#》中，强烈建议开发者**全面使用 Lambda 表达式来替代匿名方法**。

### 语法演进对比

假设我们有一个定义了两个参数并返回整数的委托：
`public delegate int MathOperation(int x, int y);`

*   **匿名方法 (C# 2.0)：** 必须使用 `delegate` 关键字，且必须显式声明参数类型。
    ```csharp
    MathOperation add = delegate(int a, int b) { return a + b; };
    ```
*   **Lambda 表达式 (C# 3.0+)：** 抛弃了 `delegate` 关键字，引入了 **Lambda 运算符 `=>`**（读作 "goes to"）。
    ```csharp
    MathOperation add = (a, b) => { return a + b; };
    ```

## 强大的类型推断

参考《C# in Depth》中对 C# 编译器智能化的剖析，Lambda 表达式最大的优势之一在于**类型推断**。

在上面的例子中，我们写的是 `(a, b)` 而不是 `(int a, int b)`。因为编译器在等号左边看到了 `MathOperation` 委托的定义，它清楚地知道这个委托需要两个 `int` 类型的参数。因此，编译器在后台自动为 `a` 和 `b` 赋予了 `int` 类型。这极大地减少了冗余的样板代码。

## Lambda表达式的语法变体

根据参数的数量和方法体的复杂程度，Lambda 表达式有多种极其简洁的变体：

### 参数列表的变体
*   **多个参数：** 必须使用括号将参数括起来。
    `(a, b) => a + b`
*   **零个参数：** 必须使用一对空括号 `()` 表示。
    `() => Console.WriteLine("Hello")`
*   **单个参数：** 如果只有一个参数，且类型可以推断，**括号可以省略**（这是最常见的 LINQ 写法）。
    `x => x * x`

### 方法体的变体 (语句 vs 表达式)
*   **语句 Lambda (Statement Lambda)：**
    如果方法体包含多条语句，必须使用大括号 `{ }` 将它们括起来。如果有返回值，必须显式使用 `return` 关键字。
    ```csharp
    MathOperation complexOp = (a, b) => 
    {
        int temp = a * 2;
        int result = temp + b;
        return result;
    };
    ```
*   **表达式 Lambda (Expression Lambda)：**
    如果方法体只有**单个表达式**，可以省略大括号 `{ }` 和 `return` 关键字。编译器会自动计算该表达式并返回其结果。
    ```csharp
    MathOperation simpleAdd = (a, b) => a + b;
    ```

## 结合事件与Lambda返回值的完整示例

Lambda 表达式非常适合用于快速订阅事件。以下代码展示了如何使用 Lambda 表达式订阅事件，并且演示了如何从 Lambda 表达式中返回值并将其打印出来。

```csharp
using System;

// 1. 定义带有返回值的委托
public delegate int CalculationDelegate(int num1, int num2);

public class Publisher
{
    // 2. 自动实现的事件
    public event CalculationDelegate OnCalculate;

    public void RaiseEvent(int x, int y)
    {
        // 确保有订阅者
        if (OnCalculate != null)
        {
            // 触发事件并接收返回值
            int result = OnCalculate.Invoke(x, y);
            Console.WriteLine($"事件触发成功，接收到订阅者的计算结果: {result}");
        }
    }
}

public class Program
{
    public static void Main()
    {
        Publisher pub = new Publisher();

        // 3. 使用 Lambda 表达式订阅事件 (语句 Lambda)
        pub.OnCalculate += (a, b) =>
        {
            Console.WriteLine($"[订阅者 1] 正在计算 {a} + {b}...");
            return a + b;
        };

        // 触发事件
        pub.RaiseEvent(10, 20); // 输出: 30

        // ----------------------------------------------------
        
        // 覆盖订阅：使用更简洁的表达式 Lambda 进行乘法计算
        // 注意：事件是多播委托，这里为了演示返回值，先清空之前的订阅
        pub.OnCalculate -= null; // (演示逻辑，实际应按需移除)
        Publisher pub2 = new Publisher();

        pub2.OnCalculate += (a, b) => a * b; // 极致简洁

        pub2.RaiseEvent(14, 2); // 输出: 28
    }
}
```

## 底层机制与闭包

与匿名方法一样，从 CLR（公共语言运行时）的视角来看，Lambda 表达式并不存在特殊的数据结构。

在《CLR via C#》中明确指出，编译 C# 代码时，编译器会自动将 Lambda 表达式提取为一个隐藏的常规方法。
*   如果 Lambda 表达式没有使用任何外部变量，它会被编译为一个**私有静态方法 (private static method)**，以获得最高性能。
*   如果 Lambda 表达式捕获了其外部作用域的局部变量（即形成了**闭包 Closure**），编译器会自动生成一个隐藏的类，将这些局部变量作为该类的字段，以延长这些变量的生命周期，防止它们随外部方法的结束而被栈销毁。
