# 内联Lambda表达式

在 C# 3.0 中，Lambda 表达式被引入以简化委托的实例化过程。根据方法体的复杂程度，Lambda 表达式在官方 C# 语言规范（及《C# in Depth》等经典著作）中被严格划分为两类：**语句 Lambda (Statement Lambdas)** 和 **表达式 Lambda (Expression Lambdas)**。

本节重点探讨的“内联 Lambda 表达式（Inline Lambda Expressions）”，在官方术语中即指 **表达式 Lambda**。它是 C# 中追求极致简洁的语法特性，也是 LINQ 能够流畅书写的基石。

## 核心概念与语法特征

内联 Lambda 表达式是一种为了处理**单一计算、单一条件判断或单一方法调用**而设计的极简语法。

**核心特征：**
1.  **无大括号 `{ }`：** 舍弃了常规方法体的作用域边界。
2.  **无 `return` 关键字：** 编译器会自动计算箭头 `=>` 右侧表达式的结果，并将其作为隐式的返回值。
3.  **无局部变量：** 由于没有方法体（没有 `{ }` 构成的大块作用域），在表达式内部无法声明局部变量。
4.  **单行限制：** 箭头右侧只能是一个合法的 C# 表达式，不能包含多条语句。

## 语法的极简演进

通过代码对比，可以直观感受到内联 Lambda 表达式是如何一步步剥离冗余代码的：

```csharp
public delegate int MathOperation(int a, int b);

public class Program
{
    public static void Main()
    {
        // 1. 常规的语句 Lambda (Statement Lambda)
        // 包含大括号和明确的 return 关键字
        MathOperation add1 = (a, b) => 
        { 
            return a + b; 
        };

        // 2. 内联 Lambda 表达式 (Expression / Inline Lambda)
        // 极其纯粹，只包含核心的计算逻辑
        MathOperation add2 = (a, b) => a + b;

        Console.WriteLine(add2(10, 20)); // 输出: 30
    }
}
```
在 `(a, b) => a + b` 中，这段代码在逻辑上依然是一个“方法”，它接收两个参数并返回它们的和，只是在语法表现上达到了最简。

## 典型实战场景：集合搜索与 LINQ

参考《Effective C#》的建议，内联 Lambda 表达式最大的发挥舞台是作为参数传递给框架的预定义方法（如集合的查找、过滤操作）。

在没有 Lambda 表达式之前，想要在数组中查找特定条件的元素，需要编写繁琐的循环或单独定义一个谓词（Predicate）方法。使用内联 Lambda 表达式后，代码的意图变得一目了然。

### 代码示例：结合 `Array.Find` 使用

```csharp
using System;

public class Program
{
    public static void Main()
    {
        int[] numbers = { 10, 25, 30, 45, 50, 65 };

        // 场景 1：查找数组中第一个大于 40 的数字
        // Array.Find 接收一个 Predicate<int> 委托 (即接收 int，返回 bool)
        // 我们传入内联 Lambda：n => n > 40
        int firstMatch = Array.Find(numbers, n => n > 40);
        Console.WriteLine($"第一个大于 40 的数字: {firstMatch}"); // 输出: 45

        // 场景 2：查找数组中所有的偶数 (使用 Array.FindAll)
        int[] evenNumbers = Array.FindAll(numbers, n => n % 2 == 0);
        Console.WriteLine($"所有的偶数: {string.Join(", ", evenNumbers)}"); // 输出: 10, 30, 50
    }
}
```
在这个例子中，`n => n > 40` 就是一个内联 Lambda 表达式。它不仅省去了单独定义方法的麻烦，更让“查找规则”与“查找动作”紧密结合在同一行代码中，极大地提升了代码的连贯性。

## 底层机制与编译器行为

尽管内联 Lambda 表达式在代码上看似只是一个简单的公式，但从 CLR（公共语言运行时）的角度来看，编译器会对其进行复杂的转换：

1.  **编译为普通委托：** 在大多数上下文中（如传递给 `Array.Find`），编译器会在底层生成一个私有的静态或实例方法，并实例化一个委托对象来指向该方法。
2.  **编译为表达式树 (Expression Trees)：** 这是高级 C# 编程（特别是 Entity Framework 等 ORM 框架）的核心。如果目标类型是 `Expression<Func<T>>` 而不是 `Func<T>`，C# 编译器**不会**将内联 Lambda 编译成可执行的 IL 代码，而是将其解析为一个**抽象语法树（AST）**的数据结构。这使得像 Entity Framework 这样的框架能够读取这个数学公式（如 `n > 40`），并将其翻译为底层的 SQL 查询语句（如 `WHERE n > 40`）。

*注意：只有单一表达式的内联 Lambda 才能被编译为表达式树，包含 `{ }` 的语句 Lambda 是无法转换为表达式树的。*



# `=>`的各种省略

看到 `=>`觉得头晕很正常，因为它在 C# 里确实身兼数职。所谓的“省略”，其实更多是 C# 为了让你少写代码而提供的**语法糖**。

我们可以把 `=>` 的用法分为两大类来拆解：**Lambda 表达式**（逻辑逻辑）和 **表达式主体定义**（结构缩写）。

---

## Lambda 表达式中的“省略”

Lambda 本质上是一个“匿名函数”。它的完整形态很啰嗦，但 C# 允许你根据情况一层层把壳剥掉。

**演变过程：**
- **完整版：** `(int x) => { return x * x; }`
- **省略类型：** `(x) => { return x * x; }`（编译器能推断出 `x` 是啥）
- **省略括号：** `x => { return x * x; }`（**只有当参数只有一个时**，才能删掉括号）
- **省略大括号和 return：** `x => x * x`（**只有当主体只有一行表达式时**，可以全删掉）
    

> **关键点：** 你看到的很多地方“省略”了 `=>` 之后的内容，其实是因为它把 `return` 和 `{}` 都吸收到那一个箭头里去了。

---

## 表达式主体定义

{% post_link 136.表达式主体成员 表达式主体成员 %}
这是 C# 6.0 及以后版本引入的，专门用来简化那些“只有一行代码”的方法或属性。这时候 `=>` 的意思是：**“这个成员的值/逻辑就是后面这一行”。**

### 属性的简化
传统写法：
```cs
public string FullName 
{
    get { return $"{FirstName} {LastName}"; }
}
```

使用 `=>` 简化：
```cs
public string FullName => $"{FirstName} {LastName}";
// 注意：这种写法默认只有 get 访问器。
```

### 方法的简化
只有一行代码的方法
传统写法：
```cs
public void PrintData() 
{
    Console.WriteLine(_data);
}
```


使用 `=>` 简化：
```cs
public void PrintData() => Console.WriteLine(_data);
```

## 什么时候可以“省略”，什么时候必须留着？

| **场景**                  | **什么时候可以简写/省略？**                      | **例子**                                                |
| ----------------------- | ------------------------------------- | ----------------------------------------------------- |
| **参数括号 `()`**           | **只有一个**参数时可以省略。没有参数或多个参数必须留着。        | `x => x*x` (OK)<br><br>  <br><br>`() => Stop()` (需括号) |
| **参数类型 `int`**          | 只要编译器能通过上下文推断出来，**通通建议省略**。           | `(x, y) => x + y`                                     |
| **大括号 `{}` 与 `return`** | 只要你的代码只有**一行表达式**，就可以成对省略。            | `x => x + 1`                                          |
| **属性中的 `get`**          | 如果是只读属性且只有一行逻辑，可以用 `=>` 代替整个 `get` 块。 | `public int Age => 18;`                               |

## 总结

 `=>` 既可以出现在**变量赋值**里（委托/Lambda），也可以出现在**类成员定义**里（属性/方法）。

- 如果在 **LINQ**（比如 `.Where(x => ...)`）里看到它，它是一个**匿名函数**。
- 如果在 **属性名后面** 直接看到它（比如 `public int Num => 10;`），它是一个**只读属性的简写**。

**一个避坑小贴士：**

如果你的逻辑超过一行，或者需要写 `if...else`（非三元表达式），那就乖乖用回传统的 `{ }` 和 `return`，不要强行写在一行里，否则代码调试起来会让你怀疑人生。
