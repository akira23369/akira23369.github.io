# 第七节：类型转换

## 第一讲：类型转换概述

### 引言

类型转换，又称类型铸造，是将变量从一种数据类型转换为另一种的过程。这是编程中基础且频繁的需求。你常会接收到一种格式的数据，但需要另一种格式来执行操作。例如，你可能从控制台输入获取用户的年龄作为字符串文本，但需要将其转换为整型以进行数学计算。C#是一种静态类型语言，意味着编译器必须知道每个变量的类型。类型转换是让我们能够灵活地在这个系统中工作的机制。

### 转换类别

C#中的转换操作可分为两大基本类别，其区分依据在于转换是否被视为"安全"或"不安全"。

**隐式转换（安全转换）**： 这类转换能确保成功执行且不会造成数据丢失。C#编译器可识别其安全性，并自动执行此类转换而无需特殊语法。当从"较小"、精度较低的类型转换为"较大"、精度更高的类型时会发生这种转换。

**显式转换（不安全转换）**： 这类转换存在信息丢失或引发异常的风险。由于转换不能确保成功，C#编译器要求开发者明确声明转换意图。这相当于告诉编译器："我知晓风险但仍要执行"。主要通过以下三种方式实现：

- 类型转换： 使用 (类型) 运算符。
    
- 解析： 使用诸如 int.Parse() 之类的辅助方法进行字符串转换。
    
- 辅助类： 使用 System.Convert 类实现更可控的类型转换。
    

我们将在后续课程中详细探讨每种方法。

## 第二讲：隐式类型转换

### 引言

隐式转换是最简单的类型转换形式。当 C#编译器能够确认转换是安全的且不会丢失数据时，会自动执行这种转换。它通常被称为"拓宽转换"，因为您正在将值移动到具有更宽范围或更高精度的数据类型中。

### 工作原理

编译器允许自动进行这种转换，因为目标类型可以完全表示源类型的所有可能值。例如，long 数据类型的范围比 int 数据类型大得多。因此，任何可能的 int 值都可以安全地放入 long 中，而不会有溢出的风险。编译器识别这一点并执行转换，不需要您使用任何特殊语法。

### 使用场景

您不需要"选择"使用它；当您将较小兼容类型的变量赋值给较大类型的变量时，它会自动发生。

### 常见示例

**int 转换为 long**：

```cs
int numberOfUsers = 50000;  
long bigNumberOfUsers = numberOfUsers; // 隐式转换。不会有数据丢失  
Console.WriteLine(bigNumberOfUsers);
```


**int 转换为 double**： int 是整数类型，而 double 可以存储小数。这种转换是安全的，因为所有整数都可以表示为带 .0 小数部分的数字。

```cs
int itemCount = 12;  
double itemCountAsDouble = itemCount; // 隐式转换。值变为 12.0  
Console.WriteLine(itemCountAsDouble);
```

**float 转换为 double**： double 比 float 具有更高的精度（更多小数位），因此这也是一种安全的、范围扩大的类型转换。

```cs
float price = 49.95F;  
double morePrecisePrice = price; // 隐式转换  
Console.WriteLine(morePrecisePrice);
```


### 面试视角

**问题**："为什么可以直接将 int 赋值给 double 变量，反过来却不行？"

**理想答案**："可以将 int 赋值给 double 是因为这是隐式的扩展转换。所有可能的整数值都能安全地用 double 类型表示而不会丢失数据，因此编译器会自动执行这种转换以提供便利和安全性。反过来则需要显式类型转换，因为可能会丢失 double 的小数部分，这种数据丢失需要程序员明确确认。"

## 第三讲：显式类型转换

### 引言

显式类型转换是一种需要手动向编译器请求的转换操作。当你需要从"较大"类型转换为"较小"类型时（这一过程称为窄化转换），就需要使用这种转换。这种操作具有潜在风险，因为它可能导致数据丢失，或者在更复杂的情况下，在运行时抛出异常。

### 工作原理：类型转换运算符（type）

通过将目标数据类型放在要转换的变量前的括号中，您可以执行显式类型转换。这样做实际上是在告诉编译器："我知道这种转换可能会丢失数据，但我接受风险并对结果负责。"

### 常见场景与数据丢失

**浮点数转整数（截断）**： 当您将 double 或 float 转换为 int 等整数类型时，整个小数部分会被截断 （直接去除），而不会进行四舍五入 。

```cs
double myDouble = 9.99;  
int myInt = (int)myDouble; // 必须使用 (int) 转换运算符  
Console.WriteLine(myInt);  // 输出: 9。.99 部分完全丢失
```


**大整数转小整数（溢出风险）**： 当你将较大的整数类型（如 long）强制转换为较小的类型（如 int）时，如果值在较小类型的范围内，转换会正常进行。但如果值过大，就会发生溢出 ，由于比特位被重新解释，最终会得到一个完全不同且看似随机的数字。

```cs
long myLong = 100;  
int myIntFromLong = (int)myLong; // 这是安全的  
Console.WriteLine(myIntFromLong); // 输出: 100  
​  
long veryLargeLong = 3000000000L; // 这个值大于 int 的最大值  
// 下面这行代码会导致溢出并得到错误的值  
// int overflowedInt = (int)veryLargeLong; 
```


### 无效类型转换异常

在面向对象编程的上下文中，如果尝试将对象强制转换为不兼容的类型，程序能够通过编译，但会在运行时抛出 InvalidCastException 异常。

### 面试视角

**问题**："以下代码 double d = 9.99; int i = (int)d; 的运行结果是什么？"

**理想答案**："变量 i 的值将是 9。将 double 显式转换为 int 时会执行截断而非四舍五入，小数部分会被完全舍弃。"这是检验你是否理解数据丢失机制的常见问题。

## 第四讲：解析

### 引言

解析是将值的字符串表示形式转换为实际数据类型的特定过程。这一过程极为常见，因为来自外部源的数据——用户输入、文本文件、网络响应——几乎总是以字符串形式到达。C#中的每种基本类型（int、double、bool 等）都提供了静态 Parse 方法来处理这种转换。

### 工作原理

Parse 方法接收字符串作为输入，并尝试将其解释为其类型的值。例如，int.Parse() 期望字符串仅包含数字（可能还有一个前导负号）。

### 风险：FormatException

Parse 方法是"乐观的"。它假定字符串格式是有效的。如果不是，该方法将通过抛出 FormatException 而失败。如果这个异常没有被处理（使用 try-catch 块，这是一个更高级的主题），你的整个应用程序将会崩溃。

### 使用场景

仅当你完全确定字符串来源可靠且始终包含有效值时，才应使用 Parse。例如，从你控制的配置文件中读取，或者在你已经通过其他方式验证了字符串之后。永远不要对直接的用户输入使用 Parse。

### 常见示例
```cs
string numberString = "123";  
int parsedInt = int.Parse(numberString); // 转换成功。parsedInt 的值是 123  
​  
string boolString = "true";  
bool parsedBool = bool.Parse(boolString); // 转换成功。parsedBool 的值是 true  
​  
string invalidNumberString = "123a";  
// 下面这行代码会抛出 FormatException 异常，如果未处理会导致程序崩溃  
// int errorInt = int.Parse(invalidNumberString); 
```


## 第五讲：TryParse

### 引言

TryParse 方法是字符串转换中安全、健壮且推荐使用的替代方案，尤其适用于处理不可靠数据（如用户输入）的场景。与 Parse 不同，它在转换失败时不会抛出异常，而是优雅地返回一个布尔值来指示转换是否成功。

### 工作原理：out 参数

TryParse 方法具有非常独特的签名，通常为 bool TryParse(string s, out T result)，其中 T 表示目标类型。

- 该方法会尝试解析输入字符串 s。
    
- 如果转换成功 ，则返回 true 并将转换后的值存入 result 变量（通过 out 关键字传递）。
    
- 如果转换失败 ，则返回 false 并将该类型的默认值（例如 int 类型的 0）存入 result 变量。
    

最关键的是，永远不会抛出异常，这使得你可以通过简单的 if 语句优雅地处理失败情况。

### 使用场景

几乎总是如此。这应该是你处理任何外部来源（用户输入、文件、网络数据）字符串转换时的默认选择。它能帮助你构建健壮的应用程序，不会因为无效输入而崩溃。

### 常见示例：处理用户输入
```cs
Console.Write("Please enter your age: ");  
string userInput = Console.ReadLine();  
​  
// 这里使用了现代的 'out 变量' 声明方式  
if (int.TryParse(userInput, out int age))  
{  
    // 只有转换成功时才会执行这个代码块  
    Console.WriteLine($"Success! You will be {age + 1} on your next birthday.");  
}  
else  
{  
    // 如果用户输入了无效内容（比如 "abc"），会执行这个代码块  
    Console.WriteLine("That is not a valid age. Please enter numbers only.");  
}
```


## 第六讲：转换方法（Convert 类）

### 引言

C#提供了一个专用的静态辅助类 System.Convert，其中包含丰富的基础数据类型转换方法。与强制类型转换或解析相比，它提供了更大的灵活性和不同的行为。

### 工作原理

Convert 类提供了一系列统一的方法，如 Convert.ToInt32()、Convert.ToDouble()、Convert.ToString()和 Convert.ToBoolean()。其中 ToInt32 是转换为标准 int 类型的方法。

### 关键差异与行为特性

**舍入与截断（核心区别）**：

- 显式类型转换 (int) 会 截断 （直接舍弃）小数部分。例如 (int)9.7 结果为 9。
    
- Convert 类执行的是向最接近的偶数舍入 （又称"银行家舍入法"）。例如 Convert.ToInt32(9.7) 结果为 10，而 Convert.ToInt32(8.5) 得 8，Convert.ToInt32(9.5) 得 10。
    
```cs
double d = 9.7;  
int castedInt = (int)d;             // 结果: 9  
int convertedInt = Convert.ToInt32(d); // 结果: 10
```


**空值处理**：

- int.Parse(null) 会抛出异常。
    
- Convert.ToInt32(null) 会优雅地返回 0。
    

### 使用场景

- 当你在不同非字符串类型之间转换（如从 `double` 转为 `int`）且更倾向于使用舍入行为而非截断时。
    
- 当你从 `object` 类型转换并需要优雅处理 `null` 值而不使用 `try-catch` 块时。
    

### 面试视角

**问题**："使用 `(int)` 和 `Convert.ToInt32()` 将 `double` 转换为 `int` 的主要区别是什么？"

**理想答案**："主要有两个关键区别。首先是转换行为：`(int)` 会截断小数部分，而 `Convert.ToInt32()` 会四舍五入到最接近的偶数。其次是空值处理：`Convert.ToInt32(null)` 返回 0，而显式转换空对象会抛出异常。`Convert` 方法通常更适合处理各种数据类型。"

## 第七讲：重要知识点备忘

1. **安全第一：始终优先使用 TryParse**： 在进行字符串转换时，特别是处理来自外部源（如用户输入）的数据时，TryParse 应是您的默认选择。它能避免因 FormatException 导致应用程序崩溃，相比使用 try-catch 块进行验证，还能使代码更加简洁。
    
2. **数据丢失是开发者的责任**： 当你使用显式转换 (type) 时，就是在告诉编译器你已意识到并接受数据丢失的风险。你必须清楚数据如何丢失（例如截断与溢出的区别）。
    
3. **了解区别：Cast、Parse、Convert**：
    
    - 强制转换 (int)：速度最快。会截断小数部分。抛出 InvalidCastException。适用于性能关键场景下兼容数值类型间的转换，且需要截断处理时。
        
    - Parse()：将有效字符串转换为目标类型。失败时抛出 FormatException。仅当输入字符串确保有效时使用。
        
    - Convert 类：最灵活。可对小数进行四舍五入。能处理 null 值。速度稍慢。当需要四舍五入或需要优雅处理多种源类型时使用。
        
4. **了解异常类型**：理解哪些操作会引发哪些异常对调试和面试至关重要。
    
    - InvalidCastException：尝试在不相容的引用类型之间转换，或对 null 对象进行类型转换时抛出。
        
    - FormatException：对格式无效的字符串使用 Parse() 方法时抛出。
        
    - OverflowException：尝试将超出目标类型范围的值进行转换时引发的异常。
        
    - ArgumentNullException：向不接受 null 参数的方法传递了空值，例如 int.Parse(null)。
