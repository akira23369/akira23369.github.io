# C# 模式匹配基础与发展脉络

> 本文目标：  
> - 理解模式匹配的核心概念及意义  
> - 回顾它在 C# 各版本中的演进  
> - 掌握基础语法与常用场景示例  
> - 为后续深入学习打下坚实基础  

---

## 一、为什么要有“模式匹配”？

在程序开发中，我们经常需要根据**对象的类型或特征**来决定执行不同的逻辑。  
传统做法常常非常冗长：

```csharp
object obj = GetData();

if (obj is string)
{
    var str = (string)obj;
    Console.WriteLine($"字符串长度为 {str.Length}");
}
else if (obj is int)
{
    var number = (int)obj;
    Console.WriteLine($"数字平方为 {number * number}");
}
else
{
    Console.WriteLine("未知类型");
}
```

这里有几个问题：
- 需要 **重复类型检查** 与 **类型转换**；
- 代码不够简洁清晰；
- 难以表达复杂结构的逻辑条件。

C# 的 **模式匹配** 语法诞生的目的就是为了解决这些痛点——  
让类型检查、取值、条件判定变成一个统一的、高级的表达式语言特性。

---

## 二、什么是“模式匹配”？

**模式匹配** 是一种语言机制，用于**检测一个对象是否符合某种模式**，  
如果符合就可以直接**提取其中的数据**并继续使用。

在语法层面，“模式”其实就是一个**匹配规则（pattern）**，它可以包括：
- **类型信息**
- **常量值**
- **结构（属性、位置）**
- **逻辑组合**

通俗地说，就是让你能写出这样的表达式：

> “如果这个对象**是某种类型**并且**某个属性值符合某个条件**，我就直接取出这个属性来用。”

---

## 三、C# 模式匹配的演进历史

C# 的模式匹配功能是 **逐版本增强** 的。  
让我们梳理一下主要演进路线：

| 版本 | 新增模式匹配特性 | 示例 |
|------|------------------|------|
| **C# 7.0** | 初代模式匹配：`is` 表达式、`switch` 对象匹配 | `if (x is int i)` |
| **C# 8.0** | 引入 **switch 表达式** 与 **属性模式（Property Pattern）** | `case Point { X: 0, Y: 0 }:` |
| **C# 9.0** | **关系模式**、**逻辑模式**、**模式组合** | `x is > 0 and < 10` |
| **C# 10.0** | 小幅语法增强，如支持常量嵌套匹配 |
| **C# 11.0** | **列表模式（List Pattern）** | `[1, 2, .., 5]` |
| **C# 12.0** | 改善 switch 表达式性能、允许模式局部推断 |

从这个表你能看到，C# 的模式匹配已经从最初的类型判断，  
发展成了能处理**复杂的数据解构与逻辑组合**的完整体系。  

---

## 四、模式匹配最基础的形式：`is` 表达式

最初的模式匹配出现在 C# 7.0。
传统 `is` 检查仅仅返回布尔值，而 C# 7 的 `is` 能直接绑定新变量并自动转换类型。

```csharp
object input = "hello";

if (input is string s)
{
    Console.WriteLine($"字符串长度：{s.Length}");
}
```

这里编译器自动完成了：
- 类型检查 (`is string`)
- 强制类型转换 (`(string)input`)
- 变量声明 (`s`)

**优点**：简洁、安全，减少强制类型转换错误。  

**注意：**
变量 `s` 的可见域只在 `if` 块中有效（编译器控制作用域）。

---

## 五、与传统 `switch` 对比的第一个增强版本（C# 7）

C# 7 起允许在 `switch` 中直接匹配类型：

```csharp
object obj = 42;

switch (obj)
{
    case int i:
        Console.WriteLine($"整数的平方：{i * i}");
        break;
    case string s:
        Console.WriteLine($"字符串长度：{s.Length}");
        break;
    case null:
        Console.WriteLine("值是 null");
        break;
    default:
        Console.WriteLine("其他类型");
        break;
}
```

这种写法比 `if...else` 更**结构化**、**可读**，节省类型判断代码。

## 六、C# 8.0：模式匹配迎来“大改进”

C# 8 引入了几个极具代表性的概念：

### **Switch 表达式**

不再仅仅是语句，而是一个可以返回值的表达式。

```csharp
object x = 3.14;

string description = x switch
{
    int i => $"整数 {i}",
    double d => $"浮点数 {d:F2}",
    string s => $"字符串（长度 {s.Length}）",
    null => "空值",
    _ => "未知类型"
};

Console.WriteLine(description);
```

特点：
- 没有 `break` 。
- 可以直接返回一个值。
- `_` 代表“兜底模式”（类似 default）。

---

### **属性模式**

可以检查对象的属性值，而不仅仅是类型。

```csharp
var point = new { X = 0, Y = 5 };

if (point is { X: 0, Y: var y })
{
    Console.WriteLine($"在Y轴上，Y = {y}");
}
```

这里 `point is { X: 0, Y: var y }` 这段代码含义是：
> 这个对象的 `X` 属性为 0，同时取出 `Y` 属性的值。

这极大地增强了模式匹配在复杂对象场景中的实用性。

---

## 七、C# 9.0：逻辑组合与关系模式

C# 9 进一步引入了“逻辑模式”和“关系模式”，让匹配表达式更加简洁。

### 关系模式

直接比较数值大小：

```csharp
int age = 25;
string category = age switch
{
    < 13 => "儿童",
    >= 13 and < 18 => "青少年",
    >= 18 and < 65 => "成年人",
    _ => "老年人"
};
```

### 逻辑模式

可以组合多个条件：

```csharp
int score = 80;
bool isMedium = score is >= 60 and <= 90;
bool isOutlier = score is < 0 or > 100;
```

非常自然地表达出复杂逻辑，不必用嵌套的 `&&` 与 `||`。

## 八、模式匹配 VS 传统判断语句

| 对比项  | if/else        | 模式匹配          |
| ---- | -------------- | ------------- |
| 可读性  | 条件复杂时易混乱       | 简洁，逻辑清晰       |
| 类型安全 | 需手动转换          | 自动推断、强类型安全    |
| 功能   | 单纯逻辑判断         | 可解构、组合、匹配复杂结构 |
| 性能   | 类似（编译器优化后差距不大） | 等价甚至更优        |

---

## 九、为什么现代 C# 开发者必须掌握模式匹配

1. **业务逻辑层代码更清晰** —— 不再一堆 if/else。  
2. **不可变对象、记录类型盛行** —— 模式匹配能直接解析结构。  
3. **更贴近函数式思维** —— 把“分支逻辑”抽象成“数据形态”。  
4. **.NET 官方库和示例大量使用** —— 比如 Pattern matching 在 ASP.NET Core Minimal API、JSON 解析器等都常见。
