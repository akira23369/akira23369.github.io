# Switch 表达式与模式匹配

> 本文目标：  
> - 彻底掌握现代 C# 的 `switch` **表达式** 与 **语句**在模式匹配中的用法  
> - 理解分支匹配顺序、守卫条件 `when`、返回值与模式组合  
> - 能用 `switch` 把复杂 if/else 逻辑收敛成简洁的“模式分发器”

---

## 一、两种 switch：语句 vs 表达式

C# 现在有两种 `switch`：

1. **switch 语句**（statement）  
   ```csharp
   switch (x)
   {
       case ...:
           ...
           break;
   }
   ```
   - 不能直接作为表达式返回值；
   - 主要用来执行一段逻辑。

2. **switch 表达式**（expression）  
   ```csharp
   var result = x switch
   {
       ... => ...,
       _ => ...
   };
   ```
   - **有返回值**，可以赋值、传递；
   - 适合根据输入“计算一个结果”。

现代 C# 中，模式匹配常用 **switch 表达式**，但很多场景仍然使用语句形式，两个都要会。

---

## 二、最基础的 switch 表达式语法

### 语法结构

```csharp
var result = expr switch
{
    pattern1 => value1,
    pattern2 => value2,
    _        => defaultValue
};
```

- `expr`：待匹配的表达式，可以是任何表达式结果；
- 每个 `pattern`：使用前一篇讲的各种模式；
- `=>` 右侧是一个 **表达式**，不能直接写多条语句；
- `_` 是兜底模式（类似传统 switch 的 `default`）。

### 简单示例：类型分派

```csharp
object obj = GetValue();

string desc = obj switch
{
    int i    => $"整数：{i}",
    string s => $"字符串（长度 {s.Length}）",
    null     => "空值",
    _        => $"未知类型：{obj.GetType().Name}"
};
```

和第 2 篇讲的模式类型结合：这里 `int i`、`string s` 是**类型模式**。

---

## 三、switch 表达式 vs 传统 switch 语句

### 逻辑对比示例

传统写法：

```csharp
string GetStatusText(int status)
{
    switch (status)
    {
        case 200: return "OK";
        case 404: return "Not Found";
        case 500: return "Server Error";
        default:  return "Unknown";
    }
}
```

switch 表达式写法：

```csharp
string GetStatusText(int status) => status switch
{
    200 => "OK",
    404 => "Not Found",
    500 => "Server Error",
    _   => "Unknown"
};
```

优点：
- 更简洁；
- 没有 `break`、`return` 的噪音；
- 更适合做“输入 → 输出”的映射。

## 四、在 switch 中使用各种模式

### 常量模式 + 类型模式

```csharp
object value = GetValue();

string result = value switch
{
    0           => "零",
    1           => "一",
    string s    => $"字符串：{s}",
    bool b      => $"布尔值：{b}",
    null        => "空",
    _           => "其他类型"
};
```

### 关系模式 + 逻辑模式

```csharp
int age = GetAge();

string category = age switch
{
    < 0                       => "非法年龄",
    < 13                      => "儿童",
    >= 13 and < 18            => "青少年",
    >= 18 and < 60            => "成年人",
    >= 60 and < 120           => "老年人",
    _                         => "疑似填错"
};
```

**注意**：分支顺序从上往下匹配，第一个匹配成功的分支生效。

---

## 五、属性模式在 switch 中的实战用法

### 判断对象属性

```csharp
string Describe(Person p) => p switch
{
    { Age: < 0 }                     => "非法年龄",
    { Age: < 18 }                    => "未成年人",
    { Age: >= 18 and < 60 }          => "成年人",
    { Age: >= 60 }                   => "老年人",
    null                             => "空对象",
    _                                => "未知"
};
```

- `{ Age: < 18 }` 是属性模式 + 关系模式；
- `p` 为 null 时，只有 `null` 分支匹配成功。

### 多属性组合

```csharp
string GetDiscountTag(Order order) => order switch
{
    { Amount: >= 1000, Customer.IsVip: true } => "至尊 VIP 折扣",
    { Amount: >= 1000 }                       => "大客户折扣",
    { Amount: >= 500 }                        => "普通折扣",
    { Amount: < 500 }                         => "无折扣",
    _                                         => "未知"
};
```

注意到：
- `Customer.IsVip` 是**嵌套属性**；
- 若 `Customer` 为 null，此模式直接失败，不是抛异常（结果是匹配不到该分支）。

## 六、位置模式与 switch：处理元组和记录类型

### 元组在 switch 中

```csharp
(string, int) action = ("Move", 10);

string result = action switch
{
    ("Move", > 0)     => "向前移动",
    ("Move", <= 0)    => "保持位置",
    ("Attack", var n) => $"发起 {n} 次攻击",
    _                 => "未知动作"
};
```

- `("Move", > 0)`：位置模式 + 关系模式；
- `("Attack", var n)`：常量 + 变量捕获。

### 自定义类型 + Deconstruct

```csharp
public record Point(int X, int Y);

string Describe(Point p) => p switch
{
    (0, 0)          => "原点",
    (> 0, > 0)      => "第一象限",
    (< 0, > 0)      => "第二象限",
    (< 0, < 0)      => "第三象限",
    (> 0, < 0)      => "第四象限",
    _               => "在坐标轴上"
};
```

`record` 类型默认支持位置解构，所以可以像处理元组一样处理它。

---

## 七、列表模式与 switch：处理集合

（需 C# 11）

```csharp
int[] arr = GetArray();

string desc = arr switch
{
    []                       => "空数组",
    [var single]             => $"单个元素：{single}",
    [0, ..]                  => "以 0 开头",
    [1, 2, .. var rest]      => $"头部是 1,2，剩余 {rest.Length} 个",
    [.., 9]                  => "以 9 结尾",
    [_, _, ..]               => "长度至少为 2",
    _                        => "其他情况"
};
```

- `[]`：空数组；
- `[a, b]`：长度为 2，元素匹配；
- `[..]` 和 `[第一, .., 最后]` 是常见套路。

## 八、守卫条件 `when`：分支内再加附加条件

有时“模式匹配 + 一个额外逻辑条件”更自然。  
这时可以使用 `when` 守卫（guard）。

### 在 switch 语句中使用

```csharp
switch (person)
{
    case { Age: var age } when age < 18:
        Console.WriteLine("未成年人");
        break;

    case { Age: var age } when age >= 18 && age < 60:
        Console.WriteLine("成年人");
        break;

    case { Age: >= 60 }:
        Console.WriteLine("老年人");
        break;
}
```

### 在 switch 表达式中使用

```csharp
string Describe(Person p) => p switch
{
    { Age: var age } when age < 0  => "非法",
    { Age: var age } when age < 18 => "未成年人",
    { Age: var age } when age < 60 => "成年人",
    { Age: var age }               => "老年人",
    _                              => "未知"
};
```

使用建议：
- **模式部分**尽量描述结构和类型；
- `when` 用于复杂逻辑或需要访问多个属性的条件。

## 九、switch 匹配顺序与“穷尽性”

### 匹配顺序：从上到下，先中先赢

```csharp
string Test(int x) => x switch
{
    _      => "总是匹配",
    1      => "永远到不了这里"
};
```

上面这种写法会被编译器警告：后面的分支永远不会被匹配。  
因此要注意：

- 把**更具体**、更“窄”的模式放在前面；
- 把 `_` 这种兜底模式放在最后。

### 穷尽性检查（编译器帮你检查是否漏了分支）

对于有穷类型（如 `enum`）和某些情况，编译器会尽力判断是否所有情况都覆盖：

```csharp
enum Color { Red, Green, Blue }

string GetName(Color color) => color switch
{
    Color.Red   => "红",
    Color.Green => "绿",
    Color.Blue  => "蓝"
    // 如果漏了某个枚举值或缺少 `_` 分支，编译器会警告
};
```

建议：
- 枚举的 switch 表达式，要么覆盖所有枚举值，要么加 `_` 兜底；
- 复杂类型尽量有兜底分支，避免未来增加字段/值导致的行为不明。

## 十、真实场景 1：Web API 请求类型分发

假设有一个统一的请求对象：

```csharp
abstract record Request;
record CreateOrder(int CustomerId, decimal Amount) : Request;
record CancelOrder(int OrderId) : Request;
record QueryOrder(int OrderId) : Request;
```

使用 switch 表达式做分发：

```csharp
Task<IResult> HandleRequestAsync(Request request) => request switch
{
    CreateOrder(var customerId, var amount) => HandleCreateAsync(customerId, amount),
    CancelOrder(var orderId)                => HandleCancelAsync(orderId),
    QueryOrder(var orderId)                 => HandleQueryAsync(orderId),
    _                                       => Task.FromResult(Results.BadRequest("Unknown request"))
};
```

- 利用 **类型模式 + 位置模式**；
- dispatch 逻辑集中而清晰；
- 新增请求类型时，只需多加一个分支。

## 十一、真实场景 2：状态机与业务流程

模拟订单状态流转：

```csharp
enum OrderStatus { Created, Paid, Shipped, Completed, Cancelled }

record Order(OrderStatus Status, bool IsVip);

string GetNextAction(Order order) => order switch
{
    { Status: OrderStatus.Created,  IsVip: true }  => "优先催付",
    { Status: OrderStatus.Created }                => "发送支付提醒",
    { Status: OrderStatus.Paid }                   => "安排发货",
    { Status: OrderStatus.Shipped }                => "提醒收货",
    { Status: OrderStatus.Completed }              => "请求评价",
    { Status: OrderStatus.Cancelled }              => "归档",
    _                                              => "未知状态"
};
```

- `OrderStatus` 用常量模式；
- `IsVip` 用属性模式；
- 行为逻辑紧凑地表达在一个函数里。

## 十二、何时用 switch，何时用 if/else？

建议：

- **单一条件，且逻辑简单**：`if/else` 更直观；
- **根据一个“核心变量”的不同形态分派逻辑**：优先用 `switch`；
- **要返回一个结果值**：优先 `switch` 表达式；
- **类型 / 结构 / 多条件组合**：优先 `switch` + 模式匹配；
- 有复杂副作用逻辑（执行多条语句）时：
  - 用 `switch 语句`，每个 `case` 内写多条语句；
  - 或者 `switch 表达式` + 抽出来的方法，比如：

    ```csharp
    void Handle(Request request)
    {
        switch (request)
        {
            case CreateOrder create:
                HandleCreate(create);
                break;
            case CancelOrder cancel:
                HandleCancel(cancel);
                break;
        }
    }
    ```

## 十三、常见错误与最佳实践

1. **把 `_` 写在前面**  
   - 会遮蔽后续分支，引发警告或逻辑错误。  
   - 一定要放最后。

2. **在 value 位置写复杂逻辑**
   ```csharp
   // 不太好
   var result = value switch
   {
       1 => DoSomethingAndReturnValue(),
       2 => { Console.WriteLine("..."); return 10; } // 语法上也不允许写语句块
   };
   ```
   正确做法：把复杂逻辑抽成方法。

3. **滥用 when 守卫**  
   - 如果能用模式本身表达，尽量不用 `when`；  
   - `when` 留给多属性、多条件的复杂逻辑。

4. **忽略 null 情况**  
   - 对引用类型作为匹配对象时：  
     - 加 `null => ...` 或  
     - 判断前写 `if (obj is null) return ...;`
