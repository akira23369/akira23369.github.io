# lock语句详解

## 一、lock是什么？跟Monitor的关系

**大白话理解**：`lock` 是 C# 提供的**语法糖**，它把 `Monitor.Enter/Exit` 的复杂写法包装成简洁的关键字。你写 `lock(obj)`，编译器会自动翻译成 `Monitor.Enter` + `try-finally` + `Monitor.Exit` 的组合。

**核心关系**：
- `lock` **完全等价于**下面这段代码：
```csharp
Monitor.Enter(obj);
try
{
    // 你的代码
}
finally
{
    Monitor.Exit(obj);
}
```
- 编译器在编译时**自动**帮你生成这段完整逻辑
- `lock` 更简洁、更安全，避免了忘记写 `finally` 导致死锁的风险

## 二、基本用法和语法

```csharp
// 1. 定义一个锁对象（必须是引用类型）
private static readonly object _lock = new object();

// 2. 使用 lock 包裹临界区
lock (_lock)
{
    // 这里面的代码是"原子的"：一次只能有一个线程进入
    // 对共享资源的操作写在这里
    _sharedCounter++;
}
```

**完整示例**：
```csharp
using System;
using System.Threading;

class BankAccount
{
    private int _balance = 1000;
    private readonly object _balanceLock = new object(); // 锁对象

    public void Withdraw(int amount)
    {
        lock (_balanceLock) // 进入临界区
        {
            if (_balance >= amount)
            {
                Console.WriteLine($"线程{Thread.CurrentThread.ManagedThreadId}：余额足够，准备取款");
                Thread.Sleep(100); // 模拟处理时间
                _balance -= amount;
                Console.WriteLine($"线程{Thread.CurrentThread.ManagedThreadId}：取款成功，新余额: {_balance}");
            }
            else
            {
                Console.WriteLine($"线程{Thread.CurrentThread.ManagedThreadId}：余额不足");
            }
        } // 离开lock块，自动释放锁
    }

    public int GetBalance()
    {
        lock (_balanceLock) // 读也要加锁，防止读到中间状态
        {
            return _balance;
        }
    }
}

class Program
{
    static void Main()
    {
        var account = new BankAccount();

        // 两个线程同时取款800（余额1000）
        var t1 = new Thread(() => account.Withdraw(800));
        var t2 = new Thread(() => account.Withdraw(800));

        t1.Start();
        t2.Start();

        t1.Join(); t2.Join();

        Console.WriteLine($"最终余额: {account.GetBalance()}"); // 一定是200，不会透支
    }
}
```

**输出结果（一定是这个结果，不再随机）**：
```
线程9：余额足够，准备取款
线程9：取款成功，新余额: 200
线程10：余额不足
最终余额: 200
```

## 三、选择锁对象的5条铁律

锁对象选错，`lock` 就白加了。这是**最核心**的知识点。

### **铁律1：必须是引用类型**
```csharp
// 错误！值类型会被装箱，每次lock的是不同对象
private static int _lock = 0;
lock (_lock) { ... } // 编译通过，但完全无效！

// 正确
private static readonly object _lock = new object();
```

**原因**：值类型 `int` 在 `lock` 时会被**装箱**成不同的 `object` 实例，每个线程锁的是"不同的门"，等于没锁。

### **铁律2：必须是私有的（private）**
```csharp
// 错误！外部代码也能锁这个对象，导致意外死锁
public object LockObject = new object(); // 公有

// 正确
private readonly object _lock = new object(); // 私有
```

**原因**：如果锁对象是 `public` 或 `protected`，外部代码也能 `lock` 它。你无法控制外部代码的行为，可能导致死锁或性能问题。

### **铁律3：可以是静态的（如果是静态方法需要）**
```csharp
class Counter
{
    private readonly object _instanceLock = new object(); // 实例锁
    
    public void InstanceMethod()
    {
        lock (_instanceLock) { ... } // OK，保护实例成员
    }

    private static readonly object _staticLock = new object(); // 静态锁

    public static void StaticMethod()
    {
        lock (_staticLock) { ... } // OK，保护静态成员
        // 错误：lock (_instanceLock) 不行，静态方法没有实例
    }
}
```

**原则**：保护**实例成员**用**实例锁**；保护**静态成员**用**静态锁**。

### **铁律4：必须是只读的（readonly）**
```csharp
// 错误！锁对象可能被替换
private object _lock = new object();

public void Method()
{
    lock (_lock) 
    {
        // 锁持有期间，_lock 被其他线程改成新对象
        // 另一个线程同时进入，导致数据竞争
        _lock = new object(); // 危险！
    }
}

// 正确
private static readonly object _lock = new object(); // readonly 禁止修改
```

**原因**：如果锁对象被替换，两个线程可能分别锁"旧门"和"新门"，同时进入临界区。

### **铁律5：不要锁 this 或 typeof**
```csharp
// 错误示范1：lock(this)
public class BadClass
{
    public void Method()
    {
        lock (this) // 危险！
        {
            // ...
        }
    }
}

// 外部代码也能 lock (instance)，导致死锁
var instance = new BadClass();
lock (instance) // 锁了同一个对象
{
    instance.Method(); // 内部又 lock(this)，死锁！
}

// 错误示范2：lock(typeof(MyClass))
lock (typeof(BadClass)) // 更危险！
{
    // 整个程序里所有 lock(typeof(BadClass)) 都会互相阻塞
}
```

**原因**：
- `this` 是公开的，外部代码能访问，无法控制
- `typeof()` 是全局的，整个 AppDomain 只有一个，范围太大
- 容易导致**非预期的死锁**

## 四、lock 的最佳实践

### **锁的范围要尽可能小**
```csharp
// 错误：锁住了整个方法，包括耗时操作
lock (_lock)
{
    LoadDataFromDatabase(); // 耗时2秒
    ProcessData();
    SaveToFile(); // 耗时1秒
} // 这3秒钟其他线程全被堵死

// 正确：只锁住真正访问共享资源的部分
var data = LoadDataFromDatabase(); // 在锁外执行

lock (_lock)
{
    _sharedData = data; // 只保护赋值操作
}
```

**原则**：锁内代码执行越快越好，**别让线程在门外等太久**。

### **避免在 lock 内调用外部代码**
```csharp
private static readonly object _lock = new object();
private static Action _callback;

public void DoWork()
{
    lock (_lock)
    {
        // 危险：_callback 是外部传入的，可能也持有其他锁
        _callback?.Invoke(); // 可能导致锁顺序颠倒，死锁！
    }
}
```

### **避免锁中锁（嵌套锁）**
```csharp
private static readonly object _lock1 = new object();
private static readonly object _lock2 = new object();

static void MethodA()
{
    lock (_lock1)
    {
        Thread.Sleep(100);
        lock (_lock2) // 嵌套
        {
            // ...
        }
    }
}

static void MethodB()
{
    lock (_lock2) // 顺序相反
    {
        Thread.Sleep(100);
        lock (_lock1) // 嵌套
        {
            // ...
        }
    }
}

// 如果 MethodA 和 MethodB 同时执行，可能死锁：
// A持有lock1等lock2，B持有lock2等lock1
```

**解决**：所有方法按**相同顺序**加锁，或使用超时机制（`Monitor.TryEnter`）。

### **读操作也要加锁（或只读锁）**
```csharp
private static readonly object _lock = new object();
private static int _sharedValue;

// 写操作
lock (_lock) { _sharedValue = 42; }

// 读操作也必须加锁，否则可能读到中间值
int value;
lock (_lock) { value = _sharedValue; } // 正确

// 如果不加锁，可能读到脏数据
int value = _sharedValue; // 错误！可能读到一半
```

**例外**：如果共享变量是**简单类型**且只有**原子操作**（如 `int` 的读取），可以用 `volatile` 或 `Interlocked`，但初学阶段建议**统一加锁**。

## 五、lock 的常见陷阱

### **陷阱1：锁字符串字面量**
```csharp
// 错误！字符串会被缓存，lock ("myLock") 在整个程序都是同一把锁
lock ("myLock") { ... }

// 正确
private static readonly object _lock = new object();
```

### **陷阱2：锁 null 对象**
```csharp
private object _lock = null;

public void Method()
{
    lock (_lock) // NullReferenceException！
    {
        // ...
    }
}
```

### **陷阱3：锁非私有字段**
```csharp
// 在基类中
protected object LockObj = new object(); // 子类也能访问，危险

// 外部代码可以：
lock (derivedInstance.LockObj) { /* 阻塞你的代码 */ }
```

### **陷阱4：异步代码里用 lock（编译错误）**
```csharp
public async Task MethodAsync()
{
    lock (_lock) // 编译错误：cannot await in the body of a lock statement
    {
        await Task.Delay(1000); // lock 内不能 await
    }
}
```

**原因**：`await` 会让线程挂起并可能切换，但锁是与线程绑定的，切换后新线程无法释放原线程的锁，导致死锁。

**解决**：用 `SemaphoreSlim.WaitAsync()` 等异步锁（后面会讲）。

### **陷阱5：误以为 lock 是线程安全的保证**
```csharp
private static readonly object _lock = new object();
private static List<int> _list = new List<int>();

// 错误：只对 Add 加锁，但其他操作没保护
lock (_lock)
{
    _list.Add(1);
}

// 另一个线程：
if (_list.Count > 0) // 没加锁！
{
    int x = _list[0]; // 可能抛出异常（Count 和索引访问不是原子的）
}
```

**原则**：**所有**访问共享资源的代码路径都要加**同一把锁**。

## 六、lock 的高级细节

### **可重入性**
```csharp
private static readonly object _lock = new object();

static void MethodA()
{
    lock (_lock)
    {
        Console.WriteLine("MethodA 进入");
        MethodB(); // 同一线程可以再次进入 lock
        Console.WriteLine("MethodA 退出");
    }
}

static void MethodB()
{
    lock (_lock)
    {
        Console.WriteLine("MethodB 进入");
    }
}

// 输出：
// MethodA 进入
// MethodB 进入
// MethodB 退出
// MethodA 退出
```

**原理**：`lock` 内部有计数器，同一线程多次进入只加锁一次，退出时计数归零才真正释放。

### **性能：无竞争 vs 有竞争**
```csharp
// 单线程调用（无竞争）：约50-100纳秒
lock (_lock) { _counter++; }

// 多线程竞争：线程阻塞、上下文切换，耗时飙升到毫秒级
```

**优化**：如果竞争不激烈，用 `Interlocked.Increment` 更快（用户模式锁）。

### **lock 不能用于值类型（编译器会阻止）**
```csharp
private static int _lock = 0;
lock (_lock) // 编译错误：int is not a reference type
{
    // ...
}
```

## 七、lock vs Monitor：何时用哪个？

```csharp
// 场景1：简单互斥，无脑 lock
lock (_lock) { /* ... */ }

// 场景2：需要超时，必须用 Monitor
if (Monitor.TryEnter(_lock, 1000))
{
    try { /* ... */ }
    finally { Monitor.Exit(_lock); }
}
else { /* 超时处理 */ }

// 场景3：需要等待/通知，必须用 Monitor
lock (_lock)
{
    while (条件不满足) Monitor.Wait(_lock);
    // 干活
    Monitor.Pulse(_lock);
}
```

**总结**：
-  **`lock` 是首选**  ：代码少，安全，不易出错
-  **`Monitor` 是备用**  ：需要高级功能时才拿出来

## 八、总结

**lock 的本质**：
- 编译器帮你写的 `Monitor.Enter/Exit` 安全模板
- 保证临界区代码的原子性、可见性、有序性

**黄金法则**：
1. **锁对象**：`private static readonly object _lock = new object();`
2. **锁范围**：越小越好，只包必要代码
3. **锁内外**：不调用外部代码，不嵌套锁
4. **读写操作**：都要加同一把锁

**记住**：`lock` 不是万能的，它只能保护"正确加锁的代码"。如果你的代码路径有任何一处忘记加锁，整个同步就失效了。

学好 `lock` 和 `Monitor`，你已经掌握了 .NET 同步的基石。


## 补充：专用的 `System.Threading.Lock` 类型
既然你在学习 C# 13，这是一个必须掌握的前沿知识。

在 C# 13 之前，我们总是用 `new object()` 来作为锁。但这其实是一种内存浪费，因为每个普通的 `object` 都带有很多不需要的包袱，且其同步机制（SyncBlock）在高并发下存在一定的性能开销。

**C# 13 引入了专门用于锁定的类型：`System.Threading.Lock`**

在 C# 13 中，最佳实践变成了这样：
```csharp
using System.Threading;

class MyClass
{
    // 1. 使用专用的 Lock 类型，而不是 object
    private static readonly Lock _modernLock = new Lock();
    private static int _sharedCount = 0;

    public void IncrementSafe()
    {
        // 2. 语法不变，依然使用 lock 关键字
        lock (_modernLock)
        {
            _sharedCount++;
        }
    }
}
```
**C# 13 `Lock` 对象的优势：**
*   **性能更好：** 底层经过重新设计，相比于锁定普通 `object`，GC 分配更少，进入和退出锁的速度更快。
*   **语义更清晰：** 明确告诉阅读代码的开发者“这个变量就是专门用来做同步锁的”，而不是一个含义模糊的 `object`。
*   **内置更安全的模式：** 如果脱离 `lock` 关键字手动使用，它提供了 `using (_modernLock.EnterScope())` 模式，比原生的 `Monitor` 更加安全且符合现代 C# 风格。
