# ManualResetEvent 详解

## 一、什么是 ManualResetEvent？（门栓模型）

**大白话理解**：`ManualResetEvent` 就像一个**带开关的门闸**：
-  **`Set()`**  ：把门打开，所有等在门口的线程**一次性全部冲过去**
-  **`Reset()`**  ：把门关上，后面来的线程继续排队等着
-  **`WaitOne()`**  ：在门前等待，直到门打开

**关键特点**：**手动**——门打开后会**一直保持打开状态**，直到你手动调用 `Reset()` 把它关上。这和下篇要讲的 `AutoResetEvent` 的"自动关门"完全不同。

---

## 二、核心方法（3个必会）

```csharp
ManualResetEvent mre = new ManualResetEvent(false); // false=初始状态关门，true=开门
```

### `WaitOne()` —— 等待门打开
```csharp
// 没有重载：一直等，直到门打开
mre.WaitOne(); 

// 带超时：等1000毫秒后不管门开不开都继续
bool isOpened = mre.WaitOne(1000);
// isOpened = true: 门开了通过
// isOpened = false: 超时了，门还关着

// 带超时和取消令牌（高级）
mre.WaitOne(1000, cancellationToken);
```

### `Set()` —— 推开门，放所有线程过去
```csharp
mre.Set(); // 门打开，所有等待的线程立即通过，后面新来的也不等
```

### `Reset()` —— 关上门，后续线程继续等
```csharp
mre.Reset(); // 门关上，后续调用 WaitOne() 的线程必须等到下次 Set()
```

## 三、完整代码示例

### 示例1：基本用法（一个线程等，一个线程开）
```csharp
using System;
using System.Threading;

class Program
{
    static void Main()
    {
        // 创建门闸，初始状态：关门（false）
        ManualResetEvent mre = new ManualResetEvent(false);

        // 服务员线程：等老板发话才开始干活
        Thread waiter = new Thread(() => {
            Console.WriteLine($"服务员线程{Thread.CurrentThread.ManagedThreadId}：等老板指令...");
            
            mre.WaitOne(); // 门没开，一直等着
            
            Console.WriteLine($"服务员线程{Thread.CurrentThread.ManagedThreadId}：收到，开始上菜！");
        });
        waiter.Start();

        Thread.Sleep(1000); // 主线程睡1秒模拟老板准备

        Console.WriteLine("老板：可以上菜了！");
        mre.Set(); // 推开门，服务员冲过去干活

        waiter.Join();
        Console.WriteLine("主线程：收工");
    }
}
```

**输出**：
```
服务员线程7：等老板指令...
[1秒后]
老板：可以上菜了！
服务员线程7：收到，开始上菜！
主线程：收工
```

static void Main()

### 示例3：门打开后持续通过，直到手动关闭

```csharp
static void Main()
{
    ManualResetEvent door = new ManualResetEvent(false); // 初始关门

    // 持续放行的保安
    new Thread(() => {
        Thread.Sleep(1000);
        Console.WriteLine("保安：门开了，大家随便进！");
        door.Set(); // 门打开，一直开着
    }).Start();

    // 3个线程，不同时间到达
    for (int i = 1; i <= 3; i++)
    {
        int id = i;
        new Thread(() => {
            Thread.Sleep(id * 500); // 分别在0.5s、1s、1.5s到达
            Console.WriteLine($"线程{id}：到达门口，等待...");
            
            door.WaitOne(); // 等门开
            
            Console.WriteLine($"线程{id}：进来了！门还开着呢");
        }).Start();
    }

    Thread.Sleep(3000);
    Console.WriteLine("\n3秒过了，关门！");
    door.Reset(); // 手动关门

    // 新来的线程必须继续等
    new Thread(() => {
        Console.WriteLine("新线程：到达门口，等待...");
        door.WaitOne(2000); // 等2秒
        Console.WriteLine("新线程：超时，进不去，走了");
    }).Start();

    Thread.Sleep(2000);
    Console.WriteLine("\n重新开门！");
    door.Set(); // 再次开门

    Thread.Sleep(500);
    Console.WriteLine("主线程：结束");
}
```

**输出**：
```
线程1：到达门口，等待...
保安：门开了，大家随便进！
线程1：进来了！门还开着呢
线程2：到达门口，等待...
线程2：进来了！门还开着呢
线程3：到达门口，等待...
线程3：进来了！门还开着呢

3秒过了，关门！
新线程：到达门口，等待...
新线程：超时，进不去，走了

重新开门！
主线程：结束
```


### 示例4：批次生产，批次消费
假设生产者每生成 3 个数据为一个批次，消费者每处理完一个批次，生产者再继续下一批次：

```csharp
using System;
using System.Collections.Generic;
using System.Threading;

class BatchProcessingExample
{
    private static Queue<int> _dataQueue = new Queue<int>();
    private static ManualResetEvent _batchReadyEvent = new ManualResetEvent(false);
    private static object _lockObj = new object();
    private const int BatchSize = 3;

    static void Main()
    {
        Thread producer = new Thread(ProduceBatches);
        Thread consumer = new Thread(ConsumeBatches);

        producer.Start();
        consumer.Start();

        producer.Join();
        consumer.Join();
    }

    static void ProduceBatches()
    {
        // 生产 3 个批次
        for (int batch = 1; batch <= 3; batch++)
        {
            Console.WriteLine($"\n[生产者] 开始生成第 {batch} 批次...");
            
            lock (_lockObj)
            {
                // 生产一个批次的数据
                for (int i = 0; i < BatchSize; i++)
                {
                    int data = batch * 10 + i;
                    _dataQueue.Enqueue(data);
                    Console.WriteLine($"  生产数据: {data}");
                    Thread.Sleep(200);
                }
            }
            
            // 批次完成，打开信号门
            Console.WriteLine($"[生产者] 第 {batch} 批次生成完毕，通知消费者！");
            _batchReadyEvent.Set();
            
            // 等待消费者处理完这个批次
            // 这里通过 Reset 门来控制下一轮
            Thread.Sleep(1000); // 给消费者处理时间
            _batchReadyEvent.Reset(); // 关闭门，下次循环消费者会再次等待
        }
    }

    static void ConsumeBatches()
    {
        // 消费 3 个批次
        for (int batch = 1; batch <= 3; batch++)
        {
            Console.WriteLine($"\n[消费者] 等待第 {batch} 批次...");
            
            _batchReadyEvent.WaitOne(); // 等待批次就绪
            
            Console.WriteLine($"[消费者] 第 {batch} 批次就绪，开始消费：");
            
            lock (_lockObj)
            {
                while (_dataQueue.Count > 0)
                {
                    int data = _dataQueue.Dequeue();
                    Console.WriteLine($"  消费数据: {data}");
                }
            }
        }
    }
}
```

**输出**（展示批次协同）：
```
[生产者] 开始生成第 1 批次...
  生产数据: 11
  生产数据: 12
  生产数据: 13
[生产者] 第 1 批次生成完毕，通知消费者！

[消费者] 第 1 批次就绪，开始消费：
  消费数据: 11
  消费数据: 12
  消费数据: 13

[消费者] 等待第 2 批次...
[生产者] 开始生成第 2 批次...
  生产数据: 21
  生产数据: 22
  生产数据: 23
...
```

## 四、实际应用场景

### **场景1：程序初始化完成通知**
```csharp
public class ApplicationInitializer
{
    private static ManualResetEvent _initComplete = new ManualResetEvent(false);
    private static bool _isInitialized = false;

    public static void Initialize()
    {
        // 在主线程执行初始化
        Console.WriteLine("初始化中...");
        Thread.Sleep(3000); // 模拟初始化耗时
        _isInitialized = true;
        
        Console.WriteLine("初始化完成，开门！");
        _initComplete.Set(); // 通知所有等待的工作线程
    }

    public static void WaitForInit()
    {
        Console.WriteLine($"工作线程{Thread.CurrentThread.ManagedThreadId}：等初始化完成...");
        _initComplete.WaitOne(); // 等开门
        Console.WriteLine($"工作线程{Thread.CurrentThread.ManagedThreadId}：初始化OK，开始干活！");
    }
}

// 使用
static void Main()
{
    // 启动多个工作线程，都等初始化
    for (int i = 1; i <= 3; i++)
    {
        new Thread(ApplicationInitializer.WaitForInit).Start();
        Thread.Sleep(100);
    }

    Thread.Sleep(1000);
    
    // 主线程执行初始化
    ApplicationInitializer.Initialize();

    Thread.Sleep(1000);
}
```

### **场景2：程序关闭信号**
```csharp
public class GracefulShutdown
{
    private static ManualResetEvent _shutdownSignal = new ManualResetEvent(false);

    public static void ListenForShutdown()
    {
        new Thread(() => {
            Console.WriteLine("监听线程：按 Enter 键关闭程序...");
            Console.ReadLine();
            Console.WriteLine("监听线程：收到关闭信号，开门！");
            _shutdownSignal.Set(); // 通知所有工作线程退出
        }).Start();
    }

    public static void WorkerTask(int id)
    {
        while (true)
        {
            // 等待100ms检查一次关闭信号
            if (_shutdownSignal.WaitOne(100))
            {
                Console.WriteLine($"工作线程{id}：收到关闭信号，退出");
                break;
            }

            Console.WriteLine($"工作线程{id}：工作中...");
            Thread.Sleep(500);
        }
    }
}

// 使用
static void Main()
{
    GracefulShutdown.ListenForShutdown();

    // 启动多个工作线程
    for (int i = 1; i <= 3; i++)
    {
        int id = i;
        new Thread(() => GracefulShutdown.WorkerTask(id)).Start();
    }

    // 等待所有线程退出
    Thread.Sleep(5000);
    Console.WriteLine("主线程：退出");
}
```

## 五、ManualResetEvent 的陷阱

### **陷阱1：忘记 Reset，门一直开着**
```csharp
ManualResetEvent mre = new ManualResetEvent(false);

// 第一次使用
mre.Set(); // 门开了
// ... 线程都通过了

// 下次再用，忘记关门
// mre.Reset(); // 注释了！

// 新线程调用 WaitOne() 直接通过，没等待
new Thread(() => {
    mre.WaitOne(); // 门还开着，不等
    Console.WriteLine("没等就执行了");
}).Start();
```

**后果**：信号丢失，线程没按预期等待。

**解决**：每次 `Set()` 后，如果下次还需要等待，**立即 `Reset()`**。

```csharp
mre.Set(); // 开门
// 等所有线程通过
Thread.Sleep(100);
mre.Reset(); // 关门，准备下次
```

---

### **陷阱2：Set 后信号永久有效，无法自动清除**
```csharp
// 需求：每个线程单独触发一次
ManualResetEvent signal = new ManualResetEvent(false);

for (int i = 0; i < 5; i++)
{
    new Thread(() => {
        signal.WaitOne(); // 等信号
        Console.WriteLine("执行");
    }).Start();
}

// 想一个一个触发
signal.Set(); Thread.Sleep(100); // 第一次
signal.Set(); Thread.Sleep(100); // 第二次——无效！门已经开了
```

**结果**：第一次 `Set()` 后，门一直开着，后面所有线程都不等待了。

**解决**：这种"每次触发一个"的需求，应该用 `AutoResetEvent`。

---

### **陷阱3：WaitOne 在 Set 之后调用，会立即通过**
```csharp
ManualResetEvent mre = new ManualResetEvent(false);

mre.Set(); // 先开门
Thread.Sleep(1000);

// 1秒后才创建线程
new Thread(() => {
    mre.WaitOne(); // 门已经开了，不等
    Console.WriteLine("立即通过");
}).Start();
```

**特点**：ManualResetEvent 会**记住信号状态**。只要调用过 `Set()`（且没 `Reset()`），后续所有 `WaitOne()` 都直接通过。

---

### **陷阱4：跨线程忘记 Dispose**
```csharp
ManualResetEvent mre = new ManualResetEvent(false);
// 使用后不 Dispose，会泄漏内核对象
```

**正确做法**：实现 `IDisposable`
```csharp
class MyWorker : IDisposable
{
    private ManualResetEvent _shutdownEvent = new ManualResetEvent(false);
    
    public void Dispose()
    {
        _shutdownEvent?.Dispose(); // 释放内核资源
    }
}
```

## 六、ManualResetEvent vs AutoResetEvent（预告）

| 特性 | ManualResetEvent | AutoResetEvent |
|------|------------------|----------------|
| **Set 后行为** | 门一直开着，直到手动 Reset | 门打开后，**只放行一个线程**，然后自动关门 |
| **适用场景** | 一次性通知所有等待线程 | 每次只唤醒一个线程（轮流） |
| **记忆口诀** | 手动开关 | 自动关门 |
| **典型用途** | 程序启动/关闭信号 | 限流，一次只放一个线程 |

**简单对比代码**：
```csharp
// ManualResetEvent: Set一次，所有线程都通过
ManualResetEvent mre = new ManualResetEvent(false);
for (int i = 0; i < 3; i++)
{
    new Thread(() => {
        mre.WaitOne();
        Console.WriteLine("通过"); // 三个都会打印
    }).Start();
}
mre.Set(); // 门开，三个全过

// AutoResetEvent: Set一次，只通过一个
AutoResetEvent are = new AutoResetEvent(false);
for (int i = 0; i < 3; i++)
{
    new Thread(() => {
        are.WaitOne();
        Console.WriteLine("通过"); // 只有一个打印
    }).Start();
}
are.Set(); // 门开，放一个，然后自动关门
```

## 七、性能与资源

- **内核对象**：`ManualResetEvent` 是内核模式同步对象，创建和等待都要经过操作系统，比 `Monitor` 慢（约10-20倍）
- **WaitOne 开销**：无竞争时约 50-100 微秒，有竞争时线程阻塞
- **适用场景**：跨进程同步、长时间等待（几秒以上）
- **不适用**：短时间高频同步（用 `Monitor` 或 `SpinWait`）

**轻量级替代**：`ManualResetEventSlim`（混合模式）
```csharp
ManualResetEventSlim slim = new ManualResetEventSlim(false); // 用户模式自旋
slim.Wait(); // 更快
slim.Set();
slim.Reset();
slim.Dispose();
```

## 八、总结

**核心记忆点**：
1. **Manual**：必须手动 `Reset()` 关门，否则门一直开
2. **Set 一次，全都过**：所有等待线程一次性全部唤醒
3. **状态记忆**：调用 `Set()` 后，信号永久有效，直到 `Reset()`
4. **适用场景**：程序启停、批量通知、多线程同步点

**什么时候用**：
- 需要一次性通知多个线程："大家开始干活！"
- 需要一个持续信号："程序正在关闭中"

**什么时候不用**：
- 需要每次只唤醒一个线程：用 `AutoResetEvent`
- 高频短时同步：用 `Monitor` 或 `Interlocked`

**下篇预告**：《AutoResetEvent》——每次只放一个线程的"自动门"，限流神器。
