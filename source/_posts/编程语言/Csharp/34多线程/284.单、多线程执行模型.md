### 单线程与多线程执行模型

#### 一、单线程执行模型

**大白话理解**：就像食堂只有一个窗口，所有人必须排一队挨个打饭。前一个人打完，后一个人才能开始。程序里所有代码按**从上到下的顺序**，一行一行执行，前面的不执行完，后面的就只能干等着。

**特点：**
- 简单直观，符合人的直觉
- 代码执行顺序固定，容易调试
- 缺点：如果某行代码卡住（比如读取大文件），整个程序就冻住了

**代码示例：**
```csharp
using System;
using System.Threading; // 后面要用到，先引用

class Program
{
    static void Main()
    {
        Console.WriteLine("主线程开始");
        
        // 单线程：三个任务必须按顺序完成
        MakeCoffee();
        MakeToast();
        FryEgg();
        
        Console.WriteLine("主线程结束");
    }
    
    static void MakeCoffee() 
    { 
        Console.WriteLine("开始泡咖啡..."); 
        Thread.Sleep(2000); // 模拟耗时2秒
        Console.WriteLine("咖啡泡好了！"); 
    }
    
    static void MakeToast() 
    { 
        Console.WriteLine("开始烤面包..."); 
        Thread.Sleep(1500); 
        Console.WriteLine("面包烤好了！"); 
    }
    
    static void FryEgg() 
    { 
        Console.WriteLine("开始煎蛋..."); 
        Thread.Sleep(2500); 
        Console.WriteLine("蛋煎好了！"); 
    }
}
```
**输出结果（必然后顺序）：**
```
主线程开始
开始泡咖啡...
咖啡泡好了！
开始烤面包...
面包烤好了！
开始煎蛋...
蛋煎好了！
主线程结束
```
**注意**：`Thread.Sleep()`就是让当前线程暂停干活，单位是毫秒。这里仅仅是为了模拟真实耗时操作。

#### 二、多线程执行模型

**大白话理解**：食堂开了3个窗口，泡咖啡、烤面包、煎蛋可以**同时进行**。这三件事由三个不同的"打饭阿姨"（线程）分别处理，互不干扰。

**关键概念：**
- **主线程**：程序启动时自动创建的线程，`Main()`方法默认就在主线程上跑
- **子线程**：手动创建的新线程，用于执行其他任务
- **并发执行**：看起来同时进行（单核CPU快速切换），或真正同时进行（多核CPU）

**代码示例：**
```csharp
using System;
using System.Threading;

class Program
{
    static void Main()
    {
        Console.WriteLine("主线程开始");
        
        // 创建三个子线程，分别执行三个任务
        Thread coffeeThread = new Thread(MakeCoffee);
        Thread toastThread = new Thread(MakeToast);
        Thread eggThread = new Thread(FryEgg);
        
        // 启动线程（只是标记为"可以开始工作了"，不代表立即执行）
        coffeeThread.Start();
        toastThread.Start();
        eggThread.Start();
        
        Console.WriteLine("主线程：三个任务已分配，我继续干别的了！");
        
        // 等待所有子线程完成（不然主线程结束程序就直接退出了）
        coffeeThread.Join(); // Join()就是"我等你干完再走"
        toastThread.Join();
        eggThread.Join();
        
        Console.WriteLine("主线程结束");
    }
    
    // 方法还是之前那三个，一模一样
    static void MakeCoffee() 
    { 
        Console.WriteLine(">>> 咖啡线程开始"); 
        Thread.Sleep(2000); 
        Console.WriteLine(">>> 咖啡线程结束"); 
    }
    
    static void MakeToast() 
    { 
        Console.WriteLine(">>> 面包线程开始"); 
        Thread.Sleep(1500); 
        Console.WriteLine(">>> 面包线程结束"); 
    }
    
    static void FryEgg() 
    { 
        Console.WriteLine(">>> 煎蛋线程开始"); 
        Thread.Sleep(2500); 
        Console.WriteLine(">>> 煎蛋线程结束"); 
    }
}
```
**可能的结果（顺序不固定）：**
```
主线程开始
主线程：三个任务已分配，我继续干别的了！
>>> 咖啡线程开始
>>> 面包线程开始
>>> 煎蛋线程开始
>>> 面包线程结束（最快，1.5秒）
>>> 咖啡线程结束（2秒）
>>> 煎蛋线程结束（最慢，2.5秒）
主线程结束
```

#### 三、新手必须知道的坑

**1. 主线程结束了，整个程序就凉了！**
```csharp
// 错误示范：没加Join()
static void Main()
{
    Thread t = new Thread(() => {
        Thread.Sleep(1000);
        Console.WriteLine("子线程：我好了！");
    });
    t.Start();
    
    Console.WriteLine("主线程：我完事了，拜拜！");
    // 主线程到这里就结束了，子线程可能还没执行完，程序直接退出！
}
```

**2. 多线程真的快吗？**
- 如果是计算密集型任务（大量数学运算），多线程在**多核CPU**上才真的快
- 如果只是简单任务，创建线程本身就有开销（食堂阿姨也要时间走到窗口）
- 上面的早餐例子，总时间由最慢的任务决定（2.5秒），而不是累加（6秒）

**3. 线程执行顺序不确定**
- 多线程启动顺序 ≠ 执行顺序 ≠ 结束顺序
- 操作系统决定哪个线程啥时候运行，咱们只能建议，不能强制

**4. 调试多线程很痛苦**
- 断点打在多线程代码里，每次执行顺序可能都不一样
- 问题可能只在特定顺序下才出现（这叫"竞态条件"，后面会讲）

#### 四、什么时候用多线程？

**适合场景：**
- 需要同时干好几件独立的事（比如游戏：一个线程渲染画面，一个线程处理网络）
- 某个任务可能卡住，但不能让界面冻住（比如UI线程和后台工作线程分离）

**不适合场景：**
- 简单的计算，顺序执行反而更快
- 任务之间有严格的先后顺序（必须先泡咖啡再喝）

---

#### 五、补充知识点：前台线程 vs 后台线程

- **前台线程（默认）**：主线程要等所有前台线程结束才退出
- **后台线程**：主线程结束时，后台线程自动被终止

```csharp
Thread t = new Thread(SomeMethod);
t.IsBackground = true; // 设为后台线程，主线程结束它也会被强制结束
t.Start();
```
**建议**：对于必须完成的任务，用前台线程；对于可有可无的辅助任务，可以设为后台线程。

---

**总结**：单线程是排队打饭，多线程是开多个窗口。多线程能提高效率，但会带来新的复杂度。先理解基本概念和代码写法，后面再学更高级的`Task`和`async/await`（那些是更优雅的多线程写法，但底层原理跟今天讲的一样）。
