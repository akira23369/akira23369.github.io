# AutoResetEvent 详解

## 一、为什么需要 AutoResetEvent？
从 ManualResetEvent 的痛点说起

**回顾 ManualResetEvent 的大问题**：
- `Set()` 一次，门**永远开着**，所有线程都通过
- 如果你只想**一个一个放行**，必须手动 `Reset()`，代码麻烦且容易忘
- **信号会累积**：没人等待时 `Set()`，信号不会丢失，下次 `WaitOne()` 直接通过

**场景**：停车场保安亭，一次只能放一辆车进去。ManualResetEvent 就像按一次按钮，栏杆一直抬起，所有车都冲进去；AutoResetEvent 就像每按一次按钮，**只放一辆车**，然后栏杆自动落下。

---

## 二、AutoResetEvent 是什么？
自动落杆的门闸

**大白话理解**：`AutoResetEvent` 是 **"自动关门"** 的信号量。调用 `Set()` 开门后，**只放行一个**等待的线程，然后**自动关门**（`Reset()`），其他线程继续等着。下次再想放行，必须再调用一次 `Set()`。

**核心行为**：
- `Set()` → 门开 → 一个线程通过 → 门**自动关**
- 如果没人等待，`Set()` 的信号会**浪费掉**（不保留）
- 多个线程等待时，按**排队顺序**一个一个放

---

## 三、核心方法


```csharp
AutoResetEvent are = new AutoResetEvent(false); // false=初始关门，true=开门
```

| 方法 | AutoResetEvent 行为 | 对比 ManualResetEvent |
|------|---------------------|-----------------------|
| **`WaitOne()`** | 等门开，通过后自动关门 | 等门开，通过后**门还开着** |
| **`Set()`** | 放**一个**线程，然后**自动关门** | 放**所有**线程，门**保持打开** |
| **`Reset()`** | 基本不用（因为自动关） | 必须手动调用，否则门一直开 |
| **信号记忆** | **不记忆**，没人等就浪费 | **会记忆**，没人等也保留 |

有`Reset()`是因为`new AutoResetEvent(true)`后可以取消

## 四、代码示例

### 示例1：基础对比——Manual vs Auto

```csharp
using System;
using System.Threading;

class Program
{
    static void Main()
    {
        Console.WriteLine("======== 测试 ManualResetEvent ========");
        ManualResetEvent mre = new ManualResetEvent(false);

        // 3个线程等待
        for (int i = 1; i <= 3; i++)
        {
            int id = i;
            new Thread(() => {
                Console.WriteLine($"Manual-线程{id}：等待...");
                mre.WaitOne();
                Console.WriteLine($"Manual-线程{id}：通过了！");
            }).Start();
            Thread.Sleep(100);
        }

        Thread.Sleep(1000);
        Console.WriteLine("Manual: Set() 一次");
        mre.Set(); // 门开，所有线程通过

        Thread.Sleep(1000); // 等它们跑完


        Console.WriteLine("\n======== 测试 AutoResetEvent ========");
        AutoResetEvent are = new AutoResetEvent(false);

        // 3个线程等待
        for (int i = 1; i <= 3; i++)
        {
            int id = i;
            new Thread(() => {
                Console.WriteLine($"Auto-线程{id}：等待...");
                are.WaitOne();
                Console.WriteLine($"Auto-线程{id}：通过了！");
            }).Start();
            Thread.Sleep(100);
        }

        Thread.Sleep(1000);
        Console.WriteLine("Auto: Set() 第一次");
        are.Set(); // 只放线程1

        Thread.Sleep(500);
        Console.WriteLine("Auto: Set() 第二次");
        are.Set(); // 只放线程2

        Thread.Sleep(500);
        Console.WriteLine("Auto: Set() 第三次");
        are.Set(); // 只放线程3

        Thread.Sleep(1000);
    }
}
```

**输出结果（仔细看区别）：**
```
======== 测试 ManualResetEvent ========
Manual-线程1：等待...
Manual-线程2：等待...
Manual-线程3：等待...
Manual: Set() 一次
Manual-线程1：通过了！
Manual-线程2：通过了！
Manual-线程3：通过了！

======== 测试 AutoResetEvent ========
Auto-线程1：等待...
Auto-线程2：等待...
Auto-线程3：等待...
Auto: Set() 第一次
Auto-线程1：通过了！  ← 只放一个！

Auto: Set() 第二次
Auto-线程2：通过了！  ← 再放一个！

Auto: Set() 第三次
Auto-线程3：通过了！  ← 再放一个！
```

**关键差异**：
- **Manual**：一次 `Set()`，三个线程全过
- **Auto**：三次 `Set()`，三个线程**依次**过

### 示例2：真实场景——停车场限流

```csharp
class ParkingLot
{
    private AutoResetEvent _parkingGate = new AutoResetEvent(true); // 初始开门
    private int _capacity = 3;
    private int _occupied = 0;
    private object _lockObj = new object();

    public void Enter(int carId)
    {
        Console.WriteLine($"车辆{carId}：到达门口...");
        
        _parkingGate.WaitOne(); // 等待放行，通过后自动关门

        lock (_lockObj)
        {
            _occupied++;
            Console.WriteLine($"车辆{carId}：进入停车场，当前占用 {_occupied}/{_capacity}");
            
            // 如果没满，再按一次按钮，让下一辆车进来
            if (_occupied < _capacity)
            {
                _parkingGate.Set(); // 再放一辆
            }
        }
    }

    public void Leave(int carId)
    {
        lock (_lockObj)
        {
            _occupied--;
            Console.WriteLine($"车辆{carId}：离开停车场，当前占用 {_occupied}/{_capacity}");
            
            // 只要还有空位，就按按钮放行
            _parkingGate.Set(); // 放下一辆
        }
    }
}

class Program
{
    static void Main()
    {
        var parking = new ParkingLot();

        // 5辆车想进来（但只有3个车位）
        for (int i = 1; i <= 5; i++)
        {
            int carId = i;
            new Thread(() => {
                parking.Enter(carId);
                Thread.Sleep(carId * 1000); // 模拟停车时间
                parking.Leave(carId);
            }).Start();
            Thread.Sleep(200);
        }

        Thread.Sleep(20000); // 等所有车走完
    }
}
```

**输出（重点看控制顺序）：**
```
车辆1：到达门口...
车辆1：进入停车场，当前占用 1/3
车辆2：到达门口...
车辆2：进入停车场，当前占用 2/3
车辆3：到达门口...
车辆3：进入停车场，当前占用 3/3
车辆4：到达门口...  ← 车辆4和5在门口等
车辆5：到达门口...

车辆1：离开停车场，当前占用 2/3
车辆4：进入停车场，当前占用 3/3  ← 离开一辆，进一辆
车辆2：离开停车场，当前占用 2/3
车辆5：进入停车场，当前占用 3/3  ← 离开一辆，进一辆
...
```

### 示例3：信号浪费问题

```csharp
static void Main()
{
    AutoResetEvent signal = new AutoResetEvent(false);

    Console.WriteLine("主线程：Set() 一次（没人等，信号浪费）");
    signal.Set(); // 没人等，信号直接消失

    Thread.Sleep(1000);

    new Thread(() => {
        Console.WriteLine("工作线程：WaitOne() 等待...");
        bool gotSignal = signal.WaitOne(2000); // 等2秒
        Console.WriteLine($"工作线程: {(gotSignal ? "收到信号" : "超时")}");
    }).Start();

    Thread.Sleep(500);
    Console.WriteLine("主线程：2秒内不再 Set()，工作线程会超时");
}
```

**输出**：
```
主线程：Set() 一次（没人等，信号浪费）
工作线程：WaitOne() 等待...
主线程：2秒内不再 Set()，工作线程会超时
工作线程: 超时
```

**教训**：`AutoResetEvent` **不会记忆信号**，调用 `Set()` 时如果没有线程在等待，这次信号就**浪费**了。

## 五、新手陷阱

### **陷阱1：Set 次数 < Wait 线程数，部分线程永远等**
```csharp
AutoResetEvent signal = new AutoResetEvent(false);

// 3个线程等
for (int i = 1; i <= 3; i++)
{
    int id = i;
    new Thread(() => {
        Console.WriteLine($"线程{id}：等...");
        signal.WaitOne(); // 等
        Console.WriteLine($"线程{id}：过了");
    }).Start();
}

Thread.Sleep(1000);
Console.WriteLine("主线程：只 Set() 一次");
signal.Set(); // 只放一个

// 结果：线程1过了，线程2和3永远卡死！
```

**解决**：确保 `Set()` 次数等于等待线程数，或用循环持续 `Set()` 直到没人等。

---

### **陷阱2：在循环里忘记 Set()**
```csharp
// 需求：5个线程轮流执行
AutoResetEvent turnSignal = new AutoResetEvent(false);

for (int i = 0; i < 5; i++)
{
    new Thread(() => {
        turnSignal.WaitOne(); // 等信号
        DoWork();
        // 错误：做完不 Set()，下一个线程永远等不到
    }).Start();
}

// 第一次 Set() 后，后续没有 Set()，只有一个线程能执行
turnSignal.Set();
```

**正确做法**：
```csharp
new Thread(() => {
    turnSignal.WaitOne();
    DoWork();
    turnSignal.Set(); // 做完主动 Set()，让下一个
}).Start();
```

---

### **陷阱3：混淆 WaitOne 返回值**
```csharp
AutoResetEvent signal = new AutoResetEvent(false);

// 线程1：等待
new Thread(() => {
    bool result = signal.WaitOne(2000); // 等2秒
    if (result) 
        Console.WriteLine("收到信号"); // 被 Set() 唤醒
    else
        Console.WriteLine("超时"); // 2秒内没 Set()
}).Start();

// 线程2：超时后 Set()
Thread.Sleep(3000);
signal.Set(); // 线程1已经超时走了，这次 Set() 没人接
```

**注意**：`WaitOne()` 返回 `bool` 很重要，必须判断是**信号唤醒**还是**超时**。

## 六、ManualResetEvent vs AutoResetEvent 对比

| 特性             | ManualResetEvent       | AutoResetEvent         |
| -------------- | ---------------------- | ---------------------- |
| **Set 后行为**    | 门开，**所有线程**通过，**保持开门** | 门开，**一个线程**通过，**自动关门** |
| **Set 次数**     | 一次 Set，永久有效            | 几次 Set，放几个线程           |
| **信号记忆**       | **会记忆**（没人等也保留）        | **不记忆**（没人等就浪费）        |
| **典型用途**       | 批量唤醒（程序启停）             | 轮流/限流（一次一个）            |
| **是否需要 Reset** | **必须手动** Reset()       | **自动** Reset()，基本不用调   |
| **类比**         | 电闸，推上去一直通电             | 按钮，按一次动一下              |

---

## 七、什么时候用 AutoResetEvent？

**适用场景**：
1. **限流控制**：一次只允许 N 个线程通过（配合信号量）
2. **轮流执行**：线程 A 做完通知 B，B 做完通知 C
3. **资源保护**：比如只有1个数据库连接，一次只用给一个线程
4. **简单信号**："我做完了，你可以开始了"

**不适用**：
- 需要一次性唤醒所有线程：用 `ManualResetEvent`
- 高频短时同步：用 `Monitor` 或 `Interlocked`
- 跨进程同步：用 `EventWaitHandle`

---

## 八、总结

**核心记忆**：
- **Auto**：自动关门，一次只放一个
- **Set 次数 = 通过线程数**：少 Set 一次，多卡死一个
- **不记忆信号**：没人等就浪费，不像 Manual 会保留

**使用口诀**：
```csharp
AutoResetEvent gate = new AutoResetEvent(false);

// 等待方
gate.WaitOne(); // 等开门，过了门自动关

// 放行方
gate.Set(); // 按一次按钮，放一个过去
gate.Set(); // 再按一次，再放一个

// 没人等的时候 Set()，信号浪费
```
