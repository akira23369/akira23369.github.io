### Thread.Interrupt() 方法详解

#### 一、Interrupt() 是干嘛用的？

**大白话理解**：`Thread.Interrupt()` 就是 **"叫醒服务"**。当一个线程正在睡觉（Sleep）或正在等人（Join）时，你想让它别等了，赶紧醒过来干活，就调用这个方法。它会扔一个异常给那个睡着的线程，强制让它醒来处理情况。

**官方定义**：中断处于 WaitSleepJoin 状态的线程。

---

#### 二、基本用法和代码示例

```csharp
using System;
using System.Threading;

class Program
{
    static void Main()
    {
        // 创建子线程，让它睡10秒
        Thread sleeper = new Thread(() => {
            try
            {
                Console.WriteLine($"线程 {Thread.CurrentThread.ManagedThreadId}：我要开始睡觉了...");
                Thread.Sleep(10000); // 计划睡10秒
                Console.WriteLine("自然醒"); // 这行不会执行
            }
            catch (ThreadInterruptedException)
            {
                Console.WriteLine("被人强行叫醒了！");
            }
        });
        
        sleeper.Start();
        Thread.Sleep(500); // 给子线程一点时间开始睡觉
        
        Console.WriteLine($"主线程：等不及了，5秒后叫醒他");
        Thread.Sleep(5000);
        
        sleeper.Interrupt(); // 叫醒子线程
        sleeper.Join(); // 等子线程处理完
        
        Console.WriteLine("主线程：完事");
    }
}
```

**执行流程**：
```
子线程：我要开始睡觉了...
主线程：等不及了，5秒后叫醒他
[5秒后]
被人强行叫醒了！
主线程：完事
```
**注意**：子线程的 `Thread.Sleep(10000)` 只睡了5秒就被强制唤醒，并抛出 `ThreadInterruptedException` 异常。

#### 三、核心特点（新手必看）

**1. 只能中断"睡觉"或"等待"的线程**
线程必须处于 `WaitSleepJoin` 状态，Interrupt 才有效。这包括：
- `Thread.Sleep()` 期间
- `t.Join()` 等待其他线程时
- 等待锁/信号量时（后面会学）

**2. 对正在干活的线程无效**
```csharp
Thread t = new Thread(() => {
    for (int i = 0; i < 1000000; i++)
    {
        // 疯狂计算中，没空睡觉
    }
});

t.Start();
Thread.Sleep(100); // 确保子线程已经开始计算

t.Interrupt(); // 无效！子线程不会收到异常，继续算它的
t.Join(); // 主线程必须等子线程算完
```
**后果**：`Interrupt()` 调用直接无效，不会抛异常，也不会停止线程。

**3. 中断后抛出 ThreadInterruptedException**
```csharp
try
{
    // 任何能阻塞的方法都可能被中断
    Thread.Sleep(Timeout.Infinite); // 无限期睡眠
}
catch (ThreadInterruptedException ex)
{
    // 必须捕获这个异常，否则线程会终止
    Console.WriteLine("被中断了：" + ex.Message);
}
```
**重点**：这个异常必须手动捕获处理，否则线程会直接崩溃。

**4. 中断状态会被"记住"**
```csharp
Thread t = new Thread(() => {
    try
    {
        Thread.Sleep(1000);
    }
    catch (ThreadInterruptedException)
    {
        Console.WriteLine("第一次被中断");
    }
    
    // 这里继续睡，不会再次被中断
    Thread.Sleep(1000); // 正常睡完
    Console.WriteLine("第二次睡眠完成");
});

t.Start();
Thread.Sleep(500);
t.Interrupt(); // 只中断一次
t.Join();
```
**注意**：一次 `Interrupt()` 只触发一次异常，不会持续有效。

#### 四、实际应用场景

**场景1：取消长时间等待的任务**
```csharp
static void Main()
{
    Thread worker = new Thread(DownloadWithTimeout);
    worker.Start();
    
    // 设置3秒超时
    Thread.Sleep(3000);
    
    if (worker.IsAlive) // 检查线程是否还活着
    {
        Console.WriteLine("3秒了还没下完，中断！");
        worker.Interrupt();
    }
    
    worker.Join();
}

static void DownloadWithTimeout()
{
    try
    {
        Console.WriteLine("开始下载大文件...");
        Thread.Sleep(10000); // 模拟下载需要10秒
        Console.WriteLine("下载完成");
    }
    catch (ThreadInterruptedException)
    {
        Console.WriteLine("下载被中断，清理资源...");
        // 关闭网络连接、删除临时文件等
    }
}
```

**场景2：优雅地通知线程退出**
```csharp
class Program
{
    static Thread workerThread;
    
    static void Main()
    {
        workerThread = new Thread(WorkLoop);
        workerThread.Start();
        
        Console.WriteLine("按任意键停止工作...");
        Console.ReadKey();
        
        workerThread.Interrupt(); // 而不是 Abort()
        workerThread.Join();
        
        Console.WriteLine("程序退出");
    }
    
    static void WorkLoop()
    {
        try
        {
            while (true)
            {
                Console.WriteLine("工作中...");
                Thread.Sleep(1000); // 每次循环都睡1秒
            }
        }
        catch (ThreadInterruptedException)
        {
            Console.WriteLine("收到中断信号，安全退出");
        }
    }
}
```
**好处**：线程可以在 `catch` 块里清理资源（关闭文件、释放锁），比强制终止更优雅。

#### 五、Interrupt() vs Abort()（重要区别）

| 特性        | Thread.Interrupt()         | Thread.Abort()         |
| --------- | -------------------------- | ---------------------- |
| **作用时机**  | 只能中断等待/睡眠的线程               | 可以终止任何状态的线程            |
| **抛出异常**  | ThreadInterruptedException | ThreadAbortException   |
| **是否已废弃** | **可用（但不推荐）**               | **已废弃（.NET 5.0+ 不支持）** |
| **安全性**   | 相对安全，可预测                   | 极度危险，不可预测              |
| **资源清理**  | 可在 catch 中清理               | 可能无法清理，导致资源泄漏          |

**Abort() 为什么被废弃？**
```csharp
// 千万别用！在 .NET Core/.NET 5+ 上运行会抛异常
Thread t = new Thread(() => {
    // 可能在任何一行被强制终止，资源无法释放
    FileStream fs = File.Open("data.txt");
    // 如果在这里 Abort，文件句柄永远没机会关闭！
    fs.Close();
});
t.Start();
Thread.Sleep(100);
t.Abort(); // 极其危险！
```

**Interrupt 的局限性**：
- 无法中断正在计算密集型任务的线程
- 必须依赖线程自己定期检查（主动 Sleep 或 Wait）
- 线程必须捕获异常并正确处理

#### 六、现代替代方案（简要了解）

虽然课程讲 `Thread` 类，但实际项目**几乎不用** `Interrupt()`，有更好的方法：

```csharp
// 推荐做法：使用取消令牌（CancellationToken）
static void ModernWay()
{
    CancellationTokenSource cts = new CancellationTokenSource();
    
    Task.Run(() => {
        while (!cts.Token.IsCancellationRequested)
        {
            Console.WriteLine("工作中...");
            Thread.Sleep(1000);
        }
        Console.WriteLine("收到取消信号，安全退出");
    }, cts.Token);
    
    Thread.Sleep(3000);
    cts.Cancel(); // 安全地发出取消信号
}
```
**优点**：
- 可以取消任何状态的线程，不限于 WaitSleepJoin
- 不需要抛异常，逻辑更清晰
- 标准做法，所有现代异步 API 都支持

**为什么课程还讲 Interrupt？**
- 理解历史遗留代码
- 理解线程同步的基本原理
- 为学习锁、信号量打基础

#### 七、新手陷阱

**陷阱1：忘记捕获异常**
```csharp
Thread t = new Thread(() => {
    Thread.Sleep(1000); // 没加 try-catch
});
t.Start();
t.Interrupt(); // 子线程会因未处理异常而终止
```

**陷阱2：在 Sleep(0) 或 Yield() 上中断**
```csharp
Thread.Sleep(0); // 时间太短，可能来不及中断
Thread.Yield();   // 不能被中断
```

**陷阱3：多个线程同时 Interrupt**
```csharp
Thread t = new Thread(() => { Thread.Sleep(5000); });
t.Start();

new Thread(() => t.Interrupt()).Start();
new Thread(() => t.Interrupt()).Start(); // 第二次调用无效
```
**结果**：只有一个 `ThreadInterruptedException`，重复中断无效。

**陷阱4：中断后线程状态混乱**
```csharp
try
{
    Thread.Sleep(1000);
}
catch (ThreadInterruptedException)
{
    // 必须决定是继续、退出还是做别的
    // 否则线程会继续执行后续代码，可能不符合预期
}
// 后续代码会继续执行！
```

#### 八、Interrupt() 的正确使用模式

```csharp
static void SafeWorker()
{
    try
    {
        while (true)
        {
            // 业务逻辑
            DoSomething();
            
            // 定期检查点
            Thread.Sleep(0); // 让线程可中断
        }
    }
    catch (ThreadInterruptedException)
    {
        Console.WriteLine("被中断，执行清理...");
        Cleanup();
        return; // 明确退出
    }
}

static void DoSomething()
{
    // 即使这里耗时很长，也必须在某处 Sleep/Wait
    for (int i = 0; i < 1000; i++)
    {
        // 模拟工作
        if (i % 100 == 0)
            Thread.Sleep(1); // 插入检查点，让线程可被中断
    }
}
```

---

**总结**：`Thread.Interrupt()` 是一个"叫醒"机制，只能打断正在睡觉或等待的线程，通过抛异常的方式通知它。虽然比 `Abort()` 安全，但限制太多，现代开发基本不用。理解它有助于学习线程同步原理，但实际项目请使用 `CancellationToken`。记住：**Interrupt 是历史遗留，看看就行，别当真用**。
