### 线程参数传递详解

#### 一、为什么需要给线程传参数？

**大白话理解**：创建子线程时，经常需要告诉它"具体干什么活"。比如主线程想让子线程下载文件，就得把"下载地址"和"保存路径"这两个信息传过去。线程方法默认不带参数，`ThreadStart` 只能执行 `void Method()` 这种无参方法，所以得想办法把数据塞进去。

---

#### 二、ParameterizedThreadStart 方式（传统方式）

这是 .NET 最早提供的参数传递机制，核心特点是：**只能传一个object类型的参数**。

**基本用法**：
```csharp
using System;
using System.Threading;

class Program
{
    static void Main()
    {
        // 1. 定义带object参数的方法
        // 2. 用ParameterizedThreadStart包装
        // 3. 在Start()方法里传入参数
        
        Thread t = new Thread(DownloadFile);
        t.Start("https://example.com/file.zip"); // 传递字符串参数
        t.Join();
    }
    
    // 方法签名必须是：void MethodName(object obj)
    static void DownloadFile(object url)
    {
        // 拿到参数后需要强制类型转换
        string downloadUrl = (string)url;
        Console.WriteLine($"线程 {Thread.CurrentThread.ManagedThreadId} 开始下载: {downloadUrl}");
        Thread.Sleep(2000); // 模拟下载
        Console.WriteLine("下载完成");
    }
}
```

**关键限制**：
1. **只能传一个参数**：方法签名必须是 `void Method(object obj)`，多一个参数都不行
2. **类型不安全**：传进去是 object，拿出来要手动转，转错就崩溃
3. **值类型会装箱**：如果传 `int` 等值类型，会自动装箱成 object，有性能损耗

**传多个参数的笨办法（用类或结构体）**：
```csharp
// 定义一个参数包类，把多个字段打包
class DownloadParams
{
    public string Url { get; set; }
    public string SavePath { get; set; }
    public int Timeout { get; set; }
}

static void Main()
{
    Thread t = new Thread(DownloadWithParams);
    
    // 把多个参数塞进一个对象
    var param = new DownloadParams
    {
        Url = "https://example.com/file.zip",
        SavePath = "C:\\temp\\file.zip",
        Timeout = 5000
    };
    
    t.Start(param); // 只传这一个对象
    t.Join();
}

static void DownloadWithParams(object obj)
{
    // 转换类型后使用
    DownloadParams param = (DownloadParams)obj;
    Console.WriteLine($"下载 {param.Url} 到 {param.SavePath}, 超时 {param.Timeout}ms");
}
```
**优点**：解决了多参数问题
**缺点**：代码啰嗦，每个业务都要定义一个新类

---

#### 三、Lambda 表达式方式（现代首选）

**Lambda 是什么**：简单说就是"**内联的小方法**"，可以直接在代码里写，不用单独定义。最厉害的是能 **"捕获"周围环境的变量** ，把外部变量自动带进去。

**基本用法**：
```csharp
using System;
using System.Threading;

class Program
{
    static void Main()
    {
        string url = "https://example.com/file.zip";
        string savePath = "C:\\temp\\file.zip";
        
        // Lambda 会自动捕获 url 和 savePath 变量
        Thread t = new Thread(() => {
            // 直接在Lambda体里使用外部变量
            Console.WriteLine($"线程 {Thread.CurrentThread.ManagedThreadId} 下载 {url}");
            Console.WriteLine($"保存到 {savePath}");
            Thread.Sleep(2000);
        });
        
        t.Start();
        t.Join();
    }
}
```

**传多个参数超简单**：
```csharp
static void Main()
{
    for (int i = 1; i <= 3; i++)
    {
        int taskId = i; // 关键点：必须在这个作用域内捕获
        
        new Thread(() => {
            Console.WriteLine($"任务 {taskId} 开始执行");
            Thread.Sleep(1000);
            Console.WriteLine($"任务 {taskId} 完成");
        }).Start();
        
        Thread.Sleep(100); // 稍微间隔一下
    }
}
```

**Lambda 的优势**：
- **不限参数数量**：想用几个用几个
- **类型安全**：编译器检查类型，不用手动转换
- **代码简洁**：不用定义额外类和方法
- **捕获变量**：自动把外部变量包进去

---

#### 四、Lambda 捕获变量的陷阱（新手必踩的坑）

这是 Lambda 最隐蔽的问题：**循环中捕获变量**。

**错误示范（99%新手会写错）**：
```csharp
for (int i = 0; i < 5; i++)
{
    // 错误！所有线程共享同一个 i 变量
    new Thread(() => {
        Thread.Sleep(100); // 确保循环先跑完
        Console.WriteLine($"任务 {i} 执行"); // 这里 i 已经是 5 了
    }).Start();
}

// 输出可能是：
任务 5 执行
任务 5 执行
任务 5 执行
任务 5 执行
任务 5 执行
```

**原因分析**：可以去看Lambda表达式的闭包那部分，简单讲Lambda捕获的变量会保存到生成的类中
- Lambda 捕获的是**变量本身**，不是变量的值
- 5 个线程都指向同一个 `i` 变量
- 当线程开始执行时，循环已经结束，`i` 变成 5

**正确姿势（在循环内创建临时变量）**：
```csharp
for (int i = 0; i < 5; i++)
{
    int current = i; // 关键点：每次循环新建一个变量
    new Thread(() => {
        Thread.Sleep(100);
        Console.WriteLine($"任务 {current} 执行"); // 捕获的是各自的 current
    }).Start();
}

// 输出（顺序不固定，但值正确）：
任务 0 执行
任务 2 执行
任务 1 执行
任务 3 执行
任务 4 执行
```

**原理**：每次循环，`current` 都是一个全新的变量，每个线程捕获属于自己的那一个。

#### 五、两种方式对比总结

| 特性 | ParameterizedThreadStart | Lambda 表达式 |
|------|------------------------|--------------|
| **参数数量** | 只能1个 object | 任意数量 |
| **类型安全** | 不安全（需手动转换） | 安全（编译器检查） |
| **代码简洁度** | 啰嗦（需定义方法） | 简洁（内联写法） |
| **多参数方案** | 需定义参数类 | 直接捕获多个变量 |
| **可读性** | 方法独立，清晰 | Lambda 太长时可读性差 |
| **性能** | 有装箱拆箱损耗 | 无装箱，效率更高 |
| **推荐度** | ⭐⭐ 不推荐 | ⭐⭐⭐⭐⭐ 强烈推荐 |

**选择建议**：
- **新项目 100% 用 Lambda**：简单、安全、方便
- **老项目维护**：看到 `ParameterizedThreadStart` 能看懂就行
- **Lambda 不要太长**：如果 Lambda 超过 10 行，建议抽成独立方法，再用 Lambda 调用

#### 六、参数传递的变量生命周期陷阱

**问题**：主线程的局部变量，子线程还能用吗？

```csharp
static void Main()
{
    string importantData = "非常重要数据";
    
    Thread t = new Thread(() => {
        Thread.Sleep(2000); // 等2秒
        Console.WriteLine(importantData); // 还能访问到吗？
    });
    
    t.Start();
    
    // importantData 是局部变量，Main 方法结束时按理说会被销毁
    // 但子线程还在用，怎么办？
}
```

**答案**：C# 编译器会**自动延长变量生命周期**。虽然 `importantData` 是 `Main` 的局部变量，但只要子线程 Lambda 捕获了它，CLR 会确保这个变量一直存活到子线程不再需要为止。

**危险情况（引用外部对象）**：
```csharp
static void Main()
{
    FileStream fs = File.OpenRead("data.txt");
    
    new Thread(() => {
        Thread.Sleep(1000);
        // 主线程可能在 Sleep 期间关闭 fs
        byte[] buffer = new byte[100];
        fs.Read(buffer, 0, 100); // 可能报错：文件句柄已关闭
    }).Start();
    
    Thread.Sleep(500);
    fs.Close(); // 危险！子线程还在用
}
```

**正确做法**：
```csharp
static void Main()
{
    FileStream fs = File.OpenRead("data.txt");
    
    new Thread(() => {
        Thread.Sleep(1000);
        byte[] buffer = new byte[100];
        fs.Read(buffer, 0, 100);
        fs.Close(); // 在使用者内部关闭
    }).Start();
    
    // 主线程不要关闭 fs，交给子线程管理
}
```

#### 七、为下下篇《自定义线程对象》做铺垫

当参数太多，或者想封装线程的"配置"和"行为"时，Lambda 也不够用：

```csharp
// 参数太多，Lambda 变得臃肿
Thread t = new Thread(() => {
    Download(url, savePath, timeout, retryCount, proxy, headers, ...);
});

// 更好的方式（自定义线程类，预告内容）：
class DownloadThread
{
    private string url;
    private string savePath;
    private int timeout;
    // ... 更多字段
    
    public DownloadThread(string url, string savePath, int timeout)
    {
        this.url = url;
        // ... 初始化
    }
    
    public void Start()
    {
        // 内部创建线程，使用实例方法，天然访问所有字段
        Thread t = new Thread(DoDownload);
        t.Start();
    }
    
    private void DoDownload()
    {
        // 直接用实例字段，不用传参数
        Console.WriteLine($"下载 {url} 到 {savePath}");
    }
}

// 使用简洁
DownloadThread dt = new DownloadThread("url", "path", 5000);
dt.Start();
```

**核心思想**：当参数超过3-4个，或者想复用线程逻辑时，**把数据和逻辑封装成类**，比 Lambda 更清爽、更易维护。

---

**总结**：参数传递是多线程编程的基础。`ParameterizedThreadStart` 是历史遗留，知道就行；Lambda 是现代首选，简洁强大但要小心变量捕获陷阱。记住循环内必须创建临时变量的铁律，理解变量生命周期，就能避免90%的参数传递bug。参数太多时，就该考虑下下篇要讲的《自定义线程对象》了。
