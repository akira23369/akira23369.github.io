# Monitor 类的 Pulse 与 Wait

## 一、为什么需要 Pulse/Wait？（从 lock 的局限性说起）

`lock` 虽然能保护共享资源，但它有个硬伤：**只能互斥，不能协调**。比如经典的生产者-消费者问题：
- 生产者想："仓库满了，我得等消费者拿走一些才能生产"
- 消费者想："仓库空了，我得等生产者造出东西才能消费"

`lock` 只能让你**进去**或**出来**，但不能让你**进去后发现条件不满足，先出来等着，条件满足了再进去**。`Monitor.Wait` 和 `Monitor.Pulse` 就是来解决这个"**条件等待**"问题的。

---

## 二、Monitor.Wait() —— 在锁里"临时让位"

**大白话理解**：你拿到锁进入仓库，发现货满了，你说："我先出去睡会儿，等你们用得差不多了叫我"。`Wait()` 就是这句话的代码实现。

**核心作用**：
1. **释放锁**：让其他线程可以进入临界区
2. **进入等待队列**：自己到旁边"休息室"排队
3. **阻塞等待**：直到有人 `Pulse` 叫你

**代码模板**：
```csharp
lock (_lock)
{
    while (条件不满足) // 必须用 while，不能用 if！
    {
        Console.WriteLine("条件不满足，我去休息室等着");
        Monitor.Wait(_lock); // 释放锁，等待被叫醒
        // 被叫醒后，会重新竞争锁，拿到锁后从这里继续执行
    }
    
    Console.WriteLine("条件满足了，我拿到锁继续干活");
    // ... 干活 ...
}
```

**为什么必须用 `while` 而不是 `if`**？
```csharp
// 错误示范
lock (_lock)
{
    if (_queue.Count == 0) // 只检查一次
    {
        Monitor.Wait(_lock);
    }
    // 被叫醒后，可能别的线程已经把队列清空了
    // 这里直接执行 Dequeue 会抛异常
    _queue.Dequeue();
}

// 正确示范
lock (_lock)
{
    while (_queue.Count == 0) // 每次醒来都检查
    {
        Monitor.Wait(_lock);
    }
    // 确保队列不为空才 Dequeue
    _queue.Dequeue();
}
```

## 三、Monitor.Pulse() —— "下一个叫号"

**大白话理解**：你消费完一个产品，发现仓库有空位了，对休息室喊一嗓子："可以了，下一个快来！"`Pulse()` 就是这句喊话。

**核心作用**：
- **叫醒一个**等待的线程（FIFO顺序，公平排队）
- **不立即释放锁**：你喊完继续干活，直到 `lock` 块结束才真正释放锁

**代码模板**：
```csharp
lock (_lock)
{
    // 修改共享状态
    _queue.Enqueue(item);
    
    Console.WriteLine("我生产了一个，通知一个消费者来取");
    Monitor.Pulse(_lock); // 叫醒一个等待的消费者
    
    // 注意：锁还没释放，要等到离开 lock 块
}

// 离开 lock 后，被叫醒的线程才能重新拿到锁
```

**重要**：如果没人等待，`Pulse()` 直接返回，**不做任何事**，也不会保留信号。

## 四、完整生产者-消费者示例

```csharp
using System;
using System.Collections.Generic;
using System.Threading;

public class Warehouse
{
    private readonly object _lock = new object();
    private readonly Queue<string> _products = new Queue<string>();
    private const int MaxCapacity = 3;

    // 生产者
    public void Produce(string product)
    {
        lock (_lock)
        {
            // 如果仓库满了，就等着
            while (_products.Count >= MaxCapacity)
            {
                Console.WriteLine($"[生产者] 仓库满了 ({_products.Count}/{MaxCapacity})，我去休息...");
                Monitor.Wait(_lock); // 释放锁，等待
            }

            // 生产产品
            _products.Enqueue(product);
            Console.WriteLine($"[生产者] 生产了 '{product}'，当前库存: {_products.Count}/{MaxCapacity}");
            
            // 通知一个消费者来取货
            Monitor.Pulse(_lock);
        }
    }

    // 消费者
    public string Consume()
    {
        lock (_lock)
        {
            // 如果仓库空了，就等着
            while (_products.Count == 0)
            {
                Console.WriteLine($"[消费者] 仓库空了，我去休息...");
                Monitor.Wait(_lock); // 释放锁，等待
            }

            // 消费产品
            string product = _products.Dequeue();
            Console.WriteLine($"[消费者] 消费了 '{product}'，剩余库存: {_products.Count}/{MaxCapacity}");
            
            // 通知一个生产者来补货
            Monitor.Pulse(_lock);
            
            return product;
        }
    }
}

class Program
{
    static void Main()
    {
        var warehouse = new Warehouse();

        // 启动生产者
        new Thread(() => {
            for (int i = 1; i <= 5; i++)
            {
                warehouse.Produce($"产品{i}");
                Thread.Sleep(500); // 生产间隔
            }
        }).Start();

        // 启动消费者
        new Thread(() => {
            for (int i = 1; i <= 5; i++)
            {
                warehouse.Consume();
                Thread.Sleep(800); // 消费间隔
            }
        }).Start();

        Thread.Sleep(10000);
    }
}
```

**输出（观察 Wait/Pulse 的协调）：**
```
[生产者] 生产了 '产品1'，当前库存: 1/3
[生产者] 生产了 '产品2'，当前库存: 2/3
[生产者] 生产了 '产品3'，当前库存: 3/3
[生产者] 仓库满了 (3/3)，我去休息...  ← 满了，等待
[消费者] 消费了 '产品1'，剩余库存: 2/3
[生产者] 被叫醒，继续生产 '产品4'   ← Pulse 生效
[生产者] 生产了 '产品4'，当前库存: 3/3
[生产者] 仓库满了 (3/3)，我去休息...
[消费者] 消费了 '产品2'，剩余库存: 2/3
[生产者] 被叫醒，生产 '产品5'
...
```

## 五、Monitor vs ManualResetEvent：核心区别

现在你已经理解了 Monitor 的 **"等待-通知"** 机制，来看 `ManualResetEvent` 有何不同。

|特性|Monitor|ManualResetEvent|
|---|---|---|
|**本质**|**排他锁** + 条件变量|**信号通知**机制|
|**主要用途**|保护共享数据（临界区）|线程间事件通知|
|**线程所有权**|**有**（只有锁持有者能操作）|**无**（任何线程可Set/Reset）|
|**等待行为**|`Wait()` 释放锁|`WaitOne()` 不持有锁|
|**通知范围**|`Pulse()` 唤醒**一个**线程|`Set()` 释放**所有**等待线程|
|**状态持久性**|无状态（依赖条件变量）|信号状态**持续保持**直到Reset|
|**性能**|极高（用户态锁）|较高（EventSlim为混合模式）|
|**跨进程**|❌ 不支持|✅ 传统版支持（命名事件）|
|**典型模式**|lock + Wait/Pulse|Set/Reset + WaitOne|
|**虚假唤醒**|需 `while(condition)` 防护|无此问题（状态明确）|

### **锁机制不同**
- **Monitor**：必须与 `lock` 配合使用，**在临界区内**等待和通知
- **ManualResetEvent**：**独立于锁**，任何线程都可以 `Set()` 或 `WaitOne()`，不需要持有锁

### **信号行为不同**
```csharp
// Monitor.Pulse()：没人等待就浪费，信号不保留
lock (_lock)
{
    Monitor.Pulse(_lock); // 休息室没人，喊话=白喊
}

// ManualResetEvent.Set()：信号会保留，下次 WaitOne() 直接通过
ManualResetEvent mre = new ManualResetEvent(false);
mre.Set(); // 没人等，但信号记住了
// 1秒后...
mre.WaitOne(); // 立即通过，因为门还开着
```

### **唤醒范围不同**
- **Monitor.Pulse()**：只叫醒**一个**等待线程
- **ManualResetEvent.Set()**：叫醒**所有**等待线程

### **使用场景对比**

| 场景 | Monitor (Pulse/Wait) | ManualResetEvent |
|------|---------------------|------------------|
| **生产者-消费者** | ✅ **完美**：在锁内协调，安全 | ❌ 不适用：无法保护队列操作 |
| **程序启动信号** | ❌ 麻烦：需要额外锁保护 | ✅ **完美**：Set一次，所有线程起飞 |
| **线程池任务同步** | ❌ 复杂：要管理多个条件变量 | ✅ **完美**：批量唤醒 |
| **资源竞争保护** | ✅ **必须**：lock 保护临界区 | ❌ 做不到：没有互斥能力 |

**核心总结**：
- **Monitor**：**锁内协调**，适合保护共享资源的**条件等待**
- **ManualResetEvent**：**锁外信号**，适合**批量通知**、**程序启停**等宏观控制

## 六、什么时候用哪个？选择指南

### **用 Monitor + Pulse/Wait 当：**
1. 你需要在**锁内**判断条件（队列空/满）
2. 你需要**精确控制**：生产一个，消费一个
3. 你要保护的是**共享数据结构**（Queue、List 等）

**典型模式**：
```csharp
lock (_lock)
{
    while (条件不满足) Monitor.Wait(_lock);
    // 操作共享资源
    Monitor.Pulse(_lock); // 通知对方
}
```

### **用 ManualResetEvent 当：**
1. 你需要**一次性通知所有线程**："开始！"或"停止！"
2. 你不需要保护共享资源（资源已用其他方式保护）
3. 你需要**信号有记忆能力**（Set 后状态保持）
4. 需要**跨进程**同步（使用传统版）

**典型模式**：
```csharp
// 主线程
mre.Set(); // 通知所有工作线程开始干活

// 工作线程
mre.WaitOne(); // 等启动信号
// 干活
```

## 七、重要提醒：不要混用

**错误示范**：
```csharp
// 想用 ManualResetEvent 做生产者-消费者
ManualResetEvent notEmpty = new ManualResetEvent(false);
Queue<int> queue = new Queue<int>();

// 消费者
notEmpty.WaitOne(); // 等队列不为空
// 错误！WaitOne() 返回后，锁还没拿，队列可能又被清空了
queue.Dequeue(); // 可能抛异常！

// 正确做法：必须用 lock 保护队列
lock (_lock)
{
    while (queue.Count == 0) Monitor.Wait(_lock);
    queue.Dequeue(); // 安全
}
```

**结论**：`ManualResetEvent` **不能替代** `lock` 保护共享资源，它只能做宏观信号通知。

---

## 八、总结

**Monitor.Pulse/Wait**：
-  **"在锁内休息"**  ：释放锁等条件，被叫醒后重新拿锁
-  **"精准对讲"**  ：Pulse 只叫一个，信号不保留
-  **"微观协调"**  ：适合保护共享数据的精细操作

**ManualResetEvent**：
-  **"在锁外等信号"**  ：不需要持有锁
-  **"广播大喇叭"**  ：Set 一次叫所有，信号有记忆
-  **"宏观指挥"**  ：适合程序启停、批量同步
