# Mutex 详解

## 一、Mutex 是什么？（互斥体的"究极进化版"）

**大白话理解**：`Mutex` 是**跨进程的 `Monitor`**。Monitor 只能在**一个进程内**的线程间同步，而 Mutex 可以像"系统全局锁"一样，让**不同进程**的线程互相排斥。

**核心特点**：
- **互斥性**：同一时间只有一个线程能持有 Mutex
- **跨进程**：可以锁住整个系统（比如防止程序重复运行）
- **内核对象**：由 Windows 内核管理，性能比 Monitor 慢但功能更强

---

## 二、基本用法和代码示例

### 构造函数
最常用的构造函数签名是这个： 
`public Mutex (bool initiallyOwned, string name, out bool createdNew);`

**`initiallyOwned`：一进场就拿钥匙吗？**
**`true`**：表示创建这个 Mutex 的线程**直接占有**它。

**`name`：是“自留地”还是“公共区”？**
这个参数决定了它是**进程内**的还是**跨进程**的：
**传 `null`**：这是一个**局部 Mutex**。只能在你当前这个程序里的线程间起作用。
**传字符串（如 `"MyAppLock"`）**：这是一个**命名 Mutex**。操作系统内核会记录这个名字。
如果两个不同的程序（比如 A.exe 和 B.exe）都去 new 一个名字相同的 Mutex，它们抢的是**同一把锁**。
**前缀技巧：**
 `Global\` 开头：全系统可见（所有用户）。
`Local\` 开头：仅在当前 Windows 登录用户会话中可见。

**`out bool createdNew`：判断自己是否是“创建者”**
返回 `true`：表示你是第一个创建该 Mutex 的人。
返回 `false`：表示该 Mutex 已经存在，你只是拿到了它的引用。



```cs
// 1. 定义一个全局唯一的名称
string mutexName = @"Global\MyUniqueGameServer_12345";

// 2. 调用构造函数
// initiallyOwned: false (先不占有)
// out createdNew: 拿到结果
Mutex mutex = new Mutex(false, mutexName, out bool isNewInstance);

if (!isNewInstance)
{
    // 如果 createdNew 是 false，说明已经有一个程序在运行并创建了这把锁
    Console.WriteLine("已经有一个老哥在跑了，我撤了。");
    return;
}

try
{
    // 正常运行逻辑
    RunProgram();
}
finally
{
    // 释放并销毁
    mutex.Dispose();
}
```

### 示例1：进程内互斥（类似 Monitor）
```csharp
using System;
using System.Threading;

class Program
{
    // 1. 创建 Mutex（false=初始未被持有）
    private static Mutex _mutex = new Mutex(false, "MyMutex");

    static void Main()
    {
        // 模拟5个线程抢一把锁
        for (int i = 1; i <= 5; i++)
        {
            int id = i;
            new Thread(() => WorkerMethod(id)).Start();
            Thread.Sleep(100);
        }

        Thread.Sleep(10000);
    }

    static void WorkerMethod(int threadId)
    {
        Console.WriteLine($"线程{threadId}：请求 Mutex...");
        
        _mutex.WaitOne(); // 等待获取互斥体
        
        Console.WriteLine($"线程{threadId}：拿到 Mutex，开始工作");
        Thread.Sleep(2000); // 模拟耗时操作
        
        Console.WriteLine($"线程{threadId}：工作完成，释放 Mutex");
        _mutex.ReleaseMutex(); // 必须释放！
    }
}
```

**输出**：
```
线程1：请求 Mutex...
线程1：拿到 Mutex，开始工作
线程2：请求 Mutex...
线程3：请求 Mutex...
线程4：请求 Mutex...
线程5：请求 Mutex...
线程1：工作完成，释放 Mutex
线程2：拿到 Mutex，开始工作
...
```

**注意**：`WaitOne()` 和 `ReleaseMutex()` 必须**严格配对**，否则其他线程会永远卡住。

### 示例2：跨进程互斥（防止程序多开）

```csharp
// Program.cs - 你的主程序入口
static class Program
{
    static Mutex _mutex;

    [STAThread]
    static void Main()
    {
        // 尝试创建名为 "Global\MyAppSingleInstance" 的 Mutex
        // Global\ 前缀表示全局（跨所有用户会话）
        // 如果已存在，CreateMutex 会返回现有对象
        bool createdNew;
        _mutex = new Mutex(true, "Global\\MyAppSingleInstance", out createdNew);

        if (!createdNew)
        {
            // 如果 Mutex 已存在，说明程序已经在运行
            Console.WriteLine("程序已经在运行了，退出！");
            MessageBox.Show("程序已经在运行，请勿重复启动！");
            return;
        }

        try
        {
            Console.WriteLine("程序启动成功，我是唯一实例");
            Application.Run(new MainForm());
        }
        finally
        {
            _mutex.ReleaseMutex(); // 程序退出时释放
        }
    }
}
```

**关键**：`createdNew` 告诉你这个 Mutex 是你**新创建**的还是**已存在**的。

### 示例3：带超时的 WaitOne

```csharp
static void TryDoWork(int timeoutMs)
{
    Console.WriteLine("尝试获取 Mutex...");
    
    // 等 timeoutMs 毫秒，拿不到就放弃
    bool gotMutex = _mutex.WaitOne(timeoutMs);
    
    if (gotMutex)
    {
        try
        {
            Console.WriteLine($"拿到 Mutex，开始工作（限时{timeoutMs}ms）");
            Thread.Sleep(1000);
        }
        finally
        {
            _mutex.ReleaseMutex();
            Console.WriteLine("释放 Mutex");
        }
    }
    else
    {
        Console.WriteLine($"等待{timeoutMs}ms后超时，放弃");
    }
}
```

## 三、Mutex 的核心特性

### **跨进程同步**
```csharp
// 进程A
Mutex m1 = new Mutex(false, "Global\\SharedMutex");
m1.WaitOne();

// 进程B（同时运行）
Mutex m2 = new Mutex(false, "Global\\SharedMutex");
m2.WaitOne(); // 会阻塞，直到进程A ReleaseMutex()
```

**命名规则**：
- `"MyMutex"`：进程内有效
-  **`"Global\MyMutex"`**  ：整个系统所有用户有效
-  **`"Local\MyMutex"`**  ：当前用户会话内有效

### **线程所有权和重入**
```csharp
// Mutex 支持同一线程多次获取（重入）
_mutex.WaitOne(); // 计数=1
_mutex.WaitOne(); // 同一线程，计数=2（会成功）
// 必须 Release 两次才能完全释放
_mutex.ReleaseMutex(); // 计数=1
_mutex.ReleaseMutex(); // 计数=0，其他线程可以获取
```

**注意**：如果线程获取了 N 次，必须 Release N 次，否则会"占着茅坑不拉屎"。

### **内核对象，性能较差**
```csharp
// Mutex 是内核对象
Mutex m = new Mutex();
m.WaitOne(); // 需要切换到内核模式，约 1000-2000 纳秒

// Monitor 是用户模式
lock (_lock) { } // 无竞争时约 50-100 纳秒，快10-20倍
```

## 四、Monitor vs Mutex：详细对比（重点）

### **对比表格**

| 特性 | **Monitor** (lock) | **Mutex** |
|------|-------------------|-----------|
| **作用范围** | **进程内**（一个程序） | **跨进程**（整个系统） |
| **性能** | **极快**（用户模式，50ns） | **较慢**（内核模式，1000ns+） |
| **所有权重入** | ✅ 支持（同线程可多次进入） | ✅ 支持（需 Release 相同次数） |
| **跨进程** | ❌ **不支持** | ✅ **支持**（通过命名） |
| **等待机制** | 与 `lock` 绑定 | 独立调用 `WaitOne()` |
| **放弃机制** | `lock` 块结束自动释放 | **必须手动** `ReleaseMutex()` |
| **超时等待** | `Monitor.TryEnter` | `WaitOne(timeout)` |
| **线程关联** | 无（任意线程可释放） | **有**（只有持有线程能释放） |
| **命名方式** | 无 | `Global\Name` 或 `Local\Name` |
| **适用场景** | 99% 的进程内同步 | 跨进程同步、防止程序多开 |

### **核心区别1：作用范围**
```csharp
// Monitor：只在当前进程有效
// 两个进程同时运行这段代码，互不影响
lock (_lock) { /* 每个进程各锁各的 */ }

// Mutex：跨进程生效
// 两个进程同时运行，只有一个能拿到锁
_mutex.WaitOne(); // 第二个进程会阻塞
```

### **核心区别2：性能差距**
```csharp
static void PerformanceTest()
{
    const int iterations = 1000000;

    object lockObj = new object();
    Mutex mutex = new Mutex(false, "TestMutex");

    Stopwatch sw = Stopwatch.StartNew();
    for (int i = 0; i < iterations; i++)
    {
        lock (lockObj) { } // 空 lock
    }
    sw.Stop();
    Console.WriteLine($"Monitor/lock: {sw.ElapsedMilliseconds}ms"); // 约 40ms

    sw.Restart();
    for (int i = 0; i < iterations; i++) 
    {
        mutex.WaitOne();
        mutex.ReleaseMutex();
    }
    sw.Stop();
    Console.WriteLine($"Mutex: {sw.ElapsedMilliseconds}ms"); // 约 900ms
}
```

### **核心区别3：线程所有权**
```csharp
// Monitor：任何线程都可以退出 lock 块（自动释放）
lock (_lock) { } // 谁最后离开 lock 块，谁释放

// Mutex：只有获取的线程才能释放
_mutex.WaitOne(); // 线程A获取
// 线程B调用下面这行会抛 ApplicationException
_mutex.ReleaseMutex(); // 错误！只能线程A释放
```

### **核心区别4：跨进程实例**
```csharp
// 进程A
using (var mutex = new Mutex(false, "Global\\MyApp"))
{
    mutex.WaitOne();
    Console.WriteLine("进程A：我拿到锁了");
    Console.ReadLine(); // 保持持有
    mutex.ReleaseMutex();
}

// 进程B（同时运行）
using (var mutex = new Mutex(false, "Global\\MyApp"))
{
    Console.WriteLine("进程B：等锁...");
    mutex.WaitOne(); // 会阻塞，直到进程A释放
    Console.WriteLine("进程B：我拿到了！");
}
```

## 五、什么时候用 Mutex？

### ✅ **必须跨进程同步时**
```csharp
// 场景1：防止程序多开
if (!createdNew) { /* 退出 */ }

// 场景2：两个进程共享文件
Mutex fileMutex = new Mutex(false, "Global\\SharedFile");
fileMutex.WaitOne();
try
{
    File.WriteAllText("shared.txt", "data");
}
finally
{
    fileMutex.ReleaseMutex();
}
```

### ✅ **需要跨进程的资源保护**
```csharp
// 进程A和进程B同时读写同一个文件
Mutex m = new Mutex(false, "Global\\FileAccess");
m.WaitOne();
// 读写文件...
m.ReleaseMutex();
```

### ❌ **不要用 Mutex 当**：
- **进程内同步**：性能差，用 `lock` 或 `Monitor`
- **高频操作**：内核切换开销太大
- **简单计数**：用 `Interlocked` 或 `SemaphoreSlim`

## 六、Mutex 的陷阱

### **陷阱1：忘记 Dispose，导致资源泄漏**

`Mutex` 是一个封装了 Win32 内核对象（如 `WaitHandle`）的包装类。这些内核对象是不受 .NET GC（垃圾回收）直接控制的。如果不 `Dispose`，这个句柄会一直占用系统资源，直到你的进程完全退出。

IO 操作硬盘资源也需要 Dispose。`Mutex` 的性质和 IO 非常相似：
- **IO 句柄**：指向的是文件流、网络套接字。
- **Mutex 句柄**：指向的是操作系统内核里的同步对象。

它们都属于**非托管资源（Unmanaged Resources）**。虽然 .NET 的析构函数（Finalizer）最终可能会在 GC 回收对象时帮你释放句柄，但 GC 的触发是不确定的。如果你的程序频繁创建 `Mutex` 而不释放，可能会导致系统的句柄数耗尽，从而引发系统级崩溃。

```csharp
// 错误
Mutex m = new Mutex(false, "MyMutex");
m.WaitOne();
// 程序退出，没 Release，也没 Dispose

// 正确
using (Mutex m = new Mutex(false, "MyMutex"))
{
    m.WaitOne();
    // ...
    m.ReleaseMutex();
} // using 自动 Dispose
```

### **陷阱2：进程崩溃导致 Mutex 被"遗弃"**
```csharp
// 进程A持有 Mutex 时崩溃（或被杀掉）
// Mutex 会变成"遗弃状态"（abandoned）

// 进程B等待时会拿到锁，但会抛 AbandonedMutexException
try
{
    mutex.WaitOne();
}
catch (AbandonedMutexException)
{
    // 需要处理：前一个持有者崩溃，共享状态可能损坏
    Console.WriteLine("警告：Mutex被遗弃，数据可能不一致");
}
```

**含义**：`AbandonedMutexException` 告诉你"前一个线程拿着锁死了，锁我帮你释放了，但数据可能烂了"。

### **陷阱3：命名冲突**
```csharp
// 两个不同的程序用了同一个名字
Mutex m1 = new Mutex(false, "MyMutex"); // 程序A
Mutex m2 = new Mutex(false, "MyMutex"); // 程序B（意外冲突）
```

**解决**：加上程序唯一前缀
```csharp
string mutexName = $"Global\\MyApp_{Environment.UserName}";
Mutex m = new Mutex(false, mutexName);
```

## 七、轻量级替代：SemaphoreSlim（进程内）

**如果不需要跨进程**，用 `SemaphoreSlim` 更快：

```csharp
// 传统 Mutex/Semaphore（内核模式）
Semaphore sem = new Semaphore(3, 3); // 约 1000ns

// 轻量级 SemaphoreSlim（混合模式）
SemaphoreSlim slim = new SemaphoreSlim(3, 3); // 约 100ns，快10倍

// 用法几乎一样
slim.Wait(); // 或 await slim.WaitAsync()，支持异步！
try { /* ... */ }
finally { slim.Release(); }
```

**对比**：
- **Semaphore**：内核对象，支持跨进程，慢
- **SemaphoreSlim**：用户态+内核混合，不支持跨进程，快，支持异步

---

## 八、总结

**Mutex 的核心**：
- **跨进程**：唯一优势
- **内核对象**：慢，但功能强
- **线程所有权**：谁拿谁放，不能乱

**Monitor vs Mutex 选择指南**：
- **进程内**：**永远**用 `Monitor`（lock）
- **跨进程**：**必须**用 `Mutex`
- **性能敏感**：进程内用 `SemaphoreSlim` 替代 `Semaphore/Mutex`

**一句话**：Mutex 是"系统级锁"，Monitor 是"进程级锁"。需要锁住整个电脑时，才请出 Mutex。
