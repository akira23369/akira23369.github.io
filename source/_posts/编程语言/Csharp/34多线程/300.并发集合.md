# C# 并发集合详解

## 一、为什么需要并发集合？（传统集合的噩梦）

**先看一个反例**：
```csharp
using System.Collections.Generic;
using System.Threading;

class Program
{
    static List<int> _list = new List<int>(); // 普通集合

    static void Main()
    {
        // 10个线程同时添加元素
        for (int i = 0; i < 10; i++)
        {
            int item = i;
            new Thread(() => {
                _list.Add(item); // 多线程操作 List，必崩溃！
            }).Start();
        }

        Thread.Sleep(1000);
        Console.WriteLine($"最终数量: {_list.Count}"); // 可能不是10，甚至抛异常
    }
}
```

**结果**：大概率抛出 `InvalidOperationException`："集合已修改；可能无法执行枚举操作"。

**原因**：`List<T>` 不是线程安全的，内部 `_size`、`_items` 等字段在多线程下会被写坏。

**传统解决方案（手动加锁）**：
```csharp
private static readonly object _lock = new object();
lock (_lock)
{
    _list.Add(item); // 安全，但麻烦
}
```

**痛点**：
- 每个操作都要写 `lock`，代码臃肿
- 容易忘记加锁，导致 bug
- 读写都要锁，并发性能差
- 复合操作（"判断存在再添加"）需要更大范围的锁

---

## 二、并发集合是什么？（自带锁的安全集合）

**官方定义**：`System.Collections.Concurrent` 命名空间下的一组**线程安全**集合，内部已经实现了精细的锁机制（甚至无锁算法），让你不用自己写 `lock`。

**核心优势**：
- **开箱即用**：直接多线程操作，不用自己加锁
- **高性能**：内部优化，比手动 `lock` 快得多
- **线程安全**：所有操作都安全，不会崩溃、不会丢数据

---

## 三、五大并发集合详解

### `ConcurrentQueue<T>` —— 线程安全队列

**特点**：多线程 enqueue 和 dequeue 都安全，无锁算法实现。

**适用场景**：任务队列、消息队列、日志缓冲。

```csharp
using System.Collections.Concurrent;

class Program
{
    static ConcurrentQueue<int> _queue = new ConcurrentQueue<int>();

    static void Main()
    {
        // 10个线程入队
        for (int i = 0; i < 10; i++)
        {
            int item = i;
            new Thread(() => {
                _queue.Enqueue(item);
                Console.WriteLine($"入队: {item}");
            }).Start();
        }

        Thread.Sleep(1000);

        // 10个线程出队
        for (int i = 0; i < 10; i++)
        {
            new Thread(() => {
                if (_queue.TryDequeue(out int result))
                {
                    Console.WriteLine($"出队: {result}");
                }
            }).Start();
        }

        Thread.Sleep(1000);
    }
}
```

**关键方法**：
- `Enqueue(T item)`：入队
- `TryDequeue(out T result)`：尝试出队（不会抛异常）
- `TryPeek(out T result)`：偷看队首元素
- `Count`：当前数量（非实时，仅估算）

---

### `ConcurrentStack<T>` —— 线程安全栈

**特点**：push 和 pop 都安全，无锁算法。

**适用场景**：递归遍历、撤销操作栈。

```csharp
static ConcurrentStack<int> _stack = new ConcurrentStack<int>();

static void Main()
{
    // 入栈
    Parallel.For(0, 10, i => { // Parallel.For 是多线程循环
        _stack.Push(i);
        Console.WriteLine($"压栈: {i}");
    });

    Thread.Sleep(100);

    // 出栈
    int item;
    while (_stack.TryPop(out item))
    {
        Console.WriteLine($"弹栈: {item}");
        Thread.Sleep(100);
    }
}
```

**关键方法**：
- `Push(T item)`：压栈
- `TryPop(out T result)`：弹栈
- `TryPeek(out T result)`：看栈顶

---

### `ConcurrentBag<T>` —— 线程安全"大杂袋"

**特点**：**无序集合**，允许重复。每个线程有自己的本地列表，性能最高。

**适用场景**：不关心顺序，只需要装东西（如对象池、临时结果收集）。

```csharp
static void Main()
{
    var bag = new ConcurrentBag<int>();

    // 1. 并行添加数据
    Parallel.For(0, 100, i => {
        bag.Add(i);
    });

    // 2. 尝试获取数据
    if (bag.TryTake(out int result))
    {
        Console.WriteLine($"取出了一个元素: {result}");
    }

    // 3. 查看但不移除
    if (bag.TryPeek(out int peekResult))
    {
        Console.WriteLine($"当前看一眼元素: {peekResult}");
    }

    // 4. 统计数量
    Console.WriteLine($"总数: {bag.Count}");
}
```

**关键方法**：
- `Add(T item)`：添加
- `TryTake(out T result)`：取出
- `TryPeek(out T result)`：查看

**注意**：`ConcurrentBag` **不保证顺序**，但性能最高，因为线程操作本地存储，无争用。

---

### `ConcurrentDictionary<TKey, TValue>` —— 线程安全字典

**特点**：最复杂的并发集合，支持多线程读写，内部分段锁（锁细化到桶级别）。

**适用场景**：缓存、并发计算结果汇总。

```csharp
class Program
{
    // 定义一个并发字典：Key是名字，Value是点击次数
    static ConcurrentDictionary<string, int> _clickStats = new ConcurrentDictionary<string, int>();

    static void Main()
    {
        Thread[] threads = new Thread[10];

        for (int i = 0; i < 10; i++)
        {
            threads[i] = new Thread(DoWork);
            threads[i].Start();
        }

        // 等待所有线程完成
        foreach (var t in threads) t.Join();

        Console.WriteLine($"最终统计结果: {_clickStats["UserA"]}");
    }

    static void DoWork()
    {
        for (int i = 0; i < 1000; i++)
        {
            // 这是并发字典最强大的方法之一
            // 如果 Key 不存在，添加 1；如果存在，在原有的值基础上 +1
            _clickStats.AddOrUpdate("UserA", 1, (key, oldValue) => oldValue + 1);
        }
    }
}
```

**关键方法**：
- `TryAdd(key, value)`：添加（不存在才加）
- `TryGetValue(key, out value)`：取值
- `AddOrUpdate(key, addValue, updateFunc)`：添加或更新（原子操作）
- `GetOrAdd(key, valueFactory)`：不存在才加，返回最终值
- `TryRemove(key, out value)`：删除

**强大之处**：
```csharp
// 原子操作：不存在就加，存在就累加
_dict.AddOrUpdate("counter", 1, (k, v) => v + 1);

// 传统写法需要 lock
lock (_lock)
{
    if (!_dict.ContainsKey("counter"))
        _dict["counter"] = 1;
    else
        _dict["counter"]++;
}
```

---

### `BlockingCollection<T>` —— 高级封装（阻塞队列）

**特点**：不是真正的集合，而是**包装器**，可以包装任何 `IProducerConsumerCollection<T>`（默认是 `ConcurrentQueue`）。

**适用场景**：生产者-消费者模式完美解决方案。

```csharp
class Program
{
    static BlockingCollection<int> _buffer = new BlockingCollection<int>(boundedCapacity: 5);

    static void Producer()
    {
        for (int i = 0; i < 10; i++)
        {
            Console.WriteLine($"生产者：生产 {i}");
            _buffer.Add(i); // 如果满了，自动阻塞等待
            Thread.Sleep(300);
        }
        _buffer.CompleteAdding(); // 告诉消费者，我完工了
    }

    static void Consumer()
    {
        foreach (int item in _buffer.GetConsumingEnumerable()) // 自动等待新数据
        {
            Console.WriteLine($"消费者：消费 {item}");
            Thread.Sleep(500);
        }
    }

    static void Main()
    {
        var producer = new Thread(Producer);
        var consumer = new Thread(Consumer);

        producer.Start();
        consumer.Start();

        producer.Join();
        consumer.Join();
    }
}
```

**关键特性**：
- `Add(item)`：添加，满了自动阻塞
- `TryAdd(item, timeout)`：带超时添加
- `Take()`：取出，空了自动阻塞
- `TryTake(out item, timeout)`：带超时取出
- `CompleteAdding()`：标记为完成
- `GetConsumingEnumerable()`：完美遍历，自动等待新数据

## 四、并发集合 vs 手动 lock 性能对比
这是一个非常经典的对决。简单来说：**`lock` 是“全村一把锁”，并发集合是“多条流水线”。**
当线程少、竞争低时，`lock` 的开销其实很小；但当线程变多，`lock` 就会变成程序的**性能瓶颈**。
- **手动 `lock` (粗粒度锁)：** 每次操作都要锁住整个字典。线程 A 在写，线程 B、C、D 都在门口站岗，CPU 频繁切换上下文，效率低下。
- **并发集合 (细粒度锁/无锁)：** 内部把数据分片。线程 A 写第一片，线程 B 写第二片，大家互不干扰。

我们用 10 个线程，每个线程做 100 万次操作，看看两者的耗时差距。
```csharp
using System;
using System.Collections.Concurrent;
using System.Collections.Generic;
using System.Diagnostics;
using System.Threading;

class PerformanceTest
{
    static int OperationsPerThread = 1000000;
    static int ThreadCount = 10;

    static void Main()
    {
        Console.WriteLine($"测试开始：{ThreadCount} 线程，每线程 {OperationsPerThread} 次操作\n");

        // --- 1. 使用 Dictionary + lock ---
        var dict = new Dictionary<int, int>();
        var lockObj = new object();
        RunTest("手动 lock (Dictionary)", () => {
            for (int i = 0; i < OperationsPerThread; i++)
            {
                lock (lockObj)
                {
                    dict[i % 1000] = i; // 模拟写入
                }
            }
        });

        // --- 2. 使用 ConcurrentDictionary ---
        var concurrentDict = new ConcurrentDictionary<int, int>();
        RunTest("并发集合 (ConcurrentDictionary)", () => {
            for (int i = 0; i < OperationsPerThread; i++)
            {
                concurrentDict[i % 1000] = i; // 内部自动处理锁
            }
        });
    }

    static void RunTest(string label, Action action)
    {
        Stopwatch sw = Stopwatch.StartNew();
        Thread[] threads = new Thread[ThreadCount];

        for (int i = 0; i < ThreadCount; i++)
        {
            threads[i] = new Thread(() => action());
            threads[i].Start();
        }

        foreach (var t in threads) t.Join();
        sw.Stop();

        Console.WriteLine($"{label} 耗时: {sw.ElapsedMilliseconds} ms");
    }
}
```

- **优先使用并发集合：** 它能帮你规避 90% 的多线程低级错误（比如忘了加锁，或者死锁）。
- **别在循环里写 `lock`：** 如果你发现一个 `for` 循环里包着一个巨大的 `lock`，那这个程序基本就退化成单线程了。这时候请务必考虑 `ConcurrentBag` 或 `ConcurrentDictionary`。

## 五、选择指南：用哪个？

| 需求              | 推荐集合                   | 原因                   |
| --------------- | ---------------------- | -------------------- |
| **任务队列，先进先出**   | `ConcurrentQueue`      | 最符合直觉                |
| **后进先出栈**       | `ConcurrentStack`      | 撤销/递归场景              |
| **只要装东西，不关心顺序** | `ConcurrentBag`        | 性能最高                 |
| **键值对缓存**       | `ConcurrentDictionary` | 分段锁，并发读写快            |
| **生产者-消费者（阻塞）** | `BlockingCollection`   | 自动阻塞，代码最简洁           |
| **需要排序**        | ❌ 没有线程安全的有序集合          | 需自己 lock + SortedSet |

并发集合之所以快，是因为它们用了 **“分片锁”** 或 **“无锁指令（CAS）”**。

- 在 `ConcurrentDictionary` 中，数据被分散在不同的桶（Buckets）里。修改 A 桶不需要知道 B 桶的情况。
- 但 **“有序”是一个全局属性**。

**如果你要保持有序：** 当你插入一个新元素时，为了保证它出现在正确的位置，你可能需要调整整个数据结构（比如红黑树的旋转或跳表的层级调整）。这种“牵一发而动全身”的操作很难进行局部加锁。为了保证绝对有序，往往需要锁住**整棵树**，这会让并发性能直接退化到单线程水平。

## 六、新手陷阱

### **陷阱1：以为并发集合的复合操作是原子的**
```csharp
// ConcurrentDictionary 的 TryAdd 是原子的
_dict.TryAdd("key", 1); // ✅ 安全

// 但下面的逻辑不是原子的
if (!_dict.ContainsKey("key")) // ① 检查
{                              // ② 可能被其他线程插入
    _dict.TryAdd("key", 1);    // ③ 再添加，可能失败
} // 这三步整体不原子！

// 正确做法：用原子方法
_dict.GetOrAdd("key", 1); // 一步到位
```

### **陷阱2：滥用 BlockingCollection 的阻塞**
```csharp
BlockingCollection<int> buffer = new BlockingCollection<int>();

// 生产者
buffer.Add(item); // 如果一直没人消费，会一直阻塞，导致内存泄漏

// 解决：设 boundedCapacity
var buffer = new BlockingCollection<int>(boundedCapacity: 1000);
```

### **陷阱3：遍历并发集合时集合被修改**
```csharp
// ConcurrentDictionary 遍历时可以被修改，遍历结果可能不一致
foreach (var kvp in _dict) // 允许，但可能漏掉新元素或看到旧元素
{
    // 不要在这里删除元素，可能抛异常
}
```

### **陷阱4：以为 Count 是实时的**
```csharp
if (_queue.Count > 0) // Count 是估算值，瞬间可能变
{
    _queue.TryDequeue(out var item); // 可能失败（Count 减了）
}
```

**正确做法**：
```csharp
// 直接用 TryDequeue，别先 Count 判断
if (_queue.TryDequeue(out var item))
{
    // 成功拿到才处理
}
```

---

## 七、最佳实践

1. **能并发集合就别 lock**：代码简洁，性能更高
2. **优先用 BlockingCollection**：它封装了等待逻辑，最省心
3. **注意复合操作**：检查-操作序列要用原子方法
4. **别用 Count 做判断**：用 `Try*` 方法的返回值
5. **BlockingCollection 必须 CompleteAdding**：否则消费者可能永远阻塞

---

## 八、总结

并发集合是 .NET 给多线程开发者的**大福利**，让你从繁琐的 `lock` 中解放出来。

**记住**：
- **Queue/Stack/Bag/Dictionary**：无锁或细粒度锁，性能高
- **BlockingCollection**：阻塞队列，生产者-消费者首选
- **别自己造轮子**：官方已经优化到极致，手写 lock 很难超越

用好并发集合，代码量少一半，bug 少一半，性能翻一番。
