# 接口

接口（Interface）是 C# 中实现多态性和解耦的最强大工具。如果说抽象类（Abstract Class）是一个半成品，那么接口就是一份**纯粹的契约（Contract）**。它定义了类型“能够做什么”，而完全不涉及“如何去做”。

## 核心概念与本质

在传统的 C# 设计中（C# 8.0 之前），接口可以被看作是一个**纯抽象类**。它只包含成员的声明，不包含任何实现逻辑。

*   **命名规范**：在 .NET 生态中，接口的名称始终以大写字母 **`I`** 开头（例如 `IVehicle`, `IDisposable`, `IEnumerable`）。
*   **契约精神**：当一个类声明实现某个接口时，它就在向编译器和调用方郑重承诺：“我一定会提供这个接口中定义的所有属性、方法、事件的完整实现。”
*   **解耦的威力**：调用方只需要针对接口进行编程，完全不需要知道底层是哪个具体的类在执行代码。这是依赖注入（DI）和控制反转（IoC）的理论基础。

## 接口的核心语法与严格约束

定义和实现接口时，需要遵循 C# 编译器设定的一系列严格规则：

1.  **成员隐式公开与抽象**：接口内部的方法、属性声明不需要（在旧版 C# 中也是不允许）书写 `public` 和 `abstract` 访问修饰符。它们**默认且只能是公开的和抽象的**。
2.  **绝对禁止状态（字段）**：接口中**绝对不能包含字段（Fields）**，无论是普通字段还是静态字段。接口只能定义行为，不能持有数据状态。
3.  **禁止构造函数**：因为接口不能被实例化，也没有字段需要初始化，所以接口不能包含构造函数。
4.  **无 `override` 关键字**：类在实现接口方法时，不需要也不能使用 `override` 关键字（这与继承抽象类不同）。实现的方法必须被标记为 `public`。
5.  **多重继承机制**：C# 严禁类的多重继承，但**允许一个类同时实现任意多个接口**。同时，接口也可以继承自其他接口（接口继承）。

## 深度对比：抽象类 vs 接口 

这是架构设计时最常面临的选择，也是极高频的面试题。

| 对比维度            | 抽象类 (Abstract Class)                    | 接口 (Interface)                        |
| :-------------- | :-------------------------------------- | :------------------------------------ |
| **继承关系**        | 单继承（一个类只能有一个基类）。                        | 多实现（一个类可以实现多个接口）。                     |
| **状态 (Fields)** | 可以包含实例字段和静态字段，维护核心状态。                   | **严格禁止**包含任何字段。                       |
| **构造函数**        | 可以有构造函数（供子类通过 `base()` 调用）。             | 不能有构造函数。                              |
| **访问修饰符**       | 可以有 `public`, `protected`, `private` 等。 | 成员默认全局公开 (`public`)。                  |
| **设计语义**        | **"Is-A" (是一个)** 关系。定义同一类事物的核心血脉。       | **"Can-Do" (能做某事)** 关系。定义跨越不同物种的通用能力。 |

## 代码实战：将抽象类重构为接口

以下代码展示了如何将一个基于抽象类的系统重构为基于接口的系统。注意字段的下放和属性的具体实现。

```csharp
using System;

// 1. 定义纯粹的契约 (接口)
public interface IEmployee
{
    // 接口中的属性（本质上是抽象的 get/set 方法声明）
    int EmployeeId { get; set; }
    string EmployeeName { get; set; }
    string Location { get; set; }

    // 接口中的方法声明（没有大括号方法体）
    double GetInsuranceAmount();
}

// 2. 子类实现接口
// 语法：类名 : 接口名
public class Manager : IEmployee
{
    // 子类必须自己维护状态（字段）
    private int _employeeId;
    
    // 实现接口属性
    public int EmployeeId 
    { 
        get { return _employeeId; }
        set 
        { 
            // 子类可以自由加入自己的业务校验规则
            if(value >= 1000 && value <= 2000)
                _employeeId = value; 
        }
    }

    // 使用自动属性快速实现接口属性
    public string EmployeeName { get; set; }
    public string Location { get; set; }

    // 实现接口方法 (必须是 public，不需要 override)
    public double GetInsuranceAmount()
    {
        return 1000.00; // Manager 的特定实现
    }
}

public class Salesman : IEmployee
{
    public int EmployeeId { get; set; }
    public string EmployeeName { get; set; }
    public string Location { get; set; }

    public double GetInsuranceAmount()
    {
        return 500.00; // Salesman 的特定实现
    }
}

public class Program
{
    public static void Main()
    {
        // 多态性：使用接口作为引用类型变量
        // 调用方根本不在乎实际的对象是 Manager 还是 Salesman
        // 只要它实现了 IEmployee，就一定有 GetInsuranceAmount 方法
        IEmployee emp1 = new Manager();
        IEmployee emp2 = new Salesman();

        Console.WriteLine($"Manager Insurance: {emp1.GetInsuranceAmount()}");
        Console.WriteLine($"Salesman Insurance: {emp2.GetInsuranceAmount()}");
    }
}
```

## 架构级思考与底层演进 (扩展阅读)

### 什么时候用接口？什么时候用抽象类？
(参考《Effective C#》)
*   **首选接口**：在现代 C# 开发中，设计模式强烈推荐 **“面向接口编程”** 。接口提供了最大的灵活性。当你需要定义一组行为，并且这些行为可能被毫无关系的类（比如 `Car` 和 `Person` 都实现了 `IMovable`）所实现时，必须使用接口。
*   **慎用/结合使用抽象类**：如果你发现多个子类中存在大量**完全重复的模板代码和共享状态**，应当使用抽象类来消除重复。在大型框架中，常见的最佳实践是**混合使用**：定义一个接口（如 `IList`），然后提供一个实现了该接口的基础抽象类（如 `CollectionBase`），子类既可以选择继承抽象类以复用代码，也可以选择直接实现接口以保持极端的灵活性。

### CLR 底层视角
在公共语言运行时（CLR）中，由于类可以实现多个接口，因此不能像单继承那样只维护一张简单的虚方法表（vtable）。当一个类实现了接口时，CLR 会为该接口在类型的内存结构中生成一张**附加的接口分发映射表（Interface Dispatch Map）**。这意味着通过接口调用方法，在底层需要进行两次指针寻址，其性能开销会**极微弱地**略高于直接调用类的虚方法，但在 99.9% 的业务开发中，这种纳秒级的性能损耗是完全可以忽略不计的。

## 接口默认方法

在 C# 8.0 之前，接口（Interface）的规则非常死板：**所有成员必须是公开的（public），且绝对不能有实现代码。**

但从 **C# 8.0** 开始，微软引入了两个颠覆性的特性：**接口默认方法（Default Interface Methods）** 和 **接口访问修饰符**。这两个特性让 C# 的接口变得非常像其他语言（如 Rust、Scala）中的 Traits（特征）。

我们把这两个特性拆开来深度剖析。

### 什么是默认方法？
现在，你可以在接口中直接为方法写 `{ ... }` 具体实现代码了。

```csharp
public interface ILogger
{
    // 传统的抽象方法，实现类必须实现它
    void Log(string message);

    // C# 8.0 新增：默认方法 (自带实现)
    void LogError(Exception ex)
    {
        // 接口中可以直接写业务逻辑！
        Log($"[ERROR] 发生异常: {ex.Message}");
    }
}
```

### 为什么需要默认方法？（核心痛点：版本兼容）
假设你写了一个开源库，里面有一个 `ILogger` 接口，全世界有 1 万个开发者写了类实现了你的 `ILogger`。
现在，你想在 `ILogger` 里加一个 `LogError` 方法。
*   **在 C# 8.0 之前**：一旦你在接口里加了新方法，那 1 万个开发者的代码**全部编译报错**，因为他们没有实现这个新方法。这叫“破坏性变更”。
*   **在 C# 8.0 之后**：你给新方法加上**默认实现**。那么，老代码完全不需要修改，完美兼容！

### 最大陷阱：必须显式转换才能调用
这是无数新手踩坑的地方。默认方法**不会被实现类继承到它的公开 API 中**！

```csharp
public class ConsoleLogger : ILogger
{
    // 只需实现没有默认代码的方法
    public void Log(string message) => Console.WriteLine(message);
}

// ---- 调用测试 ----
var logger = new ConsoleLogger();
logger.Log("Hello"); // ✅ 正常

// ❌ 编译报错！ConsoleLogger 并没有包含 LogError 方法
logger.LogError(new Exception("崩溃了")); 

// ✅ 正确做法：必须把对象当作接口类型来调用
ILogger iLogger = logger;
iLogger.LogError(new Exception("崩溃了")); 
```
**原理**：C# 团队故意这样设计，是为了防止“菱形继承问题”（一个类实现了两个接口，两个接口都有同名的默认方法，如果直接附加在类上，编译器不知道该调用哪一个。强制转为特定接口后，调用归属就清晰了）。

当然，实现类也可以**重写（Override）** 这个默认方法，这时候就不需要强转了：
```csharp
public class AdvancedLogger : ILogger
{
    public void Log(string message) => Console.WriteLine(message);

    // 重写接口的默认行为
    public void LogError(Exception ex) => Console.WriteLine("自定义的错误处理");
}
```

## 接口方法访问修饰符

既然接口可以写具体代码了，那这就引出了一个新问题：如果我写了一个很复杂的默认方法，我想把它拆分成几个小方法，但我**不想让这些小方法暴露给外部**怎么办？

因此，C# 8.0 打破了“接口里所有东西都是 public”的规矩，现在你可以使用 `private`、`protected`、`internal` 甚至 `static` 了。

### private 方法（最常用）
用于辅助默认方法，封装内部逻辑。

```csharp
public interface IFileHandler
{
    void ProcessFile(string path);

    // 默认方法
    void ProcessFiles(IEnumerable<string> paths)
    {
        foreach (var path in paths)
        {
            if (IsValid(path)) // 调用私有方法
            {
                ProcessFile(path);
            }
        }
    }

    // 接口中的私有方法！外部不可见，实现类也看不到
    private bool IsValid(string path)
    {
        return !string.IsNullOrEmpty(path) && path.EndsWith(".txt");
    }
}
```

### static 静态成员
接口现在可以包含静态方法和静态属性。这极其适合做**工厂方法**或定义**常量**。

```csharp
public interface IDatabase
{
    void Connect();

    // 接口中的静态工厂方法
    public static IDatabase CreateDefault()
    {
        return new SqlDatabase(); // SqlDatabase 是实现该接口的类
    }
    
    // 接口中的常量 (本质是 static)
    protected static string DefaultConnectionString = "Server=myServer...";
}

// 调用极其优雅：
IDatabase db = IDatabase.CreateDefault();
```

### protected 修饰符（注意它的特殊性）
接口里的 `protected` 方法，**只能被继承该接口的“子接口”调用，不能被“实现类”调用！**
（这和抽象类的 protected 概念不同）。

```csharp
public interface IBase
{
    protected void Helper() { }
}

public interface IDerived : IBase
{
    void Test()
    {
        Helper(); // ✅ 子接口可以调用
    }
}

public class MyClass : IBase
{
    public void DoSomething()
    {
        // ❌ 编译报错！实现类不能调用接口的 protected 方法
        Helper(); 
    }
}
```
