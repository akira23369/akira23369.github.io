# 基于接口的动态多态性

多态（Polymorphism）源自希腊语，意为“多种形态”。在面向对象编程中，多态是指**同一条语句在不同的上下文环境（或针对不同的对象实例）中，能够表现出不同行为的能力。** 多态赋予了软件系统极高的灵活性和可扩展性。

## 多态的两大核心分类：编译时 vs 运行时

在 C# 语言体系中，根据“决定调用哪个具体方法”的决策时机，多态被严格划分为两类：

| 特性       | 编译时多态                         | 运行时多态               |
| :------- | :---------------------------- | :------------------ |
| **别名**   | 静态多态 / 早期绑定                   | 动态多态 / 晚期绑定         |
| **典型实现** | **方法重载**                      | **方法重写 / 接口实现 **    |
| **决策者**  | **C# 编译器 (Compiler)**         | **公共语言运行时 (CLR)**   |
| **决策依据** | 根据调用时传递的**参数签名**（数量、类型、顺序）决定。 | 根据内存中**实际对象的类型**决定。 |
| **发生时机** | 代码编译成 IL（中间语言）的阶段。            | 程序真正运行、对象被实例化的阶段。   |

## 动态多态性的实现核心：引用类型与对象类型的解耦

实现动态多态性的绝对前提是：**变量的声明类型（抽象基类或接口）与其在内存中指向的实际对象类型（具体子类）分离。**

*   **引用变量（Reference Variable）**：决定了你**能调用哪些方法**（由接口或基类定义的契约）。
*   **实际对象（Actual Object）**：决定了这些方法**具体如何执行**（由子类提供的具体逻辑）。

无论是使用抽象类（Abstract Class）还是接口（Interface），其底层逻辑是完全一致的。现代 C# 架构设计中，基于接口的多态性应用最为广泛。


## 代码实战：基于抽象类的多态调用

```cs
using System;

// 1. 定义抽象类：不能被实例化
public abstract class Shape
{
    // 抽象属性：子类必须实现
    public abstract string Name { get; }

    // 抽象方法：只有声明，没有实现
    public abstract double CalculateArea();

    // 普通方法：子类可以直接继承使用
    public void Display()
    {
        Console.WriteLine($"图形: {Name}, 面积: {CalculateArea():F2}");
    }
}

// 2. 派生类：圆
public class Circle : Shape
{
    public double Radius { get; set; }
    public override string Name => "圆形";

    public Circle(double radius) => Radius = radius;

    // 重写抽象方法
    public override double CalculateArea() => Math.PI * Math.Pow(Radius, 2);
}

// 3. 派生类：矩形
public class Rectangle : Shape
{
    public double Width { get; set; }
    public double Height { get; set; }
    public override string Name => "矩形";

    public Rectangle(double width, double height)
    {
        Width = width;
        Height = height;
    }

    public override double CalculateArea() => Width * Height;
}

// 4. 多态调用
class Program
{
    static void Main()
    {
        // 关键点：父类引用指向子类对象
        Shape[] shapes = {
            new Circle(5),
            new Rectangle(4, 6)
        };

        foreach (var shape in shapes)
        {
            // 多态调用：在运行时根据对象实际类型决定调用哪个 CalculateArea
            shape.Display();
        }
    }
}
```
- **编译时**：程序只知道它是一个 `Shape`。
- **运行时**：程序发现它实际上是一个 `Circle` 或 `Rectangle`，从而调用对应的逻辑。


## 代码实战：基于接口的多态调用

以下代码展示了同一条调用语句 `emp.GetHealthInsuranceAmount()` 如何根据对象的不同，在运行时展现出截然不同的行为。

```csharp
using System;

// 1. 定义契约：所有员工必须具备计算健康保险的能力
public interface IEmployee
{
    double GetHealthInsuranceAmount();
}

// 2. 具体实现 A：经理的保险算法
public class Manager : IEmployee
{
    public double GetHealthInsuranceAmount()
    {
        // 复杂的内部逻辑...
        return 1000.00;
    }
}

// 3. 具体实现 B：销售员的保险算法
public class Salesman : IEmployee
{
    public double GetHealthInsuranceAmount()
    {
        // 复杂的内部逻辑...
        return 500.00;
    }
}

public class Program
{
    public static void Main()
    {
        // 声明一个接口类型的引用变量
        IEmployee emp;

        // 场景 1：指向 Manager 对象
        emp = new Manager();
        // 运行时决议：CLR 发现 emp 指向的是 Manager，调用 Manager 的实现
        Console.WriteLine($"Manager Insurance: {emp.GetHealthInsuranceAmount()}"); // 输出 1000

        // 场景 2：重新赋值，指向 Salesman 对象
        emp = new Salesman();
        // 运行时决议：同样的语句，但 CLR 发现对象变了，调用 Salesman 的实现
        Console.WriteLine($"Salesman Insurance: {emp.GetHealthInsuranceAmount()}"); // 输出 500
    }
}
```

**核心观察点**：
代码 `emp.GetHealthInsuranceAmount();` 在外观上没有任何改变，但它却能智能地“随机应变”。这就是动态多态的魅力所在。

## 深度拓展：CLR 是如何实现动态多态的？

在 C# 编译器将代码编译为 IL（中间语言）时，遇到 `emp.GetHealthInsuranceAmount()`，编译器并不知道这里最终会执行哪段代码，它只会生成一条 `callvirt`（调用虚方法/接口方法）的指令。

当程序运行到这一行时，CLR（公共语言运行时）会执行以下底层操作（晚期绑定过程）：
1.  检查 `emp` 变量当前指向的内存地址。
2.  读取该内存地址处对象的**对象头（Object Header）**。
3.  通过对象头找到该对象的**类型句柄（Type Handle）**，进而找到该类型对应的**接口分发映射表（Interface Dispatch Map）** 或 **虚方法表（VTable）**。
4.  在表中查找 `GetHealthInsuranceAmount` 方法对应的真实内存地址，并跳转执行。

这一过程虽然比直接调用普通方法多了一次指针查找，但现代 CPU 的缓存机制和 CLR 的高度优化，使得这种开销微乎其微。

## 架构设计与企业级应用

在真实的企业级项目中，动态多态性是构建可维护、松耦合系统的前提：

### 策略模式
上述的保险计算例子，本质上就是 GoF 设计模式中的**策略模式**。不同的类封装了不同的算法策略（经理策略、销售策略），而客户端程序只需要依赖统一的接口（`IEmployee`），可以在运行时自由切换策略。

### 依赖注入
在现代 ASP.NET Core 框架中，我们几乎总是针对接口进行编程。
*   **开发阶段**：张三负责写 `IDatabase` 接口和消费该接口的代码；李四负责写具体的 `SqlDatabase` 实现类；王五写测试用的 `MockDatabase` 实现类。三人完全并行开发。
*   **运行阶段**：通过 IoC 容器（控制反转容器），在程序启动时将具体的实例注入到接口变量中。业务逻辑代码根本不需要出现 `new SqlDatabase()` 这样的紧耦合代码。这使得系统极具弹性和可测试性。
