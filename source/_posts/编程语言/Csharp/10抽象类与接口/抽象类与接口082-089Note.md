# 第 11 节：抽象类与接口

## 第一讲：抽象

### 引言

抽象是面向对象编程的四大支柱之一。其核心原则是隐藏复杂的实现细节，仅暴露必要的高级功能。它让我们能够通过创建系统的简化模型来管理复杂性。其目标是将对象做什么与如何做分离开来。

一个完美的现实类比是驾驶汽车。要让汽车加速，你只需踩下油门踏板。你是在与一个简单、抽象的接口（踏板）进行交互。你不需要了解引擎盖下发生的复杂机械原理 —— 燃油喷射、火花塞点火、活塞运动、变速箱换挡。所有这些复杂性都被抽象掉了，使你无需成为专业机械师就能有效驾驶汽车。

在 C# 中，抽象不仅是一个概念，更是我们用来设计灵活且可维护软件的实际工具。实现抽象的两种主要机制是抽象类和接口。它们允许我们定义其他类必须遵循的 "契约"，确保一定程度的统一性和可预测性，而无需规定具体的实现细节。

## 第二讲：抽象类

### 引言

抽象类是一种特殊的基础类，它不完整且不能单独实例化。其目的是作为一组相关派生类的通用蓝图。它充当混合体，允许你提供一些共享的具体实现（公共方法和字段），同时定义派生类必须实现的 abstract 成员契约。

### 工作原理与规则

1. **声明**： 使用 abstract 关键字将类声明为抽象类： `public abstract class Shape { ... }`。
2. **实例化**： 你不能创建抽象类的对象。代码 `new Shape();` 会导致编译错误。抽象类仅用于被继承。
3. **内容**： 抽象类可以包含普通类的所有元素：字段、属性、构造函数以及具有完整实现的常规方法。
4. **抽象成员**： 其独特之处在于还可以包含 abstract 方法和属性，我们将在下一讲中详细介绍。
5. **继承**： 继承自抽象类的非抽象子类必须为所有继承的抽象成员提供实现。

### 为何及何时使用

当需要为一组具有 "是一个" 关系且共享公共代码的紧密相关类建模时，请使用抽象类。如果你有多个类（如 Circle、Rectangle、Triangle）都属于 Shape 类型，并且它们都共享诸如 Color 这样的公共属性或 DisplayInfo () 这样的公共方法，那么抽象类就是完美选择。它允许你在基类中只编写一次公共代码，避免重复。

### 示例
```cs
// 此类不能直接实例化。它是一个概念性的蓝图。
public abstract class Shape
{
    // 1. 可以包含带有实现的字段和属性。
    // 这是所有形状共享的通用逻辑。
    public string Color { get; set; }

    // 2. 可以有构造函数，由派生类调用。
    public Shape(string color)
    {
        this.Color = color;
        Console.WriteLine("Shape constructor called.");
    }

    // 3. 可以有常规的、具体的方法。
    public void DisplayColor()
    {
        Console.WriteLine($"The color of this shape is {Color}.");
    }

    // 4. 可以有抽象成员（契约）。
    // 此方法没有方法体，必须由派生类实现。
    public abstract double CalculateArea(); 
}
```

## 第三讲：抽象方法

### 引言

一个抽象方法是声明在抽象类中但没有实现体的方法。它仅由签名（访问修饰符、返回类型、名称和参数）后跟分号组成。

### 工作原理：契约

抽象方法建立了强制性契约。通过声明 `public abstract double CalculateArea();`，Shape 抽象类声明："任何想要被视为 Shape 的具体类必须提供自己特定的面积计算实现。我，Shape 类，无法提供通用实现，因为每种形状的计算公式都不同。"

### 规则

1. 抽象方法只能存在于 abstract class 中。
2. 使用 abstract 关键字声明，且没有花括号 {} 或方法体。
3. 任何继承自抽象类的非抽象类必须使用 override 关键字为所有继承的抽象方法提供实现。

### 示例

让我们创建继承自 Shape 并履行其契约的具体类。
```cs
public class Circle : Shape
{
    public double Radius { get; set; }

    // 调用基类构造函数初始化 'Color' 属性。
    public Circle(string color, double radius) : base(color)
    {
        this.Radius = radius;
    }

    // 我们必须为抽象方法提供实现。
    // 使用 'override' 关键字。
    public override double CalculateArea()
    {
        return Math.PI * Radius * Radius;
    }
}

public class Rectangle : Shape
{
    public double Width { get; set; }
    public double Height { get; set; }

    public Rectangle(string color, double width, double height) : base(color)
    {
        this.Width = width;
        this.Height = height;
    }

    // 为矩形的面积提供特定实现。
    public override double CalculateArea()
    {
        return Width * Height;
    }
}

// --- 在 Main 方法中 ---
Circle myCircle = new Circle("Red", 10);
Rectangle myRectangle = new Rectangle("Blue", 5, 10);

myCircle.DisplayColor(); // 调用基类 Shape 中的具体方法。
Console.WriteLine($"Circle Area: {myCircle.CalculateArea()}"); // 调用 Circle 类中重写的方法。

myRectangle.DisplayColor();
Console.WriteLine($"Rectangle Area: {myRectangle.CalculateArea()}");
```

## 第四讲：接口

### 引言

接口是一种纯粹的契约。它定义了一组相关的公共成员（方法、属性、事件或索引器），但不提供任何具体实现。实现接口的类或结构体向编译器保证，它将为该接口定义的所有成员提供公共实现。

如果说抽象类建模的是 "是一个" 的关系（例如 Circle 是一个 Shape），那么接口建模的则是 "能做" 的能力（例如 Car、Person 和 Document 都可以实现 ISerializable—— 它们都具备被序列化的能力）。

### 工作原理与规则

1. **声明方式**： 使用 interface 关键字。按照惯例，接口名称以大写字母 I 开头，例如 ILogger 或 IDisposable。
2. **内容**： 接口定义中的成员没有主体且没有访问修饰符。它们都隐式地为 public。
3. **实现**： 类使用冒号 (:) 语法实现接口，就像继承一样。然后，类必须为接口中定义的每个成员提供公共实现。

### 使用场景

当您想要定义可以在不相关的类之间共享的通用能力时，请使用接口。例如，您可能有 Car、Bird 和 Drone 类。它们没有逻辑上的 "is-a" 关系，因此不应该共享一个共同的基类。然而，它们都有移动的能力，因此它们都可以实现 IMovable 接口。

### 示例

让我们为任何可以保存的东西定义一个契约。

```cs
// 接口定义了"做什么"（契约），而不是"怎么做"。
public interface ISaveable
{
    void Save(); // 没有方法体，没有访问修饰符。
}

// 第一个实现该契约的类。
public class Document : ISaveable
{
    public string Text { get; set; }
    
    // 必须提供 Save 方法的公共实现。
    public void Save()
    {
        Console.WriteLine("Saving document to a .txt file...");
    }
}

// 另一个完全不相关但也实现该契约的类。
public class PlayerProgress : ISaveable
{
    public int Level { get; set; }

    // 提供自己特定的 Save 实现。
    public void Save()
    {
        Console.WriteLine("Saving player progress to the cloud...");
    }
}
```

## 第五讲：使用接口实现动态多态

### 引言

接口最强大的特性之一是能够在完全不相关的类之间实现多态。多态让我们可以编写以统一方式处理不同类对象的代码，只要这些类都实现了相同的接口。这意味着你可以创建更灵活、解耦且易于维护的系统。

### 工作原理

1. 你可以创建接口类型的变量、方法参数或集合（如 List）（例如 `List<ISaveable>`）。这些可以持有任何实现了该接口的类对象的引用。
2. 当你通过接口引用调用方法时（例如 `item.Save()`），.NET 运行时会执行动态查找。它会检查对象当前的实际类型，并执行该对象类提供的具体方法实现。

### 使用场景

当需要对一组不同对象执行常见操作时，请使用此模式。例如，您可能希望一次性保存应用程序各个部分的状态（用户进度、正在编辑的文档、应用程序设置）。只要这些类都实现了 ISaveable 接口，您就可以用相同的代码处理它们。

### 示例

让我们使用上一讲中的 ISaveable 接口以及 Document 和 PlayerProgress 类。我们将创建一个能保存任何实现该契约对象的统一方法。

```cs
public interface ISaveable
{
    void Save();
}

public class Document : ISaveable
{
    public void Save()
    {
        Console.WriteLine("Saving document to a .txt file...");
    }
}

public class PlayerProgress : ISaveable
{
    public void Save()
    {
        Console.WriteLine("Saving player progress to the cloud...");
    }
}

public class ProgressManager
{
    // 此方法适用于任何实现了 ISaveable 的对象。
    // 它与具体的 Document 和 PlayerProgress 类解耦。
    public void SaveAll(List<ISaveable> itemsToSave)
    {
        Console.WriteLine("\n--- Starting Save All Operation ---");
        foreach (ISaveable item in itemsToSave)
        {
            // 在运行时，C# 会根据 'item' 的实际对象类型
            // 调用正确的 Save() 方法。
            item.Save();
        }
        Console.WriteLine("--- Save All Operation Complete ---");
    }
}

// --- 在 Main 方法中 ---
Document myDoc = new Document();
PlayerProgress myProgress = new PlayerProgress();

// 创建接口类型的列表。
List<ISaveable> saveableItems = new List<ISaveable>();

// 可以将不同类型的对象添加到同一个列表中。
saveableItems.Add(myDoc);
saveableItems.Add(myProgress);

ProgressManager manager = new ProgressManager();
manager.SaveAll(saveableItems);
```

输出：
```cs
--- Starting Save All Operation ---
Saving document to a .txt file...
Saving player progress to the cloud...
--- Save All Operation Complete ---
```

## 第六讲：使用接口实现多重继承

### 引言

正如我们在继承章节所学，C# 强制类采用单继承机制 —— 一个类只能继承自一个基类。这条规则避免了许多复杂问题。然而在很多情况下，一个对象在逻辑上确实需要具备多种不同的角色或能力。接口正是 C# 实现这种多重继承的解决方案。

### 工作原理

一个类可以实现多个接口。只需在冒号后列出这些接口，用逗号分隔即可。通过这种方式，类承诺为其实现的所有接口中的所有成员提供公共实现。

这使得类既可以从单一基类继承主要特性（"是一个" 的关系），又可以从多个接口继承多组能力（"能做" 的关系）。

### 使用场景

当某个类需要遵循多个互不相关的契约时，可采用此模式。现实中的典型例子是多功能一体机（打印 / 扫描 / 传真），虽然是一台设备，但具备多种独立功能。

### 示例

让我们为现代智能手机建模。它 "是一个" ElectronicDevice（其基本身份），但它 "能做" 电话、相机和 GPS 导航器的工作。

```cs
// --- 契约（接口）---
public interface IPhone
{
    void MakeCall(string number);
}

public interface ICamera
{
    void TakePhoto();
}

public interface IGps
{
    string GetCurrentLocation();
}

// --- 基类 ---
public class ElectronicDevice
{
    public int BatteryLevel { get; protected set; } = 100;
}

// --- 实现多个接口的具体类 ---
// 它继承自一个基类，但实现了三个接口。
public class SmartPhone : ElectronicDevice, IPhone, ICamera, IGps
{
    // 实现 IPhone 契约
    public void MakeCall(string number)
    {
        Console.WriteLine($"Calling {number}...");
        BatteryLevel -= 5;
    }

    // 实现 ICamera 契约
    public void TakePhoto()
    {
        Console.WriteLine("Taking a photo...");
        BatteryLevel -= 2;
    }

    // 实现 IGps 契约
    public string GetCurrentLocation()
    {
        Console.WriteLine("Finding current location...");
        BatteryLevel -= 3;
        return "Kuntloor, Telangana, India";
    }
}
```

## 第七讲：接口继承

### 引言

正如类可以从其他类继承一样，接口也可以从其他接口继承。这使您能够从更小、更可重用的组件构建更复杂的契约，从而创建能力的逻辑层次结构。

### 工作原理

当派生接口从基接口继承时，它会将该基接口的所有成员纳入自己的契约中。因此，任何实现派生接口的类都必须为派生接口及其所有基接口的所有成员提供实现。

### 使用场景

使用接口继承来创建分层或分级的 API 契约。可以定义一个非常基础的接口，然后创建更专门的接口来添加更多功能，让类能够选择它们想要实现的复杂度级别。

### 示例

让我们为数据访问契约建模。有些数据源可能是只读的，而其他则支持读写操作。

```cs
// 1. 基础契约：任何可读取的对象。
public interface IReadable
{
    string Read(int id);
}

// 2. 可写入对象的契约。
public interface IWriteable
{
    void Write(string data);
}

// 3. 继承自两个基接口的派生接口。
// 这创建了一个更复杂的、支持完整读写访问的契约。
public interface IReadWrite : IReadable, IWriteable
{
    // 如有需要，也可以添加自己的新成员。
    void Delete(int id);
}

// 此类只需要具备读取能力。
public class ConfigurationReader : IReadable
{
    public string Read(int id) { /* ... 逻辑 ... */ return "config_value"; }
}

// 此类需要完整的读写删除功能。
// 通过实现 IReadWrite，它必须实现所有三个方法。
public class DatabaseConnection : IReadWrite
{
    public string Read(int id) { /* ... 逻辑 ... */ return "db_record"; }
    public void Write(string data) { /* ... 逻辑 ... */ }
    public void Delete(int id) { /* ... 逻辑 ... */ }
}
```

## 第八讲：显式接口实现

### 引言

显式接口实现是一种技术，其中实现接口成员的类成员不会在类本身公开。该成员只能通过先将对象转换为特定接口类型来访问。

### 工作原理：语法

要显式实现接口成员，需在成员名前加上接口名。前缀，并且不能使用访问修饰符（如 public）。

```cs
void IMyInterface.MyMethod() { ... }
```

### 为何及何时使用

使用此技术主要有两个原因：

1. **解决命名冲突**： 这是最常见的原因。当一个类实现了两个或多个接口，而这些接口恰好声明了名称和签名完全相同的成员时，显式实现允许类为每个接口的成员提供单独的实现而不会产生冲突。
2. **隐藏接口成员**： 有时，接口成员非常特殊化，或者不属于类的核心公共 API 的一部分。可以通过显式实现将其隐藏，保持类自身 API 的简洁。该成员仍然可访问，但仅限于那些专门使用该接口的消费者。

### 示例：解决命名冲突

假设你有两个日志记录接口，它们都有 Log 方法，但预期行为却各不相同。
```cs
public interface IFileLogger
{
    void Log(string message);
}

public interface IDatabaseLogger
{
    void Log(string message);
}

public class ReportGenerator : IFileLogger, IDatabaseLogger
{
    // 显式实现 IFileLogger。
    // 注意：没有 'public' 访问修饰符。
    void IFileLogger.Log(string message)
    {
        Console.WriteLine($"Writing to file: {message}");
    }

    // 显式实现 IDatabaseLogger。
    void IDatabaseLogger.Log(string message)
    {
        Console.WriteLine($"Writing to database: {message}");
    }
}

// --- 在 Main 方法中 ---
ReportGenerator report = new ReportGenerator();

// 这会导致编译错误，因为 Log 不是类的公共成员。
// report.Log("My message"); // 错误！

// 要调用这些方法，必须先将对象转换为特定的接口类型。
IFileLogger fileLogger = report;
fileLogger.Log("File log entry."); // 输出: Writing to file: File log entry.

IDatabaseLogger dbLogger = report;
dbLogger.Log("Database log entry."); // 输出: Writing to database: Database log entry.
```


## 第九讲：重要知识点回顾

### 引言

本讲总结了关于抽象类和接口最关键、最实用且最具面试价值的内容。能否清晰阐述它们的区别，是衡量 C# 开发者专业水平的重要标准。

### 抽象类 vs 接口：核心面试题

这是 C# 面向对象编程中最常见的面试问题之一。你必须能够明确比较两者的异同。

| 维度   | 抽象类                                                         | 接口                                                                |
| ---- | ----------------------------------------------------------- | ----------------------------------------------------------------- |
| 核心目的 | 为一组密切相关的类提供共同基类。建模 "是一个" 关系（例如 Dog 是一种 Animal）。             | 定义无关类都可以实现的共同能力或契约。建模 "能做" 关系（例如 Car 和 Document 都可以实现 ISaveable）。 |
| 实现方式 | 可以包含实现细节：字段、构造函数和带有完整方法体的方法。                                | 是纯粹的契约，传统上不能包含实现。（注意：现代 C# 允许默认接口方法，但在面试场景中除非被问及新特性，否则请坚持经典定义）。   |
| 继承关系 | 一个类只能继承一个抽象类（单继承）。                                          | 一个类可以实现多个接口。                                                      |
| 成员   | 可以包含 public、protected、private 等成员。可以拥有 static 成员和 const 字段。 | 所有成员默认为 public。不能包含实例字段或实例构造函数。                                   |
### abstract 与 virtual 方法对比

这是另一个常见的混淆点。

- **abstract 方法**：没有实现，且必须由第一个非抽象的派生类重写。
- **virtual 方法**：在基类中有实现，派生类可以选择性地重写它，以提供更具体的行为。

### 接口是解耦的契约

接口的主要力量在于解耦。当你的代码依赖于接口（ILogger）而非具体类（FileLogger）时，你可以轻松更换实现（例如改用 DatabaseLogger），而无需修改使用它的代码。这使得你的应用程序更加灵活、模块化，也更易于测试。
