# 抽象类(abstract)

## 一、 核心定义
抽象类是一种不能被直接实例化的特殊基类。它的主要存在意义是作为类层次结构中的“根节点”或“中间节点”，为派生类（子类）提供公共的字段、属性、方法定义和基础实现。

在C#中，通过在类定义前添加 `abstract` 关键字来声明抽象类。

## 二、 设计哲学与应用场景
在真实世界的领域建模中，某些概念是高度泛化的，它们仅仅是具有共性特征的集合，而不具备具体的实体形态。

**经典建模场景：**
1. **交通工具 (Vehicle)：** 现实中不存在一个单纯的“交通工具”实体，存在的只有具体的“汽车(Car)”、“公交车(Bus)”。因此，`Vehicle` 适合作为抽象类。
2. **几何图形 (Shape)：** 你可以画出一个“圆形(Circle)”或“矩形(Rectangle)”，但无法画出一个纯粹的“图形”。`Shape` 应当是抽象的。
3. **企业人员 (Employee)：** 在企业系统中，“员工”往往是一个泛化的概念。实际业务中需要操作的是“经理(Manager)”、“销售(Salesman)”或“文员(Clerk)”。直接实例化 `Employee` 是没有业务意义的。

**设计准则：**
当发现直接创建一个父类的对象在逻辑上是无意义的，且该父类仅用于向下级子类提供共享代码和契约时，应毫不犹豫地将其标记为 `abstract`。

## 三、 抽象类的核心规则与特性

### 实例化限制
*   **绝对禁止直接实例化：** 尝试使用 `new` 关键字创建抽象类的对象会导致编译期错误（`CS0144: Cannot create an instance of the abstract class or interface`）。
*   **底层原理（参考《CLR via C#》）：** 在CLR（公共语言运行时）层面，标记为 `abstract` 的类在元数据中会包含特定的标志位。JIT编译器会拒绝对此类生成 `newobj` IL指令的本地代码。

### 成员组成
抽象类在成员的包容性上非常强大，它几乎可以包含普通类（Concrete Class）能包含的所有成员，并且独占一种特殊成员：
*   **普通成员：** 字段、属性、普通方法、构造函数、析构函数、事件、索引器等（包括静态和非静态）。
*   **抽象成员 (Abstract Members)：** 抽象类可以包含 `abstract` 修饰的方法、属性、事件或索引器。这些成员只有声明，没有实现，强制要求派生类必须提供具体实现。（普通类中绝对不允许出现抽象成员）。

| 类型  | 1. 非静态字段 | 2. 非静态方法 | 3. 非静态构造函数 | 4. 非静态属性 | 5. 非静态事件 | 6. 非静态析构函数 | 7. 常量 |
| :-- | :------- | :------- | :--------- | :------- | :------- | :--------- | :---- |
| 普通类 | Yes      | Yes      | Yes        | Yes      | Yes      | Yes        | Yes   |
| 抽象类 | Yes      | Yes      | Yes        | Yes      | Yes      | Yes        | Yes   |

| 类型  | 8. 静态字段 | 9. 静态方法 | 10. 静态构造函数 | 11. 静态属性 | 12. 静态事件 | 13. 虚方法 | 14. 抽象方法 | 15. 非静态自动实现属性 | 16. 非静态索引器 |
| :-- | :------ | :------ | :--------- | :------- | :------- | :------ | :------- | :------------ | :--------- |
| 普通类 | Yes     | Yes     | Yes        | Yes      | Yes      | Yes     | No       | Yes           | Yes        |
| 抽象类 | Yes     | Yes     | Yes        | Yes      | Yes      | Yes     | Yes      | Yes           | Yes        |

### 继承机制
*   抽象类可以继承自其他普通类或抽象类，也可以实现多个接口。
*   抽象类必须被其他类继承才能发挥价值。如果一个抽象类没有任何子类，那它在系统中就是无用的死代码。
*   要使用抽象类中定义的普通成员，只能通过创建其子类的对象，通过子类对象来进行访问和调用。

## 四、 深入理解：抽象类中的构造函数
虽然抽象类不能被实例化，但**抽象类可以（且通常应该）包含构造函数**。

**最佳实践（参考《Effective C#》）：**
抽象类的构造函数不应该是 `public` 的，而应该是 `protected`。
因为抽象类不能被外部直接 `new`，提供 `public` 构造函数会产生误导。`protected` 构造函数的作用是：当派生类被实例化时，派生类的构造函数可以通过 `base()` 显式或隐式地调用父类（抽象类）的构造函数，从而正确地初始化定义在抽象类中的内部状态（如公共字段或属性）。

## 五、 代码示例
以下代码展示了如何使用抽象类来重构员工模型，包含上述提到的状态初始化和多态设计。

```csharp
using System;

// 1. 定义抽象类
public abstract class Employee
{
    // 公共属性：所有员工共享的数据
    public int EmployeeId { get; set; }
    public string Name { get; set; }
    public string Location { get; set; }

    // 推荐做法：使用 protected 构造函数供子类调用
    protected Employee(int employeeId, string name, string location)
    {
        EmployeeId = employeeId;
        Name = name;
        Location = location;
    }

    // 普通方法：所有子类共享的实现
    public void DisplayBasicInfo()
    {
        Console.WriteLine($"[ID: {EmployeeId}] {Name} - Location: {Location}");
    }

    // 抽象方法：强制子类必须提供的特定实现
    public abstract void CalculateBonus();
}

// 2. 定义派生类：经理
public class Manager : Employee
{
    public decimal TeamRevenue { get; set; }

    // 调用基类构造函数初始化基础数据
    public Manager(int id, string name, string location, decimal teamRevenue) 
        : base(id, name, location)
    {
        TeamRevenue = teamRevenue;
    }

    // 必须实现抽象类的抽象方法
    public override void CalculateBonus()
    {
        decimal bonus = TeamRevenue * 0.05m;
        Console.WriteLine($"Manager {Name}'s bonus is {bonus:C}");
    }
}

// 3. 定义派生类：销售
public class Salesman : Employee
{
    public decimal IndividualSales { get; set; }

    public Salesman(int id, string name, string location, decimal sales) 
        : base(id, name, location)
    {
        IndividualSales = sales;
    }

    public override void CalculateBonus()
    {
        decimal bonus = IndividualSales * 0.10m;
        Console.WriteLine($"Salesman {Name}'s bonus is {bonus:C}");
    }
}

// 调用端测试
class Program
{
    static void Main()
    {
        // Employee emp = new Employee(1, "Alice", "NY"); // 编译错误！无法实例化抽象类

        // 正确用法：实例化具体子类，但可以使用抽象类作为引用类型（多态）
        Employee manager = new Manager(101, "Bob", "London", 500000m);
        Employee salesman = new Salesman(102, "Charlie", "Paris", 100000m);

        // 访问继承自抽象类的普通方法
        manager.DisplayBasicInfo();
        salesman.DisplayBasicInfo();

        // 触发多态行为
        manager.CalculateBonus();
        salesman.CalculateBonus();
    }
}
```

## 六、 架构层面的对比：普通类 vs 抽象类

| 特性         | 普通类 (Normal/Concrete Class)   | 抽象类 (Abstract Class)                 |
| :--------- | :---------------------------- | :----------------------------------- |
| **实例化**    | 可以使用 `new` 实例化                | **绝对不可**使用 `new` 实例化                 |
| **继承状态**   | 可作为父类（除非被 `sealed` 修饰），也可作为子类 | 主要作为父类被继承，也可继承其他类/接口                 |
| **包含抽象成员** | **不允许**包含 `abstract` 成员       | **允许**包含 `abstract` 成员               |
| **设计意图**   | 表达一个完整、可独立存在的具体事物             | 表达一个不完整、需要子类补全的抽象概念或契约               |
| **代码复用**   | 可以提供完整的代码复用                   | 兼具**代码复用**（普通方法）与**接口契约**（抽象方法）的双重特性 |
