# 密封方法

在 C# 的多层继承体系中，多态性允许方法被一层层地重写（Override）。然而，在某些复杂的架构设计中，我们可能需要在一个特定的继承层级上“锁定”某个方法的实现，禁止更下层的派生类继续重写它。这就是 **密封方法（Sealed Methods）** 的核心作用。

## 核心概念与逻辑

密封方法的作用是**终止虚方法（Virtual Method）的重写链条**。

如果把 `virtual` 关键字看作是“开启”方法重写权限的钥匙，那么 `sealed` 关键字就是“关闭”该权限的锁。
当一个子类重写了父类的虚方法，并且确信这个重写后的逻辑是“最终版本”，不允许它的任何子孙类再次修改时，就可以将该方法声明为密封方法。

## 严格的语法规则

在 C# 中，使用密封方法有一个绝对的前提条件：**`sealed` 关键字必须且只能与 `override` 关键字组合使用。**

*   **不能用于普通方法**：普通（非虚）方法默认就是不能被重写的，因此加上 `sealed` 是毫无意义且不被编译器允许的。
*   **不能直接用于 `virtual` 方法**：在定义基类时，不能同时将方法声明为 `virtual` 和 `sealed`。因为 `virtual` 的目的就是允许重写，而 `sealed` 的目的是阻止重写，这在逻辑上是自相矛盾的。

## 代码实战：切断重写链

以下代码展示了在一个三层继承体系（`Employee` -> `Manager` -> `BranchManager`）中，如何使用密封方法锁定业务逻辑。

```csharp
using System;

// 1. 祖父类：定义虚方法，开放重写权限
public class Employee
{
    public virtual void GetInsuranceAmount()
    {
        Console.WriteLine("Employee: 保险额度为 $500");
    }
}

// 2. 父类：重写虚方法，并将其密封，切断后续重写
public class Manager : Employee
{
    // 组合使用 sealed override
    public sealed override void GetInsuranceAmount()
    {
        Console.WriteLine("Manager: 保险额度为 $1500 (不可被子类篡改)");
    }
}

// 3. 子类：尝试重写已被密封的方法 —— 将导致编译失败
public class BranchManager : Manager
{
    // 编译错误 CS0239: 'BranchManager.GetInsuranceAmount()': cannot override inherited member 'Manager.GetInsuranceAmount()' because it is sealed
    /*
    public override void GetInsuranceAmount()
    {
        Console.WriteLine("BranchManager: 试图修改保险额度");
    }
    */
}

public class Program
{
    public static void Main()
    {
        BranchManager branchManager = new BranchManager();
        // 只能继承并使用 Manager 中锁定的版本
        branchManager.GetInsuranceAmount(); // 输出: Manager: 保险额度为 $1500 (不可被子类篡改)
    }
}
```

## 架构设计与底层机制剖析

在企业级框架设计中，密封方法具有极其重要的安全性与性能价值。

### 保护类的内部不变量
根据《Effective C#》的建议，当你在派生类（如 `Manager`）中重写了一个基类方法，并且你的类中其他代码的正确执行**严重依赖**于这个重写后的逻辑时，就应该将其密封。
如果不将其密封，下一级子类（如 `BranchManager`）可能会覆盖掉你精心编写的状态维护逻辑，从而导致不可预知的系统 Bug（即“脆弱的基类问题”在多层继承中的蔓延）。

### JIT 编译器的性能优化(去虚拟化)
根据《CLR via C#》对公共语言运行时（CLR）的深入解析，虚方法的调用在底层需要通过查找对象的“虚方法表（vtable）”来实现，这比直接调用普通方法要慢。

当你将一个重写方法标记为 `sealed` 时，你实际上是在向 JIT（即时编译器）传达一个明确的信号：**这个方法绝对不会再有其他实现了**。
基于这个信号，如果 JIT 编译器看到一个变量的类型是 `Manager` 或其派生类，它就可以安全地将这个虚方法的调用进行**去虚拟化（Devirtualization）**。JIT 会直接生成调用该内存地址的机器码，甚至进行**方法内联（Method Inlining）**，从而彻底消除虚方法表查找带来的运行时性能损耗。
