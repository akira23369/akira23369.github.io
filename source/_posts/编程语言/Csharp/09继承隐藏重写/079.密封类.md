# 密封类(Sealed Class)

在面向对象设计中，继承虽然强大，但并非所有类都适合被继承。C# 提供了 `sealed`（密封）关键字，用于在类层次结构中设置“终止点”，明确禁止其他类继承该类。

## 核心概念与语法

**密封类（Sealed Class）** 是一种不能作为基类（父类）使用的类。如果尝试创建一个继承自密封类的子类，C# 编译器将直接报错。

*   **语法**：在类定义时加上 `sealed` 修饰符。
*   **设计意图**：主要用于安全性和架构设计的严谨性。当一个类的内部实现已经非常完整且固定，或者从业务逻辑上它不应该有任何派生类型时，就应当将其声明为密封类。

## 核心特性与成员约束

密封类在绝大多数方面与普通的类（普通类在 C# 中通常被称为非密封的实体类）表现一致，但存在特定的约束：

1.  **继承能力的单向性**：密封类**可以**继承其他普通类或抽象类，也**可以**实现多个接口；但它**绝对不能**被其他类继承。
2.  **可实例化**：密封类可以像普通类一样，通过 `new` 关键字创建对象实例。
3.  **禁止虚方法 (`virtual`) 和抽象方法 (`abstract`)**：
    由于密封类不能有子类，因此在密封类中定义 `virtual` 或 `abstract` 方法在逻辑上是毫无意义的（没有子类去重写它们）。编译器会禁止在密封类中声明这类方法。


## 普通类vs抽象类vs密封类 成员支持情况

| ------- | ------------ | ------------ | -------------- | ------------ | ------------ | -------------- | --------- |

### 第二部分：静态成员与特殊方法
| **类型**  | **8. 静态字段** | **9. 静态方法** | **10. 静态构造函数** | **11. 静态属性** | **12. 静态事件** | **13. 虚方法 (Virtual)** | **14. 抽象方法 (Abstract)** | **15. 非静态自动属性** | **16. 非静态索引器** |
| ------- | ----------- | ----------- | -------------- | ------------ | ------------ | --------------------- | ----------------------- | --------------- | -------------- |

| **密封类** | 是           | 是           | 是              | 是            | 是            | **否**                 | **否**                   | 是               | 是              |



### 核心要点总结：

1. **抽象方法 (Abstract Methods)**：只有**抽象类**可以拥有。普通类和密封类都不允许定义没有实现体的抽象方法。
    
2. **虚方法 (Virtual Methods)**：**密封类**不能有虚方法。因为虚方法的目的是为了让子类重写（Override），而密封类禁止被继承，所以虚方法在密封类中没有意义。
    
3. **构造函数**：虽然抽象类不能被 `new` 实例化，但它**可以且通常拥有**构造函数，供子类在实例化时通过 `base()` 调用。
    
4. **静态成员**：所有类型的类（普通、抽象、密封）都可以拥有静态成员（字段、方法、属性等）。

## 代码实战：阻止继承

以下代码演示了如何定义密封类，以及尝试继承密封类时引发的编译时拦截。

```csharp
using System;

// 1. 定义一个普通的父类
public class Employee
{
    public virtual void DoWork()
    {
        Console.WriteLine("Employee is working.");
    }
}

// 2. 将 Manager 标记为密封类 (它本身可以继承 Employee)
public sealed class Manager : Employee
{
    // 可以重写父类的方法
    public override void DoWork()
    {
        Console.WriteLine("Manager is managing.");
    }

    public void ApproveLeave()
    {
        Console.WriteLine("Leave approved.");
    }
}

// 3. 尝试继承密封类 —— 将导致编译错误！
// 编译错误 CS0509: 'BranchManager': cannot derive from sealed type 'Manager'
/*
public class BranchManager : Manager
{
    // ...
}
*/

public class Program
{
    public static void Main()
    {
        // 密封类可以正常实例化和使用
        Manager mgr = new Manager();
        mgr.DoWork();
        mgr.ApproveLeave();
    }
}
```

## 进阶应用：密封重写方法

除了密封整个类，`sealed` 关键字还可以作用于**方法级别**。
在一个多层继承体系中，如果子类重写了父类的 `virtual` 方法，但希望它的下一代子类**不要再继续重写**该方法，可以使用 `sealed override` 组合关键字。

```csharp
public class Person
{
    public virtual void Speak() { Console.WriteLine("Person speaking"); }
}

public class Teacher : Person
{
    // 重写并密封该方法，切断后续子类的重写权限
    public sealed override void Speak() { Console.WriteLine("Teacher speaking"); }
}

public class PhysicsTeacher : Teacher
{
    // 编译错误：不能重写继承的成员 'Teacher.Speak()'，因为它是密封的
    // public override void Speak() { } 
}
```

## 架构考量与底层优化 (扩展阅读)

在《CLR via C#》一书中，作者 Jeffrey Richter 强烈建议：**在默认情况下，将所有不打算被继承的类都标记为 `sealed`。**

这一最佳实践主要基于以下两个维度的考量：

### 性能优化
JIT（即时编译器）在处理密封类时可以进行深度的性能优化。因为 JIT 编译器确切地知道不可能存在任何继承自密封类的派生类，因此当调用密封类上的方法时，JIT 可以将原本的**虚方法调用（Virtual Call）** 优化为**非虚方法调用（Non-Virtual Call）**，甚至直接进行**方法内联（Method Inlining）**。这避免了运行时查找虚方法表的开销，显著提升了代码的执行效率。

### 避免“脆弱的基类”问题
《Effective C#》指出，设计一个优秀的、可被继承的基类是非常困难的（需要仔细规划受保护的成员、虚函数的挂钩点等）。如果一个类原本就没有针对继承进行专门设计和测试，允许他人随意继承可能会破坏类内部的状态封装。将其声明为 `sealed` 是一种防御性编程，明确向调用方传达：“这个类是作为最终消费品提供的，请通过组合（Composition）而不是继承来使用它。”

> **补充机制**：在 C# 中，所有的值类型（如 `struct` 和 `enum`）在底层（CLR 层级）都是隐式密封（`sealed`）的。这也解释了为什么我们永远无法继承一个结构体（Struct）。
