# 继承

继承是面向对象编程（OOP）的核心支柱之一，其核心目标是**代码复用**和**建立类与类之间的层级关系**。通过继承，可以将多个类中共享的特征（字段、属性、方法）提取到一个公共的基类中，从而实现代码的逻辑分离和模块化。

## 核心概念：Is-a 关系

继承在逻辑上表达的是一种 **"Is-a"（是一个）** 的关系。如果可以说“A 是 一种 B”，那么 A 就应该继承自 B。
*   **示例**：老虎（Tiger）是一种动物（Animal）。这里 `Animal` 是父类（Parent Class / Base Class），`Tiger` 是子类（Child Class / Derived Class）。
*   **示例**：经理（Manager）是一名员工（Employee）。`Employee` 是父类，`Manager` 是子类。

## 父类与子类的权限边界
*   **子类扩展父类**：子类不仅隐式拥有父类的所有成员（字段、属性、方法），还可以定义自己独有的成员。
*   **单向访问性**：子类可以访问父类中的非私有成员；但父类对子类的存在一无所知，**父类绝不能访问子类的任何成员**。

> **补充（参考《Effective C#》与《CLR via C#》）**：
> C# 仅支持**单继承**（Single Inheritance），即一个类只能有一个直接的父类。这与 C++ 的多重继承不同。C# 通过允许实现多个接口（Interface）来弥补单继承的局限性，同时避免了多重继承带来的“菱形问题”（致命的复杂性）。此外，C# 中所有的类最终都隐式继承自 `System.Object`。

## 内存模型与对象实例化

理解继承背后的内存分配对于掌握 C# 非常重要（**参考《CLR via C#》**）：

当创建一个子类的对象时，CLR（公共语言运行时）会在托管堆中为该对象分配内存。这块内存不仅包含子类自身定义的字段，还**完整包含了父类（以及所有更上层祖先类）定义的所有字段**。

*   假设父类 `Employee` 定义了 3 个字段。
*   子类 `Manager` 定义了 2 个独有的字段。
*   当实例化 `new Manager()` 时，内存中实际分配了 **5 个字段**的空间。
*   **注意**：即使父类中的某些字段是 `private`（私有的），它们依然会被分配在子类对象的内存中，只不过子类的代码无法直接访问它们，必须通过父类提供的 `public` 或 `protected` 属性/方法来间接操作。

## 代码实战：员工管理系统模型

以下代码演示了如何在一个实际的业务场景中应用继承。我们将公共属性（ID、姓名、位置）放在基类中，将特有属性和方法放在派生类中。

```csharp
using System;

// 1. 定义父类 (Base Class)
public class Employee
{
    // 公共属性，所有子类都将继承
    public int EmployeeId { get; set; }
    public string EmployeeName { get; set; }
    public string Location { get; set; }

    public void PrintBasicInfo()
    {
        Console.WriteLine($"ID: {EmployeeId}, Name: {EmployeeName}, Location: {Location}");
    }
}

// 2. 定义子类：Manager 继承自 Employee
// 语法：子类 : 父类
public class Manager : Employee
{
    // Manager 独有的属性
    public string Department { get; set; }

    // Manager 独有的方法
    public double GetTotalSalesOfTheYear()
    {
        // 实际项目中这里可能包含复杂的业务逻辑
        return 100000.50; 
    }
}

// 3. 定义子类：Salesman 继承自 Employee
public class Salesman : Employee
{
    // Salesman 独有的属性
    public string Region { get; set; }

    // Salesman 独有的方法
    public double GetSalesOfCurrentMonth()
    {
        return 5000.75;
    }
}

// 4. 客户端调用测试
public class Program
{
    public static void Main()
    {
        // 实例化父类
        Employee emp = new Employee();
        emp.EmployeeId = 101;
        emp.EmployeeName = "John Doe";
        emp.Location = "New York";
        // emp 只能访问 Employee 中的成员

        // 实例化子类 Manager
        Manager mgr = new Manager();
        // 继承自父类的属性
        mgr.EmployeeId = 201;
        mgr.EmployeeName = "Alice Smith";
        mgr.Location = "London";
        // 子类自有的属性和方法
        mgr.Department = "IT";
        double mgrSales = mgr.GetTotalSalesOfTheYear();

        // 实例化子类 Salesman
        Salesman sales = new Salesman();
        // 继承自父类的属性
        sales.EmployeeId = 301;
        sales.EmployeeName = "Bob Johnson";
        sales.Location = "Tokyo";
        // 子类自有的属性和方法
        sales.Region = "APAC";
        double currentSales = sales.GetSalesOfCurrentMonth();
        
        // 输出测试
        mgr.PrintBasicInfo();
        Console.WriteLine($"Manager Dept: {mgr.Department}, Yearly Sales: {mgrSales}");
    }
}
```

## 架构设计与项目结构

在实际的 C# 企业级开发中，通常会将不同的职责分离到不同的项目中：
1.  **类库项目 (Class Library - `.dll`)**：用于存放业务实体模型（如上面的 `Employee`, `Manager`, `Salesman`）。
2.  **控制台/Web 应用程序项目 (Console/Web App - `.exe` 或 Web Host)**：作为程序的启动入口。

为了在应用程序中使用类库中定义的继承体系，必须在主程序中**添加对类库的引用 (Add Reference)**。在 Visual Studio 中完成引用后，编译器才能解析外部程序集中的基类和派生类。

## 进阶与最佳实践探讨 (扩展阅读)

在掌握了基本的继承关系后，接下来的设计中需要考虑以下几个 C# 进阶特性（后续重点）：

*   **`protected` 访问修饰符**：如果不希望父类的成员暴露给外部类（`public`），但又允许子类访问，应该使用 `protected`。这是为继承专门设计的访问级别。
*   **`base` 关键字**：当子类和父类有重名成员，或者子类需要在自己的构造函数中调用父类的构造函数时，需要使用 `base` 关键字来显式指代父类。
*   **多态性 (Polymorphism) 与 `virtual` / `override`**：继承最大的威力在于多态。父类可以将方法标记为 `virtual`（虚方法），允许子类使用 `override` 进行重写，从而实现“同一个调用，不同的行为”。
*   **组合优于继承 (Composition over Inheritance)**：参考《代码大全》和《Effective C#》，虽然继承能复用代码，但它会造成类之间的**强耦合**。如果两个类之间不是严格的 "Is-a" 关系，而只是想借用一部分代码，应当优先考虑组合（"Has-a" 关系，即将一个类的实例作为另一个类的字段），而不是滥用继承。
