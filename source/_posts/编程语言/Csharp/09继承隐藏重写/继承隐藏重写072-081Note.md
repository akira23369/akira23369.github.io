# 第10节：继承

## 第一讲：继承简介

### 引言

继承是面向对象编程（OOP）的基本支柱之一，它允许我们创建一个新类（称为派生类或子类），该类可以获取现有类（称为基类或父类）的属性和行为。这种机制模拟了一种层次化的 "是一个" 关系。例如，Manager "是一个" Employee，Car "是一个" Vehicle，而 Dog "是一个" Animal。

继承的主要目的和好处在于代码复用。我们无需在多个相似的类中重复编写相同的逻辑和数据字段，而是可以将所有共享功能集中到一个基类中。派生类会自动继承这些功能，并可以添加自己独特的特性或修改继承的行为。这有助于构建更加组织有序、易于维护且逻辑清晰的代码结构。

### 实现原理：语法与成员访问

在 C# 中，通过在类声明中使用冒号(:)来建立继承关系。

语法：

```cs
public class BaseClass  
{  
    // ... 成员 ...  
}  
​  
public class DerivedClass : BaseClass  
{  
    // ... 额外成员 ...  
}
```


当 DerivedClass 继承自 BaseClass 时，它会自动获得对 BaseClass 所有 public 和 protected 成员的访问权限。关键要记住，基类的 private 成员不会被继承；它们对派生类保持完全隐藏和不可访问状态，从而保持了基类的封装性。

### 示例

让我们建立一个简单的层级模型。公司里所有员工都有姓名和 ID。而经理是一种特殊类型的员工，还拥有团队规模属性。


```cs
// 包含通用字段和方法的基类。  
public class Employee  
{  
    public string Name { get; set; }  
    public int EmployeeId { get; set; }  
​  
    public void Work()  
    {  
        Console.WriteLine($"{Name} is working.");  
    }  
}  
​  
// 派生类继承自 Employee。  
// 经理 "是一个" 员工。  
public class Manager : Employee  
{  
    // 仅属于 Manager 类的专属属性。  
    public int TeamSize { get; set; }  
}  
​  
// --- 在 Main 方法中 ---  
Manager manager = new Manager();  
​  
// 访问从 Employee 类继承的成员。  
manager.Name = "Jane Doe";  
manager.EmployeeId = 101;  
manager.Work(); // 此方法定义在 Employee 类中。  
​  
// 访问 Manager 类的专属成员。  
manager.TeamSize = 12;  
Console.WriteLine($"{manager.Name} manages a team of {manager.TeamSize}.");
```


## 第二讲：继承的类型

### 引言

虽然继承是一个广泛的概念，但 C# 对其实现方式有特定的规则。了解这些支持（和不支持）的类型对于设计正确的类层次结构至关重要。

### C#中支持的继承类型

#### 单继承

**定义**： 一个类只能直接继承自一个其他类。这是 C# 中的严格规则。

**原因**： 这条规则的存在是为了防止 "菱形继承问题"——在允许多重继承的语言中可能出现的情况。如果 ClassD 同时继承自 ClassB 和 ClassC，而 B 和 C 又都继承自拥有 DoWork() 方法的公共基类 ClassA，那么 ClassD 应该继承哪个版本的 DoWork()？C# 的单继承模型完全避免了这种歧义。

#### 多级继承

**定义**： 一个类可以派生自另一个类，而后者本身又派生自其他类，从而形成继承链。

**示例**：
```cs
public class Animal { }  
public class Mammal : Animal { }  
public class Dog : Mammal { } // Dog 继承自 Mammal 和 Animal。
```


#### 层次继承

**概念说明**： 多个类继承自同一个基类。这是一种非常常见的结构。

**示例**：
```cs
public class Vehicle { }  
public class Car : Vehicle { }  
public class Motorcycle : Vehicle { }  
public class Bus : Vehicle { }
```


### C#中不支持继承的类型

#### 多重继承（针对类）

**概念说明**： 单个类能够直接从多个基类继承的特性。

**C# 状态**： 如前所述，C# 不支持类的多重继承。

**替代方案**： 在 C# 中，这一功能通过接口实现。一个类只能继承一个基类，但可以实现多个接口。

### 面试视角

**问题**："C#支持多重继承吗？"

**理想答案**："不支持，C#为避免菱形继承等问题，强制采用单一继承模型。但通过实现多个接口，可以达到类似多重继承的效果。"

## 第三讲：base 关键字

### 引言

base 关键字是一种特殊引用，仅在派生类中可用，它允许你访问其直接基类（父类）的成员。这是你"向上"访问继承链的方式，用于使用父类中可能被隐藏或需要在子类中增强的功能。

### 为何及何时使用

1. 调用基类中已被派生类隐藏或重写的方法
    
2. 从派生类的构造函数中调用基类的特定构造函数（将在下一讲中讨论）
    

### 示例：调用基类方法

假设有一个基类 Report 和一个更具体的 FinancialReport 类。两者都有 Print() 方法。财务报告需要先打印标准标题，然后再打印其特定内容。

```cs
public class Report  
{  
    public string Title { get; set; }  
​  
    public virtual void Print() // 标记为 virtual 以便可能被重写  
    {  
        Console.WriteLine("--- Report Header ---");  
        Console.WriteLine($"Title: {Title}");  
        Console.WriteLine("---------------------");  
    }  
}  
​  
public class FinancialReport : Report  
{  
    public decimal Revenue { get; set; }  
​  
    public override void Print() // 重写基类方法  
    {  
        // 1. 使用 'base' 先调用 Report 类中的 Print() 方法。  
        base.Print();  
​  
        // 2. 然后，添加派生类的特定功能。  
        Console.WriteLine($"Revenue: {Revenue:C}");  
        Console.WriteLine("--- End of Financials ---");  
    }  
}  
​  
// --- 在 Main 方法中 ---  
FinancialReport report = new FinancialReport();  
report.Title = "Q2 Financials";  
report.Revenue = 500000;  
report.Print();


输出如下
--- Report Header ---  
Title: Q2 Financials  
---------------------  
Revenue: $500,000.00  
--- End of Financials ---
```


## 第四讲：父类的构造函数

### 引言

当创建派生类对象时，.NET 运行时会确保整个对象的状态（包括从基类继承的部分）被正确初始化。这意味着基类的构造函数总是先于派生类的构造函数执行。

### 工作原理：构造函数链

当你编写 new DerivedClass() 时，运行时会先查看 DerivedClass 的构造函数。

1. 在执行 DerivedClass 构造函数体之前，它会先调用 BaseClass 的某个构造函数。
    
2. 默认情况下，它会尝试调用基类的公共无参数构造函数。
    
3. 基类构造函数完成后，派生类构造函数的函数体将被执行。
    

### 使用 : base(...) 语法

如果基类没有无参构造函数怎么办？或者如果您需要调用基类的特定参数化构造函数来传递必要数据呢？

在这种情况下，您必须在派生类的构造函数定义中使用 : base(...) 语法。这会明确告知编译器要调用哪个基类构造函数以及向其传递哪些参数。

### 示例

让我们在创建 Employee 类时要求提供姓名和 ID。

```cs
public class Employee  
{  
    public string Name { get; private set; }  
    public int EmployeeId { get; private set; }  
​  
    // 基类只有一个参数化构造函数。  
    public Employee(string name, int employeeId)  
    {  
        Console.WriteLine("Base Employee constructor called.");  
        this.Name = name;  
        this.EmployeeId = employeeId;  
    }  
}  
​  
public class Manager : Employee  
{  
    public int TeamSize { get; set; }  
​  
    // Manager 构造函数现在必须调用 Employee 构造函数。  
    // 我们使用 ': base(...)' 语法将值传递到继承链中。  
    public Manager(string name, int employeeId, int teamSize) : base(name, employeeId)  
    {  
        Console.WriteLine("Derived Manager constructor called.");  
        // 基类构造函数已经设置了姓名和ID。  
        // 我们只需要设置此类的专属字段。  
        this.TeamSize = teamSize;  
    }  
}  
​  
// --- 在 Main 方法中 ---  
Manager manager = new Manager("Jane Doe", 101, 12);

输出如下​  
Base Employee constructor called.  
Derived Manager constructor called.
```


注意执行顺序。基类构造函数会首先运行。

### 面试视角

**问题**："如果基类只有私有构造函数会怎样？"

**理想答案**："如果一个类只有私有构造函数，它将无法被继承。派生类无法调用基类构造函数（这是必需操作），因此会导致编译时错误。"

## 第五讲：方法隐藏

### 引言

方法隐藏，也称为遮蔽(shadowing)，当派生类定义了与基类中名称和签名完全相同的方法，但没有使用 override 关键字时发生。通过这种方式，派生类的方法会隐藏基类的方法。这不是改变基类行为的方式，而是提供了一个全新的、独立的方法，只是恰巧共享了相同的名称。

### 工作原理：new 关键字与编译时解析

虽然并非强制要求，但你应该始终在派生类方法上使用 new 关键字，以明确告知编译器你打算隐藏基类方法。这样可以消除编译器警告，并使你的意图更加清晰。

理解方法隐藏最核心的概念在于：被调用的方法版本是在编译时根据引用变量的类型决定的，而非该变量中存储对象的实际类型。

### 示例

让我们看看引用类型如何决定调用结果。

```cs
public class Animal  
{  
    public void PrintInfo()  
    {  
        Console.WriteLine("This is an Animal.");  
    }  
}  
  
public class Dog : Animal  
{  
    // 'new' 显式隐藏基类的 PrintInfo() 方法。  
    public new void PrintInfo()  
    {  
        Console.WriteLine("This is a Dog.");  
    }  
}  
  
// --- 在 Main 方法中 ---  
// 1. 创建一个 Dog 对象并使用 Dog 类型引用持有它。  
Dog dogReference = new Dog();  
// 编译器看到引用类型是 'Dog'，因此将调用绑定到 Dog.PrintInfo()。  
dogReference.PrintInfo(); // 输出: This is a Dog.  
  
Console.WriteLine("--------------------");  
  
// 2. 创建一个 Dog 对象但使用 Animal 类型引用持有它。  
Animal animalReference = new Dog();   
// 编译器看到引用类型是 'Animal'。即使对象是 Dog 类型，  
// 编译器仍将调用绑定到 Animal.PrintInfo()。  
animalReference.PrintInfo(); // 输出: This is an Animal.
```


### 面试视角

**问题**：“C#中的方法隐藏是什么？”

**理想答案**：“方法隐藏是指派生类使用 new 关键字定义与基类方法签名相同的方法。这会创建一个独立于基类方法的新方法。其关键特性在于方法调用是在编译时根据引用变量的类型解析的，而非对象的运行时类型。”

## 第六讲：方法重写

### 引言

方法重写是实现运行时多态性的基础技术。它允许派生类为基类中已定义的方法提供新的特定实现。与隐藏（创建新方法）不同，重写是在继承层次结构中为现有基类方法提供替代实现。

### 工作原理：virtual 与 override 的契约

方法重写需要在基类和派生类之间通过两个关键关键字建立契约：

- **virtual（基类中）**： 基类中的方法必须标记为 virtual 关键字（或 abstract，或本身是 override）。这表示："我知道派生类可能会想提供此方法的自定义版本。"
    
- **override（派生类中）**： 派生类中的方法必须标记为 override 关键字，且必须与基类中虚方法具有完全相同的签名。这表示："我有意替换基类虚方法的实现。"
    

### 运行时多态

这是与方法隐藏的关键区别。通过重写，被调用的方法版本是在运行时根据堆上存储对象的实际类型决定的，而不管指向它的引用变量类型是什么。

### 示例：经典多态场景

```cs
public class Animal  
{  
    // 将此方法标记为 'virtual' 以便可以被重写。  
    public virtual void MakeSound()  
    {  
        Console.WriteLine("The animal makes a generic sound.");  
    }  
}  
  
public class Dog : Animal  
{  
    // 使用 'override' 为 Dog 提供特定实现。  
    public override void MakeSound()  
    {  
        Console.WriteLine("Woof!");  
    }  
}  
  
public class Cat : Animal  
{  
    // 使用 'override' 为 Cat 提供特定实现。  
    public override void MakeSound()  
    {  
        Console.WriteLine("Meow!");  
    }  
}  
  
// --- 在 Main 方法中 ---  
// 创建一个持有 'Animal' 类型引用的列表。  
List<Animal> pets = new List<Animal>();  
  
// 可以添加 Dog 和 Cat 对象，因为它们 "是" Animal 类型。  
pets.Add(new Dog());  
pets.Add(new Cat());  
pets.Add(new Animal());  
  
// 遍历列表并对每个对象调用相同的方法。  
foreach (Animal pet in pets)  
{  
    // 在运行时，CLR 检查 'pet' 指向的对象的实际类型，  
    // 并调用相应的重写方法。这就是多态性。  
    pet.MakeSound();  
}


输出如下
Woof!  
Meow!  
The animal makes a generic sound.
```


## 第七讲：密封类

### 引言

sealed 关键字是一个修饰符，当应用于类时，会阻止任何其他类继承它。这实际上在该点终止了继承链，将该类标记为最终类，并非为进一步扩展而设计。

### 工作原理

这是一个简单的编译时限制。如果你尝试从标记为 sealed 的类派生，C# 编译器将会生成错误。

```cs
// 'sealed' 关键字防止被继承。  
public sealed class FinalConfiguration  
{  
    // ... 成员 ...  
}  
  
// 以下代码行会导致编译错误：  
// 'MyConfig': cannot derive from sealed type 'FinalConfiguration'  
public class MyConfig : FinalConfiguration // 错误！  
{  
    // ...  
}
```


### 为何及何时使用

1. **设计意图**： 明确传达一个类是"完整的"且不设计用于扩展。这可以防止误用那些本不应作为父类的类。.NET 框架中最著名的例子是 System.String 类，它被声明为密封类。
    
2. **安全性**： 保护包含安全敏感逻辑的类。通过密封类，可以防止其他开发人员从中派生并重写其行为，从而绕过安全检查。
    
3. **性能**： 可能带来轻微的性能优势。当即时(JIT)编译器遇到对密封类实例的方法调用时，它知道该方法永远不会被重写版本替代。这使得编译器可以进行去虚拟化等优化，从而执行更直接、更快的方法调用。
    

## 第8讲：需要记住的重要要点

### 引言

本讲座总结了 C#继承中最关键、最实用且值得面试关注的知识点。

### 继承建模"is a"的关系

这是核心概念模型。当一个类确实是另一个类的更具体版本时，才使用继承。不要在不自然适合的地方强行建立继承关系。

### C#支持类的单继承

一个类只能有一个直接基类。这是避免歧义的基本规则。通过实现多个接口可以实现行为的多重继承。

### 基类构造函数总是优先执行

当你实例化一个派生类时，基类构造函数总是先于派生类构造函数执行。使用 : base(...) 语法可以显式控制调用哪个基类构造函数，并将必要数据沿继承链向上传递。

### 方法隐藏 vs 方法重写：核心面试问题

这是 C#面向对象编程面试中最重要的主题之一。你必须能够清晰地阐述两者区别。

**关键词**：

- **隐藏**： 在派生方法上使用 new 关键字（可选，但这是最佳实践）。基类方法不需要任何特殊关键字。
    
- **重写**： 需要在基类方法上使用 virtual（或 abstract）关键字，并在派生方法上使用 override 关键字。
    

**方法解析（关键区别）**：

- **隐藏**： 要调用的方法在编译时根据引用变量的类型确定。
    
- **重写**： 要调用的方法在运行时根据堆中存储对象的实际类型确定。这是运行时多态。
    

**目的**：

- **隐藏**： 你在派生类中引入了一个全新的独立方法，恰巧与基类方法同名。它不会替代基类方法，只是将其隐藏。
    
- **重写**： 你为现有的基类方法提供了替代实现，遵循由 virtual 关键字确立的多态契约。
    

### sealed 提供终结性

使用 sealed 关键字可显式阻止类被继承。这能传达设计意图，提升安全性，并可能带来轻微的性能优化。
