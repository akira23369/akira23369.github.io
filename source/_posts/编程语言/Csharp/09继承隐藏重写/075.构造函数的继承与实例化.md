# 构造函数的继承与实例化机制

在面向对象编程中，类的构造函数（Constructor）负责在对象实例化时初始化其内部状态（字段和属性）。当引入继承关系后，子类不仅包含自身的字段，还完整包含了父类的字段。因此，如何正确地协同调用父类与子类的构造函数，是确保对象状态一致性的关键。

## 核心职责：谁的数据谁负责

根据面向对象设计的**单一职责原则（Single Responsibility Principle）**，每个类应当只负责初始化属于自己的那部分数据：
*   **父类构造函数**：专注于初始化父类定义的字段。
*   **子类构造函数**：专注于初始化子类自身新增的字段。

**最佳实践（参考《代码大全》）**：绝对不要在子类的构造函数中直接去初始化父类的字段（即使这些字段是 `protected` 或是 `public` 的）。正确的做法是通过向父类构造函数传递参数，让父类自行完成初始化。

## 隐式调用与显式调用

### 隐式调用无参构造函数
如果父类包含一个**无参构造函数**（或者没有显式定义任何构造函数，编译器自动生成了无参构造函数），那么在实例化子类时，C# 编译器会自动在子类构造函数背后插入对父类无参构造函数的调用。

```csharp
public class Parent {
    public Parent() { Console.WriteLine("Parent initialized."); }
}
public class Child : Parent {
    // 编译器实际上隐式执行了：public Child() : base() { ... }
    public Child() { Console.WriteLine("Child initialized."); }
}
```

### 显式调用带参构造函数
如果父类**只有带参数的构造函数**，那么子类在定义构造函数时，**必须**使用 `: base(...)` 语法显式地调用父类的构造函数，并将必要的参数传递过去。否则，编译器将报错，因为它不知道该如何初始化父类的那部分内存。

## 构造函数的执行顺序

理解对象实例化时的底层执行顺序是非常重要的。根据《CLR via C#》中关于对象实例化的解析，当执行 `new Child(...)` 时，发生的步骤如下：

1.  **内存分配**：CLR 在托管堆中为该对象（包含父类和子类所有字段）分配内存，并将所有字段初始化为默认值（如 0、null）。
2.  **调用子类构造函数**：执行流进入子类构造函数，接收传递进来的参数。
3.  **向上链式调用**：**在执行子类构造函数体之前**，通过 `: base(...)` 语法，执行流立即跳转到父类的构造函数。
4.  **父类构造函数执行**：如果父类之上还有祖先类，会继续向上跳转，直到 `System.Object` 的构造函数。然后，**自顶向下**依次执行各个构造函数的代码体。
5.  **子类构造函数执行**：父类构造函数体执行完毕后，控制权交还给子类，最后执行子类构造函数的代码体。

**简而言之：参数自下而上传递，构造逻辑自顶向下（从父到子）执行。**

## 代码实战：带有继承体系的构造函数设计

以下代码展示了如何在实际项目中实现带参构造函数的链式调用，彻底分离父子类的初始化逻辑。

```csharp
using System;

// 1. 父类
public class Employee
{
    // 属性仅提供 get 访问器，强制必须通过构造函数初始化（不可变性设计）
    public int EmployeeId { get; }
    public string EmployeeName { get; }
    public string Location { get; }

    // 父类带参构造函数
    public Employee(int empId, string empName, string location)
    {
        // 这里的 this 关键字代表当前实例（即使实际创建的是子类实例）
        this.EmployeeId = empId;
        this.EmployeeName = empName;
        this.Location = location;
        Console.WriteLine("Employee (Parent) Constructor Executed.");
    }
}

// 2. 子类：Manager
public class Manager : Employee
{
    public string Department { get; }

    // 子类构造函数：接收父子两端所需的所有参数
    // 通过 : base(...) 将 empId, empName, location 向上透传给父类
    public Manager(int empId, string empName, string location, string department) 
        : base(empId, empName, location)
    {
        // 子类仅负责初始化自身的字段
        this.Department = department;
        Console.WriteLine("Manager (Child) Constructor Executed.");
    }
}

// 3. 子类：Salesman
public class Salesman : Employee
{
    public string Region { get; }

    public Salesman(int empId, string empName, string location, string region) 
        : base(empId, empName, location)
    {
        this.Region = region;
        Console.WriteLine("Salesman (Child) Constructor Executed.");
    }
}

// 4. 客户端调用
public class Program
{
    public static void Main()
    {
        Console.WriteLine("--- 实例化 Manager ---");
        // 传入 4 个参数，触发自下而上再自顶向下的初始化流程
        Manager mgr = new Manager(101, "Alice", "New York", "Finance");
        
        Console.WriteLine("\n--- 实例化 Salesman ---");
        Salesman sales = new Salesman(102, "Bob", "London", "EMEA");
    }
}
```

**上述程序的输出结果将是：**
```text
--- 实例化 Manager ---
Employee (Parent) Constructor Executed.
Manager (Child) Constructor Executed.

--- 实例化 Salesman ---
Employee (Parent) Constructor Executed.
Salesman (Child) Constructor Executed.
```

## 进阶探讨与最佳实践 (扩展阅读)

*   **只读属性与不可变类型 (Immutable Types)**：正如《Effective C#》所推荐，利用带参构造函数进行初始化，可以配合 `readonly` 字段或只包含 `get` 访问器的自动属性，从而创建不可变的类型。不可变类型在多线程环境下是绝对安全的，且极大地降低了状态管理的复杂性。
*   **字段初始化器与构造函数的执行时机**：C# 允许在声明字段时直接赋初值（如 `public string Region { get; } = "Unknown";`）。根据 CLR 规范，这些“字段初始化器”实际上会被编译器提取并插入到**本类构造函数代码体执行之前**。其实际完整执行顺序为：子类字段初始化器 -> 父类字段初始化器 -> 父类构造函数体 -> 子类构造函数体。在进行复杂的架构设计时，了解这一微观顺序有助于排查空引用异常（NullReferenceException）。
