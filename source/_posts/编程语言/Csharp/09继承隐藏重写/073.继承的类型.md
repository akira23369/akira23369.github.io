# 继承的类型

在面向对象设计中，类与类之间的继承关系可以表现出多种不同的形态。理解这些拓扑结构有助于在架构设计时做出合理的抽象。C# 语言体系中讨论的继承主要分为五种模式，但在底层实现规则上，C# 做出了一些非常严格的设计限制。

## 单一继承

单一继承是最基础、最常见的继承关系：**一个父类，一个子类**。子类直接扩展父类的功能。

*   **模型**：`A -> B`
*   **代码示例**：
    ```csharp
    public class Person 
    {
        public string Name { get; set; }
    }

    // Teacher 直接继承自 Person
    public class Teacher : Person 
    {
        public string Subject { get; set; }
    }
    ```

## 多层继承

多层继承是指类的派生关系超过两层，形成一个垂直的继承链：**祖父类 -> 父类 -> 子类**。在这个链条中，位于中间的类既是上一层的子类，又是下一层的父类。

*   **特征**：底层的子类会继承其上方所有直系祖先类的所有非私有成员。
*   **代码示例**：
    ```csharp
    public class Person { }
    
    public class Teacher : Person { }
    
    // Professor 继承自 Teacher，间接继承自 Person
    public class Professor : Teacher { }
    ```
> **架构考量（参考《代码大全》）**：虽然 C# 支持极深的多层继承，但继承层次过深（通常超过 3-4 层）会大幅增加代码的认知负荷，导致“脆弱的基类问题”。修改顶层基类可能会对底层的派生类产生意想不到的破坏。

## 层次继承

层次继承是指**一个父类派生出多个不同的子类**。这是在业务系统中对共有特征进行抽象的最典型应用场景。

*   **模型**：`A -> B` 且 `A -> C`
*   **代码示例**：
    ```csharp
    public class Person { }

    // Teacher 和 Physician 共享 Person 的特征，但各自具有不同的行为
    public class Teacher : Person { }
    public class Physician : Person { }
    ```

## 多重继承与 C# 的设计哲学

多重继承是指**一个子类同时拥有多个直接父类**。

*   **C# 的严格限制**：**C# 明确禁止类的多重继承**。
    如果尝试编写如下代码，编译器会报错（`Class cannot have multiple base classes`）：
    ```csharp
    // 编译错误示范！
    public class Teacher { }
    public class Physician { }
    public class MedicalTeacher : Teacher, Physician { } 
    ```

### 为什么 C# 禁止类的多重继承？（深入 CLR 机制）
根据《CLR via C#》的解释，禁止多重继承是为了避免 **“菱形问题”（Diamond Problem）**。如果允许类多重继承，当两个父类包含同名的方法或甚至相同的状态（字段）时，子类在调用该方法或在内存分配时会产生不可调和的歧义。这会极大增加公共语言运行时（CLR）的复杂性。

### C# 的解决方案：接口多重实现
虽然 C# 不允许继承多个类的**状态（字段/内存布局）**，但允许实现多个接口的**行为（方法契约）**。这是 C# 实现多重继承概念的标准方式。

*   **代码示例**：
    ```csharp
    public interface ITeacher 
    { 
        void Teach(); 
    }
    
    public interface IPhysician 
    { 
        void Heal(); 
    }

    // 一个类只能继承一个基类，但可以实现任意多个接口
    public class MedicalTeacher : Person, ITeacher, IPhysician
    {
        public void Teach() { Console.WriteLine("Teaching anatomy."); }
        public void Heal() { Console.WriteLine("Healing patients."); }
    }
    ```
> **补充（参考《Effective C#》）**：在系统设计时，应当优先使用接口（Interface）来定义跨越不同类层次结构的共同能力，而不是试图用一个庞大的基类去包含所有功能。

## 混合继承

混合继承并不是一种全新的独立结构，而是**上述两种或两种以上继承类型的组合**。在一个实际的企业级应用中，类的关系往往是混合继承。

*   **组合方式**：通常是 层次继承 + 多层继承 的结合体。
*   **代码示例**：
    ```csharp
    public class Person { }

    // 层次继承部分：Tailor 和 Professor 都继承自 Person
    public class Tailor : Person { }
    public class Professor : Person { }

    // 多层继承部分：MedicalProfessor 继承自 Professor，而 Professor 继承自 Person
    public class MedicalProfessor : Professor { }
    ```
    在这个模型中，以 `Person` 为顶点，同时展现了横向的并列展开（层次继承）和纵向的深入（多层继承），形成了一个复杂的树状结构。

---

### 核心总结
*   **单根性原则**：在 C# 中，所有的继承链无论多么复杂，顺着父类层层往上找，最终必定汇聚于唯一的一个顶级基类 —— `System.Object`。
*   在面临复杂的对象建模时：**复用状态（字段）用类继承，复用行为（方法契约）用接口。**
