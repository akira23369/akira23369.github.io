# 方法隐藏

在面向对象编程中，子类不仅可以继承父类的方法，还可以定义自己的方法。当子类定义了一个与父类**名称相同且参数签名相同**的方法时，就会发生“方法隐藏”（Method Hiding），也常被称为“遮蔽”（Shadowing）。

## 核心概念：什么是方法隐藏？

如果父类中有一个普通方法（非 `virtual` 虚方法），而子类由于业务需求，不想使用父类的实现，且没有权限或不打算修改父类代码时，子类可以“重新声明”一个同名同参的方法。

*   **结果**：在子类的视图中，父类的该方法被隐藏了。
*   **非破坏性**：父类的方法并没有被删除或覆盖。它依然存在于子类对象的内存布局中，只是被子类的新方法“挡住”了。

### 显式声明：`new` 关键字
当在子类中编写与父类同名的方法时，C# 编译器会发出警告（CS0108），提示子类成员隐藏了继承的成员。为了消除警告并向编译器（以及其他开发者）明确表达“我是故意隐藏父类方法的”，必须在子类方法签名前加上 **`new`** 关键字。

## 代码实战与多态性对比

理解方法隐藏最关键的一点是：**方法的调用取决于“引用变量的声明类型”，而不是“对象的实际运行时类型”。**

```csharp
using System;

// 父类
public class Employee
{
    // 父类的普通方法
    public void GetHealthInsuranceAmount()
    {
        Console.WriteLine("Employee Insurance: $500");
    }
}

// 子类 1：隐藏父类方法
public class Manager : Employee
{
    // 使用 new 关键字显式隐藏父类的同名方法
    public new void GetHealthInsuranceAmount()
    {
        Console.WriteLine("Manager Insurance: $1000");
    }
}

// 子类 2：不隐藏父类方法
public class Salesman : Employee
{
    // 默认直接继承父类的方法
}

public class Program
{
    public static void Main()
    {
        // 场景 1：使用子类引用指向子类对象
        Manager mgr = new Manager();
        mgr.GetHealthInsuranceAmount(); // 输出: Manager Insurance: $1000

        // 场景 2：使用父类引用指向子类对象 (核心区别)
        Employee baseRef = new Manager();
        baseRef.GetHealthInsuranceAmount(); // 输出: Employee Insurance: $500

        // 场景 3：未进行方法隐藏的子类
        Salesman sales = new Salesman();
        sales.GetHealthInsuranceAmount(); // 输出: Employee Insurance: $500
    }
}
```

## 深入 CLR 机制：编译时绑定 vs 运行时绑定

根据《CLR via C#》对方法调用的底层解析，方法隐藏本质上属于**静态绑定（Static Binding / 早期绑定）**。

1.  **方法隐藏 (`new`) 的底层逻辑**：
    当编译器看到 `baseRef.GetHealthInsuranceAmount()` 这行代码时，它只看 `baseRef` 这个变量的声明类型是 `Employee`。因为它不是虚方法（没有 `virtual` 修饰），编译器直接在 IL 代码中生成一个 `call` 指令，硬编码跳转到 `Employee.GetHealthInsuranceAmount()` 的内存地址。编译器**完全不关心**这块内存实际上装的是一个 `Manager` 对象。
2.  **方法重写 (`override`) 的对比预告**：
    如果父类方法是 `virtual`，子类使用 `override`，编译器会生成 `callvirt` 指令。在运行时，CLR 会去检查对象的真实类型（`Manager`），并在其方法表中查找最新的实现。

**简而言之：方法隐藏是“编译时”决定的，只看变量是什么类型；方法重写是“运行时”决定的，看对象究竟是什么。**

## 架构设计探讨：为什么要保留方法隐藏？

初学者常有的疑问是：既然方法隐藏会导致同一个对象用不同类型的变量去调用时产生不同的行为（这非常容易引发 Bug），为什么 C# 还要设计这个特性？

《C# in Depth》与《Framework Design Guidelines》（框架设计规范）中给出了核心答案：**为了应对基类库的版本控制问题（Versioning）。**

**典型场景（脆弱的基类问题）：**
1.  你使用了一个第三方库的基类 `ThirdPartyBase`。
2.  你在自己的派生类 `MyDerived` 中写了一个很有用的方法叫 `ProcessData()`。
3.  一年后，第三方库升级了。碰巧的是，第三方库的开发者在新的 `ThirdPartyBase` 中也添加了一个名为 `ProcessData()` 的方法。
4.  如果你升级了第三方库，你的代码突然出现了命名冲突。
5.  此时，C# 允许你在自己的 `ProcessData()` 前面加上 `new` 关键字。这等同于告诉编译器：“我知道父类现在也有这个方法了，但我不想重写它，我要保留我自己的独立逻辑，将其与父类的方法彻底隔离开来。”

## 最佳实践 (参考《Effective C#》)

1.  **避免滥用**：在日常业务开发中，**绝对不要**试图用 `new` 关键字来模拟多态（Polymorphism）。这会严重破坏面向对象设计中“里氏替换原则（LSP）”，导致系统行为不可预测。
2.  **默认选择**：如果希望子类能够改变父类的行为，必须在父类将方法设计为 `virtual`，并在子类使用 `override`。
3.  **唯一适用场景**：仅当遭遇不可控的第三方库更新导致的方法名冲突，或者在极特殊的向下兼容设计中，才应使用 `new` 关键字进行方法隐藏。
