**Switch-Case 语句与现代模式匹配进阶**

# Switch-Case 的核心机制与基础语法

`switch-case` 是一种专门用于**单一变量多值匹配**的条件控制结构。当需要根据一个变量的多个具体离散值（如枚举、状态码、特定字符）来决定执行不同逻辑时，它的语义比冗长的 `else-if` 阶梯更加清晰。

**核心执行规则：**
1.  **自顶向下匹配**：传入的变量会依次与每个 `case` 的值进行对比。
2.  **互斥执行**：一旦某个 `case` 匹配成功，将立刻执行该分支下的代码块。
3.  **强制中断机制**：在 C# 中，每个执行块的末尾**必须**包含跳转语句（通常是 `break`，也可以是 `return` 或 `throw`）。这会立刻终止整个 `switch` 块的执行，并将控制权交还给 `switch` 之后的下一条语句。
4.  **保底逻辑**：如果所有 `case` 均未命中，程序会执行 `default` 分支（类似于 `else`）。

**基础代码示例（基于离散值匹配）：**

```csharp
char gradeLetter = 'A';
string gradeDescription;

switch (gradeLetter)
{
    case 'O':
        gradeDescription = "Outstanding";
        break; // 必须的强制中断
    case 'A':
        gradeDescription = "Excellent";
        break;
    case 'B':
        gradeDescription = "Good";
        break;
    case 'F':
        gradeDescription = "Fail";
        break;
    default:
        gradeDescription = "None";
        break; // C# 中 default 也必须显式中断
}
```

# 深度进阶：底层架构与性能剖析 (Switch vs Else-If)

在初学者眼中，`switch` 只是 `else-if` 的语法糖，但在编译器底层（IL 与 JIT 层面），它们的运作逻辑有着本质的性能差异。

*   **Else-If 的性能痛点**：`else-if` 是**线性查找 (O(N))**。如果目标条件在阶梯的最末尾，CPU 必须将前面的所有条件依次计算一遍，这伴随着极大的“分支预测失败”风险。
*   **Switch 的底层优化**：
    *   **跳转表 (Jump Table)**：当 `switch` 匹配的是连续或密集的整数/字符时（如200,201,202,203），C# 编译器在底层会将其优化为一个哈希表式的“跳转表”。CPU 可以通过一次简单的计算（先每个减200然后类似数组按索引取值），在 **O(1) 时间复杂度**内直接跳转到目标指令内存地址，完全绕过逐个比较的过程。
    *   **字符串哈希优化**：当 `switch` 用于匹配大量的 `string` 类型时，编译器会构建一个底层的字典 (Dictionary/Hash Map)，同样实现了极高的查找效率。

**架构结论**：当离散分支数量较多（通常大于 5 个）时，无论是从代码可读性还是底层执行效率来看，`switch` 都是绝对优于 `else-if` 的选择。

# 进阶语法：合法的贯穿 (Fall-through) 与多重匹配

C/C++ 允许隐式的“贯穿”（即忘了写 `break`，代码会继续执行下一个 `case`），这曾是无数恶性 Bug 的源头。
C# 吸收了这一教训，**严禁包含代码的 case 发生隐式贯穿**。但是，C# 允许**空 case 的贯穿**，这为“多个条件共用一段逻辑”提供了优雅的解法：

```csharp
char letter = 'a';

switch (letter)
{
    // 堆叠空 case，实现逻辑 OR (即大写 A 或小写 a 都执行该逻辑)
    case 'A':
    case 'a':
        Console.WriteLine("This is a vowel A.");
        break;
    case 'E':
    case 'e':
        Console.WriteLine("This is a vowel E.");
        break;
    default:
        Console.WriteLine("Consonant or other.");
        break;
}
```

# 现代 C# 的降维打击：模式匹配 (Pattern Matching)

随着 C# 版本的迭代（特别是 C# 7.0 到 C# 9.0），`switch` 早已脱离了“只能匹配固定常量”的低级形态，进化为了强大的**模式匹配引擎**。

## 类型匹配与 when 守卫 (Type Pattern & When Clause)
现代 `switch` 可以直接判断变量的**数据类型**，并配合 `when` 关键字增加额外的业务条件判断。

```csharp
object sensorData = 45.5m; // 假设从传感器接收到未知类型数据

switch (sensorData)
{
    case int i when i > 100:
        Console.WriteLine($"High integer value: {i}");
        break;
    case int i: // 匹配整数
        Console.WriteLine($"Normal integer: {i}");
        break;
    case decimal d: // 匹配高精度浮点数
        Console.WriteLine($"Precise decimal: {d}");
        break;
    case null:
        Console.WriteLine("No data received.");
        break;
}
```

## Switch 表达式 (Switch Expressions - C# 8.0+)
传统的 `switch` 是一个**语句 (Statement)**，它的目标是“执行代码”。但在工程实践中，我们常常只是为了“根据某个值，计算并返回另一个值”（如第一节的成绩映射）。
现代 C# 引入了 **Switch 表达式**，极其精简，摒弃了繁琐的 `case` 和 `break`：

```csharp
char gradeLetter = 'B';

// 极简、函数式风格的 Switch 表达式
// 1. 变量直接放在 switch 关键字前面
// 2. 用 => 替代冒号
// 3. 用 _ 替代 default
string gradeDescription = gradeLetter switch
{
    'O' => "Outstanding",
    'A' => "Excellent",
    'B' => "Good",
    'F' => "Fail",
    _   => "None"
};
```

## 关系模式与逻辑模式 (Relational & Logical Patterns - C# 9.0+)
现在，`switch` 甚至可以直接替代复杂的 `if-else` 数值范围判断，支持使用 `>`, `<`, `>=`, `<=`, `and`, `or`, `not`：

```csharp
int marks = 75;

// 使用 Switch 表达式处理区间范围，逻辑清晰度远超 else-if 阶梯
string evaluation = marks switch
{
    >= 85 => "Exceptional",
    >= 60 and < 85 => "Passable", // 使用 and 组合条件
    < 60 and not 0 => "Needs Improvement", // 使用 not 排除特定值
    0 => "Disqualified",
    _ => "Unknown"
};
```

**总结**：现代 C# 开发中，传统的 `switch-case` 语句主要用于含有复杂多行执行逻辑的场景；而对于任何涉及到**状态映射、范围转换、赋值推导**的场景，强烈推荐使用 C# 8.0+ 的 **Switch 表达式**，它不仅代码量减少了三分之二，而且在不可变性（Immutability）和函数式编程范式上更加安全。
