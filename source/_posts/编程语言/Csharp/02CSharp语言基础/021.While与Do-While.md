While 与 Do-While 循环及底层工程实践

# 循环结构的核心要素与设计哲学

循环语句的本质是让计算机以极高的效率重复执行某段指令，直到满足特定的退出条件。无论是哪种循环，在底层逻辑上都必然包含以下四个核心生命周期阶段：

1.  **初始化 (Initialization)**：建立循环的初始状态（如设定计数器变量）。
2.  **条件校验 (Condition Evaluation)**：每次迭代前（或后）计算的一个布尔表达式。返回 `true` 则继续，`false` 则打破循环。
3.  **循环体 (Body Execution)**：实际需要重复执行的业务逻辑代码。
4.  **状态更新 (State Mutation)**：在单次迭代结束时修改初始状态（如递增/递减计数器），如果缺失这一步，将导致**死循环 (Infinite Loop)**。

# While 循环：前置守卫策略

`while` 循环采用的是**“先校验，后执行”**（前置守卫）的策略。
如果初始条件为 `false`，循环体内的代码**可能一次都不会被执行**。它非常适合那些“未知确切迭代次数，且依赖外部状态或动态条件”的场景。

**基础代码示例：**
```csharp
int count = 9;
// 倒序输出 9 到 0
while (count >= 0)
{
    Console.Write(count + " ");
    count--; // 必须的状态更新
}
```

**深度进阶：While 循环与 IEnumerator 的底层渊源**
在 C# 中，我们常用的 `foreach` 循环其实只是一个语法糖，编译器在底层会将其完全展开为一个 `while` 循环配合迭代器（`IEnumerator`）工作。理解这一点有助于掌握 C# 集合遍历的底层逻辑。

**`foreach` 在底层的真实面貌：**
```csharp
List<int> numbers = new List<int> { 1, 2, 3 };
using (IEnumerator<int> enumerator = numbers.GetEnumerator())
{
    // 底层使用 while 循环持续向前推进游标
    while (enumerator.MoveNext()) 
    {
        int currentNumber = enumerator.Current;
        Console.WriteLine(currentNumber);
    }
}
```

# Do-While 循环：后置校验与“至少执行一次”保证

`do-while` 循环采用的是**“先执行，后校验”**的策略。
无论条件是否成立，`do` 内部的代码块**绝对会执行至少一次**。它的语法特点是需要在末尾的 `while(condition)` 之后加上分号 `;`。

**架构级应用场景：轮询机制与重试策略 (Retry Pattern)**
在实际工程开发中，`do-while` 最典型的应用场景之一是**容错重试机制**。例如，尝试连接数据库或请求外部 API 时，我们总是需要“先请求一次”，如果失败了再根据条件决定是否重试。

**实战代码示例：带有最大重试次数的网络请求兜底逻辑**
```csharp
int retryCount = 0;
int maxRetries = 3;
bool isSuccess = false;

do
{
    // 1. 尝试执行有风险的操作（至少执行一次）
    isSuccess = TryConnectToDatabase(); 
    
    if (!isSuccess)
    {
        retryCount++;
        Console.WriteLine($"连接失败，正在进行第 {retryCount} 次重试...");
    }

// 2. 校验：如果没有成功，且还没达到最大重试次数，则继续循环
} while (!isSuccess && retryCount < maxRetries);
```

# 深度进阶：现代 C# 开发中的循环陷阱与最佳实践

初学者往往只关注循环的语法，但在企业级开发中，不当的循环使用会导致严重的性能危机和系统崩溃。

## 警惕 CPU 饥饿 (CPU Starvation) 与死循环
在编写后台服务时，经常会遇到 `while(true)` 构建的无限循环任务。如果循环体内没有任何阻塞或让出 CPU 时间片的机制，该线程将会瞬间占满一个 CPU 核心（即 CPU 使用率飙升至 100%）。

**现代解法：引入异步延迟 (`await Task.Delay`)**
在现代 C# 异步编程中，绝对不能在 `while(true)` 中使用 `Thread.Sleep()`（这会“钉死”当前线程）。应当使用异步的 `Task.Delay`，让出线程供线程池中的其他任务使用。

```csharp
// 后台消费者队列监控的标准写法
async Task ProcessQueueAsync(CancellationToken cancellationToken)
{
    while (!cancellationToken.IsCancellationRequested)
    {
        var item = GetNextItem();
        if (item != null)
        {
            Process(item);
        }
        else
        {
            // 队列为空时，异步等待 100 毫秒，释放当前线程
            // 绝不使用 Thread.Sleep(100);
            await Task.Delay(100, cancellationToken); 
        }
    }
}
```

## 循环体内的内存分配陷阱 (GC Pressure)
循环体是被高频执行的代码块。如果在一个迭代数十万次的 `while` 循环内部不停地使用 `new` 关键字实例化复杂对象，会在短时间内向托管堆（Heap）产生极其庞大的内存垃圾，迫使垃圾回收器（GC）频繁介入（Gen 0 / Gen 1 回收），导致程序出现明显的卡顿。

**优化准则：将对象分配移出循环 (Object Pooling/Hoisting)**
对于不需要保留状态的临时对象，应尽可能在循环外部实例化，在循环内部仅修改其属性或重置状态。

## 现代 I/O 读取范式：异步 While 循环
在处理文件流、数据库游标或网络流时，读取操作通常是阻塞的。现代 C# 强烈推荐结合异步模式使用 `while` 循环读取数据。

```csharp
using (StreamReader reader = new StreamReader("largefile.txt"))
{
    string line;
    // 异步读取，直到文件末尾。在等待磁盘 I/O 时不会阻塞主线程
    while ((line = await reader.ReadLineAsync()) != null)
    {
        ParseLine(line);
    }
}
```
