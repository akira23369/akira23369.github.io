# 第17节：处理 null 值

## 第一讲：什么是 null

### 引言
在 C#中，**null** 是一个特殊的字面量，表示值的缺失。它用于**引用类型**（如 string、object 或任何 class 实例），表示变量没有指向堆内存中的任何对象。这意味着该引用为空或不存在。

默认情况下，任何未分配对象的引用类型变量都会被初始化为 null。掌握如何处理 null 是 C#开发者最关键的技能之一，因为它是.NET 编程中最常见的运行时错误来源。

### 工作原理：NullReferenceException
null 的危险性在于它会导致可怕的 **NullReferenceException**。当你在运行时尝试访问当前为 null 的变量成员（方法、属性或字段）时，就会抛出此异常。这就像试图按下一个不存在的遥控器按钮。C#编译器并不总能检测到这种情况，因此程序可以正常编译，但运行时就会崩溃。

### 示例
让我们看一个导致此错误的简单场景。

```csharp
public class Program
{
    public static void Main(string[] args)
    {
        // 'name' 是引用类型（string）。我们显式将其设置为 null。
        // 这与未初始化的类字段的行为相同。
        string name = null;

        // 这行代码在编译器看来是合法的。编译器只知道 'name' 是 string 类型，
        // 而字符串拥有 'Length' 属性。
        Console.WriteLine("The length of the name is: " + name.Length);

        // 当代码运行时，.NET 运行时会尝试找到 'name' 指向的对象。
        // 由于它指向空（null），程序无法从空值中获取 'Length' 属性，
        // 会立即崩溃并抛出 NullReferenceException 异常。
    }
}
```

### 最佳实践与面试视角
**防御性编程**： 避免此异常的关键在于"防御性编程"。在使用对象前，特别是来自方法参数或类字段的对象时，始终应考虑检查它是否为 null。

```csharp
if (name != null)
{
    Console.WriteLine(name.Length);
}
else
{
    Console.WriteLine("Name is not provided.");
}
```

**问题**："什么是 NullReferenceException？它由什么引起？"

**理想答案**："NullReferenceException 是一种运行时错误，当你尝试访问持有 null 引用的变量成员（如方法或属性）时发生。这意味着该变量没有指向内存中的实际对象实例，因此无法执行该操作。"

## 第二讲：可空类型

### 引言
默认情况下，**值类型**（int、double、bool、struct 等）**不能为 null**。这是因为它们不是引用类型；值类型变量始终包含值本身。int 变量总是包含一个数字，即使只是 0。

然而，在实际应用中，很多情况下值类型在逻辑上可能是"缺失"或"未定义"的。例如，在数据库中，Price 或 DateOfBirth 列可能允许 NULL 值。为了在 C#中表示这种情况，该语言提供了**可空值类型**。

### 工作原理：`?` 语法与 `Nullable<T>`
通过在类型名称后添加问号（?），可以将值类型声明为可空类型。

**语法**：`int?`、`double?`、`bool?`

这种简写是一个名为 `System.Nullable<T>` 的特殊泛型结构的别名。因此，`int?` 只是 `Nullable<int>` 的更简洁写法。该结构包装了值类型并添加了两个重要属性：
- **HasValue**：一个 bool 属性，当变量持有实际值时返回 true，为 null 时返回 false。
- **Value**：类型为 T 的属性，用于获取基础值。必须在确认 HasValue 为 true 后才能访问此属性，否则会抛出 InvalidOperationException 异常。

### 示例
```csharp
public class SurveyResponse
{
    // 评分可能是可选的，因此使用可空整数。
    public int? Rating { get; set; }
}

public class Program
{
    public static void Main(string[] args)
    {
        SurveyResponse response1 = new SurveyResponse();
        response1.Rating = 5; // 赋值一个有效值。

        SurveyResponse response2 = new SurveyResponse();
        response2.Rating = null; // 表示缺失的值。

        PrintRating(response1);
        PrintRating(response2);
    }

    public static void PrintRating(SurveyResponse response)
    {
        // 访问 .Value 属性前，务必检查 HasValue
        if (response.Rating.HasValue)
        {
            Console.WriteLine($"Rating provided: {response.Rating.Value}");
        }
        else
        {
            Console.WriteLine("No rating was provided.");
        }
    }
}
```

**输出结果**：
```
Rating provided: 5
No rating was provided.
```

## 第三讲：空值合并运算符 (??)

### 引言
**空值合并运算符 ??** 是一个简洁的二元运算符，用于为可空类型或引用类型提供**默认值**（当该值为 null 时）。这是对常见 if 判断的一种简洁且高可读性的快捷写法。

### 工作原理
该运算符作用于两个操作数：`A ?? B`
1. 它会先计算左侧操作数(A)的值。
2. 如果 A **不为空**，表达式将返回 A 的值。
3. 如果 A **为空**，表达式将返回右侧操作数（B）的值。

### 使用场景
当你想使用变量的值但又需要在变量为空时回退到默认值时，可以使用此运算符。它能让你的代码更简洁且更具表现力。

### 示例
假设我们需要获取用户的昵称用于显示，但如果用户未设置昵称，则应使用其全名作为回退值。

```csharp
public class User
{
    public string FullName { get; set; }
    public string Nickname { get; set; } // 此字段可以为 null
}

// --- 在 Main 方法中 ---
User user1 = new User { FullName = "John Doe", Nickname = "Johnny" };
User user2 = new User { FullName = "Jane Smith", Nickname = null };

// 传统的 if 语句写法：
string displayName1;
if (user1.Nickname != null)
{
    displayName1 = user1.Nickname;
}
else
{
    displayName1 = user1.FullName;
}
Console.WriteLine($"Welcome, {displayName1}"); // 输出: Welcome, Johnny

// 现代、简洁的 ?? 运算符写法：
string displayName2 = user2.Nickname ?? user2.FullName;
Console.WriteLine($"Welcome, {displayName2}"); // 输出: Welcome, Jane Smith
```

## 第四讲：空值传播运算符 (?.)

### 引言
**空值传播运算符 ?.**（又称空条件运算符）是 C#的一项现代特性，旨在更安全、更简洁地处理可能包含 null 值的对象链式访问。它帮助开发者避免编写深层嵌套的 if 语句来逐级检查 null。

### 工作原理
当使用 `?.` 访问成员（属性或方法）时，C#会首先检查 `?.` 左侧的对象是否为 null。
1. 若对象为 null，整个表达式将立即短路并返回 null，而不会尝试访问右侧成员，从而避免抛出 NullReferenceException 异常。
2. 如果它不是 null，就会像往常一样访问成员。

该运算符可以链式使用。如果链式调用 `A?.B?.C` 中的任何部分为 null，整个表达式会优雅地返回 null。
还有一种用于访问索引器的版本，称为空条件索引器(`?[]`)。

### 示例
考虑一个常见场景：你需要获取客户的邮政编码。客户可能为 null，或者他们的地址可能为 null。

```csharp
public class Address { public string PostalCode { get; set; } }
public class Customer { public Address ShippingAddress { get; set; } }

public class Program
{
    public static void Main(string[] args)
    {
        Customer customerWithAddress = new Customer 
        { 
            ShippingAddress = new Address { PostalCode = "501505" } 
        };
        Customer customerWithoutAddress = new Customer { ShippingAddress = null };
        Customer nullCustomer = null;

        // --- 传统写法：嵌套 if 检查（"厄运金字塔"）---
        if (customerWithAddress != null)
        {
            if (customerWithAddress.ShippingAddress != null)
            {
                Console.WriteLine(customerWithAddress.ShippingAddress.PostalCode);
            }
        }

        // --- 现代、安全且简洁的写法 ---
        // 使用空值传播运算符。
        string postal1 = customerWithAddress?.ShippingAddress?.PostalCode;
        string postal2 = customerWithoutAddress?.ShippingAddress?.PostalCode;
        string postal3 = nullCustomer?.ShippingAddress?.PostalCode;

        // 可以结合空值合并运算符提供默认值。
        Console.WriteLine($"Postal Code 1: {postal1 ?? "Not Found"}"); // 输出: 501505
        Console.WriteLine($"Postal Code 2: {postal2 ?? "Not Found"}"); // 输出: Not Found
        Console.WriteLine($"Postal Code 3: {postal3 ?? "Not Found"}"); // 输出: Not Found
    }
}
```

## 第五讲：重要知识点备忘

1. **null 用于引用类型**： 请记住，null 表示引用变量未指向任何对象。值类型不能为 null，除非显式声明为可空类型。
2. **NullReferenceException 是开发者的责任**： 其发明者曾著名地称之为"十亿美元的错误"。现代 C#特性正是为帮助避免此问题而设计。请始终保持防御性编程，特别是处理外部数据源时务必进行 null 检查。
3. **使用可空类型(int?、bool?)处理可选值**： 当值类型在逻辑上可能没有值时（如数据库中的 NULL 字段、可选调查答案），应使用可空类型。在访问 `.Value` 属性前，务必先检查 `.HasValue` 属性以避免 InvalidOperationException 异常。
4. **优先使用 ?? 和 ?. 实现简洁与安全**： 这些运算符不仅是快捷方式；相比手动使用 `if (x != null)` 检查，它们能显著提升代码的简洁性、可读性和安全性。在现代 C#代码中应全面采用。这是开发者精通语言的标志。
5. **可空引用类型（高级面试要点）**： 在 C# 8.0 及更高版本中，可启用名为"可空引用类型"的项目级功能。启用后，编译器行为会发生反转：
   - 标准的 `string` 变量被视为不可为空类型，如果尝试为其赋值 null，编译器会发出警告。
   - 要声明允许为空的引用类型，必须像值类型一样使用 ? 语法：`string?`。
   - **重要性**： 这一特性帮助你在编译时就消除 NullReferenceException 错误，而不是等到程序在运行时崩溃。提及你对这一现代特性的了解，能展示你紧跟 C# 编写健壮代码的最佳实践。
