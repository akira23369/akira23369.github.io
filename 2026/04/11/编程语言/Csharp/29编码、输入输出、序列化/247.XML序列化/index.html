第一章：XML 基础概论

在深入 C# 代码之前，我们必须牢固掌握 XML 本身的理论基础。你已經熟悉了 JSON，这有助于理解，但 XML 有着完全不同的设计哲学。

什么是 XML？

XML，全称 Extensible Markup Language（可扩展标记语言），是一种用于存储和传输数据的标记语言。它由万维网联盟（W3C）于 1998 年发布推荐标准。

核心定义：
XML 被设计用来传输和存储数据，其焦点是数据的内容。相比之下，HTML 被设计用来显示数据，其焦点是数据的外观。

关键特性：

  1. 自描述性： XML 标签没有被预先定义。你需要自己定义标签（如 <Book>, <Price>）。这使得它具有极强的可扩展性。
  2. 平台无关性： XML 是纯文本格式，任何硬件、软件平台都可以读取和生成。
  3. 层次结构： XML 数据天然呈现树状结构（DOM 树），适合表示具有层级关系的数据。
  4. 严格语法： XML 对语法要求非常严格，标签必须闭合，大小写敏感，属性值必须加引号等。

XML 的历史与设计目标

在 90 年代末期，互联网快速发展，SGML（Standard Generalized Markup Language）虽然功能强大但过于复杂，不适合 Web 使用。HTML 虽然简单，但混用了内容与表现，且缺乏数据描述能力。

XML 的设计目标是在 SGML 的灵活性和 HTML 的易用性之间找到平衡。它最初被寄予厚望，成为 Web 服务（Web Services）、配置文件、文档存储的标准格式。虽然现在 JSON 在 Web API 领域占据了主导地位，但 XML 在企业级应用、配置文件（如 .csproj, .xml config）、文档格式（Office Open XML, PDF 内部结构）以及遗留系统中依然不可或缺。

XML 与 HTML 的区别

很多初学者容易混淆两者，以下是关键区别笔记：

特性 XML HTML
目的 存储和传输数据 显示数据
标签 自定义（用户定义） 预定义（浏览器识别）
语法严格性 极高（标签必须闭合，区分大小写） 较低（容错性强，某些标签可不闭合）
空标签 <img /> 必须闭合 <img> 通常可接受
大小写 敏感 (<Book> != <book>) 不敏感
属性值 必须加引号 有时可省略引号

重点： 在 C# 序列化中，我们生成的是 XML，必须严格遵守 XML 语法规范，否则解析器会抛出异常。

XML 与 JSON 的对比分析

既然你已经学过 JSON，对比学习能加深理解。

特性 XML JSON
体积 较大（重复的标签名） 较小（键名重复少）
可读性 较好（标签语义清晰） 好（结构紧凑）
数据类型 所有数据本质是字符串，需 Schema 定义类型 原生支持 String, Number, Boolean, Null, Array, Object
元数据 支持属性（Attributes）作为元数据 只能通过额外的键值对表示
注释 支持 <!-- --> 不支持标准注释
命名空间 原生支持 xmlns 不支持
解析速度 相对较慢（结构复杂） 相对较快
C# 支持 多种序列化器（XmlSerializer, DCS） Newtonsoft, System.Text.Json

何时选择 XML？

  1. 需要文档标记（如混合内容：文本中包含标签）。
  2. 需要严格的 Schema 验证（XSD）。
  3. 需要命名空间支持（避免标签冲突）。
  4. 对接遗留系统（SOAP Web Services, 银行接口，政府接口）。
  5. 配置文件（.NET 传统 config 文件）。

XML 文档结构详解

一个标准的 XML 文档由以下部分组成：

详细拆解：

  1. XML 声明 (Prolog): <?xml version="1.0" encoding="UTF-8"?>
    • 必须位于文档第一行（此前不能有空白）。
    • 声明版本和编码。UTF-8 是最常用的编码。
  2. 根元素 (Root Element): 整个文档必须有一个且仅有一个根元素。所有其他元素都是它的子元素。
  3. 元素 (Elements): 由开始标签 <Book>、内容和结束标签 </Book> 组成。
  4. 属性 (Attributes): 位于开始标签内，提供关于元素的额外信息。如 id="123"。
    • 在序列化设计中，通常建议简单数据用元素，元数据用属性。
  5. 文本内容 (Text Content): 元素之间的数据。
  6. CDATA 节: <![CDATA[ ... ]]> 用于包裹不需要解析器转义的内容（如包含大量 < 的代码片段）。
  7. 实体引用 (Entity References): XML 中有 5 个预定义实体：
    • &lt; (<)
    • &gt; (>)
    • &amp; (&)
    • &quot; (")
    • &apos; (')
    • 注意： 序列化器会自动处理这些转义，但手动编写 XML 时需注意。
  8. 命名空间声明 (Namespace Declaration): xmlns="..." 或 xmlns:prefix="..."。

XML Schema (XSD) 与 DTD

DTD (Document Type Definition):
较老的标准，语法非 XML 格式，功能有限，不支持数据类型（除了枚举等基础）。现在较少使用。

XSD (XML Schema Definition):
当前标准。它本身也是一个 XML 文件，用于定义 XML 文档的结构、数据类型、约束。

  • 可以定义元素必须是整数、日期或特定字符串格式。
  • 可以定义必填项、可选项。
  • C# 可以通过 xsd.exe 工具根据 XSD 生成 C# 类，或根据 C# 类生成 XSD。

在企业级集成中，通常先约定 XSD，再生成代码，确保双方数据结构一致。

第二章：.NET 中的 XML 技术栈概览

.NET 框架经过二十多年的发展，提供了多种处理 XML 的方式。选择合适的工具是成功的关键。

.NET XML 类库演变史

  1. .NET Framework 1.0/1.1: 引入了 System.Xml 和 System.Xml.Serialization。这是最经典的 XML 处理方式，基于 DOM 和 SAX 模式。
  2. .NET Framework 2.0: 增强了 XmlSerializer，引入了 DataContractSerializer 的雏形（为 WCF 准备）。
  3. .NET Framework 3.5: 引入了 LINQ to XML (System.Xml.Linq)。这是一次革命，使得 XML 操作像查询数据库一样简单，支持函数式构造。
  4. .NET Core / .NET 5+: 大部分 XML 库被保留并优化，但移除了部分旧的王牌技术（如 WCF 客户端部分功能），强调跨平台兼容性。System.Text.Json 崛起，但 XML 领域依然依赖传统库。

System.Xml.Serialization (XmlSerializer)

  • 定位： 最常用的 XML 序列化器，用于将 public 字段和属性转换为 XML。
  • 优点： 配置灵活，支持丰富的属性控制，社区资料多。
  • 缺点： 性能一般（首次启动慢，因为动态生成程序集），要求类必须有公共无参构造函数，只能序列化 public 成员。
  • 适用场景： 一般的数据持久化、Web Service 数据交换。

System.Runtime.Serialization (DataContractSerializer)

  • 定位： WCF (Windows Communication Foundation) 的默认序列化器。
  • 优点： 性能优于 XmlSerializer，支持非 public 成员（通过属性），版本控制能力强。
  • 缺点： 控制粒度不如 XmlSerializer 精细（例如很难控制属性变元素），与 WCF 绑定较深。
  • 适用场景： WCF 服务内部，或对性能有较高要求的 XML 交换。

System.Xml.Linq (LINQ to XML)

  • 定位： 内存中的 XML 树表示，侧重于操作而非单纯的序列化。
  • 优点： API 现代简洁，支持 LINQ 查询，支持函数式构造（直接 new XElement）。
  • 缺点： 不是直接的“对象转 XML"序列化器，需要手动映射（虽然可以自己写扩展方法）。
  • 适用场景： 需要灵活读取、修改 XML 结构，或 XML 结构不固定时。

System.Xml (XmlReader/XmlWriter)

  • 定位： 底层的流式读写器。
  • 优点： 性能最高，内存占用最低（不回溯，不加载整个文档）。
  • 缺点： 使用复杂，代码量大，容易出错。
  • 适用场景： 超大文件处理（GB 级别），高性能中间件。

技术选型指南

需求场景 推荐技术 理由
简单对象存为 XML 文件 XmlSerializer 简单，属性控制多
WCF 服务通信 DataContractSerializer 框架集成好，性能优
灵活查询/修改 XML LINQ to XML 语法友好，功能强
超大文件流式处理 XmlReader/Writer 内存效率最高
需要复杂验证 XSD + XmlSerializer 生态完善

第三章：XmlSerializer 深度解析（核心）

这是本文的核心部分。System.Xml.Serialization.XmlSerializer 是 C# 中处理 XML 序列化的主力军。

XmlSerializer 的工作原理

理解原理有助于调试。

  1. 反射 (Reflection): XmlSerializer 首先通过反射分析你要序列化的类型（Class）。
  2. 动态程序集 (Dynamic Assembly): 为了提高后续性能，它会动态生成一个临时的序列化程序集（Serialization Assembly）。这个程序集包含专门针对该类型的读写代码。
    • 注意： 这就是为什么第一次序列化某个类型时会比较慢。
    • 注意： 在 AOT (Ahead-of-Time) 编译环境（如 .NET Native 或某些 Xamarin 场景）中，动态生成可能受限，需要预生成序列化程序集。
  3. 缓存: 生成的序列化器会被缓存，后续针对同一类型的操作会直接使用缓存，速度变快。
  4. 约束: 由于它动态生成代码访问成员，所以被序列化的字段或属性必须是 public 的，且类必须有 public 无参构造函数。

第四章：DataContractSerializer 深度解析

WCF 时代的遗产

DataContractSerializer (DCS) 是随着 WCF (Windows Communication Foundation) introduced 的。它的设计目标是比 XmlSerializer 更快、更严格、更适合服务通信。虽然 WCF 在现代 .NET Core 中地位下降，但 DCS 依然存在于 System.Runtime.Serialization 命名空间中。

与 XmlSerializer 的核心差异

  1. 成员可见性： XmlSerializer 只能序列化 public 属性/字段。DCS 可以序列化 private 字段（只要属性有 getter/setter 且标记了 [DataMember]）。
  2. 顺序控制： XmlSerializer 按字母或 Order 属性。DCS 严格依赖 [DataMember(Order = n)]。
  3. 名称控制： DCS 使用 [DataContract(Name = "...")] 和 [DataMember(Name = "...")]。
  4. 性能： DCS 通常比 XmlSerializer 快 10% 左右，因为它不使用动态程序集生成，而是使用反射缓存。
  5. 版本容忍度： DCS 对未知数据更宽容（默认忽略未知元素），而 XmlSerializer 可能会报错或需要额外配置。

DataContract 与 DataMember 属性

版本控制与兼容性

DCS 提供了更好的版本控制支持。

  • IsRequired = false: 表示该字段在反序列化时如果缺失，不会报错，保持默认值。
  • EmitDefaultValue = false: 如果值是默认值（如 int 0, string null），则不序列化该元素，减小体积。

如果 Description 为 null，XML 中将不会出现 <Description> 节点。

第七章：高级主题与最佳实践

性能优化策略

  1. 缓存 XmlSerializer 实例： 不要每次序列化都 new XmlSerializer(typeof(T))。因为首次初始化成本高，应该将其定义为 static readonly。
  2. 预生成序列化程序集 (SGen.exe)： 在大型项目中，使用 SGen 工具预先生成序列化程序集，避免运行时动态编译，提高启动速度。
  3. 避免不必要的命名空间： 如 3.8 节所述，移除默认 xmlns 可以减少字符串处理开销。
  4. 使用 XmlWriter 替代 Serialize： 对于极高性能需求，手动编写 XmlWriter 代码比反射快得多。

  • UTF-8 vs UTF-16: .NET 内部字符串是 UTF-16。StringWriter 默认输出 UTF-16。Web 通常期望 UTF-8。
  • 解决方案： 使用 StreamWriter 指定编码。
  • BOM (Byte Order Mark): 某些旧系统要求 UTF-8 带 BOM，某些严格要求不带。new UTF8Encoding(false) 可以去掉 BOM。

异步序列化支持

传统的 XmlSerializer.Serialize 是同步的。在 .NET Core 2.1+ 中，XmlWriter 支持异步写入，但 XmlSerializer 本身没有直接的 SerializeAsync 方法。
变通方案：
使用 Task.Run 包裹同步方法，或者使用 LINQ to XML 的 SaveAsync 方法（如果使用的是 XDocument 配合 XmlWriter 异步）。
对于高并发 Web 应用，避免阻塞 IO 线程很重要。

跨平台互操作性

  • 大小写敏感： XML 元素名是大小写敏感的。确保 C# 属性名与合同一致。
  • 日期格式： XML Schema 默认日期格式是 yyyy-MM-ddTHH:mm:ss。C# DateTime 序列化通常符合此标准。但要注意时区问题（Kind=Utc vs Local）。建议统一使用 UTC 时间序列化。
  • 换行符： Windows 是 \r\n，Linux 是 \n。XML 标准化了换行符，但在生成文本文件时需注意。

常见问题： 命名空间不匹配。需要仔细检查生成的代码中的 Namespace 属性是否与对方要求一致。

大数据量 XML 导出

场景： 导出 100 万条记录为 XML。
错误做法： 将所有对象放入 List，然后 XmlSerializer.Serialize。会导致 OOM (Out Of Memory)。
正确做法： 使用 XmlWriter 流式写入。

这样内存占用极低，只取决于单条记录的大小。

第九章：常见陷阱与调试技巧

默认构造函数缺失问题

错误： System.InvalidOperationException: 无法生成临时类。
原因： 被序列化的类没有 public 无参构造函数。
解决： 添加 public MyClass() {}。即使你有带参构造函数，也必须保留无参的。

循环引用问题

错误： 栈溢出或序列化异常。
场景： A 类包含 B，B 类包含 A。
解决： XmlSerializer 不支持对象图循环引用。

  • 方法 1：打破循环（使用 ID 引用而不是对象引用）。
  • 方法 2：使用 [XmlIgnore] 忽略其中一方的属性。
  • 方法 3：改用 JSON 序列化器（如 Newtonsoft.Json 支持 ReferenceLoopHandling）。

特殊字符转义

现象： XML 中出现非法字符。
原因： 字符串中包含控制字符（如 ASCII 0-31）。
解决： 在序列化前清洗字符串。XML 1.0 对字符集有严格限制。

调试工具推荐

  1. Visual Studio 编辑器： 打开 .xml 文件会自动格式化，方便查看结构。
  2. XML 验证器： 在线工具或 VS 插件，用于验证 XML 是否符合 XSD。
  3. Fiddler / Wireshark： 如果 XML 用于网络传输，抓包查看原始 XML 报文是调试接口问题的关键。
  4. 即时窗口： 在调试时，使用 serializer.Serialize 输出到 Debug 窗口查看中间结果。

  4. 工程实践： 性能优化、安全防护、编码处理、异常调试。

XML 在未来开发中的地位

虽然 JSON 在 Web API 领域已成霸主，但 XML 不会消失。

  • 文档领域： Office 文档 (docx, xlsx) 本质是 ZIP 打包的 XML。
  • 配置领域： Java Maven (pom.xml), .NET Project (.csproj) 依然使用 XML。
  • 企业集成： 金融、医疗、政府行业的标准数据交换格式（HL7, FIPS 等）大量基于 XML。
  • SVG/ XHTML: 矢量图形和富文本依然依赖 XML 结构。

作为 C# 开发者，掌握 XML 序列化是处理企业级遗留系统、底层配置文件和复杂文档结构的必备技能。
