第一讲：字段简介

引言

在面向对象编程中，字段是直接声明在类中的变量。它们是存储数据的基本构件，代表对象的状态或属性。如果将类比作学生的蓝图，那么字段就是这张蓝图上标注姓名、学号和出生日期的线条。从该类创建的每个对象都会获得这些字段的独立副本，用以存储其独特状态。

运作原理：内存分配与对象隔离

这是一个关键概念。当你使用 new 关键字创建对象时，.NET 运行时会在称为堆（heap）的内存区域中分配一块内存。这块内存的大小足以容纳该对象类中定义的所有实例字段。

最重要的结论是：每个对象都会获得自己独立的内存块。这确保了对象之间相互隔离。修改一个对象的状态（其字段值）不会对同类的另一个对象的状态产生影响。

工作原理：复制对象引用

类属于引用类型。这意味着变量（student1）并不直接存储对象本身，而是存储该对象在堆内存中的地址（即引用）。当你将一个对象变量赋值给另一个变量时，实际上只是复制了这个内存地址。

《面试视角》

你必须能够清楚解释上述两种场景的区别。

问题：“创建两个新对象与将一个对象变量赋值给另一个有什么区别？”

理想答案：“使用 new 创建两个对象会在堆上分配两个独立的内存块，使它们彼此独立。而将一个对象变量赋值给另一个并不会创建新对象，它只是复制了内存引用。因此，两个变量指向同一个对象，通过其中一个变量所做的修改会通过另一个变量反映出来。”

第二讲：字段的访问修饰符

引言

访问修饰符是用于定义类成员可见性的关键字。它们是实现封装的核心机制，封装原则要求对象的内部数据应受到保护，避免直接且不受控制的外部访问。黄金法则是尽可能将字段设为私有。

访问修饰符列表及说明

修饰符 可访问性 使用场景
public 可以从任何位置访问 几乎不用于字段。将字段设为公共会完全破坏封装性。仅适用于常量或简单的数据传输对象(DTO)。
private 仅允许同一类中的代码访问。如果不指定修饰符，这是默认修饰符 这应该是所有字段的默认选择。它是封装原则的基石，强制要求所有数据交互必须通过公共方法或属性进行。
protected 允许包含类及其任何派生（子）类访问，即使这些子类位于不同项目中 当设计需要被继承的类时，若希望子类能直接访问某些辅助字段或数据。
internal 可在同一项目（程序集）内的任何代码中访问 适用于需要在项目内共享但不应该成为其公共 API 一部分的工具类或辅助字段。
protected internal protected 或 internal 的组合。可在同一项目中的任何代码访问，或由其他项目中的派生类访问 -
private protected private 与 protected 的组合。该字段只能由同一项目（程序集）中声明的派生类访问 -

面试视角

问题：“解释 protected 和 private protected 的区别。”

理想答案：“protected 允许任何派生类访问，无论它位于哪个项目中。而 private protected 限制更严格；它只允许与基类位于同一项目中的派生类访问。”

第三讲：静态字段

引言

静态字段属于类本身，而非任何单独的对象实例。无论创建多少个该类的对象，内存中只存在静态字段的一个副本，且所有对象共享这个副本。

工作原理：内存机制

实例字段随其所属对象一起存储在堆上，而静态字段则存储在类型元数据关联的特殊内存区域（通常位于称为高频堆的堆特殊分区中）。它仅在类型首次使用前初始化一次，通过 ClassName.FieldName 语法进行访问。

使用场景与实际案例

  1. 计数器：用于追踪一个类已创建了多少个对象。

  2. 共享资源：存储一个数据库连接字符串或日志记录器实例，供该类的所有对象共享。

  3. 单例模式：一种设计模式，通过静态字段持有类的唯一实例。

第四讲：常量字段（const）

引言

const（常量）字段声明了一个永远不能被修改的值。其值在编译时就已经固定。

工作原理：编译过程

C#编译器会在中间语言（IL）中直接用字面值替换代码中对 const 字段的所有引用。这本质上是一种编译时的"查找并替换"操作。因此，const 字段隐式是静态的，并且必须在声明时初始化。

使用场景与实际案例

  1. 数学常数：指那些在全局范围内永恒固定的数值。public const double PI = 3.14159;

  2. 物理常数：public const int SpeedOfLight = 299792458;

  3. 固定转换因子：public const int SecondsInHour = 3600;

  4. 应用全局键：当您拥有字典或配置中永不应更改的键时使用。public const string ApiKeyName = "MyApp:ApiKey";

第五讲：只读字段（readonly）

引言

只读字段的值只能被赋值一次。这个赋值可以发生在字段声明时，或者在同一类的构造函数中。构造函数执行完毕后，该字段将变为"只读"状态且不可更改。

工作原理：初始化

与 const 不同，readonly 字段的值在运行时确定。这是一个关键区别。它允许对象的每个实例拥有自己独特的、不可变的值，该值在对象创建时确定。

使用场景与实际案例

这非常适合那些在创建后不应改变的每个对象特有的值。

  1. 唯一标识符：public readonly Guid transactionId;

  2. 创建时间戳：public readonly DateTime creationDate;

  3. 依赖注入：当服务通过构造函数注入且应在对象生命周期内持续使用而无需替换时。private readonly ILogger _logger;

第七讲：关于字段需要记住的重要知识点

引言

本讲总结了在 C#中使用字段时最关键、最实用且最具面试价值的知识点。

字段代表状态
请记住，字段是类的"名词"或"形容词"。它们保存着定义任何给定对象当前状态的数据。

默认设为私有
这是封装性的黄金法则。始终将字段声明为私有。通过公共方法或属性以受控方式公开它们。

实例内存与静态内存
实例字段（readonly、public、private 等）：每创建一个对象，该字段就会产生独立副本。它们与所属对象一起存放在堆内存中。
静态字段（static）：该字段仅存在单一副本，且与类本身关联。它存储在独立内存区域，被所有对象共享。

const 与 readonly：核心面试题
你几乎肯定会被要求比较这些概念。准备好一个清晰、多要点的回答。

实例独立性 否。整个应用程序只有一个值。 是（如果是实例字段）。每个对象可以有不同的 readonly 值。
